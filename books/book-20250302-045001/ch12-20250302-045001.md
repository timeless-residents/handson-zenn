# 12. ElmとWebSocket：リアルタイムアプリケーションの実装

リアルタイムアプリケーションは、現代のウェブアプリケーション開発において、ますます重要な役割を果たしています。チャット、オンラインゲーム、リアルタイムデータ可視化など、即時性が求められる多くのアプリケーションで利用されています。Elmは、その堅牢な型システムと予測可能性により、信頼性の高いリアルタイムアプリケーションを構築するための優れた選択肢です。この章では、ElmでWebSocketを使用してリアルタイムアプリケーションを構築する方法について、段階的に解説していきます。

### WebSocketとは何か？

**1. 概要と重要性**

WebSocketは、クライアントとサーバー間の永続的な接続を確立し、双方向のリアルタイム通信を可能にする通信プロトコルです。従来のHTTPリクエスト/レスポンスモデルとは異なり、WebSocket接続は一度確立されると、サーバーとクライアントはいつでもメッセージを交換できます。これにより、リアルタイムなデータ更新やインタラクションを必要とするアプリケーションにおいて、優れたパフォーマンスと効率を実現できます。

**2. 特徴と利点**

*   **双方向通信:** サーバーとクライアントが互いにメッセージを送信できます。
*   **低レイテンシ:** 接続が確立されると、メッセージの送受信に必要なオーバーヘッドが大幅に削減されます。
*   **永続的な接続:** 接続は明示的に閉じられるまで維持されます。
*   **リアルタイム性:** ほぼ瞬時にデータが更新されます。
*   **標準化:** 多くのブラウザとサーバー環境でサポートされています。

**3. 事前準備と前提条件**

WebSocketを使う上で、特別に必要なライブラリはありません。Elmのコアライブラリに`WebSocket`モジュールが組み込まれています。ただし、サーバー側でWebSocketをサポートする仕組み（例：Node.jsの`ws`モジュール、Pythonの`websockets`ライブラリ）が必要です。ここでは、Node.jsと`ws`モジュールを使用する例で解説します。

**4. 基本的な使い方**

WebSocketの基本的な流れは以下の通りです。

1.  **クライアントからサーバーへの接続要求:** クライアントがWebSocketサーバーに接続を要求します。
2.  **サーバーによる接続の確立:** サーバーが接続要求を受け入れ、WebSocket接続を確立します。
3.  **データの送受信:** 確立された接続を通じて、サーバーとクライアントが自由にデータを送受信します。
4.  **接続の終了:** クライアントまたはサーバーが接続を閉じます。

**5. 実践的なテクニック**

ElmでWebSocket接続を扱うには、`WebSocket`モジュールを使用します。以下に基本的なコードスニペットを示します。

```elm
import Browser
import Html exposing (Html, button, div, text)
import Html.Events exposing (onClick)
import Json.Decode as Decode
import Json.Encode as Encode
import WebSocket

main : Program () Model Msg
main =
    Browser.element
        { init = init
        , view = view
        , update = update
        , subscriptions = subscriptions
        }


-- MODEL

type alias Model =
    { connected : Bool
    , message : String
    , receivedMessages : List String
    , webSocket : WebSocket.WebSocket
    }


init : () -> ( Model, Cmd Msg )
init _ =
    ( { connected = False
        , message = ""
        , receivedMessages = []
        , webSocket = WebSocket.init { onError = WebSocketError, onClose = WebSocketClosed }
      }
    , Cmd.none
    )


-- MESSAGES

type Msg
    = Connect
    | Disconnect
    | SendMessage
    | MessageReceived String
    | WebSocketError WebSocket.Error
    | WebSocketClosed
    | NewMessage String


-- UPDATE

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        Connect ->
            ( { model | connected = True }
            , WebSocket.connect "ws://localhost:8080/socket" Text (MessageReceived) model.webSocket
            )

        Disconnect ->
            ( { model | connected = False }
            , WebSocket.disconnect model.webSocket
            )

        SendMessage ->
            ( model, WebSocket.send model.message model.webSocket )

        MessageReceived message ->
            ( { model | receivedMessages = model.receivedMessages ++ [ message ] }, Cmd.none )

        WebSocketError error ->
            ( model, Debug.todo ("WebSocket Error: " ++ Debug.toString error) )

        WebSocketClosed ->
            ( { model | connected = False }, Debug.todo "WebSocket Closed" )

        NewMessage newMessage ->
            ( { model | message = newMessage }, Cmd.none )


-- SUBSCRIPTIONS

subscriptions : Model -> Sub Msg
subscriptions _ =
    Sub.none


-- VIEW

view : Model -> Html Msg
view model =
    div []
        [ div [] [ text ("Connection Status: " ++ (if model.connected then "Connected" else "Disconnected")) ]
        , button [ onClick Connect, disabled (model.connected) ] [ text "Connect" ]
        , button [ onClick Disconnect, disabled (not model.connected) ] [ text "Disconnect" ]
        , inputField NewMessage model.message
        , button [ onClick SendMessage, disabled (not model.connected) ] [ text "Send Message" ]
        , div [] [ text "Received Messages:" ]
        , div [] (List.map text model.receivedMessages)
        ]

inputField : (String -> msg) -> String -> Html msg
inputField tagger initialValue =
    Html.input
        [ Html.Attributes.type_ "text"
        , Html.Attributes.value initialValue
        , Html.Events.onInput tagger
        ] []
```

上記のコードは、WebSocketに接続し、メッセージを送受信する基本的なElmアプリケーションを示しています。

*   **`Model`:** アプリケーションの状態を保持します（接続状態、メッセージ、受信したメッセージのリスト、WebSocketオブジェクト）。
*   **`Msg`:** アプリケーションで発生する可能性のあるイベントを定義します（接続、切断、メッセージの送信、メッセージの受信、エラー、WebSocketのクローズ）。
*   **`update`:** イベントに応じてアプリケーションの状態を更新します。
*   **`view`:** ユーザーインターフェースをレンダリングします。
*   **`WebSocket.connect`:** WebSocketサーバーへの接続を確立します。`"ws://localhost:8080/socket"` はWebSocketサーバーのアドレスです。`Text` はテキスト形式のメッセージを想定していることを示します。`MessageReceived` はサーバーからメッセージを受信したときに実行される関数です。
*   **`WebSocket.send`:** サーバーにメッセージを送信します。
*   **`WebSocket.disconnect`:** WebSocket接続を切断します。
*   **`WebSocket.init`:** WebSocketオブジェクトを初期化します。`onError`と`onClose`ハンドラを設定します。

次に、サーバー側のNode.jsコードの例を示します。

```javascript
const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', ws => {
  console.log('Client connected');

  ws.on('message', message => {
    console.log(`Received message: ${message}`);
    ws.send(`Server received: ${message}`);
  });

  ws.on('close', () => {
    console.log('Client disconnected');
  });

  ws.on('error', error => {
    console.error('WebSocket error:', error);
  });
});

console.log('WebSocket server started on port 8080');
```

このNode.jsサーバーは、ポート8080でWebSocket接続をリッスンし、クライアントからメッセージを受信すると、受信したメッセージをコンソールに出力し、クライアントに応答を返します。

**6. 応用例とユースケース**

*   **チャットアプリケーション:** ユーザー間でリアルタイムにメッセージを交換できます。
*   **オンラインゲーム:** プレイヤーの位置やアクションをリアルタイムで同期できます。
*   **株価ティッカー:** 株価の変動をリアルタイムで表示できます。
*   **リアルタイムデータ可視化:** センサーデータやログデータをリアルタイムでグラフ化できます。
*   **コラボレーションツール:** ドキュメントの共同編集やホワイトボードアプリケーションをリアルタイムで実現できます。

**7. トラブルシューティング**

*   **接続エラー:** サーバーのアドレスが正しいか、サーバーが起動しているかを確認してください。
*   **メッセージの送受信エラー:** メッセージの形式が正しいか、サーバーとクライアントでデータ形式が一致しているかを確認してください（例えば、JSON形式のメッセージを扱う場合は、`Json.Decode`と`Json.Encode`を適切に使用してください）。
*   **CORSエラー:** ブラウザのセキュリティポリシーにより、異なるドメインからのWebSocket接続がブロックされる場合があります。サーバー側で適切なCORS設定を行う必要があります。
*   **WebSocket接続がすぐに切断される:** サーバー側でタイムアウト設定が短すぎる可能性があります。また、ネットワークの問題が原因である可能性もあります。
*   **Elm側のWebSocketオブジェクトの初期化エラー:** `WebSocket.init` の `onError` と `onClose`ハンドラを正しく設定しているか確認してください。これらのハンドラは、エラー発生時や接続が閉じられたときに実行される関数を指定するために重要です。

### ElmでのWebSocket接続

**1. 概要と重要性**

ElmでWebSocket接続を確立し、データを送受信することは、リアルタイムアプリケーション開発の基盤となります。Elmの型システムと関数型プログラミングのパラダイムは、安全で予測可能なWebSocketアプリケーションを構築するのに適しています。

**2. 特徴と利点**

*   **型安全:** Elmの型システムにより、メッセージの形式やデータ構造に関するエラーをコンパイル時に検出できます。
*   **予測可能性:** 副作用の少ない関数型プログラミングにより、アプリケーションの動作を理解しやすくなります。
*   **信頼性:** Elmのコンパイラは、実行時エラーが発生する可能性のあるコードを排除します。

**3. 事前準備と前提条件**

前述の通り、サーバー側でWebSocketをサポートする仕組みが必要です。ここでは、Node.jsと`ws`モジュールを使用する例で解説します。また、Elmの環境構築が完了している必要があります。

**4. 基本的な使い方**

ElmでWebSocket接続を確立するには、`WebSocket.connect`関数を使用します。この関数は、WebSocketサーバーのアドレス、メッセージの形式、およびメッセージを受信したときに実行される関数を引数として受け取ります。

```elm
WebSocket.connect "ws://localhost:8080/socket" Text MessageReceived model.webSocket
```

メッセージを送信するには、`WebSocket.send`関数を使用します。この関数は、送信するメッセージとWebSocketオブジェクトを引数として受け取ります。

```elm
WebSocket.send model.message model.webSocket
```

**5. 実践的なテクニック**

*   **JSON形式のメッセージの送受信:** JSON形式のメッセージを扱う場合は、`Json.Decode`と`Json.Encode`を使用します。

```elm
import Json.Decode as Decode
import Json.Encode as Encode

-- メッセージの定義
type alias ChatMessage =
    { user : String
    , message : String
    }

-- JSONエンコード関数
encodeChatMessage : ChatMessage -> Encode.Value
encodeChatMessage chatMessage =
    Encode.object
        [ ( "user", Encode.string chatMessage.user )
        , ( "message", Encode.string chatMessage.message )
        ]

-- JSONデコード関数
decodeChatMessage : Decode.Decoder ChatMessage
decodeChatMessage =
    Decode.map2 ChatMessage
        (Decode.field "user" Decode.string)
        (Decode.field "message" Decode.string)

-- メッセージの送信
sendMessage : ChatMessage -> Cmd Msg
sendMessage chatMessage =
    WebSocket.send (Encode.encode 0 (encodeChatMessage chatMessage)) model.webSocket

-- メッセージの受信
update msg model =
    case msg of
        MessageReceived message ->
            case Decode.decodeString decodeChatMessage message of
                Ok chatMessage ->
                    ( { model | receivedMessages = model.receivedMessages ++ [ chatMessage ] }, Cmd.none )

                Err error ->
                    ( model, Debug.todo ("JSON Decode Error: " ++ Debug.toString error) )
        ...
```

*   **エラーハンドリング:** WebSocket接続のエラーを適切に処理するために、`WebSocket.init`の`onError`ハンドラを使用します。

```elm
WebSocket.init { onError = WebSocketError, onClose = WebSocketClosed }
```

*   **再接続:** WebSocket接続が切断された場合に、自動的に再接続を試みるようにします。

```elm
update msg model =
    case msg of
        WebSocketClosed ->
            ( { model | connected = False }, Cmd.after 5000 Connect ) -- 5秒後に再接続を試みる
        ...
```

**6. 応用例とユースケース**

*   **チャットアプリケーション:** ユーザーインターフェースにメッセージを表示し、ユーザーがメッセージを送信できるようにします。
*   **オンラインゲーム:** プレイヤーの位置やアクションをJSON形式でエンコードし、サーバーに送信します。
*   **リアルタイムデータ可視化:** サーバーから受信したデータをグラフに表示します。

**7. トラブルシューティング**

*   **JSONデコードエラー:** JSON形式が正しいか、フィールド名が一致しているかを確認してください。
*   **WebSocket接続が不安定:** ネットワークの問題が原因である可能性があります。また、サーバー側の設定が適切でない可能性もあります。
*   **メッセージが正しく送信されない:** メッセージが正しくエンコードされているか、WebSocket接続が確立されているかを確認してください。

### 状態管理：WebSocket接続の状態とデータの保持

**1. 概要と重要性**

リアルタイムアプリケーションでは、WebSocket接続の状態（接続中、切断済みなど）と送受信するデータを適切に管理することが重要です。Elmのアーキテクチャは、状態管理に優れたフレームワークを提供します。

**2. 特徴と利点**

*   **単一方向データフロー:** アプリケーションの状態は、常に単一の方向（モデル -> ビュー -> メッセージ -> モデル）に流れます。これにより、状態の変化を追跡しやすくなります。
*   **イミュータブルな状態:** Elmの状態は不変です。状態が変更されるたびに、新しい状態が作成されます。これにより、副作用を減らし、アプリケーションの予測可能性を高めます。
*   **明示的な状態遷移:** 状態の変更は、メッセージを通じて明示的に行われます。これにより、状態がどのように変化するかを理解しやすくなります。

**3. 事前準備と前提条件**

Elmのアーキテクチャに関する基本的な知識が必要です。Model, Msg, Update, View の役割を理解しておきましょう。

**4. 基本的な使い方**

アプリケーションの状態は、`Model`として定義します。`Model`には、WebSocket接続の状態（`connected`など）や送受信するデータ（`receivedMessages`など）を含めます。

```elm
type alias Model =
    { connected : Bool
    , message : String
    , receivedMessages : List String
    , webSocket : WebSocket.WebSocket
    }
```

状態を変更するには、`Msg`を定義し、`update`関数で状態を更新します。

```elm
type Msg
    = Connect
    | Disconnect
    | SendMessage
    | MessageReceived String
    | WebSocketError WebSocket.Error
    | WebSocketClosed
    | NewMessage String

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        Connect ->
            ( { model | connected = True }
            , WebSocket.connect "ws://localhost:8080/socket" Text (MessageReceived) model.webSocket
            )

        Disconnect ->
            ( { model | connected = False }
            , WebSocket.disconnect model.webSocket
            )

        SendMessage ->
            ( model, WebSocket.send model.message model.webSocket )

        MessageReceived message ->
            ( { model | receivedMessages = model.receivedMessages ++ [ message ] }, Cmd.none )

        WebSocketError error ->
            ( model, Debug.todo ("WebSocket Error: " ++ Debug.toString error) )

        WebSocketClosed ->
            ( { model | connected = False }, Debug.todo "WebSocket Closed" )

        NewMessage newMessage ->
            ( { model | message = newMessage }, Cmd.none )
```

**5. 実践的なテクニック**

*   **状態のローカルストレージへの保存:** ユーザーがページをリロードした場合でも、状態を維持するために、ローカルストレージに状態を保存することができます。

```elm
import Browser.Storage

-- 初期化時にローカルストレージから状態を読み込む
init : () -> ( Model, Cmd Msg )
init _ =
    ( { connected = False
        , message = ""
        , receivedMessages = []
        , webSocket = WebSocket.init { onError = WebSocketError, onClose = WebSocketClosed }
      }
    , Browser.Storage.get "my-app-state" Decode.string
        |> Cmd.map (maybeLoadState >> LoadedState)
    )

type Msg = LoadedState (Maybe String) | ...

-- ローカルストレージから読み込んだ状態をModelに適用する
maybeLoadState : Maybe String -> Model
maybeLoadState maybeState =
  case maybeState of
    Just stateString ->
      case Json.Decode.decodeString decodeModel stateString of
        Ok model -> model
        Err _ -> defaultModel  -- デコードに失敗した場合のデフォルト値
    Nothing -> defaultModel  -- ストレージにデータがない場合のデフォルト値

decodeModel : Decode.Decoder Model
decodeModel = ... -- Modelをデコードするdecoderを実装

defaultModel : Model
defaultModel = { ... }  -- 初期状態

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
  case msg of
    LoadedState maybeState ->
      ({ maybeLoadState maybeState | webSocket = model.webSocket }, Cmd.none)

    ... other Msg handlers ...

    -- Modelが変更されたときにローカルストレージに状態を保存する
    _ ->
      let
        newModel = ...  -- Modelを更新するロジック
        encodeModel = ... -- Modelをencodeする関数
      in
        ( newModel, Browser.Storage.set "my-app-state" (Json.Encode.encode 0 (encodeModel newModel)) )

```

*   **状態の共有:** 複数のコンポーネント間で状態を共有する必要がある場合は、カスタム型を使用して状態を共有することができます。

```elm
-- カスタム型の定義
type alias SharedState =
    { user : String
    , onlineUsers : List String
    }

-- ModelにSharedStateを含める

    }
```

**6. 応用例とユースケース**

*   **チャットアプリケーション:** ユーザー名、メッセージ、オンラインユーザーのリストなどの状態を管理します。
*   **オンラインゲーム:** プレイヤーの位置、スコア、ゲームの状態などの状態を管理します。
*   **リアルタイムデータ可視化:** グラフのデータ、軸のラベル、凡例などの状態を管理します。

**7. トラブルシューティング**

*   **状態の不整合:** 状態が期待どおりに更新されない場合は、`update`関数が正しく実装されているか、メッセージが正しくディスパッチされているかを確認してください。
*   **状態の競合:** 複数のコンポーネントが同時に状態を変更しようとする場合は、状態の競合が発生する可能性があります。状態の更新をシリアライズするなどの対策を講じる必要があります。
*   **ローカルストレージの問題:** ローカルストレージに状態を保存できない場合は、ブラウザの設定を確認してください。また、ローカルストレージの容量制限を超えている可能性もあります。

### 実装例：チャットアプリケーション

**1. 概要と重要性**

チャットアプリケーションは、リアルタイムアプリケーションの代表的な例です。このセクションでは、ElmとWebSocketを使用して、基本的なチャットアプリケーションを構築する方法について解説します。

**2. 特徴と利点**

*   **リアルタイム性:** ユーザーが送信したメッセージは、他のユーザーに即座に表示されます。
*   **双方向通信:** ユーザーはメッセージを送受信できます。
*   **シンプルさ:** 基本的なチャットアプリケーションは、比較的簡単に実装できます。

**3. 事前準備と前提条件**

前述のWebSocketの知識とElmの環境構築が必要です。また、サーバー側のWebSocketサーバー（Node.jsと`ws`モジュールなど）が稼働している必要があります。

**4. 基本的な使い方**

以下の手順でチャットアプリケーションを構築します。

1.  **Modelの定義:** ユーザー名、メッセージ、受信したメッセージのリストなどの状態を`Model`として定義します。
2.  **Msgの定義:** メッセージの送信、メッセージの受信、ユーザー名の変更などのイベントを`Msg`として定義します。
3.  **update関数の実装:** イベントに応じて`Model`を更新する`update`関数を実装します。
4.  **view関数の実装:** ユーザーインターフェースをレンダリングする`view`関数を実装します。
5.  **WebSocket接続の確立:** `WebSocket.connect`関数を使用して、WebSocketサーバーへの接続を確立します。
6.  **メッセージの送受信:** `WebSocket.send`関数を使用してメッセージを送信し、`WebSocket.receive`関数を使用してメッセージを受信します。

**5. 実践的なテクニック**

以下に、チャットアプリケーションの基本的なコード例を示します。

```elm
import Browser
import Html exposing (Html, button, div, input, text)
import Html.Events exposing (onClick, onInput)
import Json.Decode as Decode
import Json.Encode as Encode
import WebSocket exposing (Error)

main : Program () Model Msg
main =
    Browser.element
        { init = init
        , view = view
        , update = update
        , subscriptions = subscriptions
        }


-- MODEL

type alias Model =
    { username : String
    , message : String
    , messages : List { user : String, content : String }
    , connected : Bool
    , webSocket : WebSocket.WebSocket
    }


init : () -> ( Model, Cmd Msg )
init _ =
    ( { username = ""
        , message = ""
        , messages = []
        , connected = False
        , webSocket = WebSocket.init { onError = websocketError, onClose = websocketClosed }
      }
    , Cmd.none
    )


-- MESSAGES

type Msg
    = Connect
    | Disconnect
    | SendMessage
    | ReceivedMessage String
    | UsernameChanged String
    | MessageChanged String
    | websocketError Error
    | websocketClosed


-- UPDATE

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        Connect ->
            ( { model | connected = True }, WebSocket.connect "ws://localhost:8080" Text ReceivedMessage model.webSocket )

        Disconnect ->
            ( { model | connected = False }, WebSocket.disconnect model.webSocket )

        SendMessage ->
            let
                newMessage =
                    Encode.object
                        [ ( "username", Encode.string model.username )
                        , ( "content", Encode.string model.message )
                        ]
            in
            ( model, WebSocket.send (Encode.encode 0 newMessage) model.webSocket )

        ReceivedMessage data ->
            case Decode.decodeString messageDecoder data of
                Ok msg ->
                    ( { model | messages = model.messages ++ [ msg ] }, Cmd.none )

                Err _ ->
                    ( model, Debug.log "Error decoding message" Cmd.none )

        UsernameChanged username ->
            ( { model | username = username }, Cmd.none )

        MessageChanged message ->
            ( { model | message = message }, Cmd.none )

        websocketError error ->
            (model, Debug.log ("WebSocket Error: " ++ (Debug.toString error)) Cmd.none)

        websocketClosed ->
            (model, Debug.log "WebSocket Closed" Cmd.none)



-- SUBSCRIPTIONS

subscriptions : Model -> Sub Msg
subscriptions _ =
    Sub.none


-- VIEW

view : Model -> Html Msg
view model =
    div []
        [ div [] [ text ("Username: " ++ model.username) ]
        , input [ Html.Attributes.type_ "text", Html.Attributes.placeholder "Enter username", onInput UsernameChanged ] []
        , div [] [ text ("Message: " ++ model.message) ]
        , input [ Html.Attributes.type_ "text", Html.Attributes.placeholder "Enter message", onInput MessageChanged ] []
        , button [ onClick SendMessage, disabled (not model.connected) ] [ text "Send" ]
        , div [] (List.map viewMessage model.messages)
        , if model.connected then
            button [ onClick Disconnect ] [ text "Disconnect" ]

          else
            button [ onClick Connect ] [ text "Connect" ]
        ]


viewMessage : { user : String, content : String } -> Html msg
viewMessage msg =
    div [] [ text (msg.user ++ ": " ++ msg.content) ]


-- JSON DECODING

messageDecoder : Decode.Decoder { user : String, content : String }
messageDecoder =
    Decode.map2 (\user content -> { user = user, content = content })
        (Decode.field "username" Decode.string)
        (Decode.field "content" Decode.string)
```

*   **ユーザーインターフェースの改善:** CSSを使用してユーザーインターフェースを改善し、より使いやすいチャットアプリケーションにします。
*   **メッセージの永続化:** データベースにメッセージを保存し、過去のメッセージを閲覧できるようにします。
*   **認証:** ユーザー認証を実装し、不正なアクセスを防ぎます。

**7. トラブルシューティング**

*   **メッセージが送信されない:** WebSocket接続が確立されているか、メッセージが正しくエンコードされているかを確認してください。
*   **メッセージが表示されない:** メッセージが正しく受信されているか、ユーザーインターフェースが正しく更新されているかを確認してください。
*   **ユーザー名の競合:** 複数のユーザーが同じユーザー名を使用している場合は、ユーザー名の一意性を保証する仕組みを実装する必要があります。
