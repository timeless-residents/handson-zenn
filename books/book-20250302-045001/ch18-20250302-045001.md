## 18. Elmとサーバーサイド連携：API設計と認証

### ElmからAPIを呼び出す

#### 概要と重要性

Elmアプリケーションを構築する上で、サーバーサイドのAPIとの連携はほぼ必須と言えるでしょう。データの取得、更新、認証など、フロントエンドだけでは実現できない機能をAPIを通じて実現します。このセクションでは、Elmから安全かつ効率的にAPIを呼び出す方法について解説します。

#### 特徴と利点

*   **型安全性**: Elmは型システムが非常に強力であるため、APIからのレスポンスをデコードする際に型エラーをコンパイル時に検出できます。これにより、ランタイムエラーを大幅に削減できます。
*   **予測可能性**: Elmアーキテクチャに沿ったAPI呼び出しを行うことで、状態管理が容易になり、アプリケーションの振る舞いを予測しやすくなります。
*   **保守性**: 明確なデータフローと型定義により、APIの変更に対する耐性が高く、コードの保守が容易になります。

#### 事前準備と前提条件

*   Elmプロジェクトがセットアップ済みであること ( `elm init` )
*   `elm-http` パッケージがインストール済みであること ( `elm install elm/http` )
*   JSONデータを返すAPIエンドポイントが利用可能であること

#### 基本的な使い方

1.  **HTTPリクエストの実装**:  `elm-http` パッケージを使って、HTTPリクエストを送信します。まずは、GETリクエストを送信する基本的な例を見てみましょう。

```elm
import Http
import Json.Decode as Decode

type alias User =
    { id : Int
    , name : String
    , email : String
    }

-- JSONデコーダーの定義
userDecoder : Decode.Decoder User
userDecoder =
    Decode.map3 User
        (Decode.field "id" Decode.int)
        (Decode.field "name" Decode.string)
        (Decode.field "email" Decode.string)


-- HTTPリクエストを送信する関数
fetchUser : String -> Cmd Msg
fetchUser url =
    Http.get
        { url = url
        , expect = Http.expectJson GotUser userDecoder
        }


-- メッセージ型
type Msg
    = FetchUser String
    | GotUser (Result Http.Error User)

-- Update関数
update msg model =
    case msg of
        FetchUser url ->
            ( model, fetchUser url )

        GotUser (Ok user) ->
            ( { model | user = Just user }, Cmd.none )

        GotUser (Err error) ->
            ( { model | error = Just error }, Cmd.none )


-- 初期モデル (userは最初はnull)
type alias Model = { user : Maybe User, error : Maybe Http.Error }
init : (Model, Cmd Msg)
init = ({user = Nothing, error = Nothing}, Cmd.none)


-- 簡単なView関数
view model =
    case model.user of
      Just user ->
          text ("User Name: " ++ user.name)
      Nothing ->
          text "Loading..."
```

この例では、`fetchUser` 関数がHTTP GETリクエストを送信し、`userDecoder` を使ってレスポンスを `User` 型にデコードします。`GotUser` メッセージは、成功または失敗の結果を扱います。

2.  **JSONデコード**:  APIからのレスポンスはJSON形式であることが一般的です。Elmでは、`Json.Decode` モジュールを使ってJSONデータをElmの型にデコードします。

   上記の例では、`userDecoder` がJSONデータを `User` 型にデコードする役割を果たしています。`Decode.field` 関数を使って、JSONオブジェクトの各フィールドを抽出します。

#### 実践的なテクニック

*   **カスタムデコーダー**:  複雑なJSON構造を扱う場合、カスタムデコーダーを作成すると便利です。例えば、日付文字列を `Posix` 型に変換するデコーダーを作成できます。

```elm
import Json.Decode as Decode
import Time

-- 日付文字列をPosix型に変換するデコーダー
dateDecoder : Decode.Decoder Time.Posix
dateDecoder =
    Decode.string
        |> Decode.andThen
            (\dateString ->
                case Time.parse dateString of
                    Ok posix ->
                        Decode.succeed posix

                    Err _ ->
                        Decode.fail "Invalid date format"
            )
```

*   **エラーハンドリング**:  APIリクエストが失敗した場合の処理を適切に行うことが重要です。`Http.expectJson` 関数は、`Result Http.Error a` 型を返します。この型を使って、エラーの種類に応じて適切な処理を行います。

```elm
        GotUser (Err error) ->
            case error of
                Http.BadUrl url ->
                    Debug.log "Bad URL" url
                    (model, Cmd.none)
                Http.Timeout ->
                    Debug.log "Timeout" ""
                    (model, Cmd.none)
                _ ->
                  ({ model | error = Just error }, Cmd.none )
```

*   **リクエストヘッダーの設定**:  APIによっては、リクエストヘッダーを設定する必要がある場合があります。`Http.request` 関数を使うと、リクエストヘッダーを自由に設定できます。

```elm
import Http

-- リクエストヘッダーを設定する例
fetchDataWithHeaders : String -> String -> Cmd Msg
fetchDataWithHeaders url token =
    Http.request
        { method = "GET"
        , headers = [ Http.header "Authorization" ("Bearer " ++ token) ]
        , url = url
        , body = Http.emptyBody
        , expect = Http.expectJson GotData myDecoder
        , timeout = Nothing -- デフォルトのタイムアウトを使用
        }
```

#### 応用例とユースケース

*   **フォームデータの送信**:  `Http.Body.form` 関数を使うと、フォームデータをPOSTリクエストで送信できます。
*   **ファイルのアップロード**:  `Http.Body.bytes` 関数を使うと、ファイルをバイト配列としてPOSTリクエストで送信できます。
*   **WebSocketとの連携**:  `elm-websocket` パッケージを使うと、WebSocketを使ってリアルタイムなデータ通信を実現できます。

#### トラブルシューティング

*   **CORSエラー**:  異なるオリジン間でAPIリクエストを行う場合、CORS (Cross-Origin Resource Sharing) エラーが発生する可能性があります。サーバーサイドで適切なCORS設定を行う必要があります。
*   **JSONデコードエラー**:  JSONデータが予期しない形式である場合、デコードエラーが発生する可能性があります。デコーダーを注意深く設計し、エラーハンドリングを適切に行う必要があります。
*   **ネットワークエラー**:  ネットワーク接続が不安定な場合、APIリクエストが失敗する可能性があります。リトライ処理を実装すると、ユーザーエクスペリエンスを向上させることができます。

このセクションでは、ElmからAPIを呼び出す基本的な方法について解説しました。JSONデコード、エラーハンドリング、リクエストヘッダーの設定など、実践的なテクニックを習得することで、より複雑なAPI連携を実現できます。

### 認証の実装

#### 概要と重要性

Elmアプリケーションをセキュアにするためには、認証の実装が不可欠です。ユーザーの識別、権限の管理、データの保護など、認証はセキュリティの基盤となります。このセクションでは、JWT (JSON Web Token) を使った認証の実装について解説します。

#### 特徴と利点

*   **ステートレス**: JWTはステートレスな認証方式であるため、サーバー側のセッション管理が不要になります。
*   **スケーラビリティ**: サーバー側の負荷が低いため、スケーラビリティに優れています。
*   **相互運用性**: JWTは標準化された形式であるため、様々な言語やプラットフォームで利用できます。

#### 事前準備と前提条件

*   サーバーサイドでJWTを生成・検証できる環境が構築済みであること
*   `elm-http` パッケージがインストール済みであること

#### 基本的な使い方

1.  **JWT (JSON Web Token)の利用**:  JWTは、ユーザーの認証情報を安全に伝達するためのトークンです。ユーザーがログインに成功すると、サーバーはJWTを生成し、クライアントに返します。クライアントは、以降のAPIリクエストでJWTをAuthorizationヘッダーに含めて送信します。

```elm
-- ログイン処理の例
login : String -> String -> Cmd Msg
login username password =
    Http.post
        { url = "/api/login"
        , body = Http.Body.json (Encode.object [ ("username", Encode.string username), ("password", Encode.string password) ])
        , expect = Http.expectJson GotToken tokenDecoder
        }

-- JWTをデコードするデコーダー
tokenDecoder : Decode.Decoder String
tokenDecoder =
    Decode.field "token" Decode.string

-- ログイン成功時のメッセージ
GotToken (Ok token) ->
    -- JWTをlocalStorageに保存
    ( { model | token = Just token }, setLocalStorage "token" token )

-- localStorageに値を設定するJavaScriptコマンド
setLocalStorage : String -> String -> Cmd Msg
setLocalStorage key value =
    Task.perform (\_ -> NoOp) (Platform.Task.succeed (Platform.js "localStorage.setItem('" ++ key ++ "', '" ++ value ++ "')"))

-- localStorageから値を取得するJavaScriptコマンド
getLocalStorage : String -> Cmd Msg
getLocalStorage key =
    Task.attempt GotTokenFromStorage (Platform.Task.succeed (Platform.js "localStorage.getItem('" ++ key ++ "')"))

GotTokenFromStorage (Ok token) ->
    case token of
        Just validToken ->
          ({ model | token = Just validToken }, Cmd.none)
        Nothing ->
          ({ model | token = Nothing }, Cmd.none)
```

2.  **セッション管理**:  Elmアプリケーションでは、JWTをLocalStorageやCookieに保存することでセッションを管理します。LocalStorageは、ブラウザを閉じてもデータが保持されるため、永続的なセッションを実装できます。Cookieは、HTTPリクエストごとに自動的に送信されるため、サーバーサイドでの認証処理を簡素化できます。

```elm
-- APIリクエスト時にJWTをAuthorizationヘッダーに含める
fetchData : String -> Cmd Msg
fetchData url =
    case model.token of
        Just token ->
            Http.get
                { url = url
                , expect = Http.expectJson GotData myDecoder
                , headers = [ Http.header "Authorization" ("Bearer " ++ token) ]
                }

        Nothing ->
            -- JWTがない場合はログインページにリダイレクト
            ( model, Navigation.pushUrl "/login" )
```

#### 実践的なテクニック

*   **リフレッシュトークン**:  JWTの有効期限が切れた場合、リフレッシュトークンを使って新しいJWTを取得することができます。リフレッシュトークンは、有効期限が長く、安全な場所に保存する必要があります。
*   **権限管理**:  JWTにユーザーの権限情報を格納することで、APIへのアクセスを制御することができます。サーバーサイドでJWTを検証する際に、ユーザーの権限を確認し、適切な処理を行います。
*   **セキュアな保存**: JWTは機密情報であるため、LocalStorageに保存する場合は、XSS (Cross-Site Scripting) 攻撃に対する対策が必要です。Cookieに保存する場合は、`HttpOnly` フラグと `Secure` フラグを設定することで、セキュリティを向上させることができます。

#### 応用例とユースケース

*   **シングルサインオン (SSO)**:  JWTを使って、複数のアプリケーション間でシングルサインオンを実現することができます。
*   **APIゲートウェイ**:  APIゲートウェイでJWTを検証することで、バックエンドAPIのセキュリティを強化することができます。
*   **マイクロサービス**:  マイクロサービスアーキテクチャでは、JWTを使ってサービス間の認証を行うことができます。

#### トラブルシューティング

*   **JWTの検証エラー**:  JWTの署名が不正である場合、または有効期限が切れている場合、検証エラーが発生します。サーバーサイドでJWTを検証する際に、エラーハンドリングを適切に行う必要があります。
*   **XSS攻撃**:  LocalStorageに保存されたJWTがXSS攻撃によって盗まれた場合、攻撃者はユーザーのアカウントを乗っ取ることができます。LocalStorageにJWTを保存する場合は、XSS攻撃に対する対策が必要です。
*   **CSRF攻撃**:  Cookieに保存されたJWTがCSRF (Cross-Site Request Forgery) 攻撃によって悪用された場合、攻撃者はユーザーの代わりにAPIリクエストを送信することができます。CookieにJWTを保存する場合は、CSRF対策が必要です。

### サーバーサイドとのデータ整合性

#### 概要と重要性

Elmアプリケーションとサーバーサイドの間でデータ整合性を保つことは、アプリケーションの信頼性を高める上で非常に重要です。データが不整合であると、予期せぬエラーや不具合が発生し、ユーザーエクスペリエンスを損なう可能性があります。このセクションでは、Elmとサーバーサイドの間でデータ整合性を保つための戦略について解説します。

#### 特徴と利点

*   **データの信頼性**: データ整合性が保たれることで、アプリケーションの表示や動作が正確になり、ユーザーは信頼してアプリケーションを利用できます。
*   **エラーの早期発見**: データ不整合が原因のエラーを早期に発見し、修正することができます。
*   **開発効率の向上**: データ整合性が保たれていることで、開発者は安心してコードを記述でき、開発効率が向上します。

#### 事前準備と前提条件

*   ElmアプリケーションとサーバーサイドのAPIが連携していること
*   データの整合性を検証するためのテストが実装されていること

#### 基本的な使い方

1.  **型定義の一致**: Elmアプリケーションとサーバーサイドで、データの型定義を一致させることが最も重要です。APIのレスポンスをデコードする際に、型エラーが発生しないように、型定義を慎重に設計する必要があります。

```elm
-- Elm側の型定義
type alias Product =
    { id : Int
    , name : String
    , price : Float
    }

-- サーバーサイドの型定義 (例: TypeScript)
interface Product {
  id: number;
  name: string;
  price: number;
}
```

2.  **データ検証**: APIから取得したデータをElmアプリケーションで使用する前に、検証を行うことが重要です。例えば、必須フィールドが欠落していないか、数値が有効な範囲内であるかなどをチェックします。

```elm
-- データ検証の例
validateProduct : Product -> Result String Product
validateProduct product =
    if String.isEmpty product.name then
        Err "Product name cannot be empty"

    else if product.price <= 0 then
        Err "Product price must be greater than 0"

    else
        Ok product
```

3.  **エラーハンドリング**: データ検証でエラーが発生した場合、適切にエラーハンドリングを行う必要があります。エラーメッセージを表示したり、エラーログを記録したりすることで、問題の特定と修正を支援します。

```elm
-- エラーハンドリングの例
        GotProduct (Ok product) ->
            case validateProduct product of
                Ok validProduct ->
                    ( { model | product = Just validProduct }, Cmd.none )

                Err error ->
                    ( { model | error = Just error }, Cmd.none )
```

#### 実践的なテクニック

*   **スキーマ駆動開発**: APIのスキーマを定義し、そのスキーマに基づいてElmの型定義とサーバーサイドの型定義を生成することで、型定義の一致を保証することができます。
*   **コントラクトテスト**: Elmアプリケーションとサーバーサイドの間で、APIのコントラクトテストを実施することで、データ整合性を検証することができます。
*   **不変データ**: Elmは不変データ構造を基本としているため、データの変更を追跡しやすく、データ不整合の原因を特定しやすくなります。

#### 応用例とユースケース

*   **eコマースサイト**: 製品情報、価格情報、在庫情報などのデータ整合性を保つことで、正確な情報をユーザーに提供することができます。
*   **金融アプリケーション**: 口座情報、取引履歴などのデータ整合性を保つことで、安全な取引を実現することができます。
*   **医療アプリケーション**: 患者情報、検査結果などのデータ整合性を保つことで、正確な診断と治療を支援することができます。

#### トラブルシューティング

*   **型エラー**: Elmの型定義とサーバーサイドの型定義が一致していない場合、型エラーが発生します。型定義を見直し、一致させる必要があります。
*   **データ検証エラー**: データが検証に失敗した場合、データの内容を確認し、修正する必要があります。
*   **APIの変更**: APIの仕様が変更された場合、Elmアプリケーションのコードを修正する必要があります。APIの変更に追従できるように、コードをモジュール化し、テストを充実させておくことが重要です。

### 実装例：認証APIと連携するアプリケーション

ここでは、認証APIと連携する簡単なTodoリストアプリケーションのElm実装例を紹介します。

#### 概要

このアプリケーションは、ユーザーがログインし、Todoリストを表示、追加、削除できる機能を備えています。JWT認証を使用し、APIとの通信には`elm-http`を使用します。

#### モデル

```elm
type alias Model =
    { isLoggedIn : Bool
    , token : Maybe String
    , todos : List Todo
    , newTodoText : String
    , error : Maybe String
    }

type alias Todo =
    { id : Int
    , text : String
    , completed : Bool
    }
```

#### メッセージ

```elm
type Msg
    = Login String String
    | LoginResult (Result Http.Error String)  -- サーバーからJWTを受け取る
    | Logout
    | FetchTodos
    | TodosResult (Result Http.Error (List Todo))
    | AddTodo
    | NewTodoTextChanged String
    | DeleteTodo Int
    | ToggleTodo Int
```

#### Update関数

```elm
update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        Login username password ->
            ( model, login username password )

        LoginResult (Ok token) ->
            ( { model | isLoggedIn = True, token = Just token, error = Nothing }, fetchTodos token)

        LoginResult (Err err) ->
            ( { model | isLoggedIn = False, token = Nothing, error = Just (toString err) }, Cmd.none )

        Logout ->
            ( { model | isLoggedIn = False, token = Nothing, todos = [], error = Nothing }, Cmd.none )

        FetchTodos ->
            case model.token of
                Just token ->
                    ( model, fetchTodos token )
                Nothing ->
                    ( model, Cmd.none ) -- ログインしていない場合

        TodosResult (Ok todos) ->
            ( { model | todos = todos, error = Nothing }, Cmd.none )

        TodosResult (Err err) ->
            ( { model | error = Just (toString err) }, Cmd.none )

        AddTodo ->
            case model.token of
                Just token ->
                    ( { model, newTodoText = "" }, addTodo token model.newTodoText )
                Nothing ->
                    ( model, Cmd.none )

        NewTodoTextChanged text ->
            ( { model | newTodoText = text }, Cmd.none )

        DeleteTodo id ->
            case model.token of
                Just token ->
                    ( model, deleteTodo token id )
                Nothing ->
                    ( model, Cmd.none )

        ToggleTodo id ->
            case model.token of
                Just token ->
                    ( model, toggleTodo token id )
                Nothing ->
                    ( model, Cmd.none )
```

#### API関数

```elm
login : String -> String -> Cmd Msg
login username password =
    Http.post
        { url = "/api/login"
        , body = Http.Body.json (Encode.object [ ("username", Encode.string username), ("password", Encode.string password) ])
        , expect = Http.expectStringResponse LoginResult
        }

fetchTodos : String -> Cmd Msg
fetchTodos token =
    Http.get
        { url = "/api/todos"
        , expect = Http.expectJson TodosResult (Decode.list todoDecoder)
        , headers = [Http.header "Authorization" ("Bearer " ++ token)]
        }

addTodo : String -> String -> Cmd Msg
addTodo token text =
  Http.post
    { url = "/api/todos"
    , headers = [Http.header "Authorization" ("Bearer " ++ token)]
    , body = Http.Body.json (Encode.object [("text", Encode.string text)])
    , expect = Http.expectWhatever (\_ -> FetchTodos)
    }

deleteTodo : String -> Int -> Cmd Msg
deleteTodo token id =
  Http.delete
    { url = "/api/todos/" ++ String.fromInt id
    , headers = [Http.header "Authorization" ("Bearer " ++ token)]
    , expect = Http.expectWhatever (\_ -> FetchTodos)
    }

toggleTodo : String -> Int -> Cmd Msg
toggleTodo token id =
  Http.put
    { url = "/api/todos/" ++ String.fromInt id ++ "/toggle"
    , headers = [Http.header "Authorization" ("Bearer " ++ token)]
    , body = Http.emptyBody
    , expect = Http.expectWhatever (\_ -> FetchTodos)
    }

todoDecoder : Decode.Decoder Todo
todoDecoder =
  Decode.map3 Todo
    (Decode.field "id" Decode.int)
    (Decode.field "text" Decode.string)
    (Decode.field "completed" Decode.bool)

```

#### View関数

```elm
view : Model -> Html Msg
view model =
    div []
        [ if model.isLoggedIn then
            div []
                [ button [ onClick Logout ] [ text "Logout" ]
                , h2 [] [ text "Todos" ]
                , input [ type_ "text", placeholder "New todo", value model.newTodoText, onInput NewTodoTextChanged ] []
                , button [ onClick AddTodo ] [ text "Add Todo" ]
                , ul [] (List.map viewTodo model.todos)
                , case model.error of
                    Just err ->
                        div [] [ text ("Error: " ++ err) ]
                    Nothing ->
                        text ""
                ]
          else
            viewLogin model
        ]


viewLogin : Model -> Html Msg
viewLogin model =
    div []
        [ input [ type_ "text", placeholder "Username", id "username"] []
        , input [ type_ "password", placeholder "Password", id = "password"] []
        , button [onClick (Login (getInputValue "username") (getInputValue "password")) ] [ text "Login" ]
        ]


viewTodo : Todo -> Html Msg
viewTodo todo =
    li []
        [ span [] [ text todo.text ]
        , button [ onClick (DeleteTodo todo.id) ] [ text "Delete" ]
        , button [ onClick (ToggleTodo todo.id) ] [ text (if todo.completed then "Uncomplete" else "Complete") ]
        ]

-- JavaScriptでinputのvalueを取得
getInputValue : String -> String
getInputValue id =
  Platform.js ("document.getElementById('" ++ id ++ "').value")

```

#### 初期化

```elm
init : ( Model, Cmd Msg )
init =
    ( { isLoggedIn = False
      , token = Nothing
      , todos = []
      , newTodoText = ""
      , error = Nothing
      }
    , Cmd.none
    )
```

#### 実行

```elm
main : Program Never Model Msg
main =
    Platform.worker
        { init = init
        , update = update
        , view = view
        , subscriptions = always Sub.none
        }

```

#### 解説

1.  **モデル**: アプリケーションの状態を保持します。ログイン状態、JWT、Todoリスト、エラーメッセージなどを管理します。
2.  **メッセージ**: アプリケーションで発生するイベントを定義します。ログイン、ログアウト、Todoの追加など、様々なイベントを表現します。
3.  **Update関数**: メッセージを受け取り、モデルを更新します。API呼び出しもここで行います。
4.  **API関数**: `elm-http`を使ってAPIを呼び出します。リクエストヘッダーにJWTを含め、認証されたAPIにアクセスします。
5.  **View関数**: モデルの状態に基づいてUIをレンダリングします。

#### 注意点

*   この例は、あくまで簡単な実装例です。実際のアプリケーションでは、エラーハンドリング、入力検証、UIの改善など、より多くの考慮事項があります。
*   セキュリティ上の理由から、JWTはLocalStorageではなく、より安全な場所に保存することを推奨します。
