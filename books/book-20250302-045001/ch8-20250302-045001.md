## 8. Elmにおける非同期処理：TaskとCmd

Elmで複雑なアプリケーションを構築する上で、非同期処理の扱いは避けて通れません。なぜなら、Webアプリケーションは外部のAPIからデータを取得したり、ユーザーの入力を監視したりといった、時間のかかる処理を頻繁に行う必要があるからです。 Elmでは、これらの非同期処理を安全かつ効率的に行うために、**Task**と**Cmd**という強力な型を提供しています。

この章では、TaskとCmdの概念を深く理解し、実際のアプリケーションで非同期処理を効果的に活用するための知識とスキルを身につけることを目指します。 HTTPリクエストからサブスクリプションまで、具体的なコード例を交えながら、Elmにおける非同期処理のすべてを解説します。

### Taskとは何か？

**Task**は、副作用を伴う可能性のある処理を表現するための型です。副作用とは、関数の実行結果が関数の引数だけで決まらず、外部の状態に依存したり、外部の状態を変更したりすることを指します。例えば、HTTPリクエスト、localStorageへのアクセス、乱数の生成などは、すべて副作用を伴う処理です。

#### 概要と重要性

Taskは、Elmの純粋関数型の性質を維持しながら、副作用を安全に扱うための重要な仕組みです。 Taskを使うことで、副作用を伴う処理を明確に分離し、コードの可読性、保守性、テスト容易性を向上させることができます。

#### 特徴と利点

*   **純粋性:** Task自体は純粋な値であり、副作用を実行しません。副作用は、TaskがElmランタイムによって実行される際に発生します。
*   **安全性:** Taskは、エラーハンドリングを強制します。 Taskが失敗した場合、エラーを適切に処理する必要があります。
*   **合成可能性:** Taskは、`andThen`や`onError`などの関数を使って、複雑な処理を組み立てることができます。

#### 事前準備と前提条件

Taskを理解するためには、Elmの基本的な構文（型、関数、モジュールなど）を理解している必要があります。また、JavaScriptにおけるPromiseや、他の言語における非同期処理の概念を知っていると、より理解が深まるでしょう。

#### 基本的な使い方

Taskの基本的な型定義は以下のようになります。

```elm
type Task error value
```

ここで、`error`はTaskが失敗した場合のエラーの型、`value`はTaskが成功した場合の値の型を表します。

最も基本的なTaskの例は、成功するTaskと失敗するTaskです。

```elm
import Task

-- 常に成功するTask
alwaysSucceed : Task Never Int
alwaysSucceed =
    Task.succeed 123

-- 常に失敗するTask
alwaysFail : Task String Never
alwaysFail =
    Task.fail "Something went wrong!"
```

`Task.succeed`関数は、指定された値で成功するTaskを生成します。 `Task.fail`関数は、指定されたエラーで失敗するTaskを生成します。 `Never`型は、決して起こりえない型を表します。

#### 実践的なテクニック

Taskを実際に使用する際には、`andThen`や`onError`などの関数を使って、Taskを合成することが重要です。

*   **`andThen`**: Taskが成功した場合に、その結果を別のTaskに渡すことができます。

```elm
import Task

stringToInt : String -> Task String Int
stringToInt str =
    case String.toInt str of
        Just num ->
            Task.succeed num

        Nothing ->
            Task.fail "Invalid integer string"

processString : String -> Task String Int
processString str =
    stringToInt str
        `Task.andThen`
            (\num ->
                Task.succeed (num * 2)
            )
```

*   **`onError`**: Taskが失敗した場合に、エラーを処理し、別のTaskにフォールバックすることができます。

```elm
import Task

safeStringToInt : String -> Task String Int
safeStringToInt str =
    stringToInt str
        `Task.onError`
            (\err ->
                Task.succeed 0
            )
```

#### 応用例とユースケース

Taskは、ファイルへの書き込み、乱数の生成、時間の遅延など、様々な副作用を伴う処理を表現するために使用できます。

```elm
import Task

-- 指定された時間だけ遅延するTask
delay : Int -> Task Never ()
delay milliseconds =
    Task.perform identity (Task.spawn (Task.delay milliseconds))

-- ランダムな整数を生成するTask
generateRandomInt : Task Never Int
generateRandomInt =
    Task.perform identity Task.generate
```

#### トラブルシューティング

*   **Taskが実行されない**: Taskは、Cmdを使ってElmランタイムに命令を送ることで初めて実行されます。 Taskを作成しただけでは、何も起こりません。
*   **型エラー**: Taskの型が期待される型と一致しない場合、コンパイルエラーが発生します。 Taskを合成する際には、型をよく確認してください。

#### まとめと次のステップ

Taskは、副作用を安全かつ効率的に扱うための強力なツールです。 `andThen`や`onError`などの関数を使って、複雑な処理を組み立てることができます。 次のステップとして、`Http`モジュールを使って、外部APIからデータを取得する方法を学びましょう。

### Cmdとは何か？

**Cmd**は、Elmランタイムに命令を伝えるための型です。 Taskの実行、サブスクリプションの開始、ブラウザへのメッセージ送信など、アプリケーションの状態を変更する処理は、すべてCmdを通して行われます。

#### 概要と重要性

Cmdは、Elmアーキテクチャの中核となる概念です。 Elmアプリケーションは、ユーザーの入力や外部からのイベントを受け取り、Cmdを生成し、それに基づいて状態を更新します。 Cmdを使うことで、アプリケーションの状態管理をシンプルかつ予測可能にすることができます。

#### 特徴と利点

*   **命令型:** Cmdは、Elmランタイムに実行すべき命令を具体的に指定します。
*   **副作用:** Cmdは、アプリケーションの状態を変更する副作用を伴います。
*   **制御:** Cmdは、どの副作用をいつ実行するかを完全に制御することができます。

#### 事前準備と前提条件

Cmdを理解するためには、Elmアーキテクチャの基本的な概念（Model, Update, View）を理解している必要があります。特に、`Update`関数がどのようにメッセージを受け取り、Modelを更新し、Cmdを返すかを理解することが重要です。

#### 基本的な使い方

Cmdの基本的な型定義は以下のようになります。

```elm
type Cmd msg
```

ここで、`msg`はCmdが実行された結果として生成されるメッセージの型を表します。

最も基本的なCmdの例は、何も実行しないCmdです。

```elm
import Cmd

-- 何も実行しないCmd
noOp : Cmd msg
noOp =
    Cmd.none
```

#### 実践的なテクニック

Cmdを実際に使用する際には、`Task.perform`や`Sub.map`などの関数を使って、TaskやサブスクリプションをCmdに変換することが重要です。

*   **`Task.perform`**: Taskを実行し、その結果をメッセージとして送信します。

```elm
import Task
import Cmd
import Html exposing (text)
import Html.App as App

type Msg
    = DataLoaded String
    | LoadData

init : () -> ( String, Cmd Msg )
init _ =
    ( "Loading...", Cmd.none )

update : Msg -> String -> ( String, Cmd Msg )
update msg model =
    case msg of
        DataLoaded data ->
            ( data, Cmd.none )

        LoadData ->
            ( model, Task.perform DataLoaded (Task.succeed "Data loaded successfully!") )

view : String -> Html Msg
view model =
    text model

main : Program Never String Msg
main =
    App.element
        { init = init ()
        , update = update
        , view = view
        , subscriptions = \_ -> Sub.none
        }
```

*   **`Sub.map`**: サブスクリプションからのメッセージを別のメッセージに変換します。

```elm
import Browser
import Html exposing (text)
import Html.App as App
import Time

type Msg
    = TimeUpdated Time.Posix
    | Tick Time.Posix

init : () -> ( String, Cmd Msg )
init _ =
    ( "Loading...", Cmd.none )

update : Msg -> String -> ( String, Cmd Msg )
update msg model =
    case msg of
        TimeUpdated time ->
            ( String.fromFloat (Time.posixToMillis time), Cmd.none )
        
        Tick time -> (model, Cmd.none)

view : String -> Html Msg
view model =
    text model

subscriptions : String -> Sub Msg
subscriptions model =
    Time.every 1000 Tick |> Sub.map TimeUpdated


main : Program Never String Msg
main =
    App.element
        { init = init ()
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

#### 応用例とユースケース

Cmdは、HTTPリクエストの送信、localStorageへのアクセス、カスタムイベントのディスパッチなど、様々な副作用を伴う処理を実行するために使用できます。

```elm
import Http
import Json.Decode as Decode
import Cmd

-- HTTPリクエストを送信し、JSONデータをデコードするCmd
fetchData : String -> (Result Http.Error a -> msg) -> Cmd msg
fetchData url toMsg =
    Http.get
        { url = url
        , expect = Http.expectJson toMsg (Decode.string)
        }
```

#### トラブルシューティング

*   **Cmdが実行されない**: Cmdは、`Update`関数から返される必要があります。 `Update`関数から返されないCmdは、実行されません。
*   **無限ループ**: `Update`関数がCmdを返し、そのCmdが再び`Update`関数を呼び出すような場合、無限ループが発生する可能性があります。

#### まとめと次のステップ

Cmdは、Elmランタイムに命令を伝えるための重要なツールです。 TaskやサブスクリプションをCmdに変換することで、アプリケーションの状態を安全かつ効率的に管理することができます。 次のステップとして、`Http`モジュールを使って、実際に外部APIからデータを取得し、表示するアプリケーションを作成してみましょう。

### HTTPリクエストの実装

ElmでHTTPリクエストを送信するには、`Http`モジュールを使用します。 `Http`モジュールは、GET、POST、PUT、DELETEなどのHTTPメソッドをサポートしており、JSONデータのデコードも簡単に行うことができます。

#### 概要と重要性

Webアプリケーションは、外部APIからデータを取得したり、サーバーにデータを送信したりするために、HTTPリクエストを頻繁に使用します。 `Http`モジュールは、ElmでHTTPリクエストを安全かつ効率的に行うための標準的な方法を提供します。

#### 特徴と利点

*   **型安全性:** `Http`モジュールは、HTTPリクエストとレスポンスの型を厳密に管理します。
*   **エラーハンドリング:** `Http`モジュールは、ネットワークエラーやサーバーエラーなどのエラーを適切に処理します。
*   **JSONデコード:** `Http`モジュールは、JSONデータを簡単にデコードすることができます。

#### 事前準備と前提条件

`Http`モジュールを使用するためには、Elmの基本的な構文（型、関数、モジュールなど）を理解している必要があります。また、HTTPプロトコルやJSONデータの形式についても理解していると、よりスムーズに学習を進めることができます。

#### 基本的な使い方

`Http`モジュールを使ってHTTPリクエストを送信するには、以下の手順に従います。

1.  `Http.get`、`Http.post`、`Http.put`、`Http.delete`などの関数を使って、リクエストを作成します。
2.  `Http.expectJson`関数を使って、レスポンスをJSONデータとしてデコードします。
3.  `Task.perform`関数を使って、HTTPリクエストを実行し、その結果をメッセージとして送信します。

```elm
import Http
import Json.Decode as Decode
import Task
import Cmd

-- APIからユーザーデータを取得するTask
fetchUserData : String -> Task Http.Error User
fetchUserData url =
    Http.get
        { url = url
        , expect = Http.expectJson decodeUser
        }

-- ユーザーデータのデコーダー
decodeUser : Decode.Decoder User
decodeUser =
    Decode.map2 User
        (Decode.field "name" Decode.string)
        (Decode.field "email" Decode.string)

-- ユーザーデータの型
type alias User =
    { name : String
    , email : String
    }

-- HTTPリクエストを実行し、ユーザーデータをロードするCmd
loadUserData : String -> (Result Http.Error User -> msg) -> Cmd msg
loadUserData url toMsg =
    Task.perform toMsg (fetchUserData url)
```

#### 実践的なテクニック

*   **カスタムヘッダーの追加:** `Http.setHeader`関数を使って、リクエストにカスタムヘッダーを追加することができます。

```elm
import Http

-- カスタムヘッダーを追加したHTTPリクエスト
fetchDataWithHeader : String -> String -> String -> Task Http.Error String
fetchDataWithHeader url headerName headerValue =
    Http.get
        { url = url
        , expect = Http.expectString
        , headers = [ Http.header headerName headerValue ]
        }
```

*   **POSTリクエストの送信:** `Http.post`関数を使って、POSTリクエストを送信することができます。 `Http.body`関数を使って、リクエストボディを構築することができます。

```elm
import Http
import Json.Encode as Encode

-- POSTリクエストを送信するTask
postData : String -> String -> Task Http.Error String
postData url data =
    Http.post
        { url = url
        , body = Http.jsonBody (Encode.string data)
        , expect = Http.expectString
        }
```

#### 応用例とユースケース

`Http`モジュールは、様々なWeb APIと連携するために使用できます。

*   **REST APIとの連携:** REST APIからデータを取得したり、サーバーにデータを送信したりすることができます。
*   **GraphQL APIとの連携:** GraphQL APIに対してクエリを実行することができます。
*   **OAuth認証:** OAuth認証に必要なHTTPリクエストを送信することができます。

#### トラブルシューティング

*   **ネットワークエラー**: ネットワークに接続されていない場合、またはサーバーがダウンしている場合、HTTPリクエストは失敗します。 エラーメッセージを適切に処理し、ユーザーに適切なフィードバックを提供する必要があります。
*   **CORSエラー**: 異なるドメイン間でHTTPリクエストを送信する場合、CORS（Cross-Origin Resource Sharing）エラーが発生する可能性があります。 サーバー側でCORSの設定を適切に行う必要があります。
*   **JSONデコードエラー**: レスポンスが期待されるJSON形式ではない場合、JSONデコードエラーが発生します。 デコーダーを修正するか、サーバー側のAPIを修正する必要があります。

#### まとめと次のステップ

`Http`モジュールは、ElmでHTTPリクエストを送信するための強力なツールです。 `Http.get`、`Http.post`などの関数を使って、様々なHTTPメソッドをサポートしています。 次のステップとして、実際に外部APIからデータを取得し、表示するアプリケーションを作成してみましょう。

### サブスクリプション：イベントハンドリング

Elmにおける**サブスクリプション**は、外部からのイベント（タイマー、キーボード入力、マウスイベント、カスタムイベントなど）を監視し、アプリケーションの状態を更新するための仕組みです。サブスクリプションを使うことで、リアクティブなアプリケーションを簡単に構築することができます。

#### 概要と重要性

Webアプリケーションは、ユーザーの入力や外部からのイベントに反応する必要があります。 サブスクリプションは、Elmでこれらのイベントを安全かつ効率的に処理するための標準的な方法を提供します。

#### 特徴と利点

*   **宣言的:** サブスクリプションは、どのイベントを監視するかを宣言的に記述します。
*   **リアクティブ:** サブスクリプションは、イベントが発生したときに自動的にメッセージを生成します。
*   **型安全性:** サブスクリプションは、イベントの型を厳密に管理します。

#### 事前準備と前提条件

サブスクリプションを理解するためには、Elmアーキテクチャの基本的な概念（Model, Update, View）を理解している必要があります。特に、`subscriptions`関数がどのようにイベントを監視し、メッセージを生成するかを理解することが重要です。

#### 基本的な使い方

サブスクリプションは、`subscriptions`関数で定義します。 `subscriptions`関数は、Modelを受け取り、`Sub msg`型の値を返します。

```elm
import Browser
import Html exposing (text)
import Html.App as App
import Time

type Msg
    = TimeUpdated Time.Posix
    | Tick Time.Posix

init : () -> ( String, Cmd Msg )
init _ =
    ( "Loading...", Cmd.none )

update : Msg -> String -> ( String, Cmd Msg )
update msg model =
    case msg of
        TimeUpdated time ->
            ( String.fromFloat (Time.posixToMillis time), Cmd.none )
        
        Tick time -> (model, Cmd.none)

view : String -> Html Msg
view model =
    text model

subscriptions : String -> Sub Msg
subscriptions model =
    Time.every 1000 Tick |> Sub.map TimeUpdated


main : Program Never String Msg
main =
    App.element
        { init = init ()
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

#### 実践的なテクニック

*   **キーボード入力の監視:** `Keyboard.downs`サブスクリプションを使って、キーボード入力を監視することができます。

```elm
import Browser
import Html exposing (text)
import Html.App as App
import Keyboard

type Msg
    = KeyPressed String

init : () -> ( String, Cmd Msg )
init _ =
    ( "", Cmd.none )

update : Msg -> String -> ( String, Cmd Msg )
update msg model =
    case msg of
        KeyPressed key ->
            ( key, Cmd.none )

view : String -> Html Msg
view model =
    text model

subscriptions : String -> Sub Msg
subscriptions model =
    Keyboard.downs KeyPressed


main : Program Never String Msg
main =
    App.element
        { init = init ()
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

*   **マウスイベントの監視:** `Mouse.clicks`サブスクリプションを使って、マウスイベントを監視することができます。

#### 応用例とユースケース

サブスクリプションは、様々なリアルタイムアプリケーションを構築するために使用できます。

*   **チャットアプリケーション:** リアルタイムでメッセージを受信するチャットアプリケーションを構築することができます。
*   **ゲーム:** ユーザーの入力をリアルタイムで処理するゲームを構築することができます。
*   **ダッシュボード:** リアルタイムでデータを表示するダッシュボードを構築することができます。

#### トラブルシューティング

*   **サブスクリプションが動作しない**: `subscriptions`関数が正しく定義されているか確認してください。
*   **メッセージが生成されない**: イベントが発生しているか確認してください。
*   **不要なサブスクリプション**: 不要なサブスクリプションは、パフォーマンスに影響を与える可能性があります。 不要なサブスクリプションは削除してください。

#### まとめと次のステップ

サブスクリプションは、Elmで外部からのイベントを監視するための強力なツールです。 サブスクリプションを使って、リアクティブなアプリケーションを簡単に構築することができます。 次のステップとして、実際にサブスクリプションを使って、リアルタイムなアプリケーションを作成してみましょう。

### 実装例：外部APIからデータを取得して表示する

これまでの知識を総合して、外部APIからデータを取得し、画面に表示する簡単なアプリケーションを作成してみましょう。 今回は、[https://jsonplaceholder.typicode.com/todos/1](https://jsonplaceholder.typicode.com/todos/1) からToDoアイテムのデータを取得し、そのタイトルを表示します。

```elm
import Browser
import Html exposing (..)
import Html.Attributes exposing (..)
import Html.App as App
import Http
import Json.Decode as Decode
import Task
import Cmd

-- MODEL

type alias Model =
    { title : String
    , loading : Bool
    , error : Maybe String
    }


initialModel : Model
initialModel =
    { title = "Loading..."
    , loading = True
    , error = Nothing
    }


-- MESSAGES

type Msg
    = FetchData
    | DataReceived (Result Http.Error Todo)


-- UPDATE

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        FetchData ->
            ( { model | loading = True, error = Nothing }, fetchData )

        DataReceived (Ok todo) ->
            ( { title = todo.title, loading = False, error = Nothing }, Cmd.none )

        DataReceived (Err err) ->
            ( { model | loading = False, error = Just (Http.errorToString err) }, Cmd.none )


fetchData : Cmd Msg
fetchData =
    Http.get
        { url = "https://jsonplaceholder.typicode.com/todos/1"
        , expect = Http.expectJson DataReceived todoDecoder
        }


-- DECODERS

type alias Todo =
    { userId : Int
    , id : Int
    , title : String
    , completed : Bool
    }


todoDecoder : Decode.Decoder Todo
todoDecoder =
    Decode.map4 Todo
        (Decode.field "userId" Decode.int)
        (Decode.field "id" Decode.int)
        (Decode.field "title" Decode.string)
        (Decode.field "completed" Decode.bool)


-- VIEW

view : Model -> Html Msg
view model =
    div []
        [ h1 [] [ text "Todo Item" ]
        , if model.loading then
            p [] [ text "Loading..." ]
          else
            case model.error of
                Just err ->
                    p [] [ text ("Error: " ++ err) ]

                Nothing ->
                    p [] [ text ("Title: " ++ model.title) ]
        , button [ onClick FetchData ] [ text "Refresh Data" ]
        ]


-- MAIN

main : Program Never Model Msg
main =
    Browser.element
        { init = \_ -> ( initialModel, fetchData )
        , view = view
        , update = update
        , subscriptions = \_ -> Sub.none
        }
```

このコードでは、

1.  `Model`型を定義し、`title`、`loading`、`error`の3つのフィールドを持つようにしました。
2.  `Msg`型を定義し、`FetchData`と`DataReceived`の2つのメッセージを持つようにしました。
3.  `update`関数を定義し、メッセージに応じてModelを更新するようにしました。
4.  `fetchData`関数を定義し、`Http.get`関数を使ってAPIからデータを取得するようにしました。
5.  `todoDecoder`を定義し、JSONデータを`Todo`型にデコードするようにしました。
6.  `view`関数を定義し、Modelに基づいてHTMLを表示するようにしました。

このアプリケーションを実行すると、最初は "Loading..." と表示されます。 外部APIからデータが取得されると、ToDoアイテムのタイトルが表示されます。 "Refresh Data"ボタンをクリックすると、再度APIからデータを取得し、表示を更新します。

この例を通して、TaskとCmdを使って、Elmで非同期処理を安全かつ効率的に行う方法を理解できたと思います。
