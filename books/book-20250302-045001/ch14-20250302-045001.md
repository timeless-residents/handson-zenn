## 14. Elmにおけるフォーム処理：入力検証とエラーハンドリング

### 概要と重要性

ElmでWebアプリケーションを開発する上で、フォーム処理は避けて通れない道です。ユーザーからの入力を受け付け、それを検証し、問題があればエラーを表示する。この一連の流れをスムーズに、そして安全に行うことが、優れたユーザーエクスペリエンスとアプリケーションの信頼性を構築する上で不可欠です。Elmの静的型付けと関数型プログラミングの特性を活かすことで、堅牢で保守性の高いフォーム処理を実現できます。この章では、Elmにおけるフォーム処理の基礎から応用までを、実践的なコード例を交えながら解説します。

### 特徴と利点

Elmでフォーム処理を行う利点は数多くあります。

*   **型安全性:** Elmのコンパイラは、フォームの入力型と処理ロジックの整合性を保証します。これにより、実行時に予期せぬエラーが発生する可能性を大幅に減らすことができます。
*   **宣言的なアプローチ:** Elmでは、フォームの状態を明示的に定義し、入力イベントに対する状態の変化を関数として記述します。これにより、コードの見通しが良く、デバッグも容易になります。
*   **優れたエラーハンドリング:** Elmの`Maybe`型や`Result`型を活用することで、入力検証のエラーを安全かつ効果的に処理できます。エラーメッセージの表示も容易に行えます。
*   **リファクタリングの容易性:** 静的型付けと関数型プログラミングの特性により、フォームの構造や検証ロジックを変更する際に、コンパイラが自動的に変更の影響範囲を検出してくれます。

*   Elmの基本的な構文 (変数定義、関数定義、型定義など)

### フォームの基本構造

#### テキストフィールド、チェックボックス、セレクトボックス

Elmでフォームを構築するには、HTML要素を`elm/html`ライブラリを使って表現します。基本的なフォーム要素であるテキストフィールド、チェックボックス、セレクトボックスの例を見てみましょう。

```elm
import Html exposing (..)
import Html.Attributes exposing (..)
import Html.Events exposing (..)


-- Model
type alias Model =
    { textInputValue : String
    , checkboxValue : Bool
    , selectValue : String
    }


initialModel : Model
initialModel =
    { textInputValue = ""
    , checkboxValue = False
    , selectValue = "option1"
    }


-- Msg
type Msg
    = TextInputChanged String
    | CheckboxChanged Bool
    | SelectChanged String


-- Update
update : Msg -> Model -> Model
update msg model =
    case msg of
        TextInputChanged newText ->
            { model | textInputValue = newText }

        CheckboxChanged newChecked ->
            { model | checkboxValue = newChecked }

        SelectChanged newSelect ->
            { model | selectValue = newSelect }


-- View
view : Model -> Html Msg
view model =
    div []
        [ label [] [ text "テキストフィールド:" ]
        , input [ type_ "text", value model.textInputValue, onInput TextInputChanged ] []
        , br [] []

        , label [] [ text "チェックボックス:" ]
        , input [ type_ "checkbox", checked model.checkboxValue, onClick (CheckboxChanged (not model.checkboxValue)) ] []
        , br [] []

        , label [] [ text "セレクトボックス:" ]
        , select [ onChange SelectChanged ]
            [ option [ value "option1", selected (model.selectValue == "option1") ] [ text "Option 1" ]
            , option [ value "option2", selected (model.selectValue == "option2") ] [ text "Option 2" ]
            , option [ value "option3", selected (model.selectValue == "option3") ] [ text "Option 3" ]
            ]
        ]


main : Program Never Model Msg
main =
    Html.beginnerProgram { model = initialModel, view = view, update = update }
```

このコードは、テキストフィールド、チェックボックス、セレクトボックスを表示する基本的なElmのアプリケーションです。

*   **テキストフィールド:** `input [ type_ "text", value model.textInputValue, onInput TextInputChanged ] []`  `onInput`属性は、テキストフィールドに入力があるたびに`TextInputChanged`メッセージを発行します。
*   **チェックボックス:** `input [ type_ "checkbox", checked model.checkboxValue, onClick (CheckboxChanged (not model.checkboxValue)) ] []`  `onClick`属性は、チェックボックスがクリックされるたびに`CheckboxChanged`メッセージを発行します。
*   **セレクトボックス:** `select [ onChange SelectChanged ] [ ... ]`  `onChange`属性は、セレクトボックスの選択が変更されるたびに`SelectChanged`メッセージを発行します。

それぞれの要素に入力された値は、`Model`に保持され、`update`関数を通じて更新されます。

### 入力値の検証

#### バリデーション関数の定義

フォームの入力値を検証するために、バリデーション関数を定義します。これらの関数は、入力値を受け取り、検証結果を`Result`型で返します。`Result`型は、成功を表す`Ok`と、失敗を表す`Err`の2つのコンストラクタを持ちます。

```elm
-- Result String Int は、成功したらInt型の値を返し、失敗したらString型の値を返すことを表す
validateEmail : String -> Result String String
validateEmail email =
    if String.contains "@" email then
        Ok email
    else
        Err "無効なメールアドレスです。"


validatePassword : String -> Result String String
validatePassword password =
    if String.length password >= 8 then
        Ok password
    else
        Err "パスワードは8文字以上である必要があります。"
```

これらの関数は、メールアドレスの形式とパスワードの長さを検証します。`validateEmail`関数は、メールアドレスに`@`が含まれているかをチェックし、`validatePassword`関数は、パスワードの長さが8文字以上であることをチェックします。

#### エラーメッセージの表示

バリデーション関数の結果に基づいて、エラーメッセージを表示します。`view`関数内で、`Result`型をパターンマッチングして、エラーメッセージを表示するか、成功した値を表示するかを決定します。

```elm
view : Model -> Html Msg
view model =
    div []
        [ label [] [ text "メールアドレス:" ]
        , input [ type_ "text", value model.email, onInput EmailChanged ] []
        , case model.emailError of
            Just error ->
                div [ class "error" ] [ text error ]
            Nothing ->
                text ""
        , br [] []

        , label [] [ text "パスワード:" ]
        , input [ type_ "password", value model.password, onInput PasswordChanged ] []
        , case model.passwordError of
            Just error ->
                div [ class "error" ] [ text error ]
            Nothing ->
                text ""
        ]
```

このコードは、メールアドレスとパスワードのエラーメッセージを表示します。`model.emailError`と`model.passwordError`は、それぞれメールアドレスとパスワードのエラーメッセージを`Maybe String`型で保持します。`Just error`の場合はエラーメッセージを表示し、`Nothing`の場合は何も表示しません。

### フォームの状態管理：入力値とエラーの状態

フォームの状態を管理するために、`Model`に以下の情報を保持します。

*   フォームの入力値 (例: `email : String`, `password : String`)
*   入力値のエラーメッセージ (例: `emailError : Maybe String`, `passwordError : Maybe String`)
*   フォーム全体のバリデーション状態 (例: `formValid : Bool`)

```elm
type alias Model =
    { email : String
    , password : String
    , emailError : Maybe String
    , passwordError : Maybe String
    , formValid : Bool
    }


initialModel : Model
initialModel =
    { email = ""
    , password = ""
    , emailError = Nothing
    , passwordError = Nothing
    , formValid = False
    }
```

`update`関数内で、入力イベントが発生するたびに、入力値を更新し、バリデーション関数を実行し、エラーメッセージを更新します。

```elm
update : Msg -> Model -> Model
update msg model =
    case msg of
        EmailChanged newEmail ->
            let
                emailResult =
                    validateEmail newEmail

                newEmailError =
                    case emailResult of
                        Ok _ ->
                            Nothing

                        Err error ->
                            Just error
            in
            { model
                | email = newEmail
                , emailError = newEmailError
                , formValid = isValid model { model | email = newEmail, emailError = newEmailError }
            }

        PasswordChanged newPassword ->
            let
                passwordResult =
                    validatePassword newPassword

                newPasswordError =
                    case passwordResult of
                        Ok _ ->
                            Nothing

                        Err error ->
                            Just error
            in
            { model
                | password = newPassword
                , passwordError = newPasswordError
                , formValid = isValid model { model | password = newPassword, passwordError = newPasswordError }
            }
```

このコードは、メールアドレスとパスワードの入力イベントを処理します。`EmailChanged`と`PasswordChanged`メッセージを受け取ると、それぞれ`validateEmail`と`validatePassword`関数を実行し、エラーメッセージを更新します。`formValid`は、フォーム全体のバリデーション状態を保持し、`isValid`関数によって更新されます。

```elm
isValid : Model -> Model -> Bool
isValid oldModel newModel =
    (newModel.emailError == Nothing) && (newModel.passwordError == Nothing) && ((oldModel.email /= newModel.email) || (oldModel.password /= newModel.password))
```

### 実装例：ログインフォーム、登録フォーム

#### ログインフォーム

```elm
import Html exposing (..)
import Html.Attributes exposing (..)
import Html.Events exposing (..)
import String


-- Model
type alias Model =
    { email : String
    , password : String
    , emailError : Maybe String
    , passwordError : Maybe String
    , formValid : Bool
    , loginSuccess : Bool
    , loginError : Maybe String
    }


initialModel : Model
initialModel =
    { email = ""
    , password = ""
    , emailError = Nothing
    , passwordError = Nothing
    , formValid = False
    , loginSuccess = False
    , loginError = Nothing
    }


-- Msg
type Msg
    = EmailChanged String
    | PasswordChanged String
    | Submit
    | LoginSuccess
    | LoginError String


-- Update
update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        EmailChanged newEmail ->
            let
                emailResult =
                    validateEmail newEmail

                newEmailError =
                    case emailResult of
                        Ok _ ->
                            Nothing

                        Err error ->
                            Just error
            in
            ( { model
                | email = newEmail
                , emailError = newEmailError
                , formValid = isValid model { model | email = newEmail, emailError = newEmailError, password = model.password, passwordError = model.passwordError }
            }
            , Cmd.none
            )

        PasswordChanged newPassword ->
            let
                passwordResult =
                    validatePassword newPassword

                newPasswordError =
                    case passwordResult of
                        Ok _ ->
                            Nothing

                        Err error ->
                            Just error
            in
            ( { model
                | password = newPassword
                , passwordError = newPasswordError
                , formValid = isValid model { model | password = newPassword, passwordError = newPasswordError, email = model.email, emailError = model.emailError }
            }
            , Cmd.none
            )

        Submit ->
            if model.formValid then
                ( model, loginCmd model.email model.password )
            else
                ( model, Cmd.none )

        LoginSuccess ->
            ( { model | loginSuccess = True, loginError = Nothing }, Cmd.none )

        LoginError error ->
            ( { model | loginSuccess = False, loginError = Just error }, Cmd.none )

--loginを模倣するためのコード
loginCmd : String -> String -> Cmd Msg
loginCmd email password =
    if email == "test@example.com" && password == "password123" then
        Cmd.ofType Msg <| Effects.task LoginSuccess (Task.succeed LoginSuccess)
    else
        Cmd.ofType Msg <| Effects.task (LoginError "メールアドレスまたはパスワードが間違っています。") (Task.succeed (LoginError "メールアドレスまたはパスワードが間違っています。"))

module Effects exposing (..)

import Task

-- a command to turn a Task into a Cmd
task : msg -> Task.Task x msg -> Cmd msg
task tagger theTask =
  Task.perform tagger theTask


-- View
view : Model -> Html Msg
view model =
    div []
        [ h1 [] [ text "ログイン" ]
        , if model.loginSuccess then
            div [] [ text "ログイン成功！" ]
          else
            form [ onSubmit Submit ]
                [ label [] [ text "メールアドレス:" ]
                , input [ type_ "text", value model.email, onInput EmailChanged ] []
                , case model.emailError of
                    Just error ->
                        div [ class "error" ] [ text error ]
                    Nothing ->
                        text ""
                , br [] []

                , label [] [ text "パスワード:" ]
                , input [ type_ "password", value model.password, onInput PasswordChanged ] []
                , case model.passwordError of
                    Just error ->
                        div [ class "error" ] [ text error ]
                    Nothing ->
                        text ""
                , br [] []

                , case model.loginError of
                    Just error ->
                        div [ class "error" ] [ text error ]
                    Nothing ->
                        text ""
                , button [ type_ "submit", disabled (not model.formValid) ] [ text "ログイン" ]
                ]
        ]


-- isValid
isValid : Model -> Model -> Bool
isValid oldModel newModel =
    (newModel.emailError == Nothing) && (newModel.passwordError == Nothing) && ((oldModel.email /= newModel.email) || (oldModel.password /= newModel.password))


-- Main
main : Program Never Model Msg
main =
    Html.beginnerProgram { model = initialModel, view = view, update = update }
```

#### 登録フォーム

登録フォームは、ログインフォームとほとんど同じ構造を持ちますが、追加のフィールド（例：名前、確認用パスワード）が含まれます。検証ロジックも、これらの追加フィールドに合わせて拡張する必要があります。

### 実践的なテクニック

*   **カスタムバリデーション:**  正規表現を使ったより複雑な検証や、APIからのデータを参照した検証など、カスタムバリデーション関数を定義することで、より高度な入力検証を実現できます。
*   **遅延バリデーション:**  入力が終わったタイミングでバリデーションを実行することで、ユーザーエクスペリエンスを向上させることができます。
*   **フォームライブラリの利用:**  `elm-form`などのライブラリを利用することで、フォームの構築と検証をより簡単に行うことができます。

### 応用例とユースケース

*   **ショッピングカート:**  数量や配送先住所の入力フォーム
*   **ブログ:**  記事の投稿フォーム
*   **SNS:**  ユーザープロフィールの編集フォーム

### トラブルシューティング

*   **エラーメッセージが表示されない:** `Maybe`型を正しく処理しているか、CSSでエラーメッセージの表示を制御しているかを確認してください。
*   **バリデーションが正しく機能しない:**  バリデーション関数のロジックが正しいか、`update`関数で正しく呼び出されているかを確認してください。
*   **フォームが送信できない:**  `formValid`が`True`になっているか、`button`要素の`disabled`属性が正しく設定されているかを確認してください。
