## 13. Elmにおけるルーティング：SPA(Single Page Application)の構築

Elmは、その堅牢性と予測可能性から、近年ますます人気を集めているフロントエンド言語です。特にSPA(Single Page Application)開発においては、コンパイラの強力な型チェックとアーキテクチャの強制力によって、保守性の高いアプリケーションを構築できます。この章では、ElmでSPAを構築する上で不可欠なルーティングについて、基本的な概念から実践的なテクニックまでを解説します。

### ルーティングの基本概念

#### 概要と重要性

SPAでは、URLの変化に応じてUIを動的に更新することで、ネイティブアプリケーションのようなスムーズなユーザーエクスペリエンスを実現します。ルーティングは、このURLとUIの対応付けを管理する仕組みであり、SPAの中核をなす重要な要素です。適切なルーティング設計は、アプリケーションのナビゲーションを容易にし、ユーザーエクスペリエンスを向上させるだけでなく、SEO対策にも貢献します。

#### URLとUIの対応付け

ルーティングの基本的な役割は、URL（Uniform Resource Locator）と、表示すべきUI（ユーザーインターフェース）を紐付けることです。例えば、`example.com/home` というURLにアクセスした場合、ホームページのコンテンツを表示し、`example.com/products/123` というURLにアクセスした場合、IDが123の商品詳細ページを表示するといった具合です。

Elmでは、このURLとUIの対応付けを、関数やデータ構造を用いて明確に記述します。これにより、コンパイラはURLの変更に対するUIの更新を監視し、エラーを早期に検出することができます。

#### ブラウザの履歴管理

SPAでは、ページ遷移のたびにブラウザの履歴を更新する必要があります。これにより、ユーザーはブラウザの「戻る」「進む」ボタンを使って、前のページや次のページに移動することができます。

Elmでは、ブラウザの履歴管理を `elm-spa` ライブラリなどの外部ライブラリを利用して行うことが一般的です。これらのライブラリは、ブラウザの履歴を安全に管理し、URLの変化を検知してUIを更新するための機能を提供します。

### elm-spaライブラリの活用

#### 概要と重要性

`elm-spa` は、ElmでSPAを構築するためのライブラリです。ルーティング、URL解析、ブラウザの履歴管理など、SPAに必要な機能を提供し、開発者がアプリケーションのロジックに集中できるように支援します。

`elm-spa` は、Elmアーキテクチャに準拠しており、Model-View-Updateパターンに基づいてアプリケーションを構築します。これにより、アプリケーションの状態管理が容易になり、テストも行いやすくなります。

#### 特徴と利点

`elm-spa` の主な特徴と利点は以下の通りです。

*   **宣言的なルーティング定義:** URLとUIの対応付けを、明確かつ宣言的に記述できます。
*   **型安全なURLパラメータ:** URLパラメータを型安全に扱うことができます。
*   **ブラウザの履歴管理:** ブラウザの履歴を自動的に管理し、「戻る」「進む」ボタンの動作をサポートします。
*   **SEO対策:** 検索エンジンがクロールしやすいように、URLを構造化することができます。
*   **テスト容易性:** Elmアーキテクチャに準拠しているため、アプリケーションのテストが容易です。

#### 事前準備と前提条件

`elm-spa` を使用するには、以下の準備が必要です。

*   Elmのインストール: Elmのコンパイラとパッケージマネージャーをインストールします。
*   `elm-spa` のインストール: `elm install elm-spa/core` コマンドを実行して、`elm-spa` ライブラリをインストールします。
*   基本的なElmの知識: Elmの基本的な構文、型システム、アーキテクチャについて理解している必要があります。

#### 基本的な使い方

`elm-spa` を使用したルーティングの基本的な流れは以下の通りです。

1.  **ページ定義:** アプリケーションで表示するページを定義します。
2.  **ルーティング設定:** URLとページの対応付けを定義します。
3.  **URLの解析:** 現在のURLを解析して、対応するページを表示します。
4.  **ページ遷移:** URLを変更することで、ページを遷移します。

具体的なコード例を見てみましょう。

```elm
module Main exposing (..)

import Browser
import Html exposing (..)
import Html.Attributes exposing (..)
import Html.Events exposing (onClick)
import Url
import Url.Parser exposing ((</>), Parser, map, s, top)


-- MODEL

type alias Model =
  { route : Route
  }


-- PAGES

type Route
    = Home
    | About
    | Product Int


pageToString : Route -> String
pageToString route =
    case route of
        Home ->
            "Home"

        About ->
            "About"

        Product id ->
            "Product " ++ String.fromInt id


-- UPDATE

type Msg
    = UrlChanged Url.Url
    | NavigateTo Route


update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        UrlChanged url ->
            ( { model | route = parseRoute url }
            , Cmd.none
            )

        NavigateTo route ->
            ( { model | route = route }
            , Browser.pushUrl (pageToString route)
            )


-- VIEW

view : Model -> Html Msg
view model =
    div []
        [ h1 [] [ text (pageToString model.route) ]
        , nav []
            [ a [ href "/", onClick (preventDefault (NavigateTo Home)) ] [ text "Home" ]
            , a [ href "/about", onClick (preventDefault (NavigateTo About)) ] [ text "About" ]
            , a [ href "/product/123", onClick (preventDefault (NavigateTo (Product 123))) ] [ text "Product 123" ]
            ]
        ]


-- ROUTING

parseRoute : Url.Url -> Route
parseRoute url =
    Url.Parser.parse routeParser url
        |> Maybe.withDefault Home

routeParser : Parser (Route -> Route) (Route)
routeParser =
    Url.Parser.oneOf
        [ map Home top
        , map About (s "about")
        , map Product (s "product" </> Url.Parser.int)
        ]

-- MAIN

init : Url.Url -> (Model, Cmd Msg)
init url =
    ( Model (parseRoute url)
    , Cmd.none
    )


main : Program Flags Model Msg
main =
    Browser.application
        { init = init
        , view = view
        , update = update
        , subscriptions = \_ -> Sub.batch [ Browser.urlChanges UrlChanged ]
        }
```

この例では、Home、About、Productの3つのページを定義し、それぞれのURLに対応付けています。`parseRoute`関数がURLを解析し、対応するRoute型の値を返します。`view`関数は、Route型の値に基づいて、表示するコンテンツを生成します。

#### 実践的なテクニック

*   **`elm-spa` の `Route` 型の活用:** アプリケーションで取りうるすべてのルートを `Route` 型で定義することで、型安全性を高めることができます。
*   **`Url.Parser` を使った複雑なURL解析:** `Url.Parser` を使用することで、複雑なURLを解析し、URLパラメータを抽出することができます。
*   **`Browser.pushUrl` を使ったページ遷移:** `Browser.pushUrl` を使用することで、ブラウザの履歴を更新しながらページ遷移を行うことができます。
*   **`preventDefault` でデフォルトの動作を抑制:** リンクのクリック時に `preventDefault` を使用することで、ブラウザのデフォルトの動作を抑制し、Elm側でページ遷移を制御することができます。

#### 応用例とユースケース

*   **ブログアプリケーション:** 記事一覧ページ、記事詳細ページ、カテゴリページなど、様々なページを持つブログアプリケーションを構築できます。
*   **ECサイト:** 商品一覧ページ、商品詳細ページ、カートページ、注文ページなど、複雑なルーティングが必要なECサイトを構築できます。
*   **ダッシュボードアプリケーション:** 複数のグラフや表を表示するダッシュボードアプリケーションを構築できます。

#### トラブルシューティング

*   **URLが正しく解析されない:** `routeParser` の定義に誤りがないか確認してください。特に、URLパラメータの型が正しいか確認してください。
*   **ページ遷移がうまくいかない:** `Browser.pushUrl` が正しく呼び出されているか確認してください。また、`preventDefault` が正しく設定されているか確認してください。
*   **ブラウザの「戻る」「進む」ボタンが動作しない:** `elm-spa` の設定に誤りがないか確認してください。特に、`Browser.urlChanges` が正しくサブスクライブされているか確認してください。

### パラメータ付きルートの定義

#### 概要と重要性

パラメータ付きルートとは、URLの一部が可変であり、その値をパラメータとして取得できるルートのことです。例えば、商品詳細ページのURL `example.com/products/123` では、`123` が商品のIDというパラメータになります。

パラメータ付きルートを使用することで、動的なコンテンツを表示するアプリケーションを柔軟に構築することができます。

#### 特徴と利点

*   **動的なコンテンツの表示:** URLの一部をパラメータとして取得し、その値に基づいて動的なコンテンツを表示できます。
*   **柔軟なルーティング設定:** 複数のパラメータを持つ複雑なURLを解析できます。
*   **型安全なパラメータ処理:** URLパラメータを型安全に扱うことができます。

#### 事前準備と前提条件

*   `elm-spa` のインストール: `elm install elm-spa/core` コマンドを実行して、`elm-spa` ライブラリをインストールします。
*   `Url.Parser` の理解: `Url.Parser` を使用してURLを解析する方法を理解している必要があります。

#### 基本的な使い方

パラメータ付きルートを定義するには、`Url.Parser` の `int`、`string`、`float` などの関数を使用します。これらの関数は、URLの一部を特定の型として解析し、その値を返します。

例：

```elm
import Url.Parser exposing ((</>), Parser, map, s, int)

-- 型定義
type Route =
    Product Int

-- ルートパーサー
routeParser : Parser (Route -> Route) Route
routeParser =
    map Product (s "product" </> int)
```

この例では、`/product/:id` というURLを解析し、`:id` を整数型のパラメータとして取得します。`Product` コンストラクタは、この整数型のIDを受け取り、`Route` 型の値を生成します。

#### 実践的なテクニック

*   **複数のパラメータの定義:** 複数のパラメータを持つURLを解析するには、`</>` 演算子を複数回使用します。
*   **オプションパラメータの定義:** オプションのパラメータを定義するには、`Maybe` 型を使用します。
*   **クエリパラメータの取得:** クエリパラメータを取得するには、`Url.Parser.query` 関数を使用します。

#### 応用例とユースケース

*   **商品詳細ページ:** 商品IDをパラメータとして受け取り、対応する商品の情報を表示します。
*   **ブログ記事詳細ページ:** 記事IDをパラメータとして受け取り、対応する記事の内容を表示します。
*   **ユーザープロフィールページ:** ユーザーIDをパラメータとして受け取り、対応するユーザーの情報を表示します。

#### トラブルシューティング

*   **パラメータが正しく解析されない:** `Url.Parser` の定義に誤りがないか確認してください。特に、パラメータの型が正しいか確認してください。
*   **URLパラメータが `Nothing` になる:** オプションパラメータの場合、パラメータが存在しない場合に `Nothing` が返されます。`Maybe.withDefault` などを使って、デフォルト値を設定することを検討してください。

### 実装例：複数のページを持つアプリケーション

#### 概要と重要性

このセクションでは、これまでの知識を応用して、複数のページを持つシンプルなアプリケーションを実際に構築します。この例を通して、ルーティングの実装方法をより具体的に理解することができます。

#### 事前準備と前提条件

*   Elmのインストール: Elmのコンパイラとパッケージマネージャーをインストールします。
*   `elm-spa` のインストール: `elm install elm-spa/core` コマンドを実行して、`elm-spa` ライブラリをインストールします。
*   基本的なElmの知識: Elmの基本的な構文、型システム、アーキテクチャについて理解している必要があります。

#### アプリケーションの仕様

今回構築するアプリケーションは、以下のページを持つシンプルなブログアプリケーションです。

*   **ホームページ:** 記事一覧を表示します。
*   **記事詳細ページ:** 選択された記事の内容を表示します。
*   **お問い合わせページ:** お問い合わせフォームを表示します。

#### 実装

まず、必要なモジュールをインポートします。

```elm
module Main exposing (..)

import Browser
import Html exposing (..)
import Html.Attributes exposing (..)
import Html.Events exposing (onClick)
import Url
import Url.Parser exposing ((</>), Parser, map, s, top, string)
```

次に、`Model`、`Msg`、`Route` 型を定義します。

```elm
-- MODEL

type alias Model =
  { route : Route
  , articles : List Article
  }

type alias Article =
    { id : Int
    , title : String
    , content : String
    }

-- PAGES

type Route
    = Home
    | ArticleDetail Int
    | Contact

-- MESSAGES

type Msg
    = UrlChanged Url.Url
    | NavigateTo Route
```

`Route` 型は、アプリケーションで取りうるすべてのルートを定義します。`Home` はホームページ、`ArticleDetail Int` は記事詳細ページ（`Int` は記事ID）、`Contact` はお問い合わせページを表します。

`update` 関数を定義します。

```elm
-- UPDATE

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        UrlChanged url ->
            ( { model | route = parseRoute url }
            , Cmd.none
            )

        NavigateTo route ->
            ( { model | route = route }
            , Browser.pushUrl (routeToString route)
            )
```

`update` 関数は、メッセージを受け取り、モデルを更新します。`UrlChanged` メッセージは、URLが変更されたときに発生し、`parseRoute` 関数を使ってURLを解析し、対応する `Route` 型の値をモデルに設定します。`NavigateTo` メッセージは、ページ遷移が発生したときに発生し、`Browser.pushUrl` 関数を使ってブラウザの履歴を更新し、URLを変更します。

`view` 関数を定義します。

```elm
-- VIEW

view : Model -> Html Msg
view model =
    div []
        [ navigation model.route
        , mainContent model
        ]

navigation : Route -> Html Msg
navigation route =
    nav [ class "navigation" ]
        [ a [ href "/", onClick (preventDefault (NavigateTo Home)), class "nav-link" ] [ text "Home" ]
        , a [ href "/contact", onClick (preventDefault (NavigateTo Contact)), class "nav-link" ] [ text "Contact" ]
        ]

mainContent : Model -> Html Msg
mainContent model =
    div [ class "main-content" ]
        (case model.route of
            Home ->
                viewHome model.articles

            ArticleDetail id ->
                viewArticleDetail model.articles id

            Contact ->
                viewContact
        )

viewHome : List Article -> Html Msg
viewHome articles =
    div []
        [ h1 [] [ text "Articles" ]
        , ul [] (List.map viewArticleLink articles)
        ]

viewArticleLink : Article -> Html Msg
viewArticleLink article =
    li [] [ a [ href ("/article/" ++ String.fromInt article.id), onClick (preventDefault (NavigateTo (ArticleDetail article.id))) ] [ text article.title ] ]

viewArticleDetail : List Article -> Int -> Html Msg
viewArticleDetail articles id =
    case List.find (\a -> a.id == id) articles of
        Just article ->
            div []
                [ h1 [] [ text article.title ]
                , p [] [ text article.content ]
                ]

        Nothing ->
            div [] [ text "Article not found" ]

viewContact : Html Msg
viewContact =
    div []
        [ h1 [] [ text "Contact Us" ]
        , p [] [ text "Please fill out the form below to contact us." ]
        ]
```

`view` 関数は、モデルを受け取り、HTMLを生成します。`mainContent` 関数は、現在のルートに基づいて、表示するコンテンツを切り替えます。`viewHome`、`viewArticleDetail`、`viewContact` 関数は、それぞれのページの内容を表示します。

`parseRoute` 関数を定義します。

```elm
-- ROUTING

parseRoute : Url.Url -> Route
parseRoute url =
    Url.Parser.parse routeParser url
        |> Maybe.withDefault Home

routeParser : Parser (Route -> Route) (Route)
routeParser =
    Url.Parser.oneOf
        [ map Home top
        , map Contact (s "contact")
        , map ArticleDetail (s "article" </> int)
        ]

routeToString : Route -> String
routeToString route =
    case route of
        Home ->
            "/"

        Contact ->
            "/contact"

        ArticleDetail id ->
            "/article/" ++ String.fromInt id
```

`parseRoute` 関数は、URLを受け取り、対応する `Route` 型の値を返します。`routeParser` は、URLを解析するためのパーサーを定義します。

最後に、`main` 関数を定義します。

```elm
-- MAIN

init : Url.Url -> (Model, Cmd Msg)
init url =
    let
        initialArticles =
            [ { id = 1, title = "First Article", content = "This is the first article." }
            , { id = 2, title = "Second Article", content = "This is the second article." }
            ]
    in
    ( Model (parseRoute url) initialArticles
    , Cmd.none
    )


main : Program Flags Model Msg
main =
    Browser.application
        { init = init
        , view = view
        , update = update
        , subscriptions = \_ -> Sub.batch [ Browser.urlChanges UrlChanged ]
        }
```

`main` 関数は、アプリケーションのエントリーポイントです。`Browser.application` 関数を使って、アプリケーションを初期化します。`init` 関数は、初期モデルとコマンドを返します。

#### 実行結果

このコードを実行すると、シンプルなブログアプリケーションが表示されます。ホームページには記事一覧が表示され、記事のタイトルをクリックすると、対応する記事詳細ページが表示されます。お問い合わせページへのリンクも表示されます。
