## 序章: WebGLとThree.jsの概要 - 3D Web開発の基礎

### 1.1 はじめに - WebGLとThree.jsの世界へようこそ

ようこそ、WebGLとThree.jsによる3D Web開発の世界へ！ 本書は、あなたのWebブラウザを強力な3Dグラフィックスエンジンに変える旅のガイド役となります。

WebGLは、Webブラウザ上でOpenGL ES 2.0をベースとした3Dグラフィックスを表示するためのJavaScript APIです。プラグインなしで、ブラウザ上で高度な3Dレンダリングを実現できます。一方、Three.jsは、WebGLをより扱いやすくするためのJavaScriptライブラリです。複雑なWebGLのコードを簡素化し、開発者がより直感的に3Dコンテンツを作成できるように設計されています。

3D Web開発は、インタラクティブな製品デモ、没入感のあるゲーム、魅力的なデータビジュアライゼーションなど、幅広い可能性を秘めています。建築、医療、教育、エンターテイメントといった様々な分野で、革新的なWebエクスペリエンスを実現できます。

**本書で扱う範囲と対象読者層:**

本書では、WebGLの基礎から、Three.jsを使った実践的な3D Webアプリケーション開発までを網羅します。具体的には、以下の内容を扱います。

*   WebGLの基本的な概念とAPI
*   Three.jsの基本的な使い方（シーン、カメラ、レンダラー、オブジェクト）
*   マテリアル、テクスチャ、ライティングの設定
*   アニメーションとインタラクションの実装
*   高度なシェーダープログラミング
*   パフォーマンス最適化
*   実用的な3D Webアプリケーションの開発例

対象読者層は、Web開発の経験があり、3Dグラフィックスに興味がある方々です。JavaScriptの基本的な知識があれば、スムーズに学習を進められます。もちろん、3Dグラフィックスの知識が全くない初心者の方でも、丁寧に解説していくのでご安心ください。経験豊富な開発者の方にも、Three.jsの高度なテクニックやパフォーマンス最適化など、役立つ情報を提供できると信じています。

本書を通じて、3D Web開発の基礎をしっかりと身につけ、創造的なWebエクスペリエンスを自由に作り出せるようになることを目指しましょう。

### 1.2 WebGLの基礎 - 3Dレンダリングパイプラインの理解

WebGLは、ローレベルなAPIであり、3Dグラフィックスのレンダリングプロセスを直接制御できます。しかし、その分、学習曲線も急です。ここでは、WebGLの基本的な概念とレンダリングパイプラインについて解説します。

**WebGL APIの概要:**

WebGL APIは、主に以下の要素で構成されています。

*   **シェーダー:** 頂点シェーダーとフラグメントシェーダーの2種類があり、GPU上で実行されるプログラムです。頂点シェーダーは、3Dモデルの頂点の位置を変換し、フラグメントシェーダーは、ピクセル（フラグメント）の色を決定します。
*   **バッファ:** 頂点データやインデックスデータを格納するためのメモリ領域です。頂点バッファには、頂点の位置、法線ベクトル、テクスチャ座標などが格納されます。インデックスバッファは、頂点の接続順序を指定します。
*   **テクスチャ:** 2D画像やキューブマップなどのデータを格納します。3Dモデルの表面にテクスチャを貼り付けることで、よりリアルな表現が可能になります。
*   **プログラム:** 頂点シェーダーとフラグメントシェーダーを組み合わせたものです。WebGLは、プログラムを実行して3Dグラフィックスをレンダリングします。
*   **WebGLコンテキスト:** WebGLの描画状態を管理するオブジェクトです。

**レンダリングパイプラインの概念:**

WebGLのレンダリングパイプラインは、以下のステップで構成されています。

1.  **頂点シェーダー:** 3Dモデルの頂点データを受け取り、モデルビュー変換、プロジェクション変換などを行います。出力は、クリップ空間における頂点の位置です。
2.  **ラスタライズ:** 頂点シェーダーの出力に基づいて、三角形をピクセル（フラグメント）に分割します。
3.  **フラグメントシェーダー:** 各ピクセル（フラグメント）の色を決定します。テクスチャマッピング、ライティング、シャドウイングなどの処理を行います。
4.  **フレームバッファ:** フラグメントシェーダーの出力に基づいて、フレームバッファにピクセルが書き込まれます。フレームバッファは、最終的に画面に表示されるイメージを保持します。

**WebGLの制約と考慮点:**

WebGLは、ローレベルなAPIであるため、いくつかの制約と考慮点があります。

*   **クロスオリジン制約:** WebGLは、異なるオリジンからのリソース（テクスチャ、モデルなど）の読み込みを制限します。CORS（Cross-Origin Resource Sharing）の設定が必要になる場合があります。
*   **シェーダー言語:** WebGLのシェーダーは、GLSL（OpenGL Shading Language）というC言語に似た言語で記述する必要があります。
*   **パフォーマンス:** WebGLアプリケーションのパフォーマンスは、ハードウェアの性能に大きく依存します。最適化が不可欠です。
*   **互換性:** WebGLは、すべてのブラウザで完全にサポートされているわけではありません。互換性を考慮する必要があります。

**まとめと次のステップ:**

WebGLは、強力な3DグラフィックスAPIですが、学習コストも高いです。しかし、Three.jsなどのライブラリを使用することで、WebGLの複雑さを軽減し、より簡単に3D Webアプリケーションを開発できます。次のセクションでは、Three.jsの導入について解説します。

### 1.3 Three.jsの導入 - シーン、カメラ、レンダラーの基本

Three.jsは、WebGLを基盤としたJavaScript 3Dライブラリであり、開発者が複雑な3Dグラフィックスをより簡単に作成できるように設計されています。シーンの管理、オブジェクトの作成、マテリアルの設定、アニメーションの実装など、3D Web開発に必要な機能が豊富に用意されています。

**Three.jsのインストールと設定:**

Three.jsをプロジェクトに導入する方法はいくつかあります。

*   **CDN:** HTMLファイルに直接CDNのURLを記述する方法です。手軽に試せるのがメリットですが、ネットワーク環境に依存します。
    ```html
    <script src="https://cdn.jsdelivr.net/npm/three@0.155.0/build/three.min.js"></script>
    ```
*   **npm:** npmを使ってThree.jsをインストールする方法です。プロジェクトの依存関係を管理しやすくなります。
    ```bash
    npm install three
    ```
    インストール後、JavaScriptファイルでThree.jsをインポートします。
    ```javascript
    import * as THREE from 'three';
    ```

**最初のThree.jsアプリケーションの作成（シンプルな立方体）:**

Three.jsを使って、シンプルな立方体を表示するアプリケーションを作成してみましょう。

1.  **HTMLファイルの作成:**
    ```html
    <!DOCTYPE html>
    <html>
    <head>
        <title>Three.js Cube</title>
        <style>
            body { margin: 0; }
            canvas { display: block; }
        </style>
    </head>
    <body>
        <script src="https://cdn.jsdelivr.net/npm/three@0.155.0/build/three.min.js"></script>
        <script>
            // JavaScriptコードはここに記述します
        </script>
    </body>
    </html>
    ```

2.  **JavaScriptコードの記述:**
    ```javascript
    // シーンを作成
    const scene = new THREE.Scene();

    // カメラを作成
    const camera = new THREE.PerspectiveCamera( 75, window.innerWidth / window.innerHeight, 0.1, 1000 );
    camera.position.z = 5;

    // レンダラーを作成
    const renderer = new THREE.WebGLRenderer();
    renderer.setSize( window.innerWidth, window.innerHeight );
    document.body.appendChild( renderer.domElement );

    // 立方体を作成
    const geometry = new THREE.BoxGeometry();
    const material = new THREE.MeshBasicMaterial( { color: 0x00ff00 } );
    const cube = new THREE.Mesh( geometry, material );
    scene.add( cube );

    // アニメーションループ
    function animate() {
        requestAnimationFrame( animate );

        cube.rotation.x += 0.01;
        cube.rotation.y += 0.01;

        renderer.render( scene, camera );
    }
    animate();
    ```

このコードを実行すると、緑色の立方体が回転するアニメーションが表示されます。

**シーン、カメラ、レンダラーの役割と連携:**

*   **シーン:** 3Dオブジェクトを配置する空間です。シーンにオブジェクトを追加することで、レンダリング対象となります。
*   **カメラ:** シーンをどのように見るかを決定します。カメラの位置、視野角、アスペクト比などを設定できます。
*   **レンダラー:** シーンとカメラの情報に基づいて、3Dグラフィックスをレンダリングします。レンダラーは、WebGLコンテキストを管理し、画面に描画を行います。

シーン、カメラ、レンダラーは、Three.jsアプリケーションの基本的な構成要素であり、これらを組み合わせることで、様々な3Dコンテンツを作成できます。

**実践的なテクニック:**

*   **レスポンシブ対応:** ブラウザのサイズに合わせて、レンダラーのサイズを調整することで、レスポンシブな3D Webアプリケーションを作成できます。
    ```javascript
    window.addEventListener( 'resize', function () {
        camera.aspect = window.innerWidth / window.innerHeight;
        camera.updateProjectionMatrix();
        renderer.setSize( window.innerWidth, window.innerHeight );
    } );
    ```
*   **マテリアルの種類:** Three.jsには、様々なマテリアルが用意されています。MeshBasicMaterial、MeshLambertMaterial、MeshPhongMaterialなど、マテリアルの種類によって、ライティングやシェーディングの効果が異なります。

**まとめと次のステップ:**

### 1.4 開発環境の構築とデバッグ - 効率的な開発ワークフロー

3D Web開発は、コードの記述だけでなく、開発環境の構築やデバッグも重要な要素です。ここでは、効率的な開発ワークフローを確立するためのツールやテクニックについて解説します。

**推奨開発環境:**

*   **エディタ:** VS Code (Visual Studio Code) は、豊富な拡張機能とデバッグ機能が利用できる、非常に人気のあるエディタです。
*   **ブラウザ:** Chrome DevToolsは、JavaScriptのデバッグ、パフォーマンスの分析、ネットワークの監視など、Web開発に必要な機能が豊富に用意されています。
*   **Webサーバー:** ローカル環境でWebアプリケーションを動作させるためには、Webサーバーが必要です。Node.jsのhttp-serverやPythonのSimpleHTTPServerなどが手軽に使えます。

**Three.jsデバッグツール:**

*   **Three.js Editor:** Three.js Editorは、ブラウザ上で3Dシーンを編集できるツールです。オブジェクトの追加、マテリアルの設定、ライティングの調整などをGUIで行うことができます。
*   **Spector.js:** Spector.jsは、WebGLのAPIコールをキャプチャし、デバッグ情報を提供してくれるツールです。シェーダーのコンパイルエラー、テクスチャの読み込みエラーなどを特定するのに役立ちます。
*   **Three.js Inspector (Chrome拡張):** Chrome拡張機能として提供されているThree.js Inspectorは、実行中のThree.jsシーンをリアルタイムに検査し、オブジェクト、マテリアル、テクスチャなどのプロパティを編集できます。

**エラーハンドリングとログ出力:**

WebGLやThree.jsのエラーは、コンソールに表示されることが多いです。エラーメッセージを注意深く確認し、原因を特定することが重要です。また、`console.log()`を使って、変数の値や処理の実行状況をログに出力することで、デバッグを効率的に行うことができます。

**実践的なテクニック:**

*   **ソースマップ:** ソースマップを使用すると、minifyされたJavaScriptコードを元のソースコードに戻してデバッグできます。VS Codeなどのエディタは、ソースマップをサポートしています。
*   **デバッグプリント:** シェーダーのデバッグには、`console.log()`のようなログ出力は使えません。代わりに、フラグメントシェーダーで色を出力することで、変数の値を確認できます。
    ```glsl
    #ifdef GL_ES
    precision highp float;
    #endif

    uniform float myValue;

    void main() {
        gl_FragColor = vec4(myValue, 0.0, 0.0, 1.0);
    }
    ```
    この例では、`myValue`の値を赤色の輝度として出力しています。
*   **パフォーマンスモニタリング:** Chrome DevToolsのPerformanceパネルを使用すると、Webアプリケーションのパフォーマンスを詳細に分析できます。ボトルネックとなっている処理を特定し、最適化を行うことで、パフォーマンスを向上させることができます。

**トラブルシューティング:**

*   **WebGLコンテキストの取得エラー:** WebGLコンテキストの取得に失敗する場合、ブラウザがWebGLをサポートしていないか、WebGLが無効になっている可能性があります。ブラウザの設定を確認してください。
*   **シェーダーのコンパイルエラー:** シェーダーのコードに誤りがある場合、コンパイルエラーが発生します。エラーメッセージを注意深く確認し、コードを修正してください。
*   **テクスチャの読み込みエラー:** テクスチャのファイルパスが間違っているか、テクスチャファイルが破損している可能性があります。ファイルパスを確認し、テクスチャファイルを再ダウンロードしてみてください。

**まとめと次のステップ:**

効率的な開発環境を構築し、デバッグスキルを磨くことで、3D Web開発の生産性を大幅に向上させることができます。本書では、今後も様々なデバッグテクニックを紹介していきます。次の章では、Three.jsの基本的なオブジェクトの作成について解説します。
