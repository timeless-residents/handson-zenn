## 第13章: Three.jsのトラブルシューティング - よくある問題と解決策

Three.jsは、Webブラウザ上で3Dコンテンツを表現するための強力なJavaScriptライブラリです。しかし、その自由度の高さゆえに、様々な問題に直面することも少なくありません。本章では、Three.js開発で頻繁に遭遇する問題とその解決策を、具体的なコード例を交えながら解説します。初心者から上級者まで、Three.jsでよりスムーズな開発を進めるための知識とノウハウを提供します。

### 13.1 レンダリングされない - オブジェクト、ライト、カメラの設定

**1. 概要と重要性**

せっかくコードを書いたのに、画面に何も表示されない…。これはThree.js初心者が最初につまづきやすい問題の一つです。原因は多岐に渡りますが、オブジェクト、ライト、カメラといった基本的な要素の設定ミスがほとんどです。このセクションでは、これらの要素が正しく設定されているかを段階的に確認し、解決策を探ります。

**2. 特徴と利点**

このセクションを読むことで、Three.jsにおけるレンダリングの基本的な仕組みを理解し、問題発生時に原因を特定し、迅速に解決できるようになります。また、オブジェクト、ライト、カメラの設定に関する理解が深まることで、より複雑なシーンを構築する際の土台となります。

**3. 事前準備と前提条件**

*   Three.jsの基本的なプロジェクトのセットアップが完了していること
*   基本的なJavaScriptの知識があること

**4. 基本的な使い方**

まず、レンダリングに必要な基本的な要素が揃っているかを確認しましょう。

```javascript
// シーンの作成
const scene = new THREE.Scene();

// カメラの作成 (PerspectiveCameraを使用)
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
camera.position.z = 5; // カメラの位置を調整

// レンダラーの作成
const renderer = new THREE.WebGLRenderer();
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// オブジェクトの作成 (例: 立方体)
const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshBasicMaterial({ color: 0x00ff00 }); // 緑色のマテリアル
const cube = new THREE.Mesh(geometry, material);
scene.add(cube);

// ライトの作成 (AmbientLightを使用)
const light = new THREE.AmbientLight(0xffffff); // 白色
scene.add(light);

// アニメーションループ
function animate() {
  requestAnimationFrame(animate);

  // キューブを回転させる
  cube.rotation.x += 0.01;
  cube.rotation.y += 0.01;

  renderer.render(scene, camera);
}

animate();
```

**5. 実践的なテクニック**

*   **オブジェクトがシーンに追加されているか:**  `scene.add(object)` を確実に実行しているか確認します。
*   **ライトが適切に設定されているか:**  特に `MeshBasicMaterial` を使用している場合、ライトがないとオブジェクトは見えません。`AmbientLight` や `DirectionalLight` などを追加しましょう。
*   **カメラの位置と方向:** カメラの位置が原点に近いと、オブジェクトに埋もれて見えないことがあります。`camera.position.z` を調整してオブジェクトから離したり、`camera.lookAt(scene.position)` でシーンの中心を見るように設定したりします。

**6. 応用例とユースケース**

例えば、建築ビジュアライゼーションで、オブジェクトの配置は正しいのに、一部屋だけ真っ暗で何も見えないというケースがあります。これは、その部屋にライトが設置されていない、またはライトの設定が間違っていることが原因と考えられます。

**7. トラブルシューティング**

*   **console.log() を活用する:**  オブジェクト、カメラ、ライトなどのインスタンスが正しく作成されているか、console.log() で確認します。
*   **デバッグツールを使用する:**  ブラウザの開発者ツールを利用して、Three.jsのエラーメッセージを確認します。
*   **簡単なシーンから始める:**  複雑なシーンで問題が発生した場合は、シンプルなシーンで基本的な要素が正しく動作するか確認し、徐々に複雑さを加えていくと原因を特定しやすくなります。

**8. まとめと次のステップ**

レンダリングされない問題は、Three.jsの基本的な要素の設定ミスが原因であることが多いです。オブジェクト、ライト、カメラの設定を丁寧に確認し、問題解決の糸口を見つけましょう。次のステップとして、Three.jsのドキュメントを参考に、様々なライトの種類やカメラの設定を試してみることをお勧めします。

### 13.2 パフォーマンスが低い - フレームレート、メモリリーク

**1. 概要と重要性**

Three.jsで美しい3Dシーンを作成しても、動きがカクカクしていたり、時間が経つにつれて動作が遅くなったりするようでは、ユーザーエクスペリエンスは台無しです。パフォーマンスの問題は、フレームレートの低下やメモリリークなどが原因で発生します。このセクションでは、Three.jsのパフォーマンスを改善するためのテクニックを解説します。

**2. 特徴と利点**

このセクションを読むことで、Three.jsにおけるパフォーマンスの問題を特定し、最適化するための知識とスキルを習得できます。フレームレートの改善、メモリリークの防止、WebGLの仕組みの理解を通じて、より効率的な3Dアプリケーションを開発できるようになります。

**3. 事前準備と前提条件**

*   Three.jsの基本的な使い方を理解していること
*   JavaScriptのパフォーマンスに関する基本的な知識があること

**4. 基本的な使い方**

まずは、現在のフレームレートを確認しましょう。

```javascript
let frameCount = 0;
let startTime = Date.now();

function animate() {
  requestAnimationFrame(animate);

  // ... レンダリング処理 ...

  frameCount++;
  let elapsedTime = Date.now() - startTime;
  if (elapsedTime > 1000) { // 1秒ごとにフレームレートを計算
    let fps = frameCount / (elapsedTime / 1000);
    console.log("FPS:", fps);
    frameCount = 0;
    startTime = Date.now();
  }

  renderer.render(scene, camera);
}

animate();
```

**5. 実践的なテクニック**

*   **オブジェクト数の削減:**  シーン内のオブジェクト数が多すぎると、レンダリングに時間がかかり、フレームレートが低下します。オブジェクトを統合したり、Lod (Level of Detail) を使用したりして、オブジェクト数を減らしましょう。

    ```javascript
    // 例: BufferGeometryUtils.mergeBufferGeometries を使用してジオメトリを統合する
    const mergedGeometry = THREE.BufferGeometryUtils.mergeBufferGeometries([geometry1, geometry2]);
    const mergedMesh = new THREE.Mesh(mergedGeometry, material);
    scene.add(mergedMesh);
    ```
*   **シェーダーの最適化:**  複雑なシェーダーは、GPUに大きな負荷をかけます。シェーダーを簡略化したり、不必要な計算を削除したりすることで、パフォーマンスを改善できます。
*   **テクスチャの最適化:**  テクスチャのサイズが大きいほど、メモリの使用量が増え、パフォーマンスが低下します。適切なサイズのテクスチャを使用したり、テクスチャ圧縮技術 (e.g., ASTC, ETC) を使用したりして、テクスチャを最適化しましょう。
*   **メモリリークの防止:**  Three.jsでは、オブジェクトを削除する際に、関連するジオメトリやマテリアルも明示的に削除する必要があります。削除せずに放置すると、メモリリークが発生し、時間が経つにつれてパフォーマンスが低下します。

    ```javascript
    // オブジェクトを削除する際の例
    scene.remove(object);
    object.geometry.dispose();
    object.material.dispose();
    object = null;
    ```

**6. 応用例とユースケース**

大規模な都市モデルをThree.jsで表示する場合、オブジェクト数が膨大になり、パフォーマンスが著しく低下することがあります。このような場合、Lod (Level of Detail) を使用して、カメラからの距離に応じてオブジェクトのディテールを調整することで、パフォーマンスを大幅に改善できます。

**7. トラブルシューティング**

*   **ブラウザの開発者ツールを使用する:**  ブラウザの開発者ツールには、パフォーマンスを分析するためのツールが用意されています。これらを利用して、ボトルネックとなっている処理を特定しましょう。
*   **Three.jsのパフォーマンスモニタリングツールを使用する:**  Three.jsには、パフォーマンスをモニタリングするためのツールが用意されています。これらを利用して、フレームレート、メモリ使用量などを監視し、問題点を特定しましょう。
*   **WebGL Inspectorを使用する:** WebGL Inspectorは、WebGLのAPIコールを詳細に分析できるツールです。これを使用すると、GPUの負荷状況を把握し、シェーダーの最適化などに役立てることができます。

**8. まとめと次のステップ**

パフォーマンスの問題は、Three.js開発において避けて通れない課題です。オブジェクト数の削減、シェーダーの最適化、メモリリークの防止など、様々なテクニックを駆使して、快適な3D体験を実現しましょう。次のステップとして、WebGLの仕組みやGPUのアーキテクチャについて学習することで、より深いレベルでパフォーマンスを最適化できるようになります。

### 13.3 テクスチャが表示されない - パス、フォーマット

**1. 概要と重要性**

テクスチャは、3Dモデルにリアリティを与えるための重要な要素です。しかし、テクスチャのパスが間違っていたり、フォーマットがThree.jsでサポートされていなかったりすると、テクスチャが表示されず、モデルが真っ黒になってしまうことがあります。このセクションでは、テクスチャが表示されない原因とその解決策を解説します。

**2. 特徴と利点**

このセクションを読むことで、Three.jsにおけるテクスチャの扱い方を理解し、テクスチャが表示されない問題を迅速に解決できるようになります。また、適切なテクスチャフォーマットの選択、テクスチャローダーの使い方、UVマッピングの理解を通じて、より高品質な3Dモデルを作成できるようになります。

**3. 事前準備と前提条件**

*   Three.jsの基本的な使い方を理解していること
*   画像のファイルフォーマットに関する基本的な知識があること

**4. 基本的な使い方**

テクスチャをロードしてマテリアルに適用する基本的なコードは以下の通りです。

```javascript
// テクスチャローダーの作成
const textureLoader = new THREE.TextureLoader();

// テクスチャのロード
textureLoader.load(
  'textures/your_texture.jpg', // テクスチャのパス
  function (texture) { // ロード完了時のコールバック関数
    // マテリアルの作成
    const material = new THREE.MeshBasicMaterial({ map: texture });

    // メッシュの作成
    const geometry = new THREE.BoxGeometry(1, 1, 1);
    const cube = new THREE.Mesh(geometry, material);
    scene.add(cube);
  },
  undefined, // ロード中のコールバック関数 (省略可能)
  function (err) { // エラー時のコールバック関数
    console.error('An error happened.', err);
  }
);
```

**5. 実践的なテクニック**

*   **テクスチャのパスが正しいか:**  テクスチャのパスは、HTMLファイルからの相対パスで指定します。パスが間違っていると、テクスチャをロードできません。ブラウザの開発者ツールで、テクスチャのロードに失敗しているか確認しましょう。
*   **テクスチャのフォーマットがThree.jsでサポートされているか:**  Three.jsは、JPEG、PNG、GIFなどの一般的な画像フォーマットをサポートしています。しかし、WebPなどの比較的新しいフォーマットを使用する場合は、別途エンコーダーが必要になることがあります。
*   **UVマッピングが正しいか:**  UVマッピングは、3Dモデルの表面にテクスチャを貼り付けるための座標です。UVマッピングが正しくないと、テクスチャが歪んで表示されたり、全く表示されなかったりします。
*   **ミップマップの生成:** ミップマップは、テクスチャを縮小表示する際に使用される、解像度の異なるテクスチャの集合です。ミップマップを生成することで、テクスチャのエイリアシングを軽減し、パフォーマンスを向上させることができます。

**6. 応用例とユースケース**

例えば、eコマースサイトで商品の3Dモデルを表示する場合、商品の質感をリアルに表現するために、高解像度のテクスチャを使用することがあります。しかし、高解像度のテクスチャはロードに時間がかかり、ユーザーエクスペリエンスを損なう可能性があります。このような場合、Lod (Level of Detail) を使用して、カメラからの距離に応じてテクスチャの解像度を調整することで、パフォーマンスと品質のバランスを取ることができます。

**7. トラブルシューティング**

*   **ブラウザの開発者ツールを使用する:**  ブラウザの開発者ツールで、テクスチャのロードに失敗しているか、エラーメッセージを確認します。
*   **テクスチャのサイズを確認する:**  テクスチャのサイズが大きすぎると、ロードに時間がかかり、ブラウザがクラッシュする可能性があります。適切なサイズのテクスチャを使用しましょう。
*   **テクスチャのフォーマットを確認する:**  Three.jsがサポートしているフォーマットかどうかを確認しましょう。WebPなどを使用する場合は、別途エンコーダーが必要になることがあります。
*   **キャッシュをクリアする:**  ブラウザのキャッシュに古いテクスチャが残っていると、新しいテクスチャが表示されないことがあります。キャッシュをクリアして、再度ロードを試みましょう。

**8. まとめと次のステップ**

テクスチャが表示されない問題は、パスの間違い、フォーマットの非対応、UVマッピングの問題など、様々な原因が考えられます。これらの原因を一つずつ丁寧に確認し、解決策を探しましょう。次のステップとして、様々なテクスチャローダーの使い方、UVマッピングの編集、テクスチャ圧縮技術などについて学習することで、より高度なテクスチャ表現をマスターできます。

### 13.4 モデルが正しく表示されない - スケール、回転、マテリアル

**1. 概要と重要性**

せっかく苦労して作成した3Dモデルが、Three.js上で意図した通りに表示されない…。これは、スケール、回転、マテリアルの設定ミスが原因であることが多いです。このセクションでは、これらの要素が正しく設定されているかを確認し、モデルを正しく表示させるためのテクニックを解説します。

**2. 特徴と利点**

このセクションを読むことで、Three.jsにおけるモデルの変換、マテリアルの設定に関する理解が深まり、モデルが正しく表示されない問題を迅速に解決できるようになります。また、モデルのスケール、回転、マテリアルを自在に操作することで、より表現力豊かな3Dシーンを作成できるようになります。

**3. 事前準備と前提条件**

*   Three.jsの基本的な使い方を理解していること
*   3Dモデリングツールに関する基本的な知識があること (Blender, Mayaなど)

**4. 基本的な使い方**

モデルをロードしてシーンに追加する基本的なコードは以下の通りです。ここではglTF形式のモデルを例に説明します。

```javascript
// glTFローダーの作成
const gltfLoader = new THREE.GLTFLoader();

// モデルのロード
gltfLoader.load(
  'models/your_model.glb', // モデルのパス
  function (gltf) { // ロード完了時のコールバック関数
    const model = gltf.scene; // モデルのシーンを取得

    // スケール、回転、位置を調整
    model.scale.set(0.1, 0.1, 0.1); // スケールを0.1倍に
    model.rotation.y = Math.PI / 2; // Y軸を中心に90度回転
    model.position.set(0, 0, 0); // 位置を原点に

    scene.add(model);
  },
  undefined, // ロード中のコールバック関数 (省略可能)
  function (error) { // エラー時のコールバック関数
    console.error('An error happened', error);
  }
);
```

**5. 実践的なテクニック**

*   **モデルのスケール、回転が正しいか:**  3Dモデリングツールで作成したモデルのスケールや回転が、Three.jsで表示する際に意図した通りになっているか確認します。スケールが大きすぎたり、小さすぎたりする場合は、`model.scale.set()` で調整します。回転が正しくない場合は、`model.rotation.set()` または `model.rotation.y` などで調整します。
*   **マテリアルが適切に設定されているか:**  モデルのマテリアルが、Three.jsでサポートされているマテリアルであるか、また、その設定が正しいかを確認します。`MeshBasicMaterial`、`MeshLambertMaterial`、`MeshPhongMaterial`などの様々なマテリアルを試してみて、最適なものを選びましょう。

**6. 応用例とユースケース**

例えば、オンラインゲームでキャラクターモデルを表示する場合、キャラクターの動きに合わせてモデルの回転やアニメーションを制御する必要があります。また、キャラクターの服装や装備を変更するために、マテリアルを動的に変更する必要もあります。

**7. トラブルシューティング**

*   **モデルのエクスポート設定を確認する:**  3Dモデリングツールからモデルをエクスポートする際に、スケール、回転、軸の設定などが正しいか確認します。特に、異なるツール間でモデルをやり取りする場合は、設定の違いに注意が必要です。
*   **原点の位置を確認する:**  モデルの原点の位置が、Three.jsで表示する際に意図した位置になっているか確認します。原点がずれていると、回転の中心がずれたり、位置がずれたりすることがあります。
*   **マテリアルの設定を確認する:**  マテリアルの色、テクスチャ、透明度などの設定が正しいか確認します。特に、ライティングの設定によっては、マテリアルの見え方が大きく変わることがあります。

**8. まとめと次のステップ**

モデルが正しく表示されない問題は、スケール、回転、マテリアルの設定ミスが原因であることが多いです。これらの要素を一つずつ丁寧に確認し、解決策を探しましょう。次のステップとして、Three.jsのアニメーション機能、シェーダーのカスタマイズ、物理エンジンとの連携などについて学習することで、よりインタラクティブでリアルな3Dシーンを作成できるようになります。
