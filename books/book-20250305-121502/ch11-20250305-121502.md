## 11. API連携：外部サービスとの連携でScriptableをパワーアップ

Scriptableは、その柔軟性とJavaScriptの記述能力によって、単なるショートカットツール以上の力を発揮します。特に、外部サービスとの連携機能は、Scriptableの可能性を飛躍的に高めます。本章では、REST APIの基礎からOAuth認証まで、外部サービスとの連携に必要な知識と具体的な方法を解説し、Scriptableをより強力なツールへと進化させる方法を学びます。

### 11.1. REST APIの基礎：APIの仕組みと使い方を理解する

**1. 概要と重要性**

API（Application Programming Interface）は、ソフトウェア同士が情報をやり取りするための共通のインターフェースです。特に、REST（Representational State Transfer）APIは、ウェブ上で広く利用されているAPI設計の原則であり、HTTPプロトコルを用いてデータにアクセスし、操作します。ScriptableでREST APIを活用することで、天気予報の取得、タスク管理、ニュースの表示など、様々な外部サービスの機能をScriptableに組み込むことができます。

**2. 特徴と利点**

*   **標準化されたインターフェース:** REST APIはHTTPメソッド（GET, POST, PUT, DELETEなど）を基盤としており、様々なプログラミング言語や環境で利用しやすいという特徴があります。
*   **データの取得と操作:** APIを通じて、外部サービスからデータを取得したり、逆にデータを送信したりできます。
*   **Scriptableとの親和性:** ScriptableはJavaScriptをベースとしているため、REST APIとの連携が非常に容易です。

**3. 事前準備と前提条件**

*   Scriptableのインストールと基本的な操作の理解。
*   HTTPプロトコルの基本的な理解（GET、POSTなど）。
*   JSON（JavaScript Object Notation）形式のデータの理解。

**4. 基本的な使い方**

ScriptableでREST APIを呼び出す基本的なコードは以下の通りです。

```javascript
let url = "https://jsonplaceholder.typicode.com/todos/1"; // サンプルAPI
let req = new Request(url);
let json = await req.loadJSON();

log(json); // 取得したJSONデータをログに出力

let title = json.title;
log("Title: " + title);

// Widgetに表示
let widget = new ListWidget();
widget.addText("Title: " + title);
Script.setWidget(widget);
Script.complete();
```

このコードは、`https://jsonplaceholder.typicode.com/todos/1`というAPIエンドポイントにGETリクエストを送信し、レスポンスとして返ってきたJSONデータを解析して、その中の"title"を表示しています。

**5. 実践的なテクニック**

*   **APIキーの管理:** APIによっては、APIキーが必要となる場合があります。APIキーはScriptableの`Keychain`を使って安全に保存し、管理することができます。

    ```javascript
    // APIキーをKeychainに保存
    Keychain.set("my_api_key", "YOUR_API_KEY");

    // APIキーをKeychainから取得
    let apiKey = Keychain.get("my_api_key");

    let url = "https://example.com/api?key=" + apiKey;
    ```

*   **エラーハンドリング:** APIリクエストが失敗した場合に備えて、try-catchブロックを使ってエラーハンドリングを行うことが重要です。

    ```javascript
    try {
        let url = "https://example.com/api";
        let req = new Request(url);
        let json = await req.loadJSON();
        log(json);
    } catch (error) {
        log("APIエラー: " + error);
        let alert = new Alert();
        alert.message = "APIリクエストでエラーが発生しました。\n" + error;
        alert.presentAlert();
    }
    ```

*   **パラメータのエンコード:** APIにパラメータを渡す際、URLエンコードが必要となる場合があります。JavaScriptの`encodeURIComponent()`関数を使用すると、簡単にURLエンコードを行うことができます。

    ```javascript
    let query = "検索キーワード";
    let encodedQuery = encodeURIComponent(query);
    let url = "https://example.com/api?q=" + encodedQuery;
    ```

**6. 応用例とユースケース**

*   **天気予報ウィジェット:** OpenWeatherMap APIを利用して、現在地の天気予報を表示するウィジェットを作成できます。
*   **株価表示ウィジェット:** 金融APIを利用して、特定の株価を表示するウィジェットを作成できます。
*   **ニュース表示ウィジェット:** ニュースAPIを利用して、最新のニュースを表示するウィジェットを作成できます。
*   **ToDoリスト連携:** Todoistなどのタスク管理APIを利用して、タスクの追加や完了処理をScriptableから行うことができます。

**7. トラブルシューティング**

*   **CORSエラー:** ブラウザのセキュリティ制限により、異なるドメインからのAPIリクエストが制限される場合があります（CORS）。この場合、APIがCORSを許可しているか、またはプロキシサーバーを経由する必要があります。Scriptable自体はネイティブアプリなのでCORSの影響を受けにくいですが、複雑な処理を伴う場合、一度バックエンドサーバーを経由する構成も検討すると良いでしょう。
*   **APIキーの有効期限切れ:** APIキーには有効期限がある場合があります。APIキーが有効であることを確認してください。
*   **レート制限:** APIによっては、一定時間内にリクエストできる回数に制限があります（レート制限）。レート制限を超えないように、リクエスト間隔を調整してください。

**8. まとめと次のステップ**

REST APIの基礎を理解し、ScriptableでAPIを呼び出す方法を学びました。次は、APIから取得したJSONデータを解析する方法について詳しく見ていきましょう。

### 11.2. JSONデータの解析：APIから取得したJSONデータを扱う

**1. 概要と重要性**

JSON（JavaScript Object Notation）は、軽量なデータ交換フォーマットであり、APIレスポンスとして最も一般的に使用されます。ScriptableでAPIから取得したデータを活用するためには、JSONデータを解析し、必要な情報を抽出する必要があります。

**2. 特徴と利点**

*   **人間にとって読みやすい:** JSONはキーと値のペアで構成されており、構造が理解しやすい。
*   **機械にとって解析しやすい:** JSONはJavaScriptオブジェクトに簡単に変換できるため、プログラムで扱いやすい。
*   **様々なプログラミング言語でサポート:** ほとんどのプログラミング言語でJSONの解析ライブラリが提供されている。

**3. 事前準備と前提条件**

*   JSON形式の基本的な理解。
*   JavaScriptのオブジェクトと配列の操作の理解。
*   前のセクション（11.1）で学んだREST APIの基本的な使い方。

**4. 基本的な使い方**

APIから取得したJSONデータは、`req.loadJSON()`メソッドでJavaScriptオブジェクトに変換されます。

```javascript
let url = "https://jsonplaceholder.typicode.com/todos/1";
let req = new Request(url);
let json = await req.loadJSON();

// JSONデータの解析
let userId = json.userId;
let id = json.id;
let title = json.title;
let completed = json.completed;

log("User ID: " + userId);
log("ID: " + id);
log("Title: " + title);
log("Completed: " + completed);
```

**5. 実践的なテクニック**

*   **ネストされたJSONデータの解析:** JSONデータがネストされている場合、ドット表記またはブラケット表記を使って、階層的にアクセスできます。

    ```javascript
    let json = {
        "user": {
            "id": 123,
            "name": "John Doe",
            "address": {
                "street": "123 Main St",
                "city": "Anytown"
            }
        }
    };

    let userName = json.user.name;
    let userCity = json.user.address.city;

    log("User Name: " + userName);
    log("User City: " + userCity);
    ```

*   **配列データの処理:** JSONデータに配列が含まれている場合、forループやforEachメソッドを使って、配列の要素を一つずつ処理できます。

    ```javascript
    let json = {
        "items": [
            {"name": "Apple", "price": 100},
            {"name": "Banana", "price": 50},
            {"name": "Orange", "price": 75}
        ]
    };

    json.items.forEach(item => {
        log("Name: " + item.name + ", Price: " + item.price);
    });
    ```

*   **存在しないキーへのアクセス:** JSONデータに存在しないキーにアクセスしようとすると、`undefined`が返されます。条件分岐を使って、キーの存在を確認してからアクセスすると、エラーを回避できます。

    ```javascript
    let json = {
        "name": "John Doe"
    };

    if (json.age !== undefined) {
        log("Age: " + json.age);
    } else {
        log("Age is not defined.");
    }
    ```

**6. 応用例とユースケース**

*   **為替レート表示ウィジェット:** 為替APIから取得したJSONデータを解析し、特定通貨の為替レートを表示するウィジェットを作成できます。
*   **ニュース記事表示ウィジェット:** ニュースAPIから取得したJSONデータを解析し、ニュース記事のタイトルと概要を表示するウィジェットを作成できます。
*   **レシピ表示ウィジェット:** レシピAPIから取得したJSONデータを解析し、材料と作り方を表示するウィジェットを作成できます。

**7. トラブルシューティング**

*   **JSONデータの形式が不正:** JSONデータが正しい形式でない場合、`req.loadJSON()`メソッドでエラーが発生します。JSONLintなどのツールを使って、JSONデータの形式を検証してください。
*   **キーのスペルミス:** JSONデータのキーのスペルミスがあると、正しい値を取得できません。キーのスペルを正確に確認してください。
*   **データ型の不一致:** JSONデータの値の型が期待するものと異なる場合、エラーが発生する可能性があります。データ型を正しく確認し、必要に応じて型変換を行ってください。例えば、文字列として返ってくる数値を `parseInt()` や `parseFloat()` で数値型に変換するなど。

**8. まとめと次のステップ**

JSONデータの解析方法を学びました。次は、APIにデータを送信するPOSTリクエストについて詳しく見ていきましょう。

### 11.3. POSTリクエスト：APIにデータを送信する

**1. 概要と重要性**

POSTリクエストは、APIにデータを送信するために使用されます。ScriptableでPOSTリクエストを送信することで、タスクの追加、メッセージの送信、データの更新など、外部サービスの機能をScriptableから操作できます。

**2. 特徴と利点**

*   **データの送信:** POSTリクエストは、APIにデータを送信するための主要な方法です。
*   **様々なデータ形式のサポート:** POSTリクエストでは、JSON、XML、フォームデータなど、様々なデータ形式を送信できます。
*   **データの作成と更新:** POSTリクエストは、新しいデータを作成したり、既存のデータを更新したりするために使用できます。

**3. 事前準備と前提条件**

*   HTTPメソッド（POST）の基本的な理解。
*   JSON形式の基本的な理解。
*   前のセクション（11.1, 11.2）で学んだREST APIの基本的な使い方とJSONデータの解析方法。

**4. 基本的な使い方**

ScriptableでPOSTリクエストを送信する基本的なコードは以下の通りです。

```javascript
let url = "https://jsonplaceholder.typicode.com/posts";
let req = new Request(url);

// リクエストヘッダーの設定
req.method = "POST";
req.headers = {
    "Content-Type": "application/json"
};

// リクエストボディの設定
let data = {
    "userId": 1,
    "title": "Scriptable POST Request",
    "body": "This is a test POST request from Scriptable."
};
req.body = JSON.stringify(data);

// リクエストの送信
let json = await req.loadJSON();

log(json); // レスポンスデータをログに出力
```

このコードは、`https://jsonplaceholder.typicode.com/posts`というAPIエンドポイントにPOSTリクエストを送信し、JSON形式のデータを送信しています。

**5. 実践的なテクニック**

*   **FormDataの送信:** フォームデータを送信する場合は、`URLSearchParams`オブジェクトを使用します。

    ```javascript
    let url = "https://example.com/api/login";
    let req = new Request(url);

    req.method = "POST";
    req.headers = {
        "Content-Type": "application/x-www-form-urlencoded"
    };

    let formData = new URLSearchParams();
    formData.append("username", "myuser");
    formData.append("password", "mypassword");

    req.body = formData.toString();

    let json = await req.loadJSON();
    log(json);
    ```

*   **認証ヘッダーの追加:** APIによっては、認証ヘッダーが必要となる場合があります。認証ヘッダーは、`req.headers`に追加します。

    ```javascript
    let url = "https://example.com/api/protected";
    let req = new Request(url);

    req.method = "POST";
    req.headers = {
        "Authorization": "Bearer " + "YOUR_ACCESS_TOKEN",
        "Content-Type": "application/json"
    };

    let data = {
        "message": "Hello, API!"
    };
    req.body = JSON.stringify(data);

    let json = await req.loadJSON();
    log(json);
    ```

*   **エラーハンドリング:** POSTリクエストが失敗した場合に備えて、try-catchブロックを使ってエラーハンドリングを行うことが重要です（11.1と同様）。

**6. 応用例とユースケース**

*   **タスク管理アプリへのタスク追加:** Todoistなどのタスク管理APIにPOSTリクエストを送信して、新しいタスクを追加できます。
*   **チャットアプリへのメッセージ送信:** SlackなどのチャットAPIにPOSTリクエストを送信して、メッセージを送信できます。
*   **データベースへのデータ登録:** FirebaseなどのデータベースAPIにPOSTリクエストを送信して、新しいデータを登録できます。
*   **IFTTTとの連携:** IFTTTのWebhookにPOSTリクエストを送信することで、様々なサービスと連携した自動化を実現できます。

**7. トラブルシューティング**

*   **Content-Typeの間違い:** 送信するデータの形式とContent-Typeが一致しない場合、APIがデータを正しく処理できない場合があります。Content-Typeを正しく設定してください。例えば、JSONデータを送信する場合は`application/json`、フォームデータを送信する場合は`application/x-www-form-urlencoded`を設定します。
*   **リクエストボディの形式が不正:** リクエストボディの形式がAPIの仕様と異なる場合、エラーが発生する可能性があります。APIのドキュメントを参照して、正しい形式でデータを送信してください。
*   **APIのレート制限:** POSTリクエストも、APIのレート制限の対象となる場合があります。レート制限を超えないように、リクエスト間隔を調整してください。
*   **API側のエラー:** API側に問題がある場合、POSTリクエストが失敗する可能性があります。APIの状態を確認するか、APIの提供元に問い合わせてください。HTTPステータスコード(500番台など)が返ってきた場合は、API側の問題である可能性が高いです。

**8. まとめと次のステップ**

POSTリクエストの送信方法を学びました。次は、APIを利用するための認証方法であるOAuth認証について詳しく見ていきましょう。

### 11.4. OAuth認証：APIを利用するための認証方法

**1. 概要と重要性**

OAuth（Open Authorization）は、ユーザー名とパスワードを共有せずに、あるサービス（Scriptable）から別のサービス（API）へのアクセスを許可するための標準的な認証プロトコルです。多くのAPIがOAuth認証を必要とするため、ScriptableでAPI連携を行う上で、OAuth認証の理解は不可欠です。

**2. 特徴と利点**

*   **安全性の向上:** ユーザー名とパスワードを共有せずに、APIへのアクセスを許可できるため、セキュリティが向上します。
*   **柔軟なアクセス制御:** アクセス許可の範囲を限定できるため、ユーザーは自分のデータをより細かく管理できます。
*   **標準化された認証プロトコル:** OAuthは広く利用されている標準的な認証プロトコルであり、様々なAPIで利用できます。

**3. 事前準備と前提条件**

*   OAuthの基本的な概念の理解（認可サーバー、リソースサーバー、クライアントなど）。
*   APIプロバイダーが提供するOAuthクライアントの登録。
*   前のセクション（11.1, 11.2, 11.3）で学んだREST APIの基本的な使い方、JSONデータの解析方法、POSTリクエストの送信方法。

**4. 基本的な使い方**

OAuth認証の基本的な流れは以下の通りです。

1.  **認可リクエスト:** ScriptableからAPIの認可サーバーに認可リクエストを送信します。
2.  **ユーザーの認証と認可:** 認可サーバーはユーザーに認証を求め、ScriptableにAPIへのアクセスを許可するかどうかを確認します。
3.  **認可コードの取得:** ユーザーがアクセスを許可した場合、認可サーバーはScriptableに認可コードを返します。
4.  **アクセストークンの取得:** Scriptableは認可コードを使って、認可サーバーからアクセストークンを取得します。
5.  **APIリクエスト:** Scriptableはアクセストークンを使って、APIリソースサーバーにAPIリクエストを送信します。

ScriptableでOAuth認証を行うための具体的なコードは、APIプロバイダーによって異なります。多くのAPIプロバイダーは、OAuth認証を簡素化するためのライブラリやSDKを提供しています。

ここでは、一般的なOAuth認証の流れを示す例として、`URLScheme` を利用した認証フローのイメージを記述します。**このコードはあくまで概念を示すもので、実際の動作にはOAuthライブラリなどの追加実装が必要となる場合があります。**

```javascript
// APIプロバイダーから取得したクライアントID、クライアントシークレット、リダイレクトURI
const clientId = "YOUR_CLIENT_ID";
const clientSecret = "YOUR_CLIENT_SECRET";
const redirectUri = "scriptable:///oauth-callback"; // ScriptableのURL Scheme

// 認可エンドポイント
const authorizationEndpoint = "https://example.com/oauth2/authorize";

// アクセストークンエンドポイント
const tokenEndpoint = "https://example.com/oauth2/token";

// 認可リクエストURLの作成
const authorizationUrl = `${authorizationEndpoint}?client_id=${clientId}&redirect_uri=${encodeURIComponent(redirectUri)}&response_type=code&scope=read,write`;

// URLスキームでブラウザを開き、認可ページを表示
Safari.open(authorizationUrl);

// ユーザーが認可を完了すると、ScriptableのURLスキームが呼び出される
// URLスキームのコールバックで、認可コードを取得する
// (ScriptableのURLスキームハンドラーに実装が必要)

// 認可コードを取得する関数 (これはあくまで例)
async function handleOAuthCallback(url) {
  const urlComponents = new URL(url);
  const code = urlComponents.searchParams.get("code");

  if (code) {
    // アクセストークンをリクエスト
    const tokenResponse = await requestAccessToken(code);
    log(tokenResponse);
    // アクセストークンを保存
    Keychain.set("accessToken", tokenResponse.access_token);
  } else {
    log("Authorization failed.");
  }
}

// アクセストークンをリクエストする関数
async function requestAccessToken(code) {
  const req = new Request(tokenEndpoint);
  req.method = "POST";
  req.headers = {
    "Content-Type": "application/x-www-form-urlencoded"
  };
  req.body = `grant_type=authorization_code&code=${code}&redirect_uri=${encodeURIComponent(redirectUri)}&client_id=${clientId}&client_secret=${clientSecret}`;

  const json = await req.loadJSON();
  return json;
}

// OAuthコールバックURLの例 (実際のScriptableのURLスキームハンドラーに実装)
// scriptable:///oauth-callback?code=YOUR_AUTHORIZATION_CODE
```

このコードは、ユーザーをAPIプロバイダーの認可ページにリダイレクトし、認可コードを取得して、アクセストークンをリクエストする流れを示しています。

**5. 実践的なテクニック**

*   **アクセストークンの保存:** 取得したアクセストークンは、`Keychain`を使って安全に保存し、管理することが重要です。
*   **アクセストークンのリフレッシュ:** アクセストークンには有効期限があるため、期限切れになった場合は、リフレッシュトークンを使って新しいアクセストークンを取得する必要があります。

    ```javascript
    // アクセストークンのリフレッシュ
    async function refreshAccessToken() {
        let refreshToken = Keychain.get("refreshToken");
        let url = "https://example.com/oauth2/token";
        let req = new Request(url);
        req.method = "POST";
        req.headers = {
            "Content-Type": "application/x-www-form-urlencoded"
        };
        req.body = `grant_type=refresh_token&refresh_token=${refreshToken}&client_id=${clientId}&client_secret=${clientSecret}`;

        let json = await req.loadJSON();
        Keychain.set("accessToken", json.access_token);
        // 新しいリフレッシュトークンが返ってきた場合は更新
        if (json.refresh_token) {
            Keychain.set("refreshToken", json.refresh_token);
        }
        return json.access_token;
    }
    ```

*   **OAuthライブラリの利用:** 複雑なOAuth認証処理を簡素化するために、OAuthライブラリの利用を検討してください。現状Scriptable向けのOAuthライブラリは少ないため、もし見つからない場合は、上記のように自力で実装する必要があります。

**6. 応用例とユースケース**

**4. 具体的な連携例**

**a. Twitterとの連携**

*   **ユースケース:** タイムラインの表示、ツイートの投稿。
*   **API:** Twitter API v2。
*   **認証:** OAuth 2.0。

```javascript
// Twitter APIの認証情報（要設定）
const apiKey = Keychain.get("twitter_api_key");
const apiSecret = Keychain.get("twitter_api_secret");
const accessToken = Keychain.get("twitter_access_token");
const accessTokenSecret = Keychain.get("twitter_access_token_secret");

// タイムラインを取得する関数
async function getTimeline() {
    let url = "https://api.twitter.com/2/users/me/tweets"; // 自分のツイートを取得
    let req = new Request(url);
    req.headers = {
        "Authorization": `Bearer ${accessToken}` // OAuth2.0 Bearer Token
    };

    try {
        let json = await req.loadJSON();
        return json.data;
    } catch (error) {
        log("Twitter API Error: " + error);
        return null;
    }
}

// タイムラインを表示する関数
async function displayTimeline() {
    let tweets = await getTimeline();

    if (tweets) {
        let widget = new ListWidget();
        widget.addText("Twitter Timeline");

        for (let tweet of tweets) {
            widget.addText(tweet.text);
        }

        Script.setWidget(widget);
        Script.complete();
    } else {
        log("Failed to fetch timeline.");
        Script.complete();
    }
}

await displayTimeline();
```

**b. Google Sheetsとの連携**

*   **ユースケース:** スプレッドシートの読み書き。
*   **API:** Google Sheets API。
*   **認証:** OAuth 2.0。

```javascript
// Google Sheets APIの認証情報（要設定）
const spreadsheetId = "YOUR_SPREADSHEET_ID";
const apiKey = Keychain.get("google_sheets_api_key");
const accessToken = Keychain.get("google_sheets_access_token");

// スプレッドシートからデータを読み込む関数
async function readSheet() {
    let url = `https://sheets.googleapis.com/v4/spreadsheets/${spreadsheetId}/values/Sheet1!A1:B2?key=${apiKey}`;
    let req = new Request(url);
    req.headers = {
        "Authorization": `Bearer ${accessToken}`
    };

    try {
        let json = await req.loadJSON();
        return json.values;
    } catch (error) {
        log("Google Sheets API Error: " + error);
        return null;
    }
}

// データを表示する関数
async function displaySheetData() {
    let data = await readSheet();

    if (data) {
        let widget = new ListWidget();
        widget.addText("Google Sheets Data");

        for (let row of data) {
            widget.addText(row.join(", "));
        }

        Script.setWidget(widget);
        Script.complete();
    } else {
        log("Failed to fetch sheet data.");
        Script.complete();
    }
}

await displaySheetData();
```

**c. IFTTTとの連携**

*   **ユースケース:** 特定の条件が満たされた場合に、IFTTTのWebhookをトリガーする。
*   **API:** IFTTT Webhooks。
*   **認証:** Webhooksキー。

```javascript
// IFTTT Webhooksの認証情報（要設定）
const iftttWebhookUrl = "https://maker.ifttt.com/trigger/{event}/with/key/{YOUR_IFTTT_KEY}";
const iftttEventName = "my_event"; // IFTTTで設定したイベント名

// IFTTT Webhookをトリガーする関数
async function triggerIfttt() {
    let url = iftttWebhookUrl.replace("{event}", iftttEventName).replace("{YOUR_IFTTT_KEY}", Keychain.get("ifttt_webhook_key"));
    let req = new Request(url);
    req.method = "POST";
    req.headers = {
        "Content-Type": "application/json"
    };
    req.body = JSON.stringify({
        "value1": "Scriptable",
        "value2": "IFTTT",
        "value3": "Webhook"
    });

    try {
        let json = await req.loadJSON();
        log("IFTTT Webhook Triggered: " + JSON.stringify(json)); // IFTTTからのレスポンスをログ出力
    } catch (error) {
        log("IFTTT Webhook Error: " + error);
    }
}

await triggerIfttt();
```

**5. 実践的なテクニック**

*   **APIのドキュメントを熟読する:** 各APIのドキュメントには、APIの仕様、認証方法、利用制限などが詳しく記載されています。APIを正しく利用するためには、ドキュメントを熟読することが重要です。
*   **エラーハンドリングを徹底する:** APIリクエストが失敗した場合に備えて、try-catchブロックを使ってエラーハンドリングを行うことが重要です。
*   **APIキーの管理を徹底する:** APIキーは、Scriptableの`Keychain`を使って安全に保存し、管理することが重要です。
*   **レート制限を考慮する:** APIによっては、一定時間内にリクエストできる回数に制限があります（レート制限）。レート制限を超えないように、リクエスト間隔を調整してください。
*   **ログ出力を活用する:** `log()`関数を使って、APIリクエストの結果や変数の値をログに出力することで、デバッグを効率的に行うことができます。
