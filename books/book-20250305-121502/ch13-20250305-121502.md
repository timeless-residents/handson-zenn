## 13. URLスキーム：アプリ間連携の魔法

### 13.1. URLスキームとは：アプリを起動するための特別なURL

**概要と重要性**

URLスキームとは、Webブラウザだけでなく、特定のアプリを直接起動できる特別なURLのことです。Webサイトのアドレスが `https://` や `http://` で始まるように、アプリを起動するURLは、アプリ固有のスキームで始まります。例えば、メールアプリなら `mailto:` 、電話アプリなら `tel:` といった具合です。

このURLスキームを理解し使いこなすことで、Scriptableから他のアプリを起動したり、逆に他のアプリからScriptableを起動したりと、アプリ間連携の可能性が大きく広がります。これは、iOSやiPadOSの強力な機能の一つであり、ワークフローを自動化する上で非常に重要な役割を果たします。

**特徴と利点**

*   **アプリの直接起動:** URLスキームを使用すると、ユーザーはWebブラウザを経由せずに、特定のアプリを直接開くことができます。
*   **特定機能の実行:** アプリによっては、URLスキームで起動する際に特定のパラメータを渡すことができ、アプリ内の特定の機能を直接実行させることが可能です。例えば、メールアプリを特定の宛先で新規メール作成画面を開いたり、マップアプリで特定の場所を検索したりできます。
*   **自動化の実現:** Scriptableのような自動化アプリと組み合わせることで、タスクを自動化し、日々の作業効率を向上させることができます。

**事前準備と前提条件**

*   iOSまたはiPadOSデバイス
*   Scriptableアプリのインストール (App Storeから無料でダウンロード可能)
*   連携したいアプリがURLスキームに対応していること (多くの主要アプリは対応していますが、念のため確認が必要です)

**基本的な使い方**

ScriptableでURLスキームを使ってアプリを起動するには、`URLScheme.openURL(url)` 関数を使用します。 `url` 引数には、起動したいアプリのURLスキームを文字列で指定します。

```javascript
// メールアプリを起動する例
let mailUrl = "mailto:test@example.com?subject=Hello&body=This is a test email.";
URLScheme.openURL(mailUrl);

// 電話アプリを起動する例 (発信前に確認ダイアログが表示されます)
let telUrl = "tel:0123456789";
URLScheme.openURL(telUrl);

// SafariでGoogleを開く例
let safariUrl = "https://www.google.com";
URLScheme.openURL(safariUrl);
```

**実践的なテクニック**

*   **URLエンコード:** URLに日本語や特殊文字を含める場合は、URLエンコードを行う必要があります。JavaScriptの`encodeURIComponent()`関数を使うと便利です。
*   **条件分岐:** `URLScheme.canOpenURL(url)` 関数を使うと、指定したURLスキームに対応するアプリがインストールされているかどうかを確認できます。これを利用して、アプリがインストールされている場合にのみURLスキームを実行するように条件分岐を作成できます。

```javascript
// LINEアプリがインストールされているか確認し、インストールされている場合のみ起動する
let lineUrl = "line://msg/text/Hello%20from%20Scriptable!";
if (URLScheme.canOpenURL(lineUrl)) {
  URLScheme.openURL(lineUrl);
} else {
  console.log("LINEアプリがインストールされていません。");
  let alert = new Alert();
  alert.title = "LINE";
  alert.message = "LINEアプリがインストールされていません。\nApp Storeからインストールしてください。";
  alert.addAction("OK");
  alert.presentAlert();
}
```

**応用例とユースケース**

*   **リマインダーアプリにタスクを追加:** URLスキームを利用して、Scriptableからリマインダーアプリに新しいタスクを自動的に追加できます。
*   **カレンダーアプリに予定を追加:** 同様に、カレンダーアプリに予定を自動的に追加することも可能です。
*   **特定の場所をGoogle Mapsで開く:** 現在地情報と組み合わせて、特定の場所をGoogle Mapsで自動的に開くことができます。
*   **SNSへの投稿を自動化:** URLスキームに対応したSNSアプリ (Twitter, Facebookなど) を利用して、投稿を自動化できます。

**トラブルシューティング**

*   **URLスキームが正しくない:** スペルミスや大文字小文字の区別、不要なスペースなど、URLスキームが正しく記述されているか確認してください。
*   **アプリがURLスキームに対応していない:** 対象のアプリがURLスキームに対応しているか、アプリのドキュメントやWebサイトで確認してください。
*   **セキュリティ設定:** iOSの設定で、アプリが他のアプリを起動することを許可しているか確認してください。(設定 -> プライバシー -> [連携したいアプリ] -> 他のAppとの連携)

**まとめと次のステップ**

URLスキームは、Scriptableを使った自動化の強力な武器です。様々なアプリのURLスキームを調べて、自分だけの便利なワークフローを作成してみてください。 次のセクションでは、よく使うURLスキームについて詳しく解説します。

### 13.2. よく使うURLスキーム：メール、電話、メッセージ、マップ…

**概要と重要性**

前のセクションでURLスキームの基本的な使い方を学びました。このセクションでは、特によく使うURLスキームについて詳しく解説します。これらのURLスキームをマスターすることで、Scriptableから様々なアプリを自在に操り、さらに高度な自動化を実現することができます。

**特徴と利点**

*   **利便性の向上:** 日常的に利用するアプリをScriptableから直接操作することで、作業効率が大幅に向上します。
*   **カスタマイズ性:** 各URLスキームには様々なパラメータを指定できるため、ニーズに合わせて柔軟にカスタマイズできます。
*   **多様な連携:** メール、電話、メッセージ、マップなど、様々なアプリとの連携が可能になります。

**事前準備と前提条件**

*   iOSまたはiPadOSデバイス
*   Scriptableアプリのインストール
*   連携したいアプリがインストールされていること (当然ですが)

**基本的な使い方**

以下に、よく使うURLスキームとその使い方をまとめます。

*   **メール (mailto:)**

    *   **基本的な形式:** `mailto:<メールアドレス>?subject=<件名>&body=<本文>`
    *   **例:** `mailto:test@example.com?subject=Hello&body=This is a test email.`
    *   **パラメータ:**
        *   `to`: 宛先メールアドレス (複数指定する場合はカンマ区切り)
        *   `cc`: CC宛先メールアドレス (複数指定する場合はカンマ区切り)
        *   `bcc`: BCC宛先メールアドレス (複数指定する場合はカンマ区切り)
        *   `subject`: 件名
        *   `body`: 本文
    *   **注意点:** 本文に改行を含める場合は、`%0D%0A` でエンコードする必要があります。
*   **電話 (tel:)**

    *   **基本的な形式:** `tel:<電話番号>`
    *   **例:** `tel:0123456789`
    *   **注意点:** 発信前に確認ダイアログが表示されます。
*   **メッセージ (sms:)**

    *   **基本的な形式:** `sms:<電話番号>&body=<メッセージ本文>`
    *   **例:** `sms:0123456789&body=Hello from Scriptable!`
*   **マップ (maps:)**

    *   **基本的な形式:** `maps://?q=<検索キーワード>` または `maps://?daddr=<目的地の住所>&saddr=<出発地の住所>`
    *   **例:**
        *   `maps://?q=ラーメン`
        *   `maps://?daddr=東京都庁&saddr=新宿駅`
    *   **パラメータ:**
        *   `q`: 検索キーワード
        *   `daddr`: 目的地の住所
        *   `saddr`: 出発地の住所
        *   `ll`: 緯度,経度 (例: `ll=35.6895,139.6917`)
        *   `z`: ズームレベル (1-20)
*   **Safari (https://, http://)**

    *   **基本的な形式:** `https://<URL>` または `http://<URL>`
    *   **例:**
        *   `https://www.google.com`
        *   `http://example.com`

**実践的なテクニック**

*   **現在地情報の取得とマップ連携:** `Location.current()` 関数で現在地情報を取得し、その情報を `maps://` URLスキームに組み込むことで、現在地から目的地までの経路を自動的に表示させることができます。
*   **連絡先アプリとの連携:** 連絡先アプリのURLスキームを利用して、特定の連絡先の情報を表示したり、連絡先に電話をかけたりすることができます。(連絡先アプリのURLスキームは、`vcard://` などがあります。詳しくは後述します。)
*   **クリップボードの内容を本文に挿入:** クリップボードの内容を`Pasteboard.paste()`で取得し、それをメールやメッセージの本文に挿入することができます。

```javascript
// 現在地情報を取得してGoogle Mapsで表示する例
let location = await Location.current();
let latitude = location.latitude;
let longitude = location.longitude;
let mapsUrl = `maps://?ll=${latitude},${longitude}&z=15`;
URLScheme.openURL(mapsUrl);
```

**応用例とユースケース**

*   **毎朝のルーチン:** 天気予報を取得し、その情報をメールで自動送信する。
*   **会議のリマインダー:** 会議の開始時間前に、場所をGoogle Mapsで自動的に表示する。
*   **緊急時の連絡:** 現在地情報をメッセージで緊急連絡先に自動送信する。
*   **買い物リストの作成と共有:** Scriptableで買い物リストを作成し、それをメッセージアプリで家族や友人と共有する。

**トラブルシューティング**

*   **URLエンコードの問題:** URLに日本語や特殊文字が含まれている場合、URLエンコードが正しく行われているか確認してください。
*   **パラメータの誤り:** 各URLスキームで利用できるパラメータの種類や形式が正しいか、アプリのドキュメントやWebサイトで確認してください。
*   **プライバシー設定:** 位置情報や連絡先情報へのアクセス許可がScriptableに与えられているか確認してください。(設定 -> プライバシー -> [位置情報サービス/連絡先] -> Scriptable)

**まとめと次のステップ**

このセクションでは、よく使うURLスキームについて詳しく解説しました。これらのURLスキームを使いこなすことで、Scriptableの可能性はさらに広がります。次のセクションでは、カスタムURLスキームについて学び、さらに自由なアプリ連携を実現しましょう。

### 13.3. カスタムURLスキーム：Scriptableから他のアプリを起動

**概要と重要性**

これまでのセクションでは、一般的なURLスキームについて学びました。しかし、すべてのアプリが標準的なURLスキームに対応しているわけではありません。そこで重要になるのが、カスタムURLスキームです。カスタムURLスキームとは、特定のアプリが独自に定義したURLスキームのことです。

このセクションでは、カスタムURLスキームを使ってScriptableから他のアプリを起動する方法について詳しく解説します。これにより、標準的なURLスキームに対応していないアプリとも連携できるようになり、自動化の幅が格段に広がります。

**特徴と利点**

*   **より多くのアプリとの連携:** 標準的なURLスキームに対応していないアプリとも連携できるようになります。
*   **高度なカスタマイズ:** アプリによっては、カスタムURLスキームで起動する際に複雑なパラメータを渡すことができ、より高度な連携が可能です。
*   **独自のワークフロー:** 既存のURLスキームでは実現できない、独自のワークフローを作成できます。

**事前準備と前提条件**

*   iOSまたはiPadOSデバイス
*   Scriptableアプリのインストール
*   連携したいアプリがカスタムURLスキームに対応していること (重要!)
*   連携したいアプリのカスタムURLスキームの情報を事前に調べておくこと

**基本的な使い方**

カスタムURLスキームを使ってアプリを起動する基本的な流れは、標準的なURLスキームの場合と変わりません。`URLScheme.openURL(url)` 関数を使用します。

```javascript
// 例えば、Notionアプリを起動する例 (NotionのカスタムURLスキームは "notion://" )
let notionUrl = "notion://open";
URLScheme.openURL(notionUrl);
```

ただし、カスタムURLスキームはアプリによって形式が大きく異なるため、事前に情報を調べておく必要があります。アプリの公式サイト、開発者ドキュメント、またはインターネット検索で情報を探しましょう。

**実践的なテクニック**

*   **カスタムURLスキームの調べ方:**
    *   **アプリの公式サイトや開発者ドキュメント:** 最も確実な方法です。
    *   **インターネット検索:** "[アプリ名] URLスキーム" で検索してみましょう。
    *   **URLスキーム解析ツール:** 一部のツールは、インストールされたアプリのURLスキームを解析することができます。
*   **パラメータの指定:** カスタムURLスキームには、様々なパラメータを指定できる場合があります。パラメータの種類や形式はアプリによって異なるため、ドキュメントをよく読んで確認してください。
*   **URLエンコード:** カスタムURLスキームでも、URLに日本語や特殊文字を含める場合は、URLエンコードが必要です。

```javascript
// Obsidianアプリで特定のノートを開く例 (ObsidianのカスタムURLスキーム)
let vaultName = "MyVault";
let noteName = "Daily Note";
let obsidianUrl = `obsidian://open?vault=${encodeURIComponent(vaultName)}&file=${encodeURIComponent(noteName)}`;
URLScheme.openURL(obsidianUrl);
```

**応用例とユースケース**

*   **タスク管理アプリとの連携:** Todoist, Things, OmniFocusなどのタスク管理アプリのカスタムURLスキームを利用して、タスクの追加や編集を自動化できます。
*   **ノートアプリとの連携:** Bear, Evernote, Notion, ObsidianなどのノートアプリのカスタムURLスキームを利用して、ノートの作成や検索を自動化できます。
*   **クリップボード管理アプリとの連携:** Paste, Copiedなどのクリップボード管理アプリのカスタムURLスキームを利用して、クリップボードの内容を操作できます。
*   **ファイル管理アプリとの連携:** Documents, FileBrowserなどのファイル管理アプリのカスタムURLスキームを利用して、ファイルの操作を自動化できます。

**トラブルシューティング**

*   **カスタムURLスキームが間違っている:** スペルミスやパラメータの誤りなど、カスタムURLスキームが正しく記述されているか確認してください。
*   **アプリがカスタムURLスキームに対応していない:** 対象のアプリがカスタムURLスキームに対応しているか、アプリのドキュメントやWebサイトで確認してください。
*   **パラメータの形式が間違っている:** カスタムURLスキームで指定できるパラメータの種類や形式が正しいか、アプリのドキュメントやWebサイトで確認してください。
*  **セキュリティ上の制限:** 一部のアプリは、セキュリティ上の理由から、カスタムURLスキームでの動作に制限を設けている場合があります。

**まとめと次のステップ**

カスタムURLスキームを理解し使いこなすことで、Scriptableから様々なアプリを連携させ、高度な自動化を実現することができます。次のセクションでは、ScriptableからScriptableを起動する方法について学び、複数のスクリプトを連携させてより複雑なワークフローを構築しましょう。

### 13.4. ScriptableからScriptableを起動：複数のスクリプトを連携させる

**概要と重要性**

ここまでは、Scriptableから他のアプリを起動する方法について学んできました。しかし、Scriptableの真価は、複数のスクリプトを連携させることで発揮されます。このセクションでは、Scriptableから別のScriptableスクリプトを起動する方法について詳しく解説します。

複数のスクリプトを連携させることで、複雑なタスクを分割し、モジュール化された再利用可能なコードを作成できます。これにより、コードの保守性が向上し、より高度な自動化が可能になります。

**特徴と利点**

*   **コードのモジュール化:** 複雑なタスクを小さなスクリプトに分割し、コードを整理できます。
*   **コードの再利用性:** 複数のスクリプトで共通の処理を共有できます。
*   **ワークフローの複雑化:** より複雑な自動化ワークフローを構築できます。
*   **デバッグの容易化:** スクリプトを個別にテストできるため、デバッグが容易になります。

**事前準備と前提条件**

*   iOSまたはiPadOSデバイス
*   Scriptableアプリのインストール
*   連携したいScriptableスクリプトが既に作成されていること

**基本的な使い方**

Scriptableから別のScriptableスクリプトを起動するには、`scriptable:///run/<スクリプト名>` というURLスキームを使用します。`<スクリプト名>` には、起動したいスクリプトの名前を指定します。

```javascript
// "MySecondScript" という名前のスクリプトを起動する例
let scriptUrl = "scriptable:///run/MySecondScript";
URLScheme.openURL(scriptUrl);
```

**実践的なテクニック**

*   **パラメータの受け渡し:** 起動するスクリプトにパラメータを渡すには、`scriptable:///run/<スクリプト名>?<パラメータ名>=<値>` という形式でURLスキームを指定します。起動されるスクリプトでは、`args.plainTexts` 配列からパラメータの値を取得できます。

```javascript
// 起動する側のスクリプト
let scriptName = "MySecondScript";
let parameter1 = "Hello";
let parameter2 = "World";
let scriptUrl = `scriptable:///run/${scriptName}?param1=${encodeURIComponent(parameter1)}&param2=${encodeURIComponent(parameter2)}`;
URLScheme.openURL(scriptUrl);

// 起動される側のスクリプト (MySecondScript)
let param1 = args.plainTexts[0]; // "Hello"
let param2 = args.plainTexts[1]; // "World"
console.log(`param1: ${param1}`);
console.log(`param2: ${param2}`);
```

*   **JSON形式でのパラメータ渡し:** 複数のパラメータを渡す場合、JSON形式でパラメータを渡すと便利です。`args.plainTexts[0]` にJSON文字列が格納されるため、それを `JSON.parse()` で解析します。

```javascript
// 起動する側のスクリプト
let scriptName = "MySecondScript";
let parameters = {
  name: "John Doe",
  age: 30,
  city: "New York"
};
let jsonString = JSON.stringify(parameters);
let scriptUrl = `scriptable:///run/${scriptName}?data=${encodeURIComponent(jsonString)}`;
URLScheme.openURL(scriptUrl);

// 起動される側のスクリプト (MySecondScript)
let jsonString = args.plainTexts[0];
let data = JSON.parse(jsonString);
console.log(`Name: ${data.name}`);
console.log(`Age: ${data.age}`);
console.log(`City: ${data.city}`);
```

**応用例とユースケース**

*   **タスクの分割:** 天気予報を取得するスクリプトと、それを通知するスクリプトを別々に作成し、連携させる。
*   **共通処理の共有:** APIリクエストを行うスクリプトを作成し、複数のスクリプトから共有して利用する。
*   **複雑なワークフロー:** 複数のスクリプトを連携させて、一連のタスクを自動的に実行するワークフローを構築する。
    *   例えば、「毎朝7時に天気予報を取得し、今日の予定をカレンダーから取得し、それらをまとめてNotionに記録する」といった複雑なタスクを、複数のスクリプトに分割して連携させることができます。

**トラブルシューティング**

*   **スクリプト名が間違っている:** 起動したいスクリプトの名前が正しく記述されているか確認してください。
*   **パラメータのエンコード:** パラメータに特殊文字が含まれている場合、正しくURLエンコードされているか確認してください。
*   **パラメータの解析:** 起動される側のスクリプトで、パラメータが正しく解析されているか確認してください。`args.plainTexts` のインデックスが正しいか、JSON形式の場合は `JSON.parse()` が正しく動作しているかなどを確認します。
*   **スクリプトの実行権限:** スクリプトが他のスクリプトを実行することを許可しているか確認してください。(Scriptableの設定 -> スクリプト -> [連携したいスクリプト] -> 他のスクリプトを実行)

**まとめと次のステップ**

ScriptableからScriptableを起動する方法を学ぶことで、コードのモジュール化と再利用性が向上し、より複雑な自動化ワークフローを構築できるようになります。次のセクションでは、X-Callback-URLについて学び、連携したアプリからのコールバックを受け取る方法について解説します。

### 13.5. X-Callback-URL：連携したアプリからのコールバックを受け取る

**概要と重要性**

これまでのセクションでは、Scriptableから他のアプリを起動する方法について学んできました。しかし、アプリ間連携は一方通行ではありません。X-Callback-URLを使うと、連携したアプリからScriptableに結果を返す、つまり「コールバック」を受け取ることができます。

X-Callback-URLは、特にアプリ間のデータのやり取りや、処理結果の通知が必要な場合に非常に強力です。これにより、Scriptableでより高度なインタラクティブな自動化を実現できます。

**特徴と利点**

*   **双方向の連携:** アプリ間連携が一方通行ではなくなり、双方向のデータのやり取りが可能になります。
*   **処理結果の取得:** 連携したアプリでの処理結果をScriptableで取得し、利用できます。
*   **インタラクティブな自動化:** ユーザーの操作に応じて、動的に処理を分岐させることができます。

**事前準備と前提条件**

*   iOSまたはiPadOSデバイス
*   Scriptableアプリのインストール
*   連携したいアプリがX-Callback-URLに対応していること (重要!)
*   連携したいアプリのX-Callback-URLの情報を事前に調べておくこと

**基本的な使い方**

X-Callback-URLを使うには、連携するアプリのURLスキームに、以下のパラメータを追加します。

*   `x-success`: 処理が成功した場合に呼び出されるURL
*   `x-error`: 処理が失敗した場合に呼び出されるURL
*   `x-cancel`: 処理がキャンセルされた場合に呼び出されるURL

これらのURLには、Scriptableスクリプトを起動するためのURLスキーム (`scriptable:///run/<スクリプト名>`) を指定します。

```javascript
// 連携する側のスクリプト (例: Workflowyというアウトラインプロセッサアプリを起動する)
let workflowyUrl = "workflowy://x-callback-url/add?text=New%20item";
workflowyUrl += "&x-success=" + encodeURIComponent("scriptable:///run/SuccessCallback");
workflowyUrl += "&x-error=" + encodeURIComponent("scriptable:///run/ErrorCallback");
workflowyUrl += "&x-cancel=" + encodeURIComponent("scriptable:///run/CancelCallback");
URLScheme.openURL(workflowyUrl);

// 成功時のコールバックスクリプト (SuccessCallback)
let successMessage = "Workflowyへの追加に成功しました！";
let alert = new Alert();
alert.title = "成功";
alert.message = successMessage;
alert.addAction("OK");
await alert.presentAlert();

// 失敗時のコールバックスクリプト (ErrorCallback)
let errorMessage = "Workflowyへの追加に失敗しました...";
let alert = new Alert();
alert.title = "エラー";
alert.message = errorMessage;
alert.addAction("OK");
await alert.presentAlert();

// キャンセル時のコールバックスクリプト (CancelCallback)
let cancelMessage = "Workflowyへの追加がキャンセルされました。";
let alert = new Alert();
alert.title = "キャンセル";
alert.message = cancelMessage;
alert.addAction("OK");
await alert.presentAlert();
```

この例では、Workflowyというアプリに新しい項目を追加する処理を依頼し、成功、失敗、キャンセルの場合にそれぞれ異なるScriptableスクリプトが呼び出されます。

**実践的なテクニック**

*   **コールバックパラメータの受け渡し:** 連携するアプリによっては、コールバックURLにパラメータを付与して、処理結果の情報をScriptableに渡すことができます。

```javascript
// 連携する側のスクリプト
let workflowyUrl = "workflowy://x-callback-url/add?text=New%20item";
workflowyUrl += "&x-success=" + encodeURIComponent("scriptable:///run/SuccessCallback?result=[[result]]"); // Workflowyが[[result]]というプレースホルダーをサポートしている場合
URLScheme.openURL(workflowyUrl);

// 成功時のコールバックスクリプト (SuccessCallback)
let result = args.plainTexts[0]; // Workflowyから渡された結果
let successMessage = `Workflowyへの追加に成功しました！\n結果: ${result}`;
let alert = new Alert();
alert.title = "成功";
alert.message = successMessage;
alert.addAction("OK");
await alert.presentAlert();
```

*   **エラー処理の強化:** `x-error` コールバックでエラーコードやエラーメッセージを取得し、より詳細なエラーハンドリングを行うことができます。

**応用例とユースケース**

*   **タスク管理アプリとの連携:** タスク管理アプリにタスクを追加し、追加が完了したことをScriptableで確認する。
*   **テキストエディタとの連携:** テキストエディタでテキストを編集し、編集結果をScriptableで取得して、別の処理に利用する。
*   **画像編集アプリとの連携:** 画像編集アプリで画像を編集し、編集後の画像をScriptableで取得して、クラウドにアップロードする。
*   **認証処理の連携:** 連携するアプリで認証を行い、認証結果をScriptableに通知し、その結果に基づいて処理を分岐する。

**トラブルシューティング**

*   **X-Callback-URLに対応していない:** 連携したいアプリがX-Callback-URLに対応しているか、アプリのドキュメントやWebサイトで確認してください。
*   **コールバックURLが間違っている:** コールバックURLに指定したScriptableスクリプトの名前が正しいか、URLエンコードが正しく行われているか確認してください。
*   **コールバックパラメータの解析:** コールバックパラメータが正しく解析されているか確認してください。`args.plainTexts` のインデックスが正しいか、パラメータ名が正しいかなどを確認します。
*   **セキュリティ上の制限:** 一部のアプリは、セキュリティ上の理由から、X-Callback-URLでの動作に制限を設けている場合があります。

**まとめと次のステップ**

X-Callback-URLを理解し使いこなすことで、アプリ間連携の可能性がさらに広がります。連携したアプリからのコールバックを受け取り、それに基づいて処理を分岐させることで、より高度なインタラクティブな自動化を実現できます。

この章で学んだURLスキームの知識を活かして、自分だけの便利な自動化ワークフローを作成してみてください。Scriptableは、あなたの創造性を刺激し、日々の作業を効率化するための強力なツールとなるでしょう。
