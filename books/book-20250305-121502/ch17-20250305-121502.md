# 17. トラブルシューティング：よくある問題とその解決策（Scriptable編）

Scriptable を使ったスクリプト開発でも、ウィジェットが正しく表示されない、API リクエストでエラーが発生する、スクリプトが予期せず動作しないなど、さまざまなトラブルに直面することがあります。ここでは、iOS の Scriptable 環境における代表的な問題と、その原因・対策、デバッグのポイントを具体的なコード例とともに紹介します。

---

## 17.1. ウィジェットが表示されない：原因と対策

### 17.1.1. 概要

Scriptable で作成したウィジェットが実際にホーム画面に表示されない場合、以下の点を確認しましょう。  
ウィジェットは ListWidget オブジェクトで作成し、必ず `Script.setWidget(widget)` および `Script.complete()` を呼び出す必要があります。

### 17.1.2. 主な原因と対策

1. **ウィジェットオブジェクトが作成されていない、または設定ミス**  
   - **対策:** ウィジェット作成時に、必ず `new ListWidget()` でオブジェクトを作成し、内容を追加した後に `Script.setWidget(widget)` を実行する。

   ```javascript
   let widget = new ListWidget();
   widget.addText("Hello, Scriptable!");
   Script.setWidget(widget);
   Script.complete();
   ```

2. **スクリプトがウィジェットとして実行されていない**  
   - **対策:** Scriptable アプリ内で実行する場合と、ウィジェットとして実行する場合とで動作が異なるため、`config.runsInWidget` を利用して表示確認用のコードを追加する。

   ```javascript
   if (!config.runsInWidget) {
     widget.presentMedium();
   }
   ```

3. **ウィジェットのレイアウトやスタイルの問題**  
   - **対策:** ウィジェット内のテキストや画像のサイズ、配置、背景色などのスタイルを確認し、適切に設定する。

   ```javascript
   widget.backgroundColor = new Color("#ffffff");
   let title = widget.addText("Widget Title");
   title.font = Font.boldSystemFont(16);
   title.centerAlignText();
   ```

4. **ファイルやデータの読み込みエラー**  
   - **対策:** FileManager や Request でエラーが発生していないか、コンソールログで確認する。

### 17.1.3. デバッグのコツ

- **コンソールログの活用:**  
  `console.log()` を使って、各処理の前後で状態を出力することで、どこで問題が発生しているかを特定します。

  ```javascript
  console.log("ウィジェット作成開始");
  // ...ウィジェット作成コード...
  console.log("ウィジェット設定完了");
  ```

- **QuickLook の利用:**  
  作成したウィジェットの中身を確認するために、`QuickLook.present()` を利用する。

  ```javascript
  if (!config.runsInWidget) {
    QuickLook.present(widget);
  }
  ```

## 17.2. API エラーが発生する：エラーコードの意味と対処法

### 17.2.1. 概要

Scriptable では Request オブジェクトを使って Web API にアクセスします。API からのレスポンスがエラーコード (例：401, 404, 500 など) を返す場合、リクエストパラメータや認証情報の設定ミスが原因であることが多いです。

### 17.2.2. 対策例

以下は、API リクエスト時にエラーコードをチェックし、エラー内容をコンソールに出力する例です。

```javascript
async function fetchData(url, apiKey) {
  try {
    let req = new Request(url);
    req.headers = { 'X-API-Key': apiKey };
    let response = await req.load();
    // 正常なレスポンスの場合はここに来る
    return JSON.parse(response);
  } catch (error) {
    console.error("APIリクエストエラー:", error);
    // ここでエラーコードやエラーメッセージを解析し、対策を実装
    throw error;
  }
}

// 使用例
const apiUrl = "https://api.example.com/data";
const apiKey = "YOUR_API_KEY";

fetchData(apiUrl, apiKey)
  .then(data => {
    console.log("取得データ:", data);
  })
  .catch(error => {
    console.error("データ取得に失敗しました:", error);
  });
```

### 17.2.3. ポイント

- **エラーメッセージの確認:** API のレスポンスに含まれるエラーメッセージやコードを確認する。  
- **認証情報の見直し:** API キーやトークンが正しく設定されているか、期限切れではないか確認する。  
- **リクエストパラメータのチェック:** 必須パラメータが不足していないか、値が正しいか確認する。

## 17.3. スクリプトが正常に動作しない：デバッグのコツ

### 17.3.1. 概要

Scriptable スクリプトが期待通りに動作しない場合、コンソールログや QuickLook、ブレークポイントを活用して原因を追求します。

### 17.3.2. デバッグの手順

1. **エラーメッセージの確認**  
   - コンソールに出力されるエラーメッセージを注意深く読む。
2. **ログ出力の活用**  
   - 各処理前後に `console.log()` を配置し、処理の流れと変数の値を確認する。

   ```javascript
   console.log("処理開始: calculateSum");
   function calculateSum(a, b) {
     console.log("a =", a, "b =", b);
     let sum = a + b;
     console.log("sum =", sum);
     return sum;
   }
   calculateSum(5, 3);
   ```

3. **QuickLook で中身を確認**  
   - 生成したオブジェクトや画像ファイルなどは `QuickLook.present()` で内容を確認する。

4. **コードの分割とレビュー**  
   - 問題箇所を切り出して、個別にテストしながら原因を特定する。

### 17.3.3. 実践的なテクニック

- **小さな部品に分割:** 大きな処理を複数の小さな関数に分け、それぞれを個別にテストする。
- **変更履歴の管理:** Scriptable スクリプトはバージョン管理をしておくと、どの変更が問題を引き起こしたか追跡しやすくなります。

## 17.4. メモリ不足エラー：メモリを節約する方法

### 17.4.1. 概要

Scriptable で大量のデータや画像を扱う場合、メモリ不足エラーが発生する可能性があります。iOS のリソース制約の中で効率的にメモリを使用するための対策が必要です。

### 17.4.2. 対策例

1. **データの分割読み込み**  
   - 画像などの大きなデータは、必要な部分だけを読み込むように工夫する。

2. **不要なオブジェクトの解放**  
   - 使用済みの変数を `null` に設定するなどして、ガベージコレクションが実行されるようにする。

   ```javascript
   let largeData = new Array(1000000).fill(1);
   // 処理後
   largeData = null;
   ```

3. **画像のリサイズとキャッシュ**  
   - 画像を表示する際は、必要最小限のサイズにリサイズし、キャッシュを活用する。

   ※ 15.3 で紹介した画像リサイズスクリプトを参照

### 17.4.3. 実践的なテクニック

- **オブジェクトプーリング:** 頻繁に生成・破棄するオブジェクトは、プールから再利用する仕組みを検討する。
- **不要データの削除:** FileManager を使って不要なファイルを定期的に削除する。

## 17.5. バージョンアップによる不具合：過去バージョンに戻す方法

### 17.5.1. 概要

Scriptable のスクリプトは、バージョン管理（例えば Git）で管理することが可能です。スクリプトを更新した結果、動作に問題が生じた場合は、過去の安定版に戻すことで迅速に対応できます。

### 17.5.2. 対策例

1. **Git での管理**  
   - 変更前に必ずコミットし、問題発生時は `git checkout <コミットハッシュ>` で以前の状態に戻す。

   ```bash
   git log
   git checkout <コミットハッシュ>
   ```

2. **バックアップからの復元**  
   - 事前にバックアップを取っておき、問題発生時に復元する。

3. **デプロイメントツールの利用**  
   - Scriptable の場合、コードは iCloud や GitHub で管理できるため、安定版に切り替える運用を行う。

### 17.5.3. 実践的なテクニック

- **ブルーグリーンデプロイメント:** 新旧スクリプトを併用し、問題があればすぐに旧バージョンに切り替える。
- **カナリアリリース:** 新しいスクリプトの変更を段階的に適用し、不具合の影響範囲を限定する。

## 総まとめと展望

Scriptable を利用した自動化スクリプトの開発では、ウィジェットの表示や API 連携、ファイル操作など、さまざまな側面でトラブルが発生することがあります。  
今回紹介したトラブルシューティングの手法を参考に、以下のポイントを意識して開発を進めましょう。

- **開発者ツール（console.log や QuickLook）の積極的な活用**  
- **エラーハンドリングの徹底とログ出力**  
- **小さな部品に分割してデバッグすること**  
- **リソース（メモリ・ファイル）の管理を徹底すること**  
- **バージョン管理で常に安全な状態を保つこと**

これらの対策を講じることで、Scriptable を活用したスクリプトの品質と安定性が向上し、日常の自動化業務がよりスムーズに進むはずです。次のステップとして、さらなる自動テストの導入やパフォーマンスチューニングを検討し、より信頼性の高い自動化環境の構築を目指しましょう。
