## 18. トラブルシューティング：よくあるエラーとその解決策

この章では、システム開発や運用において頻繁に遭遇するエラーとその解決策について解説します。API連携、データベース、セキュリティという３つの主要な領域に焦点を当て、それぞれの分野で起こりうる問題とその具体的な解決策を、初心者にも理解しやすいように段階的に説明していきます。

### API連携のエラー：認証エラー、レート制限

#### 概要と重要性

API（Application Programming Interface）連携は、現代のアプリケーション開発において不可欠な要素です。外部サービスやデータへのアクセスを可能にし、アプリケーションの機能を拡張します。しかし、API連携には特有のエラーが発生しやすく、それらのエラーに対処することは、システムの安定性と信頼性を確保する上で非常に重要です。認証エラーとレート制限は、API連携において最も頻繁に遭遇する問題の二つです。

*   **認証エラー:** APIを利用するためには、通常、認証が必要です。認証エラーは、APIキーが無効である、誤ったクレデンシャルを使用している、あるいは権限がないなどの理由で発生します。
*   **レート制限:** 多くのAPIは、一定時間内に許可されるリクエスト数を制限しています。これは、APIの過負荷を防ぎ、公平な利用を促進するための措置です。レート制限を超過すると、APIからエラーが返され、アプリケーションの機能が停止する可能性があります。

#### 特徴と利点

API連携におけるエラーへの適切な対応は、以下のような利点をもたらします。

*   **システムの安定性:** エラーハンドリングを適切に行うことで、予期せぬエラーによるアプリケーションのクラッシュや停止を防ぎます。
*   **ユーザーエクスペリエンスの向上:** エラーメッセージを分かりやすく表示し、ユーザーに適切なガイダンスを提供することで、ストレスのない利用体験を提供します。
*   **開発効率の向上:** エラーの原因を迅速に特定し、修正することで、開発サイクルを短縮し、生産性を向上させます。
*   **API利用コストの最適化:** レート制限を意識した設計にすることで、不要なAPIリクエストを削減し、コストを抑制します。

#### 事前準備と前提条件

このセクションでは、API連携を行うための基本的な準備と前提条件について説明します。

1.  **APIキーの取得:** 連携したいAPIのドキュメントを参照し、APIキーを取得します。通常、APIプロバイダのウェブサイトでアカウントを作成し、APIキーを発行してもらう必要があります。
2.  **APIドキュメントの確認:** APIの利用方法、リクエストの形式、レスポンスの形式、エラーコードなどを理解するために、APIドキュメントをよく読んでください。
3.  **開発環境の構築:** プログラミング言語（Python、JavaScript、Javaなど）と、APIリクエストを送信するためのライブラリ（requests、axios、HttpClientなど）をインストールします。
4.  **認証方式の理解:** APIがどのような認証方式（APIキー、OAuth、Basic認証など）をサポートしているかを確認し、適切な認証ヘッダーを設定する方法を理解します。
5.  **レート制限の確認:** APIのレート制限に関する情報を確認し、アプリケーションが制限を超えないように設計します。

#### 基本的な使い方

ここでは、API連携における基本的なリクエストの送信とレスポンスの処理方法を説明します。

**Pythonの例:**

```python
import requests
import json

API_KEY = "YOUR_API_KEY"
API_ENDPOINT = "https://api.example.com/data"

headers = {
    "Authorization": f"Bearer {API_KEY}"
}

try:
    response = requests.get(API_ENDPOINT, headers=headers)
    response.raise_for_status()  # HTTPエラーが発生した場合に例外を発生させる

    data = response.json()
    print(json.dumps(data, indent=4))

except requests.exceptions.HTTPError as errh:
    print(f"HTTP Error: {errh}")
except requests.exceptions.ConnectionError as errc:
    print(f"Connection Error: {errc}")
except requests.exceptions.Timeout as errt:
    print(f"Timeout Error: {errt}")
except requests.exceptions.RequestException as err:
    print(f"Request Error: {err}")

```

**解説:**

1.  **requestsライブラリのインポート:** `import requests` でrequestsライブラリをインポートします。
2.  **APIキーとエンドポイントの設定:** APIキーとAPIのエンドポイントを適切な値に置き換えます。
3.  **ヘッダーの設定:** 認証に必要なヘッダーを設定します。ここでは、Bearerトークンを使用する例を示しています。
4.  **リクエストの送信:** `requests.get()` でAPIにGETリクエストを送信します。
5.  **エラーハンドリング:** `try-except` ブロックを使用して、発生する可能性のあるエラー（HTTPエラー、接続エラー、タイムアウトなど）を捕捉します。`response.raise_for_status()` は、HTTPステータスコードが200番台以外の場合に例外を発生させます。
6.  **レスポンスの処理:** `response.json()` でJSON形式のレスポンスをPythonの辞書に変換し、 `json.dumps()` で整形して表示します。

#### 実践的なテクニック

**認証エラーの解決策:**

*   **APIキーの確認:** APIキーが正しいことを確認します。コピー＆ペーストの際にスペースや改行が含まれていないか注意してください。
*   **APIキーの有効期限:** APIキーに有効期限がある場合、期限が切れていないか確認します。
*   **権限の確認:** APIキーに、アクセスしようとしているリソースへの権限があるか確認します。

**レート制限の解決策:**

*   **リクエスト数の削減:** 不要なAPIリクエストを削減するために、データのキャッシュやバッチ処理を検討します。
*   **レート制限の確認:** APIのドキュメントでレート制限のルールを確認し、制限を超えないようにリクエストを送信します。
*   **リトライの実装:** レート制限を超過した場合、一定時間待機してからリクエストを再試行する処理を実装します。指数バックオフ戦略を採用すると、より効果的です。
*   **レートリミットヘッダーの利用:**  APIレスポンスヘッダーに含まれるレートリミットに関する情報（`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`など）を利用して、レート制限を超えないようにリクエストを制御します。

**リトライ処理の例（Python）:**

```python
import requests
import time

def call_api_with_retry(url, headers, max_retries=3, retry_delay=2):
    """
    APIを呼び出し、レート制限エラーが発生した場合にリトライする。

    Args:
        url (str): APIのエンドポイントURL。
        headers (dict): リクエストヘッダー。
        max_retries (int): 最大リトライ回数。
        retry_delay (int): リトライ間の待機時間（秒）。

    Returns:
        requests.Response: APIからのレスポンス。
        None: 最大リトライ回数を超えた場合。
    """
    for attempt in range(max_retries):
        try:
            response = requests.get(url, headers=headers)
            response.raise_for_status()  # HTTPエラーが発生した場合に例外を発生させる
            return response
        except requests.exceptions.HTTPError as e:
            if e.response.status_code == 429:  # レート制限エラーの場合
                print(f"レート制限に達しました。{retry_delay}秒後にリトライします ({attempt + 1}/{max_retries})")
                time.sleep(retry_delay)
                retry_delay *= 2  # 指数バックオフ
            else:
                print(f"HTTPエラー: {e}")
                return None  # レート制限以外のエラーの場合はリトライしない
        except Exception as e:
            print(f"エラーが発生しました: {e}")
            return None  # その他のエラーの場合はリトライしない

    print("最大リトライ回数を超えました。")
    return None

# 使用例
API_KEY = "YOUR_API_KEY"
API_ENDPOINT = "https://api.example.com/data"
headers = {
    "Authorization": f"Bearer {API_KEY}"
}

response = call_api_with_retry(API_ENDPOINT, headers)

if response:
    data = response.json()
    print(data)
else:
    print("API呼び出しに失敗しました。")
```

#### 応用例とユースケース

*   **ソーシャルメディア分析:** Twitter APIやFacebook Graph APIを利用して、特定のキーワードに関する投稿を収集し、感情分析を行うアプリケーション。
*   **eコマース:** Amazon Marketplace APIを利用して、商品の価格や在庫情報を取得し、価格比較サイトを作成するアプリケーション。
*   **天気予報:** OpenWeatherMap APIを利用して、特定の地域の天気予報を取得し、ユーザーに表示するアプリケーション。

これらのアプリケーションでは、認証エラーやレート制限に適切に対応することで、安定したサービスを提供できます。例えば、ソーシャルメディア分析アプリケーションでは、APIキーを安全に管理し、レート制限を超えないようにリクエストを調整する必要があります。

#### トラブルシューティング

*   **エラーメッセージの解釈:** APIから返されるエラーメッセージをよく読んで、問題の原因を特定します。APIドキュメントには、通常、エラーコードとその意味が記載されています。
*   **ログの確認:** アプリケーションのログを確認して、APIリクエストの送信状況やエラー発生時の情報を分析します。
*   **ネットワークの確認:** APIサーバーにアクセスできることを確認します。ファイアウォールやプロキシの設定が正しくない場合、APIにアクセスできません。
*   **デバッグツール:** ブラウザの開発者ツールや、APIクライアント（Postmanなど）を使用して、APIリクエストを送信し、レスポンスを確認します。
*   **APIプロバイダーへの問い合わせ:** 問題が解決しない場合は、APIプロバイダーに問い合わせることを検討してください。

#### まとめと次のステップ

API連携は強力な機能を提供しますが、エラーへの適切な対応が不可欠です。認証エラーとレート制限は、API連携において最も一般的な問題の二つであり、これらのエラーに効果的に対処するためのテクニックを習得することは、システムの信頼性と安定性を向上させる上で重要です。

次のステップとして、API連携のセキュリティを強化するための対策を学びましょう。APIキーの安全な管理方法、OAuth 2.0などの認証プロトコルの利用、APIゲートウェイの導入などを検討してください。

### データベースのエラー：接続エラー、クエリエラー

#### 概要と重要性

データベースは、アプリケーションの重要なデータを保存し、管理するための基盤です。データベースに正常に接続し、データを操作することは、アプリケーションの機能を実現する上で不可欠です。しかし、データベース連携には特有のエラーが発生しやすく、それらのエラーに対処することは、データの整合性を保ち、システムの可用性を確保する上で非常に重要です。接続エラーとクエリエラーは、データベース連携において最も頻繁に遭遇する問題の二つです。

*   **接続エラー:** データベースサーバーに接続できない場合、接続エラーが発生します。原因としては、データベースサーバーが起動していない、ネットワークの問題、認証情報の誤りなどが考えられます。
*   **クエリエラー:** SQLクエリの構文が誤っている、存在しないテーブルやカラムを参照している、データ型の不一致などの理由でクエリエラーが発生します。

#### 特徴と利点

データベース連携におけるエラーへの適切な対応は、以下のような利点をもたらします。

*   **データの整合性:** エラーハンドリングを適切に行うことで、データの損失や破損を防ぎます。
*   **システムの可用性:** 接続エラーが発生した場合でも、自動的に再接続を試みるなどの対策を講じることで、システムのダウンタイムを最小限に抑えます。
*   **セキュリティの向上:** クエリエラーの原因となるSQLインジェクション攻撃からシステムを保護します。
*   **パフォーマンスの向上:** クエリの最適化を行うことで、クエリエラーの発生を減らし、データベースのパフォーマンスを向上させます。

#### 事前準備と前提条件

このセクションでは、データベース連携を行うための基本的な準備と前提条件について説明します。

1.  **データベースサーバーのインストールと設定:** 使用するデータベースサーバー（MySQL、PostgreSQL、SQL Serverなど）をインストールし、必要な設定を行います。
2.  **データベースの作成:** アプリケーションで使用するデータベースを作成します。
3.  **ユーザーの作成と権限の付与:** データベースにアクセスするためのユーザーを作成し、必要な権限（SELECT、INSERT、UPDATE、DELETEなど）を付与します。
4.  **データベースドライバのインストール:** プログラミング言語で使用するデータベースドライバ（MySQL Connector/Python、psycopg2、JDBCなど）をインストールします。
5.  **接続情報の確認:** データベースサーバーのホスト名、ポート番号、データベース名、ユーザー名、パスワードなどの接続情報を確認します。

#### 基本的な使い方

ここでは、データベースへの接続、クエリの実行、結果の処理などの基本的な操作方法を説明します。

**Pythonの例（MySQL）:**

```python
import mysql.connector

DB_HOST = "localhost"
DB_NAME = "mydatabase"
DB_USER = "myuser"
DB_PASSWORD = "mypassword"

try:
    # データベースに接続
    mydb = mysql.connector.connect(
        host=DB_HOST,
        user=DB_USER,
        password=DB_PASSWORD,
        database=DB_NAME
    )

    # カーソルオブジェクトを作成
    mycursor = mydb.cursor()

    # SQLクエリを実行
    sql = "SELECT * FROM customers"
    mycursor.execute(sql)

    # 結果を取得
    myresult = mycursor.fetchall()

    # 結果を表示
    for x in myresult:
        print(x)

except mysql.connector.Error as err:
    print(f"エラー: {err}")

finally:
    # データベース接続を閉じる (エラーが発生しても必ず実行)
    if 'mydb' in locals() and mydb.is_connected(): # mydbが定義されていて、かつ接続されている場合のみ
        mycursor.close()
        mydb.close()
        print("データベース接続を閉じました")

```

**解説:**

1.  **mysql.connectorライブラリのインポート:** `import mysql.connector` でmysql.connectorライブラリをインポートします。
2.  **接続情報の設定:** データベースサーバーのホスト名、データベース名、ユーザー名、パスワードを適切な値に置き換えます。
3.  **データベースへの接続:** `mysql.connector.connect()` でデータベースに接続します。
4.  **カーソルオブジェクトの作成:** `mydb.cursor()` でカーソルオブジェクトを作成します。カーソルは、SQLクエリを実行し、結果を処理するためのインターフェースです。
5.  **SQLクエリの実行:** `mycursor.execute()` でSQLクエリを実行します。
6.  **結果の取得:** `mycursor.fetchall()` でクエリの結果を取得します。`fetchall()` は、すべての結果をリストとして返します。
7.  **結果の表示:** 取得した結果を表示します。
8.  **エラーハンドリング:** `try-except` ブロックを使用して、発生する可能性のあるエラー（接続エラー、クエリエラーなど）を捕捉します。
9.  **接続のクローズ:** `finally`ブロックで、データベース接続をクローズします。これは、エラーが発生した場合でも必ず実行されるため、リソースリークを防ぐことができます。`mydb.is_connected()`で接続状態を確認し、接続されている場合のみクローズ処理を行うようにすることで、mydbが定義されていない場合のエラーを回避できます。

#### 実践的なテクニック

**接続エラーの解決策:**

*   **データベースサーバーの確認:** データベースサーバーが起動していることを確認します。
*   **ネットワークの確認:** データベースサーバーにアクセスできることを確認します。ファイアウォールやプロキシの設定が正しくない場合、データベースにアクセスできません。
*   **接続情報の確認:** ホスト名、ポート番号、データベース名、ユーザー名、パスワードなどの接続情報が正しいことを確認します。
*   **タイムアウトの設定:** 接続タイムアウトを設定し、接続に時間がかかりすぎる場合にエラーを発生させます。
*   **再接続の実装:** 接続エラーが発生した場合、一定時間待機してから再接続を試みる処理を実装します。

**クエリエラーの解決策:**

*   **SQLクエリの確認:** SQLクエリの構文が正しいことを確認します。スペルミスや構文エラーがないか注意深く確認してください。
*   **テーブルとカラムの確認:** 参照しているテーブルやカラムが存在することを確認します。
*   **データ型の確認:** 挿入または更新しようとしているデータの型が、テーブルのカラムの型と一致することを確認します。
*   **SQLインジェクション対策:** ユーザーからの入力をSQLクエリに直接埋め込むことを避け、プレースホルダーやエスケープ処理を使用して、SQLインジェクション攻撃を防ぎます。
*   **エラーメッセージの解釈:** データベースから返されるエラーメッセージをよく読んで、問題の原因を特定します。

**SQLインジェクション対策の例（Python）:**

```python
import mysql.connector

DB_HOST = "localhost"
DB_NAME = "mydatabase"
DB_USER = "myuser"
DB_PASSWORD = "mypassword"

try:
    mydb = mysql.connector.connect(
        host=DB_HOST,
        user=DB_USER,
        password=DB_PASSWORD,
        database=DB_NAME
    )

    mycursor = mydb.cursor()

    # ユーザーからの入力を取得
    user_input = input("ユーザー名を入力してください: ")

    # SQLインジェクション対策として、プレースホルダーを使用
    sql = "SELECT * FROM users WHERE username = %s"
    val = (user_input,)  # タプルとして値を渡す

    mycursor.execute(sql, val)

    myresult = mycursor.fetchall()

    for x in myresult:
        print(x)

except mysql.connector.Error as err:
    print(f"エラー: {err}")

finally:
    if 'mydb' in locals() and mydb.is_connected():
        mycursor.close()
        mydb.close()
        print("データベース接続を閉じました")

```

**解説:**

*   **プレースホルダーの使用:** SQLクエリの中で、ユーザーからの入力値を直接埋め込む代わりに、プレースホルダー（`%s`）を使用します。
*   **execute() メソッドへの値の渡し:** `mycursor.execute()` メソッドの第2引数に、プレースホルダーに対応する値をタプルとして渡します。データベースドライバが、これらの値を安全にエスケープ処理し、SQLインジェクション攻撃を防ぎます。

#### 応用例とユースケース

*   **ウェブアプリケーション:** ユーザーアカウント、商品情報、注文履歴などのデータをデータベースに保存し、管理するウェブアプリケーション。
*   **モバイルアプリケーション:** ローカルデータベースまたはリモートデータベースにデータを保存し、管理するモバイルアプリケーション。
*   **データ分析:** 大量のデータをデータベースに格納し、SQLクエリやデータ分析ツールを使用して分析するシステム。

これらのアプリケーションでは、接続エラーやクエリエラーに適切に対応することで、データの整合性を保ち、システムの安定性を確保できます。例えば、eコマースサイトでは、注文処理中にデータベース接続が失われた場合でも、トランザクションをロールバックし、データの不整合を防ぐ必要があります。

#### トラブルシューティング

*   **エラーメッセージの解釈:** データベースから返されるエラーメッセージをよく読んで、問題の原因を特定します。
*   **ログの確認:** アプリケーションのログを確認して、データベース接続やクエリ実行の状況を分析します。
*   **データベースサーバーのログ:** データベースサーバーのログを確認して、エラーの原因を特定します。
*   **データベース管理ツール:** データベース管理ツール（phpMyAdmin、pgAdminなど）を使用して、データベースの状態やテーブルの構造を確認します。
*   **SQLクエリのテスト:** SQLクエリをデータベース管理ツールで直接実行して、エラーが発生するかどうかを確認します。

#### まとめと次のステップ

データベース連携は、アプリケーションの重要な要素です。接続エラーとクエリエラーは、データベース連携において最も一般的な問題の二つであり、これらのエラーに効果的に対処するためのテクニックを習得することは、データの整合性を保ち、システムの可用性を向上させる上で重要です。

次のステップとして、データベースのパフォーマンスを向上させるための対策を学びましょう。インデックスの作成、クエリの最適化、キャッシュの利用などを検討してください。

### セキュリティのエラー：脆弱性、不正アクセス

#### 概要と重要性

セキュリティは、現代のアプリケーション開発において最も重要な考慮事項の一つです。脆弱性や不正アクセスは、システムの機密性、完全性、可用性を脅かす可能性があり、甚大な損害をもたらす可能性があります。セキュリティ対策を適切に実施し、セキュリティエラーに効果的に対処することは、ユーザーの信頼を得て、ビジネスを守る上で不可欠です。

*   **脆弱性:** ソフトウェアの欠陥や設計上の不備により、攻撃者がシステムを不正に操作できる可能性のある箇所。
*   **不正アクセス:** 許可されていないユーザーがシステムにアクセスしたり、データを盗み見たり、改ざんしたりする行為。

#### 特徴と利点

セキュリティエラーへの適切な対応は、以下のような利点をもたらします。

*   **データ漏洩の防止:** 機密データを不正アクセスから保護し、データ漏洩のリスクを軽減します。
*   **システムの可用性の維持:** DDoS攻撃やマルウェア感染からシステムを保護し、システムのダウンタイムを最小限に抑えます。
*   **ユーザーの信頼獲得:** 安全なシステムを提供することで、ユーザーからの信頼を獲得し、ビジネスの成長を促進します。
*   **法的責任の軽減:** 個人情報保護法などの法律や規制を遵守し、法的責任を軽減します。

#### 事前準備と前提条件

このセクションでは、セキュリティ対策を実施するための基本的な準備と前提条件について説明します。

1.  **セキュリティに関する知識の習得:** OWASP Top 10などのセキュリティに関する知識を習得します。
2.  **セキュリティポリシーの策定:** アプリケーションのセキュリティに関するポリシーを策定します。
3.  **セキュリティツールの導入:** 静的コード分析ツール、動的アプリケーションセキュリティテストツール、脆弱性スキャナなどのセキュリティツールを導入します。
4.  **セキュリティトレーニングの実施:** 開発者や運用担当者に対して、セキュリティに関するトレーニングを実施します。
5.  **インシデントレスポンス計画の策定:** セキュリティインシデントが発生した場合の対応計画を策定します。

#### 基本的な使い方

ここでは、代表的な脆弱性とその対策について説明します。

**1. SQLインジェクション:**

*   **脆弱性の概要:** ユーザーからの入力を適切に検証せずにSQLクエリに埋め込むことで、攻撃者が任意のSQLクエリを実行できる脆弱性。
*   **対策:** プレースホルダーやエスケープ処理を使用し、ユーザーからの入力をSQLクエリに直接埋め込まないようにします。

**2. クロスサイトスクリプティング (XSS):**

*   **脆弱性の概要:** 悪意のあるスクリプトをウェブサイトに埋め込み、他のユーザーのブラウザで実行させることで、情報を盗み取ったり、偽のコンテンツを表示させたりする攻撃。
*   **対策:** ユーザーからの入力を適切にエスケープ処理し、HTMLタグやJavaScriptコードが無効化されるようにします。 Content Security Policy (CSP) を導入し、信頼できるソースからのスクリプトのみを実行するように制限します。

**3. クロスサイトリクエストフォージェリ (CSRF):**

*   **脆弱性の概要:** ユーザーがログインしているウェブサイトを悪用し、ユーザーの意図しないリクエストを送信させる攻撃。
*   **対策:** フォームにCSRFトークンを埋め込み、リクエストが正規のものかどうかを検証します。 SameSite属性を設定し、クロスサイトのリクエストに対してCookieの送信を制限します。

**4. 認証とセッション管理の不備:**

*   **脆弱性の概要:** 不十分な認証メカニズムやセッション管理の不備により、攻撃者が不正にログインしたり、セッションを乗っ取ったりする可能性のある脆弱性。
*   **対策:** 強力なパスワードポリシーを適用し、多要素認証を導入します。セッションIDを安全に管理し、セッションの有効期限を設定します。

**5. 機密データの露出:**

*   **脆弱性の概要:** エラーメッセージやログファイルなどに機密情報（APIキー、パスワードなど）が露出している脆弱性。
*   **対策:** エラーメッセージを適切に処理し、機密情報が露出しないようにします。機密情報を安全な場所に保管し、アクセス制限を設定します。

**CSRF対策の例（Python, Flaskフレームワーク）:**

```python
from flask import Flask, render_template, request, session, redirect, url_for
import os

app = Flask(__name__)
app.secret_key = os.urandom(24)  # セッションを安全にするための秘密鍵

@app.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'POST':
        username = request.form['username']
        password = request.form['password']
        # ここでユーザー認証を行う (例: データベース照合)
        if username == 'testuser' and password == 'password':  # テスト用
            session['logged_in'] = True
            return redirect(url_for('transfer'))
        else:
            return render_template('login.html', error='認証に失敗しました')
    return render_template('login.html')

@app.route('/transfer', methods=['GET', 'POST'])
def transfer():
    if not session.get('logged_in'):
        return redirect(url_for('login'))

    if request.method == 'POST':
        # CSRFトークンの検証
        if request.form.get('csrf_token') == session.get('csrf_token'):
            amount = request.form['amount']
            # ここで送金処理を行う
            return render_template('transfer_success.html', amount=amount)
        else:
            return render_template('transfer.html', error='不正なリクエストです')

    # CSRFトークンの生成
    csrf_token = os.urandom(24).hex()  # ランダムなトークンを生成
    session['csrf_token'] = csrf_token
    return render_template('transfer.html', csrf_token=csrf_token)

@app.route('/logout')
def logout():
    session.pop('logged_in', None)
    return redirect(url_for('login'))

@app.before_request
def before_request():
    # すべてのリクエストの前に実行される処理
    # セッションを常に永続化する (セキュアな方法で)
    session.permanent = True
    app.permanent_session_lifetime = timedelta(minutes=30) # セッションの有効期限を設定

if __name__ == '__main__':
    from datetime import timedelta
    app.run(debug=True)

```

**解説:**

1.  **CSRFトークンの生成:** `/transfer` ルートで、ランダムなCSRFトークンを生成し、セッションに保存します。
2.  **フォームへのトークンの埋め込み:** `transfer.html` テンプレートで、CSRFトークンを隠しフィールドとしてフォームに埋め込みます。
3.  **トークンの検証:** `/transfer` ルートで、POSTリクエストを受信した場合、フォームから送信されたCSRFトークンとセッションに保存されているトークンを比較し、一致するかどうかを検証します。
4.  **セッションの永続化とタイムアウト:** `before_request` デコレータを使用して、セッションを常に永続化し、セキュアな方法でCookieを管理します。また、セッションの有効期限を設定し、一定時間経過後に自動的にログアウトするようにします。
