## 15. ワイヤレス通信 - WiFi、Bluetooth、LoRaWAN の活用

### 15.1. WiFi 通信の基礎 - ESP32、ESP8266

**15.1.1. 概要と重要性**

WiFi（Wireless Fidelity）は、現代の IoT（Internet of Things）デバイスにおいて、インターネット接続を提供する最も一般的な無線通信技術の一つです。 特に、低価格で高性能なマイコンである ESP32 や ESP8266 は、WiFi 機能を内蔵しており、様々な IoT プロジェクトで中心的な役割を果たしています。このセクションでは、ESP32 と ESP8266 を用いた WiFi 通信の基礎を学び、具体的なコード例を通して、その活用方法を理解していきます。

**15.1.2. 特徴と利点**

WiFi の主な特徴は以下の通りです。

- **高速データ通信:** 大量のデータを比較的短時間で送受信できます。
- **広範なネットワーク:** 多くの場所に WiFi アクセスポイントが存在し、広い範囲でインターネットに接続できます。
- **確立された規格:** IEEE 802.11 規格に基づいているため、互換性が高く、安定した通信が可能です。

ESP32 と ESP8266 の利点は以下の通りです。

- **低コスト:** 非常に安価に入手できます。
- **高機能:** WiFi だけでなく、Bluetooth やその他の周辺機能を内蔵しています。
- **豊富なドキュメント:** 開発コミュニティが活発で、豊富な情報やライブラリが利用可能です。

**15.1.3. 事前準備と前提条件**

- **開発環境:** Arduino IDE、PlatformIO などの開発環境をインストールし、ESP32/ESP8266 の開発ボードを設定する必要があります。
- **ハードウェア:** ESP32 または ESP8266 開発ボード、USB ケーブル。
- **ソフトウェア:** Arduino IDE または PlatformIO に、ESP32/ESP8266 のボードマネージャをインストールします。
- **ネットワーク環境:** WiFi ルーターとインターネット接続が必要です。

**15.1.4. 基本的な使い方**

以下は、ESP32 で WiFi に接続する基本的なコード例です（Arduino IDE を使用）。

```arduino
#include <WiFi.h>

const char* ssid     = "YOUR_WIFI_SSID";       // WiFiのSSID
const char* password = "YOUR_WIFI_PASSWORD";   // WiFiのパスワード

void setup() {
  Serial.begin(115200);
  delay(10);

  Serial.println("Connecting to WiFi");

  WiFi.begin(ssid, password);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("");
  Serial.println("WiFi connected");
  Serial.println("IP address: ");
  Serial.println(WiFi.localIP());
}

void loop() {
  // ここにメインの処理を記述
  delay(10000); // 10秒ごとにIPアドレスを表示
  Serial.print("IP address: ");
  Serial.println(WiFi.localIP());
}
```

**コードの説明:**

1.  `#include <WiFi.h>`：WiFi ライブラリをインクルードします。
2.  `ssid`と`password`：WiFi の SSID とパスワードを定義します。
3.  `WiFi.begin(ssid, password)`：WiFi ネットワークへの接続を開始します。
4.  `WiFi.status() != WL_CONNECTED`：接続が確立されるまで待ちます。
5.  `WiFi.localIP()`：接続された IP アドレスを取得します。

ESP8266 の場合も、同様のコードで動作しますが、ライブラリ名が若干異なります。

```arduino
#include <ESP8266WiFi.h>

const char* ssid     = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";

void setup() {
  Serial.begin(115200);
  delay(10);

  Serial.println("Connecting to WiFi");

  WiFi.begin(ssid, password);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("");
  Serial.println("WiFi connected");
  Serial.println("IP address: ");
  Serial.println(WiFi.localIP());
}

void loop() {
  // ここにメインの処理を記述
  delay(10000); // 10秒ごとにIPアドレスを表示
  Serial.print("IP address: ");
  Serial.println(WiFi.localIP());
}
```

**15.1.5. 実践的なテクニック**

- **静的 IP アドレスの設定:** DHCP ではなく、固定の IP アドレスを設定することで、ネットワーク上でのデバイスの識別が容易になります。

  ```arduino
  IPAddress staticIP(192,168,1,100);  // デバイスのIPアドレス
  IPAddress gateway(192,168,1,1);     // ゲートウェイのIPアドレス
  IPAddress subnet(255,255,255,0);     // サブネットマスク
  IPAddress dns(192,168,1,1);          // DNSサーバー

  WiFi.config(staticIP, gateway, subnet, dns);
  ```

- **WiFi Manager ライブラリの利用:** WiFi の SSID とパスワードを Web インターフェースから設定できる便利なライブラリです。特に、複数の WiFi ネットワークに接続する必要がある場合に便利です。

**15.1.6. 応用例とユースケース**

- **Web サーバーの構築:** ESP32/ESP8266 を Web サーバーとして使用し、センサーデータを Web ページで表示したり、デバイスを制御したりできます。
- **クラウドへのデータ送信:** MQTT プロトコルを使って、センサーデータをクラウドサービス（例：AWS IoT、Google Cloud IoT）に送信し、データの可視化や分析を行うことができます。
- **スマートホームデバイス:** 照明、エアコン、ドアロックなどの家電製品を、スマートフォンや音声アシスタントから制御するスマートホームデバイスを開発できます。

**15.1.7. トラブルシューティング**

- **WiFi に接続できない:** SSID とパスワードが正しいか確認してください。また、WiFi ルーターの設定で、MAC アドレスフィルタリングが有効になっていないか確認してください。
- **IP アドレスが取得できない:** DHCP サーバーが正しく動作しているか確認してください。静的 IP アドレスを設定している場合は、IP アドレスがネットワーク上で重複していないか確認してください。
- **通信が不安定:** WiFi ルーターとの距離が遠すぎるか、電波干渉が発生している可能性があります。

**15.1.8. まとめと次のステップ**

このセクションでは、ESP32/ESP8266 を用いた WiFi 通信の基礎を学びました。次のステップとして、Web サーバーの構築や MQTT プロトコルを用いたクラウドへのデータ送信など、より高度な応用例に挑戦してみましょう。

### 15.2. Bluetooth 通信の基礎 - BLE（Bluetooth Low Energy）

**15.2.1. 概要と重要性**

Bluetooth、特に BLE（Bluetooth Low Energy）は、近距離無線通信技術として、IoT デバイスで広く利用されています。BLE は、従来の Bluetooth に比べて消費電力が非常に低いため、バッテリー駆動のデバイスに適しています。このセクションでは、BLE 通信の基礎を学び、特に ESP32 を用いた BLE 通信の実践的な方法を解説します。

**15.2.2. 特徴と利点**

BLE の主な特徴は以下の通りです。

- **低消費電力:** バッテリー駆動のデバイスに適しています。
- **近距離通信:** 通常、数メートルから数十メートルの範囲で通信が可能です。
- **多様なプロファイル:** 様々な用途に対応したプロファイル（例：心拍数モニター、温度センサー）が定義されています。

ESP32 の利点は以下の通りです。

- **WiFi と Bluetooth の両方を内蔵:** 一つのチップで両方の無線通信を利用できます。
- **低コスト:** 比較的に安価に入手できます。
- **豊富な開発環境:** Arduino IDE、PlatformIO など、多様な開発環境が利用可能です。

**15.2.3. 事前準備と前提条件**

- **開発環境:** Arduino IDE、PlatformIO などの開発環境をインストールし、ESP32 の開発ボードを設定する必要があります。
- **ハードウェア:** ESP32 開発ボード、USB ケーブル。
- **ソフトウェア:** Arduino IDE または PlatformIO に、ESP32 のボードマネージャをインストールします。
- **BLE 対応デバイス:** スマートフォン、タブレット、PC など、BLE に対応したデバイスが必要です。

**15.2.4. 基本的な使い方**

以下は、ESP32 で BLE アドバタイズメント（周辺へのデバイスの存在を知らせる信号）を送信する基本的なコード例です（Arduino IDE を使用）。

```arduino
#include <BLEDevice.h>
#include <BLEUtils.h>
#include <BLEServer.h>

// BLE Service UUID (Universal Unique Identifier)
#define SERVICE_UUID        "4fafc201-1fb5-459e-8fcc-c5c9c331914b"
// BLE Characteristic UUID
#define CHARACTERISTIC_UUID "beb5483e-36e1-4688-b7f5-ea07361b26a8"

void setup() {
  Serial.begin(115200);
  Serial.println("Starting BLE work!");

  BLEDevice::init("MyESP32"); // BLEデバイス名を設定

  BLEServer *pServer = BLEDevice::createServer(); // BLEサーバーを作成

  BLEService *pService = pServer->createService(SERVICE_UUID); // BLEサービスを作成

  BLECharacteristic *pCharacteristic = pService->createCharacteristic(
                                         CHARACTERISTIC_UUID,
                                         BLECharacteristic::PROPERTY_READ   |
                                         BLECharacteristic::PROPERTY_WRITE  |
                                         BLECharacteristic::PROPERTY_NOTIFY
                                       );

  pCharacteristic->setValue("Hello World"); // 初期値を設定

  pService->start(); // サービスを開始

  BLEAdvertising *pAdvertising = BLEDevice::getAdvertising(); // アドバタイズメントを取得
  pAdvertising->addServiceUUID(SERVICE_UUID); // サービスUUIDを追加
  pAdvertising->setScanResponse(true);
  pAdvertising->setMinPreferred(0x06);  // helps with iPhone connections issue
  pAdvertising->setMinPreferred(0x12);
  BLEDevice::startAdvertising(); // アドバタイズメントを開始
  Serial.println("Characteristic defined! Now you can read it in your phone!");
}

void loop() {
  delay(2000);
}
```

**コードの説明:**

1.  `#include <BLEDevice.h>`, `#include <BLEUtils.h>`, `#include <BLEServer.h>`：BLE ライブラリをインクルードします。
2.  `SERVICE_UUID`と`CHARACTERISTIC_UUID`：BLE のサービスとキャラクタリスティックの UUID を定義します。これらは、BLE デバイスを識別し、通信を確立するために使用されます。
3.  `BLEDevice::init("MyESP32")`：BLE デバイスの名前を設定します。
4.  `BLEServer *pServer = BLEDevice::createServer()`：BLE サーバーを作成します。
5.  `BLEService *pService = pServer->createService(SERVICE_UUID)`：BLE サービスを作成します。
6.  `BLECharacteristic *pCharacteristic = pService->createCharacteristic(...)`：BLE キャラクタリスティックを作成します。
7.  `pAdvertising->addServiceUUID(SERVICE_UUID)`：アドバタイズメントにサービス UUID を追加します。
8.  `BLEDevice::startAdvertising()`：アドバタイズメントを開始します。

このコードを実行すると、ESP32 は"MyESP32"という名前で BLE デバイスとしてアドバタイズメントを送信します。スマートフォンなどの BLE 対応デバイスでスキャンすると、このデバイスが見つかるはずです。

**15.2.5. 実践的なテクニック**

- **データ送受信:** キャラクタリスティックを通じてデータを送受信します。データの形式は、文字列、数値、バイナリデータなど、自由に定義できます。
- **Notification と Indication:** BLE の Notification と Indication は、サーバーからクライアントにデータを非同期に送信する仕組みです。Notification は、クライアントが受信確認を必要としない一方通行の送信方法であり、Indication は、クライアントからの受信確認を必要とする信頼性の高い送信方法です。
- **セキュリティ:** ペアリングや暗号化を設定することで、BLE 通信のセキュリティを強化できます。

**15.2.6. 応用例とユースケース**

- **ウェアラブルデバイス:** 心拍数モニター、フィットネストラッカーなどのウェアラブルデバイスは、BLE を使ってスマートフォンや PC にデータを送信します。
- **スマートロック:** スマートフォンから BLE 経由でドアロックを制御できます。
- **ビーコン:** BLE ビーコンを使って、特定の場所での情報提供や位置情報の特定が可能です。
- **環境センサー:** 温湿度センサーなどの環境センサーから、BLE 経由でデータを収集し、スマートフォンやクラウドに送信できます。

**15.2.7. トラブルシューティング**

- **BLE デバイスが見つからない:** ESP32 の電源が入っているか確認してください。また、BLE のスキャン範囲内にいるか確認してください。
- **ペアリングできない:** パスキーや PIN コードが正しいか確認してください。また、セキュリティ設定が正しく行われているか確認してください。
- **データが送受信できない:** キャラクタリスティックの UUID が正しいか確認してください。また、データの形式が一致しているか確認してください。

### 15.3. LoRaWAN 通信の基礎 - 長距離低消費電力通信

**15.3.1. 概要と重要性**

LoRaWAN（Long Range Wide Area Network）は、長距離で低消費電力の通信を実現する無線通信技術です。IoT デバイスが広範囲に分散している場合や、バッテリー駆動で長期間運用する必要がある場合に特に有効です。このセクションでは、LoRaWAN 通信の基礎を学び、具体的なデバイス設定やネットワーク構成について解説します。

**15.3.2. 特徴と利点**

LoRaWAN の主な特徴は以下の通りです。

- **長距離通信:** 数キロメートルから数十キロメートルの範囲で通信が可能です。
- **低消費電力:** バッテリー駆動で数年間運用できる場合があります。
- **免許不要の周波数帯:** ISM バンド（920MHz 帯など）を使用するため、免許は不要です（国や地域によって異なります）。
- **広範囲なカバレッジ:** 一つのゲートウェイで広範囲のデバイスをカバーできます。

**15.3.3. 事前準備と前提条件**

- **LoRaWAN デバイス:** LoRaWAN モジュールを搭載したデバイス（例：TTGO LoRa32、Heltec WiFi LoRa 32）。
- **LoRaWAN ゲートウェイ:** LoRaWAN ネットワークに接続するためのゲートウェイ。
- **LoRaWAN ネットワークサーバー:** LoRaWAN デバイスからのデータを受信し、アプリケーションサーバーに転送するネットワークサーバー（例：The Things Network (TTN), ChirpStack）。
- **開発環境:** Arduino IDE、PlatformIO などの開発環境をインストールし、LoRaWAN デバイスを設定する必要があります。

**15.3.4. 基本的な使い方**

以下は、TTGO LoRa32 を使用して The Things Network (TTN)に接続し、データを送信する基本的なコード例です（Arduino IDE を使用）。

まず、以下のライブラリをインストールする必要があります。

- MCCI LoRaWAN LMIC library

```arduino
#include <lmic.h>
#include <hal/hal.h>
#include <SPI.h>

// TTN Device EUI
static const u1_t PROGMEM DEVEUI[8]= { 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX };
void os_getDevEui (u1_t *buf) { memcpy_P(buf, DEVEUI, 8);}

// TTN Application EUI
static const u1_t PROGMEM APPEUI[8]= { 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX };
void os_getArtEui (u1_t *buf) { memcpy_P(buf, APPEUI, 8);}

// TTN Application Key
static const u1_t PROGMEM APPKEY[16] = { 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX, 0xXX };
void os_getDevKey (u1_t* buf) {  memcpy_P(buf, APPKEY, 16);}


// LoRaWAN NwkSKey, ArtSKey, DevAddr
// See instructions for more information:
// https://github.com/matthijskooijman/arduino-lmic/blob/master/examples/ttn-otaa/ttn-otaa.ino

static osjob_t sendjob;

// Schedule TX every this many seconds (might become longer due to duty
// cycle limitations).
const unsigned TX_INTERVAL = 60;

// Pin mapping
const lmic_pinmap lmic_pins = {
    .nss = 18,
    .rxtx = LMIC_UNUSED_PIN,
    .rst = 14,
    .dio = {26, 33, 32},
};

void onEvent (ev_t ev) {
    Serial.print(os_getTime());
    Serial.print(": ");
    switch(ev) {
        case EV_SCAN_TIMEOUT:
            Serial.println(F("EV_SCAN_TIMEOUT"));
            break;
        case EV_BEACON_FOUND:
            Serial.println(F("EV_BEACON_FOUND"));
            break;
        case EV_BEACON_MISSED:
            Serial.println(F("EV_BEACON_MISSED"));
            break;
        case EV_BEACON_LOST:
            Serial.println(F("EV_BEACON_LOST"));
            break;
        case EV_TXCOMPLETE:
            Serial.println(F("EV_TXCOMPLETE (includes waiting for RX windows)"));
            if (LMIC.txrxFlags & TXRX_ACK)
              Serial.println(F("Received ack"));
            if (LMIC.dataLen) {
              Serial.print(F("Received "));
              Serial.print(LMIC.dataLen);
              Serial.println(F(" bytes of payload"));
            }
            os_setTimedCallback(&sendjob, os_getTime()+sec2osticks(TX_INTERVAL), do_send);
            break;
        case EV_LOST_TSYNC:
            Serial.println(F("EV_LOST_TSYNC"));
            break;
        case EV_RESET:
            Serial.println(F("EV_RESET"));
            break;
        case EV_RXCOMPLETE:
            // data received in ping slot
            Serial.println(F("EV_RXCOMPLETE"));
            break;
        case EV_LINK_DEAD:
            Serial.println(F("EV_LINK_DEAD"));
            break;
        case EV_LINK_ALIVE:
            Serial.println(F("EV_LINK_ALIVE"));
            break;
         default:
            Serial.print(F("Unknown event: "));
            Serial.println((unsigned)ev);
            break;
    }
}

void do_send(osjob_t* job){
    // Check if there is not a current TX/RX job running
    if (LMIC.opmode & OP_TXRXPEND) {
        Serial.println(F("OP_TXRXPEND, not sending"));
    } else {
        // Prepare upstream data transmission at the next possible time.
        // Replace 'Hello, world!' with your sensor data
        String sensorData = "Hello, LoRaWAN!";
        LMIC_setTxData2(1, (uint8_t *)sensorData.c_str(), sensorData.length(), 0);
        Serial.println(F("Packet queued"));
    }
    // Next TX is scheduled after TX_COMPLETE event.
}

void setup() {
    Serial.begin(115200);
    Serial.println(F("Starting"));

    // LMIC init
    os_init();
    // Reset the MAC state. Session and pending data transfers will be discarded.
    LMIC_reset();

    // Set static session parameters. Instead of dynamically establishing a session
    // by joining the network, preconfigure a fixed session.
    #ifdef PROGMEM
    // On AVR, these values are stored in flash and only copied to RAM
    // once. Copy them to a temporary buffer here, LMIC_setSession will
    // copy them into its own buffers.
    u4_t netid = 0;
    devaddr_t devaddr = 0x260116CC;
    u1_t nwkKey[16];
    u1_t artKey[16];
    memcpy_P(nwkKey, NWKSKEY, 16);
    memcpy_P(artKey, APPSKEY, 16);
    LMIC_setSession (netid, devaddr, nwkKey, artKey);
    #else
    // If not running an AVR with PROGMEM, just use the arrays directly
    LMIC_setSession (0x1, 0x260116CC, NWKSKEY, APPSKEY);
    #endif

    // TTN uses SF9 for its RX2 window.
    LMIC.dn2Dr = DR_SF9;

    // Set data rate and transmit power for uplink (note: txpow seems to be ignored by the library)
    LMIC_setDrTxpow(DR_SF7,14);

    // Join the network, disabling OTAA
    LMIC_setOtaaIdentity(DEVEUI, APPEUI, APPKEY);

    // Disable link check validation
    LMIC_setLinkCheckMode(0);

    // TTN uses SF9 for its RX2 window.
    LMIC.dn2Dr = DR_SF9;

    // Set data rate and transmit power for uplink (note: txpow seems to be ignored by the library)
    LMIC_setDrTxpow(DR_SF7,14);

    // Schedule a send job
    do_send(&sendjob);
}

void loop() {
    os_runloop_once();
}
```

**コードの説明:**

1.  `#include <lmic.h>`, `#include <hal/hal.h>`, `#include <SPI.h>`：LoRaWAN ライブラリをインクルードします。
2.  `DEVEUI`, `APPEUI`, `APPKEY`：The Things Network (TTN)で登録したデバイスの Device EUI, Application EUI, Application Key を設定します。
3.  `lmic_pinmap`：LoRaWAN モジュールのピン設定を定義します。
4.  `os_init()`：LMIC（LoRaWAN MAC in C）ライブラリを初期化します。
5.  `LMIC_setOtaaIdentity()`：OTAA（Over-The-Air Activation）でデバイスをアクティベートするために必要な情報を設定します。
6.  `LMIC_setDrTxpow()`：データレートと送信電力を設定します。
7.  `LMIC_setLinkCheckMode(0)`：リンクチェックを無効化します。
8.  `do_send()`：データを送信する関数です。

**TTN の設定:**

1.  TTN のウェブサイトにアクセスし、アカウントを作成します。
2.  アプリケーションを登録し、デバイスを追加します。
3.  デバイスの Device EUI, Application EUI, Application Key をコピーし、上記のコードに貼り付けます。

**15.3.5. 実践的なテクニック**

- **アダプティブデータレート (ADR):** LoRaWAN ネットワークは、ADR を使ってデバイスのデータレートを自動的に調整し、消費電力を最適化します。
- **クラス A、B、C デバイス:** LoRaWAN デバイスは、通信のタイミングによってクラス A、B、C に分類されます。クラス A は最も低消費電力で、クラス C は最もリアルタイム性が高いです。
- **データの暗号化:** LoRaWAN は、AES128 暗号化を使ってデータを保護します。

**15.3.6. 応用例とユースケース**

- **スマート農業:** 土壌水分センサーや温度センサーから、LoRaWAN 経由でデータを収集し、灌漑や施肥を最適化します。
- **スマートシティ:** 街灯の制御、ゴミ箱の満杯状況の監視、駐車場管理など、様々な都市インフラを LoRaWAN で管理できます。
- **資産追跡:** GPS トラッカーを搭載した LoRaWAN デバイスを使って、車両や貨物の位置を追跡します。
- **環境モニタリング:** 大気汚染物質の濃度、水質、騒音レベルなどを LoRaWAN でモニタリングします。

**15.3.7. トラブルシューティング**

- **デバイスが TTN に接続できない:** Device EUI, Application EUI, Application Key が正しいか確認してください。また、ゲートウェイが正しく設定されているか確認してください。
- **データが TTN に届かない:** データレートが低すぎるか、送信電力が弱すぎる可能性があります。また、電波干渉が発生している可能性があります。
- **消費電力が高い:** 送信頻度が高すぎるか、ADR が正しく機能していない可能性があります。

### 15.4. 通信プロトコルの選定 - MQTT、HTTP、CoAP

**15.4.1. 概要と重要性**

IoT デバイスがデータを送受信するためには、適切な通信プロトコルを選択することが重要です。MQTT、HTTP、CoAP は、IoT 環境でよく使用される通信プロトコルであり、それぞれ異なる特徴と利点があります。このセクションでは、これらのプロトコルの概要を学び、どのような場合にどのプロトコルを選択すべきかを解説します。

**15.4.2. 各プロトコルの特徴と利点**

- **MQTT (Message Queuing Telemetry Transport):**

  - **特徴:** 軽量なパブリッシュ/サブスクライブ型のメッセージングプロトコルです。
  - **利点:**
    - **低帯域幅:** 帯域幅が限られた環境に適しています。
    - **リアルタイム性:** リアルタイムなデータ配信に適しています。
    - **柔軟性:** 多数のデバイスとサーバー間の通信を効率的に管理できます。
  - **ユースケース:** センサーデータの収集、スマートホームデバイスの制御、産業用オートメーションなど。

- **HTTP (Hypertext Transfer Protocol):**

  - **特徴:** ウェブブラウザとウェブサーバー間の通信に使用される最も一般的なプロトコルです。
  - **利点:**
    - **汎用性:** ほとんどのデバイスとネットワークでサポートされています。
    - **標準化:** 広く普及しており、多くのツールやライブラリが利用可能です。
    - **可視性:** 通信内容を簡単に確認できます。
  - **ユースケース:** ウェブベースのインターフェース、API との連携、ファイルのダウンロードなど。

- **CoAP (Constrained Application Protocol):**

  - **特徴:** リソースが限られたデバイス向けに設計された HTTP に似たプロトコルです。
  - **利点:**
    - **軽量:** HTTP よりも軽量で、リソースが限られたデバイスに適しています。
    - **UDP ベース:** TCP よりもオーバーヘッドが少ない UDP を使用します。
    - **RESTful:** HTTP と同様の RESTful アーキテクチャを採用しています。
  - **ユースケース:** スマート照明、環境センサー、スマートメーターなど。

**15.4.3. プロトコルの選定基準**

以下の要素を考慮して、適切な通信プロトコルを選択します。

- **帯域幅:** 帯域幅が限られている場合は、MQTT や CoAP が適しています。
- **消費電力:** バッテリー駆動のデバイスでは、消費電力の低い MQTT や CoAP が有利です。
- **リアルタイム性:** リアルタイムなデータ配信が必要な場合は、MQTT が適しています。
- **セキュリティ:** セキュリティが重要な場合は、TLS/SSL で暗号化された MQTT や HTTP を使用します。
- **複雑性:** プロトコルの実装と管理の複雑さを考慮します。MQTT は比較的簡単に実装できますが、CoAP はより複雑な場合があります。
- **既存のインフラ:** 既存のインフラとの互換性を考慮します。HTTP は広くサポートされているため、既存のウェブサーバーや API との連携が容易です。

**15.4.4. 各プロトコルの基本的な使い方**

- **MQTT:**

  - **概要:** デバイスは MQTT ブローカーに接続し、トピックに対してメッセージをパブリッシュ（送信）またはサブスクライブ（受信）します。
  - **コード例 (ESP32 Arduino):**

  ```arduino
  #include <WiFi.h>
  #include <PubSubClient.h>

  const char* ssid = "YOUR_WIFI_SSID";
  const char* password = "YOUR_WIFI_PASSWORD";
  const char* mqtt_server = "YOUR_MQTT_BROKER_IP";

  WiFiClient espClient;
  PubSubClient client(espClient);
  long lastMsg = 0;
  char msg[50];
  int value = 0;

  void setup() {
    Serial.begin(115200);
    WiFi.begin(ssid, password);
    while (WiFi.status() != WL_CONNECTED) {
      delay(500);
      Serial.print(".");
    }
    client.setServer(mqtt_server, 1883);
  }

  void reconnect() {
    while (!client.connected()) {
      Serial.print("Attempting MQTT connection...");
      if (client.connect("ESP32Client")) {
        Serial.println("connected");
      } else {
        Serial.print("failed, rc=");
        Serial.print(client.state());
        Serial.println(" try again in 5 seconds");
        delay(5000);
      }
    }
  }

  void loop() {
    if (!client.connected()) {
      reconnect();
    }
    client.loop();

    long now = millis();
    if (now - lastMsg > 2000) {
      lastMsg = now;
      ++value;
      snprintf(msg, 50, "hello world #%ld", value);
      Serial.print("Publish message: ");
      Serial.println(msg);
      client.publish("outTopic", msg);
    }
  }
  ```

- **HTTP:**

  - **概要:** デバイスは HTTP リクエストをサーバーに送信し、レスポンスを受信します。
  - **コード例 (ESP32 Arduino):**

  ```arduino
  #include <WiFi.h>
  #include <HTTPClient.h>

  const char* ssid = "YOUR_WIFI_SSID";
  const char* password = "YOUR_WIFI_PASSWORD";
  const char* serverName = "http://yourserver.com/api/data";

  void setup() {
    Serial.begin(115200);
    WiFi.begin(ssid, password);
    while (WiFi.status() != WL_CONNECTED) {
      delay(500);
      Serial.print(".");
    }
  }

  void loop() {
    if (WiFi.status() == WL_CONNECTED) {
      HTTPClient http;
      http.begin(serverName);
      int httpResponseCode = http.GET();

      if (httpResponseCode > 0) {
        Serial.print("HTTP Response code: ");
        Serial.println(httpResponseCode);
        String payload = http.getString();
        Serial.println(payload);
      } else {
        Serial.print("Error code: ");
        Serial.println(httpResponseCode);
      }

      http.end();
    }
    delay(30000);
  }
  ```

- **CoAP:**

  - **概要:** デバイスは CoAP リクエストをサーバーに送信し、レスポンスを受信します。CoAP は UDP ベースで軽量な通信を目的としています。

  **注意:** 現状、Arduino IDE で動作する安定した CoAP クライアントライブラリは少ないです。より複雑な環境(Linux ベースなど)で CoAP は効果を発揮します。

**15.4.5. 実践的なテクニック**

- **QoS (Quality of Service) (MQTT):** MQTT では、メッセージの配信品質を制御するために、QoS レベルを設定できます。QoS 0 は「最大 1 回配信」、QoS 1 は「少なくとも 1 回配信」、QoS 2 は「正確に 1 回配信」を保証します。
- **RESTful API (HTTP):** HTTP を使用する場合は、RESTful API を設計することで、リソースの管理とアクセスを効率化できます。
- **観察 (CoAP):** CoAP では、クライアントがリソースを観察し、リソースの状態が変化したときにサーバーから通知を受け取ることができます。

**15.4.6. 応用例とユースケース**

- **MQTT:** スマートホーム（照明、温度制御）、産業用センサーネットワーク、リアルタイムデータ分析。
- **HTTP:** ウェブインターフェース、API 連携、ファイル転送、クラウドサービスとの連携。
- **CoAP:** スマート照明、環境センサー、スマートメーター、リソース制約のある IoT デバイス。

**15.4.7. トラブルシューティング**

- **MQTT:** 接続の問題、認証の問題、メッセージの配信の問題。
- **HTTP:** サーバーエラー、タイムアウト、認証の問題。
- **CoAP:** パケット損失、再送の問題、リソースの発見の問題。
