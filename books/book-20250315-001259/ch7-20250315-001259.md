# 第7章：会議議事録自動作成チャットボットの実装  

## 7.1 会議録音と音声データの収集

### 7.1.1 概要と目的

会議議事録自動作成の第一歩は、会議の高品質な音声データの収集です。LINE WORKSは、社内コミュニケーションの主要ツールとして、オンライン会議や電話会議の録音機能と連携可能な環境を提供します。ここでは、適切な機材の選定や録音環境の整備、録音データのクラウド保存など、会議の音声データを確実に収集する方法を解説します。

### 7.1.2 音声収集の基本ステップ

1. **機材と環境の整備:**  
   ・高品質な外部マイクや専用ICレコーダーを用いる。  
   ・会議室内の雑音対策（ノイズキャンセリング機能の活用）。  
2. **録音の実施:**  
   ・会議開始前にLINE WORKSの専用録音機能または連携アプリで録音を開始し、会議終了時に停止する。  
3. **ファイル管理:**  
   ・録音ファイルに会議日時、議題、参加者情報などのメタデータを付与し、クラウドストレージ（例：LINE WORKS Drive、Google Drive）に保存する。

### 7.1.3 実践的なポイント

- **マイクの配置と録音レベルの調整:** 適切な位置にマイクを設置し、最適な録音レベルに設定することで、後工程の音声認識精度が向上します。  
- **参加者への周知:** 会議の冒頭で録音開始を参加者に伝え、録音の目的と利用方法について理解を得ることが大切です。

## 7.2 音声認識と文字起こし

### 7.2.1 概要と目的

収集した音声データを文字情報に変換する音声認識は、会議議事録自動作成の重要なステップです。高精度な文字起こしが、後続の要約・議事録生成の品質に直結します。ここでは、Google Cloud Speech-to-Text などの外部APIを利用した文字起こしの実装例と、その注意点について説明します。

### 7.2.2 文字起こしの基本手法

#### Google Cloud Speech-to-Text を用いた例

```python
import io
import os
from google.cloud import speech

# 認証情報の設定（サービスアカウントのJSONファイルのパスを指定）
os.environ["GOOGLE_APPLICATION_CREDENTIALS"] = "path/to/your/service-account-file.json"

def transcribe_file(speech_file: str) -> str:
    """指定された音声ファイルを文字起こしする"""
    client = speech.SpeechClient()
    with io.open(speech_file, "rb") as audio_file:
        content = audio_file.read()
    audio = speech.RecognitionAudio(content=content)
    config = speech.RecognitionConfig(
        encoding=speech.RecognitionConfig.AudioEncoding.LINEAR16,
        sample_rate_hertz=16000,
        language_code="ja-JP",
    )
    response = client.recognize(config=config, audio=audio)
    transcript = ""
    for result in response.results:
        transcript += result.alternatives[0].transcript + "\n"
    return transcript

# 実行例
transcript = transcribe_file("path/to/your/audio-file.wav")
print("文字起こし結果:\n", transcript)
```

### 7.2.3 実践的なテクニック

- **ノイズ除去とファイル形式変換:** 音質向上のため、録音後にノイズ除去を行い、認識エンジンが推奨する形式（例：WAV）に変換します。  
- **発話区間の分割:** 長時間録音の場合は、会話区間ごとにファイルを分割して認識させることで、認識精度を向上させます。

## 7.3 議事録の作成：Claude 3.7による要約と構造化

### 7.3.1 概要と目的

文字起こしされた生テキストは、そのままでは冗長で読みづらい場合が多いため、Claude 3.7の自然言語処理機能を活用して、テキストを要約・構造化し、わかりやすい議事録として整形します。LINE WORKSで受信した会議音声のテキストデータを基に、重要な議題、決定事項、タスクを抽出し、Markdown形式などで整った議事録を自動生成します。

### 7.3.2 Claude 3.7による議事録生成の実装例

```python
import anthropic
import os

# Anthropic APIキーを環境変数から取得
client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

def create_meeting_minutes(transcript: str) -> str:
    """
    文字起こしされた会議テキストを元に、Claude 3.7 を用いて議事録を生成する関数。
    プロンプトには、会議の目的、議題、決定事項、タスクの抽出およびMarkdown形式での出力を指示する。
    """
    prompt = f"""以下の会議記録から、議事録を作成してください。

【要求事項】
- 会議の目的と結論を簡潔にまとめる。
- 主な議題と議論のポイントを箇条書きで記述する。
- 決定事項やタスク、アクションアイテムを明示する。
- Markdown形式で出力する。

【会議記録】
{transcript}

【議事録】:
"""
    response = client.messages.create(
        model="claude-3-opus-20240229",
        max_tokens=2048,
        messages=[{"role": "user", "content": prompt}],
    )
    return response.content[0].text

# 例：文字起こしデータをもとに議事録生成
transcript_data = """
[会議開始]
A: 本日は新製品のマーケティング戦略について議論します。
B: ターゲット層は20代から30代の女性です。
C: SNSでのプロモーションが効果的だと思います。
A: インフルエンサーマーケティングも検討しましょう。
[決定事項]
- SNSプロモーションを実施する。
- インフルエンサーマーケティングを検討する。
[タスク]
- B: SNSプロモーションの企画書を作成 (期日: 1週間後)。
- C: インフルエンサーリストを作成 (期日: 1週間後)。
[会議終了]
"""
minutes = create_meeting_minutes(transcript_data)
print("生成された議事録:\n", minutes)
```

### 7.3.3 プロンプトエンジニアリングのポイント

- **具体的な指示:** Markdown形式での出力、議事録の各要素（目的、議題、決定事項、タスク）の抽出を明記。  
- **例示:** 具体的な会議記録をプロンプトに含めることで、Claude 3.7が期待する出力形式を把握しやすくします。  
- **フィードバック:** 生成された議事録を人間がレビューし、次回以降のプロンプト改善に活かす仕組みを検討します。

## 7.4 議事録の共有と活用

### 7.4.1 概要と目的

生成された議事録は、会議参加者や関係者に迅速かつ正確に共有する必要があります。LINE WORKSは、チャットベースでの情報共有に優れており、議事録の自動配信や通知機能を活用することで、情報の伝達とフィードバックの取得を効率化できます。

### 7.4.2 共有方法と実装例

#### LINE WORKS への自動共有

LINE WORKS API を利用して、生成された議事録をチャットメッセージとして送信する例です。以下は、シンプルな送信関数の例です。

```python
import requests
import os

def send_minutes_to_line_works(minutes: str):
    """
    LINE WORKS API を利用して、生成された議事録を送信する関数
    """
    url = "https://apis.worksmobile.com/v1/bots/your_bot_id/messages"
    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {os.getenv('LINE_WORKS_API_TOKEN')}"
    }
    data = {
        "accountId": os.getenv("LINE_WORKS_ACCOUNT_ID"),
        "content": {
            "type": "text",
            "text": minutes
        }
    }
    response = requests.post(url, headers=headers, json=data)
    if response.status_code == 200:
        print("LINE WORKSに議事録送信完了")
    else:
        print("送信失敗:", response.status_code, response.text)

# 例：生成された議事録をLINE WORKSに送信
send_minutes_to_line_works(minutes)
```

### 7.4.3 実践的なポイント

- **共有テンプレート:** 議事録に共通のフォーマット（会議日時、参加者、議題など）を自動付与する。  
- **通知とフィードバック:** 議事録共有後、参加者からのコメントやフィードバックを受け付け、次回以降の議事録改善に活用する仕組みを構築する。  
- **タスク管理連携:** 議事録から抽出されたタスクを、タスク管理ツール（例：Asana、Trello）と連携させることで、アクションの追跡を容易にする。

## 7.5 LINE WORKS × Claude 3.7 × MCP 統合による全体運用

### 7.5.1 統合の意義

本システムは、LINE WORKSをフロントエンド、Claude 3.7による自然言語処理、そしてMCP（Model Context Protocol）を活用して、会議録音から議事録生成、そしてその共有までの一連のプロセスを自動化・統合します。これにより、以下の効果が得られます。

- **業務効率の向上:** 手作業による議事録作成を大幅に削減し、会議後の情報伝達を迅速化。  
- **正確性と一貫性:** Claude 3.7の高精度な要約と、MCPによる文脈情報の一元管理により、議事録の品質が向上。  
- **多チャネル対応:** LINE WORKSだけでなく、他の社内チャネルにも議事録を柔軟に共有できる体制を実現。

### 7.5.2 統合処理の全体フローと実装例

以下は、ユーザー（会議参加者）の問い合わせから始まり、音声認識、議事録生成、そして最終的にLINE WORKSへ共有するまでの統合処理の例です。MCPは、各工程間で文脈情報を一元管理する役割を担います。

```python
import os
import time
import random
import logging
import asyncio
import json
from contextlib import AsyncExitStack
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
import httpx

logging.basicConfig(level=logging.INFO, format="%(asctime)s - %(levelname)s - %(message)s")

# --- Configuration クラス ---
class Configuration:
    def __init__(self) -> None:
        from dotenv import load_dotenv
        load_dotenv()
        self.api_key = os.getenv("LLM_API_KEY")
    
    @staticmethod
    def load_config(file_path: str) -> dict:
        with open(file_path, "r") as f:
            return json.load(f)
    
    @property
    def llm_api_key(self) -> str:
        if not self.api_key:
            raise ValueError("LLM_API_KEY not found in environment variables")
        return self.api_key

# --- FAQデータベース（生回答の例） ---
FAQ_DATABASE = {
    "meeting_minutes": "議事録の基本フォーマットとして、会議の目的、議題、決定事項、タスクを記載します。"
}

# --- Claude 3.7 連携 ---
def call_claude_for_minutes(transcript: str, raw_template: str, context: dict = None) -> str:
    """
    Claude 3.7 に対して、会議の文字起こしから議事録を生成するプロンプトを投げる模擬実装
    """
    logging.info("Claude 3.7 への議事録生成リクエスト開始...")
    if context:
        logging.info("MCP: 文脈情報を受信: " + str(context))
    time.sleep(random.uniform(0.5, 1.0))
    enriched_minutes = (
        f"{raw_template} 以下、要約された議事録:\n"
        "【会議目的】新製品のマーケティング戦略の策定\n"
        "【主な議題】ターゲット層の明確化、SNSプロモーション、インフルエンサーマーケティングの検討\n"
        "【決定事項】SNSプロモーション実施、インフルエンサーマーケティングの検討\n"
        "【タスク】企画書作成（B担当、1週間後）、インフルエンサーリスト作成（C担当、1週間後）\n"
    )
    logging.info("Claude 3.7 議事録生成完了")
    return enriched_minutes

# --- MCP を利用した文脈情報取得 ---
def get_mcp_context(user_id: str) -> dict:
    context = {"last_transcript": "Previous meeting transcript details"}
    logging.info("MCP: 文脈情報取得: " + str(context))
    return context

# --- LINE WORKS への議事録送信 ---
def send_minutes_to_line_works(minutes: str) -> None:
    url = "https://apis.worksmobile.com/v1/bots/your_bot_id/messages"
    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {os.getenv('LINE_WORKS_API_TOKEN')}"
    }
    data = {
        "accountId": os.getenv("LINE_WORKS_ACCOUNT_ID"),
        "content": {
            "type": "text",
            "text": minutes
        }
    }
    response = httpx.post(url, headers=headers, json=data)
    if response.status_code == 200:
        logging.info("LINE WORKSに議事録送信完了")
    else:
        logging.error("送信失敗: %s - %s", response.status_code, response.text)

# --- Server, Tool, LLMClient, ChatSession クラスは第6章と共通の実装例を利用（省略） ---
# ※ ここでは前章と同様の MCP サーバー接続管理クラスやツール管理クラスを流用します

# --- 統合チャットセッションで議事録作成を含む対話の統括 ---
class ChatSession:
    def __init__(self, servers: list, llm_client: LLMClient) -> None:
        self.servers = servers
        self.llm_client = llm_client

    async def cleanup_servers(self) -> None:
        cleanup_tasks = [asyncio.create_task(server.cleanup()) for server in self.servers]
        if cleanup_tasks:
            await asyncio.gather(*cleanup_tasks, return_exceptions=True)

    async def start(self) -> None:
        try:
            for server in self.servers:
                await server.initialize()
            messages = [{"role": "system", "content": "Meeting Minutes Generation Session Initialized."}]
            # ユーザーからの議事録生成依頼をシミュレーション
            while True:
                try:
                    user_input = input("会議議事録生成依頼を入力（exitで終了）: ").strip()
                    if user_input.lower() in ["quit", "exit"]:
                        logging.info("セッション終了")
                        break

                    messages.append({"role": "user", "content": user_input})
                    # ここでは、音声認識済みの議事録原稿（文字起こし）を user_input と仮定
                    raw_template = FAQ_DATABASE.get("meeting_minutes")
                    context = get_mcp_context("user123")
                    minutes = call_claude_for_minutes(user_input, raw_template, context)
                    logging.info("生成された議事録:\n%s", minutes)
                    send_minutes_to_line_works(minutes)
                    messages.append({"role": "assistant", "content": minutes})
                except KeyboardInterrupt:
                    logging.info("セッション終了")
                    break
        finally:
            await self.cleanup_servers()

class LLMClient:
    def __init__(self, api_key: str) -> None:
        self.api_key = api_key

    def get_response(self, messages: list[dict]) -> str:
        return "Simulated LLM response for meeting minutes."

# --- Server, Tool クラスおよびその他の MCP クライアント処理は前章と同様に実装（省略） ---

# --- main() 関数 ---
async def main() -> None:
    config = Configuration()
    server_config = config.load_config("servers_config.json")
    servers = [Server(name, srv_config) for name, srv_config in server_config["mcpServers"].items()]
    llm_client = LLMClient(config.llm_api_key)
    chat_session = ChatSession(servers, llm_client)
    await chat_session.start()

if __name__ == "__main__":
    asyncio.run(main())
```
