## 第10章：Notarization必須！Appleの審査をパスする

この章では、macOSアプリケーションを開発・配布する上で避けて通れないNotarization（公証）について、徹底的に解説します。Appleの審査をパスし、Gatekeeperのセキュリティをクリアして、ユーザーに安心してアプリケーションを使ってもらうために、Notarizationの仕組み、具体的な手順、そしてトラブルシューティングまで、網羅的に理解していきましょう。

### Notarizationとは？Gatekeeper対策

**概要と重要性**

Notarizationとは、AppleがmacOSアプリケーションのセキュリティを強化するために導入した仕組みです。簡単に言うと、Appleがあなたのアプリケーションに「安全ですよ」というお墨付きを与えるプロセスです。このお墨付きがないと、macOSに標準搭載されているセキュリティ機能であるGatekeeperが、アプリケーションの起動をブロックする可能性があります。

Gatekeeperは、ユーザーをマルウェアから保護するために、インターネットからダウンロードされたアプリケーションが安全かどうかを検証します。Notarizationを受けていないアプリケーションは、Gatekeeperによって「開発元が未確認のアプリケーション」として扱われ、ユーザーに警告が表示されるか、最悪の場合は起動を拒否されてしまいます。

**特徴と利点**

Notarizationを受けることによって、以下のようなメリットがあります。

*   **Gatekeeperによる起動ブロックの回避:** ユーザーは警告なしにアプリケーションを起動できます。
*   **信頼性の向上:** Appleからのお墨付きがあるため、ユーザーは安心してアプリケーションを利用できます。
*   **ブランドイメージの向上:** セキュリティ意識の高い開発者として認識され、ブランドイメージが向上します。
*   **macOSの最新機能への対応:** 今後、AppleはNotarizationを必須とする可能性があり、早期に対応することで将来的なリスクを回避できます。

**事前準備と前提条件**

Notarizationを受けるためには、以下の準備が必要です。

1.  **Apple Developer Programへの登録:** 有料のApple Developer Programに登録する必要があります。（登録方法については後述）
2.  **有効な開発者証明書:** アプリケーションを署名するために有効な開発者証明書が必要です。
3.  **Xcodeのインストール:** Xcodeを使用してアプリケーションをビルドし、署名する必要があります。
4.  **App-Specific Passwordの作成:** Notarizationの申請には、App-Specific Passwordを使用します。（作成方法については後述）
5.  **ターミナルの使用:** Notarizationの申請と確認は、主にターミナルからコマンドを実行して行います。

**基本的な使い方**

Notarizationの基本的な流れは以下の通りです。

1.  **アプリケーションのビルドと署名:** Xcodeでアプリケーションをビルドし、開発者証明書で署名します。
2.  **Notarizationの申請:** `notarytool`コマンドを使用して、アプリケーションをAppleに送信し、Notarizationを申請します。
3.  **Notarizationのステータス確認:** `notarytool`コマンドを使用して、Notarizationのステータスを確認します。
4.  **アプリケーションの配布:** Notarizationが完了したら、アプリケーションを配布します。

**実践的なテクニック**

*   **自動化:** Notarizationのプロセスを自動化するために、スクリプトやCI/CDツールを活用しましょう。
*   **トラブルシューティング:** エラーが発生した場合は、エラーメッセージをよく読み、Appleのドキュメントやコミュニティフォーラムを参考に解決策を探しましょう。
*   **最新情報の追跡:** AppleはNotarizationの要件を頻繁に変更するため、常に最新情報を追跡しましょう。

**応用例とユースケース**

*   **社内配布アプリケーション:** 社内だけで使用するアプリケーションも、Notarizationを受けることでセキュリティを強化できます。
*   **オープンソースアプリケーション:** オープンソースアプリケーションも、Notarizationを受けることで、より多くのユーザーに安心して利用してもらえます。
*   **プラグイン/拡張機能:** macOSアプリケーションのプラグインや拡張機能も、Notarizationを受けることで、セキュリティリスクを低減できます。

**トラブルシューティング**

*   **「開発元が未確認のため開けません」というエラーが表示される:** Notarizationを受けていないか、Gatekeeperの設定が厳しすぎる可能性があります。
*   **Notarizationの申請に失敗する:** Apple Developer Programの登録状況、証明書の有効期限、App-Specific Passwordの誤りなどを確認してください。
*   **Notarizationのステータスが長時間「In Progress」のまま変わらない:** Appleのサーバーが混雑しているか、何らかの問題が発生している可能性があります。しばらく待ってから再度確認するか、Apple Developer Supportに問い合わせてください。

**まとめと次のステップ**

Notarizationは、macOSアプリケーションのセキュリティを確保し、ユーザーに安心して利用してもらうための重要なプロセスです。次のセクションでは、Apple Developer Programへの登録とApp-Specific Passwordの作成について、詳しく解説します。

### Apple Developer Programへの登録とApp-Specific Passwordの作成

**概要と重要性**

Notarizationを受けるためには、Apple Developer Programへの登録が必須です。また、Notarizationの申請には、通常のApple IDのパスワードではなく、App-Specific Passwordを使用する必要があります。ここでは、これらの手順について詳しく解説します。

**特徴と利点**

*   **Apple Developer Programへの登録:** アプリケーションの署名、Notarizationの申請、App Storeへの公開など、Appleのエコシステムを利用するために必要な手続きです。
*   **App-Specific Passwordの作成:** 通常のApple IDのパスワードとは別に、特定のアプリケーションやサービス専用のパスワードを作成することで、セキュリティを強化できます。

**事前準備と前提条件**

*   **Apple ID:** Apple Developer Programへの登録には、Apple IDが必要です。
*   **クレジットカード:** Apple Developer Programへの登録には、年会費が必要です。

**基本的な使い方**

**1. Apple Developer Programへの登録**

1.  Apple Developer Programのウェブサイトにアクセスします。
2.  「Enroll」ボタンをクリックします。
3.  Apple IDでサインインします。
4.  組織（企業、団体、政府機関）として登録するか、個人として登録するかを選択します。
5.  必要な情報を入力し、登録手続きを完了します。
6.  年会費を支払います。

**2. App-Specific Passwordの作成**

1.  Apple IDのアカウントページにアクセスします。（[https://appleid.apple.com/](https://appleid.apple.com/)）
2.  Apple IDでサインインします。
3.  「セキュリティ」セクションに移動します。
4.  「App-Specific Passwords」セクションで、「Generate Password...」をクリックします。
5.  パスワードの名前を入力します。（例: "Notarization")
6.  生成されたパスワードをコピーして安全な場所に保存します。**このパスワードは一度しか表示されません。**

**実践的なテクニック**

*   **App-Specific Passwordの管理:** 複数のアプリケーションやサービスでApp-Specific Passwordを使用する場合は、パスワードマネージャーなどを活用して安全に管理しましょう。
*   **2ファクタ認証の有効化:** Apple IDのセキュリティをさらに強化するために、2ファクタ認証を有効にしましょう。

**応用例とユースケース**

*   **CI/CD環境でのNotarization:** CI/CDパイプラインでNotarizationを自動化する際に、App-Specific Passwordを使用します。
*   **複数人での開発:** 複数人で開発を行う場合、各開発者がそれぞれApp-Specific Passwordを作成することで、セキュリティリスクを分散できます。

**トラブルシューティング**

*   **Apple Developer Programへの登録に失敗する:** 入力情報に誤りがないか、クレジットカード情報が正しいかを確認してください。
*   **App-Specific Passwordの作成に失敗する:** Apple IDのセキュリティ設定を確認し、2ファクタ認証が有効になっているか確認してください。

**まとめと次のステップ**

Apple Developer Programへの登録とApp-Specific Passwordの作成が完了したら、次のセクションでは、`notarytool`コマンドの使い方について詳しく解説します。

### `notarytool`コマンドの使い方：Notarizationの申請と確認

**概要と重要性**

`notarytool`は、Appleが提供するコマンドラインツールで、Notarizationの申請とステータス確認を行うために使用します。このツールを使いこなすことで、Notarizationのプロセスを効率的に管理できます。`notarytool`は macOS 12.3 以降に含まれています。それ以前のバージョンでは `xcrun altool` を利用する必要がありますが、`notarytool` の利用が推奨されています。

**特徴と利点**

*   **コマンドラインインターフェース:** ターミナルから簡単に操作できます。
*   **自動化:** スクリプトやCI/CDツールに組み込んで、Notarizationのプロセスを自動化できます。
*   **詳細なステータス情報:** Notarizationのステータスを詳細に確認できます。

**事前準備と前提条件**

*   **`notarytool`のインストール:** Xcode Command Line Toolsがインストールされている必要があります。通常、Xcodeをインストールすると自動的にインストールされます。
*   **Apple Developer Programへの登録:** 前述の通り、Apple Developer Programへの登録が必要です。
*   **App-Specific Passwordの作成:** 前述の通り、App-Specific Passwordを作成する必要があります。

**基本的な使い方**

`notarytool`の基本的なコマンドは以下の通りです。

*   **`notarytool submit`:** Notarizationの申請を行います。
*   **`notarytool info`:** Notarizationのステータスを確認します。
*   **`notarytool history`:** 過去のNotarizationの履歴を表示します。

**1. Notarizationの申請**

```bash
notarytool submit <アプリケーションのパス> \
--keychain-profile "<キーチェーンプロファイル名>"
```

または

```bash
notarytool submit <アプリケーションのパス> \
--apple-id "<Apple ID>" \
--password "<App-Specific Password>" \
--team-id "<Team ID>"
```

*   `<アプリケーションのパス>`: Notarizationを申請するアプリケーションのパスを指定します。例: `/path/to/MyApp.app`
*   `--keychain-profile "<キーチェーンプロファイル名>"`: Xcodeで設定したキーチェーンプロファイル名を指定します。Xcodeの設定でDistribution用の証明書とプロビジョニングプロファイルを選択している場合、`--keychain-profile`オプションが便利です。`codesign` コマンドで利用する証明書を指定する際に利用するキーチェーンプロファイルを指定します。

または

*   `--apple-id "<Apple ID>"`: Apple IDを指定します。
*   `--password "<App-Specific Password>"`: App-Specific Passwordを指定します。
*   `--team-id "<Team ID>"`: Team IDを指定します。Apple Developer Programのメンバーシップ情報に記載されています。

`--apple-id`, `--password`, `--team-id` は、キーチェーンプロファイルを設定していない場合に利用します。

**2. Notarizationのステータス確認**

```bash
notarytool info <リクエストUUID>
```

*   `<リクエストUUID>`: Notarizationの申請時に返されたリクエストUUIDを指定します。

**実践的なテクニック**

*   **キーチェーンプロファイルの作成:** Xcodeでキーチェーンプロファイルを作成し、`notarytool`で利用することで、コマンドを簡略化できます。

    *   Xcodeを起動
    *   Xcodeメニューから「Xcode」→「Settings」を選択
    *   「Accounts」タブを選択
    *   Apple IDを選択し、「Manage Certificates...」をクリック
    *   「+」ボタンをクリックし、「Apple Distribution」を選択
    *   キーチェーンアクセスを求められたら許可
    *   ターミナルで`security find-identity -v -p codesigning` コマンドを実行して証明書を確認
    *   `notarytool submit`コマンドで `--keychain-profile "<キーチェーンプロファイル名>"` オプションを指定

*   **スクリプトの作成:** Notarizationの申請とステータス確認を自動化するスクリプトを作成しましょう。

**応用例とユースケース**

*   **CI/CDパイプラインでのNotarization:** CI/CDパイプラインに`notarytool`コマンドを組み込むことで、アプリケーションのビルドからNotarizationまでを自動化できます。
*   **複数環境でのNotarization:** 開発環境、テスト環境、本番環境など、複数の環境でNotarizationを行う場合、スクリプトやCI/CDツールを活用して効率的に管理できます。

**トラブルシューティング**

*   **`notarytool`コマンドが見つからない:** Xcode Command Line Toolsがインストールされているか確認してください。
*   **Notarizationの申請に失敗する:** エラーメッセージをよく読み、Apple Developer Programの登録状況、証明書の有効期限、App-Specific Passwordの誤り、アプリケーションの署名などに問題がないか確認してください。

    *   **一般的なエラー:**
        *   **"No suitable signing certificate found."**: 有効なDistribution証明書がキーチェーンに存在しない場合に発生します。Xcodeで証明書を作成し、キーチェーンにインストールされていることを確認してください。
        *   **"The specified application could not be found."**: アプリケーションのパスが間違っているか、アプリケーションが存在しない場合に発生します。パスを確認してください。
        *   **"Invalid username or password."**: Apple IDまたはApp-Specific Passwordが間違っている場合に発生します。正しい情報を入力してください。
        *   **"You are not authorized to submit notary requests."**: Apple Developer Programの契約が有効でないか、必要な権限がない場合に発生します。Apple Developer Programの契約状況を確認し、必要な権限があることを確認してください。
*   **Notarizationのステータスが長時間「In Progress」のまま変わらない:** Appleのサーバーが混雑しているか、何らかの問題が発生している可能性があります。しばらく待ってから再度確認するか、Apple Developer Supportに問い合わせてください。
*   **ステータス確認で"Invalid Submission ID"と表示される**： UUIDが間違っている可能性があります。 申請時のレスポンスを再度確認してください。

**まとめと次のステップ**

`notarytool`コマンドを使いこなすことで、Notarizationのプロセスを効率的に管理できます。この章で学んだ知識を活かして、あなたのmacOSアプリケーションをNotarizationし、ユーザーに安心して利用してもらいましょう。

Notarizationは、macOSアプリケーション開発において非常に重要なステップです。この章で解説した内容を参考に、Notarizationを正しく理解し、実践することで、Appleの審査をパスし、安全なアプリケーションを提供できるようになります。
