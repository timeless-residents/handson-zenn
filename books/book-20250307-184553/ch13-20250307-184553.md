## 第12章：PyInstaller, DMGbuild, codesign, Notarization の自動化

### GitHub Actions ワークフローの例：Python環境構築、依存関係インストール

#### 概要と重要性

ソフトウェア開発において、自動化は効率化と品質向上のための鍵となります。特に、PyInstallerによる実行ファイルの作成、DMGbuildによるパッケージング、codesignによる署名、そしてmacOSのNotarizationといった一連の作業は、手動で行うと時間と労力がかかり、人的ミスが発生する可能性も高まります。GitHub Actionsを使用することで、これらのプロセスを自動化し、再現性のあるビルド環境を構築できます。

#### 特徴と利点

GitHub Actionsは、GitHubリポジトリで発生するイベント（push、pull request、scheduleなど）に応じてワークフローを実行できるCI/CDプラットフォームです。

*   **自動化**: コードが変更されるたびにビルド、パッケージング、署名、Notarizationを自動的に実行できます。
*   **再現性**: ワークフローは定義された環境で実行されるため、ビルド結果の一貫性が保たれます。
*   **効率化**: 人的ミスを減らし、開発者の時間を節約できます。
*   **可視化**: ビルドのステータスやログをGitHub上で確認できます。

#### 事前準備と前提条件

*   GitHubアカウント
*   GitHubリポジトリ
*   Pythonプロジェクト（PyInstallerで実行ファイルを作成できる状態）
*   macOS開発環境（codesignとNotarizationに必要なツール）
*   Apple Developer Programへの登録 (Notarizationに必要)
*   環境変数として設定する各種秘密鍵や証明書 (後述)

#### 基本的な使い方

GitHub Actionsのワークフローは、YAML形式のファイルで定義されます。`.github/workflows`ディレクトリ内にワークフローファイルを作成します。以下に、Python環境構築、依存関係インストール、PyInstaller実行、DMGbuildの実行を行う基本的なワークフローの例を示します。

```yaml
name: Build and Package

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: macos-latest # macOSの最新バージョンを使用

    steps:
      - uses: actions/checkout@v3 # リポジトリをチェックアウト

      - name: Set up Python 3.x
        uses: actions/setup-python@v4
        with:
          python-version: '3.x' # Python 3.x系を使用

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt # 依存関係をインストール
          pip install pyinstaller dmgbuild # PyInstallerとDMGbuildをインストール

      - name: Run PyInstaller
        run: pyinstaller --onefile your_script.py # PyInstallerを実行

      - name: Create DMG
        run: dmgbuild -s dmgbuild.settings dist/YourApp.dmg # DMGbuildを実行

      - name: Upload Artifact
        uses: actions/upload-artifact@v3
        with:
          name: YourApp.dmg
          path: dist/YourApp.dmg
```

このワークフローは、`main`ブランチへのpushまたはpull requestが発生したときにトリガーされます。

1.  `actions/checkout@v3`でリポジトリをチェックアウトします。
2.  `actions/setup-python@v4`でPython 3.xを設定します。
3.  `pip install -r requirements.txt`で依存関係をインストールします。
4.  `pyinstaller --onefile your_script.py`でPyInstallerを実行し、単一の実行ファイルを作成します。`your_script.py`は、PyInstallerで実行ファイルを作成したいPythonスクリプトの名前に置き換えてください。
5.  `dmgbuild -s dmgbuild.settings dist/YourApp.dmg`でDMGファイルを作成します。`dmgbuild.settings`はDMGbuildの設定ファイル、`YourApp.dmg`は作成するDMGファイルの名前です。
6.  `actions/upload-artifact@v3`で作成されたDMGファイルをアーティファクトとしてアップロードし、ダウンロードできるようにします。

#### 実践的なテクニック

*   **キャッシュの利用**: 依存関係のインストールをキャッシュすることで、ワークフローの実行時間を短縮できます。

    ```yaml
    - name: Cache dependencies
      uses: actions/cache@v3
      with:
        path: ~/.cache/pip
        key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
        restore-keys: |
          ${{ runner.os }}-pip-
    ```

*   **並列処理**: 複数のジョブを並列に実行することで、ビルド時間を短縮できます。
*   **エラーハンドリング**: ワークフローが失敗した場合に通知を受け取るように設定できます。

    ```yaml
    - name: Send Slack Notification
      if: failure()
      uses: rtCamp/action-slack-notify@v2
      env:
        SLACK_CHANNEL: '#your-slack-channel'
        SLACK_COLOR: '#FF0000'
        SLACK_TITLE: 'Build Failed'
        SLACK_MESSAGE: 'The build failed. Check the logs for details.'
        SLACK_WEBHOOK: ${{ secrets.SLACK_WEBHOOK }}
    ```

*   **詳細なログ**: ログを詳細に出力するように設定することで、問題の特定が容易になります。`run`ステップに`-v`オプションを追加することで、詳細なログを出力できます。

#### 応用例とユースケース

*   **リリースプロセス**: タグが作成されたときに、自動的にビルド、パッケージング、署名、Notarizationを行い、リリースを作成できます。
*   **ナイトリービルド**: 毎日自動的にビルドを行い、開発チームに最新のビルドを提供できます。
*   **プルリクエストの検証**: プルリクエストが作成されたときに、自動的にビルドを行い、テストを実行し、品質を検証できます。

#### トラブルシューティング

*   **依存関係のエラー**: 依存関係のバージョンが競合している可能性があります。`requirements.txt`でバージョンを明示的に指定するか、`pipenv`や`poetry`などのパッケージ管理ツールを使用することを検討してください。
*   **PyInstallerのエラー**: PyInstallerの設定が間違っている可能性があります。PyInstallerのドキュメントを参考に、適切な設定を行ってください。
*   **DMGbuildのエラー**: DMGbuildの設定ファイルが間違っている可能性があります。DMGbuildの設定ファイルを確認し、正しい設定を行ってください。

#### まとめと次のステップ

GitHub Actionsを使用することで、PyInstallerによる実行ファイルの作成、DMGbuildによるパッケージングを自動化できます。次のステップとして、codesignによる署名とNotarizationの自動化について学習しましょう。

### ビルド、パッケージング、署名、Notarizationの自動化

#### 概要と重要性

macOSアプリケーションを配布するには、Appleのcodesignツールで署名し、Notarization（公証）を受ける必要があります。これらのプロセスもGitHub Actionsで自動化することで、開発者はアプリケーションの品質向上に集中できます。

#### 特徴と利点

*   **セキュリティ**: 署名とNotarizationにより、アプリケーションの信頼性を高めることができます。
*   **ユーザーエクスペリエンス**: 署名されていないアプリケーションは、macOSによって警告が表示されるため、ユーザーエクスペリエンスが低下します。
*   **自動化**: これらのプロセスを自動化することで、時間と労力を節約できます。

#### 事前準備と前提条件

*   Apple Developer Programへの登録
*   Developer ID証明書 (codesignに使用)
*   Application Loaderまたは`xcrun altool` (Notarizationに使用)
*   Apple IDとアプリ固有のパスワード (Notarizationに使用)
*   環境変数として設定する各種秘密鍵や証明書 (後述)

#### 基本的な使い方

以下のワークフロー例では、codesignによる署名とNotarizationを自動化します。

```yaml
name: Build, Sign, and Notarize

on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: macos-latest

    steps:
      - uses: actions/checkout@v3

      - name: Set up Python 3.x
        uses: actions/setup-python@v4
        with:
          python-version: '3.x'

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pyinstaller dmgbuild

      - name: Run PyInstaller
        run: pyinstaller --onefile your_script.py

      - name: Create DMG
        run: dmgbuild -s dmgbuild.settings dist/YourApp.dmg

      - name: Codesign
        run: |
          security import "${{ secrets.CERTIFICATE_PATH }}" -k ~/Library/Keychains/login.keychain-db -T /usr/bin/codesign # 証明書をインポート
          codesign --deep --force --verify --verbose --options runtime --sign "${{ secrets.DEVELOPER_ID }}" dist/YourApp.dmg # 署名

      - name: Notarize
        run: |
          xcrun notarytool submit dist/YourApp.dmg --keychain-profile "AC_PASSWORD" --wait

      - name: Staple
        run: xcrun stapler staple dist/YourApp.dmg

      - name: Upload Artifact
        uses: actions/upload-artifact@v3
        with:
          name: YourApp.dmg
          path: dist/YourApp.dmg
```

このワークフローは、`main`ブランチへのpush時にトリガーされます。

1.  これまでのステップと同様に、リポジトリをチェックアウトし、Python環境を構築し、依存関係をインストールし、PyInstallerを実行し、DMGファイルを作成します。
2.  **Codesign**:
    *   `security import "${{ secrets.CERTIFICATE_PATH }}" -k ~/Library/Keychains/login.keychain-db -T /usr/bin/codesign`で、証明書をキーチェーンにインポートします。`secrets.CERTIFICATE_PATH`は、証明書のパスを含むシークレットです。
    *   `codesign --deep --force --verify --verbose --options runtime --sign "${{ secrets.DEVELOPER_ID }}" dist/YourApp.dmg`で、DMGファイルに署名します。`secrets.DEVELOPER_ID`は、Developer IDを含むシークレットです。`--options runtime` は Hardened Runtime を有効にします。
3.  **Notarize**:
    *  `xcrun notarytool submit dist/YourApp.dmg --keychain-profile "AC_PASSWORD" --wait`で、DMGファイルをNotarizationのためにAppleに送信します。`--keychain-profile "AC_PASSWORD"` は環境変数 `AC_PASSWORD`に設定されたApple IDのパスワードを使用することを意味します。 `secrets.APP_SPECIFIC_PASSWORD` など別の名前に変更する場合は、後の環境変数設定で対応する名称で設定してください。 `--wait`オプションは、Notarizationが完了するまで待機することを意味します。`xcrun altool` が非推奨になったため、`notarytool`を使用します。
4.  **Staple**:
    *   `xcrun stapler staple dist/YourApp.dmg`で、Notarizationの情報をDMGファイルに埋め込みます。これにより、オフライン環境でもアプリケーションが正常に起動できます。
5.  `actions/upload-artifact@v3`で、署名およびNotarizationされたDMGファイルをアーティファクトとしてアップロードします。

#### 実践的なテクニック

*   **証明書の管理**: 証明書は非常に重要なので、安全に管理する必要があります。GitHub Secretsを使用して、証明書を暗号化して保存し、ワークフローでのみアクセスできるようにします。
*   **エラーハンドリング**: 署名またはNotarizationが失敗した場合、ワークフローを停止し、エラーメッセージを表示するように設定します。
*   **ログの確認**: 署名およびNotarizationのログを注意深く確認し、問題が発生していないか確認します。
*   **複数プラットフォーム対応**: macOSだけでなく、WindowsやLinux向けのビルドも自動化できます。

#### 応用例とユースケース

*   **Electronアプリケーション**: Electronアプリケーションのビルド、署名、Notarizationを自動化できます。
*   **クロスプラットフォームアプリケーション**: QtやFlutterなどのクロスプラットフォームフレームワークを使用して開発されたアプリケーションのビルド、署名、Notarizationを自動化できます。
*   **社内配布**: 社内配布用のアプリケーションの署名、Notarizationを自動化できます。

#### トラブルシューティング

*   **署名のエラー**: 証明書が正しくインストールされているか、有効期限が切れていないか確認してください。また、`codesign`コマンドのオプションが正しいか確認してください。
*   **Notarizationのエラー**: Apple Developer Programの契約が有効であるか、Apple IDとアプリ固有のパスワードが正しいか確認してください。また、Appleのサーバーが混雑している場合、Notarizationが失敗することがあります。時間を置いて再度試してみてください。
*   **Stapleのエラー**: Notarizationが完了していない場合、Stapleが失敗することがあります。Notarizationが完了するまで待ってから、Stapleを実行してください。

#### まとめと次のステップ

GitHub Actionsを使用することで、PyInstallerによる実行ファイルの作成、DMGbuildによるパッケージング、codesignによる署名、Notarizationを自動化できます。次のステップとして、環境変数の設定とシークレットの管理について学習しましょう。

### 環境変数の設定：シークレットの管理

#### 概要と重要性

ワークフローで使用するAPIキー、パスワード、証明書などの機密情報は、GitHub Secretsに安全に保存する必要があります。これらの情報をコードに直接記述したり、公開リポジトリにコミットしたりすることは絶対に避けてください。

#### 特徴と利点

*   **セキュリティ**: 機密情報を暗号化して保存し、ワークフローでのみアクセスできるようにします。
*   **管理**: 機密情報を一元的に管理できます。
*   **監査**: 機密情報の使用状況を監査できます。

#### 事前準備と前提条件

*   GitHubリポジトリ
*   機密情報 (APIキー、パスワード、証明書など)

#### 基本的な使い方

1.  GitHubリポジトリの「Settings」タブを開きます。
2.  左側のメニューから「Secrets and variables」 > 「Actions」を選択します。
3.  「New repository secret」ボタンをクリックします。
4.  シークレットの名前と値を入力します。
5.  「Add secret」ボタンをクリックします。

ワークフローでシークレットを使用するには、`${{ secrets.SECRET_NAME }}`構文を使用します。`SECRET_NAME`は、シークレットの名前に置き換えてください。

```yaml
steps:
  - name: Use secret
    run: echo "API Key: ${{ secrets.API_KEY }}"
```

この例では、`API_KEY`という名前のシークレットの値を出力します。

**macOSでの証明書（*.p12）の扱い**

macOSのcodesignで使用する証明書をGitHub Actionsの環境にセットアップするのは若干手間がかかります。以下に具体的な手順を示します。

1.  **証明書のBase64エンコード**: まず、ローカルのmacOS環境で証明書をBase64エンコードします。ターミナルで以下のコマンドを実行します。

    ```bash
    openssl pkcs12 -in your_certificate.p12 -nodes -password pass: | base64 | tr -d '\n'
    ```

    `your_certificate.p12` はあなたの証明書ファイル名に置き換えてください。パスワードは証明書作成時に設定したものを入力します。
    出力された文字列全体をコピーします。

2.  **GitHub Secretsへの登録**: GitHubリポジトリのSettings > Secrets > Actions に移動し、「New repository secret」をクリックします。
    *   Name: `CERTIFICATE_BASE64` (名前は何でも良いですが、わかりやすい名前にします)
    *   Value: 先ほどコピーしたBase64エンコードされた文字列を貼り付けます。
    「Add secret」をクリックして保存します。

3.  **ワークフローの修正**: GitHub Actionsのワークフローで、Base64デコードして証明書をキーチェーンにインポートするステップを追加します。

    ```yaml
    - name: Import certificate
      run: |
        echo "${{ secrets.CERTIFICATE_BASE64 }}" | base64 --decode > certificate.p12
        security import certificate.p12 -k ~/Library/Keychains/login.keychain-db -T /usr/bin/codesign -P ""
    ```

    このステップでは、まずGitHub Secretsに保存されたBase64エンコードされた証明書データをデコードし、`certificate.p12`というファイルに保存します。次に、`security import`コマンドを使用して、この証明書をキーチェーンにインポートします。`-P ""`はパスワードが空であることを意味します。証明書にパスワードが設定されている場合は、`-P password` のように指定します。

4.  **証明書の削除**: ワークフローの最後に、証明書ファイルを削除するステップを追加することを推奨します。これにより、環境に機密情報が残るのを防ぎます。

    ```yaml
    - name: Remove certificate
      if: always()
      run: rm certificate.p12
    ```

    `if: always()` は、前のステップが成功または失敗した場合でも、このステップが常に実行されるようにするためのものです。

#### 実践的なテクニック

*   **最小権限の原則**: シークレットを使用するジョブのみにアクセス権を付与します。
*   **シークレットのローテーション**: 定期的にシークレットをローテーションすることで、セキュリティを向上させます。
*   **ブランチ保護**: シークレットが誤って公開されないように、ブランチ保護ルールを設定します。

#### 応用例とユースケース

*   **API連携**: APIキーを安全に管理し、API連携を自動化できます。
*   **データベースアクセス**: データベースのパスワードを安全に管理し、データベースへのアクセスを自動化できます。
*   **デプロイメント**: デプロイメントキーを安全に管理し、デプロイメントを自動化できます。

#### トラブルシューティング

*   **シークレットが見つからない**: シークレットの名前が正しいか、シークレットがリポジトリに設定されているか確認してください。
*   **シークレットの値が間違っている**: シークレットの値が正しいか確認してください。また、シークレットの値が変更された場合、ワークフローを更新する必要があります。
*   **シークレットのアクセス権がない**: シークレットを使用するジョブにアクセス権が付与されているか確認してください。

#### まとめと次のステップ

GitHub Secretsを使用することで、機密情報を安全に管理し、ワークフローを安全に実行できます。この章で説明したテクニックを使用することで、PyInstaller, DMGbuild, codesign, Notarizationを自動化し、安全で効率的なソフトウェア開発プロセスを構築できます。
