## 第9章：codesignとNotarization：macOSアプリの信頼性を確保する

macOSのセキュリティモデルの中核をなすのが、コード署名 (codesign) と Notarization です。これらは、ユーザーがダウンロードし実行するアプリケーションの信頼性を保証するための重要な仕組みです。特にmacOSアプリを開発・配布する開発者にとって、codesignとNotarizationは避けて通れないプロセスであり、適切に理解し実践することで、ユーザーに安全なアプリ体験を提供し、開発者自身の信頼性を高めることができます。

### コード署名（codesign）とは？仕組みと重要性

#### 概要と重要性

コード署名は、アプリケーション、プラグイン、フレームワークなどの実行可能ファイルにデジタル署名を付与するプロセスです。これは、ソフトウェアが作成者によって署名されたものであり、署名後に改ざんされていないことを証明します。言い換えれば、あなたが作ったアプリだよ！と証明するハンコのようなものです。

macOSでは、コード署名はGatekeeperというセキュリティ機能と密接に連携しています。Gatekeeperは、署名されていない、または無効な署名を持つアプリケーションの実行をブロックすることで、ユーザーを悪意のあるソフトウェアから保護します。

#### 特徴と利点

*   **信頼性の確立:** ユーザーは、署名されたアプリケーションが信頼できるソースから提供されていることを確認できます。
*   **改ざんの防止:** 署名されたアプリケーションが改ざんされた場合、署名は無効になり、ユーザーに警告が表示されます。
*   **Gatekeeperとの連携:** macOSのセキュリティ機能であるGatekeeperが、コード署名を利用してアプリの安全性を判断します。
*   **Notarizationの前提条件:** AppleによるNotarizationを受けるためには、適切なコード署名が必須です。

#### 事前準備と前提条件

*   **Apple Developer Programへの登録:** コード署名に必要な証明書を取得するには、Apple Developer Programへの登録が必要です。
*   **Xcodeのインストール:** コード署名を行うためのツール(`codesign`コマンド)は、Xcodeに付属しています。

#### 基本的な使い方

`codesign`コマンドは、ターミナルから実行します。基本的な構文は以下の通りです。

```bash
codesign [options] path/to/application
```

主なオプションは次のとおりです。

*   `-s identity`: 使用する署名ID (証明書) を指定します。
*   `-f`: 既存の署名を上書きします。
*   `--options runtime`: Hardened Runtimeを有効にします。(後述)
*   `--timestamp`: タイムスタンプを付与します。

#### 実践的なテクニック

アプリケーションのコード署名を行う基本的な手順は次のとおりです。

1.  **証明書の確認:** `security find-identity -v -p codesigning` コマンドを使用して、利用可能な署名ID (証明書) を確認します。

2.  **コード署名:**  `codesign -s "Your Developer ID" -f --options runtime path/to/YourApp.app` コマンドでアプリケーションに署名します。 `"Your Developer ID"`の部分は、ステップ1で確認した署名IDに置き換えてください。

3.  **署名の検証:** `codesign -v -d path/to/YourApp.app` コマンドで署名が正しく適用されているか確認します。

4.  **Gatekeeperの検証:** 署名後、初めてアプリケーションを起動する際にGatekeeperのダイアログが表示されることを確認します。（環境設定によっては表示されないこともあります）

**Hardened Runtimeについて:**

`--options runtime` オプションは、Hardened Runtime を有効にするためのものです。Hardened Runtimeは、アプリのセキュリティを強化する追加の保護機能を提供します。具体的には、以下の機能が含まれます。

*   **ライブラリの不正なロード防止:** アプリが予期しないライブラリをロードするのを防ぎます。
*   **動的なコード生成の制限:** アプリが実行時にコードを生成する機能を制限します。（JITコンパイラなど）
*   **Data Execution Prevention (DEP) の強化:** メモリの実行可能領域を制限し、バッファオーバーフロー攻撃などを防ぎます。

Hardened Runtimeは、macOS Mojave (10.14) 以降で導入された機能であり、Notarizationの要件にもなっています。

#### 応用例とユースケース

*   **コマンドラインツールの署名:** Homebrewなどで配布するコマンドラインツールにも、コード署名を行うことで、ユーザーの信頼を得やすくなります。
*   **Plugin/Extensionの署名:** サードパーティ製のPluginやExtensionを開発する場合、コード署名は必須です。
*   **企業内配布:** 企業内で利用するアプリケーションを配布する際、社内用の証明書で署名することで、セキュリティを確保できます。

#### トラブルシューティング

*   **"code object is not signed at all" エラー:** 証明書が正しくインストールされていないか、または署名IDが正しく指定されていない可能性があります。`security find-identity -v -p codesigning` コマンドで証明書を確認し、`-s` オプションで正しい署名IDを指定してください。
*   **"invalid resource specification rule(s)" エラー:** アプリケーションのバンドル構造に問題がある可能性があります。`codesign` コマンドを実行する前に、アプリケーションのバンドル構造が正しいことを確認してください。(特にResourcesディレクトリの構成など)
*   **Gatekeeperがアプリをブロックする:** 証明書が信頼されていない可能性があります。システム環境設定の「セキュリティとプライバシー」で、開発者を信頼するように設定するか、証明書をキーチェーンに追加してください。 (ただし、これは推奨される方法ではありません。Notarizationを受けることを強く推奨します。)

#### まとめと次のステップ

コード署名は、macOSアプリケーションの信頼性を確保するための重要なプロセスです。適切なコード署名を行うことで、Gatekeeperによる保護を有効にし、Notarizationを受けるための準備が整います。次のステップでは、Notarizationについて詳しく解説します。

### 開発者IDの取得と証明書の設定

#### 概要と重要性

開発者IDは、Appleが発行するデジタル証明書で、あなたが正当な開発者であることを証明します。これを使用することで、あなたの署名付きアプリケーションはGatekeeperによって信頼され、ユーザーは安心してインストールし実行できます。

#### 特徴と利点

*   **Gatekeeperの信頼:** 開発者IDで署名されたアプリは、Gatekeeperによってブロックされにくくなります。
*   **Notarizationの必須条件:** AppleによるNotarizationを受けるためには、開発者IDが必須です。
*   **ユーザーからの信頼:** 署名されたアプリは、ユーザーに安心感を与え、ダウンロードやインストールを促進します。

#### 事前準備と前提条件

*   **Apple Developer Programへの登録:** まだ登録していない場合は、Apple Developer Programに登録する必要があります。(年間費用がかかります)
*   **Apple ID:** Apple Developer Programへの登録に使用するApple IDが必要です。

#### 基本的な使い方

開発者IDの取得と証明書の設定は、主にXcodeを通じて行います。

1.  **XcodeでApple IDを登録:** Xcodeの環境設定を開き、「アカウント」タブでApple IDを登録します。
2.  **証明書の作成:** Xcodeでプロジェクトを開き、「Signing & Capabilities」タブを選択します。「Automatically manage signing」にチェックを入れると、Xcodeが自動的に必要な証明書を作成してくれます。もし手動で証明書を作成する場合は、[Apple Developer Webサイト](https://developer.apple.com/) にアクセスし、「Certificates, Identifiers & Profiles」セクションから証明書を作成します。証明書のタイプとして「Developer ID Application」を選択してください。
3.  **証明書のダウンロードとインストール:** 作成した証明書をダウンロードし、キーチェーンアクセスにインストールします。

**証明書の種類について:**

Apple Developer Programには、いくつかの種類の証明書があります。

*   **Development Certificate:** 開発中に使用する証明書です。主に自分のデバイスでアプリをテストするために使用します。
*   **Distribution Certificate:** アプリをApp Storeに提出したり、TestFlightを通じて配布したり、Notarizationを受けるために使用する証明書です。Distribution Certificateには、さらに以下の種類があります。
    *   **iOS Distribution:** iOSアプリを配布するために使用します。
    *   **macOS Distribution (Developer ID):** macOSアプリをApp Store外で配布するために使用します。これが今回必要な証明書です。
    *   **macOS App Store:** macOSアプリをApp Storeで配布するために使用します。

#### 実践的なテクニック

*   **証明書の管理:** キーチェーンアクセスで証明書を安全に管理します。証明書の有効期限切れに注意し、期限が切れる前に更新してください。
*   **自動署名の活用:** Xcodeの自動署名機能を活用することで、証明書の管理を簡素化できます。ただし、自動署名がうまく動作しない場合は、手動で署名設定を行う必要があります。
*   **Provisioning Profileの理解:** Provisioning Profileは、どのデバイスでどのアプリを実行できるかを定義するファイルです。開発時にはDevelopment Provisioning Profile、配布時にはDistribution Provisioning Profileを使用します。

#### 応用例とユースケース

*   **macOSアプリの配布:** 開発者IDを使用して署名されたアプリは、自身のウェブサイトや他のプラットフォームを通じて配布できます。
*   **企業内アプリの配布:** 社内用のアプリを開発し、開発者IDを使用して署名することで、従業員に安全に配布できます。

#### トラブルシューティング

*   **"No matching signing certificate found" エラー:** 必要な証明書がキーチェーンにインストールされていないか、またはXcodeで正しいApple IDが選択されていない可能性があります。Xcodeのアカウント設定を確認し、証明書を再ダウンロードしてインストールしてください。
*   **"Code signing is required for product type 'Application' in SDK 'macOS'" エラー:** プロジェクトの署名設定が正しく構成されていない可能性があります。Xcodeの「Signing & Capabilities」タブで、正しい証明書とProvisioning Profileが選択されていることを確認してください。
*   **証明書の有効期限切れ:** 証明書の有効期限が切れると、アプリの署名が無効になります。キーチェーンアクセスで証明書の有効期限を確認し、期限が切れる前に更新してください。

#### まとめと次のステップ

開発者IDの取得と証明書の設定は、macOSアプリの信頼性を確保するための重要な第一歩です。正しい証明書を設定し、Xcodeで署名設定を行うことで、Gatekeeperに信頼されるアプリを作成できます。次のステップでは、`codesign`コマンドの使い方をさらに詳しく解説します。

### `codesign`コマンドの使い方：基本的なオプション

#### 概要と重要性

`codesign`コマンドは、ターミナルから直接コード署名を行うための強力なツールです。XcodeのGUIを通じて署名を行うこともできますが、`codesign`コマンドを理解することで、より柔軟な署名プロセスを実現できます。特に、CI/CD環境での自動署名や、複雑な署名要件に対応する場合に役立ちます。

#### 特徴と利点

*   **柔軟性:** さまざまなオプションを組み合わせることで、詳細な署名設定が可能です。
*   **自動化:** スクリプトから`codesign`コマンドを実行することで、署名プロセスを自動化できます。
*   **トラブルシューティング:** 署名に関する問題を診断するための情報を提供します。

#### 事前準備と前提条件

*   **Xcodeのインストール:** `codesign`コマンドはXcodeに付属しています。
*   **開発者IDの取得と証明書の設定:** 前述のセクションで説明した手順に従って、開発者IDを取得し、証明書を設定しておく必要があります。

#### 基本的な使い方

`codesign`コマンドの基本的な構文は次のとおりです。

```bash
codesign [options] path/to/application
```

主なオプションと使用例を以下に示します。

*   `-s identity`: 使用する署名ID (証明書) を指定します。

    ```bash
    codesign -s "Developer ID Application: Your Name (Your Team ID)" path/to/YourApp.app
    ```

*   `-f`: 既存の署名を上書きします。

    ```bash
    codesign -f -s "Developer ID Application: Your Name (Your Team ID)" path/to/YourApp.app
    ```

*   `--options runtime`: Hardened Runtimeを有効にします。

    ```bash
    codesign -s "Developer ID Application: Your Name (Your Team ID)" --options runtime path/to/YourApp.app
    ```

*   `--timestamp`: タイムスタンプを付与します。タイムスタンプを付与することで、証明書の有効期限が切れた後でも、署名が有効な期間内に署名されたことが証明できます。Notarizationを受ける場合は必須です。

    ```bash
    codesign -s "Developer ID Application: Your Name (Your Team ID)" --timestamp path/to/YourApp.app
    ```

*   `--entitlements path/to/entitlements.plist`: Entitlementsファイルへのパスを指定します。Entitlementsファイルは、アプリが要求する権限 (例えば、カメラへのアクセス、ネットワークへのアクセスなど) を定義します。

    ```bash
    codesign -s "Developer ID Application: Your Name (Your Team ID)" --entitlements YourApp.entitlements path/to/YourApp.app
    ```

*   `-v`: 詳細な出力を表示します。署名プロセス中に発生したエラーや警告を表示するのに役立ちます。

    ```bash
    codesign -v -s "Developer ID Application: Your Name (Your Team ID)" path/to/YourApp.app
    ```

*   `-d`: アプリケーションの署名情報を表示します。署名に使用された証明書やEntitlementsなどの情報を確認できます。

    ```bash
    codesign -d -s "Developer ID Application: Your Name (Your Team ID)" path/to/YourApp.app
    ```

*   `-r`: 署名の要件を指定します。通常は必要ありませんが、特定の条件を満たす場合にのみ署名を有効にする必要がある場合に利用します。

#### 実践的なテクニック

*   **複数のターゲットの署名:** Xcodeプロジェクトに複数のターゲット (例えば、アプリケーション本体とExtension) が含まれている場合、それぞれのターゲットに対して個別に署名を行う必要があります。
*   **スクリプトでの自動署名:** CI/CD環境で`codesign`コマンドをスクリプトから実行することで、署名プロセスを自動化できます。環境変数を使用して、署名IDやEntitlementsファイルのパスなどを設定すると便利です。
*   **Entitlementsファイルの管理:** Entitlementsファイルは、アプリが要求する権限を定義する重要なファイルです。EntitlementsファイルをGitなどのバージョン管理システムで管理し、変更履歴を追跡できるようにすることをお勧めします。
*   **カスタムビルド設定の利用:** Xcodeのカスタムビルド設定を利用して、デバッグビルドとリリースビルドで異なる署名設定を適用できます。

#### 応用例とユースケース

*   **CI/CD環境での自動署名:** Jenkins、GitHub Actions、GitLab CIなどのCI/CDツールを使用して、`codesign`コマンドを自動的に実行し、ビルドされたアプリケーションに署名できます。
*   **コマンドラインツールの署名:** Homebrewなどで配布するコマンドラインツールに署名する場合、`codesign`コマンドを使用します。
*   **Plugin/Extensionの署名:** サードパーティ製のPluginやExtensionを開発する場合、`codesign`コマンドを使用して、それぞれのバンドルに署名します。

#### トラブルシューティング

*   **"unsealed contents present in the bundle" エラー:** アプリケーションのバンドル内に、署名されていないファイルが存在する可能性があります。`codesign`コマンドを実行する前に、バンドル内の不要なファイルを削除してください。
*   **"resource fork, Finder information, or similar detritus not allowed" エラー:** アプリケーションのバンドル内に、macOSのリソースフォークやFinder情報などの不要なデータが含まれている可能性があります。`xattr -cr path/to/YourApp.app` コマンドを実行して、これらのデータを削除してください。
*   **"the code signature is invalid" エラー:** アプリケーションの署名が無効になっている可能性があります。署名に使用した証明書が有効であること、および署名後にアプリケーションが改ざんされていないことを確認してください。

#### まとめと次のステップ

`codesign`コマンドは、macOSアプリケーションの署名を制御するための強力なツールです。基本的なオプションを理解し、実践的なテクニックを習得することで、柔軟かつ効率的な署名プロセスを実現できます。次のステップでは、Notarizationについて詳しく解説します。

Notarizationについては、Apple Developer Webサイトのドキュメントをご参照ください。Notarizationは、コード署名に続く重要なステップであり、macOSアプリのセキュリティをさらに強化するためのものです。
