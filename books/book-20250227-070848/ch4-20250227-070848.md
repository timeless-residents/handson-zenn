## 第3章：Dockerコンテナ実践 - 人気アプリケーションのデプロイ

### Webサーバー構築：Nginx/ApacheのDocker化、HTTPS設定

**1. 概要と重要性**

Webサーバーは、インターネット上でWebサイトやアプリケーションを提供するための基盤です。Dockerを使ってNginxやApacheをコンテナ化することで、環境構築の簡素化、デプロイの高速化、そして異なる環境間での一貫性を実現できます。HTTPS設定を組み込むことで、Webサイトのセキュリティを強化し、ユーザーの信頼を得ることができます。

**2. 特徴と利点**

*   **Nginx:** 高性能なリバースプロキシ、ロードバランサー、HTTPサーバーとして機能します。軽量で設定が容易な点が特徴です。
*   **Apache:** 豊富なモジュールと柔軟な設定が可能なWebサーバーです。長年の実績があり、多くのWebアプリケーションで利用されています。
*   **Docker化の利点:**
    *   環境依存性の排除：開発、テスト、本番環境で同一の環境を再現できます。
    *   スケーラビリティ：コンテナの数を増減させることで、負荷に応じて柔軟に対応できます。
    *   容易なデプロイ：Dockerイメージを配布するだけで、環境構築の手間を省けます。

**3. 事前準備と前提条件**

*   Dockerがインストールされていること
*   Docker Composeがインストールされていること（任意ですが、複数コンテナを扱う場合は推奨）
*   基本的なLinuxコマンドの知識

**4. 基本的な使い方**

**NginxのDocker化:**

```dockerfile
# Dockerfile
FROM nginx:latest
COPY ./nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
```

*   `FROM nginx:latest`: 公式のNginxイメージをベースにします。
*   `COPY ./nginx.conf /etc/nginx/nginx.conf`: ローカルの`nginx.conf`ファイルをコンテナ内のNginx設定ファイルにコピーします。
*   `EXPOSE 80`: ポート80を外部に公開します。

```nginx
# nginx.conf (例)
events {}
http {
    server {
        listen 80;
        server_name example.com;
        root /usr/share/nginx/html;
        index index.html;

        location / {
            try_files $uri $uri/ =404;
        }
    }
}
```

Dockerイメージをビルドし、実行します。

```bash
docker build -t my-nginx .
docker run -d -p 80:80 my-nginx
```

**ApacheのDocker化:**

```dockerfile
# Dockerfile
FROM httpd:latest
COPY ./index.html /usr/local/apache2/htdocs/
EXPOSE 80
```

*   `FROM httpd:latest`: 公式のApacheイメージをベースにします。
*   `COPY ./index.html /usr/local/apache2/htdocs/`: ローカルの`index.html`ファイルをApacheのドキュメントルートにコピーします。
*   `EXPOSE 80`: ポート80を外部に公開します。

Dockerイメージをビルドし、実行します。

```bash
docker build -t my-apache .
docker run -d -p 80:80 my-apache
```

**HTTPS設定:**

Let's Encryptを使ってHTTPS証明書を取得し、NginxまたはApacheに設定します。

**Nginxの場合:**

```nginx
# nginx.conf (例)
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

**Apacheの場合:**

```apache
# VirtualHost 設定 (例)
<VirtualHost *:80>
    ServerName example.com
    Redirect permanent / https://example.com/
</VirtualHost>

<VirtualHost *:443>
    ServerName example.com
    DocumentRoot /var/www/html

    SSLEngine on
    SSLCertificateFile /etc/letsencrypt/live/example.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/example.com/privkey.pem

    <Directory "/var/www/html">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

**5. 実践的なテクニック**

*   **Dockerfileの最適化:** 不要なレイヤーを削減し、イメージサイズを小さくします。
*   **設定ファイルの外部化:** 環境変数や設定ファイルを使って、柔軟な設定を可能にします。
*   **ログ管理:** Dockerログを適切な場所に保存し、監視します。
*   **ヘルスチェック:** コンテナの状態を監視し、異常があれば自動的に再起動します。

**6. 応用例とユースケース**

*   **Webサイトホスティング:** 静的サイトや動的サイトをホスティングします。
*   **リバースプロキシ:** バックエンドサーバーへのアクセスを制御し、セキュリティを向上させます。
*   **ロードバランサー:** 複数台のサーバーに負荷を分散し、可用性を高めます。

**7. トラブルシューティング**

*   **ポート競合:** 別のプロセスが同じポートを使用している可能性があります。
*   **設定ファイルのエラー:** 設定ファイルの構文エラーや論理的な誤りがないか確認します。
*   **権限の問題:** ファイルやディレクトリへのアクセス権が適切に設定されているか確認します。
*   **コンテナの起動失敗:** ログを確認し、エラーの原因を特定します。

**8. まとめと次のステップ**

NginxやApacheをDocker化することで、Webサーバーの管理が容易になり、スケーラビリティや可用性が向上します。HTTPS設定を組み込むことで、セキュリティも強化できます。次のステップとして、WebアプリケーションのDocker化や、CI/CDパイプラインの構築を検討してみましょう。

### データベース構築：MySQL/PostgreSQLのDocker化、データ永続化

**1. 概要と重要性**

データベースは、アプリケーションのデータを保存・管理するための重要なコンポーネントです。MySQLやPostgreSQLをDockerコンテナとして実行することで、データベースの環境構築を簡素化し、複数の環境で一貫性のあるデータベース環境を構築できます。データの永続化は、コンテナが停止または削除された場合でもデータを保持するために不可欠です。

**2. 特徴と利点**

*   **MySQL:** 世界中で広く利用されているオープンソースのリレーショナルデータベース管理システムです。使いやすさと豊富な機能が特徴です。
*   **PostgreSQL:** 高度な機能と標準規格への準拠を重視した、オープンソースのリレーショナルデータベース管理システムです。複雑なデータモデルやトランザクション処理に適しています。
*   **Docker化の利点:**
    *   環境構築の簡素化：データベースサーバーのインストールや設定の手間を省けます。
    *   バージョンの管理：複数のバージョンのデータベースを簡単に切り替えることができます。
    *   データの隔離：コンテナごとに独立したデータベース環境を提供します。
    *   容易なバックアップとリストア：Dockerイメージやボリュームをバックアップすることで、データベースのバックアップとリストアが容易になります。

**3. 事前準備と前提条件**

*   Dockerがインストールされていること
*   Docker Composeがインストールされていること（推奨）
*   基本的なSQLの知識

**4. 基本的な使い方**

**MySQLのDocker化:**

```dockerfile
# Dockerfile (最小構成)
FROM mysql:latest
ENV MYSQL_ROOT_PASSWORD=your_root_password
EXPOSE 3306
```

*   `FROM mysql:latest`: 公式のMySQLイメージをベースにします。
*   `ENV MYSQL_ROOT_PASSWORD=your_root_password`: MySQLのrootユーザーのパスワードを設定します。必ず安全なパスワードを設定してください。
*   `EXPOSE 3306`: MySQLが使用するポート3306を外部に公開します。

```bash
docker build -t my-mysql .
docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=your_root_password my-mysql
```

**PostgreSQLのDocker化:**

```dockerfile
# Dockerfile (最小構成)
FROM postgres:latest
ENV POSTGRES_PASSWORD=your_postgres_password
EXPOSE 5432
```

*   `FROM postgres:latest`: 公式のPostgreSQLイメージをベースにします。
*   `ENV POSTGRES_PASSWORD=your_postgres_password`: PostgreSQLの`postgres`ユーザーのパスワードを設定します。必ず安全なパスワードを設定してください。
*   `EXPOSE 5432`: PostgreSQLが使用するポート5432を外部に公開します。

```bash
docker build -t my-postgres .
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=your_postgres_password my-postgres
```

**データ永続化:**

Dockerボリュームを使って、データベースのデータを永続化します。

**Docker Composeを使った例:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  mysql:
    image: mysql:latest
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: your_root_password
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

  postgres:
    image: postgres:latest
    restart: always
    environment:
      POSTGRES_PASSWORD: your_postgres_password
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  mysql_data:
  postgres_data:
```

*   `volumes`: Dockerボリュームを定義します。`mysql_data`と`postgres_data`はそれぞれMySQLとPostgreSQLのデータを保存するためのボリュームです。
*   `- mysql_data:/var/lib/mysql`:  MySQLコンテナ内の`/var/lib/mysql`ディレクトリを`mysql_data`ボリュームにマウントします。
*   `- postgres_data:/var/lib/postgresql/data`: PostgreSQLコンテナ内の`/var/lib/postgresql/data`ディレクトリを`postgres_data`ボリュームにマウントします。

Docker Composeを使ってコンテナを起動します。

```bash
docker-compose up -d
```

**5. 実践的なテクニック**

*   **環境変数の利用:** データベースの接続情報や設定を環境変数で管理します。
*   **初期化スクリプト:** コンテナ起動時にデータベースの初期化スクリプトを実行します。
*   **バックアップとリストア:** 定期的にデータベースのバックアップを取得し、リストアの手順を確立します。
*   **レプリケーション:** 複数のデータベースサーバーを連携させ、可用性を高めます。

**6. 応用例とユースケース**

*   **Webアプリケーションのデータベース:** Webアプリケーションのデータを保存・管理します。
*   **データ分析:** 大量のデータを収集・分析します。
*   **機械学習:** 機械学習モデルの学習データを保存・管理します。

**7. トラブルシューティング**

*   **接続エラー:** データベースサーバーへの接続が確立できない場合は、ネットワーク設定やファイアウォール設定を確認します。
*   **認証エラー:** データベースへの認証に失敗する場合は、ユーザー名やパスワードが正しいか確認します。
*   **データ消失:** データが消失した場合は、バックアップからデータをリストアします。
*   **コンテナ起動時のエラー:** 環境変数の設定ミス、ポート競合、ボリュームのマウントエラーなどが考えられます。Dockerログを確認し、エラーメッセージに基づいて問題を解決します。

**8. まとめと次のステップ**

MySQLやPostgreSQLをDocker化することで、データベースの管理が容易になり、環境構築の手間を省くことができます。データ永続化を行うことで、コンテナが停止または削除された場合でもデータを保持できます。次のステップとして、データベースのバックアップとリストア、レプリケーションの設定を検討してみましょう。

### メディアサーバー構築：Plex/JellyfinのDocker化、ストリーミング設定

**1. 概要と重要性**

PlexとJellyfinは、ローカルに保存された動画、音楽、写真などのメディアコンテンツを整理し、様々なデバイスでストリーミング再生できるメディアサーバーです。Dockerを使ってこれらのメディアサーバーを構築することで、環境構築が容易になり、サーバーの管理が簡素化されます。

**2. 特徴と利点**

*   **Plex:** 商用ソフトウェアであり、使いやすいインターフェースと豊富な機能が特徴です。有料プランでは、さらに高度な機能を利用できます。
*   **Jellyfin:** オープンソースのソフトウェアであり、完全に無料で利用できます。カスタマイズ性が高く、自由度の高いメディアサーバーを構築できます。
*   **Docker化の利点:**
    *   環境構築の簡素化：メディアサーバーのインストールや設定の手間を省けます。
    *   リソースの効率的な利用：コンテナごとにリソースを割り当てることで、サーバーのリソースを効率的に利用できます。
    *   容易なアップグレード：Dockerイメージを更新するだけで、メディアサーバーを簡単にアップグレードできます。

**3. 事前準備と前提条件**

*   Dockerがインストールされていること
*   Docker Composeがインストールされていること（推奨）
*   メディアコンテンツ（動画、音楽、写真など）
*   Plexアカウント（Plexの場合）

**4. 基本的な使い方**

**PlexのDocker化:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  plex:
    image: plexinc/pms-docker:latest
    restart: always
    ports:
      - "32400:32400/tcp"
      - "3005:3005/tcp"
      - "8324:8324/tcp"
      - "32469:32469/tcp"
      - "1900:1900/udp"
      - "32410:32410/udp"
      - "32412:32412/udp"
      - "32413:32413/udp"
      - "32414:32414/udp"
    environment:
      - PLEX_CLAIM=YOUR_PLEX_CLAIM_TOKEN #Plex Passを持っている場合は設定
      - ADVERTISE_IP=http://YOUR_SERVER_IP:32400 #Plex Media ServerにアクセスするためのIPアドレスまたはドメイン
    volumes:
      - ./config:/config
      - ./transcode:/transcode
      - ./media:/data

```

*   `image: plexinc/pms-docker:latest`: 公式のPlex Media Serverイメージをベースにします。
*   `ports`: Plex Media Serverが使用するポートを公開します。
*   `environment`: 環境変数を設定します。`PLEX_CLAIM`はPlex Passを持っている場合に設定します。`ADVERTISE_IP`はPlex Media ServerにアクセスするためのIPアドレスまたはドメインを設定します。
*   `volumes`: Dockerボリュームをマウントします。`./config`はPlexの設定ファイルを保存するためのボリューム、`./transcode`はトランスコードされたファイルを保存するためのボリューム、`./media`はメディアファイルを保存するためのボリュームです。

**JellyfinのDocker化:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  jellyfin:
    image: jellyfin/jellyfin:latest
    restart: always
    ports:
      - "8096:8096"
      - "8920:8920" # HTTPSポート (オプション)
      - "7359:7359/udp"
      - "1900:1900/udp"
    volumes:
      - ./config:/config
      - ./cache:/cache
      - ./media:/data
    environment:
      - JELLYFIN_PublishedServerUrl=http://YOUR_SERVER_IP:8096 #JellyfinサーバーにアクセスするためのURL

```

*   `image: jellyfin/jellyfin:latest`: 公式のJellyfinイメージをベースにします。
*   `ports`: Jellyfinが使用するポートを公開します。
*   `volumes`: Dockerボリュームをマウントします。`./config`はJellyfinの設定ファイルを保存するためのボリューム、`./cache`はキャッシュファイルを保存するためのボリューム、`./media`はメディアファイルを保存するためのボリュームです。
*   `environment`: 環境変数を設定します。`JELLYFIN_PublishedServerUrl`はJellyfinサーバーにアクセスするためのURLを設定します。

Docker Composeを使ってコンテナを起動します。

```bash
docker-compose up -d
```

**5. 実践的なテクニック**

*   **ハードウェアアクセラレーション:** GPUを使って動画のトランスコードを高速化します。

*   **メディアライブラリの整理:** メディアファイルを適切なディレクトリに整理し、PlexやJellyfinが認識しやすいようにします。
*   **字幕設定:** 字幕ファイルをメディアファイルと同じディレクトリに保存し、PlexやJellyfinで字幕を表示できるようにします。

**6. 応用例とユースケース**

*   **ホームメディアサーバー:** 家庭内のメディアコンテンツを集中管理し、様々なデバイスでストリーミング再生します。
*   **プライベートクラウドストレージ:** メディアファイルをクラウドに保存し、どこからでもアクセスできるようにします。
*   **コミュニティメディアサーバー:** 特定のグループ内でメディアコンテンツを共有します。

**7. トラブルシューティング**

*   **メディアファイルが認識されない:** ファイル形式が対応しているか、ファイル名やディレクトリ構造が正しいか確認します。
*   **トランスコードエラー:** ハードウェアアクセラレーションの設定が正しいか、GPUドライバーが最新であるか確認します。
*   **ネットワーク接続の問題:** ファイアウォールやルーターの設定を確認し、必要なポートが開いているか確認します。
*   **Plexアカウントの問題:** Plexアカウントにログインできない場合は、アカウント情報が正しいか、Plex Passの有効期限が切れていないか確認します。
*   **Jellyfinにアクセスできない:** `JELLYFIN_PublishedServerUrl`が正しく設定されているか確認します。

**8. まとめと次のステップ**

PlexやJellyfinをDocker化することで、メディアサーバーの構築が容易になり、管理が簡素化されます。ハードウェアアクセラレーションを利用することで、動画のトランスコードを高速化できます。次のステップとして、メディアライブラリの整理や、ネットワーク設定の最適化を検討してみましょう。

### ファイル同期：Nextcloud/SeafileのDocker化、データ暗号化

**1. 概要と重要性**

NextcloudとSeafileは、DropboxやGoogle Driveのようなファイル同期・共有サービスを自社で構築できるオープンソースソフトウェアです。Dockerを使ってこれらのサービスを構築することで、環境構築が容易になり、データのプライバシーとセキュリティを強化できます。データ暗号化は、保存されたデータを不正アクセスから保護するために不可欠です。

**2. 特徴と利点**

*   **Nextcloud:** 幅広い機能と豊富なアプリが特徴です。ファイル同期・共有だけでなく、カレンダー、連絡先、タスク管理などの機能も利用できます。
*   **Seafile:** 高速なファイル同期と高いセキュリティが特徴です。大容量ファイルの転送や、機密性の高いデータの共有に適しています。
*   **Docker化の利点:**
    *   環境構築の簡素化：ファイル同期サーバーのインストールや設定の手間を省けます。
    *   容易なアップグレード：Dockerイメージを更新するだけで、ファイル同期サーバーを簡単にアップグレードできます。
    *   リソースの効率的な利用：コンテナごとにリソースを割り当てることで、サーバーのリソースを効率的に利用できます。
    *   データの隔離：コンテナごとに独立したファイル同期環境を提供します。

**3. 事前準備と前提条件**

*   Dockerがインストールされていること
*   Docker Composeがインストールされていること（推奨）
*   ドメイン名（HTTPS設定を行う場合）
*   SSL証明書（HTTPS設定を行う場合）

**4. 基本的な使い方**

**NextcloudのDocker化:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  db:
    image: mariadb:10.5
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: your_root_password
      MYSQL_DATABASE: nextcloud
      MYSQL_USER: nextcloud
      MYSQL_PASSWORD: your_nextcloud_password
    volumes:
      - db_data:/var/lib/mysql

  app:
    image: nextcloud:latest
    restart: always
    ports:
      - "8080:80"
    volumes:
      - nextcloud_data:/var/www/html
    depends_on:
      - db
    environment:
      - MYSQL_HOST=db
      - MYSQL_DATABASE=nextcloud
      - MYSQL_USER=nextcloud
      - MYSQL_PASSWORD=your_nextcloud_password
      - NEXTCLOUD_ADMIN_USER=admin
      - NEXTCLOUD_ADMIN_PASSWORD=your_admin_password

volumes:
  db_data:
  nextcloud_data:
```

*   `db`: MariaDBコンテナを定義します。Nextcloudのデータベースとして使用します。
*   `app`: Nextcloudコンテナを定義します。
*   `depends_on`: `app`コンテナが`db`コンテナに依存していることを示します。
*   `volumes`: Dockerボリュームをマウントします。`db_data`はMariaDBのデータを保存するためのボリューム、`nextcloud_data`はNextcloudのデータを保存するためのボリュームです。
*   `environment`: 環境変数を設定します。データベースの接続情報やNextcloudの管理者アカウントを設定します。

### 自動化ツール：Jenkins/GitLab RunnerのDocker化、CI/CDパイプライン構築

**1. 概要と重要性**

JenkinsとGitLab Runnerは、ソフトウェア開発の自動化を支援するツールです。Jenkinsは、オープンソースのCI/CD（継続的インテグレーション/継続的デリバリー）サーバーであり、様々なタスクを自動化できます。GitLab Runnerは、GitLab CI/CDと連携して、ビルド、テスト、デプロイなどのパイプラインを実行するエージェントです。Dockerを使ってこれらのツールを構築することで、環境構築が容易になり、CI/CDパイプラインの構築を簡素化できます。

**2. 特徴と利点**

*   **Jenkins:** 豊富なプラグインと柔軟な設定が特徴です。様々な開発言語やツールに対応しており、複雑なCI/CDパイプラインを構築できます。
*   **GitLab Runner:** GitLab CI/CDとの統合が容易であり、YAMLファイルでCI/CDパイプラインを定義できます。
*   **Docker化の利点:**
    *   環境構築の簡素化：CI/CDツールのインストールや設定の手間を省けます。
    *   再現性の確保：CI/CD環境をDockerイメージとして定義することで、開発、テスト、本番環境で同一の環境を再現できます。
    *   スケーラビリティ：必要に応じてCI/CDエージェントの数を増減させることで、負荷に応じて柔軟に対応できます。
    *   容易なアップグレード：Dockerイメージを更新するだけで、CI/CDツールを簡単にアップグレードできます。

**3. 事前準備と前提条件**

*   Dockerがインストールされていること
*   Docker Composeがインストールされていること（推奨）
*   Gitリポジトリ
*   JenkinsサーバーまたはGitLabアカウント

**4. 基本的な使い方**

**JenkinsのDocker化:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  jenkins:
    image: jenkins/jenkins:lts
    restart: always
    ports:
      - "8080:8080"
      - "50000:50000"
    volumes:
      - jenkins_home:/var/jenkins_home

volumes:
  jenkins_home:
```

*   `image: jenkins/jenkins:lts`: 公式のJenkinsイメージをベースにします。`lts`はLong Term Supportの略で、安定版を意味します。
*   `ports`: Jenkinsが使用するポートを公開します。8080はWeb UIにアクセスするためのポート、50000はJenkinsエージェントがJenkinsサーバーに接続するためのポートです。
*   `volumes`: Dockerボリュームをマウントします。`jenkins_home`はJenkinsの設定ファイルやプラグインを保存するためのボリュームです。

Docker Composeを使ってコンテナを起動します。

```bash
docker-compose up -d
```

**GitLab RunnerのDocker化:**

```yaml
# docker-compose.yml
version: "3.8"
services:
  gitlab-runner:
    image: gitlab/gitlab-runner:latest
    restart: always
    volumes:
      - ./config:/etc/gitlab-runner
      - /var/run/docker.sock:/var/run/docker.sock #Docker in Docker を実現するための設定

```

*   `image: gitlab/gitlab-runner:latest`: 公式のGitLab Runnerイメージをベースにします。
*   `volumes`: Dockerボリュームをマウントします。`./config`はGitLab Runnerの設定ファイルを保存するためのボリュームです。`/var/run/docker.sock:/var/run/docker.sock`は、GitLab Runnerコンテナ内でDockerコマンドを実行できるようにするための設定です。（Docker in Docker）

GitLab RunnerをGitLabサーバーに登録します。

```bash
docker run --rm -it -v ./config:/etc/gitlab-runner gitlab/gitlab-runner register
```

GitLab Runnerの登録時に、GitLabサーバーのURLとトークンを入力する必要があります。これらの情報は、GitLabプロジェクトの設定画面から取得できます。

**CI/CDパイプライン構築:**

`/.gitlab-ci.yml`ファイルを作成し、CI/CDパイプラインを定義します。

```yaml
# .gitlab-ci.yml (例)
stages:
  - build
  - test
  - deploy

build:
  stage: build
  image: node:16
  script:
    - npm install
    - npm run build

test:
  stage: test
  image: node:16
  script:
    - npm test

deploy:
  stage: deploy
  image: alpine/git
  script:
    - git config --global user.email "YOUR_EMAIL"
    - git config --global user.name "YOUR_NAME"
    - git remote add origin "https://${GITLAB_USER_NAME}:${GITLAB_USER_PASSWORD}@${CI_SERVER_HOST}/${CI_PROJECT_PATH}.git"
    - git push origin HEAD:main
  only:
    - main
```

*   `stages`: CI/CDパイプラインのステージを定義します。
*   `build`, `test`, `deploy`: 各ステージのジョブを定義します。
*   `image`: ジョブを実行するためのDockerイメージを指定します。
*   `script`: ジョブの実行スクリプトを指定します。
*   `only`: ジョブを実行するブランチを指定します。

**5. 実践的なテクニック**

*   **Dockerfileの利用:** CI/CDパイプラインで必要なツールやライブラリをインストールしたDockerイメージを作成し、環境の再現性を高めます。
*   **キャッシュの利用:** ビルドキャッシュを利用して、ビルド時間を短縮します。
*   **テストの自動化:** テストを自動化し、コードの品質を維持します。
*   **デプロイの自動化:** デプロイを自動化し、リリースサイクルを短縮します。

**6. 応用例とユースケース**

*   **WebアプリケーションのCI/CD:** Webアプリケーションのビルド、テスト、デプロイを自動化します。
*   **モバイルアプリケーションのCI/CD:** モバイルアプリケーションのビルド、テスト、リリースを自動化します。
*   **インフラストラクチャの自動化:** インフラストラクチャのプロビジョニングや構成管理を自動化します。

**7. トラブルシューティング**

*   **CI/CDパイプラインが失敗する:** ログを確認し、エラーの原因を特定します。
*   **GitLab Runnerが登録できない:** GitLab Runnerの設定ファイルを確認し、GitLabサーバーのURLやトークンが正しいか確認します。
*   **Docker in Dockerの問題:** `/var/run/docker.sock`のマウント設定が正しいか確認します。
*   **環境変数の設定ミス:** GitLab CI/CDの設定画面で定義した環境変数が、`.gitlab-ci.yml`ファイルで正しく参照されているか確認します。

**8. まとめと次のステップ**

JenkinsやGitLab RunnerをDocker化することで、CI/CD環境の構築が容易になり、ソフトウェア開発の自動化を促進できます。CI/CDパイプラインを構築することで、開発サイクルを短縮し、コードの品質を向上させることができます。次のステップとして、Dockerfileを作成し、より複雑なCI/CDパイプラインを構築してみましょう。

### トラブルシューティング：ポート競合、データアクセス権の問題

**1. 概要と重要性**

Dockerコンテナの運用において、ポート競合とデータアクセス権の問題は頻繁に発生するトラブルです。これらの問題を解決することで、コンテナが正常に動作し、データが適切に保護されるようになります。

**2. ポート競合**

**原因:**

*   別のコンテナまたはプロセスが、同じポートを使用している。
*   コンテナの設定で、公開ポートが正しく設定されていない。

**解決策:**

1.  **ポートの使用状況を確認:** `netstat -tulnp`コマンドで、どのプロセスがどのポートを使用しているかを確認します。
2.  **コンテナのポート設定を変更:** Dockerfileまたはdocker-compose.ymlファイルで、公開ポートを変更します。
3.  **ホスト側のポート設定を変更:** ホスト側のファイアウォールやリバースプロキシの設定を変更します。

**例:**

```bash
# ポート8080を使用しているプロセスを確認
netstat -tulnp | grep 8080
```

docker-compose.ymlファイルのポート設定を変更する例:

```yaml
# docker-compose.yml
version: "3.8"
services:
  web:
    image: nginx:latest
    ports:
      - "8081:80" # ホスト側のポートを8081に変更
```

**3. データアクセス権の問題**

**原因:**

*   コンテナ内で実行されるプロセスが、ホスト側のファイルやディレクトリへのアクセス権を持っていない。
*   Dockerボリュームのマウント時に、適切なアクセス権が設定されていない。

**解決策:**

1.  **ホスト側のファイルやディレクトリのアクセス権を変更:** `chown`コマンドや`chmod`コマンドで、適切なアクセス権を設定します。
2.  **Dockerボリュームのマウント時にユーザーIDとグループIDを指定:** `--user`オプションまたはdocker-compose.ymlファイルで、コンテナ内で実行されるプロセスのユーザーIDとグループIDを指定します。
3.  **Dockerfileでユーザーを作成:** Dockerfileで専用のユーザーを作成し、そのユーザーでプロセスを実行します。

**例:**

ホスト側のファイル`/data/app.log`のアクセス権を、ユーザー`www-data`とグループ`www-data`に与える例:

```bash
sudo chown www-data:www-data /data/app.log
```

docker-compose.ymlファイルでユーザーIDとグループIDを指定する例:

```yaml
# docker-compose.yml
version: "3.8"
services:
  app:
    image: my-app:latest
    user: "1000:1000" # ユーザーIDとグループIDを1000に設定
    volumes:
      - /data:/data
```

**4. その他のトラブルシューティング**

*   **ログの確認:** コンテナのログを確認し、エラーメッセージに基づいて問題を解決します。
*   **Docker Composeの再起動:** `docker-compose down`コマンドでコンテナを停止し、`docker-compose up`コマンドで再
