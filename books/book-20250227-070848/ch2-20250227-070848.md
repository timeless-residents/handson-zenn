## 第1章：基礎体力作り - Ubuntu Serverセットアップと基本操作

この章では、Ubuntu Serverを安全かつ効率的に使いこなすための基礎体力を養います。GUIレス環境でのインストールから始まり、ネットワーク設定、SSHによるリモートアクセス、そして必須コマンドライン操作まで、サーバー運用の基盤となる知識とスキルを丁寧に解説します。

### Ubuntu Server最新版のインストール：GUIレスでどこまでできるか？

**概要と重要性**

Ubuntu Serverのインストールは、サーバー構築の第一歩であり、その後の運用を左右する重要なプロセスです。GUIレス環境でのインストールは、リソース効率が高く、セキュリティ面でも有利です。ここでは、最小限のリソースでUbuntu Serverを起動し、必要な設定をコマンドラインで行う方法を学びます。

**特徴と利点**

*   **リソース効率:** GUIがないため、CPUやメモリの使用量を抑えられ、サーバーのパフォーマンスを最大限に引き出せます。
*   **セキュリティ:** GUI関連の脆弱性の影響を受けにくく、攻撃対象となる範囲を狭められます。
*   **自動化:** インストールプロセスを自動化しやすく、大量のサーバーを効率的に展開できます。

**事前準備と前提条件**

*   Ubuntu ServerのISOイメージファイル（最新版推奨）
*   インストール先のサーバーまたは仮想マシン
*   インターネット接続（初期設定時）
*   起動可能なUSBドライブまたはDVD
*   ターミナルソフト（PuTTY, Tera Termなど）

**基本的な使い方**

1.  **ISOイメージのダウンロード:** Ubuntuの公式ウェブサイトから、最新のUbuntu ServerのISOイメージをダウンロードします。
2.  **ブータブルメディアの作成:** ダウンロードしたISOイメージをUSBドライブまたはDVDに書き込みます。RufusやEtcherなどのツールを使用すると簡単です。
3.  **サーバーの起動:** 作成したブータブルメディアからサーバーを起動します。
4.  **インストーラの起動:** 起動時に表示されるメニューから「Install Ubuntu Server」を選択します。
5.  **言語、キーボードレイアウトの選択:** 指示に従って、言語とキーボードレイアウトを選択します。
6.  **ネットワーク設定:** DHCPを使用するか、手動でIPアドレスを設定するかを選択します。DHCP環境であれば自動的にIPアドレスが割り当てられます。
7.  **ディスクの構成:** パーティション構成を選択します。初心者の方は「ディスク全体を使用する」を選択するのが簡単です。必要に応じてLVM（論理ボリュームマネージャ）を設定することも可能です。
8.  **ユーザー情報の設定:** ユーザー名、パスワード、サーバー名を指定します。セキュリティのため、強力なパスワードを設定してください。
9.  **SSHサーバーのインストール:** SSHサーバーをインストールするかどうかを選択します。リモートアクセスに必須なので、必ずインストールしてください。
10. **追加パッケージのインストール:** 必要に応じて、snapdやその他のパッケージを選択してインストールします。
11. **インストールの完了:** インストールが完了したら、サーバーを再起動します。

**実践的なテクニック**

*   **自動インストールの設定 (Unattended Installation):** kickstartファイルを作成することで、インストールの全工程を自動化できます。これにより、大量のサーバーを迅速かつ一貫性のある方法で展開できます。
*   **仮想環境でのテスト:** 本番環境にインストールする前に、VirtualBoxやVMwareなどの仮想環境でテストインストールを行い、設定を確認することをお勧めします。

**応用例とユースケース**

*   **クラウド環境での自動プロビジョニング:** AnsibleやTerraformなどの構成管理ツールと組み合わせることで、クラウド環境でのサーバー構築を自動化できます。
*   **コンテナ基盤の構築:** DockerやKubernetesなどのコンテナ技術と組み合わせて、アプリケーションのデプロイメント環境を構築できます。

**トラブルシューティング**

*   **インストールが途中で止まる:** ISOイメージが破損している可能性があります。再度ダウンロードし、書き込みツールを変えて試してください。
*   **ネットワーク接続が確立できない:** DHCPサーバーが正常に動作しているか、手動で設定したIPアドレスが正しいか確認してください。
*   **ディスクのエラー:** ディスクに不良セクタがある可能性があります。別のディスクを使用するか、ディスクのエラーチェックを行ってください。

**まとめと次のステップ**

GUIレスでのUbuntu Serverインストールは、サーバー運用の基礎を築く上で不可欠です。次のステップでは、インストールしたサーバーにリモートアクセスし、ネットワーク設定をさらに詳しく見ていきます。

### ネットワーク設定：固定IPアドレス、DNS、ホスト名の設定徹底解説

**概要と重要性**

サーバーのネットワーク設定は、外部との通信を確立し、サービスの可用性を維持するために非常に重要です。固定IPアドレスの設定、DNSの設定、ホスト名の設定は、ネットワーク環境においてサーバーを識別し、アクセスを可能にするための基本的な要素です。

**特徴と利点**

*   **固定IPアドレス:** サーバーのIPアドレスが常に一定であるため、外部からのアクセスが安定します。
*   **DNS設定:** ドメイン名からIPアドレスへの変換を可能にし、Webサイトやメールサーバーなどのサービスを提供できます。
*   **ホスト名設定:** ネットワーク内でサーバーを識別するための名前を設定し、管理を容易にします。

**事前準備と前提条件**

*   Ubuntu Serverがインストール済みであること
*   管理者権限を持つユーザーアカウント
*   ネットワーク管理者から提供されたIPアドレス、ネットマスク、ゲートウェイ、DNSサーバーの情報

**基本的な使い方**

1.  **固定IPアドレスの設定:**
    *   `netplan`の設定ファイルを編集します。通常は`/etc/netplan/01-network-manager-all.yaml`のような名前のファイルです。

    ```yaml
    network:
      version: 2
      renderer: networkd
      ethernets:
        ens33: # ネットワークインターフェース名（ifconfigまたはip addrで確認）
          dhcp4: no
          addresses: [192.168.1.100/24] # 設定するIPアドレスとネットマスク
          gateway4: 192.168.1.1 # ゲートウェイアドレス
          nameservers:
              addresses: [8.8.8.8, 8.8.4.4] # DNSサーバーアドレス
    ```
    *   設定ファイルを編集後、以下のコマンドで設定を適用します。
        ```bash
        sudo netplan apply
        ```

2.  **DNS設定:**
    *   上記`netplan`ファイルで設定する方法の他に、`/etc/resolv.conf`ファイルを編集する方法もありますが、`netplan`を使うのが推奨です。
    *   必要に応じて、`/etc/hosts`ファイルにホスト名とIPアドレスの対応を記述することもできます。

3.  **ホスト名の設定:**
    *   `/etc/hostname`ファイルを編集します。
        ```bash
        sudo nano /etc/hostname
        ```
        ファイルに新しいホスト名を記述し、保存します。
    *   `/etc/hosts`ファイルにもホスト名を記述します。
        ```bash
        sudo nano /etc/hosts
        ```
        以下の行を修正または追加します。
        ```
        127.0.0.1   localhost
        127.0.1.1   <新しいホスト名>
        ```
    *   以下のコマンドでホスト名を変更を反映します。
        ```bash
        sudo hostnamectl set-hostname <新しいホスト名>
        ```
    *   サーバーを再起動します。

**実践的なテクニック**

*   **複数のネットワークインターフェース:** 複数のネットワークインターフェースがある場合は、それぞれのインターフェースに対して個別にIPアドレスを設定する必要があります。
*   **VLANの設定:** VLAN（Virtual LAN）を使用する場合は、`netplan`でVLANインターフェースを作成し、IPアドレスを設定します。

**応用例とユースケース**

*   **Webサーバーの構築:** 固定IPアドレスとDNS設定により、Webサイトを公開できます。
*   **メールサーバーの構築:** メールサーバーを運用するためには、正引きと逆引きのDNS設定が必須です。
*   **データベースサーバーの構築:** データベースサーバーに固定IPアドレスを設定することで、アプリケーションからの接続が安定します。

**トラブルシューティング**

*   **ネットワークに接続できない:** IPアドレス、ネットマスク、ゲートウェイの設定が正しいか確認してください。
*   **DNS名前解決ができない:** DNSサーバーの設定が正しいか、DNSサーバーが正常に動作しているか確認してください。
*   **ホスト名が変更されない:** `/etc/hostname`と`/etc/hosts`の両方のファイルを修正し、サーバーを再起動してください。

**まとめと次のステップ**

ネットワーク設定は、サーバーの可用性とセキュリティを確保するための重要な要素です。次のステップでは、SSHによるリモートアクセスを設定し、サーバーを安全に管理する方法を学びます。

### SSHによるリモートアクセス：セキュリティ対策、公開鍵認証の導入

**概要と重要性**

SSH（Secure Shell）は、サーバーに安全にリモートアクセスするためのプロトコルです。パスワード認証に加えて、公開鍵認証を導入することで、セキュリティを大幅に向上させることができます。

**特徴と利点**

*   **暗号化通信:** SSHは、クライアントとサーバー間の通信を暗号化し、盗聴や改ざんから保護します。
*   **公開鍵認証:** パスワードの代わりに、公開鍵と秘密鍵を使用することで、総当たり攻撃に対する耐性を高めます。
*   **ポートフォワーディング:** SSHトンネルを使用することで、安全でないプロトコルを暗号化されたチャネルで転送できます。

**事前準備と前提条件**

*   Ubuntu Serverがインストール済みであること
*   SSHサーバーがインストールされていること（通常はデフォルトでインストールされています）
*   SSHクライアント（PuTTY, Tera Term, OpenSSHなど）
*   鍵ペア生成ツール（ssh-keygenなど）

**基本的な使い方**

1.  **公開鍵と秘密鍵の生成:**
    *   ローカルマシンで以下のコマンドを実行し、鍵ペアを生成します。
        ```bash
        ssh-keygen -t rsa -b 4096
        ```
        パスフレーズを設定するかどうか尋ねられます。セキュリティのため、設定することを推奨します。
2.  **公開鍵のサーバーへのコピー:**
    *   生成された公開鍵（通常は`~/.ssh/id_rsa.pub`）の内容を、サーバーの`~/.ssh/authorized_keys`ファイルに追記します。
        以下のコマンドを使用すると、簡単にコピーできます。
        ```bash
        ssh-copy-id user@server_ip
        ```
        もしくは、以下のコマンドで手動でコピーすることも可能です。
        ```bash
        cat ~/.ssh/id_rsa.pub | ssh user@server_ip 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'
        ```
3.  **SSHクライアントでの接続:**
    *   SSHクライアントで、秘密鍵を指定してサーバーに接続します。
        ```bash
        ssh -i ~/.ssh/id_rsa user@server_ip
        ```
4.  **パスワード認証の無効化:**
    *   セキュリティを強化するため、パスワード認証を無効にすることを推奨します。
        `/etc/ssh/sshd_config`ファイルを編集します。
        ```bash
        sudo nano /etc/ssh/sshd_config
        ```
        以下の行を修正します。
        ```
        PasswordAuthentication no
        ```
    *   変更を反映するため、SSHサーバーを再起動します。
        ```bash
        sudo systemctl restart sshd
        ```

**実践的なテクニック**

*   **ポートの変更:** SSHのデフォルトポート（22番）を変更することで、ポートスキャン攻撃のリスクを軽減できます。
*   **Fail2banの導入:** Fail2banを導入することで、不正なログイン試行を検出し、自動的にIPアドレスをブロックできます。
*   **SSH Config:** ローカルマシンの`~/.ssh/config`ファイルにサーバーの情報を記述することで、SSH接続を簡略化できます。

**応用例とユースケース**

*   **安全なファイル転送:** `scp`または`sftp`コマンドを使用することで、ファイルを安全にサーバーに転送できます。
*   **リモートコマンド実行:** SSHを使用して、サーバー上でコマンドをリモート実行できます。
*   **VPN構築:** SSHトンネルを利用して、VPN（Virtual Private Network）を構築できます。

**トラブルシューティング**

*   **公開鍵認証がうまくいかない:** 公開鍵が`~/.ssh/authorized_keys`ファイルに正しく追記されているか、ファイルの権限が正しいか確認してください。
*   **SSH接続が拒否される:** SSHサーバーが起動しているか、ファイアウォールでSSHポートが許可されているか確認してください。
*   **パスワード認証が無効にならない:** `/etc/ssh/sshd_config`ファイルを修正後、SSHサーバーを再起動したか確認してください。

**まとめと次のステップ**

SSHによるリモートアクセスは、サーバーを安全に管理するための不可欠なスキルです。次のステップでは、必須コマンドライン操作を学び、サーバーの管理を効率化する方法を探ります。

### 必須コマンドライン操作：apt, systemctl, journalctlを使いこなす

**概要と重要性**

Ubuntu Serverの管理は、主にコマンドラインを通じて行われます。`apt`、`systemctl`、`journalctl`は、Ubuntu Serverを管理する上で必須となるコマンドであり、パッケージの管理、サービスの制御、ログの確認など、サーバー運用のあらゆる面で利用されます。

**特徴と利点**

*   **apt (Advanced Package Tool):** パッケージのインストール、アップデート、削除を簡単に行えます。
*   **systemctl:** サービスの起動、停止、再起動、状態確認をsystemdを通じて行えます。
*   **journalctl:** サーバーのログを効率的に確認し、問題の特定やトラブルシューティングに役立てることができます。

**事前準備と前提条件**

*   Ubuntu Serverがインストール済みであること
*   管理者権限を持つユーザーアカウント

**基本的な使い方**

1.  **apt:**
    *   **パッケージリストの更新:**
        ```bash
        sudo apt update
        ```
    *   **パッケージのインストール:**
        ```bash
        sudo apt install <パッケージ名>
        ```
    *   **パッケージの削除:**
        ```bash
        sudo apt remove <パッケージ名>
        ```
        設定ファイルも削除する場合は`purge`を使用します。
        ```bash
        sudo apt purge <パッケージ名>
        ```
    *   **パッケージのアップグレード:**
        ```bash
        sudo apt upgrade
        ```
    *   **システム全体のアップグレード:**
        ```bash
        sudo apt full-upgrade
        ```
    *   **パッケージの検索:**
        ```bash
        apt search <キーワード>
        ```
    *   **パッケージの詳細情報の表示:**
        ```bash
        apt show <パッケージ名>
        ```
2.  **systemctl:**
    *   **サービスの起動:**
        ```bash
        sudo systemctl start <サービス名>
        ```
    *   **サービスの停止:**
        ```bash
        sudo systemctl stop <サービス名>
        ```
    *   **サービスの再起動:**
        ```bash
        sudo systemctl restart <サービス名>
        ```
    *   **サービスの状態確認:**
        ```bash
        sudo systemctl status <サービス名>
        ```
    *   **サービスの自動起動設定:**
        ```bash
        sudo systemctl enable <サービス名>
        ```
    *   **サービスの自動起動解除:**
        ```bash
        sudo systemctl disable <サービス名>
        ```
    *   **すべてのサービスの状態一覧:**
        ```bash
        sudo systemctl list-units --type=service
        ```
3.  **journalctl:**
    *   **すべてのログの表示:**
        ```bash
        sudo journalctl
        ```
    *   **特定のサービスのログの表示:**
        ```bash
        sudo journalctl -u <サービス名>
        ```
    *   **特定の日時のログの表示:**
        ```bash
        sudo journalctl --since "2023-10-27" --until "2023-10-28"
        ```
    *   **リアルタイムでログを表示:**
        ```bash
        sudo journalctl -f
        ```
    *   **エラーメッセージのみを表示:**
        ```bash
        sudo journalctl -p err
        ```

**実践的なテクニック**

*   **aptのキャッシュ管理:** `apt clean`コマンドでダウンロード済みのパッケージファイルを削除し、ディスクスペースを節約できます。
*   **systemctlの依存関係:** サービスの起動順序を制御するために、`Requires=`や`After=`などのオプションをsystemdの設定ファイルで使用します。
*   **journalctlのフィルタリング:** ログメッセージの重要度やキーワードでフィルタリングすることで、必要な情報を効率的に抽出できます。

**応用例とユースケース**

*   **Webサーバーのメンテナンス:** `apt`でApacheやNginxをアップデートし、`systemctl`でサービスを再起動します。問題が発生した場合は、`journalctl`でログを確認します。
*   **データベースサーバーのトラブルシューティング:** `journalctl`でデータベースサーバーのログを確認し、エラーメッセージや警告メッセージを分析します。
*   **セキュリティアップデートの適用:** `apt update`と`apt upgrade`を定期的に実行し、セキュリティ脆弱性を修正します。

**トラブルシューティング**

*   **aptが動作しない:** リポジトリの設定が正しいか、インターネット接続が確立されているか確認してください。
*   **systemctlでサービスが起動しない:** サービスの設定ファイルにエラーがないか、必要な依存関係が満たされているか確認してください。
*   **journalctlでログが表示されない:** 権限がない可能性があります。`sudo`をつけて実行してください。また、ログローテーションの設定を確認してください。

**まとめと次のステップ**

`apt`、`systemctl`、`journalctl`を使いこなすことは、Ubuntu Serverの管理において非常に重要です。これらのコマンドを習得することで、サーバーの運用、保守、トラブルシューティングを効率的に行うことができます。次の章では、この章で学んだ知識を元に、より高度なサーバー管理技術について学びます。

### トラブルシューティング：インストール失敗、ネットワーク接続エラー

**概要と重要性**

Ubuntu Serverのインストールやネットワーク接続は、様々な要因によって失敗する可能性があります。これらの問題を解決するためには、体系的なトラブルシューティングのアプローチが必要です。

**特徴と利点**

*   **体系的なアプローチ:** 問題の切り分け、原因の特定、解決策の適用という手順を踏むことで、効率的に問題を解決できます。
*   **ログ分析:** エラーメッセージやログを分析することで、問題の原因を特定できます。
*   **コミュニティの活用:** Ubuntuのコミュニティやフォーラムを活用することで、解決策を見つけられる場合があります。

**事前準備と前提条件**

*   Ubuntu Serverのインストールメディア
*   ネットワーク接続環境
*   ターミナルソフト（PuTTY, Tera Termなど）
*   エラーメッセージやログ

**基本的な使い方**

1.  **インストール失敗:**
    *   **原因の特定:** インストールログ（`/var/log/installer/syslog`など）を確認し、エラーメッセージを分析します。
    *   **解決策:**
        *   ISOイメージが破損していないか確認し、再度ダウンロードします。
        *   ブータブルメディアの作成方法が正しいか確認します。
        *   ディスクに不良セクタがないか確認します。
        *   BIOSの設定が正しいか確認します（ブート順序など）。
2.  **ネットワーク接続エラー:**
    *   **原因の特定:** `ifconfig`または`ip addr`コマンドで、ネットワークインターフェースが認識されているか確認します。`ping`コマンドで、ゲートウェイやDNSサーバーに到達できるか確認します。
    *   **解決策:**
        *   ケーブルが正しく接続されているか確認します。
        *   IPアドレス、ネットマスク、ゲートウェイの設定が正しいか確認します。
        *   DNSサーバーの設定が正しいか確認します。
        *   ファイアウォールの設定がネットワーク接続を妨げていないか確認します。

**実践的なテクニック**

*   **Verboseモード:** インストール時にverboseモードを使用することで、より詳細なログを表示できます。
*   **デバッグツールの活用:** `tcpdump`や`wireshark`などのネットワーク分析ツールを使用することで、ネットワークトラフィックを監視し、問題を特定できます。

**応用例とユースケース**

*   **クラウド環境でのトラブルシューティング:** クラウドプロバイダーが提供するログや監視ツールを活用し、インスタンスの起動失敗やネットワーク接続問題を解決します。
*   **コンテナ環境でのトラブルシューティング:** DockerやKubernetesのログを確認し、コンテナの起動失敗やネットワーク接続問題を解決します。

**トラブルシューティング**

*   **エラーメッセージが理解できない:** エラーメッセージをインターネットで検索し、関連する情報を収集します。
*   **解決策が見つからない:** UbuntuのコミュニティフォーラムやStack Overflowなどで質問し、専門家の助けを求めます。
*   **問題が再現しない:** 問題が発生した状況を詳細に記録し、再現手順を確立します。

**まとめと次のステップ**

トラブルシューティングは、サーバー管理において不可欠なスキルです。体系的なアプローチ、ログ分析、コミュニティの活用を通じて、様々な問題を解決することができます。この章で学んだ知識を活かし、より複雑なサーバー管理の課題に挑戦していきましょう。
