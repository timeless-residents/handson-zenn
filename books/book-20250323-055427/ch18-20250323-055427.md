## 第 18 章: ゲームエンジンへの組み込み: Unity, Godot, GameMaker

### ゲームエンジンの選定: プロジェクトに最適なツール

**概要と重要性**

ゲームエンジンは、ゲーム開発における強力な味方です。アセットの管理、物理演算、スクリプト記述、ビルドなど、ゲーム制作に必要な機能を包括的に提供します。しかし、数多くのエンジンが存在するため、プロジェクトの規模、ジャンル、ターゲットプラットフォーム、そして開発チームのスキルセットに最適なものを選ぶことが成功への第一歩となります。

**特徴と利点**

- **Unity:** クロスプラットフォーム対応に優れ、アセットストアが充実。C#によるスクリプト記述が可能です。大規模プロジェクトからインディーゲームまで幅広く対応できます。
- **Godot:** オープンソースでロイヤリティフリー。GDScript という Python に似た独自のスクリプト言語を使用します。2D ゲーム開発に特に強みを発揮しますが、3D ゲームも開発可能です。
- **GameMaker Studio 2:** 2D ゲーム開発に特化しており、ビジュアルスクリプティングと独自のスクリプト言語 GML を使用できます。プログラミング初心者でも比較的簡単にゲームを作成できます。

| エンジン           | 特徴                                             | 利点                                                                                | 弱点                                                                           | 向き不向き                                                          |
| ------------------ | ------------------------------------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Unity              | クロスプラットフォーム、C#、豊富なアセットストア | 汎用性が高く、大規模プロジェクトにも対応可能。コミュニティが活発。                  | 学習コストが高め、プロジェクト規模によってはパフォーマンスチューニングが必要。 | 3D/2D 両方。大規模プロジェクト、モバイルゲーム、VR/AR ゲーム        |
| Godot              | オープンソース、GDScript、ロイヤリティフリー     | コストパフォーマンスが高い。2D ゲーム開発に最適。柔軟性が高くカスタマイズしやすい。 | ドキュメントが Unity ほど充実していない。日本語情報が少ない。                  | 2D ゲーム、インディーゲーム、実験的なプロジェクト                   |
| GameMaker Studio 2 | 2D 特化、ビジュアルスクリプティング、GML         | プログラミング初心者でも扱いやすい。短期間でゲームを作成できる。                    | 3D ゲームには不向き。大規模プロジェクトには向かない。GML の学習が必要。        | 2D ゲーム、特にアクションゲーム、シューティングゲーム、パズルゲーム |

**事前準備と前提条件**

- **Unity:** Unity Hub のインストールと Unity エディタのインストール、C#の基本的な知識。
- **Godot:** Godot Engine のダウンロードとインストール、GDScript の基本的な知識。
- **GameMaker Studio 2:** GameMaker Studio 2 のインストールとライセンス認証、GML の基本的な知識（もしくはビジュアルスクリプティングの知識）。

**基本的な使い方**

ここでは、各エンジンで新しいプロジェクトを作成し、基本的なシーンを設定する手順を説明します。

- **Unity:**

  1. Unity Hub を起動し、新しいプロジェクトを作成します。テンプレートは「2D」を選択すると、2D ゲーム開発に適した設定でプロジェクトが作成されます。
  2. プロジェクト名と保存場所を指定し、「作成」をクリックします。
  3. シーンが自動的に作成されます。「Hierarchy」ウィンドウに「Main Camera」と「Directional Light」が存在することを確認します。

- **Godot:**

  1. Godot Engine を起動し、「New Project」をクリックします。
  2. プロジェクト名と保存場所を指定し、「Create Folder」をクリックします。
  3. レンダラーを選択します。2D ゲームの場合は「GLES2」を選択すると、より幅広いプラットフォームに対応できます。
  4. 「Create & Edit」をクリックします。
  5. シーンを作成します。「Scene」メニューから「New Scene」を選択し、「2D Scene」を選択します。

- **GameMaker Studio 2:**
  1. GameMaker Studio 2 を起動し、「New」をクリックします。
  2. プロジェクト名と保存場所を指定し、「Create」をクリックします。
  3. 新しいオブジェクトを作成します。「Resources」ウィンドウで右クリックし、「Create」->「Object」を選択します。

**実践的なテクニック**

どのエンジンでも、ドット絵を使用する際は、アンチエイリアスをオフに設定することが重要です。これにより、ドット絵のピクセルがぼやけるのを防ぎ、鮮明な見た目を維持できます。

- **Unity:** インポート設定で「Filter Mode」を「Point (no filter)」に設定します。
- **Godot:** インポート設定で「Filter」を「Nearest」に設定します。
- **GameMaker Studio 2:** スプライトエディタで「Interpolate borders」のチェックを外します。

**応用例とユースケース**

- **Unity:** 大規模な RPG ゲームの開発。豊富なアセットストアと C#の柔軟性を活かして、複雑なシステムを構築できます。
- **Godot:** スタイリッシュな 2D プラットフォーマーゲームの開発。GDScript のシンプルさと Godot の 2D 機能の強力さを活かして、個性的なゲームを作成できます。
- **GameMaker Studio 2:** レトロなアーケードゲームの開発。GameMaker Studio 2 の使いやすさと 2D 特化の機能で、短期間で完成度の高いゲームを作成できます。

**トラブルシューティング**

- **ドット絵がぼやける:** インポート設定でアンチエイリアスが有効になっている可能性があります。上記の手順でアンチエイリアスをオフにしてください。
- **パフォーマンスが低い:** ドット絵の解像度が高すぎる可能性があります。不必要に高解像度のドット絵を使用しないようにしましょう。
- **画面サイズに合わせるとドット絵が歪む:** カメラの設定やスプライトの伸縮方法を見直してください。ピクセルパーフェクトな描画を維持するように設定する必要があります。

**まとめと次のステップ**

このセクションでは、ゲームエンジンの選定から基本的な設定、ドット絵のインポートまでを学びました。次のステップでは、実際にキャラクターを動かし、当たり判定を実装し、ゲームロジックを組み込む方法を学習します。

### ドット絵素材のインポートと設定: 解像度、ピクセルパーフェクト

**概要と重要性**

ドット絵ゲームにおいて、素材のインポートと設定は、見た目の品質を大きく左右する重要なプロセスです。特に、解像度とピクセルパーフェクトの設定は、ドット絵本来のシャープでレトロな雰囲気を維持するために不可欠です。適切な設定を行わないと、ドット絵がぼやけたり、歪んだりして、意図した表現を損なう可能性があります。

**特徴と利点**

- **解像度の最適化:** ゲームの画面解像度に合わせてドット絵の解像度を調整することで、パフォーマンスを向上させることができます。
- **ピクセルパーフェクト:** ドット絵のピクセルが整数倍で拡大縮小されるように設定することで、ドット絵のシャープさを維持し、意図しないぼやけを防ぎます。
- **一貫性のある見た目:** 全てのドット絵素材の設定を統一することで、ゲーム全体を通して一貫性のある視覚体験を提供できます。

**事前準備と前提条件**

- ドット絵素材（キャラクター、背景、アイテムなど）が用意されていること。
- 各ゲームエンジンでのテクスチャインポートの基本的な知識。

**基本的な使い方**

各エンジンでのドット絵素材のインポートと設定手順を説明します。

- **Unity:**

  1. ドット絵素材をプロジェクトの「Assets」フォルダにドラッグ＆ドロップします。
  2. インポートされたテクスチャを選択し、「Inspector」ウィンドウで以下の設定を行います。
     - **Texture Type:** Sprite (2D and UI)
     - **Sprite Mode:** Single または Multiple (アニメーションによって選択)
     - **Pixels Per Unit:** ドット絵の解像度に合わせて調整します（例: 16x16 のドット絵なら 16）。
     - **Filter Mode:** Point (no filter)
     - **Compression:** None
  3. Sprite Mode が Multiple の場合、Sprite Editor を開き、スプライトを個別に切り分けます。

- **Godot:**

  1. ドット絵素材をプロジェクトのフォルダにコピーします。
  2. Godot エディタでファイルシステムからドット絵素材を選択し、「Import」ウィンドウで以下の設定を行います。
     - **Preset:** 2D Pixel
     - **Filter:** Nearest
     - **Mipmaps:** false
  3. 「Reimport」をクリックします。

- **GameMaker Studio 2:**
  1. 「Resources」ウィンドウで右クリックし、「Create」->「Sprite」を選択します。
  2. スプライトエディタを開き、「Load Sprite」をクリックしてドット絵素材を読み込みます。
  3. スプライトエディタで以下の設定を行います。
     - **Interpolate borders:** チェックを外します。
     - **Precise collision checking:** 必要に応じてチェックを入れます。
     - **Origin:** スプライトの原点を設定します（例: 中央、左上など）。

**実践的なテクニック**

- **Unity:** Pixel Perfect Camera を使用すると、カメラの設定だけでピクセルパーフェクトな描画を実現できます。Unity Asset Store から「Pixel Perfect Camera」をインストールし、カメラにアタッチします。
- **Godot:** Project Settings で「Display」->「Viewport」->「Snap 2D Transforms to Pixel」を有効にすると、2D オブジェクトの座標が整数値にスナップされ、ピクセルパーフェクトな描画を維持できます。
- **GameMaker Studio 2:** Viewport の設定を適切に行うことで、画面サイズが異なる場合でもドット絵の見た目を維持できます。Game Settings で「Graphics」->「Display」->「Interpolate pixels when scaling」のチェックを外します。

**応用例とユースケース**

- **RPG ゲーム:** キャラクター、モンスター、アイテムのドット絵素材をインポートし、解像度とピクセルパーフェクトを設定することで、レトロな雰囲気を再現できます。
- **プラットフォーマーゲーム:** タイルセットのドット絵素材をインポートし、解像度とピクセルパーフェクトを設定することで、シャープで正確なジャンプや移動を実現できます。
- **シューティングゲーム:** 弾丸、敵キャラクターのドット絵素材をインポートし、解像度とピクセルパーフェクトを設定することで、高速な動きでもぼやけない、見やすいビジュアルを実現できます。

**トラブルシューティング**

- **ドット絵がぼやける:**
  - インポート設定でアンチエイリアスが有効になっている可能性があります。上記の手順でアンチエイリアスをオフにしてください。
  - カメラの Orthographic Size が整数値になっていない可能性があります。整数値に調整してください。
  - 画面の拡大率が整数倍になっていない可能性があります。整数倍に調整してください。
- **ドット絵が歪む:**
  - スプライトの伸縮方法が適切でない可能性があります。スケールを整数倍に設定するか、ピクセルパーフェクトな描画を維持するように設定してください。
  - カメラの位置がピクセル単位でずれている可能性があります。カメラの位置をピクセル単位で調整してください。
- **異なる解像度のドット絵素材を混在させると見た目が不自然になる:**
  - できる限り、全てのドット絵素材の解像度を統一することをおすすめします。どうしても混在させる場合は、解像度の比率を整数倍にすることで、違和感を軽減できます。

**まとめと次のステップ**

このセクションでは、ドット絵素材のインポートと設定、特に解像度とピクセルパーフェクトの重要性について学びました。次のステップでは、実際にキャラクターを動かし、当たり判定を実装し、ゲームロジックを組み込む方法を学習します。これらの設定が完了すれば、ゲーム開発における視覚的な基礎が確立されます。

### プログラミング: キャラクター制御、当たり判定、ゲームロジック

**概要と重要性**

ゲームの心臓部とも言えるプログラミングは、キャラクターを動かし、敵と戦い、ゲームのルールを定義する上で不可欠です。キャラクター制御、当たり判定、そしてゲームロジックの構築は、プレイヤーに没入感と楽しさを提供するために最も重要な要素です。

**特徴と利点**

- **キャラクター制御:** キーボード、マウス、ゲームパッドなどの入力デバイスからの入力を受け取り、キャラクターの動き（移動、ジャンプ、攻撃など）を制御します。
- **当たり判定:** キャラクターと敵、キャラクターと地形、弾丸と敵など、ゲーム内のオブジェクト同士の衝突を検出し、適切な処理を行います（ダメージの計算、ゲームオーバーなど）。
- **ゲームロジック:** ゲームのルール、スコアの計算、イベントの発生など、ゲーム全体の進行を管理します。

**事前準備と前提条件**

- 各ゲームエンジンのスクリプト言語（C#, GDScript, GML）の基本的な知識。
- 各ゲームエンジンの API（Application Programming Interface）の基本的な知識。
- 必要なアセット（キャラクターのスプライト、敵のスプライト、背景など）が用意されていること。

**基本的な使い方**

各エンジンでのキャラクター制御、当たり判定、ゲームロジックの実装方法を説明します。

- **Unity:**

  **キャラクター制御 (C#):**

  ```csharp
  using UnityEngine;

  public class PlayerController : MonoBehaviour
  {
      public float speed = 5f;
      public float jumpForce = 10f;
      private Rigidbody2D rb;
      private bool isGrounded;

      void Start()
      {
          rb = GetComponent<Rigidbody2D>();
      }

      void Update()
      {
          // 移動
          float moveX = Input.GetAxis("Horizontal");
          rb.velocity = new Vector2(moveX * speed, rb.velocity.y);

          // ジャンプ
          if (Input.GetButtonDown("Jump") && isGrounded)
          {
              rb.AddForce(Vector2.up * jumpForce, ForceMode2D.Impulse);
              isGrounded = false;
          }
      }

      void OnCollisionEnter2D(Collision2D collision)
      {
          if (collision.gameObject.CompareTag("Ground"))
          {
              isGrounded = true;
          }
      }
  }
  ```

  1.  新しい C#スクリプトを作成し、「PlayerController」などの名前を付けます。
  2.  スクリプトをキャラクターの GameObject にアタッチします。
  3.  キャラクターの GameObject に Rigidbody2D コンポーネントを追加します。
  4.  移動速度、ジャンプ力などの変数を調整します。
  5.  地面との当たり判定のために、地面の GameObject に「Ground」タグを付けます。

  **当たり判定 (C#):**

  Unity では、Collider2D コンポーネントと OnCollisionEnter2D などのメソッドを使用して当たり判定を実装します。上記の例では、地面との当たり判定を実装しています。敵との当たり判定は、敵の GameObject に Collider2D コンポーネントを追加し、PlayerController スクリプトで OnCollisionEnter2D メソッドを実装することで実現できます。

  **ゲームロジック (C#):**

  ```csharp
  using UnityEngine;
  using UnityEngine.UI;

  public class GameManager : MonoBehaviour
  {
      public int score = 0;
      public Text scoreText;

      public void AddScore(int amount)
      {
          score += amount;
          scoreText.text = "Score: " + score;
      }
  }
  ```

  1.  新しい C#スクリプトを作成し、「GameManager」などの名前を付けます。
  2.  スクリプトを GameObject にアタッチします。
  3.  スコア、ライフ、ゲームオーバーなどの変数を管理します。
  4.  AddScore などのメソッドを作成し、スコアを更新します。
  5.  UI Text オブジェクトを作成し、スコアを表示します。

- **Godot:**

  **キャラクター制御 (GDScript):**

  ```gdscript
  extends KinematicBody2D

  export var speed = 200
  export var jump_force = -600
  var velocity = Vector2.ZERO
  var gravity = 1200

  func _physics_process(delta):
      # 移動
      var move_x = Input.get_action_strength("ui_right") - Input.get_action_strength("ui_left")
      velocity.x = move_x * speed

      # ジャンプ
      if is_on_floor() and Input.is_action_just_pressed("ui_accept"):
          velocity.y = jump_force

      # 重力
      velocity.y += gravity * delta

      velocity = move_and_slide(velocity, Vector2.UP)
  ```

  1.  新しいシーンを作成し、KinematicBody2D ノードを追加します。
  2.  KinematicBody2D ノードに Sprite ノードを追加し、キャラクターのスプライトを設定します。
  3.  KinematicBody2D ノードに CollisionShape2D ノードを追加し、当たり判定の形状を設定します。
  4.  新しい GDScript を作成し、「player.gd」などの名前を付けます。
  5.  スクリプトを KinematicBody2D ノードにアタッチします。
  6.  移動速度、ジャンプ力などの変数を調整します。

  **当たり判定 (GDScript):**

  Godot では、KinematicBody2D ノードの move_and_slide メソッドを使用すると、自動的に当たり判定が行われます。上記の例では、move_and_slide メソッドを使用して移動と当たり判定を同時に行っています。他のオブジェクトとの当たり判定は、Area2D ノードを使用することで実現できます。

  **ゲームロジック (GDScript):**

  ```gdscript
  extends Node

  var score = 0
  var lives = 3

  func add_score(amount):
      score += amount
      print("Score: ", score)

  func lose_life():
      lives -= 1
      print("Lives: ", lives)
      if lives <= 0:
          game_over()

  func game_over():
      print("Game Over!")
  ```

  1.  新しいシーンを作成し、Node ノードを追加します。
  2.  Node ノードに GDScript をアタッチします。
  3.  スコア、ライフ、ゲームオーバーなどの変数を管理します。
  4.  add_score、lose_life、game_over などの関数を作成し、ゲームロジックを実装します。
  5.  UI 要素（Label など）を作成し、スコアやライフを表示します。

- **GameMaker Studio 2:**

  **キャラクター制御 (GML):**

  ```gml
  // Create Event
  speed = 4;
  jump_speed = 10;
  gravity = 0.5;
  vspeed = 0;

  // Step Event
  var move = keyboard_check(vk_right) - keyboard_check(vk_left);
  x += move * speed;

  if (place_meeting(x, y + 1, obj_ground)) {
      vspeed = 0;
      if (keyboard_check_pressed(vk_space)) {
          vspeed = -jump_speed;
      }
  } else {
      vspeed += gravity;
  }

  y += vspeed;
  ```

  1.  新しいオブジェクトを作成し、「obj_player」などの名前を付けます。
  2.  オブジェクトにスプライトを設定します。
  3.  Create Event で変数を初期化します（移動速度、ジャンプ力、重力など）。
  4.  Step Event で入力を受け取り、キャラクターの動きを制御します。
  5.  水平方向の移動は、`x += move * speed;` で実現します。
  6.  ジャンプは、`vspeed` 変数を操作することで実現します。
  7.  地面との当たり判定は、`place_meeting` 関数を使用します。

  **当たり判定 (GML):**

  GameMaker Studio 2 では、`place_meeting` 関数や `collision_circle` 関数などを使用して当たり判定を実装します。上記の例では、地面との当たり判定を`place_meeting`関数で実装しています。

  **ゲームロジック (GML):**

  ```gml
  // Create Event
  score = 0;
  lives = 3;

  // Step Event
  // スコアを加算する
  if (/* スコアを加算する条件 */) {
      score += 10;
  }

  // ライフを減らす
  if (/* ライフを減らす条件 */) {
      lives -= 1;
      if (lives <= 0) {
          // ゲームオーバー
          room_goto(rm_gameover);
      }
  }

  // Draw Event (GUIレイヤーに描画)
  draw_set_font(fnt_default);
  draw_set_color(c_white);
  draw_text(10, 10, "Score: " + string(score));
  draw_text(10, 30, "Lives: " + string(lives));
  ```

  1.  ゲームロジックを管理するオブジェクトを作成します（例: obj_game_manager）。
  2.  Create Event でスコア、ライフなどの変数を初期化します。
  3.  Step Event でゲームロジックを実装します（スコアの計算、ライフの管理、ゲームオーバーの判定など）。
  4.  Draw Event でスコアやライフを表示します。GUI レイヤーに描画することで、カメラの移動に影響されずに UI を表示できます。

**実践的なテクニック**

- **ステートマシン:** キャラクターの状態（アイドル、歩行、ジャンプ、攻撃など）を管理するために、ステートマシンを使用すると、複雑なキャラクター制御をより整理できます。
- **オブジェクトプール:** 大量のオブジェクト（弾丸など）を生成・破棄する場合、オブジェクトプールを使用すると、パフォーマンスを向上させることができます。
- **デバッグ:** デバッグツールを使用して、コードのバグを特定し、修正します。ログを出力したり、ブレークポイントを設定したりすることで、コードの動作を詳細に分析できます。

**応用例とユースケース**

- **RPG ゲーム:** 敵との戦闘システム、アイテムの使用、スキルツリーなどを実装します。
- **プラットフォーマーゲーム:** ジャンプ、ダッシュ、壁ジャンプなどの高度な移動アクションを実装します。
- **シューティングゲーム:** 敵の AI、弾丸の軌道、パワーアップなどを実装します。

**トラブルシューティング**

- **キャラクターが動かない:** スクリプトがアタッチされているか、入力の設定が正しいかを確認してください。
- **当たり判定がうまくいかない:** Collider2D コンポーネントが適切に設定されているか、当たり判定のコードが正しいかを確認してください。
- **ゲームがクラッシュする:** コードにエラーがないか、メモリリークがないかを確認してください。デバッグツールを使用して、エラーの原因を特定します。
