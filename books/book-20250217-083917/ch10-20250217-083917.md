## 10. 自動売買システム構築の基礎: API連携と注文処理

### 10.1. 自動売買システムのアーキテクチャ

#### 概要と重要性

自動売買システムは、あらかじめ設定したルールに基づいて、プログラムが自動的に株式やFXなどの取引を行うシステムです。人間の感情に左右されずに客観的な判断で取引を行えるため、高度なトレード戦略を効率的に実行できます。本セクションでは、自動売買システムの基本的なアーキテクチャについて解説します。

#### 特徴と利点

自動売買システムの主な利点は以下の通りです。

*   **感情の排除:** 感情的な判断による誤ったトレードを防ぎます。
*   **時間的制約の克服:** 24時間稼働させることができ、機会損失を減らせます。
*   **バックテストの実施:** 過去のデータを用いて戦略の有効性を検証できます。
*   **効率的な取引:** 複数の市場や銘柄を同時に監視し、迅速な取引が可能です。

#### 事前準備と前提条件

*   プログラミングの基礎知識（Python, JavaScriptなど）
*   証券会社APIの利用に必要な口座開設
*   APIキーの取得

#### 基本的な使い方

自動売買システムのアーキテクチャは、一般的に以下の要素で構成されます。

1.  **データ取得:** 証券会社APIや外部データソースから、リアルタイムの株価や為替レートなどのデータを取得します。
2.  **戦略ロジック:** 取得したデータに基づいて、売買の判断を行うルールを記述します。
3.  **注文処理:** 戦略ロジックの判断に従い、証券会社APIを通じて注文を送信します。
4.  **ポジション管理:** 現在保有しているポジション（建玉）を管理し、決済のタイミングを判断します。
5.  **リスク管理:** 損失を最小限に抑えるためのリスク管理ルールを適用します。
6.  **ログ記録:** システムの動作状況や取引履歴を記録し、分析や改善に役立てます。

#### 実践的なテクニック

以下は、Pythonを使った自動売買システムの基本的なアーキテクチャの例です。

```python
import requests
import time

# APIキーの設定
API_KEY = "YOUR_API_KEY"
SECRET_KEY = "YOUR_SECRET_KEY"

# 証券会社APIのエンドポイント
ORDER_URL = "https://api.example.com/order"
POSITION_URL = "https://api.example.com/position"
PRICE_URL = "https://api.example.com/price?symbol=AAPL" #AAPLはAppleのティッカーシンボル

def get_price():
    """リアルタイムの株価を取得する"""
    response = requests.get(PRICE_URL)
    response.raise_for_status() # エラーが発生した場合に例外を発生させる
    data = response.json()
    return data["price"]

def send_order(symbol, side, quantity, price):
    """注文を送信する"""
    payload = {
        "symbol": symbol,
        "side": side, # "buy" or "sell"
        "quantity": quantity,
        "price": price,
        "api_key": API_KEY,
        "secret_key": SECRET_KEY
    }
    response = requests.post(ORDER_URL, json=payload)
    response.raise_for_status()
    data = response.json()
    return data

def get_position(symbol):
    """現在のポジションを取得する"""
    response = requests.get(POSITION_URL + f"?symbol={symbol}")
    response.raise_for_status()
    data = response.json()
    return data["quantity"]

# 簡単な移動平均線を使った売買戦略
def trading_strategy():
    """売買戦略のロジック"""
    try:
        price = get_price()
        position = get_position("AAPL")

        # 例：単純移動平均線を計算（過去5日間の平均）
        # (実際には、より複雑な計算が必要です)
        ma_5 = (price + get_price() + get_price() + get_price() + get_price()) / 5

        # ゴールデンクロス発生
        if price > ma_5 and position == 0:
            print("買いシグナル！")
            send_order("AAPL", "buy", 10, price) # 成行注文
        # デッドクロス発生
        elif price < ma_5 and position > 0:
            print("売りシグナル！")
            send_order("AAPL", "sell", position, price) # 成行注文
        else:
            print("様子見...")

    except requests.exceptions.RequestException as e:
        print(f"APIエラー: {e}") # APIエラーを詳細に表示
    except Exception as e:
        print(f"予期せぬエラー: {e}") # その他のエラーを詳細に表示

# メインループ
if __name__ == "__main__":
    while True:
        trading_strategy()
        time.sleep(60) # 1分ごとに実行
```

#### 応用例とユースケース

*   **高頻度取引（HFT）：** 非常に短い時間間隔で大量の取引を行うシステム。
*   **裁定取引（アービトラージ）：** 異なる市場間の価格差を利用して利益を得るシステム。
*   **トレンドフォロー:** トレンドに乗って利益を追求するシステム。
*   **リバーサル戦略:** 相場の反転を予測して利益を追求するシステム。

#### トラブルシューティング

*   **API接続エラー:** APIキーの誤りやネットワーク接続の問題が考えられます。APIキーを再確認し、ネットワーク接続を確認してください。
*   **注文エラー:** 証券会社の取引時間外や注文数量の制限などが原因として考えられます。取引時間や制限を確認してください。
*   **レート制限:** APIの使用回数制限を超過すると、一時的にAPIが利用できなくなることがあります。レート制限を超えないように、APIの使用回数を調整してください。

### 10.3. APIキーの取得と認証

#### 概要と重要性

証券会社APIを利用するためには、APIキーと呼ばれる認証情報が必要です。APIキーは、APIを利用するユーザーを識別し、アクセス権限を管理するために使用されます。APIキーの取得と認証は、自動売買システムを構築する上で不可欠な手順です。

#### 特徴と利点

APIキーを取得することで、証券会社APIへのアクセスが可能になり、以下の操作を行うことができます。

*   リアルタイムの株価や為替レートなどのデータを取得する。
*   注文を送信する。
*   口座情報を確認する。
*   ポジションを管理する。

#### 事前準備と前提条件

*   選定した証券会社の口座開設
*   証券会社のウェブサイトでAPI利用申請

#### 基本的な使い方

証券会社のウェブサイトでAPI利用申請を行い、APIキーとシークレットキーを取得します。APIキーは、公開鍵のようなもので、APIリクエストに含めて送信します。シークレットキーは、秘密鍵のようなもので、APIリクエストの署名（認証）に使用します。

#### 実践的なテクニック

APIキーとシークレットキーの利用例（Python）。

```python
import requests
import hashlib
import hmac
import time

# APIキーとシークレットキーの設定
API_KEY = "YOUR_API_KEY"
SECRET_KEY = "YOUR_SECRET_KEY"

# 証券会社APIのエンドポイント
ORDER_URL = "https://api.example.com/order"

def create_signature(message, secret_key):
    """APIリクエストの署名を生成する"""
    message = message.encode('utf-8')
    secret_key = secret_key.encode('utf-8')
    signature = hmac.new(secret_key, message, hashlib.sha256).hexdigest()
    return signature

def send_order(symbol, side, quantity, price):
    """注文を送信する"""
    timestamp = str(int(time.time()))
    message = f"{timestamp}{symbol}{side}{quantity}{price}"
    signature = create_signature(message, SECRET_KEY)

    payload = {
        "symbol": symbol,
        "side": side,
        "quantity": quantity,
        "price": price,
        "timestamp": timestamp,
        "api_key": API_KEY,
        "signature": signature
    }

    response = requests.post(ORDER_URL, json=payload)
    response.raise_for_status()
    data = response.json()
    return data
```

**注意:** シークレットキーは、絶対に他人に漏らさないように厳重に管理してください。ソースコードに直接記述せず、環境変数や設定ファイルに保存することを推奨します。

#### 応用例とユースケース

*   **多要素認証:** APIキーに加えて、OTP（One-Time Password）などの多要素認証を導入することで、セキュリティを強化できます。

#### トラブルシューティング

*   **APIキーの有効期限:** APIキーには有効期限が設定されている場合があります。有効期限が切れていないか確認してください。
*   **IPアドレス制限:** APIへのアクセスを特定のIPアドレスに制限している場合があります。アクセス元のIPアドレスが制限されていないか確認してください。
*   **アクセス権限:** APIキーに付与されたアクセス権限が、必要な操作を許可しているか確認してください。

### 10.4. 注文処理: 成行注文、指値注文、逆指値注文

#### 概要と重要性

自動売買システムにおいて、注文処理は最も重要な機能の一つです。プログラムが自動的に注文を送信し、取引を実行することで、効率的なトレードを実現します。本セクションでは、成行注文、指値注文、逆指値注文といった基本的な注文方法について解説します。

#### 特徴と利点

*   **成行注文:** 現在の市場価格で即座に注文を執行します。約定を最優先とする場合に適しています。
*   **指値注文:** 指定した価格以下（買い注文の場合）または以上（売り注文の場合）になった場合に注文を執行します。希望する価格で取引したい場合に適しています。
*   **逆指値注文:** 指定した価格以上（買い注文の場合）または以下（売り注文の場合）になった場合に成行注文を執行します。損失を限定したり、トレンドに乗ったりするために使用します。

#### 事前準備と前提条件

*   証券会社APIの利用準備
*   APIキーの取得と認証

#### 基本的な使い方

各注文方法のAPIリクエスト例（Python）。

```python
import requests

# 証券会社APIのエンドポイント
ORDER_URL = "https://api.example.com/order"

def send_market_order(symbol, side, quantity):
    """成行注文を送信する"""
    payload = {
        "symbol": symbol,
        "side": side, # "buy" or "sell"
        "quantity": quantity,
        "order_type": "market",
        "api_key": API_KEY, # 先に定義済みのAPIキー
        "signature": SIGNATURE # 先に定義済みの署名
    }
    response = requests.post(ORDER_URL, json=payload)
    response.raise_for_status()
    data = response.json()
    return data

def send_limit_order(symbol, side, quantity, price):
    """指値注文を送信する"""
    payload = {
        "symbol": symbol,
        "side": side,
        "quantity": quantity,
        "price": price,
        "order_type": "limit",
        "api_key": API_KEY,
        "signature": SIGNATURE
    }
    response = requests.post(ORDER_URL, json=payload)
    response.raise_for_status()
    data = response.json()
    return data

def send_stop_order(symbol, side, quantity, stop_price):
    """逆指値注文を送信する"""
    payload = {
        "symbol": symbol,
        "side": side,
        "quantity": quantity,
        "stop_price": stop_price,
        "order_type": "stop",
        "api_key": API_KEY,
        "signature": SIGNATURE
    }
    response = requests.post(ORDER_URL, json=payload)
    response.raise_for_status()
    data = response.json()
    return data
```

**注意:** 注文処理は、実際の資金を使って行う前に、必ずテスト環境で動作確認を行ってください。注文数量や価格を誤ると、意図しない損失が発生する可能性があります。

#### 実践的なテクニック

*   **OCO（One Cancels the Other）注文:** 利益確定の指値注文と損切りの逆指値注文を同時に出し、どちらか一方が約定したら、もう一方を自動的にキャンセルする注文方法。
*   **IFD（If Done）注文:** 新規注文が約定したら、自動的に決済注文を出す注文方法。

#### 応用例とユースケース

*   **自動損切り:** 損失が一定額に達した場合、自動的にポジションを決済するシステム。
*   **自動利益確定:** 利益が一定額に達した場合、自動的にポジションを決済するシステム。
*   **ブレイクアウト戦略:** 株価が特定の価格帯を突破した場合、自動的に買い注文を出すシステム。

#### トラブルシューティング

*   **注文エラー:** 注文が拒否された場合、エラーメッセージを確認し、原因を特定してください。
*   **約定遅延:** 市場の状況によっては、注文がすぐに約定しない場合があります。
*   **スリッページ:** 成行注文の場合、注文時の価格と実際に約定した価格に差が生じることがあります。

### 10.5. ポジション管理: 現在のポジションの確認と決済

#### 概要と重要性

自動売買システムにおいて、ポジション管理は非常に重要な役割を果たします。現在のポジション（建玉）を正確に把握し、適切なタイミングで決済することで、利益を最大化し、損失を最小限に抑えることができます。

#### 特徴と利点

*   **リアルタイムなポジション把握:** 現在保有しているポジションの数量、平均取得価格、評価損益などをリアルタイムで確認できます。
*   **自動決済:** 設定したルールに基づいて、自動的にポジションを決済できます。
*   **リスク管理:** ポジションのリスクを評価し、必要に応じてポジションを調整できます。

#### 事前準備と前提条件

*   証券会社APIの利用準備
*   APIキーの取得と認証
*   注文処理の実装

#### 実践的なテクニック

*   **トレーリングストップ:** 株価が上昇するにつれて、逆指値注文の価格を自動的に引き上げることで、利益を確保しながら、さらなる上昇を狙うことができます。
*   **ポジションサイジング:** リスク許容度に応じて、ポジションのサイズを調整することで、損失を限定することができます。

#### 応用例とユースケース

*   **ポートフォリオ管理:** 複数の銘柄のポジションを管理し、ポートフォリオ全体のリスクを評価するシステム。

#### トラブルシューティング

*   **ポジション情報の不一致:** 証券会社のウェブサイトで表示されるポジション情報と、APIで取得したポジション情報に差異がある場合、APIのキャッシュやデータの更新頻度を確認してください。
*   **決済エラー:** ポジションを決済しようとした際にエラーが発生した場合、注文数量や価格、市場の状況などを確認してください。

### 10.6. API Rate Limitの考慮: エラーハンドリング

#### 概要と重要性

証券会社APIは、通常、API Rate Limit（APIの使用回数制限）を設定しています。これは、サーバーへの負荷を軽減し、安定したサービスを提供するために必要な措置です。API Rate Limitを超過すると、APIの利用を一時的に制限されることがあります。そのため、自動売買システムを構築する際には、API Rate Limitを考慮し、適切なエラーハンドリングを行う必要があります。

#### 特徴と利点

*   **API Rate Limitの把握:** 証券会社APIのドキュメントを確認し、API Rate Limit（1分あたりのリクエスト数など）を把握します。
*   **リクエスト間隔の調整:** API Rate Limitを超えないように、APIリクエストの間隔を調整します。
*   **エラーハンドリング:** API Rate Limitを超過した場合のエラーハンドリングを実装します。

#### 事前準備と前提条件

*   証券会社APIの利用準備
*   APIキーの取得と認証
*   注文処理の実装
*   ポジション管理の実装

#### 基本的な使い方

API Rate Limitを超えないように、APIリクエストの間隔を調整する例（Python）。

```python
import time
import requests

# APIリクエストの間隔（秒）
REQUEST_INTERVAL = 0.5

def get_price(symbol):
    """株価を取得する"""
    try:
        response = requests.get(f"https://api.example.com/price?symbol={symbol}")
        response.raise_for_status()
        data = response.json()
        return data["price"]
    except requests.exceptions.RequestException as e:
        print(f"APIエラー: {e}")
        return None
    except Exception as e:
        print(f"予期せぬエラー: {e}")
        return None
    finally:
        time.sleep(REQUEST_INTERVAL) # API Rate Limitを超えないように待機
```

API Rate Limitを超過した場合のエラーハンドリング例（Python）。

```python
import time
import requests

def send_order(symbol, side, quantity, price):
    """注文を送信する"""
    try:
        response = requests.post("https://api.example.com/order", json={
            "symbol": symbol,
            "side": side,
            "quantity": quantity,
            "price": price,
            "api_key": API_KEY,
            "signature": SIGNATURE
        })
        response.raise_for_status()
        data = response.json()
        return data
    except requests.exceptions.HTTPError as e:
        if e.response.status_code == 429:  # Rate Limit超過の場合
            print("API Rate Limitを超過しました。")
            time.sleep(60)  # 60秒待機してリトライ
            return send_order(symbol, side, quantity, price)  # 再帰的にリトライ
        else:
            print(f"注文エラー: {e}")
            return None
    except Exception as e:
        print(f"予期せぬエラー: {e}")
        return None
```

#### 実践的なテクニック

*   **キューイング:** APIリクエストをキューに格納し、API Rate Limitを超えないように順番に処理する。
*   **バックオフ:** API Rate Limitを超過した場合、指数関数的に待機時間を長くする。

#### 応用例とユースケース

*   **高頻度取引（HFT）:** API Rate Limitを最大限に活用し、高頻度で取引を行うシステム。
*   **データ収集:** 大量のデータを収集する場合、API Rate Limitを考慮しながら、効率的にデータを収集する。

#### トラブルシューティング

*   **API Rate Limitの誤認識:** 証券会社APIのドキュメントをよく確認し、API Rate Limitを正しく理解してください。
*   **エラーハンドリングの不備:** API Rate Limitを超過した場合のエラーハンドリングが不十分だと、システムが停止する可能性があります。
