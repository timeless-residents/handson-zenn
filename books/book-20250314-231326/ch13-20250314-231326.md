## 第13章: WebAssemblyとScratch - 未来の高速化技術

### 13.1 WebAssemblyとは何か？ - ブラウザの限界を超える

**1. 概要と重要性**

WebAssembly（Wasm）は、Webブラウザ上で高パフォーマンスなコードを実行するための新しいバイナリ命令形式です。従来のJavaScriptに比べて、ネイティブコードに近い速度で動作するため、ゲーム、高度なグラフィックス処理、複雑な計算処理など、JavaScriptだけでは難しかった処理をブラウザ上で実現できます。

特にScratchのようなビジュアルプログラミング環境では、複雑なアルゴリズムや処理をWebAssemblyにオフロードすることで、プロジェクトのパフォーマンスを大幅に向上させることが期待できます。重い処理をWasmに任せ、Scratchはインタラクティブな要素や視覚的な表現に集中することで、より快適でリッチな体験を提供できるようになります。

**2. 特徴と利点**

*   **高速性:** ネイティブコードに近い速度で動作するため、JavaScriptよりも高速な処理が可能です。
*   **安全性:** サンドボックス化された環境で実行されるため、セキュリティ上のリスクが低いです。
*   **移植性:** 異なるプラットフォームやアーキテクチャで動作するため、幅広い環境で利用できます。
*   **言語互換性:** C、C++、Rustなど、様々な言語で記述されたコードをWebAssemblyにコンパイルできます。

ScratchにおいてWebAssemblyを活用する主な利点は以下の通りです。

*   **複雑な計算処理の高速化:** 特に、数値計算や物理シミュレーションなど、CPU負荷の高い処理を高速化できます。
*   **大規模データの処理:** 大量のデータを扱う処理も、WebAssemblyの効率的なメモリ管理により高速化が期待できます。
*   **高度なアルゴリズムの実装:** JavaScriptではパフォーマンスがネックだった複雑なアルゴリズムを、実用的な速度で実装できます。

**3. 事前準備と前提条件**

*   **WebAssembly開発環境:** WebAssemblyをコンパイルするためのツールチェインが必要です。今回は、Emscriptenというツールを使用します。Emscriptenは、C/C++コードをWebAssemblyにコンパイルするための包括的なツールキットです。
    *   Emscriptenのインストール: [https://emscripten.org/docs/getting_started/downloads.html](https://emscripten.org/docs/getting_started/downloads.html) を参照し、指示に従ってインストールしてください。
*   **ScratchLink:** WebAssemblyとScratchを連携させるために、ScratchLinkが必要となる場合があります（ネットワーク通信を伴う場合など）。
*   **基本的なプログラミング知識:** C/C++などのプログラミング言語の基本的な知識があると理解が深まります。

**4. 基本的な使い方**

1.  **C/C++コードの作成:** WebAssemblyとしてコンパイルするC/C++コードを作成します。

2.  **Emscriptenによるコンパイル:** Emscriptenを使ってC/C++コードをWebAssemblyにコンパイルします。

3.  **Scratchへの組み込み:** コンパイルされたWebAssemblyモジュールを、ScratchのカスタムブロックやJavaScript拡張機能として組み込みます。

**5. 実践的なテクニック**

以下に、簡単な処理をWebAssemblyで記述し、Scratchに組み込む例を示します。今回は、単純な足し算の関数をWasmで実装し、Scratchから呼び出すことを目指します。

**ステップ1: C++コードの作成 (add.cpp)**

```cpp
#include <iostream>

extern "C" {
  int add(int a, int b) {
    return a + b;
  }
}
```

このコードは、`add`という名前の関数を定義しています。この関数は2つの整数を受け取り、それらの和を返します。`extern "C"`は、C++コンパイラに対して、この関数をC言語のリンク規則に従ってコンパイルするように指示します。これは、JavaScriptからWebAssembly関数を呼び出す際に必要です。

**ステップ2: WebAssemblyへのコンパイル**

Emscriptenを使ってC++コードをWebAssemblyにコンパイルします。ターミナルを開き、以下のコマンドを実行します。

```bash
emcc add.cpp -o add.js -s EXPORTED_FUNCTIONS="['_add']" -s MODULARIZE=1 -s 'EXPORT_NAME="AddModule"' -s ENVIRONMENT=web
```

各オプションの意味は以下の通りです。

*   `emcc`: Emscriptenのコンパイラ
*   `add.cpp`: コンパイルするC++ファイル
*   `-o add.js`: 出力ファイル名 (JavaScriptラッパーを含む)
*   `-s EXPORTED_FUNCTIONS="['_add']"`: エクスポートする関数を指定 (アンダースコアを付加)
*   `-s MODULARIZE=1`: モジュール形式で出力
*   `-s 'EXPORT_NAME="AddModule"'`: モジュールのエクスポート名を指定
*   `-s ENVIRONMENT=web`: ブラウザ環境向けに最適化

このコマンドを実行すると、`add.js`と`add.wasm`というファイルが生成されます。`add.js`はWebAssemblyモジュールをロードし、JavaScriptから利用するためのラッパーコードを含んでいます。`add.wasm`は実際のWebAssemblyバイナリファイルです。

**ステップ3: Scratchでの利用**

Scratchでカスタムブロックを作成し、`add.js`を読み込んで`add`関数を呼び出すように設定します。

1.  Scratchのエディタを開き、「拡張機能」メニューから「JavaScript」を選択します。

2.  以下のJavaScriptコードを記述します。

```javascript
class AddExtension {
  constructor() {
    this.module = null;
    this.isReady = false;

    createAddModule().then(module => {
      this.module = module;
      this.isReady = true;
      console.log("AddModule loaded");
    });
  }

  getInfo() {
    return {
      id: 'addextension',
      name: 'Add Extension',
      blocks: [
        {
          opcode: 'addNumbers',
          blockType: Scratch.BlockType.REPORTER,
          text: 'add [A] + [B]',
          arguments: {
            A: {
              type: Scratch.ArgumentType.NUMBER,
              defaultValue: 1
            },
            B: {
              type: Scratch.ArgumentType.NUMBER,
              defaultValue: 2
            }
          }
        }
      ]
    };
  }

  addNumbers(args) {
    if (!this.isReady) return 0;
    const a = args.A;
    const b = args.B;
    return this.module._add(a, b);
  }
}

Scratch.extensions.register(new AddExtension());
```

このコードは、`AddExtension`という名前のScratch拡張機能を定義しています。コンストラクタで`add.js`をロードし、`addNumbers`という名前のカスタムブロックを定義しています。`addNumbers`ブロックは、2つの引数を受け取り、WebAssemblyの`add`関数を呼び出して結果を返します。

**ステップ4: Scratchブロックの実行**

作成したカスタムブロックをScratchのスクリプトで使用します。例えば、`A`に10、`B`に20を設定して`addNumbers`ブロックを実行すると、30が返されます。

**6. 応用例とユースケース**

*   **高度な数学関数:** 三角関数、指数関数、対数関数など、JavaScriptのMathオブジェクトにない高度な数学関数をWebAssemblyで実装し、Scratchで利用できます。
*   **画像処理:** 画像のフィルタリング、色変換、エッジ検出などの処理をWebAssemblyで実装し、Scratchの画像処理機能を拡張できます。
*   **物理シミュレーション:** 物理エンジンをWebAssemblyで実装し、Scratchでよりリアルな物理シミュレーションを実現できます。
*   **AI/機械学習:** 機械学習モデルをWebAssemblyで実行し、Scratchで高度なAI機能を実装できます。

**7. トラブルシューティング**

*   **コンパイルエラー:** Emscriptenのバージョンが古い場合や、設定が間違っている場合にコンパイルエラーが発生することがあります。Emscriptenのドキュメントを参照し、正しい設定を確認してください。
*   **JavaScriptエラー:** WebAssemblyモジュールのロードに失敗した場合や、JavaScriptコードにエラーがある場合にJavaScriptエラーが発生することがあります。ブラウザの開発者ツールを使ってエラーの内容を確認し、修正してください。
*   **パフォーマンスの問題:** WebAssemblyのパフォーマンスが期待通りでない場合、コンパイルオプションが最適化されていない可能性があります。Emscriptenの最適化オプションを調整し、パフォーマンスを向上させてください。

**8. まとめと次のステップ**

WebAssemblyを使うことで、Scratchプロジェクトのパフォーマンスを大幅に向上させることができます。簡単な例から始めて、徐々に複雑な処理をWebAssemblyにオフロードしていくことで、より高度なScratchプロジェクトを作成することができます。次は、より複雑なアルゴリズムや処理をWebAssemblyで実装し、Scratchに組み込んでみましょう。例えば、簡単なソートアルゴリズムをWasmで実装し、Scratchのリストのソートを高速化することができます。

### 13.2 Scratchのカスタムブロック - 機能を拡張する

**1. 概要と重要性**

Scratchのカスタムブロックは、Scratchの機能を拡張するための強力なツールです。既存のブロックを組み合わせるだけでなく、独自のブロックを作成することで、より複雑な処理や独自の機能をScratchに追加することができます。

カスタムブロックは、Scratchプロジェクトの再利用性を高め、コードを整理しやすくする効果もあります。何度も同じ処理を繰り返す場合に、カスタムブロックとしてまとめることで、コードの見通しが良くなり、メンテナンスも容易になります。

**2. 特徴と利点**

*   **機能拡張性:** Scratchの標準機能にない独自の機能を追加できます。
*   **再利用性:** 作成したカスタムブロックは、他のScratchプロジェクトでも利用できます。
*   **可読性:** 複雑な処理をカスタムブロックとしてまとめることで、コードの見通しが良くなります。
*   **保守性:** カスタムブロックを修正するだけで、そのブロックを使用しているすべての箇所が修正されます。

WebAssemblyとカスタムブロックを連携させることで、WebAssemblyの高速な処理をScratchから簡単に利用できるようになります。カスタムブロックをWebAssemblyのインターフェースとして利用することで、Scratchのプログラミング体験を損なうことなく、パフォーマンスを向上させることができます。

**3. 事前準備と前提条件**

*   **Scratchの基本的な操作:** Scratchのエディタの基本的な操作を理解している必要があります。
*   **カスタムブロックの作成経験:** カスタムブロックの作成方法を理解している必要があります。
*   **WebAssemblyの知識:** WebAssemblyの基本的な知識があると理解が深まります。
*   **JavaScriptの知識:** Scratch拡張機能を作成するために、JavaScriptの知識が必要となります。

**4. 基本的な使い方**

1.  **カスタムブロックの作成:** Scratchのエディタでカスタムブロックを作成します。

2.  **JavaScriptコードの記述:** カスタムブロックの機能を実装するためのJavaScriptコードを記述します。このJavaScriptコードの中で、WebAssemblyの関数を呼び出します。

3.  **Scratch拡張機能の登録:** JavaScriptコードをScratch拡張機能として登録します。

**5. 実践的なテクニック**

前のセクションで作成した`add.js`と`add.wasm`を使用し、Scratchのカスタムブロックから呼び出す方法を説明します。

1.  **カスタムブロックの定義:** Scratchのエディタで、`addNumbers`という名前のカスタムブロックを作成します。このブロックは、2つの引数を受け取り、それらの和を返します。

2.  **JavaScriptコードの記述:** Scratch拡張機能を作成し、`addNumbers`ブロックの機能を実装します。

```javascript
class AddExtension {
```

3.  **Scratch拡張機能の登録:** JavaScriptコードをScratch拡張機能として登録します。Scratchのエディタで、「拡張機能」メニューから「JavaScript」を選択し、JavaScriptコードを貼り付けます。

4.  **カスタムブロックの実行:** 作成したカスタムブロックをScratchのスクリプトで使用します。`A`と`B`に値を設定し、`addNumbers`ブロックを実行すると、WebAssemblyで計算された和が返されます。

**6. 応用例とユースケース**

*   **複雑なアルゴリズムの実装:** WebAssemblyで実装した複雑なアルゴリズムを、カスタムブロックとしてScratchに実装できます。例えば、グラフ探索アルゴリズムや暗号化アルゴリズムなどを実装できます。
*   **外部APIとの連携:** WebAssemblyで実装した外部APIとの連携機能を、カスタムブロックとしてScratchに実装できます。例えば、Webカメラの画像処理や音声認識などを実装できます。
*   **独自のゲームエンジンの作成:** WebAssemblyで実装したゲームエンジンを、カスタムブロックとしてScratchに実装できます。例えば、3Dゲームエンジンや物理エンジンなどを実装できます。

**7. トラブルシューティング**

*   **カスタムブロックが表示されない:** JavaScriptコードにエラーがある場合や、Scratch拡張機能の登録に失敗した場合、カスタムブロックが表示されないことがあります。ブラウザの開発者ツールを使ってエラーの内容を確認し、修正してください。
*   **カスタムブロックが動作しない:** JavaScriptコードのロジックに誤りがある場合や、WebAssemblyの関数呼び出しに失敗した場合、カスタムブロックが動作しないことがあります。JavaScriptコードのデバッグを行い、WebAssemblyの関数が正しく呼び出されているか確認してください。
*   **パフォーマンスの問題:** カスタムブロックの処理が遅い場合、WebAssemblyのパフォーマンスが最適化されていない可能性があります。WebAssemblyのコンパイルオプションを調整し、パフォーマンスを向上させてください。

**8. まとめと次のステップ**

カスタムブロックを使うことで、Scratchの機能を大幅に拡張できます。WebAssemblyとカスタムブロックを連携させることで、WebAssemblyの高速な処理をScratchから簡単に利用できるようになり、より高度なScratchプロジェクトを作成することができます。次は、より複雑なアルゴリズムや処理をWebAssemblyで実装し、カスタムブロックとしてScratchに組み込んでみましょう。例えば、簡単な画像フィルタをWasmで実装し、Scratchで画像加工ツールを作ることができます。

### 13.3 パフォーマンスチューニング - 速度を極める

**1. 概要と重要性**

Scratchプロジェクトのパフォーマンスは、ユーザーエクスペリエンスに大きな影響を与えます。特に、複雑なゲームやアニメーションでは、処理が遅延すると操作性が悪くなり、ユーザーの満足度が低下する可能性があります。WebAssemblyを活用することで、Scratchプロジェクトのパフォーマンスを大幅に向上させることができますが、WebAssemblyのパフォーマンスを最大限に引き出すためには、パフォーマンスチューニングが不可欠です。

パフォーマンスチューニングは、ボトルネックとなっている処理を特定し、最適化することで、プロジェクト全体の処理速度を向上させるプロセスです。WebAssemblyの特性を理解し、適切な最適化手法を適用することで、Scratchプロジェクトのパフォーマンスを劇的に改善することができます。

**2. 特徴と利点**

*   **処理速度の向上:** パフォーマンスチューニングを行うことで、Scratchプロジェクトの処理速度を向上させることができます。
*   **操作性の改善:** 処理速度が向上することで、操作性が改善され、より快適なユーザーエクスペリエンスを提供できます。
*   **リソースの効率的な利用:** パフォーマンスチューニングを行うことで、CPUやメモリなどのリソースを効率的に利用できます。
*   **バッテリー消費の抑制:** パフォーマンスチューニングを行うことで、バッテリー消費を抑制することができます（モバイルデバイスの場合）。

WebAssemblyを活用した高速化テクニックを駆使することで、Scratchプロジェクトのパフォーマンスを最大限に引き出すことができます。

**3. 事前準備と前提条件**

*   **Scratchの基本的な操作:** Scratchのエディタの基本的な操作を理解している必要があります。
*   **WebAssemblyの知識:** WebAssemblyの基本的な知識があると理解が深まります。
*   **JavaScriptの知識:** Scratch拡張機能を作成するために、JavaScriptの知識が必要となります。
*   **パフォーマンス測定ツール:** ブラウザの開発者ツールなど、パフォーマンスを測定するためのツールが必要です。

**4. 基本的な使い方**

1.  **パフォーマンス測定:** ブラウザの開発者ツールなどを使って、Scratchプロジェクトのパフォーマンスを測定します。ボトルネックとなっている処理を特定します。

2.  **WebAssemblyの最適化:** ボトルネックとなっている処理をWebAssemblyで実装し、最適化します。

3.  **Scratchへの組み込み:** 最適化されたWebAssemblyモジュールを、ScratchのカスタムブロックやJavaScript拡張機能として組み込みます。

4.  **パフォーマンスの再測定:** パフォーマンスを再測定し、改善効果を確認します。必要に応じて、さらに最適化を行います。

**5. 実践的なテクニック**

Scratchのゲームの処理速度を向上させる例を示します。今回は、大量のオブジェクトを扱うゲームを想定し、オブジェクトの座標計算をWebAssemblyで高速化します。

**ステップ1: パフォーマンス測定**

まずは、最適化前のScratchプロジェクトのパフォーマンスを測定します。ブラウザの開発者ツールの「パフォーマンス」タブを開き、ゲームを実行してパフォーマンスを記録します。CPUの使用率やフレームレートなどを確認し、ボトルネックとなっている処理を特定します。

**ステップ2: C++コードの作成 (object.cpp)**

大量のオブジェクトの座標計算を行うC++コードを作成します。

```cpp
#include <vector>

struct Object {
  float x;
  float y;
  float speedX;
  float speedY;
};

extern "C" {
  void updateObjects(float* x, float* y, float* speedX, float* speedY, int numObjects, float deltaTime) {
    for (int i = 0; i < numObjects; ++i) {
      x[i] += speedX[i] * deltaTime;
      y[i] += speedY[i] * deltaTime;
    }
  }
}
```

このコードは、`updateObjects`という名前の関数を定義しています。この関数は、オブジェクトの座標と速度の配列、オブジェクトの数、deltaTime（経過時間）を受け取り、各オブジェクトの座標を更新します。

**ステップ3: WebAssemblyへのコンパイル**

Emscriptenを使ってC++コードをWebAssemblyにコンパイルします。

```bash
emcc object.cpp -o object.js -s EXPORTED_FUNCTIONS="['_updateObjects']" -s MODULARIZE=1 -s 'EXPORT_NAME="ObjectModule"' -s ENVIRONMENT=web -O3
```

`-O3`オプションは、コンパイラの最適化レベルを最大に設定します。

**ステップ4: Scratchでの利用**

Scratchでカスタムブロックを作成し、`object.js`を読み込んで`updateObjects`関数を呼び出すように設定します。

```javascript
class ObjectExtension {
  constructor() {
    this.module = null;
    this.isReady = false;

    createObjectModule().then(module => {
      this.module = module;
      this.isReady = true;
      console.log("ObjectModule loaded");
    });
  }

  getInfo() {
    return {
      id: 'objectextension',
      name: 'Object Extension',
      blocks: [
        {
          opcode: 'updateObjects',
          blockType: Scratch.BlockType.COMMAND,
          text: 'update objects num [NUM] dt [DT]',
          arguments: {
            NUM: {
              type: Scratch.ArgumentType.NUMBER,
              defaultValue: 100
            },
            DT: {
              type: Scratch.ArgumentType.NUMBER,
              defaultValue: 0.1
            }
          }
        }
      ]
    };
  }

  updateObjects(args) {
    if (!this.isReady) return;
    const numObjects = args.NUM;
    const deltaTime = args.DT;

    // Scratchのリストから座標と速度の配列を取得
    const xList = Scratch.vm.runtime.globalVariables['x']; // xという名前のリスト
    const yList = Scratch.vm.runtime.globalVariables['y'];
    const speedXList = Scratch.vm.runtime.globalVariables['speedX'];
    const speedYList = Scratch.vm.runtime.globalVariables['speedY'];

    if (!xList || !yList || !speedXList || !speedYList) {
      console.warn("リストが見つかりません。Scratchでリストを作成してください (x, y, speedX, speedY)");
      return;
    }

    const x = new Float32Array(xList.value); // リストの値をFloat32Arrayに変換
    const y = new Float32Array(yList.value);
    const speedX = new Float32Array(speedXList.value);
    const speedY = new Float32Array(speedYList.value);

    // WebAssembly関数を呼び出し
    this.module._updateObjects(x.byteOffset, y.byteOffset, speedX.byteOffset, speedY.byteOffset, numObjects, deltaTime);

    // 更新された座標をScratchのリストに書き戻し (省略)
  }
}

Scratch.extensions.register(new ObjectExtension());
```

**ステップ5: パフォーマンスの再測定**

最適化されたWebAssemblyモジュールを組み込んだScratchプロジェクトのパフォーマンスを再度測定します。CPUの使用率やフレームレートなどが改善されていることを確認します。

**6. 応用例とユースケース**

*   **物理エンジンの高速化:** 物理エンジンの計算処理をWebAssemblyで実装し、ゲームの物理シミュレーションを高速化できます。
*   **3Dレンダリングの高速化:** 3Dレンダリングの計算処理をWebAssemblyで実装し、ゲームのグラフィックス処理を高速化できます。
*   **AI処理の高速化:** AIアルゴリズムの計算処理をWebAssemblyで実装し、ゲームのAI処理を高速化できます。

**7. トラブルシューティング**

*   **WebAssemblyのパフォーマンスが期待通りでない:** コンパイルオプションが最適化されていない可能性があります。`-O3`オプションなど、最適化レベルを高く設定してください。
*   **JavaScriptとWebAssembly間のデータ転送が遅い:** データ転送のオーバーヘッドを最小限にするために、できるだけJavaScriptとWebAssembly間のデータ転送を減らすようにしてください。
*   **メモリリーク:** WebAssemblyモジュールでメモリリークが発生している可能性があります。メモリリークを検出するためのツールを使用し、メモリリークを修正してください。

**8. まとめと次のステップ**

パフォーマンスチューニングは、Scratchプロジェクトのパフォーマンスを最大限に引き出すために不可欠です。WebAssemblyを活用した高速化テクニックを駆使することで、より快適でリッチなScratchプロジェクトを作成することができます。次は、より複雑な処理をWebAssemblyで実装し、パフォーマンスチューニングを行い、Scratchプロジェクトの可能性を広げてみましょう。例えば、音声処理、動画処理、ネットワーク処理などをWasmで行い、Scratchと連携させることができます。
