## 第4章: AIの第一歩 - 簡単な敵キャラクターを賢くする

### 4.1 AIって難しくない！ - 基本的なAIの考え方

#### 概要と重要性

AI（人工知能）と聞くと、なんだか難しそう、特別な知識が必要そう…と感じてしまうかもしれません。でも、心配ご無用！この章では、Scratchを使って、ゲームに登場する敵キャラクターを賢く動かすことを通して、AIの基本的な考え方を楽しく学んでいきます。AIの基礎を理解することで、ゲーム開発だけでなく、様々な分野で応用できる発想力や問題解決能力が身につきます。

#### 特徴と利点

ScratchでAIを学ぶことの大きな利点は、難しい数式や複雑なプログラミング言語の知識がなくても、視覚的にAIの仕組みを理解できることです。ブロックを組み合わせるだけで、敵キャラクターに「考えて」行動させることができるので、プログラミング初心者でも気軽にAIの世界に足を踏み入れられます。

#### 事前準備と前提条件

このセクションでは、Scratchの基本的な操作（スプライトの移動、条件分岐、繰り返し処理など）を理解していることを前提とします。もしScratchの操作に不安がある場合は、Scratchの公式チュートリアルや入門書などを参考に、基本的な操作をマスターしてからこの章に進んでください。

#### 基本的な使い方

AIの基本となる考え方は、「状態遷移」と「行動決定」です。

*   **状態遷移:** キャラクターが置かれている状況を表します。例えば、「敵はプレイヤーから近い距離にいる」「敵の体力は低い」などです。
*   **行動決定:** キャラクターがどのような行動を取るかを決定します。例えば、「プレイヤーを攻撃する」「安全な場所に逃げる」などです。

Scratchでは、これらの状態と行動を、「もし～なら」ブロックや「ずっと」ブロックを組み合わせて表現します。

#### 実装例：敵キャラクターがプレイヤーを追いかけるAIを実装

まずは、最もシンプルな例として、敵キャラクターがプレイヤーを追いかけるAIを実装してみましょう。

1.  **スプライトの準備:** Scratchで、敵キャラクターとプレイヤーのスプライトを用意します。
2.  **変数の設定:** 敵キャラクターのX座標、Y座標、プレイヤーのX座標、Y座標をそれぞれ変数として定義します。
3.  **初期設定:** ゲーム開始時に、敵キャラクターとプレイヤーの位置を初期位置に設定します。
4.  **追跡処理:** 敵キャラクターに以下のスクリプトを追加します。

```scratch
ずっと
  もし <(距離 (敵) から (プレイヤー) まで) < (100)> なら
    もし <(x座標 (プレイヤー)) > (x座標 (敵))> なら
      (x座標を (5) ずつ変える)
    でなければ
      (x座標を (-5) ずつ変える)
    もし <(y座標 (プレイヤー)) > (y座標 (敵))> なら
      (y座標を (5) ずつ変える)
    でなければ
      (y座標を (-5) ずつ変える)
  でなければ
    // プレイヤーが遠くにいる場合は、何もしない
  end
end
```

このスクリプトは、敵キャラクターが常にプレイヤーの位置を監視し、一定距離内にプレイヤーがいる場合は、プレイヤーの方向に近づくように移動する、という処理を行います。

#### 実践的なテクニック

よりスムーズな追跡を実現するために、角度と距離を使って移動する方法があります。

```scratch
ずっと
  もし <(距離 (敵) から (プレイヤー) まで) < (100)> なら
    (向きを ((プレイヤー) から (敵) への角度) にする)
    (10) 歩動かす
  でなければ
    // プレイヤーが遠くにいる場合は、何もしない
  end
end
```

このスクリプトでは、敵キャラクターはまずプレイヤーの方向を向き、その後、その方向に一定距離移動します。これにより、より自然な動きでプレイヤーを追いかけるようになります。

#### 応用例とユースケース

この基本的な追跡AIは、様々なゲームに応用できます。例えば、

*   **鬼ごっこゲーム:** 敵キャラクターが鬼役となり、プレイヤーを追いかける。
*   **シューティングゲーム:** 敵キャラクターがプレイヤーに向かって弾を発射する。
*   **パズルゲーム:** 敵キャラクターが特定のルートを巡回し、プレイヤーの邪魔をする。

#### トラブルシューティング

*   **敵キャラクターが壁を通り抜けてしまう:** 敵キャラクターが壁にぶつかった際に、移動を停止させる処理を追加する必要があります。
*   **敵キャラクターの動きがぎこちない:** 移動速度を調整したり、移動方法を工夫したりすることで、より自然な動きにすることができます。
*   **敵キャラクターがプレイヤーに近づきすぎると止まってしまう:** 敵キャラクターとプレイヤーとの間に一定の距離を保つように、移動処理を調整する必要があります。

#### まとめと次のステップ

このセクションでは、AIの基本的な考え方と、Scratchで簡単な追跡AIを実装する方法を学びました。次のセクションでは、敵キャラクターの動きをより複雑にし、状況に応じて行動を変化させるAIを実装していきます。

### 4.2 敵の動きをデザインする - パターン認識と行動選択

#### 概要と重要性

前のセクションでは、敵キャラクターがプレイヤーを追いかけるという単純なAIを実装しました。このセクションでは、敵キャラクターに「パターン認識」と「行動選択」の能力を与え、状況に応じて賢く行動するように進化させます。これにより、ゲームの難易度を調整したり、より面白いゲーム体験を提供したりすることができます。

#### 特徴と利点

パターン認識と行動選択を実装することで、敵キャラクターは単にプレイヤーを追いかけるだけでなく、自分の体力やプレイヤーとの距離などの情報を基に、攻撃、防御、逃走などの様々な行動を選択できるようになります。これにより、敵キャラクターはより手ごわい存在になり、ゲームの面白さが向上します。

#### 事前準備と前提条件

このセクションでは、前セクションで作成した追跡AIをベースに、敵キャラクターに体力や攻撃力などのパラメータを追加し、これらのパラメータを基に行動を決定する処理を実装します。

#### 基本的な使い方

*   **パターン認識:** 敵キャラクターが置かれている状況を把握します。具体的には、プレイヤーとの距離、敵の体力、敵の攻撃力などの情報を収集します。
*   **行動選択:** 収集した情報を基に、敵キャラクターがどのような行動を取るかを決定します。例えば、プレイヤーとの距離が近い場合は攻撃、体力が低い場合は逃走、などです。

Scratchでは、「もし～なら」ブロックを使って、これらの条件分岐を表現します。

#### 実装例：敵キャラクターが状況に応じて行動を変化させるAIを実装

敵キャラクターに、以下の3つの行動を追加してみましょう。

1.  **攻撃:** プレイヤーとの距離が近い場合に実行。
2.  **防御:** 敵の体力が低い場合に実行。
3.  **逃走:** 敵の体力が非常に低い場合に実行。

まず、敵キャラクターに以下の変数とリストを追加します。

*   **変数:**
    *   体力: 敵キャラクターの現在の体力。
    *   攻撃力: 敵キャラクターの攻撃力。
    *   防御力: 敵キャラクターの防御力。
*   **リスト:**
    *   行動パターン: 敵キャラクターが実行可能な行動を格納するリスト (例: "攻撃", "防御", "逃走")。
    *   行動優先度: 各行動パターンの優先度を格納するリスト (例: 攻撃の優先度, 防御の優先度, 逃走の優先度)。

次に、敵キャラクターに以下のスクリプトを追加します。

```scratch
ずっと
  もし <(体力) > (50)> なら
    もし <(距離 (敵) から (プレイヤー) まで) < (50)> なら
      (プレイヤーを攻撃する) // 攻撃行動を実行するカスタムブロック
    でなければ
      (プレイヤーを追跡する) // 前セクションで作成した追跡AI
    end
  でなければ
    もし <(体力) > (20)> なら
      (防御する) // 防御行動を実行するカスタムブロック
    でなければ
      (逃走する) // 逃走行動を実行するカスタムブロック
    end
  end
end
```

このスクリプトは、敵キャラクターの体力とプレイヤーとの距離を監視し、それぞれの状況に応じて異なる行動を実行します。

**カスタムブロックの定義例:**

*   **プレイヤーを攻撃する:**

```scratch
定義 プレイヤーを攻撃する
  もし <(タイマー) - (最後の攻撃時間) > (2)> なら // 攻撃間隔を設定
    (プレイヤーの体力を (攻撃力) ずつ変える)
    (最後の攻撃時間を (タイマー) にする)
    (「攻撃！」と言う (2) 秒)
  end
```

*   **防御する:**

```scratch
定義 防御する
  (防御力を (2) ずつ増やす)
  (3) 秒待つ
  (防御力を (2) ずつ減らす)
```

*   **逃走する:**

```scratch
定義 逃走する
  (向きを ((プレイヤー) から (敵) への角度 + (180)) にする) // プレイヤーと反対方向を向く
  (10) 歩動かす
```

#### 実践的なテクニック

行動優先度リストを利用することで、より複雑な行動選択ロジックを実装できます。例えば、敵キャラクターの体力とプレイヤーとの距離だけでなく、時間帯やプレイヤーの行動パターンなども考慮して行動を決定することができます。

#### 応用例とユースケース

このパターン認識と行動選択のAIは、様々なゲームに応用できます。

*   **RPG:** 敵キャラクターが、プレイヤーのレベルや装備に応じて、攻撃方法や防御方法を変化させる。
*   **ストラテジーゲーム:** 敵ユニットが、自軍の資源状況や敵ユニットの配置に応じて、攻撃目標や移動ルートを決定する。
*   **シミュレーションゲーム:** NPCキャラクターが、自分の欲求や周囲の状況に応じて、行動を決定する。

#### トラブルシューティング

*   **敵キャラクターが同じ行動ばかり繰り返す:** 行動選択のロジックに偏りがないか確認し、各行動の優先度を調整する必要があります。
*   **敵キャラクターの行動が予測可能すぎる:** 行動選択にランダム性を取り入れることで、敵キャラクターの行動を予測しにくくすることができます。
*   **敵キャラクターの行動が不自然:** 行動選択のロジックを見直し、より自然な行動パターンになるように調整する必要があります。

#### まとめと次のステップ

このセクションでは、敵キャラクターにパターン認識と行動選択の能力を与え、状況に応じて賢く行動するように進化させました。次のセクションでは、強化学習の概念を導入し、敵キャラクターが試行錯誤しながら最適な行動を学習するAIを実装していきます。

### 4.3 強化学習への扉 - 未来のAIプログラマーを目指して

#### 概要と重要性

これまでのセクションでは、敵キャラクターの行動を事前にプログラミングしていましたが、このセクションでは、敵キャラクター自身が経験を通して最適な行動を学習する「強化学習」の概念を導入します。強化学習は、ゲームAIだけでなく、ロボット制御、自動運転、金融など、様々な分野で応用されている最先端のAI技術です。

#### 特徴と利点

強化学習を導入することで、敵キャラクターは、開発者が事前に想定していなかったような行動パターンを学習したり、ゲームの進行に合わせて柔軟に行動を変化させたりすることができます。これにより、ゲームの難易度を自動的に調整したり、より個性的な敵キャラクターを作り出すことができます。

#### 事前準備と前提条件

このセクションでは、前セクションで作成した行動選択AIをベースに、敵キャラクターに報酬を与える仕組みを導入し、報酬を最大化するように行動を学習させる処理を実装します。

#### 基本的な使い方

強化学習の基本的な概念は、以下の3つです。

*   **状態:** キャラクターが置かれている状況を表します。（例：プレイヤーとの距離、敵の体力）
*   **行動:** キャラクターが取りうる行動を表します。（例：攻撃、防御、逃走）
*   **報酬:** キャラクターの行動に対する評価を表します。（例：プレイヤーを攻撃してダメージを与えたら報酬を与える、体力が減ったら報酬を減らす）

強化学習アルゴリズムは、キャラクターが様々な行動を試行錯誤し、最も多くの報酬を得られるように行動を学習していきます。

#### 実装例：敵キャラクターが試行錯誤しながら最適な行動を学習するAIを実装

最も単純な強化学習アルゴリズムである「Q学習」をScratchで実装してみましょう。

1.  **Q値テーブルの作成:** 各状態と行動の組み合わせに対する「Q値」を格納するテーブルを作成します。Scratchでは、このテーブルをリストで表現します。Q値とは、ある状態で特定の行動を取った場合に、将来的にどれだけの報酬が得られるかの期待値です。
2.  **状態の定義:** 敵キャラクターの状態を定義します。ここでは、簡単のため、プレイヤーとの距離と敵の体力の2つのパラメータを離散化し、状態を表現します。
3.  **行動の定義:** 敵キャラクターが取りうる行動を定義します。（例：攻撃、防御、逃走）
4.  **報酬の定義:** 各行動に対する報酬を定義します。例えば、プレイヤーを攻撃してダメージを与えた場合は報酬+1、体力が減った場合は報酬-1、などです。
5.  **Q値の更新:** 敵キャラクターが行動するたびに、Q値を更新します。Q値の更新式は以下の通りです。

    ```
    Q(s, a) = Q(s, a) + α * (R + γ * max(Q(s', a')) - Q(s, a))
    ```

    *   Q(s, a): 状態sで行動aを取った場合のQ値
    *   α: 学習率（0から1の間の値）
    *   R: 行動aを取った結果得られた報酬
    *   γ: 割引率（0から1の間の値）
    *   s': 次の状態
    *   a': 次の状態s'で最も高いQ値を持つ行動

ScratchでQ学習を実装するスクリプトは以下のようになります。

```scratch
// 初期設定
(学習率を (0.1) にする)
(割引率を (0.9) にする)

// Q値テーブルの初期化
(状態リスト) を作成する
(行動リスト) を作成する
(Q値テーブル) を作成する // 各状態と行動の組み合わせに対するQ値を格納するリスト

// 状態の定義 (例: プレイヤーとの距離、敵の体力)
定義 現在の状態を決定する
  (プレイヤーとの距離 (distance) を計算する)
  (敵の体力 (health) を取得する)
  // 距離と体力を離散化して状態IDを生成
  (状態ID) を (distance) + (health) にする  // 例: 簡略化のため、距離と体力の合計を状態IDとする

// 行動の定義 (例: 攻撃、防御、逃走)
定義 行動を選択する
  (ε-greedy法で行動を選択する) // εの確率でランダムな行動を選択し、(1-ε)の確率でQ値が最大の行動を選択する
  // (ε) の確率でランダムな行動を選択
  もし <(乱数 (1) から (100) まで) < (ε * (100))> なら
    (ランダムな行動) を選択する
  でなければ
    // Q値が最大の行動を選択
    (Q値が最大の行動) を選択する
  end

// 報酬の定義
定義 報酬を与える
  // 行動に応じて報酬を設定
  もし <(選択された行動) = (攻撃)> なら
    もし <(プレイヤーにダメージを与えた)> なら
      (報酬) を (1) にする
    でなければ
      (報酬) を (-0.1) にする // 攻撃が当たらなかった場合はペナルティ
    end
  でなければ
    もし <(選択された行動) = (防御)> なら
      もし <(敵がダメージを受けた)> なら
        (報酬) を (-0.5) にする // 防御に失敗した場合はペナルティ
      でなければ
        (報酬) を (0.2) にする  // 防御に成功した場合は報酬
      end
    でなければ
       // ... 他の行動に対する報酬を設定
    end
  end

// Q値の更新
定義 Q値を更新する
  (新しいQ値) を ((現在のQ値) + ((学習率) * ((報酬) + ((割引率) * (次の状態で最大のQ値)) - (現在のQ値)))) にする)
  // Q値テーブルを更新
  (Q値テーブルの(現在の状態ID)番目を(新しいQ値)で置き換える)

// メインループ
ずっと
  (現在の状態を決定する)
  (行動を選択する)
  (行動を実行する)
  (報酬を与える)
  (Q値を更新する)
end
```

#### 実践的なテクニック

*   **ε-greedy法:** 行動選択にε-greedy法を用いることで、探索と利用のバランスを取ることができます。ε-greedy法とは、εの確率でランダムな行動を選択し、(1-ε)の確率でQ値が最大の行動を選択する方法です。
*   **状態の離散化:** 連続値である状態を離散化することで、Q値テーブルのサイズを小さくすることができます。
*   **報酬の設計:** 適切な報酬を設計することで、敵キャラクターに望ましい行動を学習させることができます。

#### 応用例とユースケース

強化学習は、様々なゲームAIに応用できます。

*   **対戦ゲーム:** 敵キャラクターが、プレイヤーの行動パターンを学習し、最適な戦略を導き出す。
*   **シミュレーションゲーム:** NPCキャラクターが、環境の変化に適応し、最適な行動を学習する。
*   **パズルゲーム:** AIが、ゲームのルールを学習し、最適な解法を見つけ出す。

#### トラブルシューティング

*   **敵キャラクターが全く学習しない:** 学習率や割引率が適切でない可能性があります。これらのパラメータを調整してみてください。
*   **敵キャラクターが不安定な行動をする:** 報酬の設計が適切でない可能性があります。報酬を見直してみてください。
*   **学習に時間がかかりすぎる:** 状態の離散化の粒度を粗くしたり、Q値テーブルのサイズを小さくしたりすることで、学習時間を短縮することができます。

#### まとめと次のステップ
