## 第15章：パフォーマンス最適化 - より滑らかな動作のために

Three.jsで作成したWebアプリケーションが、思い通りに滑らかに動かない…それはよくある悩みです。しかし、諦める必要はありません。本書で学んだ知識を応用し、さらにこれから紹介するパフォーマンス最適化のテクニックを駆使することで、見違えるようにスムーズな動作を実現できます。

この章では、Three.jsアプリケーションのパフォーマンスを改善するための具体的な方法を、レンダリング負荷、GPU負荷、ブラウザ側の最適化という3つの視点から解説します。コードスニペットや設定例を交えながら、段階的に理解を深められるように構成しました。

### レンダリング負荷の削減

レンダリング負荷とは、CPUが処理しなければならないオブジェクトの数や複雑さを指します。ここを改善することで、フレームレートの向上に大きく貢献できます。

**1. オブジェクト数の削減**

*   **概要と重要性**: シーン内のオブジェクト数が多いほど、描画処理に時間がかかります。特に、大量のオブジェクトを表示する必要がある場合に重要です。
*   **特徴と利点**: オブジェクト数を減らすことで、CPU負荷を直接的に軽減し、描画速度を向上させます。
*   **事前準備と前提条件**: シーン内のオブジェクト構成を理解している必要があります。
*   **基本的な使い方**:

    *   **オブジェクトの統合**: 複数のオブジェクトを単一のオブジェクトに統合します。例えば、多数のキューブで構成された建物を、一つのメッシュに統合することができます。

        ```javascript
        // 例：複数のキューブをマージして一つのジオメトリにする
        const geometry = new THREE.Geometry();
        for (let i = 0; i < cubes.length; i++) {
            cubes[i].updateMatrix();
            geometry.merge(cubes[i].geometry, cubes[i].matrix);
        }
        const material = new THREE.MeshBasicMaterial({color: 0xff0000});
        const mergedMesh = new THREE.Mesh(geometry, material);
        scene.add(mergedMesh);

        // 元のキューブは削除
        cubes.forEach(cube => scene.remove(cube));
        ```
    *   **インスタンス化**: 同じジオメトリを複数回使用する場合、`InstancedMesh`を使用します。これにより、メモリ使用量を削減し、レンダリング効率を向上させます。

        ```javascript
        // 例：インスタンスメッシュの使用
        const geometry = new THREE.BoxGeometry(1, 1, 1);
        const material = new THREE.MeshBasicMaterial({color: 0x00ff00});
        const count = 1000;
        const mesh = new THREE.InstancedMesh(geometry, material, count);

        for (let i = 0; i < count; i++) {
            const matrix = new THREE.Matrix4();
            // ランダムな位置に配置
            matrix.setPosition(Math.random() * 10, Math.random() * 10, Math.random() * 10);
            mesh.setMatrixAt(i, matrix);
        }
        scene.add(mesh);
        ```
*   **実践的なテクニック**:

    *   **LOD (Level of Detail)**: カメラからの距離に応じて、オブジェクトのディテールレベルを切り替えます。遠くのオブジェクトは、より単純なモデルを使用することで、レンダリング負荷を軽減できます。

        ```javascript
        // 例：LODの実装
        const lod = new THREE.LOD();

        // 高精細モデル
        const highDetailGeometry = new THREE.SphereGeometry(1, 32, 32);
        const highDetailMesh = new THREE.Mesh(highDetailGeometry, material);
        lod.addLevel(highDetailMesh, 0); // 距離0から表示

        // 低精細モデル
        const lowDetailGeometry = new THREE.SphereGeometry(1, 8, 8);
        const lowDetailMesh = new THREE.Mesh(lowDetailGeometry, material);
        lod.addLevel(lowDetailMesh, 20); // 距離20から表示

        lod.position.set(0, 0, -10);
        scene.add(lod);
        ```

*   **応用例とユースケース**: 大規模な都市景観や森林などのレンダリングに有効です。
*   **トラブルシューティング**: LODの切り替えが不自然にならないように、適切な距離を設定することが重要です。
*   **まとめと次のステップ**: オブジェクト数の削減は、パフォーマンス最適化の基本です。次のステップでは、ジオメトリの最適化について学びます。

**2. ジオメトリの最適化 (BufferGeometryの共有)**

*   **概要と重要性**: ジオメトリデータは、メモリと処理能力を大量に消費します。特に、同じ形状を繰り返し使用する場合、ジオメトリを共有することで大幅な最適化が可能です。
*   **特徴と利点**: メモリ使用量を削減し、描画速度を向上させます。`BufferGeometry`の共有は、Three.jsにおける基本的な最適化手法です。
*   **事前準備と前提条件**: 同じ形状のオブジェクトが複数存在すること。
*   **基本的な使い方**:

    ```javascript
    // 例：BufferGeometryの共有
    const geometry = new THREE.BoxGeometry(1, 1, 1);
    const material = new THREE.MeshBasicMaterial({color: 0xff0000});

    const mesh1 = new THREE.Mesh(geometry, material);
    const mesh2 = new THREE.Mesh(geometry, material);
    const mesh3 = new THREE.Mesh(geometry, material);

    mesh1.position.set(-2, 0, 0);
    mesh2.position.set(0, 0, 0);
    mesh3.position.set(2, 0, 0);

    scene.add(mesh1);
    scene.add(mesh2);
    scene.add(mesh3);
    ```

    この例では、`BoxGeometry`を3つのメッシュで共有しています。これにより、ジオメトリデータを一度だけメモリにロードすればよいため、メモリ使用量を削減できます。

*   **実践的なテクニック**:

    *   **ジオメトリの簡略化**: `SimplifyModifier`などを使用して、オブジェクトの形状を維持しつつ、ポリゴン数を削減します。
        ```javascript
        // 例：SimplifyModifierの使用
        const modifier = new THREE.SimplifyModifier();
        const simplifiedGeometry = modifier.modify(geometry, 0.5); // ポリゴン数を50%削減
        const mesh = new THREE.Mesh(simplifiedGeometry, material);
        scene.add(mesh);
        ```

*   **応用例とユースケース**: 同じ形状のオブジェクトが多数存在するゲームや、建築ビジュアライゼーションなどで有効です。
*   **トラブルシューティング**: ジオメトリを共有すると、一つのメッシュを変更すると、共有しているすべてのメッシュに影響が及ぶことに注意が必要です。必要に応じて、`geometry.clone()`を使用して、独立したジオメトリを作成します。
*   **まとめと次のステップ**: ジオメトリの最適化は、メモリ使用量を削減し、パフォーマンスを向上させる効果的な手段です。次のステップでは、不要なテクスチャの削除について学びます。

**3. 不要なテクスチャの削除**

*   **概要と重要性**: テクスチャは、オブジェクトの見た目を豊かにするために不可欠ですが、解像度が高すぎたり、不要なテクスチャを使用したりすると、メモリを圧迫し、パフォーマンスを低下させる可能性があります。
*   **特徴と利点**: メモリ使用量を削減し、テクスチャのロード時間を短縮します。
*   **事前準備と前提条件**: シーン内のテクスチャ使用状況を把握している必要があります。
*   **基本的な使い方**:

    *   **テクスチャの解像度調整**: オブジェクトのサイズやカメラからの距離に応じて、適切な解像度のテクスチャを使用します。必要以上に高解像度のテクスチャを使用しないように注意してください。

        ```javascript
        // 例：テクスチャのロードと解像度調整
        const textureLoader = new THREE.TextureLoader();
        textureLoader.load('texture.jpg', function (texture) {
            texture.minFilter = THREE.LinearMipmapLinearFilter; // ミップマップを使用
            texture.generateMipmaps = true; // ミップマップを生成
            const material = new THREE.MeshBasicMaterial({map: texture});
            const mesh = new THREE.Mesh(geometry, material);
            scene.add(mesh);
        });
        ```
    *   **テクスチャアトラス**: 複数の小さなテクスチャを1つの大きなテクスチャにまとめることで、テクスチャのロード回数を減らし、パフォーマンスを向上させます。

*   **実践的なテクニック**:

    *   **テクスチャ圧縮**: DDSやPVRTCなどの圧縮形式を使用することで、テクスチャのファイルサイズを削減し、ロード時間を短縮します。Three.jsでは、`THREE.DDSLoader`や`THREE.PVRLoader`を使用して、これらの形式のテクスチャをロードできます。
    *   **データURLの利用を避ける**: データURLはファイルサイズが大きくなりやすく、パフォーマンスに悪影響を与える可能性があります。できる限り、外部ファイルとしてテクスチャをロードするようにしましょう。

*   **応用例とユースケース**: モバイルデバイス向けのゲームや、テクスチャを多用するアプリケーションなどで有効です。
*   **トラブルシューティング**: テクスチャの解像度を下げすぎると、オブジェクトの見た目が損なわれる可能性があります。適切な解像度を見つけるために、試行錯誤が必要です。
*   **まとめと次のステップ**: 不要なテクスチャの削除は、メモリ使用量を削減し、パフォーマンスを向上させるために重要なステップです。次のステップでは、GPUの負荷軽減について学びます。

### GPUの負荷軽減

GPUは、グラフィック処理の中核を担うプロセッサです。GPUの負荷が高すぎると、フレームレートが低下し、カクつきの原因となります。

**1. シャドウの最適化 (シャドウマップの解像度調整)**

*   **概要と重要性**: シャドウは、シーンにリアリティを与えるために重要な要素ですが、シャドウマップの解像度が高すぎると、GPUに大きな負荷がかかります。
*   **特徴と利点**: シャドウマップの解像度を下げることで、GPU負荷を軽減し、フレームレートを向上させます。
*   **事前準備と前提条件**: シーンにシャドウを適用していること。
*   **基本的な使い方**:

    ```javascript
    // 例：シャドウマップの解像度調整
    renderer.shadowMap.enabled = true; // シャドウを有効にする
    renderer.shadowMap.type = THREE.PCFSoftShadowMap; // ソフトシャドウを使用

    // ライトの設定
    const light = new THREE.DirectionalLight(0xffffff, 1);
    light.position.set(1, 1, 1);
    light.castShadow = true; // シャドウを生成する
    light.shadow.mapSize.width = 512; // シャドウマップの幅
    light.shadow.mapSize.height = 512; // シャドウマップの高さ
    light.shadow.camera.near = 0.5;
    light.shadow.camera.far = 500;
    scene.add(light);
    ```

    `light.shadow.mapSize.width`と`light.shadow.mapSize.height`で、シャドウマップの解像度を調整できます。値を小さくするほど、GPU負荷は軽減されますが、シャドウの品質は低下します。

*   **実践的なテクニック**:

    *   **シャドウの種類の選択**: Three.jsでは、`THREE.BasicShadowMap`、`THREE.PCFShadowMap`、`THREE.PCFSoftShadowMap`など、さまざまな種類のシャドウマップを使用できます。`THREE.BasicShadowMap`は最も高速ですが、品質は最も低いです。`THREE.PCFSoftShadowMap`は最も高品質ですが、GPU負荷は最も高くなります。シーンの要件に応じて、適切な種類のシャドウマップを選択してください。
    *   **シャドウの表示範囲の調整**: `light.shadow.camera.near`と`light.shadow.camera.far`で、シャドウの表示範囲を調整できます。範囲を狭めるほど、シャドウマップの解像度を高く保つことができます。
    *   **シャドウを受けないオブジェクトの設定**: シャドウを生成する必要のないオブジェクトは、`mesh.receiveShadow = false`を設定することで、シャドウの計算をスキップできます。

*   **応用例とユースケース**: 大規模な屋外シーンや、複数のライトを使用するシーンなどで有効です。
*   **トラブルシューティング**: シャドウマップの解像度を下げすぎると、シャドウが粗くなる可能性があります。適切な解像度を見つけるために、試行錯誤が必要です。
*   **まとめと次のステップ**: シャドウの最適化は、GPU負荷を軽減し、パフォーマンスを向上させるために重要なステップです。次のステップでは、ポストエフェクトの調整について学びます。

**2. ポストエフェクトの調整**

*   **概要と重要性**: ポストエフェクトは、レンダリングされた画像に様々な視覚効果を加えることができますが、処理負荷が高く、パフォーマンスに大きな影響を与える可能性があります。
*   **特徴と利点**: ポストエフェクトの設定を調整することで、GPU負荷を軽減し、フレームレートを向上させます。
*   **事前準備と前提条件**: シーンにポストエフェクトを適用していること。`EffectComposer`などのライブラリを使用している場合は、その設定も理解している必要があります。
*   **基本的な使い方**:

    ```javascript
    // 例：EffectComposerの設定
    const composer = new THREE.EffectComposer(renderer);
    composer.addPass(new THREE.RenderPass(scene, camera));

    // グレースケールエフェクト
    const effectGrayScale = new THREE.ShaderPass(THREE.LuminosityShader);
    composer.addPass(effectGrayScale);

    // ブラーエフェクト
    const effectBlur = new THREE.ShaderPass(THREE.GaussianBlurShader);
    effectBlur.uniforms[ "h" ].value = 1.0 / 512;
    effectBlur.uniforms[ "v" ].value = 1.0 / 512;
    composer.addPass(effectBlur);
    ```

*   **実践的なテクニック**:

    *   **ポストエフェクトの種類の選択**: 使用するポストエフェクトの種類によって、GPU負荷は大きく異なります。例えば、ブラーエフェクトは、比較的負荷の高いエフェクトです。シーンの要件に応じて、必要なエフェクトのみを使用するようにしましょう。
    *   **エフェクトのパラメータ調整**: ポストエフェクトには、様々なパラメータがあります。これらのパラメータを調整することで、エフェクトの品質を下げずに、GPU負荷を軽減できる場合があります。例えば、ブラーエフェクトの半径を小さくしたり、サンプル数を減らしたりすることができます。
    *   **レンダーターゲットの解像度調整**: `EffectComposer`で使用するレンダーターゲットの解像度を下げることで、GPU負荷を軽減できます。ただし、解像度を下げすぎると、画質が低下する可能性があります。

*   **応用例とユースケース**: 映画のような雰囲気を出したい場合や、特定の視覚効果を強調したい場合などに使用されます。
*   **トラブルシューティング**: ポストエフェクトを多用すると、パフォーマンスが著しく低下する可能性があります。必要なエフェクトのみを使用し、パラメータを適切に調整することが重要です。
*   **まとめと次のステップ**: ポストエフェクトの調整は、GPU負荷を軽減し、パフォーマンスを向上させるために重要なステップです。次のステップでは、シェーダーの最適化について学びます。

**3. シェーダーの最適化**

*   **概要と重要性**: シェーダーは、GPU上で実行されるプログラムであり、オブジェクトの見た目を決定します。複雑なシェーダーを使用すると、GPUに大きな負荷がかかり、パフォーマンスが低下する可能性があります。
*   **特徴と利点**: シェーダーのコードを最適化することで、GPU負荷を軽減し、フレームレートを向上させます。
*   **事前準備と前提条件**: GLSL (OpenGL Shading Language) の知識が必要です。カスタムシェーダーを使用している場合は、そのコードを理解している必要があります。
*   **基本的な使い方**:

    *   **不要な計算の削除**: シェーダー内で不要な計算を行っていないか確認します。例えば、使用されていない変数の計算や、常に同じ値を返す関数の呼び出しなどを削除することができます。
    *   **複雑な処理の簡略化**: 複雑な処理を、より単純な処理に置き換えることができる場合があります。例えば、`pow()`関数は、比較的負荷の高い関数です。可能な限り、乗算で代替するようにしましょう。
    *   **条件分岐の削減**: シェーダー内で条件分岐を多用すると、GPUの並列処理能力を十分に活かせない場合があります。可能な限り、条件分岐を削減するようにしましょう。

*   **実践的なテクニック**:

    *   **ローカル変数とグローバル変数の使い分け**: ローカル変数は、グローバル変数よりも高速にアクセスできます。頻繁に使用する変数は、ローカル変数として宣言するようにしましょう。
    *   **vec3とvec4の使い分け**: 不要な要素を持つベクトルを使用しないようにしましょう。例えば、色を表現する場合は、`vec3` (RGB) で十分な場合、`vec4` (RGBA) を使用する必要はありません。
    *   **シェーダーコンパイラの最適化オプションの利用**: Three.jsでは、シェーダーコンパイラの最適化オプションを利用することができます。`renderer.compile()`メソッドを使用すると、シェーダーを事前にコンパイルし、実行時のパフォーマンスを向上させることができます。

*   **応用例とユースケース**: 特殊なマテリアルやエフェクトを実装する場合に、シェーダーの最適化が重要になります。
*   **トラブルシューティング**: シェーダーのコードを誤って変更すると、オブジェクトの見た目が崩れる可能性があります。変更を行う前に、必ずバックアップを作成するようにしましょう。
*   **まとめと次のステップ**: シェーダーの最適化は、GPU負荷を軽減し、パフォーマンスを向上させるために重要なステップです。次のステップでは、ブラウザの最適化について学びます。

### ブラウザの最適化

ブラウザは、Webアプリケーションを実行するプラットフォームです。ブラウザ側の最適化を行うことで、Three.jsアプリケーションのパフォーマンスをさらに向上させることができます。

**1. requestAnimationFrameの適切な利用**

*   **概要と重要性**: `requestAnimationFrame`は、ブラウザの描画サイクルに合わせて関数を呼び出すためのAPIです。これを使用することで、スムーズなアニメーションを実現し、CPU負荷を軽減することができます。
*   **特徴と利点**: ブラウザの描画サイクルに同期してアニメーションを行うため、無駄なレンダリングを避け、パフォーマンスを向上させます。
*   **事前準備と前提条件**: アニメーションループを実装していること。
*   **基本的な使い方**:

    ```javascript
    // 例：requestAnimationFrameの使用
    function animate() {
        requestAnimationFrame(animate);

        // シーンの更新処理
        cube.rotation.x += 0.01;
        cube.rotation.y += 0.01;

        renderer.render(scene, camera);
    }

    animate();
    ```

    `requestAnimationFrame(animate)`は、ブラウザに`animate`関数を次の描画サイクルで実行するように指示します。`animate`関数内では、シーンの更新処理とレンダリング処理を行います。

*   **実践的なテクニック**:

    *   **setIntervalやsetTimeoutの代替**: `setInterval`や`setTimeout`を使用する代わりに、`requestAnimationFrame`を使用するようにしましょう。`setInterval`や`setTimeout`は、ブラウザの描画サイクルとは無関係に実行されるため、無駄なレンダリングが発生する可能性があります。
    *   **非表示タブでのアニメーション停止**: ブラウザのタブが非表示になっている場合は、アニメーションを停止することで、CPU負荷を軽減することができます。`document.hidden`プロパティを使用して、タブの状態を監視することができます。

*   **応用例とユースケース**: すべてのアニメーション処理に使用されます。
*   **トラブルシューティング**: `requestAnimationFrame`を使用しても、アニメーションがカクつく場合は、他の最適化手法を検討する必要があります。
*   **まとめと次のステップ**: `requestAnimationFrame`の適切な利用は、ブラウザ側の最適化の基本です。次のステップでは、メモリリークの防止について学びます。

**2. メモリリークの防止**

*   **概要と重要性**: メモリリークとは、不要になったメモリが解放されずに、プログラムがメモリを使い続ける状態です。メモリリークが発生すると、アプリケーションのパフォーマンスが徐々に低下し、最終的にはクラッシュする可能性があります。
*   **特徴と利点**: メモリリークを防止することで、アプリケーションの安定性を向上させ、パフォーマンスを維持することができます。
*   **事前準備と前提条件**: JavaScriptのメモリ管理の基本を理解している必要があります。
*   **基本的な使い方**:

    *   **イベントリスナーの解除**: 不要になったイベントリスナーは、必ず解除するようにしましょう。

        ```javascript
        // 例：イベントリスナーの解除
        const button = document.getElementById('myButton');
        function handleClick() {
            console.log('Button clicked');
        }
        button.addEventListener('click', handleClick);

        // イベントリスナーの解除
        button.removeEventListener('click', handleClick);
        ```
    *   **オブジェクトの破棄**: 不要になったオブジェクトは、`dispose()`メソッドを呼び出して、メモリから解放するようにしましょう。特に、`Geometry`、`Material`、`Texture`などのThree.jsオブジェクトは、`dispose()`メソッドを呼び出す必要があります。

        ```javascript
        // 例：オブジェクトの破棄
        geometry.dispose();
        material.dispose();
        texture.dispose();
        ```
    *   **循環参照の回避**: オブジェクトが互いに参照し合う循環参照が発生すると、ガベージコレクションが正しく機能せず、メモリリークが発生する可能性があります。循環参照が発生しないように、オブジェクトの参照関係を注意深く管理する必要があります。

*   **実践的なテクニック**:

    *   **メモリプロファイラの利用**: ブラウザの開発者ツールには、メモリプロファイラが搭載されています。これを使用すると、メモリの使用状況を監視し、メモリリークの原因を特定することができます。
    *   **厳格モードの利用**: JavaScriptの厳格モード (`"use strict";`) を使用すると、潜在的なエラーを早期に発見することができます。

*   **応用例とユースケース**: 長時間動作するアプリケーションや、大量のデータを扱うアプリケーションで、メモリリークの防止が重要になります。
*   **トラブルシューティング**: メモリリークが発生した場合、原因の特定が難しい場合があります。メモリプロファイラを使用し、メモリの使用状況を注意深く監視する必要があります。
*   **まとめと次のステップ**: メモリリークの防止は、アプリケーションの安定性を維持するために不可欠です。次のステップでは、ガベージコレクションの最適化について学びます。

**3. ガベージコレクションの最適化**

*   **概要と重要性**: ガベージコレクションは、不要になったメモリを自動的に解放する仕組みです。しかし、ガベージコレクションが頻繁に実行されると、アプリケーションのパフォーマンスが低下する可能性があります。
*   **特徴と利点**: ガベージコレクションの実行頻度を減らすことで、アプリケーションのパフォーマンスを向上させることができます。
*   **事前準備と前提条件**: JavaScriptのガベージコレクションの仕組みを理解している必要があります。
*   **基本的な使い方**:

    *   **オブジェクトの再利用**: 新しいオブジェクトを頻繁に作成する代わりに、既存のオブジェクトを再利用するようにしましょう。

        ```javascript
        // 例：オブジェクトの再利用
        const vector = new THREE.Vector3();
        function updatePosition() {
            // 新しいベクトルを作成する代わりに、既存のベクトルを再利用する
            vector.set(Math.random(), Math.random(), Math.random());
            object.position.copy(vector);
        }
        ```
    *   **オブジェクトプーリング**: 大量のオブジェクトを頻繁に作成および破棄する必要がある場合は、オブジェクトプーリングを使用することで、ガベージコレクションの実行頻度を減らすことができます。オブジェクトプーリングは、事前にオブジェクトを作成しておき、必要に応じて再利用するテクニックです。

*   **実践的なテクニック**:

    *   **大きなオブジェクトの分割**: 大きなオブジェクトを扱う場合、オブジェクトを分割して、必要な部分だけを更新するようにしましょう。これにより、ガベージコレクションの対象となるメモリの量を減らすことができます。
    *   **不要なオブジェクトの早期破棄**: オブジェクトが不要になったら、できるだけ早く破棄するようにしましょう。

*   **応用例とユースケース**: 大量のオブジェクトを扱うゲームや、リアルタイムデータ処理を行うアプリケーションで、ガベージコレクションの最適化が重要になります。
*   **トラブルシューティング**: ガベージコレクションの最適化は、アプリケーションのコード構造に大きく依存するため、一般的な解決策はありません。アプリケーションの特性に合わせて、最適な方法を検討する必要があります。
