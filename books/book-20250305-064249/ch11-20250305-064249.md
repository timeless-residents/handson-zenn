## 第11章：IoTプロトコル：LoRaWAN、Sigfox

### 11.1 LoRaWAN：長距離無線通信

#### 11.1.1 概要と重要性

LoRaWAN (Long Range Wide Area Network) は、バッテリー駆動のIoTデバイスが長距離にわたって少量データを効率的に送信できるように設計された無線通信プロトコルです。 スマートシティ、農業、産業モニタリングなど、広範囲に分散したセンサーネットワークを構築する上で非常に重要な役割を果たします。従来のセルラーネットワークと比較して、LoRaWANは低コスト、低消費電力、広いカバレッジ範囲を提供するため、IoTデバイスの接続において魅力的な選択肢となります。

#### 11.1.2 特徴と利点

LoRaWANには、他の無線通信技術と比較して、以下のような特徴と利点があります。

*   **長距離通信:** 数キロメートルから数十キロメートルに及ぶ通信範囲をサポートします。
*   **低消費電力:** バッテリー駆動のデバイスで数年間動作することを可能にします。
*   **双方向通信:** デバイスからネットワークへ、またネットワークからデバイスへの双方向通信をサポートします。
*   **セキュリティ:** AES暗号化によるセキュリティ機能を備えており、データの機密性と完全性を保護します。
*   **オープンスタンダード:** LoRa Allianceによって標準化されており、異なるベンダーのデバイス間の相互運用性を確保します。
*   **アダプティブ・データレート (ADR):** デバイスとゲートウェイ間の距離や電波状況に応じて、データレートを自動的に調整し、バッテリー寿命を最適化します。

#### 11.1.3 事前準備と前提条件

LoRaWANを利用するためには、以下の要素が必要です。

*   **LoRaWAN対応デバイス:** センサー、アクチュエータなど、LoRaWANプロトコルをサポートするデバイス。
*   **LoRaWANゲートウェイ:** デバイスからのLoRa信号を受信し、IPネットワークを介してLoRaWANネットワークサーバーに転送する役割を担います。
*   **LoRaWANネットワークサーバー:** デバイスの認証、データのルーティング、セキュリティ管理などを行います。多くの商用LoRaWANネットワークサーバーが存在し、The Things Network (TTN) のようなオープンソースのオプションもあります。
*   **アプリケーションサーバー:** ネットワークサーバーから受信したデータを処理し、アプリケーションに提供する役割を担います。

#### 11.1.4 基本的な使い方

LoRaWANデバイスをネットワークに接続する基本的な手順は以下の通りです。

1.  **デバイスの設定:** LoRaWANデバイスに、デバイスEUI (Extended Unique Identifier)、アプリケーションEUI、アプリケーションキーなどの認証情報を設定します。これらの情報は、デバイスの製造元から提供されます。
2.  **ゲートウェイの設置:** LoRaWANゲートウェイを、デバイスが通信可能な範囲に設置し、インターネットに接続します。ゲートウェイの設定は、メーカーの指示に従って行います。
3.  **ネットワークサーバーへの登録:** デバイスをLoRaWANネットワークサーバーに登録します。TTNのようなオープンソースのネットワークサーバーを利用する場合は、Webコンソールからデバイスを登録できます。
4.  **データの送受信:** デバイスからデータを送信し、アプリケーションサーバーで受信することを確認します。双方向通信をテストする場合は、アプリケーションサーバーからデバイスにコマンドを送信してみます。

**設定例 (The Things Networkを使用):**

1.  **TTNアカウントの作成:** The Things Networkのウェブサイトでアカウントを作成します。
2.  **アプリケーションの作成:** TTNコンソールで新しいアプリケーションを作成します。
3.  **デバイスの登録:** アプリケーションに新しいデバイスを登録し、デバイスEUI、アプリケーションEUI、アプリケーションキーを入力します。
4.  **ゲートウェイの接続:** TTNに接続されたLoRaWANゲートウェイが、あなたのデバイスの範囲内にあることを確認します。
5.  **データ送信のテスト:** デバイスからデータを送信し、TTNコンソールでデータが受信されることを確認します。

**コードスニペット (Arduino LoRaWANライブラリを使用):**

```cpp
#include <lmic.h>
#include <hal/hal.h>
#include <SPI.h>

// LoRaWAN NwkSKey, network session key
static const PROGMEM u1_t NWKSKEY[16] = { /* ネットワークセッションキー */ };

// LoRaWAN AppSKey, application session key
static const u1_t PROGMEM APPSKEY[16] = { /* アプリケーションセッションキー */ };

// LoRaWAN end-device address (DevAddr)
static const u4_t DEVADDR = 0x /* デバイスアドレス */;

// These callbacks are only used in over-the-air activation, so skip them
void os_getArtEui (u1_t* buf) { }
void os_getDevEui (u1_t* buf) { }
void os_getDevKey (u1_t* buf) { }

static osjob_t sendjob;

const unsigned TX_INTERVAL = 60;

void onEvent (ev_t ev) {
  Serial.print(os_getTime());
  Serial.print(": ");
  switch(ev) {
    case EV_SCAN_TIMEOUT:
      Serial.println(F("EV_SCAN_TIMEOUT"));
      break;
    case EV_BEACON_FOUND:
      Serial.println(F("EV_BEACON_FOUND"));
      break;
    case EV_BEACON_MISSED:
      Serial.println(F("EV_BEACON_MISSED"));
      break;
    case EV_BEACON_LOST:
      Serial.println(F("EV_BEACON_LOST"));
      break;
    case EV_JOINING:
      Serial.println(F("EV_JOINING"));
      break;
    case EV_JOINED:
      Serial.println(F("EV_JOINED"));
      break;
    case EV_RFU1:
      Serial.println(F("EV_RFU1"));
      break;
    case EV_JOIN_FAILED:
      Serial.println(F("EV_JOIN_FAILED"));
      break;
    case EV_REJOIN_FAILED:
      Serial.println(F("EV_REJOIN_FAILED"));
      break;
    case EV_TXCOMPLETE:
      Serial.println(F("EV_TXCOMPLETE (includes waiting for RX windows)"));
      if (LMIC.txrxFlags & TXRX_ACK)
        Serial.println(F("Received ack"));
      if (LMIC.dataLen) {
        Serial.println(F("Received "));
        Serial.println(LMIC.dataLen);
        Serial.println(F(" bytes of payload"));
      }
      os_setTimedCallback(&sendjob, os_getTime()+TX_INTERVAL, do_send);
      break;
    case EV_LOST_TSYNC:
      Serial.println(F("EV_LOST_TSYNC"));
      break;
    case EV_RESET:
      Serial.println(F("EV_RESET"));
      break;
    case EV_RXCOMPLETE:
      // data received in ping slot
      Serial.println(F("EV_RXCOMPLETE"));
      break;
    case EV_LINK_DEAD:
      Serial.println(F("EV_LINK_DEAD"));
      break;
    case EV_LINK_ALIVE:
      Serial.println(F("EV_LINK_ALIVE"));
      break;
    default:
      Serial.println(F("Unknown event"));
      break;
  }
}

void do_send(osjob_t* job) {
    // Check if there is not a current TX/RX job running
    if (LMIC.opmode & OP_TXRXPEND) {
        Serial.println(F("OP_TXRXPEND, not sending"));
    } else {
        // Prepare upstream data transmission at the next possible time.
        LMIC_setTxData2(1, "Hello", sizeof("Hello")-1, 0);
        Serial.println(F("Packet queued"));
    }
    // Next TX is scheduled after TX_COMPLETE event.
}

void setup() {
  Serial.begin(115200);
  Serial.println(F("Starting"));

  #ifdef VCC_ENABLE
  // For Pinoccio Scout:
  pinMode(VCC_ENABLE, OUTPUT);
  digitalWrite(VCC_ENABLE, HIGH);
  delay(1000);
  #endif

  // LMIC init
  os_init();
  // Reset the MAC state. Session and pending data transfers will be discarded.
  LMIC_reset();

  // Set static session parameters. Instead of dynamically establishing a session
  // by joining the network, precomputed session parameters are be provided.
  #ifdef PROGMEM
  // On AVR, these values are stored in flash memory (PROGMEM)
  memcpy_P(LMIC.nwkSKey, NWKSKEY, sizeof(NWKSKEY));
  #else
  memcpy(LMIC.nwkSKey, NWKSKEY, sizeof(NWKSKEY));
  #endif
  memcpy(LMIC.appSKey, APPSKEY, sizeof(APPSKEY));
  LMIC.devaddr = DEVADDR;

  // Disable link check validation
  LMIC_setLinkCheckMode(0);

  // TTN uses SF9 for its first DR
  LMIC_setDrTxpow(DR_SF9,14);

  // Set data rate and transmit power for uplink (note: txpow seems to be ignored by the library)
  //LMIC_setDrTxpow(DR_SF7,14);

  // Schedule a timed job to run at the next oportunity (os)
  os_setTimedCallback(&sendjob, os_getTime()+1, do_send);
}

void loop() {
    os_runloop_once();
}
```

#### 11.1.5 実践的なテクニック

*   **アンテナの最適化:** LoRaWANの通信範囲を最大化するために、アンテナの種類や設置場所を慎重に検討します。外部アンテナを使用することで、通信範囲を大幅に改善できる場合があります。
*   **ADRの活用:** アダプティブ・データレート (ADR) を有効にすることで、デバイスとゲートウェイ間の距離や電波状況に応じて、データレートを自動的に調整し、バッテリー寿命を最適化できます。
*   **ペイロードの最適化:** 送信するデータ量を最小限に抑えることで、バッテリー寿命を延ばし、ネットワークの負荷を軽減できます。データの圧縮やエンコーディングなどの技術を活用しましょう。
*   **ゲートウェイの冗長化:** 複数のゲートウェイを設置することで、ネットワークの信頼性を高め、単一障害点を排除できます。

#### 11.1.6 応用例とユースケース

*   **スマートシティ:** 街灯の制御、駐車場の監視、ゴミ箱の満杯状況の監視など。
*   **農業:** 土壌水分センサー、気温センサー、灌漑システムの制御など。
*   **産業モニタリング:** 機械の稼働状況の監視、設備の故障予測、在庫管理など。
*   **物流:** 貨物の追跡、温度管理、盗難防止など。
*   **環境モニタリング:** 大気汚染の監視、水質監視、森林火災の早期発見など。

**具体的なユースケース: スマート農業**

LoRaWANを利用したスマート農業では、畑に設置された土壌水分センサーや気温センサーからデータを収集し、灌漑システムを自動的に制御することができます。これにより、水資源の無駄を減らし、作物の収量を向上させることができます。また、肥料の散布量を最適化することで、環境負荷を軽減することも可能です。

#### 11.1.7 トラブルシューティング

*   **通信が確立できない:**
    *   デバイスの認証情報 (デバイスEUI、アプリケーションEUI、アプリケーションキー) が正しいことを確認します。
    *   ゲートウェイがインターネットに接続されていることを確認します。
    *   デバイスとゲートウェイ間の距離が適切であることを確認します。
    *   電波干渉がないか確認します。
*   **バッテリーの消耗が早い:**
    *   ADRが有効になっているか確認します。
    *   送信頻度を減らすことを検討します。
    *   ペイロードのサイズを最適化します。
*   **データが正しく受信されない:**
    *   ペイロードのフォーマットが正しいことを確認します。
    *   暗号化の設定が正しいことを確認します。

#### 11.1.8 まとめと次のステップ

LoRaWANは、長距離、低消費電力のIoTアプリケーションに最適な無線通信プロトコルです。スマートシティ、農業、産業モニタリングなど、幅広い分野で活用できます。LoRaWANの基本的な使い方を理解し、実践的なテクニックを習得することで、IoTプロジェクトを成功に導くことができます。

次のステップとしては、実際にLoRaWAN対応デバイスを購入し、The Things Networkなどのオープンソースのネットワークサーバーを利用して、簡単なIoTアプリケーションを構築してみることをお勧めします。また、LoRa Allianceのウェブサイトで、最新の技術情報や事例を学ぶことも重要です。

### 11.2 Sigfox：低消費電力広域ネットワーク

#### 11.2.1 概要と重要性

Sigfoxは、LoRaWANと同様に、低消費電力広域ネットワーク (LPWAN) 技術の一つであり、グローバルなIoT接続を提供することを目指しています。 特に、シンプルで低コストな双方向通信を必要とするアプリケーションに適しています。Sigfoxは、免許不要のスペクトラムを使用し、非常に狭い帯域幅でデータを送信することで、長距離通信と低消費電力を実現しています。

#### 11.2.2 特徴と利点

Sigfoxには、以下のような特徴と利点があります。

*   **グローバルなカバレッジ:** 世界中の多くの国でネットワークが展開されており、グローバルなIoTソリューションを構築するのに適しています。
*   **低消費電力:** バッテリー駆動のデバイスで数年間動作することを可能にします。
*   **低コスト:** 通信料金が比較的安価であり、大規模なデバイス展開に適しています。
*   **シンプルなアーキテクチャ:** ネットワーク構成がシンプルであり、デバイスの開発や導入が容易です。
*   **免許不要のスペクトラム:** 免許取得の必要がないため、迅速なデバイスの展開が可能です。
*   **双方向通信:** デバイスからネットワークへ、またネットワークからデバイスへの双方向通信をサポートします。ただし、下り方向の通信は上り方向よりも制限が厳しくなっています。

#### 11.2.3 事前準備と前提条件

Sigfoxを利用するためには、以下の要素が必要です。

*   **Sigfox対応デバイス:** センサー、アクチュエータなど、Sigfoxプロトコルをサポートするデバイス。
*   **Sigfoxサブスクリプション:** Sigfoxネットワークへの接続料金を支払う必要があります。
*   **Sigfoxネットワーク:** Sigfoxオペレーターによって提供されるネットワークカバレッジが必要です。
*   **アプリケーションサーバー:** Sigfoxクラウドから受信したデータを処理し、アプリケーションに提供する役割を担います。

#### 11.2.4 基本的な使い方

Sigfoxデバイスをネットワークに接続する基本的な手順は以下の通りです。

1.  **デバイスの認証:** SigfoxデバイスをSigfoxネットワークに登録し、デバイスIDとPACコードを取得します。これらの情報は、デバイスの製造元から提供されます。
2.  **Sigfoxクラウドの設定:** Sigfoxクラウドにデバイスを登録し、データの送受信先となるアプリケーションサーバーを設定します。
3.  **データの送受信:** デバイスからデータを送信し、アプリケーションサーバーで受信することを確認します。双方向通信をテストする場合は、アプリケーションサーバーからデバイスにコマンドを送信してみます。

**設定例:**

1.  **Sigfoxアカウントの作成:** SigfoxのウェブサイトまたはSigfoxオペレーターを通じてアカウントを作成します。
2.  **デバイスの登録:** Sigfoxクラウドで新しいデバイスを登録し、デバイスIDとPACコードを入力します。
3.  **コールバックの設定:** Sigfoxクラウドで、デバイスから送信されたデータを受信するアプリケーションサーバーへのコールバックを設定します。コールバックには、HTTP POSTリクエストを使用できます。
4.  **データ送信のテスト:** デバイスからデータを送信し、アプリケーションサーバーでデータが受信されることを確認します。

**コードスニペット (Sigfoxライブラリを使用):**

```cpp
#include <SigFox.h>

#define SIGFOX_BAUDRATE 57600

void setup() {
  Serial.begin(115200);
  Serial.println("Starting Sigfox Example");

  // Initialize Sigfox module
  SigFox.begin(SIGFOX_BAUDRATE);

  // Wait for the module to be ready
  delay(100);

  // Print Sigfox device ID and PAC code
  Serial.print("Device ID: ");
  Serial.println(SigFox.ID(), HEX);
  Serial.print("PAC: ");
  Serial.println(SigFox.PAC(), HEX);
}

void loop() {
  // Send a message
  String message = "Hello Sigfox!";
  Serial.print("Sending: ");
  Serial.println(message);

  // Send the message
  int result = SigFox.send(message);

  // Check the result
  if (result == 1) {
    Serial.println("Message sent successfully!");
  } else {
    Serial.print("Error sending message: ");
    Serial.println(result);
  }

  // Wait for a few seconds
  delay(5000);
}
```

#### 11.2.5 実践的なテクニック

*   **メッセージサイズの最適化:** Sigfoxは、1メッセージあたりのペイロードサイズが非常に限られています (最大12バイト)。そのため、データを効率的にエンコードし、必要な情報のみを送信するように心がける必要があります。
*   **送信頻度の制限:** Sigfoxネットワークには、1日あたりの送信回数に制限があります (通常、1日あたり140メッセージ)。送信頻度を適切に調整し、制限を超えないように注意する必要があります。
*   **双方向通信の活用:** Sigfoxは双方向通信をサポートしていますが、下り方向の通信は上り方向よりも制限が厳しくなっています。下り方向の通信は、緊急時や重要なコマンドの送信に限定し、上り方向の通信を最適化するように心がけましょう。
*   **地理位置情報の活用:** Sigfoxネットワークは、デバイスの位置情報を推定する機能を提供しています。この機能を活用することで、GPSモジュールを搭載せずに、デバイスの位置情報を取得できます。

#### 11.2.6 応用例とユースケース

*   **アセットトラッキング:** 貨物、車両、コンテナなどの追跡。
*   **スマートメーター:** 水道、電気、ガスメーターの自動検針。
*   **セキュリティ:** アラームシステム、盗難防止装置。
*   **サプライチェーン管理:** 在庫管理、商品の追跡。
*   **環境モニタリング:** 温度、湿度、気圧などの監視。

**具体的なユースケース: アセットトラッキング**

Sigfoxを利用したアセットトラッキングでは、貨物やコンテナにSigfox対応のトラッカーを取り付け、その位置情報をリアルタイムで追跡することができます。これにより、貨物の紛失や盗難を防止し、サプライチェーンの効率化に貢献できます。

#### 11.2.7 トラブルシューティング

*   **通信が確立できない:**
    *   Sigfoxサブスクリプションが有効であることを確認します。
    *   デバイスがSigfoxネットワークのカバレッジエリア内にあることを確認します。
    *   デバイスIDとPACコードが正しいことを確認します。
*   **データが正しく受信されない:**
    *   コールバックの設定が正しいことを確認します。
    *   ペイロードのフォーマットが正しいことを確認します。
*   **バッテリーの消耗が早い:**
    *   送信頻度を減らすことを検討します。
    *   ディープスリープモードを活用し、消費電力を抑えます。

Sigfoxは、グローバルなIoT接続を低コストで実現できる魅力的なLPWAN技術です。アセットトラッキング、スマートメーター、セキュリティなど、幅広い分野で活用できます。Sigfoxの基本的な使い方を理解し、実践的なテクニックを習得することで、IoTプロジェクトを成功に導くことができます。
