## 10. NFTゲーム開発：Immutable Xを使ったゲーム設計

### 10.1 ゲームデザイン：NFTを活用したゲームメカニクス

#### 概要と重要性

NFT（Non-Fungible Token：非代替性トークン）は、デジタルアセットの所有権を証明し、唯一無二であることを保証する技術です。NFTゲームは、この特性をゲームに取り入れ、プレイヤーがゲーム内のアイテムやキャラクターを所有し、取引できるようにする新しいゲームジャンルです。NFTを活用することで、ゲームのエコシステムを活性化し、プレイヤーエンゲージメントを高め、新たな収益源を創出することができます。

#### 特徴と利点

NFTを活用したゲームメカニクスには、以下のような特徴と利点があります。

*   **所有権の確立:** プレイヤーはゲーム内のアセットを完全に所有し、ゲームの運営に依存せずに自由に取引できます。
*   **希少性の創出:** NFTの特性により、ゲーム内のアイテムやキャラクターに希少性を持たせることができます。これにより、コレクション性や価値を高め、プレイヤーのモチベーションを向上させます。
*   **相互運用性:** NFTは異なるゲームやプラットフォーム間で移動できるため、ゲーム間の連携やアセットの再利用が可能です。
*   **コミュニティ形成:** NFTの取引や収集を通じて、プレイヤー間のコミュニティ形成を促進します。
*   **新たな収益源:** ゲーム開発者は、NFTの販売や取引手数料を通じて、新たな収益源を得ることができます。プレイヤーも、ゲーム内で獲得したNFTを売却することで収益を得ることが可能です。

#### 事前準備と前提条件

NFTゲームのデザインを始める前に、以下の点を考慮する必要があります。

*   **ゲームジャンル:** どのようなゲームジャンルでNFTを活用するかを決定します。RPG、トレーディングカードゲーム、ストラテジーゲームなど、様々な選択肢があります。
*   **NFTの活用方法:** どのようにNFTをゲームに取り入れるかを検討します。アイテム、キャラクター、土地など、様々なアセットをNFT化することができます。
*   **経済モデル:** ゲーム内の経済モデルを設計します。NFTの供給量、価格設定、取引手数料などを考慮し、持続可能な経済システムを構築する必要があります。
*   **ブロックチェーンの選択:** どのブロックチェーン上でNFTを発行するかを決定します。Immutable X、Ethereum、Polygonなど、様々な選択肢があります。本章ではImmutable Xを使用します。
*   **ウォレットの準備:** NFTを保管・取引するためのウォレットを準備します。MetaMask、WalletConnectなどが利用できます。

#### 基本的な使い方

NFTを活用したゲームメカニクスの基本的な使い方を、いくつかの例を通して解説します。

*   **アイテムのNFT化:** ゲーム内のアイテムをNFT化し、プレイヤーが所有・取引できるようにします。例えば、レアアイテムや強力な武器をNFT化することで、コレクション性や価値を高めることができます。
*   **キャラクターのNFT化:** ゲーム内のキャラクターをNFT化し、プレイヤーが育成・取引できるようにします。キャラクターの能力や外見をNFTのメタデータに記録することで、唯一無二の存在として扱うことができます。
*   **土地のNFT化:** ゲーム内の土地をNFT化し、プレイヤーが所有・開発できるようにします。土地を所有することで、資源を採掘したり、建物を建てたり、他のプレイヤーと取引したりすることができます。
*   **ゲーム内通貨のNFT化:** ゲーム内で使用する通貨をNFT化し、プレイヤーが取引できるようにします。これにより、ゲーム外の取引所での取引も可能になり、ゲームのエコシステムを活性化させることができます。

#### 実践的なテクニック

より高度なNFTゲームメカニクスを実装するためのテクニックを紹介します。

*   **NFTのレアリティ設定:** NFTのメタデータにレアリティ情報を追加し、希少性を表現します。例えば、Common、Uncommon、Rare、Epicなどのレアリティを設定し、出現確率や能力値を調整します。
*   **NFTの合成・進化:** 複数のNFTを合成して、新しいNFTを生成するメカニクスを実装します。例えば、同じ種類のアイテムNFTを合成して、より強力なアイテムNFTを生成することができます。
*   **NFTのレンタル:** NFTを他のプレイヤーにレンタルできるシステムを実装します。これにより、NFTを所有していないプレイヤーも、一時的にNFTを使用できるようになり、ゲームへの参加障壁を下げることができます。
*   **NFTのステーキング:** NFTをステーキングすることで、ゲーム内通貨やアイテムなどの報酬を得られるシステムを実装します。これにより、NFTの長期保有を促し、ゲームのエコシステムを安定させることができます。
*   **DAO（分散型自律組織）の活用:** NFTホルダーがゲームの運営方針を決定できるDAOを設立します。これにより、プレイヤーの意見を反映したゲーム開発が可能になり、コミュニティのエンゲージメントを高めることができます。

#### 応用例とユースケース

実際にNFTを活用したゲームの応用例とユースケースを紹介します。

*   **Axie Infinity:** モンスターを育成・対戦させるNFTゲーム。Axieと呼ばれるモンスターをNFT化し、プレイヤーはAxieを育成・繁殖させて、他のプレイヤーとの対戦に参加します。
*   **Decentraland:** 仮想空間内の土地をNFT化し、プレイヤーが自由な活動を行えるメタバースプラットフォーム。土地を所有することで、建物を建てたり、イベントを開催したり、他のプレイヤーと交流したりすることができます。
*   **The Sandbox:** ユーザーがボクセルアートを作成・共有できるNFTゲーム。作成したアセットをNFT化し、マーケットプレイスで販売することができます。
*   **CryptoKitties:** 猫を育成・繁殖させるNFTゲーム。猫をNFT化し、プレイヤーは猫を収集・繁殖させて、珍しい猫をコレクションします。

#### トラブルシューティング

NFTゲームのデザインでよくあるトラブルシューティングを紹介します。

*   **NFTの価値変動:** NFTの価値は市場の需要と供給によって変動するため、価値が大きく下落する可能性があります。価値変動のリスクを軽減するために、NFTの供給量を調整したり、NFTのユーティリティを高めたりする対策が必要です。
*   **ガス代の高騰:** Ethereumなどのブロックチェーンでは、トランザクションごとにガス代（手数料）が発生します。ガス代が高騰すると、NFTの取引コストが高くなり、プレイヤーの負担が増加します。ガス代を軽減するために、レイヤー2ソリューション（Immutable Xなど）を利用したり、トランザクションを最適化したりする対策が必要です。
*   **セキュリティリスク:** NFTはデジタルアセットであるため、ハッキングや詐欺などのセキュリティリスクが存在します。セキュリティ対策として、ウォレットのセキュリティを強化したり、スマートコントラクトの脆弱性を修正したりする対策が必要です。
*   **法規制の不確実性:** NFTに関する法規制はまだ整備されていないため、法的なリスクが存在します。法規制の動向を注視し、必要に応じて専門家のアドバイスを受ける必要があります。

### 10.2 ゲーム開発フレームワーク：Unity, Unreal Engine

#### 概要と重要性

UnityとUnreal Engineは、現代のゲーム開発において最も人気のあるゲームエンジンです。これらのエンジンは、強力なツール、豊富なアセットストア、活発なコミュニティを提供し、開発者が高品質なゲームを迅速かつ効率的に作成することを可能にします。NFTゲーム開発においても、これらのエンジンを活用することで、従来のゲーム開発の知識やスキルを活かしながら、NFTの機能を統合することができます。

#### 特徴と利点

UnityとUnreal Engineは、それぞれ独自の特徴と利点を持っています。

**Unity:**

*   **使いやすさ:** 直感的なインターフェースと豊富なドキュメントにより、初心者でも比較的簡単に習得できます。
*   **クロスプラットフォーム対応:** Windows、macOS、iOS、Android、Webなど、様々なプラットフォームに対応しています。
*   **アセットストア:** 豊富なアセットストアがあり、3Dモデル、テクスチャ、スクリプト、エディタ拡張など、様々なアセットを購入・利用できます。
*   **C#スクリプト:** C#を使ってゲームロジックを記述します。C#は汎用性の高いプログラミング言語であり、ゲーム開発以外の分野でも広く利用されています。

**Unreal Engine:**

*   **グラフィック性能:** 非常に高品質なグラフィック表現が可能です。特に、リアルな表現を必要とするゲームに適しています。
*   **ブループリント:** プログラミングの知識がなくても、ビジュアルスクリプティングツールであるブループリントを使ってゲームロジックを記述できます。
*   **C++サポート:** C++を使ってゲームロジックを記述することもできます。C++はパフォーマンスの高いプログラミング言語であり、複雑なゲームロジックを実装するのに適しています。
*   **ロイヤリティフリー（一部条件あり）：** Unreal Engineで開発したゲームの売上が一定額を超えるまで、ロイヤリティを支払う必要はありません。

どちらのエンジンを選択するかは、ゲームのジャンル、必要な機能、開発チームのスキルセットなどによって異なります。

#### 事前準備と前提条件

UnityまたはUnreal Engineを使用してNFTゲームを開発する前に、以下の点を準備する必要があります。

*   **ゲームエンジンのインストール:** 公式サイトからUnityまたはUnreal Engineをダウンロードしてインストールします。
*   **開発環境の構築:** 開発に必要なツールやSDKをインストールし、開発環境を構築します。
*   **プログラミング言語の学習:** Unityの場合はC#、Unreal Engineの場合はブループリントまたはC++の基礎を学習します。
*   **Immutable X SDKの導入:** Immutable XのAPIをUnityまたはUnreal Engineで使用するためのSDKを導入します。SDKはImmutable Xのドキュメントサイトからダウンロードできます。
*   **ウォレット接続の準備:** プレイヤーがゲームにウォレットを接続できるように、ウォレット接続ライブラリを導入します。Web3.jsやEthers.jsなどが利用できます。

#### 基本的な使い方

UnityまたはUnreal Engineを使ってNFTゲームを開発する基本的な使い方を解説します。

**Unityの場合:**

1.  **プロジェクトの作成:** Unity Hubで新しいプロジェクトを作成します。テンプレートは3Dまたは2Dを選択します。
2.  **Immutable X SDKのインポート:** ダウンロードしたImmutable X SDKをUnityプロジェクトにインポートします。
3.  **ウォレット接続の実装:** Web3.jsやEthers.jsなどのウォレット接続ライブラリを使用して、プレイヤーがウォレットを接続できるようにします。
4.  **NFTの取得・表示:** Immutable XのAPIを使用して、プレイヤーが所有するNFTを取得し、ゲーム内に表示します。
5.  **NFTの取引の実装:** Immutable XのAPIを使用して、NFTの取引機能を実装します。

**Unreal Engineの場合:**

1.  **プロジェクトの作成:** Unreal Engine Launcherで新しいプロジェクトを作成します。テンプレートはThird PersonまたはBlankを選択します。
2.  **Immutable X SDKのインポート:** ダウンロードしたImmutable X SDKをUnreal Engineプロジェクトにインポートします。C++プロジェクトの場合は、SDKをビルドする必要があります。
3.  **ウォレット接続の実装:** Web3.jsやEthers.jsなどのウォレット接続ライブラリを使用して、プレイヤーがウォレットを接続できるようにします。C++またはブループリントで実装します。
4.  **NFTの取得・表示:** Immutable XのAPIを使用して、プレイヤーが所有するNFTを取得し、ゲーム内に表示します。
5.  **NFTの取引の実装:** Immutable XのAPIを使用して、NFTの取引機能を実装します。

#### 実践的なテクニック

より高度なNFTゲーム開発を行うためのテクニックを紹介します。

*   **非同期処理:** ブロックチェーンとの通信は時間がかかるため、非同期処理を使用して、ゲームの動作をスムーズにします。C#の場合はasync/await、C++の場合はstd::asyncなどを使用します。
*   **UI/UXの最適化:** NFTゲームは従来のゲームとは異なるUI/UXが必要となる場合があります。ウォレット接続、NFTの表示、取引など、NFTに関連するUI/UXを最適化します。
*   **セキュリティ対策:** NFTゲームはセキュリティリスクが高いため、セキュリティ対策を徹底します。入力値の検証、不正アクセスの防止、スマートコントラクトの監査などを行います。
*   **パフォーマンス最適化:** NFTゲームはブロックチェーンとの通信やNFTの処理など、パフォーマンスに影響を与える要素が多いため、パフォーマンス最適化を行います。アセットの最適化、コードの最適化、描画負荷の軽減などを行います。

#### 応用例とユースケース

UnityまたはUnreal Engineを使用して開発されたNFTゲームの応用例とユースケースを紹介します。

*   **Ember Sword (Unreal Engine):** ランドをNFTとして所有できるMMORPG。プレイヤーはランドを所有し、資源を採掘したり、建物を建てたり、他のプレイヤーと取引したりすることができます。
*   **Illuvium (Unreal Engine):** モンスターを収集・対戦させるNFTゲーム。Illuvialと呼ばれるモンスターをNFT化し、プレイヤーはIlluvialを収集・育成させて、他のプレイヤーとの対戦に参加します。
*   **Guild of Guardians (Unity):** モバイル向けのファンタジーRPG。ヒーローをNFT化し、プレイヤーはヒーローを育成・強化して、ダンジョンを攻略したり、他のプレイヤーと協力したりすることができます。

#### トラブルシューティング

UnityまたはUnreal EngineでNFTゲームを開発する際によくあるトラブルシューティングを紹介します。

*   **Immutable X SDKのインポートエラー:** Immutable X SDKが正しくインポートされない場合は、SDKのバージョンがUnityまたはUnreal Engineのバージョンと互換性があるか確認します。また、必要な依存関係がインストールされているか確認します。
*   **ウォレット接続エラー:** ウォレット接続がうまくいかない場合は、ウォレットのバージョンが最新であるか確認します。また、Web3.jsやEthers.jsなどのウォレット接続ライブラリの設定が正しいか確認します。
*   **APIリクエストエラー:** Immutable XのAPIリクエストが失敗する場合は、APIキーが正しいか確認します。また、APIのエンドポイントが正しいか確認します。
*   **パフォーマンス問題:** ゲームのパフォーマンスが低い場合は、アセットの最適化、コードの最適化、描画負荷の軽減などを行います。

### 10.3 NFTゲームのアーキテクチャ：クライアント、サーバー、ブロックチェーン

#### 概要と重要性

NFTゲームのアーキテクチャは、従来のオンラインゲームのアーキテクチャとは異なり、クライアント、サーバー、ブロックチェーンという3つの主要なコンポーネントで構成されています。これらのコンポーネントが連携することで、NFTの所有権を確立し、ゲーム内での取引を可能にします。適切なアーキテクチャ設計は、NFTゲームのパフォーマンス、セキュリティ、スケーラビリティに大きな影響を与えるため、非常に重要です。

#### 特徴と利点

NFTゲームのアーキテクチャは、以下のような特徴と利点があります。

*   **分散型所有権:** ブロックチェーン上にNFTの所有権が記録されるため、ゲーム運営者に依存せずに、プレイヤーがアセットを完全に所有できます。
*   **透明性:** ブロックチェーン上のすべてのトランザクションは公開されており、透明性が高いです。これにより、不正行為を防止し、信頼性を高めることができます。
*   **セキュリティ:** ブロックチェーンのセキュリティ機能により、NFTの改ざんや不正な取引を防止できます。
*   **相互運用性:** NFTは異なるゲームやプラットフォーム間で移動できるため、ゲーム間の連携やアセットの再利用が可能です。

#### 事前準備と前提条件

NFTゲームのアーキテクチャを設計する前に、以下の点を考慮する必要があります。

*   **ゲームの種類:** ゲームの種類によって、必要なアーキテクチャが異なります。例えば、大規模なMMORPGと小規模なカードゲームでは、必要なサーバーの構成やブロックチェーンの利用方法が異なります。
*   **ブロックチェーンの選択:** ブロックチェーンの種類によって、APIの仕様やセキュリティレベルが異なります。Immutable X、Ethereum、Polygonなど、ゲームの要件に合ったブロックチェーンを選択する必要があります。
*   **スケーラビリティ:** 多くのプレイヤーが同時にアクセスしても、ゲームが正常に動作するように、スケーラビリティを考慮する必要があります。
*   **セキュリティ:** ハッキングや詐欺などのセキュリティリスクからゲームを保護するために、セキュリティ対策を講じる必要があります。

#### 基本的な使い方

NFTゲームのアーキテクチャの基本的な構成要素と、それぞれの役割について解説します。

*   **クライアント:** プレイヤーがゲームをプレイするためのアプリケーションです。UnityまたはUnreal Engineなどのゲームエンジンで開発されます。クライアントは、プレイヤーからの入力を受け付け、サーバーに送信し、サーバーから受信したゲームの状態を表示します。また、ウォレット接続やNFTの表示などの機能も担当します。
*   **サーバー:** ゲームロジックを実行し、ゲームの状態を管理するサーバーです。サーバーは、クライアントからのリクエストを処理し、データベースにデータを保存します。また、ブロックチェーンとの通信を行い、NFTの所有権を確認したり、NFTの取引を処理したりします。
*   **ブロックチェーン:** NFTの所有権を記録し、NFTの取引を処理する分散型台帳です。Immutable Xなどのレイヤー2ソリューションを使用することで、トランザクションの処理速度を向上させ、ガス代を削減することができます。

これらのコンポーネントは、以下のように連携します。

1.  プレイヤーがクライアントからゲームにアクセスします。
2.  クライアントは、ウォレット接続を確立し、プレイヤーのウォレットアドレスを取得します。
3.  クライアントは、サーバーにリクエストを送信し、ゲームの状態を取得します。
4.  サーバーは、ブロックチェーンにアクセスし、プレイヤーが所有するNFTの情報を取得します。
5.  サーバーは、取得したNFTの情報とゲームの状態をクライアントに送信します。
6.  クライアントは、受信した情報に基づいて、ゲーム画面を表示します。
7.  プレイヤーがゲーム内でNFTを取引する場合、クライアントはサーバーに取引リクエストを送信します。
8.  サーバーは、ブロックチェーンに取引リクエストを送信し、取引を処理します。
9.  ブロックチェーンは、取引を検証し、トランザクションを記録します。
10. サーバーは、ブロックチェーンから取引結果を受信し、ゲームの状態を更新します。
11. サーバーは、更新されたゲームの状態をクライアントに送信します。
12. クライアントは、受信した情報に基づいて、ゲーム画面を更新します。

#### 実践的なテクニック

より高度なNFTゲームアーキテクチャを構築するためのテクニックを紹介します。

*   **マイクロサービスアーキテクチャ:** ゲームの機能を複数の独立したサービスに分割し、それぞれのサービスを独立して開発・デプロイ・スケーリングできるようにします。これにより、開発効率を向上させ、システムの可用性を高めることができます。
*   **API Gateway:** クライアントからのリクエストをルーティングし、認証・認可などのセキュリティ機能を一元的に管理するAPI Gatewayを導入します。これにより、セキュリティを強化し、システムの複雑さを軽減することができます。
*   **CDN (Content Delivery Network):** ゲームのアセット（画像、動画、音声など）をCDNにキャッシュすることで、コンテンツの配信速度を向上させ、サーバーの負荷を軽減します。
*   **データベースの最適化:** ゲームの状態を保存するデータベースのパフォーマンスを最適化します。インデックスの作成、クエリの最適化、データベースのシャーディングなどを行います。
*   **キャッシュの活用:** 頻繁にアクセスされるデータをキャッシュすることで、データベースへのアクセス回数を減らし、パフォーマンスを向上させます。RedisやMemcachedなどのキャッシュサーバーを利用します。

#### 応用例とユースケース

様々な種類のNFTゲームアーキテクチャの応用例とユースケースを紹介します。

*   **大規模MMORPG:** プレイヤー数が多く、ゲームの世界が広大なMMORPGでは、マイクロサービスアーキテクチャを採用し、ゲームの機能を複数の独立したサービスに分割することが一般的です。例えば、キャラクター管理サービス、アイテム管理サービス、戦闘サービスなどを独立して開発・デプロイ・スケーリングします。
*   **トレーディングカードゲーム:** カードの所有権をNFTとして管理し、プレイヤー間でカードを取引できるトレーディングカードゲームでは、ブロックチェーンとの連携が重要になります。カードの所有権の確認、カードの取引処理、カードの生成などをブロックチェーン上で行います。
*   **仮想空間プラットフォーム:** プレイヤーが自由にコンテンツを作成・共有できる仮想空間プラットフォームでは、NFTを活用してコンテンツの所有権を確立し、クリエイターエコノミーを構築します。土地、建物、アバターなどのコンテンツをNFTとして所有し、他のプレイヤーと取引したり、レンタルしたりすることができます。

#### トラブルシューティング

NFTゲームのアーキテクチャ設計でよくあるトラブルシューティングを紹介します。

*   **ブロックチェーンとの通信エラー:** ブロックチェーンとの通信がうまくいかない場合は、APIキーが正しいか確認します。また、APIのエンドポイントが正しいか確認します。ブロックチェーンのノードが正常に動作しているか確認します。
*   **サーバーの負荷が高い:** サーバーの負荷が高い場合は、サーバーのスペックを向上させるか、サーバーの数を増やすなどの対策が必要です。また、データベースの最適化やキャッシュの活用などを行うことで、サーバーの負荷を軽減することができます。
*   **セキュリティ問題:** ハッキングや詐欺などのセキュリティ問題が発生した場合は、セキュリティ対策を見直す必要があります。入力値の検証、不正アクセスの防止、スマートコントラクトの監査などを行います。
*   **スケーラビリティの問題:** プレイヤー数が増加すると、ゲームのパフォーマンスが低下する場合があります。スケーラビリティの問題を解決するためには、マイクロサービスアーキテクチャを採用したり、CDNを活用したり、データベースを最適化したりするなどの対策が必要です。

```csharp
using UnityEngine;
using UnityEngine.UI;
using System.Threading.Tasks;
using Nethereum.Web3;
using Nethereum.Web3.Accounts;
using Nethereum.Hex.HexTypes;

public class WalletConnector : MonoBehaviour
{
    public Text walletAddressText;
    public Button connectWalletButton;
    private string accountAddress;
    private Web3 web3;

    void Start()
    {
        connectWalletButton.onClick.AddListener(ConnectWallet);
    }

    async void ConnectWallet()
    {
#if UNITY_WEBGL && !UNITY_EDITOR
        // WebGLプラットフォームでMetaMaskと接続
        accountAddress = await ConnectToMetaMask();
        walletAddressText.text = "Wallet Address: " + accountAddress;
#else
        // エディタまたは他のプラットフォームでのモックアップ
        accountAddress = "0x0000000000000000000000000000000000000000";
        walletAddressText.text = "Wallet Address: " + accountAddress + " (Mocked)";
#endif
    }

    private async Task<string> ConnectToMetaMask()
    {
        try
        {
            web3 = new Web3();
            // MetaMaskに接続を要求
            string address = await Web3.EnableEthereum();

            if (string.IsNullOrEmpty(address))
            {
                Debug.LogError("Failed to connect to MetaMask");
                return null;
            }

            return address;
        }
        catch (System.Exception e)
        {
            Debug.LogError("Exception connecting to MetaMask: " + e.Message);
            return null;
        }
    }
    public string GetAccountAddress()
    {
        return accountAddress;
    }

    public Web3 GetWeb3()
    {
        return web3;
    }
}
```

5.  **NFTFetcher.cs:**

```csharp
using UnityEngine;
using UnityEngine.UI;
using System.Collections.Generic;
using ImmutableX.SDK.Models;
using ImmutableX.SDK;
using System.Threading.Tasks;

public class NFTFetcher : MonoBehaviour
{
    public GameObject nftItemPrefab;
    public Transform nftContainer;
    public WalletConnector walletConnector;
    private ImmutableXClient immutableXClient;
    private ListNftsResponse nfts;

    async void Start()
    {
        // Immutable Xクライアントの設定
        immutableXClient = new ImmutableXClient(ImmutableXClient.MainnetAPIUrl);

        // NFTの取得と表示
        await FetchAndDisplayNFTs();
    }

    async Task FetchAndDisplayNFTs()
    {
        string accountAddress = walletConnector.GetAccountAddress();
        if (string.IsNullOrEmpty(accountAddress))
        {
            Debug.LogError("Wallet not connected.");
            return;
        }

        nfts = await immutableXClient.GetNFTs(owner: accountAddress);

        if (nfts != null && nfts.result != null)
        {
            foreach (var nft in nfts.result)
            {
                GameObject nftItem = Instantiate(nftItemPrefab, nftContainer);
                NFTItem item = nftItem.GetComponent<NFTItem>();
                if (item != null)
                {
                    item.SetNFTData(nft);
                }
            }
        }
        else
        {
            Debug.LogError("Failed to fetch NFTs.");
        }
    }
}
```

6. **NFTItem.cs:**

```csharp
using UnityEngine;
using UnityEngine.UI;
using ImmutableX.SDK.Models;

public class NFTItem : MonoBehaviour
{
    public RawImage nftImage;
    public Text nftNameText;

    public void SetNFTData(Nft nft)
    {
        nftNameText.text = nft.name;
        StartCoroutine(LoadImage(nft.image_url)); // 非同期で画像をロード
    }

    // 画像を非同期でロードしてRawImageに設定
    private System.Collections.IEnumerator LoadImage(string url)
    {
        using (WWW www = new WWW(url))
        {
            yield return www;

            if (string.IsNullOrEmpty(www.error))
            {
                Texture2D texture = www.texture;
                nftImage.texture = texture;
            }
            else
            {
                Debug.LogError("Failed to load image: " + www.error);
            }
        }
    }
}
```
