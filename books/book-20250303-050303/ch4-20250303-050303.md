# 4. チェーンコード開発：スマートコントラクト実装の全貌

本章では、Hyperledger Fabric におけるスマートコントラクト、すなわち「チェーンコード」の開発手法について、基礎から高度な実装例まで幅広く解説します。読者は本章を通して、チェーンコードの基本構造、台帳とのやり取り、サンプル実装、パッケージングとデプロイ、さらにはテスト・デバッグやアップグレード、プライベートデータコレクションの活用方法まで、実務に直結する知識と技術を体系的に学ぶことができます。

---

## 4.1 チェーンコード開発の概要

Hyperledger Fabric において、チェーンコードは台帳と直接やり取りを行うビジネスロジックの実装体です。ブロックチェーン上で動作するスマートコントラクトとして、企業間の取引、資産管理、サプライチェーンの追跡など、あらゆる業務プロセスの自動化を実現します。

### 4.1.1 チェーンコードの役割
- **業務ロジックの実装**  
  各トランザクションがどのように実行され、台帳に反映されるかを定義します。
- **台帳データの読み書き**  
  台帳上の状態を変更するための read–write set を生成し、トランザクション検証に利用されます。
- **エンドースメントの実施**  
  トランザクションの実行結果に署名を行い、ネットワーク全体での合意形成に貢献します。

### 4.1.2 チェーンコード開発のメリット
- **柔軟性**  
  Go、Java、Node.js など複数言語に対応しているため、既存の開発リソースを活用可能です。
- **安全性**  
  台帳の不変性と暗号技術により、高いセキュリティと信頼性が担保されます。
- **自動化と効率化**  
  業務プロセスの自動化によって、人為的ミスを減少させ、取引の迅速化を実現します。

## 4.3 チェーンコードの基本構造

ここでは、Go 言語によるチェーンコードの基本的な構造を解説します。以下は、シンプルなチェーンコードの例です。

### 4.3.1 サンプルコードの全体像

```go
package main

import (
    "fmt"
    "github.com/hyperledger/fabric-contract-api-go/contractapi"
)

// SmartContract はチェーンコードのメイン構造体です
type SmartContract struct {
    contractapi.Contract
}

// Init は初期化処理（オプション）
func (s *SmartContract) Init(ctx contractapi.TransactionContextInterface) error {
    return nil
}

// YourFunction はサンプル関数です
func (s *SmartContract) YourFunction(ctx contractapi.TransactionContextInterface, param1 string, param2 string) (string, error) {
    // ビジネスロジックの実装
    return "結果", nil
}

func main() {
    chaincode, err := contractapi.NewChaincode(&SmartContract{})
    if err != nil {
        fmt.Printf("Error creating chaincode: %s", err.Error())
        return
    }
    if err := chaincode.Start(); err != nil {
        fmt.Printf("Error starting chaincode: %s", err.Error())
    }
}
```

### 4.3.2 各部の解説
- **パッケージ宣言**  
  `package main` により、実行可能なバイナリとしてビルドされることを示します。
- **インポート**  
  必要なライブラリ（標準ライブラリ、Fabric の SDK など）をインポートします。
- **SmartContract 構造体**  
  `contractapi.Contract` を埋め込むことで、チェーンコードの基本機能を継承しています。
- **初期化関数 Init**  
  チェーンコードのデプロイ時に一度だけ呼ばれる初期化処理です。必要に応じて台帳初期化などのロジックを実装します。
- **ビジネスロジック関数**  
  実際の業務ロジックを実装する関数群です。ここではサンプルとして `YourFunction` を定義しています。
- **main 関数**  
  チェーンコードのインスタンス生成と起動を行います。

## 4.4 台帳とのやり取り：データの読み書き

チェーンコードでは、Fabric の台帳と直接データのやり取りを行います。これを実現するために、`ctx.GetStub()` メソッドを利用して、状態の読み書きを行います。

### 4.4.1 資産の作成例

以下は、台帳に新しい資産を作成する例です。

```go
import (
    "encoding/json"
    "fmt"
)

type Asset struct {
    ID    string `json:"ID"`
    Value string `json:"Value"`
}

func (s *SmartContract) CreateAsset(ctx contractapi.TransactionContextInterface, id string, value string) error {
    assetJSON, err := ctx.GetStub().GetState(id)
    if err != nil {
        return fmt.Errorf("台帳の読み取りに失敗しました: %v", err)
    }
    if assetJSON != nil {
        return fmt.Errorf("資産 %s は既に存在します", id)
    }

    asset := Asset{ID: id, Value: value}
    assetJSON, err = json.Marshal(asset)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutState(id, assetJSON)
}
```

### 4.4.2 資産の読み取り例

台帳から資産情報を読み出す処理は以下の通りです。

```go
func (s *SmartContract) ReadAsset(ctx contractapi.TransactionContextInterface, id string) (*Asset, error) {
    assetJSON, err := ctx.GetStub().GetState(id)
    if err != nil {
        return nil, fmt.Errorf("台帳の読み取りに失敗しました: %v", err)
    }
    if assetJSON == nil {
        return nil, fmt.Errorf("資産 %s は存在しません", id)
    }

    var asset Asset
    err = json.Unmarshal(assetJSON, &asset)
    if err != nil {
        return nil, err
    }
    return &asset, nil
}
```

### 4.4.3 データの更新と削除

データ更新や削除も、基本的な読み書き操作と同様に実装します。更新例としては、既存資産の所有者変更などが挙げられます。

```go
func (s *SmartContract) UpdateAsset(ctx contractapi.TransactionContextInterface, id string, newValue string) error {
    asset, err := s.ReadAsset(ctx, id)
    if err != nil {
        return err
    }
    asset.Value = newValue

    assetJSON, err := json.Marshal(asset)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutState(id, assetJSON)
}

func (s *SmartContract) DeleteAsset(ctx contractapi.TransactionContextInterface, id string) error {
    exists, err := s.AssetExists(ctx, id)
    if err != nil {
        return err
    }
    if !exists {
        return fmt.Errorf("資産 %s は存在しません", id)
    }
    return ctx.GetStub().DelState(id)
}
```

このように、台帳とのやり取りの基本操作をマスターすることが、チェーンコード開発の第一歩となります。

## 4.5 サンプルチェーンコードの実装例

ここでは、より実践的なサンプルとして、アセット転送チェーンコードの例を詳しく解説します。以下は、基本的な資産転送のチェーンコード例です。

### 4.5.1 アセット転送チェーンコードの全体像

```go
package main

import (
    "encoding/json"
    "fmt"
    "github.com/hyperledger/fabric-contract-api-go/contractapi"
)

// AssetTransfer チェーンコードの実装
type AssetTransfer struct {
    contractapi.Contract
}

// Asset は台帳に保存する資産を表す構造体です
type Asset struct {
    ID             string `json:"ID"`
    Owner          string `json:"Owner"`
    Value          int    `json:"Value"`
    CreationDate   string `json:"CreationDate"`
    LastUpdateDate string `json:"LastUpdateDate"`
}

// InitLedger は台帳に初期データを追加する関数です
func (s *AssetTransfer) InitLedger(ctx contractapi.TransactionContextInterface) error {
    assets := []Asset{
        {ID: "asset1", Owner: "山田", Value: 100, CreationDate: "2023-01-01", LastUpdateDate: "2023-01-01"},
        {ID: "asset2", Owner: "佐藤", Value: 200, CreationDate: "2023-01-02", LastUpdateDate: "2023-01-02"},
    }

    for _, asset := range assets {
        assetJSON, err := json.Marshal(asset)
        if err != nil {
            return err
        }
        err = ctx.GetStub().PutState(asset.ID, assetJSON)
        if err != nil {
            return fmt.Errorf("台帳への書き込みに失敗しました: %v", err)
        }
    }
    return nil
}

// CreateAsset は新しい資産を作成する関数です
func (s *AssetTransfer) CreateAsset(ctx contractapi.TransactionContextInterface, id string, owner string, value int, creationDate string) error {
    exists, err := s.AssetExists(ctx, id)
    if err != nil {
        return err
    }
    if exists {
        return fmt.Errorf("資産 %s は既に存在します", id)
    }

    asset := Asset{
        ID:             id,
        Owner:          owner,
        Value:          value,
        CreationDate:   creationDate,
        LastUpdateDate: creationDate,
    }
    assetJSON, err := json.Marshal(asset)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutState(id, assetJSON)
}

// ReadAsset は資産を読み取る関数です
func (s *AssetTransfer) ReadAsset(ctx contractapi.TransactionContextInterface, id string) (*Asset, error) {
    assetJSON, err := ctx.GetStub().GetState(id)
    if err != nil {
        return nil, fmt.Errorf("台帳の読み取りに失敗しました: %v", err)
    }
    if assetJSON == nil {
        return nil, fmt.Errorf("資産 %s は存在しません", id)
    }

    var asset Asset
    err = json.Unmarshal(assetJSON, &asset)
    if err != nil {
        return nil, err
    }
    return &asset, nil
}

// UpdateAsset は既存資産を更新する関数です
func (s *AssetTransfer) UpdateAsset(ctx contractapi.TransactionContextInterface, id string, owner string, value int, updateDate string) error {
    asset, err := s.ReadAsset(ctx, id)
    if err != nil {
        return err
    }
    asset.Owner = owner
    asset.Value = value
    asset.LastUpdateDate = updateDate

    assetJSON, err := json.Marshal(asset)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutState(id, assetJSON)
}

// DeleteAsset は資産を削除する関数です
func (s *AssetTransfer) DeleteAsset(ctx contractapi.TransactionContextInterface, id string) error {
    exists, err := s.AssetExists(ctx, id)
    if err != nil {
        return err
    }
    if !exists {
        return fmt.Errorf("資産 %s は存在しません", id)
    }
    return ctx.GetStub().DelState(id)
}

// AssetExists は資産の存在確認関数です
func (s *AssetTransfer) AssetExists(ctx contractapi.TransactionContextInterface, id string) (bool, error) {
    assetJSON, err := ctx.GetStub().GetState(id)
    if err != nil {
        return false, fmt.Errorf("台帳の読み取りに失敗しました: %v", err)
    }
    return assetJSON != nil, nil
}
 
// GetAllAssets は台帳上のすべての資産を取得する関数です
func (s *AssetTransfer) GetAllAssets(ctx contractapi.TransactionContextInterface) ([]*Asset, error) {
    resultsIterator, err := ctx.GetStub().GetStateByRange("", "")
    if err != nil {
        return nil, err
    }
    defer resultsIterator.Close()

    var assets []*Asset
    for resultsIterator.HasNext() {
        queryResponse, err := resultsIterator.Next()
        if err != nil {
            return nil, err
        }
        var asset Asset
        err = json.Unmarshal(queryResponse.Value, &asset)
        if err != nil {
            return nil, err
        }
        assets = append(assets, &asset)
    }
    return assets, nil
}

// TransferAsset は資産の所有権を転送する関数です
func (s *AssetTransfer) TransferAsset(ctx contractapi.TransactionContextInterface, id string, newOwner string) error {
    asset, err := s.ReadAsset(ctx, id)
    if err != nil {
        return err
    }
    asset.Owner = newOwner

    assetJSON, err := json.Marshal(asset)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutState(id, assetJSON)
}

func main() {
    assetChaincode, err := contractapi.NewChaincode(&AssetTransfer{})
    if err != nil {
        fmt.Printf("Error creating asset-transfer chaincode: %v", err)
        return
    }
    if err := assetChaincode.Start(); err != nil {
        fmt.Printf("Error starting asset-transfer chaincode: %v", err)
    }
}
```

### 4.5.2 解説とポイント
- **初期化関数 (InitLedger)**  
  台帳に事前に資産を登録することで、ネットワーク起動時の状態確認に利用します。
- **CRUD 操作**  
  CreateAsset, ReadAsset, UpdateAsset, DeleteAsset の各関数で、基本的な台帳操作の流れを把握します。
- **所有権移転 (TransferAsset)**  
  資産の所有者を変更する処理は、ビジネスロジックの中でも非常に重要な機能です。

## 4.6 チェーンコードのパッケージングとデプロイ

チェーンコードを実際のネットワーク上で実行するためには、パッケージングとデプロイのプロセスが必要です。ここでは、Fabric 2.x のライフサイクル管理を利用した一連の流れを解説します。

### 4.6.1 チェーンコードのパッケージング

まず、チェーンコードの依存関係を管理した上で、チェーンコードをパッケージ化します。

```bash
cd ~/fabric-samples/chaincode/asset-transfer
go mod tidy
```

次に、テストネットワークが起動している状態で、以下のコマンドを実行してチェーンコードパッケージを作成します。

```bash

export PATH=${PWD}/../bin:$PATH
export FABRIC_CFG_PATH=$PWD/../config/
peer lifecycle chaincode package asset-transfer.tar.gz --path ../chaincode/asset-transfer --lang golang --label asset_transfer_1.0
```

各組織のピアに対して、チェーンコードパッケージをインストールします。

### 4.6.3 チェーンコード定義の承認とコミット

各組織がチェーンコード定義を承認した後、最終的にコミットしてチェーンコードを有効化します。Org1 と Org2 両方で承認手順を実施し、その後コミットします。



## 4.8 テストとデバッグ手法

チェーンコード開発において、単体テストおよび統合テストは極めて重要です。ここでは、Go 言語用のテストフレームワークを利用した単体テストの実装例や、統合テストの実施方法について解説します。

### 4.8.1 単体テストの実装例

以下は、モックを利用した単体テストのサンプルコードです。

```go
package main

import (
    "testing"
    
    "github.com/hyperledger/fabric-chaincode-go/shim"
    "github.com/hyperledger/fabric-contract-api-go/contractapi"
    "github.com/stretchr/testify/mock"
    "github.com/stretchr/testify/require"
)

// MockStub は shim.ChaincodeStubInterface のモック実装です
type MockStub struct {
    mock.Mock
    shim.ChaincodeStubInterface
}

func (ms *MockStub) GetState(key string) ([]byte, error) {
    args := ms.Called(key)
    return args.Get(0).([]byte), args.Error(1)
}

func (ms *MockStub) PutState(key string, value []byte) error {
    args := ms.Called(key, value)
    return args.Error(0)
}

type MockContext struct {
    contractapi.TransactionContextInterface
    stub *MockStub
}

func (mc *MockContext) GetStub() shim.ChaincodeStubInterface {
    return mc.stub
}

func TestCreateAsset(t *testing.T) {
    assetTransfer := new(AssetTransfer)
    
    // モックの設定
    mockStub := new(MockStub)
    mockContext := new(MockContext)
    mockContext.stub = mockStub
    
    // 新規資産作成のテスト
    mockStub.On("GetState", "asset1").Return([]byte{}, nil)
```

## 4.9 チェーンコードのアップグレード

運用中のチェーンコードに変更を加える場合、アップグレード手順が必要です。Fabric のライフサイクル管理機能を用いて、シーケンス番号を増やすことで新バージョンのチェーンコードを導入します。

### 4.9.1 新バージョンパッケージの作成

既存チェーンコードの変更を反映させた新バージョンをパッケージ化します。

```bash
cd ~/fabric-samples/chaincode/asset-transfer
go mod tidy
peer lifecycle chaincode package asset-transfer_v2.0.tar.gz --path ../chaincode/asset-transfer --lang golang --label asset_transfer_2.0
```

### 4.9.2 各組織へのインストールと承認

新バージョンのチェーンコードを各組織のピアにインストールし、承認プロセスを実施します。

```bash
export CC_PACKAGE_ID=asset_transfer_2.0:新しいIDに置き換え
peer lifecycle chaincode approveformyorg -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --channelID mychannel --name asset-transfer --version 2.0 --package-id $CC_PACKAGE_ID --sequence 2 --tls --cafile ${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem
```

その後、コミットを実行します。

```bash
peer lifecycle chaincode commit -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --channelID mychannel --name asset-transfer --version 2.0 --sequence 2 --tls --cafile ${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem --peerAddresses localhost:7051 --tlsRootCertFiles ${PWD}/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt --peerAddresses localhost:9051 --tlsRootCertFiles ${PWD}/organizations/peerOrganizations/org2.example.com/peers/peer0.org2.example.com/tls/ca.crt
```

これにより、新バージョンのチェーンコードがネットワークに反映されます。

## 4.10 プライベートデータコレクションの活用

プライバシー保護が求められるケースでは、プライベートデータコレクションを利用して、機密データを一部の承認されたピア間だけで共有する方法が有効です。

### 4.10.1 プライベートデータコレクションの定義

プライベートデータコレクションは、JSON ファイルで定義されます。以下は例です。

```json
[
    {
        "name": "assetCollection",
        "policy": "OR('Org1MSP.member', 'Org2MSP.member')",
        "requiredPeerCount": 1,
        "maxPeerCount": 3,
        "blockToLive": 100000,
        "memberOnlyRead": true
    },
    {
        "name": "assetPrivateDetails",
        "policy": "OR('Org1MSP.member')",
        "requiredPeerCount": 0,
        "maxPeerCount": 3,
        "blockToLive": 3,
        "memberOnlyRead": true
    }
]
```

### 4.10.2 チェーンコードでのプライベートデータ利用例

プライベートデータコレクションにデータを書き込む例を以下に示します。

```go
func (s *SmartContract) CreateAssetPrivateData(ctx contractapi.TransactionContextInterface, id string) error {
    // パブリックデータの保存
    asset := Asset{
        ID:     id,
        Owner:  "公開所有者",
        Value:  100,
    }
    assetJSON, err := json.Marshal(asset)
    if err != nil {
        return err
    }
    err = ctx.GetStub().PutState(id, assetJSON)
    if err != nil {
        return err
    }

    // プライベートデータの保存
    privateData := map[string]interface{}{
        "owner": "秘密の所有者",
        "value": "極秘の値",
    }
    privateDataJSON, err := json.Marshal(privateData)
    if err != nil {
        return err
    }
    return ctx.GetStub().PutPrivateData("assetPrivateDetails", id, privateDataJSON)
}
```

この実装により、実際の資産データはパブリックに公開されず、プライベートコレクション内で管理されます。
