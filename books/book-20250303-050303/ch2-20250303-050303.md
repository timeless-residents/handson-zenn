# 2. 環境構築：Hyperledger Fabric 開発環境のセットアップ

本章では、Hyperledger Fabric の実践開発を始めるための環境構築手順について、詳細かつ実践的に解説します。Apple Silicon 搭載の Mac（M1/M2/M3）を中心とした macOS 環境において、必要なツールのインストール方法、環境変数の設定、Docker や VSCode の導入、さらには Fabric サンプルやバイナリのダウンロード方法まで、段階的に説明していきます。各セクションは、実際の開発現場で直面する課題に対応できるよう、具体的なコマンド例やトラブルシューティングのヒントも豊富に盛り込んでいます。

本章の学習を終えると、読者は以下のことができるようになります。

- macOS 環境において、必要なツール（Homebrew、Git、Docker、Go、Node.js、jq、VSCode など）をインストールし、正しく動作させる方法を理解できる
- Hyperledger Fabric のサンプルコードやバイナリをダウンロードし、環境変数を設定する手順を把握できる
- Docker 環境の動作確認や、テストネットワークの起動、停止、再起動に関する基本的な操作を習得できる
- 発生しがちなトラブルやエラーに対する対処方法を理解し、環境構築の際の問題解決に役立てることができる

以下、各セクションごとに詳細な解説を行います。

---

## 2.1 はじめに

Hyperledger Fabric は、エンタープライズ向けブロックチェーンプラットフォームとして、企業間での安全かつ効率的なデータ共有を実現するために設計されています。しかし、その高機能なプラットフォームを利用するには、まず適切な開発環境を構築する必要があります。特に Apple Silicon 搭載の Mac は、従来の Intel ベースの Mac とは異なる点があり、ツールのインストールや設定に注意が必要です。本節では、開発環境構築の全体像と、これから解説する各手順の概要を紹介します。

Hyperledger Fabric の開発環境は、大きく以下の 3 つのフェーズに分けられます。

1. **必要ツールのインストール**  
   macOS におけるパッケージマネージャー Homebrew や Git、Docker、Go、Node.js、jq、VSCode など、Fabric 開発に必要な各種ツールのインストール手順を確認します。

2. **環境変数および設定ファイルの構築**  
   Fabric のバイナリやサンプルコードを使用するために、環境変数の設定や設定ファイルの配置方法を学びます。

3. **テストネットワークの起動と動作確認**  
   ダウンロードした Fabric サンプルを使用し、テストネットワークの起動、チャネル作成、ネットワーク構成の確認、さらにはトラブルシューティングの方法について、実践的に確認していきます。

本章を通して、読者は開発環境構築に必要な全知識を網羅的に習得し、次章以降のチェーンコード開発やネットワーク運用にスムーズに進むための基盤を確立できるようになります。

## 2.2 必要なツールのインストール

### 2.2.1 Homebrew のインストール

Homebrew は、macOS 向けのパッケージマネージャーであり、必要なソフトウェアを簡単にインストールできるため、まずはこれを導入します。Apple Silicon 搭載の Mac では、Homebrew のインストール先が従来のパスとは異なります。以下のコマンドをターミナルに入力してインストールを行います。

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

インストール後、Homebrew の実行ファイルのパスをシェル設定ファイル（.zshrc や .bash_profile）に追加します。Apple Silicon では次のように設定します。

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zshrc
source ~/.zshrc
```

この操作により、brew コマンドがシェル内で認識され、今後のツールインストールが円滑に行えます。

### 2.2.2 Git のインストール

ソースコードの管理およびバージョン管理ツールとして Git は必須です。Homebrew を使ってインストールするには、以下のコマンドを実行します。

```bash
brew install git
```

Git のインストール後は、ユーザー名やメールアドレスなどの初期設定も行いましょう。

```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

### 2.2.3 Docker Desktop のインストール

Hyperledger Fabric は、複数のコンテナを用いてネットワークを構築するため、Docker の導入は必須です。Apple Silicon 対応版の Docker Desktop を、以下の公式サイトからダウンロードしてインストールします。

- [Docker Desktop for Mac (Apple Silicon)](https://www.docker.com/products/docker-desktop/)

インストール後、Docker Desktop を起動し、動作確認を行います。リソースの割り当てについては、以下の推奨設定を参考にしてください。

- **CPU コア**: 4 コア以上
- **メモリ**: 8GB 以上
- **ディスク容量**: 50GB 以上

### 2.2.4 Go 言語のインストール

Hyperledger Fabric のチェーンコード開発には、Go 言語が推奨されています。Homebrew を利用して Go をインストールするには、次のコマンドを実行します。

```bash
brew install go
```

インストール後、Go の開発環境を整えるために、以下の環境変数をシェル設定ファイルに追加します。

```bash
echo 'export GOPATH=$HOME/go' >> ~/.zshrc
echo 'export PATH=$PATH:$GOPATH/bin' >> ~/.zshrc
source ~/.zshrc
```

これにより、Go 言語のビルドツールやライブラリが正しく動作するようになります。

### 2.2.5 Node.js と npm のインストール

Fabric のアプリケーション開発や SDK 利用には、Node.js および npm の導入も重要です。以下のコマンドで Homebrew を使用してインストールします。

```bash
brew install node
```

インストールが完了したら、バージョン確認を行い、正しく導入されたことを確認してください。

```bash
node -v
npm -v
```

### 2.2.6 jq のインストール

jq は JSON データの加工や整形を行うための軽量コマンドラインツールです。Hyperledger Fabric の設定やログ解析で活用するため、以下のコマンドでインストールします。

```bash
brew install jq
```

### 2.2.7 Visual Studio Code のインストール

コード編集用の統合開発環境（IDE）として、Visual Studio Code（VSCode）は非常に有用です。Homebrew の cask コマンドを利用してインストールします。

```bash
brew install --cask visual-studio-code
```

インストール後、VSCode を起動して、開発に必要な拡張機能（後述）を追加していきます。

---

## 2.3 VSCode 拡張機能の導入

VSCode は、Hyperledger Fabric の開発において、コード編集やデバッグ、コンテナ管理など多くの機能を提供します。以下に、特に推奨される拡張機能とその導入方法を示します。

### 2.3.1 IBM Blockchain Platform Extension

この拡張機能は、Fabric ネットワークの管理やチェーンコードのデプロイ、デバッグに特化したツールです。VSCode の拡張機能マーケットプレイスで「IBM Blockchain Platform」を検索し、インストールします。インストール後、サイドバーに専用のブロックチェーンビューが追加され、ネットワーク構成の確認や操作が簡単に行えます。

### 2.3.2 Go Extension

Go 言語でチェーンコードを開発するためには、Go 用の拡張機能が必要です。拡張機能マーケットプレイスで「Go」を検索し、インストールします。これにより、コード補完、Lint、デバッグなど、Go 開発に必要な機能が強化されます。

### 2.3.3 Docker Extension

Docker コンテナの管理を VSCode 内で行うために、Docker 拡張機能をインストールします。これにより、コンテナの状態確認、ログの閲覧、イメージの管理が容易になります。

### 2.3.4 YAML Extension

Hyperledger Fabric の設定ファイル（configtx.yaml、core.yaml など）は YAML 形式で記述されているため、YAML 拡張機能をインストールして、構文チェックや補完機能を活用します。

## 2.4 Hyperledger Fabric サンプルとバイナリのダウンロード

Hyperledger Fabric の開発を始めるためには、サンプルコードやバイナリのダウンロードが不可欠です。公式の Fabric Samples リポジトリには、ネットワーク構築、チェーンコード開発、運用管理などのためのサンプルが豊富に用意されています。以下の手順でサンプルとバイナリをダウンロードします。

### 2.4.1 サンプルディレクトリの作成と移動

まず、ホームディレクトリに Fabric Samples 用のディレクトリを作成し、そこに移動します。

```bash
mkdir -p ~/fabric-samples
cd ~/fabric-samples
```

### 2.4.2 ダウンロードスクリプトの実行

公式に用意されたスクリプトを使用して、Fabric サンプルとバイナリをダウンロードします。以下のコマンドは、Fabric の特定バージョン（例：2.5.4 と 1.5.6）をダウンロードするものです。

```bash
curl -sSL https://bit.ly/2ysbOFE | bash -s -- 2.5.4 1.5.6
```

このスクリプトは、以下の処理を自動で行います。

- Fabric サンプルコードのダウンロード
- Fabric バイナリのダウンロード
- ドキュメントや設定ファイルの取得

ダウンロードが完了すると、`fabric-samples` ディレクトリ内に複数のサンプルプロジェクトと、`bin`、`config` などのディレクトリが作成されます。

---

## 2.5 環境変数の設定

Fabric バイナリやサンプルコードを利用するためには、適切な環境変数の設定が必要です。以下の手順で、主要な環境変数を設定し、シェルに反映させます。

### 2.5.1 PATH の設定

Fabric のバイナリが保存されている `~/fabric-samples/bin` を PATH に追加します。シェルの設定ファイル（例：.zshrc）に以下を追記します。

```bash
echo 'export PATH=$PATH:$HOME/fabric-samples/bin' >> ~/.zshrc
source ~/.zshrc
```

### 2.5.2 FABRIC_CFG_PATH の設定

Fabric の設定ファイルが保存されているディレクトリを、FABRIC_CFG_PATH 環境変数に設定します。

```bash
echo 'export FABRIC_CFG_PATH=$HOME/fabric-samples/config' >> ~/.zshrc
source ~/.zshrc
```

これにより、Fabric の各種コマンドが適切な設定ファイルを参照できるようになります。

---

## 2.6 Docker 環境の動作確認

Fabric ネットワークは、Docker コンテナ上で動作するため、Docker 環境が正しく構築されているか確認する必要があります。以下のコマンドで、Docker と Docker Compose のバージョン情報が表示されるか確認してください。

```bash
docker version
docker-compose version
```

両コマンドともに、バージョン情報が正常に表示されれば、Docker 環境は正しくセットアップされています。エラーが発生する場合は、Docker Desktop の設定やリソース割り当てを再確認してください。

## 2.7 セットアップスクリプトの利用

環境構築手順を自動化するために、Fabric Samples にはセットアップスクリプトが用意されています。これにより、毎回手動で各ツールをインストールする手間を省くことができます。以下は、セットアップスクリプトの使用例です。

### 2.7.1 セットアップスクリプトの実行

まず、スクリプトの権限を確認し、実行可能にします。例として、`scripts/setup.sh` を使用する場合は次のようにします。

```bash
chmod +x ./scripts/setup.sh
./scripts/setup.sh
```

このスクリプトは、ネットワークの起動前に不要な Docker コンテナやボリュームをクリーンアップし、環境の初期状態を整えます。

## 2.8 デモネットワークの検証

環境構築が完了したら、Fabric サンプルを用いて実際にネットワークを起動し、動作確認を行います。ここでは、テストネットワークの起動、チャネルの作成、コンテナの状態確認、ネットワーク停止の手順について説明します。

### 2.8.1 テストネットワークの起動

Fabric Samples に含まれる `test-network` は、簡単なネットワーク構築のためのプロジェクトです。以下のコマンドで、テストネットワークを起動します。

```bash
cd ~/fabric-samples/test-network
./network.sh up
```

実行後、以下のようなメッセージが表示されるはずです。

```
Creating network "fabric_test" with the default driver
Creating orderer.example.com    ... done
Creating peer0.org1.example.com ... done
Creating peer0.org2.example.com ... done
```

### 2.8.2 チャネルの作成と参加確認

ネットワークが起動したら、次にチャネルを作成します。チャネルは、参加者間でプライベートな取引を行うための論理的な区分です。以下のコマンドでチャネルを作成します。

```bash
./network.sh createChannel -c mychannel
```

チャネルが作成された後、各ピアがチャネルに参加しているかどうかを確認します。Org1 のピアの場合は、以下のコマンドを実行します。

```bash
peer channel list
```

出力例は以下のようになります。

```
Channels peers has joined:
  mychannel
```

### 2.8.3 ネットワーク設定の検証

さらに、ネットワークの各コンポーネント（オーダラー、ピア、CA サーバー）の状態を確認します。Docker コンテナの一覧を確認するには、以下のコマンドを使用します。

```bash
docker ps
```

各コンテナのログも確認し、正常に動作していることをチェックします。

```bash
docker logs -f peer0.org1.example.com
docker logs -f orderer.example.com
```

## 2.9 トラブルシューティング

環境構築中に発生しうる一般的な問題とその解決方法について、以下にまとめます。これらの対策を理解しておくことで、トラブル発生時に迅速に対応できるようになります。

### 2.9.1 Docker コンテナの起動エラー

- **原因**: Docker Desktop が起動していない、または十分なリソースが割り当てられていない可能性があります。
- **対策**:
  1. Docker Desktop を起動し、設定で CPU、メモリ、ディスク容量のリソースを確認する。
  2. 以下のコマンドで不要なコンテナやボリュームを削除する：
  
     ```bash
     docker system prune -a
     docker volume prune
     ```

### 2.9.2 バイナリやサンプルのダウンロード失敗

- **原因**: インターネット接続の不具合、またはプロキシ設定の問題が考えられます。
- **対策**:
  1. インターネット接続を確認し、必要に応じてプロキシ設定を行う。
  2. 再度以下のコマンドを実行して、ダウンロードを試みる：
  
     ```bash
     curl -sSL https://bit.ly/2ysbOFE | bash -s -- 2.5.4 1.5.6
     ```

### 2.9.3 環境変数が反映されない

- **原因**: シェル設定ファイルが正しく読み込まれていない可能性があります。
- **対策**:
  1. 設定ファイル（~/.zshrc や ~/.bash_profile）を再読み込みする：
  
     ```bash
     source ~/.zshrc
     ```
  
  2. PATH や FABRIC_CFG_PATH の設定が正しいか確認する。

### 2.9.4 テストネットワークの起動エラー

- **原因**: ネットワーク内のコンテナ間通信や設定ファイルの不整合が原因となる場合があります。
- **対策**:
  1. 既存のネットワークを停止し、環境をクリーンアップする：
  
     ```bash
     ./network.sh down
     docker system prune -a
     docker volume prune
     ```
  
  2. 再度ネットワークを起動し、ログを確認して問題箇所を特定する。

## 2.10 環境構築のベストプラクティス

開発環境を構築する際には、以下のベストプラクティスを守ることで、スムーズな開発が可能となります。

### 2.10.1 定期的なアップデートとバックアップ

- **ツールのアップデート**: Homebrew、Docker、Go など、各ツールは定期的にアップデートを行い、最新のセキュリティパッチや機能拡張を取り入れることが重要です。
- **環境設定のバックアップ**: シェル設定ファイルや重要な設定ファイルは、Git リポジトリやバックアップツールを用いて定期的にバックアップしましょう。

### 2.10.2 スクリプトによる自動化

手動でのセットアップ作業はミスの温床となります。できる限りスクリプトを利用して環境構築手順を自動化し、再現性を確保しましょう。例えば、セットアップスクリプトを作成して、以下の手順を一括実行できるようにします。

```bash
#!/bin/bash
# setup-environment.sh

# Homebrew のインストール確認
if ! command -v brew &> /dev/null; then
  echo "Homebrew が見つかりません。インストールを開始します。"
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
fi

# 必要なツールのインストール
brew install git docker go node jq

# VSCode のインストール
brew install --cask visual-studio-code

# 環境変数の設定
echo 'export PATH=$PATH:$HOME/fabric-samples/bin' >> ~/.zshrc
echo 'export FABRIC_CFG_PATH=$HOME/fabric-samples/config' >> ~/.zshrc
source ~/.zshrc

echo "環境構築が完了しました。"
```

このように、自動化スクリプトを用意することで、環境構築にかかる工数を大幅に削減できます。

### 2.10.3 ドキュメントの整備

環境構築手順やトラブルシューティングの情報は、プロジェクトのドキュメントとして整備しておくことが重要です。これにより、新たなメンバーが参加した際にもスムーズに環境設定が行え、問題発生時の原因追及が容易になります。

**Q2: 環境変数が正しく設定されない場合はどうすればよいですか？**  
A2: シェル設定ファイル（.zshrc や .bash_profile）を確認し、`source` コマンドで再読み込みしてください。また、設定内容に誤りがないかダブルチェックすることを推奨します。

**Q3: セットアップスクリプトが失敗する場合の対処法は？**  
A3: スクリプト内でエラーが発生した場合、エラーメッセージをよく確認し、各コマンドを手動で実行して問題箇所を特定してください。インターネット接続の確認や、各ツールのバージョンチェックも有効です。
