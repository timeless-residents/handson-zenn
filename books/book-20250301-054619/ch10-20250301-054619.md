## 第10章：Fine-tuning：モデルをカスタマイズする

大規模言語モデル（LLM）は、その汎用性の高さから様々なタスクで利用されていますが、特定のドメインやタスクにおいては、必ずしも最適なパフォーマンスを発揮できるとは限りません。そこで重要になるのが **Fine-tuning** です。Fine-tuningは、既存の学習済みモデルを、より限定的なデータセットを用いて追加学習させることで、特定のタスクに特化した性能を引き出す技術です。この章では、Fine-tuningの基礎から実践的なテクニック、評価方法、そしてデプロイまでを網羅的に解説し、読者の皆様が自身のプロジェクトでFine-tuningを効果的に活用できるようになることを目指します。

### Fine-tuningの概要とメリット

#### 1. 概要と重要性

Fine-tuningとは、大規模なデータセットで事前学習されたモデル（Pre-trained Model）を、より小規模な特定のタスクに最適化されたデータセットで追加学習させるプロセスです。これにより、モデルは元の汎用的な知識に加え、特定のタスクに特化した知識を獲得し、そのタスクにおけるパフォーマンスを向上させることができます。

Fine-tuningの重要性は、主に以下の点に集約されます。

*   **データ効率:** 大規模なデータセットをゼロから学習させる必要がないため、少ないデータ量でも高い精度を達成できます。
*   **計算資源の節約:** 事前学習済みのモデルを再利用するため、学習に必要な計算コストを大幅に削減できます。
*   **迅速な開発:** 新しいタスクへの適応が容易であり、開発サイクルを短縮できます。

#### 2. 特徴と利点

Fine-tuningの主な特徴と利点は以下の通りです。

*   **高い精度:** 特定のタスクに特化したデータで学習することで、汎用モデルよりも高い精度を期待できます。
*   **適応性:** 様々なタスクに対応可能であり、テキスト分類、テキスト生成、質問応答など幅広い応用が可能です。
*   **カスタマイズ性:** 学習データやハイパーパラメータを調整することで、ニーズに合わせたモデルを構築できます。
*   **知識の転移:** 事前学習で得られた知識を新しいタスクに転移できるため、学習効率が向上します。

#### 3. 事前準備と前提条件

Fine-tuningを行う前に、以下の準備が必要です。

*   **学習済みモデルの選定:** 目的のタスクに適した事前学習済みモデルを選択します。Hugging Face Transformersライブラリなどを活用すると、様々なモデルを簡単に利用できます。
*   **データセットの準備:** Fine-tuningに使用するデータセットを準備します。データセットは、目的のタスクに合致している必要があり、十分な量と品質が求められます。
*   **開発環境の構築:** Python、PyTorch、TensorFlowなどの必要なライブラリをインストールし、GPU環境を構築します。
*   **Fine-tuningフレームワークの選択:** Hugging Face Transformers、LightningなどのFine-tuningをサポートするフレームワークを選択します。

#### 4. 基本的な使い方

ここでは、Hugging Face Transformersライブラリを使ったFine-tuningの基本的な手順を説明します。

**例：テキスト分類のFine-tuning**

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer, TrainingArguments
from datasets import load_dataset

# 1. モデルとトークナイザーのロード
model_name = "bert-base-uncased"  # 使用する事前学習済みモデル
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2) # 2クラス分類

# 2. データセットのロード (例: SST-2)
dataset = load_dataset("sst2")
train_dataset = dataset["train"]
eval_dataset = dataset["validation"]

# 3. データセットの前処理
def tokenize_function(examples):
    return tokenizer(examples["text"], padding="max_length", truncation=True)

tokenized_train_dataset = train_dataset.map(tokenize_function, batched=True)
tokenized_eval_dataset = eval_dataset.map(tokenize_function, batched=True)

# 4. Trainerの定義
training_args = TrainingArguments(
    output_dir="./results",
    evaluation_strategy="epoch",
    num_train_epochs=3,          # エポック数
    per_device_train_batch_size=16, # バッチサイズ
    per_device_eval_batch_size=16,
    learning_rate=2e-5,          # 学習率
    weight_decay=0.01,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_train_dataset,
    eval_dataset=tokenized_eval_dataset,
    tokenizer=tokenizer,
)

# 5. Fine-tuningの実行
trainer.train()

# 6. モデルの保存
model.save_pretrained("./fine_tuned_model")
tokenizer.save_pretrained("./fine_tuned_model")
```

**コード解説:**

*   `AutoTokenizer.from_pretrained()`と`AutoModelForSequenceClassification.from_pretrained()`で、事前学習済みモデルとそのトークナイザーをロードします。`num_labels`で分類するクラス数を指定します。
*   `load_dataset()`でHugging Face Datasetsライブラリからデータセットをロードします。ここではSST-2 (Stanford Sentiment Treebank)を使用しています。
*   `tokenize_function()`でテキストデータをトークン化し、モデルに入力できる形式に変換します。`padding`と`truncation`でテキストの長さを調整します。
*   `TrainingArguments`で学習に関する設定を行います。`output_dir`はモデルの保存先、`evaluation_strategy`は評価のタイミング、`num_train_epochs`はエポック数、`per_device_train_batch_size`はバッチサイズ、`learning_rate`は学習率、`weight_decay`は正則化の強さを指定します。
*   `Trainer`でモデル、学習設定、データセット、トークナイザーを指定し、Fine-tuningを実行します。
*   `model.save_pretrained()`と`tokenizer.save_pretrained()`でFine-tuning後のモデルとトークナイザーを保存します。

#### 5. 実践的なテクニック

Fine-tuningの効果を最大限に引き出すためには、以下のテクニックを考慮することが重要です。

*   **ハイパーパラメータの調整:** 学習率、バッチサイズ、エポック数などのハイパーパラメータを調整することで、モデルの精度を向上させることができます。グリッドサーチやランダムサーチなどの手法を用いて、最適なハイパーパラメータを見つけ出すことが一般的です。
*   **学習率スケジューラの利用:** 学習率を一定にするのではなく、学習の進行に合わせて変化させることで、より安定した学習を実現できます。AdamWオプティマイザーに組み込まれているような、warmup期間を設定するなどのスケジューラが有効です。
*   **データ拡張:** データセットのサイズが小さい場合、データ拡張を行うことでモデルの汎化性能を高めることができます。テキストの言い換え、ランダムな削除、挿入などの手法があります。
*   **レイヤーごとの学習率調整:** モデルのレイヤーごとに異なる学習率を設定することで、Fine-tuningの効果を向上させることができます。一般的に、事前学習済みのレイヤーは学習率を小さく、新しいタスクに適応させるレイヤーは学習率を大きく設定します。
*   **アダプターモジュールの利用:** モデル全体をFine-tuningするのではなく、一部のレイヤー（アダプターモジュール）のみを学習させることで、計算コストを削減し、過学習を防ぐことができます。
*   **MixUpやCutMixなどの正則化手法:** これらの手法は、学習データ間の補間を行うことで、モデルの汎化性能を高めます。
*   **知識蒸留:** より小さいモデルに対して、Fine-tuning済みの大きなモデルの知識を転移させることで、軽量でありながら高性能なモデルを構築できます。

#### 7. トラブルシューティング

Fine-tuningを行う際に、いくつかの問題が発生することがあります。以下に代表的な問題とその解決策を紹介します。

*   **過学習:** 学習データに過剰に適合し、未知のデータに対する汎化性能が低下する。
    *   **解決策:** データ拡張、正則化（L1/L2正則化、ドロップアウト）、学習率の調整、早期終了などの手法を試す。
*   **学習の不安定性:** 学習が収束せず、損失関数が振動する。
    *   **解決策:** 学習率を下げる、バッチサイズを小さくする、オプティマイザーを変更する（例：AdamからSGD）、warmup期間を設定するなどの手法を試す。
*   **メモリ不足:** GPUメモリが不足し、学習が中断される。
    *   **解決策:** バッチサイズを小さくする、勾配累積を行う、モデルのサイズを小さくする、混合精度学習を行うなどの手法を試す。
*   **評価指標の停滞:** 学習が進んでも、評価指標が改善されない。
    *   **解決策:** 学習データを確認する（ノイズや誤りがないか）、モデルのアーキテクチャを見直す、学習タスクの定義を見直すなどの手法を試す。
*   **Out of Memoryエラー:** バッチサイズを小さくしてもOOMが発生する場合、不要な変数やテンソルを削除したり、`torch.cuda.empty_cache()`を呼び出してキャッシュをクリアする。
*   **学習データの不均衡:** 特定のクラスのデータが極端に少ない場合、データ拡張、重み付き損失関数、サンプリング調整などの手法を試す。

**注意点:**

*   Fine-tuningは、事前学習済みのモデルに依存するため、元のモデルの性能を超えることは難しい。
*   Fine-tuningに使用するデータセットは、目的のタスクに合致している必要があり、十分な量と品質が求められる。
*   Fine-tuningは、計算コストがかかるため、十分な計算資源が必要となる。

*   **学習データ:** モデルが学習に使用したデータセットを確認し、目的のタスクと類似しているかを確認します。
*   **ライセンス:** モデルのライセンスを確認し、商用利用が可能かどうかを確認します。

*   **テキスト分類:** `bert-base-uncased`、`roberta-base`
*   **テキスト生成:** `gpt2`、`t5-small`
*   **質問応答:** `bert-large-uncased-whole-word-masking-finetuned-squad`

```python
from transformers import AutoModelForSequenceClassification

```

**2. データセットの準備:**

Fine-tuningに使用するデータセットを準備します。データセットは、目的のタスクに合致している必要があり、十分な量と品質が求められます。

*   **データ収集:** 公開されているデータセットを利用するか、自身でデータを収集します。
*   **データクリーニング:** データセットにノイズや誤りがないかを確認し、必要に応じて修正します。
*   **データの前処理:** テキストデータのトークン化、数値データのスケーリングなど、モデルに入力できる形式にデータを変換します。
*   **データ分割:** データセットを学習用、検証用、テスト用に分割します。一般的に、学習用データは全体の80%、検証用データは10%、テスト用データは10%程度に分割します。

**例:**

```python
from datasets import load_dataset

dataset = load_dataset("imdb")
train_dataset = dataset["train"]
eval_dataset = dataset["test"]
```

*   **GPUの認識:** GPUが正しく認識されていない場合、学習が非常に遅くなることがあります。GPUドライバが正しくインストールされているか、PyTorchやTensorFlowがGPUを認識しているかを確認してください。

### Fine-tuningの実行

#### 1. 概要と重要性

Fine-tuningの準備が整ったら、いよいよモデルの学習を行います。このセクションでは、Fine-tuningの実行方法について詳しく解説します。様々なテクニックや設定項目を理解し、効果的なFine-tuningを実現しましょう。

#### 2. 特徴と利点

Fine-tuningを適切に実行することで、以下の利点が得られます。

*   **モデルの精度向上:** 準備したデータセットを用いてモデルを学習することで、特定のタスクに対する精度を向上させることができます。
*   **効率的な学習:** 事前学習済みのモデルを利用するため、ゼロから学習するよりも少ない計算コストで学習できます。
*   **柔軟なカスタマイズ:** ハイパーパラメータや学習方法を調整することで、モデルを柔軟にカスタマイズできます。

#### 3. 事前準備と前提条件

*   第10.2章で説明したデータセットの準備と開発環境の構築が完了していること。
*   使用するFine-tuningフレームワーク（Hugging Face Transformersなど）の基本的な使い方を理解していること。
*   GPU環境が利用可能であること（推奨）。

#### 4. 基本的な使い方

ここでは、Hugging Face Transformersライブラリを使ったFine-tuningの基本的な手順を説明します。

**1. モデルとトークナイザーのロード:**

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification

model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2) # 例：2クラス分類
```

**2. データセットの前処理:**

```python
from datasets import load_dataset

dataset = load_dataset("glue", "mrpc") # 例：GLUE MRPCデータセット

def tokenize_function(examples):
    return tokenizer(examples["text1"], examples["text2"], padding="max_length", truncation=True)

tokenized_datasets = dataset.map(tokenize_function, batched=True)
```

**3. Trainerの定義:**

```python
from transformers import TrainingArguments, Trainer

training_args = TrainingArguments(
    output_dir="./results",
    evaluation_strategy="epoch",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    weight_decay=0.01,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    tokenizer=tokenizer,
)
```

**4. Fine-tuningの実行:**

```python
trainer.train()
```

**5. モデルの保存:**

```python
model.save_pretrained("./fine_tuned_model")
tokenizer.save_pretrained("./fine_tuned_model")
```

#### 5. 実践的なテクニック

*   **混合精度学習 (Mixed Precision Training):** `fp16=True`をTrainingArgumentsに追加することで、GPUメモリの使用量を削減し、学習速度を向上させることができます。大規模なモデルをFine-tuningする際に特に有効です。

```python
training_args = TrainingArguments(
    output_dir="./results",
    evaluation_strategy="epoch",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    weight_decay=0.01,
    fp16=True,  # 混合精度学習を有効化
)
```

*   **勾配累積 (Gradient Accumulation):** バッチサイズを小さくせざるを得ない場合に、`gradient_accumulation_steps`を設定することで、複数のミニバッチの勾配を累積し、より大きなバッチサイズで学習するのと同等の効果を得ることができます。

```python
training_args = TrainingArguments(
    output_dir="./results",
    evaluation_strategy="epoch",
    num_train_epochs=3,
    per_device_train_batch_size=8, # 小さめのバッチサイズ
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    weight_decay=0.01,
    gradient_accumulation_steps=2, # 勾配累積ステップ数
)
```

*   **チェックポイントの保存:** `save_strategy="epoch"`や`save_steps`を設定することで、学習中に定期的にモデルのチェックポイントを保存することができます。これにより、学習が中断された場合でも、途中から再開することができます。

```python
training_args = TrainingArguments(
    output_dir="./results",
    evaluation_strategy="epoch",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    weight_decay=0.01,
    save_strategy="epoch", # 各エポック終了時に保存
    #save_steps=500, # 500ステップごとに保存 (save_strategy="steps"が必要)
)
```

*   **より高度なオプティマイザの利用:** AdamWは多くの場合に有効ですが、より高度なオプティマイザ（例：Adafactor, Sophia）を試すことで、精度が向上する可能性があります。

*   **学習率スケジューラの調整:** `lr_scheduler_type`パラメータで学習率スケジューラの種類を変更できます。`"linear"`, `"cosine"`, `"polynomial"`などが利用可能です。

#### 6. 応用例とユースケース

*   **テキスト生成:** 事前学習済みのGPT-2モデルをFine-tuningして、特定のスタイルやテーマのテキストを生成する。
*   **質問応答:** 事前学習済みのBERTモデルをFine-tuningして、特定のドメイン（医療、法律など）に関する質問に答えるシステムを構築する。
*   **翻訳:** 事前学習済みのMarianMTモデルをFine-tuningして、特定の言語ペア間の翻訳精度を向上させる。

#### 7. トラブルシューティング

*   **GPUメモリ不足:** バッチサイズを小さくする、勾配累積を行う、混合精度学習を有効にする、モデルのサイズを小さくするなどの対策を講じます。
*   **学習が進まない:** 学習率を調整する、オプティマイザーを変更する、データセットを確認する、モデルのアーキテクチャを見直すなどの対策を講じます。
*   **損失関数が発散する:** 学習率を下げる、勾配クリッピングを行う、データセットを確認するなどの対策を講じます。
*   **CUDA related error:** CUDAのバージョンが適切でない、GPUドライバが古いなどの可能性があります。CUDAとGPUドライバのバージョンを確認し、必要に応じてアップデートしてください。

*   **継続的な改善:** デプロイ後のモデルをモニタリングすることで、性能劣化を検出し、モデルを継続的に改善することができます。

#### 4. 基本的な使い方

**1. モデルのロード:**

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification

model_path = "./fine_tuned_model" # Fine-tuning済みのモデルのパス
tokenizer = AutoTokenizer.from_pretrained(model_path)
model = AutoModelForSequenceClassification.from_pretrained(model_path)
```

**2. 評価の実行:**

```python
import torch
from datasets import load_dataset
from torch.utils.data import DataLoader
from tqdm import tqdm

# データセットの準備
dataset = load_dataset("glue", "mrpc") # 例：GLUE MRPCデータセット
test_dataset = dataset["test"]

def tokenize_function(examples):
    return tokenizer(examples["text1"], examples["text2"], padding="max_length", truncation=True, return_tensors="pt")

tokenized_test_dataset = test_dataset.map(tokenize_function, batched=True)
tokenized_test_dataset = tokenized_test_dataset.remove_columns(["text1", "text2", "idx"])
tokenized_test_dataset = tokenized_test_dataset.rename_column("label", "labels")
tokenized_test_dataset.set_format("torch")

# データローダーの準備
dataloader = DataLoader(tokenized_test_dataset, batch_size=32)

# 評価の実行
model.eval()
device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)

correct_predictions = 0
total_predictions = 0

with torch.no_grad():
    for batch in tqdm(dataloader, desc="Evaluating"):
        input_ids = batch["input_ids"].to(device)
        attention_mask = batch["attention_mask"].to(device)
        labels = batch["labels"].to(device)

        outputs = model(input_ids, attention_mask=attention_mask)
        logits = outputs.logits
        predictions = torch.argmax(logits, dim=-1)

        correct_predictions += torch.sum(predictions == labels).item()
        total_predictions += labels.size(0)

accuracy = correct_predictions / total_predictions
print(f"Accuracy: {accuracy}")
```

**3. デプロイ:**

デプロイの方法は、デプロイ先の環境や目的に応じて異なります。以下に代表的なデプロイ方法を紹介します。

*   **クラウドプラットフォーム:** AWS SageMaker, Google Cloud AI Platform, Azure Machine Learningなどのクラウドプラットフォームを利用して、モデルをデプロイします。スケーラビリティや可用性が高く、運用管理も容易です。
*   **コンテナ:** Dockerコンテナにモデルをパッケージングし、Kubernetesなどのコンテナオーケストレーションツールを利用してデプロイします。環境の再現性が高く、様々な環境で動作させることができます。
*   **APIサーバー:** FlaskやFastAPIなどのフレームワークを利用してAPIサーバーを構築し、モデルをAPIとして公開します。REST APIやGraphQL APIなど、様々なAPI形式に対応できます。

**例：FastAPIを使ったAPIサーバーの構築**

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch

app = FastAPI()

# モデルのロード
model_path = "./fine_tuned_model"
tokenizer = AutoTokenizer.from_pretrained(model_path)
model = AutoModelForSequenceClassification.from_pretrained(model_path)
device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)
model.eval()

# リクエストボディの定義
class InputText(BaseModel):
    text1: str
    text2: str

# エンドポイントの定義
@app.post("/predict")
async def predict(input_text: InputText):
    try:
        # テキストのトークン化
        inputs = tokenizer(input_text.text1, input_text.text2, padding=True, truncation=True, return_tensors="pt").to(device)

        # 推論の実行
        with torch.no_grad():
            outputs = model(**inputs)
            logits = outputs.logits
            prediction = torch.argmax(logits, dim=-1).item()

        return {"prediction": prediction}
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

# 実行方法：uvicorn main:app --reload
```
