## 6. HonoでAPI開発 - CRUD操作とデータ永続化

この章では、Honoを使ってCRUD APIを構築し、データの永続化を実現する方法について解説します。API開発におけるCRUD操作の実装、データベースの選定、ORM/ODMの利用、そして型定義とバリデーションの重要性について、具体的なコード例を交えながら詳しく解説していきます。

### 6.1 HonoでCRUD APIを構築する

**概要と重要性**

CRUD（Create, Read, Update, Delete）は、API開発における基本的な操作です。これらの操作を効率的に実装することで、データの作成、取得、更新、削除をスムーズに行い、アプリケーションの基盤を構築できます。Honoを使うことで、軽量かつ高速なAPIを簡単に構築できます。

**特徴と利点**

*   **高速なルーティング:** Honoは非常に高速なルーティングエンジンを搭載しており、リクエストを効率的に処理できます。
*   **シンプルなAPI:** HonoのAPIはシンプルで直感的であり、初心者でも容易に学習できます。
*   **ミドルウェア:** ミドルウェアを利用することで、認証、ロギング、エラーハンドリングなどの共通処理を簡単に実装できます。
*   **TypeScriptサポート:** TypeScriptを完全にサポートしており、型安全なAPIを構築できます。

**事前準備と前提条件**

*   Node.jsとnpm（またはYarn、pnpm）がインストールされていること。
*   Honoプロジェクトがセットアップされていること。まだの場合は、以下のコマンドでプロジェクトを作成します。

    ```bash
    npm create hono my-hono-app
    cd my-hono-app
    npm install
    ```

**基本的な使い方**

以下の例では、シンプルなメモアプリのCRUD APIをHonoで実装します。

```typescript
import { Hono } from 'hono'
import { zValidator } from '@hono/zod-validator'
import { z } from 'zod'

const app = new Hono()

// メモの型定義
interface Memo {
  id: string
  title: string
  content: string
}

// メモのデータストア (本番環境ではデータベースを使用)
const memos: Memo[] = []

// Zodスキーマの定義
const memoSchema = z.object({
  title: z.string().min(1, { message: "Title must be at least 1 character." }),
  content: z.string().optional(),
});

// GET /memos - メモ一覧を取得
app.get('/memos', (c) => {
  return c.json(memos)
})

// GET /memos/:id - 特定のメモを取得
app.get('/memos/:id', (c) => {
  const id = c.req.param('id')
  const memo = memos.find((memo) => memo.id === id)
  if (!memo) {
    return c.json({ message: 'Memo not found' }, 404)
  }
  return c.json(memo)
})

// POST /memos - メモを作成
app.post('/memos', zValidator('json', memoSchema), (c) => {
  const { title, content } = c.req.valid('json')
  const id = crypto.randomUUID()
  const newMemo: Memo = { id, title, content: content || '' }
  memos.push(newMemo)
  return c.json(newMemo, 201)
})

// PUT /memos/:id - メモを更新
app.put('/memos/:id', zValidator('json', memoSchema), (c) => {
  const id = c.req.param('id')
  const { title, content } = c.req.valid('json')
  const memoIndex = memos.findIndex((memo) => memo.id === id)
  if (memoIndex === -1) {
    return c.json({ message: 'Memo not found' }, 404)
  }
  memos[memoIndex] = { id, title, content: content || '' }
  return c.json(memos[memoIndex])
})

// DELETE /memos/:id - メモを削除
app.delete('/memos/:id', (c) => {
  const id = c.req.param('id')
  const memoIndex = memos.findIndex((memo) => memo.id === id)
  if (memoIndex === -1) {
    return c.json({ message: 'Memo not found' }, 404)
  }
  memos.splice(memoIndex, 1)
  return c.json({ message: 'Memo deleted' }, 204)
})

export default app
```

**実践的なテクニック**

*   **ミドルウェアの活用:** 認証やロギングなどの共通処理はミドルウェアとして実装することで、コードの再利用性と保守性を向上させることができます。
*   **エラーハンドリング:** グローバルなエラーハンドリングを実装することで、予期せぬエラーが発生した場合でもアプリケーションを安定させることができます。
*   **APIバージョニング:** APIの変更を行う場合、バージョニングを導入することで、既存のクライアントへの影響を最小限に抑えることができます。

**応用例とユースケース**

*   **ブログAPI:** ブログ記事の作成、取得、更新、削除を行うAPIを構築することができます。
*   **タスク管理API:** タスクの作成、取得、更新、削除を行うAPIを構築することができます。
*   **ECサイトAPI:** 商品の作成、取得、更新、削除を行うAPIを構築することができます。

**トラブルシューティング**

*   **404エラー:** ルーティングの設定が正しいか確認してください。
*   **500エラー:** サーバー側のエラーが発生しています。ログを確認して原因を特定してください。
*   **CORSエラー:** CORSの設定が正しいか確認してください。

### 6.2 データベースの選択 - SQLite, PostgreSQL, MongoDB

**概要と重要性**

データベースの選択は、API開発において非常に重要な決定です。適切なデータベースを選択することで、データの整合性、パフォーマンス、スケーラビリティを確保することができます。

**特徴と利点**

*   **SQLite:** 軽量でファイルベースのデータベースです。開発環境や小規模なアプリケーションに適しています。
*   **PostgreSQL:** 高度な機能を備えたオープンソースのリレーショナルデータベースです。データの整合性が重要となるアプリケーションに適しています。
*   **MongoDB:** ドキュメント指向のNoSQLデータベースです。柔軟なスキーマが求められるアプリケーションに適しています。

**事前準備と前提条件**

*   各データベースがインストールされ、設定されていること。

**基本的な使い方**

1.  **SQLite:**

    *   `sqlite3`コマンドラインツールを使ってデータベースを作成します。

        ```bash
        sqlite3 mydb.db
        ```

    *   テーブルを作成します。

        ```sql
        CREATE TABLE memos (
          id TEXT PRIMARY KEY,
          title TEXT NOT NULL,
          content TEXT
        );
        ```

2.  **PostgreSQL:**

    *   `psql`コマンドラインツールを使ってデータベースに接続します。

        ```bash
        psql -d mydb -U myuser
        ```

    *   テーブルを作成します。

        ```sql
        CREATE TABLE memos (
          id TEXT PRIMARY KEY,
          title TEXT NOT NULL,
          content TEXT
        );
        ```

3.  **MongoDB:**

    *   MongoDBに接続します。

        ```javascript
        const { MongoClient } = require('mongodb');
        const uri = 'mongodb://localhost:27017/mydb';
        const client = new MongoClient(uri);

        async function run() {
          try {
            await client.connect();
            console.log("Connected correctly to server");

            const db = client.db('mydb');

            // Use the database to insert document
            const memosCollection = db.collection('memos');

          } catch (err) {
            console.log(err.stack);
          } finally {
            await client.close();
          }
        }

        run().catch(console.dir);
        ```
**Honoとの連携例（SQLite）**

```typescript
import { Hono } from 'hono'
import { Database } from 'bun:sqlite'

const app = new Hono()
const db = new Database('mydb.db')

db.exec('CREATE TABLE IF NOT EXISTS memos (id TEXT PRIMARY KEY, title TEXT NOT NULL, content TEXT);')

app.get('/memos', async (c) => {
  const memos = db.prepare('SELECT * FROM memos').all()
  return c.json(memos)
})

app.post('/memos', async (c) => {
  const { title, content } = await c.req.json()
  const id = crypto.randomUUID()
  db.prepare('INSERT INTO memos (id, title, content) VALUES (?, ?, ?)').run(id, title, content)
  return c.json({ id, title, content }, 201)
})

export default app
```

**実践的なテクニック**

*   **接続プーリング:** データベースへの接続数を管理することで、パフォーマンスを向上させることができます。
*   **インデックス:** クエリのパフォーマンスを向上させるために、適切なインデックスを作成します。
*   **トランザクション:** 複数の操作をまとめて実行することで、データの整合性を確保することができます。

**応用例とユースケース**

*   **SQLite:** 小規模な個人プロジェクトやプロトタイピングに適しています。
*   **PostgreSQL:** 企業向けの複雑なデータ管理が必要なアプリケーションに適しています。
*   **MongoDB:** 大量の非構造化データを扱うアプリケーションに適しています。

**トラブルシューティング**

*   **接続エラー:** データベースへの接続設定が正しいか確認してください。
*   **クエリのパフォーマンス:** クエリの実行計画を確認し、ボトルネックを特定してください。
*   **データの整合性:** トランザクションを利用して、データの整合性を確保してください。

### 6.3 ORM/ODMの利用 - Prisma, Drizzle ORM, Mongoose

**概要と重要性**

ORM (Object-Relational Mapper) および ODM (Object-Document Mapper) は、データベース操作を抽象化し、開発者がオブジェクト指向のコードでデータベースを操作できるようにするツールです。これにより、SQLやデータベース固有の構文を直接記述する必要がなくなり、開発効率が向上します。

**特徴と利点**

*   **Prisma:** TypeScriptに特化したORMで、型安全性を重視しています。マイグレーション機能も充実しており、データベースのスキーマ管理を容易にします。
*   **Drizzle ORM:** TypeScriptファーストを謳う軽量なORM。SQLに近い感覚で扱えるため、柔軟性が高いのが特徴です。
*   **Mongoose:** MongoDBに特化したODMで、スキーマ定義やバリデーション機能を備えています。Node.js環境でのMongoDB開発に広く利用されています。

**事前準備と前提条件**

*   Node.jsとnpm（またはYarn、pnpm）がインストールされていること。
*   データベースがセットアップされていること。
*   ORM/ODMのクライアントライブラリがインストールされていること。

**基本的な使い方**

1.  **Prisma:**

    *   Prisma CLIをインストールします。

        ```bash
        npm install -D prisma
        npm install -D @prisma/client
        npx prisma init
        ```

    *   `schema.prisma`ファイルにデータベースのスキーマを定義します。

        ```prisma
        generator client {
          provider = "prisma-client-js"
        }

        datasource db {
          provider = "sqlite"
          url      = "file:./dev.db"
        }

        model Memo {
          id      String   @id @default(uuid())
          title   String
          content String?
        }
        ```

    *   マイグレーションを実行してデータベースを更新します。

        ```bash
        npx prisma migrate dev --name init
        ```

    *   Prisma Clientを使ってデータベースを操作します。

        ```typescript
        import { PrismaClient } from '@prisma/client'

        const prisma = new PrismaClient()

        async function main() {
          const memo = await prisma.memo.create({
            data: {
              title: 'My first memo',
              content: 'Hello Prisma!',
            },
          })
          console.log(memo)
        }

        main()
          .catch((e) => {
            throw e
          })
          .finally(async () => {
            await prisma.$disconnect()
          })
        ```

2. **Drizzle ORM**
    *   Drizzle ORM と SQLite の必要なパッケージをインストールします。

        ```bash
        npm install @drizzle/sqlite drizzle-orm sqlite
        ```

    *   データベース接続とスキーマを定義します。

        ```typescript
        import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';
        import { drizzle } from 'drizzle-orm/sqlite';
        import Database from 'better-sqlite3';

        export const memos = sqliteTable('memos', {
          id: text('id').primaryKey(),
          title: text('title').notNull(),
          content: text('content'),
        });

        const sqlite = new Database('mydb.db');
        export const db = drizzle(sqlite);
        ```
    *  Drizzle ORM を使用してクエリを実行します。

        ```typescript
        import { db, memos } from './schema';
        import { randomUUID } from 'crypto';
        import { eq } from 'drizzle-orm';

        async function main() {
          // Create
          const newMemo = {
            id: randomUUID(),
            title: 'My first memo',
            content: 'Hello Drizzle ORM!',
          };
          await db.insert(memos).values(newMemo);

          // Read
          const allMemos = await db.select().from(memos);
          console.log(allMemos);

          // Update
          await db.update(memos).set({ content: 'Updated content' }).where(eq(memos.id, newMemo.id));

          // Delete
          await db.delete(memos).where(eq(memos.id, newMemo.id));
        }

        main();
        ```

3.  **Mongoose:**

    *   Mongooseをインストールします。

        ```bash
        npm install mongoose
        ```

    *   スキーマを定義します。

        ```javascript
        const mongoose = require('mongoose');

        const memoSchema = new mongoose.Schema({
          title: { type: String, required: true },
          content: String,
        });

        const Memo = mongoose.model('Memo', memoSchema);
        ```

    *   データベースに接続し、モデルを使ってデータベースを操作します。

        ```javascript
        mongoose.connect('mongodb://localhost:27017/mydb', { useNewUrlParser: true, useUnifiedTopology: true })
          .then(() => console.log('Connected to MongoDB'))
          .catch((err) => console.error('MongoDB connection error:', err));

        async function main() {
          const memo = new Memo({ title: 'My first memo', content: 'Hello Mongoose!' });
          await memo.save();
          console.log(memo);
        }

        main();
        ```

### 6.4 型定義の活用とバリデーション

**概要と重要性**

型定義とバリデーションは、API開発において非常に重要な要素です。型定義を適切に行うことで、コードの可読性、保守性、安全性を向上させることができます。また、バリデーションを実装することで、不正なデータがAPIに送信されるのを防ぎ、アプリケーションの安定性を確保することができます。

**特徴と利点**

*   **型定義:** TypeScriptなどの型付き言語を使用することで、コンパイル時に型エラーを検出することができます。
*   **バリデーション:** リクエストボディやクエリパラメータの値を検証することで、不正なデータを拒否することができます。

**事前準備と前提条件**

*   TypeScriptがインストールされ、設定されていること。
*   バリデーションライブラリ（Zod, Yupなど）がインストールされていること。

**基本的な使い方**

1.  **型定義:**

    *   インターフェースまたは型エイリアスを使って、APIで使用するデータの型を定義します。

        ```typescript
        interface Memo {
          id: string
          title: string
          content: string
        }
        ```

2.  **バリデーション:**

    *   バリデーションライブラリを使って、リクエストボディやクエリパラメータの値を検証します。

        ```typescript
        import { z } from 'zod'

        const memoSchema = z.object({
          title: z.string().min(1),
          content: z.string().optional(),
        })

        // Hono のミドルウェアとして使用する例
        import { zValidator } from '@hono/zod-validator'

        app.post('/memos', zValidator('json', memoSchema), (c) => {
          const { title, content } = c.req.valid('json')
          // ...
        })

        ```

**実践的なテクニック**

*   **カスタムバリデーション:** 複雑なバリデーションルールを実装するために、カスタムバリデーション関数を作成します。
*   **エラーハンドリング:** バリデーションエラーが発生した場合、適切なエラーメッセージをクライアントに返します。
*   **型推論:** TypeScriptの型推論機能を活用して、コードの記述量を減らします。

**応用例とユースケース**

*   **ユーザー登録API:** ユーザー名、パスワード、メールアドレスなどのバリデーションを行います。
*   **商品登録API:** 商品名、価格、在庫数などのバリデーションを行います。
*   **検索API:** 検索キーワードのバリデーションを行います。

**トラブルシューティング**

*   **バリデーションエラー:** バリデーションルールが正しいか確認してください。
*   **型エラー:** 型定義が正しいか確認してください。
*   **実行時エラー:** 型定義と実際のデータの型が一致しているか確認してください。
