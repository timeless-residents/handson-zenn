## 11. 実践的ユースケース - GitHub Actions連携

本章では、BackstageとGitHub Actionsを連携させることで、開発ワークフローをどのように効率化できるのかを解説します。GitHub Actionsのステータス表示や、実行トリガーといった、具体的なプラグインの使用方法をステップバイステップで説明します。Backstageをより強力な開発プラットフォームへと進化させるための知識と実践的なノウハウを習得しましょう。

### 11.1 GitHub Actions連携のメリット

#### 1. 概要と重要性

現代のソフトウェア開発において、CI/CDパイプラインは不可欠な要素です。GitHub Actionsは、GitHub上で直接CI/CDを構築・実行できる強力なツールであり、多くの開発チームで採用されています。BackstageとGitHub Actionsを連携させることで、開発者はBackstageのUIからGitHub Actionsの実行状況を把握したり、ワークフローをトリガーしたりできるようになり、開発効率を大幅に向上させることができます。

#### 2. 特徴と利点

GitHub Actions連携の主なメリットは以下の通りです。

*   **可視性の向上:** Backstage上でGitHub Actionsの実行状況をリアルタイムに確認できるため、ビルドやテストの進捗を把握しやすくなります。
*   **ワークフローの効率化:** Backstageから直接GitHub Actionsのワークフローをトリガーできるため、手動での操作を減らし、迅速なデプロイメントを実現できます。
*   **一元管理:** 開発に必要な情報をBackstageに集約することで、開発者は複数のツールを行き来する必要がなくなり、集中して作業に取り組めます。
*   **コラボレーションの促進:** チームメンバー間でGitHub Actionsの実行状況を共有しやすくなり、問題発生時の連携がスムーズになります。

#### 3. 事前準備と前提条件

GitHub Actions連携を行うには、以下の準備が必要です。

*   **GitHubアカウントとリポジトリ:** GitHub Actionsを実行するリポジトリが必要です。
*   **Backstage環境:** Backstageがセットアップされている必要があります。
*   **Personal Access Token (PAT):** GitHub Actionsの情報をBackstageから取得するために、`repo`スコープを持つPersonal Access Tokenが必要です。
*   **GitHub Actionsプラグイン:** BackstageにGitHub Actions関連のプラグインをインストールする必要があります (後述)。

#### 4. 基本的な使い方

GitHub Actions連携の基本的な流れは以下の通りです。

1.  **Personal Access Tokenの作成:** GitHubで`repo`スコープを持つPersonal Access Tokenを作成します。
2.  **Backstageの設定:** 作成したPATをBackstageの設定ファイル (`app-config.yaml`) に記述します。
3.  **プラグインのインストールと設定:** GitHub Actions関連のプラグインをBackstageにインストールし、設定を行います。
4.  **エンティティへのアノテーション追加:** Backstageのエンティティ定義にGitHub Actionsに関するアノテーションを追加します。

#### 5. 実践的なテクニック

Backstageの`app-config.yaml`にPATを追加する例:

```yaml
github:
  token: <YOUR_PERSONAL_ACCESS_TOKEN>
```

エンティティ定義にアノテーションを追加する例 (カタログ情報でリポジトリを紐付ける):

```yaml
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: my-component
  description: My awesome component
  annotations:
    github.com/project-slug: <YOUR_GITHUB_ORG>/<YOUR_GITHUB_REPO>
spec:
  type: service
  lifecycle: production
  owner: my-team
```

#### 6. 応用例とユースケース

*   **プルリクエストの自動テスト:** プルリクエストが作成された際に、自動的にテストを実行するワークフローをBackstageからトリガーする。
*   **デプロイメントの自動化:** コードがmainブランチにマージされた際に、自動的にデプロイメントを実行するワークフローをBackstageからトリガーする。
*   **定期的なメンテナンス:** 定期的に実行されるメンテナンススクリプトを、Backstageからスケジュール実行する。

#### 7. トラブルシューティング

*   **認証エラー:** Personal Access Tokenが正しく設定されているか確認してください。スコープが`repo`になっているかも確認してください。
*   **API Rate Limit:** GitHub API Rate Limitに達した場合、一時的にデータの取得が制限されます。時間をおいて再度試してください。もし頻繁に発生する場合は、GitHub Enterprise Serverの利用を検討してください。
*   **プラグインの不具合:** プラグインのバージョンが最新であるか確認してください。

#### 8. まとめと次のステップ

GitHub Actions連携により、BackstageはCI/CDパイプラインの中心的な存在となり、開発者の生産性を向上させることができます。次のステップでは、具体的なプラグインの使用方法について詳しく解説します。

### 11.2 GitHub Actionsのステータスを表示するプラグイン

#### 1. 概要と重要性

GitHub Actionsのステータスを表示するプラグインを使用することで、Backstage上でリポジトリのビルド状況やテスト結果などを一目で確認できるようになります。これにより、問題発生時の迅速な対応や、デプロイメントの判断をサポートします。

#### 2. 特徴と利点

*   **リアルタイムな情報:** GitHub Actionsの実行状況をリアルタイムに表示します。
*   **視覚的な表現:** ビルドの成功・失敗を色分けして表示するため、状況を把握しやすくなります。
*   **詳細な情報:** ビルドの詳細なログや、実行時間などを確認できます。

#### 3. 事前準備と前提条件

*   **GitHub Actions連携:** GitHub Actionsとの連携が設定されている必要があります (11.1を参照)。
*   **`@backstage/plugin-github-actions`のインストール:** BackstageにGitHub Actionsのステータスを表示するプラグインをインストールする必要があります。

#### 4. 基本的な使い方

1.  **プラグインのインストール:** Backstageプロジェクトのルートディレクトリで以下のコマンドを実行します。

    ```bash
    yarn add @backstage/plugin-github-actions
    yarn add @backstage/plugin-github-actions-common
    ```

2.  **プラグインの登録:** `packages/app/src/components/catalog/EntityPage.tsx`に以下のコードを追加して、プラグインを登録します。

    ```tsx
    import {
      EntityGithubActionsContent,
    } from '@backstage/plugin-github-actions';

    // ...

    const overviewContent = (
      <Grid container spacing={3}>
        <Grid item xs={12}>
          <EntityAboutCard />
        </Grid>
        <Grid item xs={12}>
          <EntityGithubActionsContent />
        </Grid>
      </Grid>
    );
    ```

3.  **エンティティへのアノテーション追加:** エンティティ定義 (`catalog-info.yaml`) にGitHub Actionsに関するアノテーションを追加します。

    ```yaml
    apiVersion: backstage.io/v1alpha1
    kind: Component
    metadata:
      name: my-component
      description: My awesome component
      annotations:
        github.com/project-slug: <YOUR_GITHUB_ORG>/<YOUR_GITHUB_REPO>
    spec:
      type: service
      lifecycle: production
      owner: my-team
    ```

4.  **Backstageの再起動:** Backstageを再起動して、変更を反映させます。

#### 5. 実践的なテクニック

*   **カスタム表示:** プラグインの設定をカスタマイズすることで、表示する情報を絞り込んだり、独自のスタイルを適用したりできます。
*   **フィルター:** 特定のワークフローやブランチのステータスのみを表示するように設定できます。

#### 6. 応用例とユースケース

*   **ダッシュボード:** 複数のコンポーネントのGitHub Actionsステータスをまとめて表示するダッシュボードを作成する。
*   **アラート:** ビルドが失敗した場合に、Slackなどのチャットツールに通知を送るように設定する。

#### 7. トラブルシューティング

*   **ステータスが表示されない:** エンティティ定義のアノテーションが正しいか確認してください。Personal Access Tokenが正しく設定されているかも確認してください。
*   **古い情報が表示される:** ブラウザのキャッシュをクリアして、最新の情報を取得してください。

#### 8. まとめと次のステップ

GitHub Actionsのステータス表示プラグインを使用することで、開発者はBackstage上でGitHub Actionsの実行状況をリアルタイムに把握できます。次のステップでは、GitHub Actionsの実行をトリガーするプラグインについて解説します。

### 11.3 GitHub Actionsの実行をトリガーするプラグイン

#### 1. 概要と重要性

GitHub Actionsの実行をトリガーするプラグインを使用することで、Backstageから直接GitHub Actionsのワークフローを実行できるようになります。これにより、手動での操作を減らし、開発ワークフローを自動化できます。

#### 2. 特徴と利点

*   **簡単な操作:** BackstageのUIからボタンをクリックするだけで、ワークフローを実行できます。
*   **パラメータの指定:** ワークフローにパラメータを渡すことができるため、柔軟な実行が可能です。
*   **権限管理:** 特定のユーザーのみがワークフローを実行できるように、権限を設定できます。

#### 3. 事前準備と前提条件

*   **GitHub Actions連携:** GitHub Actionsとの連携が設定されている必要があります (11.1を参照)。
*   **`@backstage/plugin-github-actions`のインストール:** GitHub Actionsのステータスを表示するプラグインがインストールされている必要があります (11.2を参照)。
*   **ワークフローの定義:** 実行するGitHub Actionsのワークフローが定義されている必要があります。
*   **APIエンドポイントの準備:**  GitHub ActionsのワークフローをトリガーするためのAPIエンドポイントを自分で用意するか、既存のサービスを利用する必要があります。この例では、独自のAPIエンドポイントを用意する方法を説明します。

#### 4. 基本的な使い方

**1. バックエンドプラグインの作成:**

GitHub ActionsのワークフローをトリガーするためのAPIエンドポイントを提供するバックエンドプラグインを作成します。

```bash
# Backstageプロジェクトのルートディレクトリで実行
yarn new
```

プラグインの種類として `backend-plugin` を選択し、プラグイン名を `github-actions-trigger` とします。

**2. バックエンドプラグインの実装:**

作成したバックエンドプラグイン (`packages/backend-plugin-github-actions-trigger/src/index.ts`) に、以下のコードを追加します。

```typescript
import { createRouter } from '@backstage/plugin-github-actions-trigger-backend';
import { Router } from 'express';
import { PluginEnvironment } from '@backstage/backend-plugin-api';

export async function createPlugin(
  env: PluginEnvironment,
): Promise<Router> {
  return await createRouter({
    logger: env.logger,
    discovery: env.discovery,
    config: env.config,
  });
}
```

次に、`packages/backend-plugin-github-actions-trigger/src/router.ts`に以下のコードを追加して、GitHub ActionsのワークフローをトリガーするAPIエンドポイントを実装します。

```typescript
import { Router } from 'express';
import { Logger } from 'winston';
import { Config } from '@backstage/config';
import { DiscoveryService } from '@backstage/backend-plugin-api';
import { Octokit } from '@octokit/rest';
import { PassThrough } from 'stream';
import { getBearerToken } from '@backstage/plugin-auth-node';
import { AuthenticationError, NotAllowedError } from '@backstage/errors';

export interface RouterOptions {
  logger: Logger;
  config: Config;
  discovery: DiscoveryService;
}

export async function createRouter(
  options: RouterOptions,
): Promise<Router> {
  const { logger, config } = options;

  const router = Router();
  router.use(express.json());

  router.post('/trigger/:owner/:repo/:workflow_id', async (req, res) => {
    const { owner, repo, workflow_id } = req.params;
    const { ref, inputs } = req.body;
    const token = getBearerToken(req);

    if (!token) {
      throw new AuthenticationError('Authentication required');
    }

    const githubToken = config.getOptionalString('github.token') || token;

    if (!githubToken) {
        throw new NotAllowedError(
            "Missing github.token in config or Authorization header",
        );
    }

    const octokit = new Octokit({ auth: githubToken });

    try {
      await octokit.actions.createWorkflowDispatch({
        owner,
        repo,
        workflow_id,
        ref,
        inputs,
      });

      res.json({ message: 'Workflow dispatched successfully' });
    } catch (error) {
      logger.error(`Failed to dispatch workflow: ${error}`);
      res.status(500).json({ error: 'Failed to dispatch workflow' });
    }
  });

  router.get('/health', (_req, res) => {
    logger.info('PONG!');
    res.json({ status: 'ok' });
  });
  return router;
}
```

**5. フロントエンドプラグインの実装:**

作成したフロントエンドプラグイン (`packages/plugin-github-actions-trigger-ui/src/components/GithubActionsTriggerCard.tsx`) に、以下のコードを追加します。

```tsx
import React, { useState } from 'react';
import {
  Card,
  CardContent,
  Typography,
  Button,
  TextField,
  Dialog,
  DialogActions,
  DialogContent,
  DialogTitle,
  Grid,
  makeStyles,
} from '@material-ui/core';
import { useEntity } from '@backstage/plugin-catalog-react';
import { useApi, githubAuthApiRef } from '@backstage/core-plugin-api';

const useStyles = makeStyles((theme) => ({
  root: {
    minWidth: 275,
  },
  button: {
    margin: theme.spacing(1),
  },
  textField: {
    margin: theme.spacing(1),
  },
}));

export const GithubActionsTriggerCard = () => {
  const { entity } = useEntity();
  const githubAuthApi = useApi(githubAuthApiRef);
  const classes = useStyles();
  const [open, setOpen] = useState(false);
  const [ref, setRef] = useState('main');
  const [input1, setInput1] = useState('');
  const [input2, setInput2] = useState('');

  const handleOpen = () => {
    setOpen(true);
  };

  const handleClose = () => {
    setOpen(false);
  };

  const handleTrigger = async () => {
    const projectSlug = entity.metadata.annotations?.['github.com/project-slug'];

    if (!projectSlug) {
      alert('GitHub project slug annotation is missing.');
      return;
    }

    const [owner, repo] = projectSlug.split('/');

    if (!owner || !repo) {
      alert('Invalid GitHub project slug annotation.');
      return;
    }

    const workflowId = 'my-workflow.yml'; // ワークフローのファイル名を指定

    try {
      // GitHub認証を行う
      const githubToken = await githubAuthApi.getAccessToken(['repo']);

      const response = await fetch(`/api/github-actions-trigger/trigger/${owner}/${repo}/${workflowId}`, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'Authorization': `Bearer ${githubToken}`,
        },
        body: JSON.stringify({
          ref: ref,
          inputs: {
            input1: input1,
            input2: input2,
          },
        }),
      });

      if (response.ok) {
        alert('Workflow triggered successfully!');
      } else {
        const errorData = await response.json();
        alert(`Failed to trigger workflow: ${errorData.error}`);
      }
    } catch (error) {
      alert(`Failed to trigger workflow: ${error}`);
    }

    handleClose();
  };

  return (
    <Card className={classes.root}>
      <CardContent>
        <Typography variant="h6" component="h2">
          GitHub Actions Trigger
        </Typography>
        <Button
          variant="contained"
          color="primary"
          className={classes.button}
          onClick={handleOpen}
        >
          Trigger Workflow
        </Button>
        <Dialog open={open} onClose={handleClose} aria-labelledby="form-dialog-title">
          <DialogTitle id="form-dialog-title">Trigger GitHub Actions Workflow</DialogTitle>
          <DialogContent>
            <Typography variant="body2">
              Enter the ref (branch or tag) and input parameters for the workflow.
            </Typography>
            <TextField
              autoFocus
              margin="dense"
              id="ref"
              label="Ref (Branch/Tag)"
              type="text"
              fullWidth
              className={classes.textField}
              value={ref}
              onChange={(e) => setRef(e.target.value)}
            />
            <TextField
              margin="dense"
              id="input1"
              label="Input 1"
              type="text"
              fullWidth
              className={classes.textField}
              value={input1}
              onChange={(e) => setInput1(e.target.value)}
            />
            <TextField
              margin="dense"
              id="input2"
              label="Input 2"
              type="text"
              fullWidth
              className={classes.textField}
              value={input2}
              onChange={(e) => setInput2(e.target.value)}
            />
          </DialogContent>
          <DialogActions>
            <Button onClick={handleClose} color="primary">
              Cancel
            </Button>
            <Button onClick={handleTrigger} color="primary">
              Trigger
            </Button>
          </DialogActions>
        </Dialog>
      </CardContent>
    </Card>
  );
};
```

#### 8. まとめと次のステップ

GitHub Actionsの実行をトリガーするプラグインを使用することで、開発者はBackstageから直接GitHub Actionsのワークフローを実行できるようになり、開発ワークフローを大幅に自動化できます。次のステップでは、BackstageとGitHub Actionsを連携させた、より高度なユースケースについて検討します。例えば、ソフトウェアテンプレートと組み合わせることで、新規プロジェクトの作成からデプロイメントまでを自動化することができます。
