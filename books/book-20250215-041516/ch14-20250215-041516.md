## 14. Hono & Stream Deckによる開発ダッシュボード構築

開発者にとって、常に最新の情報を把握し、迅速にアクションを起こせる環境は非常に重要です。ビルドのステータス、デプロイの状況、エラーログ、パフォーマンス指標など、様々な情報を一目で確認できる開発ダッシュボードは、開発効率を大幅に向上させる強力なツールとなります。

本章では、軽量で高速なWebフレームワークであるHonoと、カスタマイズ可能な入力デバイスであるStream Deckを組み合わせ、自分だけの開発ダッシュボードを構築する方法を解説します。HonoでダッシュボードAPIを作成し、Stream Deckに情報を表示するプラグインを開発することで、リアルタイムな情報を手元で確認できる環境を構築します。

### 14.1 開発ダッシュボードの重要性

#### 1.1.1 概要と重要性

開発ダッシュボードは、開発プロセス全体を可視化し、開発者が迅速に状況を把握し、問題に対処できるようにするためのツールです。従来のダッシュボードはWebブラウザで表示されるものが主流でしたが、Stream Deckのような物理デバイスに情報を表示することで、より迅速かつ直感的に情報にアクセスできるようになります。

#### 1.1.2 特徴と利点

*   **リアルタイムな情報表示:** ビルドのステータス、デプロイ状況、エラーログなどをリアルタイムで表示します。
*   **迅速な問題解決:** 異常を早期に検出し、迅速な問題解決を支援します。
*   **開発効率の向上:** 必要な情報を一目で確認できるため、開発者はより重要なタスクに集中できます。
*   **カスタマイズ性:** 必要な情報を自由に選択し、表示形式をカスタマイズできます。
*   **集中力維持:** 全画面表示のダッシュボードではなく、手元のStream Deckで必要な情報だけを確認できるため、集中力を維持しやすくなります。

#### 1.1.3 実務での具体的なユースケース

*   **CI/CDパイプラインの監視:** GitHub Actions、CircleCIなどのCI/CDパイプラインの実行状況を監視し、ビルドの成功/失敗を即座に把握します。
*   **エラーログの監視:** Sentry、Bugsnagなどのエラー追跡ツールと連携し、エラーの発生状況をリアルタイムで監視します。
*   **パフォーマンス指標の監視:** Datadog、New Relicなどのパフォーマンス監視ツールと連携し、CPU使用率、メモリ使用量、レスポンスタイムなどのパフォーマンス指標を監視します。
*   **タスク管理:** Jira、Asanaなどのタスク管理ツールと連携し、自分の担当タスクのステータスを表示します。
*   **GitHubアクティビティの監視:** 自分のGitHubのプルリクエスト、issue、コメントなどのアクティビティを表示します。

#### 1.1.4 まとめと次のステップ

開発ダッシュボードは、開発効率を向上させるための重要なツールです。次のセクションでは、Honoを使用してダッシュボードAPIを構築する方法を解説します。

### 14.2 HonoでダッシュボードAPIを構築する

#### 14.2.1 概要と重要性

Honoは、Cloudflare Workers、Deno、Node.jsなど、様々な環境で動作する軽量で高速なWebフレームワークです。本セクションでは、Honoを使用して、Stream Deckに表示する情報を配信するためのダッシュボードAPIを構築します。

#### 14.2.2 特徴と利点

*   **軽量:** 非常に軽量なフレームワークであるため、高速に動作します。
*   **高速:** パフォーマンスが優れており、リアルタイムな情報配信に適しています。
*   **柔軟性:** 様々な環境で動作するため、既存のインフラストラクチャに簡単に統合できます。
*   **型安全:** TypeScriptをサポートしており、型安全な開発が可能です。
*   **ミドルウェア:** ミドルウェアを利用することで、認証、ロギングなどの共通処理を簡単に実装できます。

#### 14.2.3 事前準備と前提条件

*   Node.js (v18以上推奨)
*   npmまたはyarn
*   Hono CLI (`npm install -g hono`)

#### 14.2.4 基本的な使い方

1.  **プロジェクトの作成:**

    ```bash
    hono create dashboard-api
    cd dashboard-api
    npm install
    ```

2.  **APIエンドポイントの定義:**

    `src/index.ts` を編集して、APIエンドポイントを定義します。

    ```typescript
    import { Hono } from 'hono'
    import { cors } from 'hono/cors'

    const app = new Hono()

    // CORSミドルウェアの設定 (Stream Deckからのリクエストを許可するため)
    app.use(cors({
      origin: '*' // 本番環境では許可するオリジンを制限してください
    }))

    app.get('/', (c) => {
      return c.text('Hello Hono!')
    })

    // ビルドステータスを返すAPI
    app.get('/api/build-status', (c) => {
      // ここでビルドステータスを取得する処理を実装します
      // 例：CI/CDツールからAPIを呼び出してステータスを更新する
      const status = 'success' // または 'failed', 'pending'
      const commitHash = 'abcdef1234567890'
      return c.json({ status, commitHash })
    })

    // エラーログを返すAPI
    app.get('/api/error-logs', (c) => {
      // ここでエラーログを取得する処理を実装します
      // 例：Sentry APIからエラーログを取得する
      const errors = [
        { message: 'TypeError: Cannot read property of undefined', timestamp: new Date() },
        { message: 'ReferenceError: variable is not defined', timestamp: new Date() },
      ]
      return c.json(errors)
    })

    // パフォーマンス指標を返すAPI
    app.get('/api/performance', (c) => {
      // ここでパフォーマンス指標を取得する処理を実装します
      // 例：Datadog APIからパフォーマンス指標を取得する
      const cpuUsage = 75 // CPU使用率 (%)
      const memoryUsage = 80 // メモリ使用率 (%)
      const responseTime = 200 // レスポンスタイム (ms)
      return c.json({ cpuUsage, memoryUsage, responseTime })
    })

    export default app
    ```

3.  **開発サーバーの起動:**

    ```bash
    npm run dev
    ```

    `http://localhost:3000` にアクセスして、`Hello Hono!` が表示されることを確認します。

4.  **APIエンドポイントのテスト:**

    `http://localhost:3000/api/build-status`、`http://localhost:3000/api/error-logs`、`http://localhost:3000/api/performance` にアクセスして、JSONデータが返されることを確認します。

#### 14.2.5 実践的なテクニック

*   **CORSの設定:** Stream Deckからのリクエストを許可するために、CORSミドルウェアを設定する必要があります。本番環境では、`origin` を適切なドメインに制限してください。
*   **環境変数の利用:** APIキー、データベース接続情報などの機密情報を環境変数として管理します。Honoでは、`dotenv` などのライブラリを使用して環境変数を読み込むことができます。

    ```bash
    npm install dotenv
    ```

    `.env` ファイルを作成し、環境変数を定義します。

    ```
    API_KEY=your_api_key
    DATABASE_URL=your_database_url
    ```

    `src/index.ts` で環境変数を読み込みます。

    ```typescript
    import { Hono } from 'hono'
    import { cors } from 'hono/cors'
    import { z } from 'zod'
    import { zValidator } from '@hono/zod-validator'
    import * as dotenv from 'dotenv'

    dotenv.config()

    const apiKey = process.env.API_KEY

    const app = new Hono()

    app.use(cors({
      origin: '*' // 本番環境では許可するオリジンを制限してください
    }))

    // リクエストボディのバリデーション
    const schema = z.object({
      name: z.string(),
      age: z.number().min(18),
    })

    app.post('/api/user', zValidator('json', schema), (c) => {
      const { name, age } = c.req.valid('json')
      console.log(name, age)
      return c.json({ message: `Hello ${name}, you are ${age} years old.` })
    })


    app.get('/', (c) => {
      return c.text('Hello Hono!')
    })

    // ビルドステータスを返すAPI
    app.get('/api/build-status', (c) => {
      // ここでビルドステータスを取得する処理を実装します
      // 例：CI/CDツールからAPIを呼び出してステータスを更新する
      const status = 'success' // または 'failed', 'pending'
      const commitHash = 'abcdef1234567890'
      return c.json({ status, commitHash })
    })

    // エラーログを返すAPI
    app.get('/api/error-logs', (c) => {
      // ここでエラーログを取得する処理を実装します
      // 例：Sentry APIからエラーログを取得する
      const errors = [
        { message: 'TypeError: Cannot read property of undefined', timestamp: new Date() },
        { message: 'ReferenceError: variable is not defined', timestamp: new Date() },
      ]
      return c.json(errors)
    })

    // パフォーマンス指標を返すAPI
    app.get('/api/performance', (c) => {
      // ここでパフォーマンス指標を取得する処理を実装します
      // 例：Datadog APIからパフォーマンス指標を取得する
      const cpuUsage = 75 // CPU使用率 (%)
      const memoryUsage = 80 // メモリ使用率 (%)
      const responseTime = 200 // レスポンスタイム (ms)
      return c.json({ cpuUsage, memoryUsage, responseTime })
    })

    export default app
    ```

*   **データの取得:** APIからデータを取得する際には、`node-fetch` などのライブラリを使用します。
*   **データのキャッシュ:** 頻繁にアクセスされるデータは、キャッシュに保存することでAPIの負荷を軽減できます。Honoでは、`lru-cache` などのライブラリを使用してキャッシュを実装できます。

#### 14.2.6 応用例とユースケース

*   **GitHub Actionsのステータス:** GitHub Actions APIを使用して、ワークフローの実行状況を取得し、Stream Deckに表示します。
*   **Sentryのエラーログ:** Sentry APIを使用して、エラーログを取得し、Stream Deckに表示します。
*   **Datadogのパフォーマンス指標:** Datadog APIを使用して、パフォーマンス指標を取得し、Stream Deckに表示します。

#### 14.2.7 トラブルシューティング

*   **CORSエラー:** Stream DeckからのリクエストがCORSによってブロックされる場合は、CORSミドルウェアの設定を確認してください。
*   **APIエラー:** APIリクエストが失敗する場合は、APIキー、URL、リクエストパラメータなどを確認してください。
*   **データ形式のエラー:** APIから返されるデータ形式がStream Deckプラグインで期待される形式と異なる場合は、データ変換処理を実装してください。

#### 14.2.8 まとめと次のステップ

Honoを使用して、Stream Deckに表示する情報を配信するためのダッシュボードAPIを構築しました。次のセクションでは、Stream Deckでダッシュボードを表示するプラグインを開発する方法を解説します。

### 14.3 Stream Deckでダッシュボードを表示するプラグイン

#### 14.3.1 概要と重要性

Stream Deckは、Elgato社が販売するカスタマイズ可能な入力デバイスです。本セクションでは、Stream Deck SDKを使用して、Honoで構築したダッシュボードAPIからデータを取得し、Stream Deckに表示するプラグインを開発します。

#### 14.3.2 特徴と利点

*   **カスタマイズ性:** ボタンの数、アイコン、アクションを自由にカスタマイズできます。
*   **リアルタイムな情報表示:** APIからデータを取得し、リアルタイムで情報を表示できます。
*   **操作性:** ボタンを押すだけで、様々なアクションを実行できます。
*   **拡張性:** Stream Deck SDKを使用することで、独自のプラグインを開発できます。

#### 14.3.3 事前準備と前提条件

*   Stream Deck本体
*   Stream Deck SDK
*   開発環境 (Visual Studio Codeなど)
*   Stream Deck Software

Stream Deck SDKは、Elgato社のWebサイトからダウンロードできます。

#### 14.3.4 基本的な使い方

1.  **プロジェクトの作成:**

    Stream Deck SDKを使用して、新しいプラグインプロジェクトを作成します。

2.  **プラグインの設定:**

    `manifest.json` ファイルを編集して、プラグインの名前、説明、アイコン、アクションなどを設定します。

    ```json

      "Name": "Dashboard Plugin",
      "Icon": "images/icon.png",

      "URL": "https://example.com",
      "Category": "Development",
      "CategoryIcon": "images/categoryIcon.png",
      "OS": [
        {
          "Platform": "mac",
          "MinimumVersion": "10.11"
        },

      ],

    ```

3.  **HTML/JavaScriptコードの記述:**

    `index.html` ファイルにHTML/JavaScriptコードを記述して、Stream Deckに表示する内容を定義します。

    ```html
    <!DOCTYPE html>
    <html>
    <head>
      <meta charset="utf-8">
      <title>Dashboard Plugin</title>
      <link rel="stylesheet" href="css/style.css">
    </head>
    <body>
      <div class="container">
        <p id="status"></p>
        <p id="commit"></p>
      </div>
      <script src="js/script.js"></script>
    </body>
    </html>
    ```

    `js/script.js` ファイルにJavaScriptコードを記述して、Honoで構築したAPIからデータを取得し、Stream Deckに表示します。

    ```javascript
    // connectElgatoStreamDeckSocket(inPort, inPluginUUID, inRegisterEvent, inInfo) は、streamdeck.js で定義されている Stream Deck SDK の関数
    // プラグイン起動時に Stream Deck Software から呼び出される。
    const connectElgatoStreamDeckSocket = (inPort, inPluginUUID, inRegisterEvent, inInfo) => {
      // WebSocket オブジェクトを作成
      websocket = new WebSocket('ws://127.0.0.1:' + inPort)

      // WebSocket が開いたら
      websocket.onopen = () => {
        // プラグインを Stream Deck Software に登録
        registerPluginOrPI(inRegisterEvent, inPluginUUID)
      }

      // WebSocket でエラーが発生したら
      websocket.onerror = (evt) => {
        console.warn('Websocket Error: ' + evt, websocket)
      }

      // WebSocket が閉じたら
      websocket.onclose = (evt) => {
        // 1000 は通常のクローズ
        if (evt.code !== 1000) {
          console.warn('Websocket closed with code: ' + evt.code + ' and reason: ' + evt.reason)
          // 必要に応じて再接続処理を記述
        }
      }

      // WebSocket でメッセージを受信したら
      websocket.onmessage = (evt) => {
        // 受信したメッセージを JSON として解析
        const jsonObj = JSON.parse(evt.data)

        // 受信したメッセージの種類に応じて処理を分岐
        if (jsonObj.event === 'didReceiveSettings') {
          // 設定を受信した場合
          console.log('didReceiveSettings', jsonObj)
        } else if (jsonObj.event === 'keyDown') {
          // キーが押された場合
          console.log('keyDown', jsonObj)
          fetchBuildStatus(jsonObj.context);
        } else if (jsonObj.event === 'keyUp') {
          // キーが離された場合
          console.log('keyUp', jsonObj)
        } else {
          // その他のイベントの場合
          console.log('onmessage', jsonObj)
        }
      }
    }

    // プラグインまたは Property Inspector を Stream Deck Software に登録する関数
    const registerPluginOrPI = (inRegisterEvent, inPluginUUID) => {
      // 登録イベントと UUID を含む JSON オブジェクトを作成
      const json = {
        event: inRegisterEvent,
        uuid: inPluginUUID
      }

      // JSON オブジェクトを文字列に変換
      const jsonStr = JSON.stringify(json)

      // WebSocket を使用して Stream Deck Software にメッセージを送信
      websocket.send(jsonStr)
    }

    // Stream Deck に表示するテキストを設定する関数
    function setTitle(context, title) {
      const json = {
        event: 'setTitle',
        context: context,
        payload: {
          title: title,
          target: 0 // 0: 表示、1: ハードウェア
        }
      }
      websocket.send(JSON.stringify(json))
    }

    // ビルドステータスを取得して Stream Deck に表示する関数
    async function fetchBuildStatus(context) {
      try {
        const response = await fetch('http://localhost:3000/api/build-status');
        const data = await response.json();

        const statusText = `Build: ${data.status}`;
        const commitText = `Commit: ${data.commitHash.substring(0, 7)}`; // 最初の7文字だけ表示

        setTitle(context, statusText + '\n' + commitText); // 改行を追加
      } catch (error) {
        console.error('Error fetching build status:', error);
        setTitle(context, 'Error');
      }
    }
    ```

    Stream Deck SDKに付属のビルドツールを使用して、プラグインをビルドします。

5.  **プラグインのインストール:**

    ビルドされたプラグインをStream Deck Softwareにインストールします。

6.  **Stream Deckの設定:**

    Stream Deck Softwareで、インストールされたプラグインをStream Deckのボタンに割り当てます。

#### 14.3.5 実践的なテクニック

*   **画像の表示:** Stream Deck SDKを使用して、画像をStream Deckに表示できます。
*   **設定画面の作成:** `propertyInspector.html` ファイルを作成して、プラグインの設定画面を定義できます。設定画面では、APIキー、URLなどの設定をユーザーが変更できるようにします。
*   **定期的なデータ更新:** `setInterval` 関数を使用して、定期的にAPIからデータを取得し、Stream Deckに表示する情報を更新します。

#### 14.3.6 応用例とユースケース

*   **ビルドステータスの表示:** CI/CDパイプラインのビルドステータスをStream Deckに表示します。
*   **エラーログの表示:** SentryのエラーログをStream Deckに表示します。
*   **パフォーマンス指標の表示:** Datadogのパフォーマンス指標をStream Deckに表示します。
*   **タスク管理:** Jira、Asanaなどのタスク管理ツールと連携し、自分の担当タスクのステータスを表示します。

#### 14.3.7 トラブルシューティング

*   **プラグインが認識されない:** `manifest.json` ファイルの設定を確認してください。特に、`UUID` が重複していないか、`CodePath` が正しいかを確認してください。
*   **APIリクエストが失敗する:** APIキー、URL、リクエストパラメータなどを確認してください。
*   **データが表示されない:** JavaScriptコードでエラーが発生していないか確認してください。Stream Deck Softwareのコンソールでエラーログを確認できます。
*  **Stream DeckがAPIにアクセスできない:** Hono APIが起動しているか、CORS設定が正しいかを確認してください。

#### 14.3.8 まとめと次のステップ

Stream Deck SDKを使用して、Honoで構築したダッシュボードAPIからデータを取得し、Stream Deckに表示するプラグインを開発しました。このプラグインを使用することで、リアルタイムな情報を手元で確認できる開発ダッシュボードを構築できます。

この章で学んだことを応用して、自分に必要な情報を表示する独自のプラグインを開発してみてください。例えば、GitHubのプルリクエスト、Slackのメンション、RSSフィードなどを表示するプラグインを作成することができます。

また、HonoとStream Deckの組み合わせは、開発ダッシュボード以外にも様々な用途に活用できます。例えば、スマートホームの制御、プレゼンテーションの操作、ゲームの操作など、アイデア次第で様々な可能性が広がります。
