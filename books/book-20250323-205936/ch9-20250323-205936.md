## 9. サプライチェーン分析：効率化とコスト削減を実現する

サプライチェーンは、原材料の調達から製品が顧客の手に届くまでの一連の流れを指します。このサプライチェーン全体を分析し、最適化することで、企業の効率性を高め、コストを大幅に削減することが可能です。本章では、サプライチェーン分析の中でも特に重要な「需要予測」「在庫管理」「輸送ルート最適化」の 3 つの要素に焦点を当て、実践的なテクニックとユースケースを交えながら解説します。

### 9.1 需要予測：在庫最適化と欠品防止

#### 9.1.1 概要と重要性

需要予測とは、過去のデータや市場動向を分析し、将来の製品やサービスの需要量を予測することです。正確な需要予測は、過剰な在庫を抱えるリスクを減らし、欠品による顧客満足度の低下を防ぐ上で不可欠です。需要予測が甘いと、無駄な在庫コストが発生したり、販売機会を逃したりする可能性があります。逆に、予測が的確であれば、在庫を最適化し、迅速な顧客対応を実現できます。

#### 9.1.2 特徴と利点

需要予測には、以下のような特徴と利点があります。

- **在庫コストの削減:** 適切な在庫量を維持することで、保管費用や陳腐化リスクを低減できます。
- **欠品防止:** 需要に見合った在庫を確保することで、顧客の要求に迅速に対応できます。
- **生産計画の最適化:** 需要予測に基づいて生産計画を調整することで、効率的な生産体制を構築できます。
- **顧客満足度の向上:** 必要な時に必要な製品を提供することで、顧客の信頼とロイヤリティを高めることができます。
- **リスク管理:** 需要変動に対する備えを強化し、サプライチェーン全体の安定性を向上させます。

#### 9.1.3 事前準備と前提条件

需要予測を行うためには、以下の事前準備が必要です。

1.  **データ収集:** 過去の販売データ、市場データ、季節変動データ、プロモーションデータなど、需要に影響を与える可能性のあるデータを収集します。
2.  **データクレンジング:** 収集したデータに誤りや欠損がないかを確認し、必要に応じて修正または削除します。
3.  **予測モデルの選択:** データの種類や予測精度に合わせて、適切な予測モデルを選択します（例：移動平均法、指数平滑法、ARIMA モデルなど）。
4.  **予測ツールの導入:** 需要予測を効率的に行うためのツール（例：Excel、統計解析ソフトウェア、専用の需要予測システム）を導入します。
5.  **予測担当者の育成:** 需要予測の知識とスキルを持つ担当者を育成します。

#### 9.1.4 基本的な使い方

ここでは、Excel を用いた移動平均法による需要予測の基本的な使い方を説明します。

**手順:**

1.  **Excel の準備:** Excel を起動し、過去の販売データを入力します。例えば、A 列に日付、B 列に販売数量を入力します。
2.  **移動平均の計算:** C 列に移動平均を計算する式を入力します。例えば、5 期間の移動平均を計算する場合、C6 セルに「=AVERAGE(B2:B6)」と入力し、C7 セル以降にコピーします。
3.  **予測値の算出:** 最新の移動平均値を、次の期間の予測値として使用します。例えば、C 列の最後の値が 100 であれば、次の期間の予測値は 100 となります。
4.  **グラフ化:** 過去の販売データと予測値をグラフ化し、予測の精度を目視で確認します。

**例:**

| 日付   | 販売数量 | 移動平均 (5 期間) |
| ------ | -------- | ----------------- |
| 2023/1 | 100      |                   |
| 2023/2 | 110      |                   |
| 2023/3 | 120      |                   |
| 2023/4 | 130      |                   |
| 2023/5 | 140      | 120               |
| 2023/6 | 150      | 130               |
| 2023/7 | 160      | 140               |
| 2023/8 | 170      | 150               |
| 2023/9 | 180      | 160               |

この例では、2023 年 10 月の予測値は 160 となります。

#### 9.1.5 実践的なテクニック

- **季節変動の考慮:** 季節性のある製品の場合、季節指数を用いて需要予測を調整します。
- **イベントの影響の考慮:** イベント（セール、キャンペーンなど）が需要に与える影響を考慮し、予測モデルに組み込みます。
- **外部データの活用:** 経済指標、市場トレンド、競合他社の動向など、外部データも活用して予測精度を高めます。
- **予測精度の評価:** MAPE（平均絶対パーセント誤差）などの指標を用いて、予測精度を定期的に評価し、モデルを改善します。
- **需要予測システムの導入:** 複雑な予測モデルを使用する場合や、大量のデータを扱う場合は、専用の需要予測システムの導入を検討します。

#### 9.1.6 応用例とユースケース

- **アパレル業界:** 過去の販売データとトレンド情報を基に、次のシーズンの売れ筋商品を予測し、在庫を最適化します。
- **食品業界:** 天候やイベント情報を考慮し、特定の食品の需要を予測し、欠品を防ぎます。
- **小売業界:** 店舗ごとの販売データと地域情報を基に、各店舗の在庫を最適化し、顧客満足度を向上させます。
- **製造業:** 部品の需要を予測し、必要な部品を必要な時に調達することで、生産ラインの停止を防ぎます。
- **EC サイト:** アクセスログや購買履歴を分析し、個々の顧客のニーズに合わせた商品を提案することで、売上を向上させます。

#### 9.1.7 トラブルシューティング

- **予測精度が低い:** データが不足している、予測モデルが適切でない、外部要因を考慮していないなどの原因が考えられます。データを追加したり、予測モデルを変更したり、外部要因を考慮したりすることで、予測精度を向上させることができます。
- **予測結果と実際の需要が大きく異なる:** 予測モデルが過去のデータに過剰に適合している（過学習）可能性があります。モデルを簡素化したり、検証データを用いてモデルを評価したりすることで、過学習を防ぐことができます。
- **需要予測システムが正常に動作しない:** システムのエラー、データの不整合、ネットワークの問題などが考えられます。システムログを確認したり、データを修正したり、ネットワーク環境を改善したりすることで、問題を解決できます。

#### 9.1.8 まとめと次のステップ

需要予測は、在庫最適化と欠品防止に不可欠な要素です。本セクションでは、需要予測の基本的な使い方から実践的なテクニックまでを解説しました。次のステップとしては、実際に自社のデータを用いて需要予測を行い、その結果を基に在庫管理や生産計画を改善していくことをお勧めします。また、需要予測システムを導入することで、より高度な分析が可能になります。

### 9.2 在庫管理：ABC 分析、安全在庫

#### 9.2.1 概要と重要性

在庫管理とは、製品や原材料の在庫量を適切に管理し、必要な時に必要な量を供給できるようにすることです。適切な在庫管理は、過剰な在庫を抱えるリスクを減らし、欠品による機会損失を防ぐ上で非常に重要です。在庫管理が不十分だと、保管費用や陳腐化リスクが増大したり、顧客からの注文に対応できなかったりする可能性があります。効率的な在庫管理を行うことで、コストを削減し、顧客満足度を向上させることができます。

#### 9.2.2 特徴と利点

在庫管理には、以下のような特徴と利点があります。

- **コスト削減:** 過剰な在庫を減らし、保管費用や陳腐化リスクを低減できます。
- **欠品防止:** 顧客の要求に迅速に対応し、機会損失を防ぎます。
- **キャッシュフローの改善:** 在庫を最適化することで、資金の固定化を防ぎ、キャッシュフローを改善できます。
- **生産性の向上:** 必要な時に必要な部品を供給することで、生産ラインの停止を防ぎ、生産性を向上させます。
- **顧客満足度の向上:** 迅速な顧客対応と安定した製品供給により、顧客の信頼とロイヤリティを高めることができます。

#### 9.2.3 事前準備と前提条件

在庫管理を行うためには、以下の事前準備が必要です。

1.  **在庫データの収集:** 製品、原材料、仕掛品などの在庫データを収集します。
2.  **在庫データの整理:** 収集した在庫データを整理し、在庫管理システムに入力します。
3.  **在庫管理システムの導入:** 在庫管理を効率的に行うためのシステム（例：Excel、在庫管理ソフトウェア、ERP システム）を導入します。
4.  **在庫管理ルールの策定:** 在庫の補充方法、保管場所、棚卸方法など、在庫管理に関するルールを策定します。
5.  **在庫管理担当者の育成:** 在庫管理の知識とスキルを持つ担当者を育成します。

#### 9.2.4 基本的な使い方

ここでは、ABC 分析と安全在庫の計算方法について説明します。

**1. ABC 分析**

ABC 分析とは、在庫を重要度に応じて A、B、C の 3 つのグループに分類し、重点的に管理する在庫を特定する手法です。

**手順:**

1.  **在庫データの準備:** 各在庫品目の年間使用金額（単価 × 年間使用量）を計算します。
2.  **ランキング:** 年間使用金額の高い順に在庫品目を並べます。
3.  **累積金額と累積構成比の計算:** 年間使用金額の累積金額と累積構成比を計算します。
4.  **グループ分け:** 累積構成比に基づいて、在庫品目を A、B、C の 3 つのグループに分類します。一般的に、A グループは上位 70%、B グループは次の 20%、C グループは残りの 10%とします。
5.  **管理方法の決定:** 各グループに応じて、在庫管理の方法を決定します。A グループは重点的に管理し、発注頻度を高め、在庫量を最小限に抑えます。C グループは比較的管理を簡素化し、発注頻度を低く、在庫量を多めにします。

**例:**

| 在庫品目 | 年間使用量 | 単価 | 年間使用金額 | 累積金額 | 累積構成比 | グループ |
| -------- | ---------- | ---- | ------------ | -------- | ---------- | -------- |
| 品目 A   | 1000       | 100  | 100000       | 100000   | 50%        | A        |
| 品目 B   | 500        | 80   | 40000        | 140000   | 70%        | A        |
| 品目 C   | 200        | 50   | 10000        | 150000   | 75%        | B        |
| 品目 D   | 100        | 30   | 3000         | 153000   | 76.5%      | B        |
| 品目 E   | 50         | 20   | 1000         | 154000   | 77%        | C        |

**2. 安全在庫**

安全在庫とは、需要変動やリードタイムの遅延に備えて、常に確保しておくべき在庫量のことです。安全在庫が不足すると、欠品が発生する可能性が高まります。

**計算式:**

安全在庫 = 安全係数 × リードタイム中の需要の標準偏差

**例:**

- リードタイム: 5 日
- 1 日の平均需要: 10 個
- 1 日の需要の標準偏差: 2 個
- 安全係数: 1.64 (95%の確率で欠品を防ぐ場合)

安全在庫 = 1.64 × (2 × √5) = 7.33 ≈ 8 個

この場合、安全在庫として 8 個を確保しておくことで、95%の確率で欠品を防ぐことができます。

#### 9.2.5 実践的なテクニック

- **発注点の最適化:** 発注点を適切に設定することで、在庫切れを防ぎつつ、在庫量を最小限に抑えることができます。
- **定期発注方式:** 一定期間ごとに定期的に発注を行う方式です。需要が安定している場合に適しています。
- **定量発注方式:** 在庫量が一定レベルを下回ったら、一定量を発注する方式です。需要変動が大きい場合に適しています。
- **VMI (Vendor Managed Inventory):** ベンダーが顧客の在庫を管理し、自動的に補充する方式です。サプライチェーン全体の効率化に貢献します。
- **需要予測との連携:** 需要予測の結果を在庫管理に反映させることで、より正確な在庫管理が可能になります。

#### 9.2.6 応用例とユースケース

- **小売業界:** ABC 分析を用いて、売れ筋商品を重点的に管理し、欠品を防ぎます。
- **製造業:** 安全在庫を適切に設定することで、生産ラインの停止を防ぎます。
- **EC サイト:** VMI を導入することで、在庫管理の負担を軽減し、顧客への迅速な商品提供を実現します。
- **病院:** 医薬品の在庫を適切に管理し、必要な時に必要な医薬品を提供できるようにします。
- **建設業:** 資材の在庫を適切に管理し、工事現場での資材不足を防ぎます。

#### 9.2.7 トラブルシューティング

- **在庫が過剰:** 需要予測が誤っている、発注量が多すぎる、リードタイムが短いなどの原因が考えられます。需要予測の精度を高めたり、発注量を調整したり、リードタイムを短縮したりすることで、在庫過剰を解消できます。
- **在庫切れが発生:** 需要予測が誤っている、安全在庫が不足している、発注遅延が発生しているなどの原因が考えられます。需要予測の精度を高めたり、安全在庫を増やしたり、発注プロセスを改善したりすることで、在庫切れを防ぐことができます。
- **在庫管理システムが正常に動作しない:** システムのエラー、データの不整合、ネットワークの問題などが考えられます。システムログを確認したり、データを修正したり、ネットワーク環境を改善したりすることで、問題を解決できます。

### 9.3 輸送ルート最適化：コスト削減と納期短縮

#### 9.3.1 概要と重要性

輸送ルート最適化とは、製品や原材料を輸送する際に、コストを最小限に抑えつつ、納期を最短にするための最適なルートを選択することです。効率的な輸送ルートは、燃料費や人件費などの輸送コストを削減し、リードタイムを短縮することで、顧客満足度を向上させることができます。輸送ルートが非効率だと、輸送コストが増大したり、納期が遅れたりする可能性があります。

#### 9.3.2 特徴と利点

輸送ルート最適化には、以下のような特徴と利点があります。

- **コスト削減:** 燃料費、人件費、車両維持費などの輸送コストを削減できます。
- **納期短縮:** リードタイムを短縮し、顧客への迅速な商品提供を実現できます。
- **輸送効率の向上:** 車両の積載率を向上させ、輸送効率を高めることができます。
- **環境負荷の低減:** 燃料消費量を削減し、二酸化炭素排出量を低減できます。
- **リアルタイム追跡:** 輸送状況をリアルタイムで把握し、遅延やトラブルに迅速に対応できます。

#### 9.3.3 事前準備と前提条件

輸送ルート最適化を行うためには、以下の事前準備が必要です。

1.  **輸送データの収集:** 輸送距離、輸送時間、輸送コスト、配送先、交通状況などの輸送データを収集します。
2.  **輸送データの整理:** 収集した輸送データを整理し、輸送ルート最適化システムに入力します。
3.  **輸送ルート最適化システムの導入:** 輸送ルート最適化を効率的に行うためのシステム（例：地図ソフト、ルート検索 API、専用の輸送ルート最適化システム）を導入します。
4.  **制約条件の定義:** 時間指定、積載量制限、通行禁止道路など、輸送ルートに関する制約条件を定義します。
5.  **輸送担当者の育成:** 輸送ルート最適化の知識とスキルを持つ担当者を育成します。

#### 9.3.4 基本的な使い方

ここでは、Google Maps API を用いた簡単な輸送ルート最適化の例を紹介します。これはあくまで概念的なもので、実際の業務で利用するにはより高度なツールが必要になることをご了承ください。

**手順:**

1.  **Google Maps API キーの取得:** Google Cloud Platform で Google Maps API キーを取得します。
2.  **API の有効化:** Distance Matrix API と Directions API を有効化します。
3.  **Python ライブラリのインストール:** `googlemaps`ライブラリをインストールします。

```bash
pip install googlemaps
```

4.  **コードの作成:** 以下の Python コードを参考に、出発地、経由地、目的地を設定し、最適なルートを検索します。

```python
import googlemaps

# APIキーを設定
gmaps = googlemaps.Client(key='YOUR_API_KEY')

# 出発地、経由地、目的地を設定
origin = '東京駅'
waypoints = ['新宿駅', '渋谷駅']
destination = '横浜駅'

# Directions APIでルートを検索
directions_result = gmaps.directions(origin,
                                     destination,
                                     waypoints=waypoints,
                                     optimize_waypoints=True, # 経由地の順序を最適化
                                     mode="driving") # 移動手段を指定

# 結果を表示
if directions_result:
    print("総距離:", directions_result[0]['legs'][0]['distance']['text'])
    print("総時間:", directions_result[0]['legs'][0]['duration']['text'])
    print("最適な経由地の順序:", directions_result[0]['waypoint_order'])
else:
    print("ルートが見つかりませんでした。")

```

**解説:**

- `googlemaps.Client(key='YOUR_API_KEY')`で Google Maps API クライアントを初期化します。`YOUR_API_KEY`は、取得した API キーに置き換えてください。
- `gmaps.directions()`でルートを検索します。
  - `origin`: 出発地
  - `destination`: 目的地
  - `waypoints`: 経由地（リスト形式）
  - `optimize_waypoints=True`: 経由地の順序を最適化
  - `mode`: 移動手段（"driving"は自動車）
- `directions_result[0]['legs'][0]['distance']['text']`で総距離を取得します。
- `directions_result[0]['legs'][0]['duration']['text']`で総時間を取得します。
- `directions_result[0]['waypoint_order']`で最適な経由地の順序を取得します。

#### 9.3.5 実践的なテクニック

- **複数配送先の最適化 (TSP: Traveling Salesman Problem):** 複数の配送先を効率的に巡回するルートを決定します。専用のソルバーやアルゴリズム（例：遺伝的アルゴリズム、焼きなまし法）を使用します。
- **時間枠制約の考慮:** 配送先ごとに指定された時間枠（例：午前中、午後）を考慮して、ルートを決定します。
- **積載量制約の考慮:** 車両の積載量制限を考慮して、ルートを決定します。
- **リアルタイム交通情報の活用:** リアルタイムの交通情報を活用して、渋滞を回避するルートを決定します。
- **配送車両の最適化:** 配送車両の種類（トラック、バイクなど）を最適化し、コストを削減します。
- **共同配送:** 複数の企業が共同で配送を行うことで、輸送効率を向上させます。

#### 9.3.6 応用例とユースケース

- **宅配業者:** 複数の配達先を効率的に巡回するルートを決定し、配達時間を短縮します。
- **物流会社:** 複数の倉庫から配送先への最適な輸送ルートを決定し、輸送コストを削減します。
- **食品配送業者:** 時間指定配送に対応し、鮮度を保ちながら商品を配送します。
- **建設業者:** 資材を建設現場に効率的に輸送するルートを決定し、工事の遅延を防ぎます。
- **医療機関:** 血液や臓器などの緊急輸送ルートを最適化し、迅速な医療提供を実現します。

#### 9.3.7 トラブルシューティング

- **最適なルートが見つからない:** 制約条件が厳しすぎる、データが不正確などの原因が考えられます。制約条件を緩和したり、データを修正したりすることで、最適なルートが見つかる可能性があります。
- **リアルタイム交通情報が反映されない:** API の制限、ネットワークの問題などが考えられます。API の利用状況を確認したり、ネットワーク環境を改善したりすることで、問題を解決できます。
- **輸送ルート最適化システムが正常に動作しない:** システムのエラー、データの不整合、ネットワークの問題などが考えられます。システムログを確認したり、データを修正したり、ネットワーク環境を改善したりすることで、問題を解決できます。
