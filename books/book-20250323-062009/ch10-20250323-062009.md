## 第 9 章：行動分析：ユーザーとシステムの異常な振る舞いを検知する

### ユーザー行動分析（UEBA）

**1. 概要と重要性**

ユーザー行動分析（User and Entity Behavior Analytics, UEBA）は、ユーザーやエンティティ（デバイス、アプリケーションなど）の通常行動を学習し、そこからの逸脱を検知することで、セキュリティリスクや不正行為を早期に発見する技術です。従来のセキュリティ対策が既知の脅威に焦点を当てるのに対し、UEBA は未知の脅威や内部不正を検知する能力に優れています。

サイバー攻撃は高度化の一途を辿り、従来の境界防御だけでは防ぎきれないケースが増えています。内部からの不正アクセスや、従業員のアカウントが乗っ取られた場合など、通常のアクセス権限を利用した攻撃は、従来のセキュリティシステムでは見過ごされがちです。UEBA は、このような異常な振る舞いを検知し、セキュリティチームにアラートを発することで、迅速な対応を可能にします。

**2. 特徴と利点**

UEBA の主な特徴と利点は以下の通りです。

- **異常検知:** ユーザーの通常行動を学習し、そこからの逸脱を自動的に検知します。
- **未知の脅威への対応:** 既知のシグネチャに依存しないため、ゼロデイ攻撃や高度な標的型攻撃（APT）にも有効です。
- **内部不正の発見:** 内部関係者による不正アクセスや情報漏洩を早期に発見します。
- **コンテキスト分析:** 複数のイベントやデータを関連付けて分析することで、より正確なリスク評価を可能にします。
- **自動化:** 行動分析、リスクスコアリング、アラート生成などを自動化し、セキュリティチームの負担を軽減します。
- **可視化:** ユーザーの行動パターンやリスク状況を可視化し、セキュリティ対策の改善に役立てます。

**3. 事前準備と前提条件**

UEBA を導入する前に、以下の準備と前提条件を確認してください。

- **データソースの特定:** ユーザー行動を分析するために必要なデータソースを特定します。例えば、認証ログ、アクセスログ、アプリケーションログ、ネットワークトラフィックなどがあります。
- **データ収集基盤の構築:** 特定したデータソースからデータを収集し、一元的に管理するための基盤を構築します。SIEM（Security Information and Event Management）やログ管理システムなどを活用します。
- **データの前処理:** 収集したデータを UEBA システムで分析できるように、適切な形式に変換します。データのクレンジング、正規化、エンリッチメントなどを行います。
- **UEBA システムの選定:** 自社の要件に合った UEBA システムを選定します。オンプレミス型、クラウド型、ハイブリッド型など、様々な導入形態があります。
- **プライバシーへの配慮:** UEBA は個人情報を扱うため、プライバシーポリシーを遵守し、適切なセキュリティ対策を講じる必要があります。

**4. 基本的な使い方**

UEBA の基本的な使い方は以下の通りです。

1.  **データソースの接続:** UEBA システムに、特定したデータソースを接続します。
2.  **学習期間の設定:** UEBA システムに、ユーザーの通常行動を学習させるための期間を設定します。通常、数週間から数ヶ月程度の期間が必要です。
3.  **ポリシーの設定:** UEBA システムに、検知したい異常行動のルールを設定します。例えば、特定の時間帯にアクセスする、通常と異なる場所からアクセスするなどがあります。
4.  **アラートの監視:** UEBA システムが生成するアラートを監視し、必要に応じて調査を行います。
5.  **ルールの調整:** アラートの内容や頻度を分析し、ルールの精度を向上させます。
6.  **フィードバックループの構築:** 誤検知や見逃しが発生した場合、その原因を分析し、UEBA システムの改善に繋げます。

**5. 実践的なテクニック**

UEBA を効果的に活用するための実践的なテクニックをいくつか紹介します。

- **ベースラインの確立:** ユーザーやエンティティの通常行動を正確に把握するために、十分な期間をかけてベースラインを確立します。
- **コンテキスト情報の活用:** ユーザーの役割、部署、アクセス権限などのコンテキスト情報を活用することで、より正確な異常検知が可能になります。
- **機械学習アルゴリズムの活用:** 複数の機械学習アルゴリズムを組み合わせることで、様々な種類の異常行動を検知できます。
- **リスクスコアリング:** 異常行動のリスクレベルをスコアリングし、優先順位をつけて対応することで、効率的なインシデント対応が可能になります。
- **相関分析:** 複数のアラートを関連付けて分析することで、より複雑な攻撃や不正行為を検知できます。

例えば、以下のようなスクリプトで、特定のユーザーのログイン失敗回数を監視し、閾値を超えた場合にアラートを生成する簡単な例を考えてみましょう。(擬似コード)

```python
import datetime

def analyze_login_failures(user_id, log_data, threshold=3):
  """
  指定されたユーザーのログイン失敗回数を分析し、閾値を超えた場合にアラートを生成します。

  Args:
    user_id: ユーザーID
    log_data: ログインログのリスト
    threshold: アラートを生成するログイン失敗回数の閾値

  Returns:
    アラートメッセージ（閾値を超えた場合）、または None
  """
  login_failures = 0
  for log in log_data:
    if log['user_id'] == user_id and log['status'] == 'failed' and log['timestamp'] > datetime.datetime.now() - datetime.timedelta(minutes=10): # 過去10分以内の失敗のみカウント
      login_failures += 1

  if login_failures > threshold:
    return f"Alert: User {user_id} has {login_failures} failed login attempts in the last 10 minutes."
  else:
    return None

# 例：
log_data = [
  {'user_id': 'john.doe', 'status': 'success', 'timestamp': datetime.datetime.now()},
  {'user_id': 'john.doe', 'status': 'failed', 'timestamp': datetime.datetime.now()},
  {'user_id': 'john.doe', 'status': 'failed', 'timestamp': datetime.datetime.now()},
  {'user_id': 'john.doe', 'status': 'failed', 'timestamp': datetime.datetime.now()},
  {'user_id': 'jane.doe', 'status': 'success', 'timestamp': datetime.datetime.now()}
]

alert = analyze_login_failures('john.doe', log_data)
if alert:
  print(alert) # Alert: User john.doe has 3 failed login attempts in the last 10 minutes.
```

このコードはあくまで例であり、実際の環境ではログの形式や取得方法が異なるため、適宜修正する必要があります。また、より高度な UEBA システムでは、機械学習アルゴリズムを用いて、ユーザーの通常行動を学習し、閾値を動的に調整することで、より正確な異常検知を実現します。

**6. 応用例とユースケース**

UEBA は、様々な分野で活用できます。以下に、具体的な応用例とユースケースをいくつか紹介します。

- **金融機関:** 不正送金、クレジットカードの不正利用、マネーロンダリングなどの検知
- **医療機関:** 患者情報の不正アクセス、医薬品の横流し、インサイダー取引などの検知
- **製造業:** 知的財産の漏洩、産業スパイ、サプライチェーン攻撃などの検知
- **小売業:** POS システムの不正操作、顧客情報の漏洩、従業員の不正行為などの検知
- **官公庁:** 機密情報の漏洩、サイバー攻撃、情報システムの不正利用などの検知

例えば、ある企業では、UEBA を導入したことで、従業員が深夜に機密ファイルにアクセスしていることを検知しました。調査の結果、その従業員は退職予定であり、競合他社への転職を計画していることが判明しました。企業は事前に情報漏洩を防止することができ、大きな損害を回避することができました。

**7. トラブルシューティング**

UEBA の導入・運用において、よく発生するトラブルとその解決策を以下に示します。

- **誤検知が多い:** ルールの精度が低い、ベースラインの確立が不十分などの原因が考えられます。ルールの調整、ベースラインの再構築、コンテキスト情報の活用などを試してください。
- **検知漏れが多い:** データソースが不足している、ルールの範囲が狭すぎるなどの原因が考えられます。データソースの追加、ルールの範囲の拡大、機械学習アルゴリズムの活用などを検討してください。
- **パフォーマンスが低い:** データ量が多すぎる、システムのリソースが不足しているなどの原因が考えられます。データ量の削減、システムのリソース増強、分散処理の導入などを検討してください。
- **プライバシーの問題:** 個人情報の取り扱いに関する規定が不十分な場合、プライバシー問題が発生する可能性があります。プライバシーポリシーの見直し、匿名化技術の導入などを検討してください。

### システム行動分析（SBA）

**1. 概要と重要性**

システム行動分析（System Behavior Analytics, SBA）は、サーバー、ネットワーク機器、アプリケーションなどのシステムエンティティの通常行動を学習し、そこからの逸脱を検知することで、セキュリティリスクやパフォーマンス問題、運用上の異常を早期に発見する技術です。UEBA が主にユーザーに焦点を当てるのに対し、SBA はシステム全体の状態を把握し、異常な振る舞いを検知することに特化しています。

システムの異常は、セキュリティ侵害の兆候であるだけでなく、パフォーマンスの低下やサービスの停止など、ビジネスに大きな影響を与える可能性があります。SBA は、このような潜在的な問題を早期に発見し、迅速な対応を可能にすることで、ビジネスの安定性と信頼性を向上させます。

**2. 特徴と利点**

SBA の主な特徴と利点は以下の通りです。

- **システム全体の可視化:** サーバー、ネットワーク機器、アプリケーションなど、システム全体の状況を可視化します。
- **異常検知:** システムエンティティの通常行動を学習し、そこからの逸脱を自動的に検知します。
- **根本原因分析:** 異常発生の原因を特定し、問題を迅速に解決するための情報を提供します。
- **パフォーマンス最適化:** システムのパフォーマンスボトルネックを特定し、改善策を提案します。
- **運用効率の向上:** システムの監視、分析、トラブルシューティングなどを自動化し、運用チームの負担を軽減します。
- **セキュリティ強化:** 悪意のあるアクティビティや脆弱性を早期に発見し、セキュリティリスクを低減します。

**3. 事前準備と前提条件**

SBA を導入する前に、以下の準備と前提条件を確認してください。

- **監視対象システムの特定:** SBA で監視するシステムエンティティを特定します。サーバー、ネットワーク機器、アプリケーション、データベースなどがあります。
- **データソースの特定:** システム行動を分析するために必要なデータソースを特定します。システムログ、パフォーマンスメトリクス、ネットワークトラフィックなどがあります。
- **データ収集基盤の構築:** 特定したデータソースからデータを収集し、一元的に管理するための基盤を構築します。SIEM、ログ管理システム、APM（Application Performance Monitoring）ツールなどを活用します。
- **データの前処理:** 収集したデータを SBA システムで分析できるように、適切な形式に変換します。データのクレンジング、正規化、エンリッチメントなどを行います。
- **SBA システムの選定:** 自社の要件に合った SBA システムを選定します。オンプレミス型、クラウド型、ハイブリッド型など、様々な導入形態があります。
- **システムのベースライン設定:** SBA システムが学習するための、システムの通常時のベースラインを設定します。

**4. 基本的な使い方**

SBA の基本的な使い方は以下の通りです。

1.  **データソースの接続:** SBA システムに、特定したデータソースを接続します。
2.  **学習期間の設定:** SBA システムに、システムエンティティの通常行動を学習させるための期間を設定します。通常、数週間から数ヶ月程度の期間が必要です。

4.  **アラートの監視:** SBA システムが生成するアラートを監視し、必要に応じて調査を行います。
5.  **ルールの調整:** アラートの内容や頻度を分析し、ルールの精度を向上させます。

- **相関分析:** 複数のアラートを関連付けて分析することで、より複雑な攻撃やシステム障害を検知できます。
- **自動修復:** 異常発生時に、自動的にシステムを修復する仕組みを構築することで、ダウンタイムを最小限に抑えることができます。

例えば、Linux の CPU 使用率を監視し、異常な状態を検知する簡単なスクリプト例を挙げます。(擬似コード)

```python
import psutil
import time

def analyze_cpu_usage(threshold=80):
  """
  CPU使用率を監視し、閾値を超えた場合にアラートを生成します。

  Args:
    threshold: アラートを生成するCPU使用率の閾値 (%)

  Returns:
    アラートメッセージ（閾値を超えた場合）、または None
  """
  cpu_usage = psutil.cpu_percent(interval=1)
  if cpu_usage > threshold:
    return f"Alert: CPU usage is high: {cpu_usage}%"
  else:
    return None

# 例：
while True:
  alert = analyze_cpu_usage()
  if alert:
    print(alert)
  time.sleep(60) # 1分ごとに監視
```

このスクリプトはあくまで例であり、より高度な SBA システムでは、過去のデータに基づいて CPU 使用率の予測モデルを構築し、予測値からの乖離を検知することで、より早期に異常を検知します。また、複数のメトリクスを組み合わせることで、より複雑なシステム異常を検知することも可能です。

### 行動分析の実装

**1. 概要と重要性**

UEBA と SBA は、どちらも行動分析を用いて異常を検知する技術ですが、その実装方法は異なります。このセクションでは、行動分析を実際に実装する際の一般的なアプローチ、考慮事項、およびツールについて説明します。行動分析の実装は、データの収集、加工、分析、そしてアラート生成という一連の流れを構築することであり、その成否はセキュリティ対策全体の効果に大きく影響します。

**2. 特徴と利点**

行動分析の実装には、様々なアプローチがありますが、主な特徴と利点は以下の通りです。

- **柔軟性:** 自社の環境や要件に合わせて、柔軟にカスタマイズできます。
- **費用対効果:** オープンソースのツールやライブラリを活用することで、導入コストを抑えることができます。

**4. 基本的な使い方**

行動分析の実装は、以下のステップで進めます。

1.  **データ収集:** 特定したデータソースからデータを収集します。ログ収集ツール（Fluentd、Logstash など）、API、データベースクエリなどを使用します。
2.  **データ加工:** 収集したデータを分析しやすい形式に加工します。データのクレンジング、正規化、集計、特徴量抽出などを行います。
3.  **分析モデルの構築:** 機械学習アルゴリズム（教師あり学習、教師なし学習、強化学習など）を用いて、分析モデルを構築します。
4.  **異常検知:** 構築した分析モデルを用いて、異常な行動を検知します。閾値設定、スコアリング、クラスタリングなどを使用します。
5.  **アラート生成:** 異常を検知した場合、セキュリティ担当者にアラートを通知します。メール、Slack、SIEM などを使用します。
6.  **検証と改善:** アラートの精度を検証し、必要に応じて分析モデルやルールを改善します。

**5. 実践的なテクニック**

行動分析を効果的に実装するための実践的なテクニックをいくつか紹介します。

- **特徴量エンジニアリング:** 適切な特徴量を選択・作成することで、分析モデルの精度を向上させることができます。例えば、時間帯、頻度、量、相関関係などがあります。
- **機械学習アルゴリズムの選択:** データの種類や分析目的に合わせて、適切な機械学習アルゴリズムを選択します。例えば、異常検知には、Isolation Forest、One-Class SVM、Autoencoder などがよく使用されます。
- **ハイパーパラメータチューニング:** 機械学習アルゴリズムのハイパーパラメータを調整することで、分析モデルの性能を最適化することができます。
- **アンサンブル学習:** 複数の分析モデルを組み合わせることで、よりロバストな異常検知を実現できます。
- **リアルタイム処理:** 大量のデータをリアルタイムに処理し、迅速な異常検知を実現します。ストリーミング処理フレームワーク（Apache Kafka、Apache Flink など）を使用します。

例えば、Python と scikit-learn ライブラリを使って、ログイン試行回数に基づいて異常を検知する簡単なコード例を以下に示します。

```python
import numpy as np
from sklearn.ensemble import IsolationForest

def detect_login_anomaly(login_attempts):
  """
  ログイン試行回数に基づいて異常を検知します。

  Args:
    login_attempts: ログイン試行回数のリスト

  Returns:
    異常と判定されたインデックスのリスト
  """
  # データを2次元配列に変換
  X = np.array(login_attempts).reshape(-1, 1)

  # Isolation Forestモデルの構築
  model = IsolationForest(n_estimators=100, contamination='auto', random_state=42)
  model.fit(X)

  # 異常スコアの計算
  scores = model.decision_function(X)

  # 異常と判定されたインデックスの取得
  anomalies = np.where(scores < 0)[0]

  return anomalies

# 例：
login_attempts = [1, 2, 3, 1, 2, 3, 1, 2, 3, 100, 2, 3, 1, 2, 3]
anomalies = detect_login_anomaly(login_attempts)
print(f"Anomalies found at indices: {anomalies}") # Anomalies found at indices: [9]
```

このコードは、`IsolationForest`という異常検知アルゴリズムを使用しており、ログイン試行回数が異常に高い（この例では 100）場合に、異常と判定します。

行動分析の実装において、よく発生するトラブルとその解決策を以下に示します。
