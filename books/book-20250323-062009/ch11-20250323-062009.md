## 第 10 章：相関分析：複数の脅威情報を繋ぎ合わせる

### はじめに

セキュリティの世界では、日々大量のログやアラートが発生します。これらの情報は、一見すると無関係に見えるかもしれませんが、相関分析を用いることで、背後に潜む脅威の全体像を浮かび上がらせることができます。相関分析は、複数のイベントやデータを関連付け、より高度な分析や対応を可能にするための強力なツールです。本章では、相関分析の基礎から応用まで、実践的な知識とテクニックを解説します。

### 相関ルールの作成

#### 1. 概要と重要性

相関ルールとは、特定の条件やパターンに合致するイベントを検出するためのルールです。これらのルールは、セキュリティイベント間の関連性を定義し、単独では見過ごされがちな脅威を特定するのに役立ちます。相関ルールを適切に作成することで、誤検知を減らし、真に重要なインシデントに集中することができます。

#### 2. 特徴と利点

- **早期発見:** 攻撃の初期段階で兆候を捉え、被害を最小限に抑える。
- **高度な分析:** 複数の情報源からのデータを統合し、複雑な攻撃を解明する。
- **自動化:** インシデント対応プロセスを自動化し、効率を向上させる。
- **カスタマイズ:** 環境に合わせてルールを調整し、特定の脅威に対応する。

#### 3. 事前準備と前提条件

- **ログ収集基盤:** 様々な情報源からのログを収集・保存できるシステム（SIEM など）。
- **ログの正規化:** 異なる形式のログを統一された形式に変換するプロセス。
- **脅威インテリジェンス:** 既知の攻撃パターンや脆弱性に関する情報。
- **セキュリティの知識:** 攻撃の種類、手法、兆候に関する基本的な知識。

#### 4. 基本的な使い方

相関ルールは、一般的に以下の要素で構成されます。

- **イベントソース:** 監視対象となるログやアラートの種類（例：ファイアウォールログ、IDS アラート）。
- **条件:** イベントの内容を評価するための条件式（例：特定の IP アドレスからのアクセス、特定の URL へのアクセス）。
- **アクション:** 条件が満たされた場合に実行するアクション（例：アラートの発報、ログの記録、インシデントの起票）。

以下は、基本的な相関ルールの例です（擬似コード）。

```
rule suspicious_login {
  on firewall.log and authentication.log
  where firewall.src_ip == authentication.src_ip
    and authentication.result == "failed"
    and firewall.action == "allow"
  within 5 minutes
  then
    alert("Suspicious login attempt detected from IP: " + firewall.src_ip);
}
```

このルールは、ファイアウォールログと認証ログを監視し、同じ IP アドレスからのアクセスで認証が失敗し、かつファイアウォールがそのアクセスを許可している場合に、不審なログイン試行としてアラートを発報します。`within 5 minutes` は、これらのイベントが 5 分以内に発生した場合にのみルールが適用されることを意味します。

#### 5. 実践的なテクニック

- **ベースラインの確立:** 通常時のログパターンを把握し、異常な活動を特定する。
- **閾値の設定:** アラートの頻度を調整するために、イベントの発生回数や時間間隔に閾値を設定する。
- **ホワイトリストの活用:** 誤検知を減らすために、既知の安全なイベントをルールから除外する。
- **ルールのテスト:** 作成したルールをテスト環境で検証し、意図通りに動作するか確認する。
- **ルールの文書化:** ルールの目的、条件、アクションを明確に記述し、運用担当者が理解できるようにする。

#### 6. 応用例とユースケース

- **ブルートフォース攻撃の検出:** 短時間内に複数の認証失敗が発生した場合にアラートを発報する。
- **マルウェア感染の疑い:** 特定のファイルハッシュを持つファイルがダウンロードされた場合にアラートを発報する。
- **データ漏洩の兆候:** 大量のデータが短時間内に外部に送信された場合にアラートを発報する。
- **内部不正の検出:** 従業員が通常アクセスしないファイルやシステムにアクセスした場合にアラートを発報する。

例えば、特定の従業員が深夜に通常アクセスしないサーバにアクセスしようとしたログを検出するルールを作成できます。

```
rule potential_insider_threat {
  on access.log
  where user == "john.doe"
    and server == "sensitive_server"
    and time_of_day >= "00:00" and time_of_day <= "06:00"
  then
    alert("Potential insider threat detected: John Doe accessing sensitive server during off-hours.");
}
```

#### 7. トラブルシューティング

- **アラートの過剰発生:** ルールの条件を厳しくし、閾値を調整する。
- **アラートの未検出:** ルールの条件を緩め、ログソースを確認する。
- **パフォーマンスの問題:** ルールの複雑さを軽減し、インデックスを活用する。
- **ログの欠落:** ログ収集の設定を確認し、ログが適切に収集されているか確認する。

例えば、アラートが過剰に発生する場合は、ルールに時間的制約を追加して、同じイベントが短時間内に複数回発生した場合にのみアラートを発報するように修正できます。

```
rule excessive_failed_logins {
  on authentication.log
  where authentication.result == "failed"
  group by authentication.username
  having count() > 5
  within 1 minute
  then
    alert("Excessive failed login attempts detected for user: " + authentication.username);
}
```

#### 8. まとめと次のステップ

相関ルールの作成は、効果的なセキュリティ監視の基盤です。本セクションで解説した知識とテクニックを活用し、自社の環境に合わせたルールを作成し、継続的に改善していくことが重要です。次のステップとして、相関エンジンについて学び、作成したルールを実際に運用する方法を理解しましょう。

### 相関エンジン

#### 1. 概要と重要性

相関エンジンは、作成された相関ルールに基づいてログやイベントをリアルタイムに分析し、脅威を検出するためのシステムです。相関エンジンは、セキュリティ監視の中核となるコンポーネントであり、高度な脅威を迅速に特定し、対応するための重要な役割を果たします。

#### 2. 特徴と利点

- **リアルタイム分析:** ログやイベントをリアルタイムに処理し、即座に脅威を検出する。
- **スケーラビリティ:** 大量のログやイベントを効率的に処理できる。
- **柔軟性:** 様々なログソースに対応し、カスタマイズされたルールを適用できる。
- **可視化:** 検出された脅威を可視化し、インシデント対応を支援する。

#### 3. 事前準備と前提条件

- **相関ルール:** 作成された相関ルール（前述）。
- **インフラストラクチャ:** 相関エンジンを動作させるためのハードウェアおよびソフトウェアリソース。
- **ログ収集基盤:** ログが相関エンジンに適切に供給されるように設定されていること。
- **ネットワーク構成:** 相関エンジンがログソースにアクセスできるネットワーク構成。

#### 4. 基本的な使い方

相関エンジンは、一般的に以下のステップで動作します。

1.  **ログの受信:** 様々なログソースからログを受信する。
2.  **ログの解析:** 受信したログを解析し、必要な情報を抽出する。
3.  **ルールの評価:** 抽出された情報に基づいて、相関ルールを評価する。
4.  **アラートの発報:** ルールの条件が満たされた場合、アラートを発報する。
5.  **アクションの実行:** アラートに基づいて、自動的なアクションを実行する（例：インシデントの起票、隔離）。

以下は、相関エンジンの設定例です（擬似コード）。

```
correlation_engine {
  rules = [
    suspicious_login,
    potential_insider_threat,
    excessive_failed_logins
  ]
  log_sources = [
    firewall.log,
    authentication.log,
    access.log
  ]
  alert_destination = "siem.server"
}
```

この設定は、`suspicious_login`, `potential_insider_threat`, `excessive_failed_logins`という 3 つのルールを適用し、`firewall.log`, `authentication.log`, `access.log`からログを受信し、アラートを`siem.server`に送信するように設定しています。

#### 5. 実践的なテクニック

- **ルールの優先順位:** 重要なルールを優先的に評価するように設定する。
- **アラートの集約:** 関連するアラートをまとめて、インシデントの全体像を把握しやすくする。
- **アラートの抑制:** 不要なアラートの発報を抑制するために、アラート抑制ルールを設定する。
- **自動レスポンス:** 検出された脅威に対して、自動的に対応するアクションを設定する（例：IP アドレスのブロック、アカウントの無効化）。

#### 6. 応用例とユースケース

- **DDoS 攻撃の緩和:** DDoS 攻撃の兆候を検出し、自動的にトラフィックをフィルタリングする。
- **ランサムウェア感染の阻止:** ランサムウェアの実行を検出し、感染を阻止する。
- **ゼロデイ攻撃の検出:** 既知の攻撃パターンに合致しない、未知の攻撃を検出する。
- **コンプライアンス違反の監視:** 企業のポリシーや規制に違反する行為を検出し、是正措置を講じる。

例えば、異常なネットワークトラフィックパターンを検出して、DDoS 攻撃の可能性を警告するルールを設定できます。

```
rule ddos_detection {
  on network.traffic
  where destination_port == 80 or destination_port == 443
  group by source_ip
  having sum(bytes) > 10GB
  within 1 minute
  then
    alert("Potential DDoS attack detected from IP: " + source_ip);
    block_ip(source_ip, 60); // ブロック処理を60秒実行
}
```

#### 7. トラブルシューティング

- **パフォーマンスの問題:** ルールの最適化、ハードウェアリソースの増強、インデックスの活用。
- **アラートの欠落:** ルールの設定を確認し、ログが適切に解析されているか確認する。
- **相関エンジンの停止:** ログソースとの接続を確認し、エラーログを調査する。
- **誤検知:** ルールの条件を修正し、ホワイトリストを活用する。

例えば、相関エンジンのパフォーマンスが低下している場合は、CPU 使用率やメモリ使用率を監視し、ボトルネックとなっている箇所を特定します。ルールの実行時間が長い場合は、ルールを分割したり、より効率的な条件式を使用したりすることで、パフォーマンスを改善できます。

#### 8. まとめと次のステップ

相関エンジンは、セキュリティ監視の自動化と高度化に不可欠なツールです。本セクションで解説した知識とテクニックを活用し、自社の環境に最適な相関エンジンを構築し、運用していくことが重要です。次のステップとして、相関分析の応用について学び、より高度な脅威検出と対応能力を身につけましょう。

### 相関分析の応用

#### 1. 概要と重要性

相関分析の応用とは、基本的な相関分析の概念を拡張し、より複雑な脅威を検出したり、インシデント対応を高度化したりするためのテクニックです。高度な相関分析を駆使することで、未知の脅威をプロアクティブに検出し、セキュリティ体制を強化することができます。

#### 2. 特徴と利点

- **高度な脅威検出:** 複雑な攻撃キャンペーンや APT 攻撃を検出する。
- **プロアクティブな防御:** 既知の脅威だけでなく、未知の脅威にも対応する。
- **インシデント対応の効率化:** インシデントの根本原因を特定し、迅速な対応を可能にする。
- **脅威インテリジェンスの活用:** 外部の脅威インテリジェンス情報を活用し、攻撃の兆候を早期に検出する。

#### 3. 事前準備と前提条件

- **相関ルールの作成スキル:** 高度な相関ルールを作成できる能力。
- **相関エンジンの知識:** 相関エンジンの設定や運用に関する深い知識。
- **脅威インテリジェンス:** 外部の脅威情報源へのアクセス。
- **セキュリティ分析のスキル:** ログやアラートを分析し、脅威を特定する能力。

#### 4. 基本的な使い方

相関分析の応用では、以下のようなテクニックが用いられます。

- **行動分析:** ユーザーやシステムのアクティビティを監視し、異常な行動を検出する。
- **機械学習:** 機械学習モデルを用いて、脅威を予測したり、異常を検出したりする。
- **脅威インテリジェンスの統合:** 外部の脅威インテリジェンス情報を相関ルールに組み込み、攻撃の兆候を早期に検出する。
- **グラフ分析:** イベント間の関係性をグラフ構造で表現し、隠れた脅威を可視化する。

以下は、行動分析を用いた相関ルールの例です（擬似コード）。

```
rule unusual_file_access {
  on file.access
  where user == "john.doe"
  and file_type == "sensitive_document"
  group by user, file_type
  having count() > baseline_access_count(user, file_type) * 2 // 通常アクセス回数の2倍以上
  within 1 day
  then
    alert("Unusual file access detected for user: " + user);
}
```

このルールは、特定のユーザーが機密文書にアクセスする回数を監視し、通常時のアクセス回数の 2 倍以上アクセスした場合に、異常な行動としてアラートを発報します。`baseline_access_count(user, file_type)`は、過去のアクセスログから算出したベースラインのアクセス回数を返す関数です。

#### 5. 実践的なテクニック

- **多段階相関:** 複数のイベントを段階的に関連付け、複雑な攻撃を検出する。
- **時間ベースの相関:** イベントの時間的な関係性を分析し、攻撃のタイミングを把握する。
- **地理情報に基づく相関:** IP アドレスの地理情報を活用し、不審なアクセスを検出する。
- **ユーザーエンティティ行動分析 (UEBA):** ユーザーの行動パターンを学習し、異常な行動を検出する。

例えば、特定のユーザーが通常とは異なる時間帯に VPN 接続し、その後機密ファイルにアクセスした場合にアラートを発報する多段階相関ルールを作成できます。

```
rule suspicious_vpn_and_file_access {
  stage 1:
    on vpn.connection
    where user == "john.doe"
    and time_of_day >= "00:00" and time_of_day <= "06:00"
    then
      set_context(user, "vpn_access_time", time_of_day);

  stage 2:
    on file.access
    where user == "john.doe"
    and file_type == "sensitive_document"
    and time_of_day >= context_get(user, "vpn_access_time")
    within 30 minutes
    then
      alert("Suspicious VPN connection and file access detected for user: " + user);
}
```

#### 6. 応用例とユースケース

- **APT 攻撃の検出:** 標的型攻撃の初期段階を検出し、被害を未然に防ぐ。
- **内部不正の高度な検出:** 従業員の異常な行動を分析し、データ漏洩や不正行為を検出する。
- **サプライチェーン攻撃の検出:** サプライチェーンを経由した攻撃を検出し、ビジネスへの影響を最小限に抑える。
- **クラウド環境のセキュリティ監視:** クラウド環境におけるセキュリティイベントを分析し、設定ミスや脆弱性を検出する。

例えば、ある企業が、サプライチェーン攻撃を受けているかどうかを調べるために、サプライヤーからの通信ログを分析し、通常とは異なる通信パターンや、既知の攻撃に関連する IP アドレスとの通信を検出するルールを作成できます。

#### 7. トラブルシューティング

- **複雑性の管理:** ルールをモジュール化し、段階的にテストする。
- **パフォーマンスの最適化:** 高度なテクニックはリソースを消費するため、パフォーマンスを継続的に監視し、最適化する。
- **誤検知の削減:** ルールの精度を高めるために、継続的にチューニングを行う。
- **データの品質:** 分析に使用するデータの品質を確保する。

例えば、UEBA（User and Entity Behavior Analytics）を使用している場合、誤検知を減らすために、学習期間を十分に確保し、ユーザーの行動パターンを正確に把握する必要があります。また、機械学習モデルの精度を定期的に評価し、必要に応じて再トレーニングを行うことが重要です。

#### 8. まとめと次のステップ

相関分析の応用は、セキュリティ監視を高度化し、より強力な防御体制を構築するための鍵となります。本セクションで解説した知識とテクニックを活用し、自社の環境に合わせた高度な相関分析を実践し、継続的に改善していくことが重要です。今後は、AI や機械学習などの最新技術を活用し、相関分析をさらに進化させていくことが期待されます。
