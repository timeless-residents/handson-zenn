## 第 16 章：セキュリティに関する最新トレンド：サプライチェーン攻撃、ゼロトラスト

近年のサイバー攻撃は、より巧妙化し、その標的も変化し続けています。特に、ソフトウェアサプライチェーン攻撃とゼロトラストという概念は、現代のセキュリティ対策において無視できない重要なトレンドです。本章では、これらのトレンドについて詳しく解説し、実践的な対策を提示します。

### サプライチェーン攻撃

#### 1. 概要と重要性

サプライチェーン攻撃とは、ソフトウェアの開発から配布、運用に至るまでの過程（サプライチェーン）に関わる組織やツールを攻撃対象とする手法です。従来の直接的な攻撃と異なり、信頼された第三者を経由することで、攻撃の検知を困難にし、より広範囲に影響を及ぼす可能性があります。 SolarWinds 社の Orion プラットフォームに対する大規模なサプライチェーン攻撃は、その深刻さを如実に示しています。 この攻撃では、Orion のアップデートにマルウェアが仕込まれ、数千もの企業や政府機関が被害を受けました。

#### 2. 特徴と利点（ここでは攻撃側の視点）

サプライチェーン攻撃の利点は、攻撃者が一度侵入に成功すれば、複数の組織に同時に影響を与えられる点です。また、攻撃対象が信頼されているため、セキュリティ対策を迂回しやすいという特徴があります。従来の境界防御型セキュリティでは防ぎきれない、新たな脅威として認識されています。

#### 3. 事前準備と前提条件

サプライチェーン攻撃への対策を講じるためには、まず自社のソフトウェアサプライチェーン全体を可視化する必要があります。具体的には、利用しているソフトウェア、ライブラリ、開発ツール、そしてそれらの提供元を洗い出し、リスク評価を行うことが重要です。また、SBOM（Software Bill of Materials）の作成と利用は、サプライチェーンの透明性を高める上で不可欠です。

#### 4. 基本的な使い方

サプライチェーン攻撃への対策は多岐にわたりますが、以下に基本的なアプローチを示します。

- **SBOM（Software Bill of Materials）の導入:** ソフトウェア部品表を作成し、利用しているソフトウェアの構成要素を明確にします。これにより、脆弱性のある部品を特定しやすくなります。
- **ソフトウェア署名の検証:** ソフトウェアの配布元が提供する署名を検証し、改ざんされていないことを確認します。
- **脆弱性管理の徹底:** 利用しているソフトウェアの脆弱性情報を常に監視し、迅速なパッチ適用を行います。
- **サプライヤーリスク管理:** サプライヤーのセキュリティ対策状況を評価し、リスクの高いサプライヤーとの取引を制限します。
- **最小権限の原則:** ソフトウェアやツールに対するアクセス権限を必要最小限に絞り、不正アクセスによる被害を抑制します。
- **多層防御:** 単一の防御策に依存せず、複数のセキュリティ対策を組み合わせることで、攻撃に対する耐性を高めます。

#### 5. 実践的なテクニック

以下に、具体的な対策例をコードスニペットや設定例を用いて示します。

**a. SBOM の生成と利用（Dependency Track の例）**

Dependency Track は、SBOM を管理し、脆弱性分析を行うためのオープンソースツールです。

1.  Dependency Track をインストールし、起動します。
2.  ソフトウェアの依存関係ファイルを Dependency Track にアップロードします（例：Maven の`pom.xml`、npm の`package-lock.json`）。

    ```bash
    # Mavenの場合
    mvn org.cyclonedx:cyclonedx-maven-plugin:2.7.5:makeBom -DoutputName=bom.xml
    ```

3.  Dependency Track は、アップロードされたファイルから SBOM を生成し、脆弱性情報を自動的に分析します。
4.  脆弱性が検出された場合は、Dependency Track のダッシュボードから詳細な情報を確認し、対応策を検討します。

**b. ソフトウェア署名の検証（GNU Privacy Guard (GPG) の例）**

GPG を使ってソフトウェアの署名を検証します。

1.  配布元からソフトウェアとその署名ファイル（例：`software.tar.gz` と `software.tar.gz.asc`）を入手します。
2.  配布元の公開鍵をインポートします。

    ```bash
    gpg --keyserver hkp://keys.gnupg.net --recv-keys <配布元の公開鍵ID>
    ```

3.  署名を検証します。

    ```bash
    gpg --verify software.tar.gz.asc software.tar.gz
    ```

    検証が成功した場合、「Good signature」と表示されます。署名が無効な場合、警告が表示されます。

**c. 脆弱性スキャンの自動化 (OWASP ZAP の例)**

OWASP ZAP は、Web アプリケーションの脆弱性スキャンを行うためのオープンソースツールです。 Jenkins などの CI/CD パイプラインに組み込むことで、脆弱性スキャンを自動化できます。

```bash
# ZAP Dockerイメージを使ってスキャンを実行
docker run -v $(pwd):/zap/wrk/:rw -t owasp/zap2docker-weekly zap-baseline.py -t http://example.com -g gen.conf -x results.xml

# results.xmlを解析して脆弱性を報告
```

#### 6. 応用例とユースケース

- **自動車業界:** 車載ソフトウェアのサプライチェーンは複雑であり、多くのサプライヤーが関与しています。SBOM を活用してソフトウェア部品を追跡し、脆弱性のある部品を迅速に特定することで、車両の安全性を確保します。
- **金融業界:** 金融機関は、多くのソフトウェアを利用しており、その多くは外部ベンダーから提供されています。サプライヤーリスク管理を徹底し、ソフトウェアのセキュリティ評価を行うことで、金融システムの安定性を維持します。
- **政府機関:** 政府機関は、機密情報を扱うシステムを運用しており、サプライチェーン攻撃による情報漏洩のリスクが高くなっています。ソフトウェア署名の検証を義務付け、改ざんされたソフトウェアの利用を防ぐことで、情報セキュリティを強化します。

#### 7. トラブルシューティング

- **SBOM の作成に失敗する場合:** 利用しているツールが SBOM を生成する機能をサポートしているか確認してください。また、依存関係ファイルの形式が正しいか確認してください。
- **署名の検証に失敗する場合:** 配布元の公開鍵が正しいか確認してください。また、ソフトウェアが改ざんされていないか確認してください。
- **脆弱性スキャンで誤検知が発生する場合:** スキャンの設定を調整し、誤検知を除外してください。また、脆弱性情報の信頼性を確認してください。

#### 8. まとめと次のステップ

サプライチェーン攻撃は、現代のセキュリティにおける深刻な脅威であり、組織はサプライチェーン全体を可視化し、セキュリティ対策を講じる必要があります。SBOM の導入、ソフトウェア署名の検証、脆弱性管理の徹底など、多層的なアプローチが重要です。次のステップとして、自社のサプライチェーンにおけるリスク評価を行い、優先順位をつけて対策を実施することをお勧めします。また、ゼロトラストアーキテクチャの導入も、サプライチェーン攻撃に対する有効な防御策となります。

### ゼロトラスト

#### 1. 概要と重要性

ゼロトラストとは、「決して信頼せず、常に検証する」という原則に基づいたセキュリティモデルです。従来の境界防御型セキュリティとは異なり、ネットワークの内外を問わず、全てのアクセスを信用しないという考え方が根底にあります。リモートワークの普及やクラウドサービスの利用拡大により、従来の境界が曖昧になる中、ゼロトラストは現代のセキュリティ対策における重要なパラダイムシフトとなっています。 ゼロトラストは、単なる技術的な対策ではなく、組織全体のセキュリティ文化を変革するアプローチです。

#### 2. 特徴と利点

ゼロトラストの主な特徴は以下の通りです。

- **マイクロセグメンテーション:** ネットワークを細かく分割し、アクセス制御を厳格化することで、攻撃範囲を限定します。
- **最小権限の原則:** ユーザーやアプリケーションに対するアクセス権限を必要最小限に絞り、不正アクセスによる被害を抑制します。
- **多要素認証（MFA）:** ユーザー認証に複数の要素を組み合わせることで、不正アクセスのリスクを低減します。
- **継続的な監視と分析:** ネットワークトラフィックやユーザーアクティビティを継続的に監視し、異常な挙動を早期に検知します。
- **デバイスのセキュリティ:** 接続するデバイスのセキュリティ状態を評価し、安全なデバイスのみアクセスを許可します。

ゼロトラストの利点は、攻撃者がネットワークに侵入した場合でも、被害を最小限に抑えることができる点です。また、リモートワークやクラウドサービスの利用を安全に推進することができます。

#### 3. 事前準備と前提条件

ゼロトラストを導入する前に、以下の準備が必要です。

- **現状のセキュリティ体制の評価:** 現在のセキュリティ対策の課題を洗い出し、ゼロトラストの導入によって何を改善したいかを明確にします。
- **ビジネス要件の理解:** ゼロトラストの導入がビジネスに与える影響を評価し、適切なバランスを見つけます。
- **リソースの確保:** ゼロトラストの導入には、人員、技術、予算が必要です。必要なリソースを確保します。
- **組織文化の変革:** ゼロトラストは、組織全体のセキュリティ文化を変革するアプローチです。従業員の理解と協力を得るために、教育やトレーニングを実施します。

#### 4. 基本的な使い方

ゼロトラストの導入は段階的に行うことが推奨されます。以下に、基本的なステップを示します。

1.  **ID とアクセスの管理:** ユーザーの ID とアクセス権限を集中管理し、最小権限の原則を適用します。
2.  **デバイスのセキュリティ:** デバイスのセキュリティ状態を評価し、安全なデバイスのみアクセスを許可します。
3.  **ネットワークのマイクロセグメンテーション:** ネットワークを細かく分割し、アクセス制御を厳格化します。
4.  **アプリケーションのセキュリティ:** アプリケーションの脆弱性を管理し、安全なアプリケーションのみ利用を許可します。
5.  **データの保護:** データの暗号化やアクセス制御を強化し、データの機密性と完全性を保護します。
6.  **継続的な監視と分析:** ネットワークトラフィックやユーザーアクティビティを継続的に監視し、異常な挙動を早期に検知します。

#### 5. 実践的なテクニック

以下に、具体的な対策例をコードスニペットや設定例を用いて示します。

**a. 多要素認証（MFA）の設定（Google Workspace の例）**

Google Workspace で MFA を設定します。

1.  Google Workspace の管理コンソールにログインします。
2.  [セキュリティ] > [2 段階認証プロセス] に移動します。
3.  ユーザーに対して 2 段階認証を有効にします。
4.  ユーザーは、スマートフォンアプリ（Google Authenticator など）やセキュリティキーを使って 2 段階認証を設定します。

**b. マイクロセグメンテーションの設定（Cisco ACI の例）**

Cisco ACI を使ってネットワークをマイクロセグメント化します。

```
# ACI Fabricへのログイン
apic login -c <APICのIPアドレス> -u <ユーザー名> -p <パスワード>

# VRFの作成
aci vrf create -n <VRF名> -t tenant

# ブリッジドメインの作成
aci bridge-domain create -n <ブリッジドメイン名> -v <VRF名>

# エンドポイントグループ（EPG）の作成
aci epg create -n <EPG名> -v <ブリッジドメイン名>

# コントラクトの作成
aci contract create -n <コントラクト名>

# コントラクトへのフィルターの追加
aci filter create -n <フィルター名> -p ip -d tcp -s 80 -e destinationPort

# EPG間のコントラクトの適用
aci epg consume -n <EPG名> -c <コントラクト名>
aci epg provide -n <EPG名> -c <コントラクト名>
```

**c. 最小権限の原則の適用（AWS IAM の例）**

AWS IAM を使って最小権限の原則を適用します。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::my-bucket/my-object"
    },
    {
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*"
    }
  ]
}
```

このポリシーは、`my-bucket`の`my-object`に対する`s3:GetObject`アクションのみを許可し、他の全てのアクションを拒否します。

#### 6. 応用例とユースケース

- **金融機関:** 金融機関は、機密性の高い顧客情報を扱っており、ゼロトラストを導入することで、情報漏洩のリスクを低減し、規制遵守を強化します。
- **医療機関:** 医療機関は、患者の個人情報を扱っており、ゼロトラストを導入することで、個人情報保護法（HIPAA）などの規制遵守を強化します。
- **製造業:** 製造業は、知的財産や機密情報を扱っており、ゼロトラストを導入することで、産業スパイやデータ漏洩のリスクを低減します。

#### 7. トラブルシューティング

- **MFA の設定でユーザーがロックアウトされる場合:** 回復コードやバックアップ認証方法を用意しておきます。
- **マイクロセグメンテーションの設定でアプリケーションが動作しなくなる場合:** ファイアウォールルールを見直し、必要な通信を許可します。
- **最小権限の原則を適用した結果、必要な操作ができなくなる場合:** ロールやポリシーを見直し、必要な権限を付与します。

#### 8. まとめと次のステップ

ゼロトラストは、現代のセキュリティにおける重要なパラダイムシフトであり、組織はゼロトラストの原則に基づいてセキュリティ対策を再構築する必要があります。多要素認証、マイクロセグメンテーション、最小権限の原則など、多層的なアプローチが重要です。次のステップとして、自社のビジネス要件とリスクを評価し、ゼロトラストの導入計画を策定することをお勧めします。また、サプライチェーン攻撃対策と合わせて、ゼロトラストアーキテクチャを導入することで、より強固なセキュリティ体制を構築できます。
