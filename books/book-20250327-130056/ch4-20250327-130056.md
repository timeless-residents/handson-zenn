## 第 3 章：情報収集：攻撃対象の情報を徹底的に洗い出す

攻撃の成功は、どれだけ対象について深く理解しているかに大きく左右されます。この章では、攻撃対象の情報を徹底的に洗い出すためのさまざまな手法、すなわち情報収集（Information Gathering）について解説します。オープンソースインテリジェンス (OSINT) から、アクティブな偵察 (Reconnaissance)、そして Web サイト構造の分析まで、幅広くカバーすることで、読者が自身のスキルセットと目的に合った情報収集戦略を立てられるようにすることを目指します。

### OSINT (Open Source Intelligence)

OSINT とは、公開されている情報源から情報を収集・分析する手法です。インターネット上には想像以上に多くの情報が公開されており、これらを効果的に活用することで、攻撃対象の隠れた側面を明らかにすることができます。

#### Google Hacking：検索演算子を利用した情報収集

**1. 概要と重要性**

Google Hacking は、Google などの検索エンジンを、高度な検索演算子（Advanced Operators）を使って特定目的のために活用するテクニックです。 通常の検索では見つけられない、機密情報や脆弱性のある Web ページを発見することができます。攻撃対象の特定のファイル形式、ディレクトリ、エラーメッセージなどを効率的に探し出すことが可能です。

**2. 特徴と利点**

- **手軽さ**: 無料で利用できる Google 検索を使用するため、特別なツールや費用は不要です。
- **効率性**: 検索演算子を組み合わせることで、ピンポイントな情報収集が可能です。
- **情報量**: インターネット上に公開されている膨大な情報の中から必要なものを選び出すことができます。

**3. 事前準備と前提条件**

- インターネット接続環境
- Google などの検索エンジンへのアクセス
- 検索演算子の理解

**4. 基本的な使い方**

Google 検索で以下の演算子を使用します。

- `site:` 特定のドメインに限定して検索 (例: `site:example.com`)
- `filetype:` 特定のファイル形式を検索 (例: `filetype:pdf`)
- `inurl:` URL に特定の文字列を含むページを検索 (例: `inurl:admin`)
- `intitle:` タイトルに特定の文字列を含むページを検索 (例: `intitle:login`)
- `intext:` 本文に特定の文字列を含むページを検索 (例: `intext:"password reset"`)
- `ext:` 特定の拡張子を持つファイルを検索 (例: `ext:log`)
- `cache:` Web ページのキャッシュされたバージョンを表示
- `related:` 特定の Web ページと類似した Web ページを検索
- `info:` Web ページに関する情報を表示
- `-` 除外キーワード (例: `security -wordpress`)

**5. 実践的なテクニック**

- **機密ファイルの検索**: `site:example.com filetype:pdf "internal"` (example.com の内部情報を含む PDF ファイルを検索)
- **ログインページの検索**: `site:example.com inurl:login` (example.com のログインページを検索)
- **脆弱性のあるソフトウェアの検索**: `intitle:"index of" "software name"` (特定のソフトウェアのディレクトリを表示)
- **設定ファイルの検索**: `site:example.com filetype:config` (example.com の設定ファイルを検索)

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 公開されている設定ファイルやエラーメッセージから脆弱性を特定。
- **脅威インテリジェンス**: 組織に関連する機密情報や漏洩情報を早期に発見。
- **情報漏洩の監視**: 自社ドメインに関連する機密情報の公開を検知。

**7. トラブルシューティング**

- **検索結果が多すぎる**: 検索演算子を組み合わせて、より具体的な検索クエリを作成する。
- **検索結果が少なすぎる**: キーワードを見直したり、関連するキーワードを追加する。
- **検索エンジンによるブロック**: CAPTCHA 認証が必要になる場合がある。IP アドレスを変えたり、検索頻度を調整する。

**8. まとめと次のステップ**

Google Hacking は、OSINT の強力なツールです。検索演算子を理解し、実践的なテクニックを習得することで、攻撃対象の情報を効率的に収集できます。 次のステップとして、他の OSINT ツールや手法と組み合わせることで、より包括的な情報収集を目指しましょう。

#### Shodan：インターネットに接続されたデバイスの検索

**1. 概要と重要性**

Shodan は、インターネットに接続されたデバイスを検索できる検索エンジンです。Web サイトだけでなく、ルーター、Web カメラ、産業用制御システムなど、あらゆるデバイスを識別し、その情報を収集できます。これにより、脆弱性のあるデバイスや設定ミスを発見し、潜在的な攻撃経路を特定できます。

**2. 特徴と利点**

- **広範な検索範囲**: Web サイトだけでなく、IoT デバイスなど、あらゆるインターネット接続デバイスを検索可能。
- **詳細な情報**: デバイスの種類、ソフトウェアバージョン、ポート情報など、詳細な情報を取得可能。
- **脆弱性の特定**: 特定のソフトウェアバージョンや設定に存在する脆弱性を特定可能。

**3. 事前準備と前提条件**

- Shodan アカウントの作成 (無料アカウントでも利用可能)
- インターネット接続環境
- 基本的なネットワーク知識

**4. 基本的な使い方**

Shodan の検索ボックスにキーワードを入力して検索します。

- **IP アドレス**: `192.168.1.1` (特定の IP アドレスを持つデバイスを検索)
- **ポート**: `port:22` (22 番ポートが開いているデバイスを検索)
- **国**: `country:"JP"` (日本にあるデバイスを検索)
- **都市**: `city:"Tokyo"` (東京にあるデバイスを検索)
- **OS**: `os:"Windows"` (Windows OS を実行しているデバイスを検索)
- **製品**: `product:"Apache"` (Apache Web サーバーを実行しているデバイスを検索)
- **バージョン**: `version:"2.4.38"` (特定のバージョンのソフトウェアを実行しているデバイスを検索)

**5. 実践的なテクニック**

- **脆弱性のあるデバイスの検索**: `product:"Apache" version:"2.2"` (古いバージョンの Apache を実行しているデバイスを検索)
- **デフォルト認証情報を使用しているデバイスの検索**: `product:"Webcam" has_screenshot:true` (Web カメラのスクリーンショットを表示し、デフォルト認証情報が使用されているか確認)
- **特定のネットワーク範囲のデバイスの検索**: `net:"192.168.1.0/24"` (特定のネットワーク範囲にあるデバイスを検索)

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 脆弱性のあるデバイスを特定し、攻撃経路を確立。
- **IoT セキュリティ**: 自社ネットワーク内の IoT デバイスのセキュリティ状況を評価。
- **脅威インテリジェンス**: 特定の脆弱性を持つデバイスの分布を調査。

**7. トラブルシューティング**

- **検索結果が多すぎる**: より具体的な検索クエリを使用する。フィルタリングオプションを活用する。
- **API 制限**: 無料アカウントの場合、API の利用に制限がある。有料アカウントへのアップグレードを検討する。
- **誤検知**: Shodan の情報が必ずしも最新であるとは限らない。手動で確認する。

**8. まとめと次のステップ**

Shodan は、インターネットに接続されたデバイスを網羅的に検索できる強力なツールです。脆弱性のあるデバイスの特定や、攻撃対象のネットワーク構成の把握に役立ちます。次のステップとして、Censys などの類似ツールと比較検討し、より効果的な情報収集戦略を確立しましょう。

#### Censys：証明書情報を利用した情報収集

**1. 概要と重要性**

Censys は、Shodan と同様にインターネットに接続されたデバイスを検索できる検索エンジンですが、特に TLS/SSL 証明書に焦点を当てている点が特徴です。証明書情報は、Web サイトのドメイン名、組織名、IP アドレスなど、多くの情報を含んでいます。これらの情報を分析することで、攻撃対象のインフラストラクチャ全体像を把握し、関連するドメインやサブドメインを発見できます。

**2. 特徴と利点**

- **証明書情報の詳細な分析**: TLS/SSL 証明書に含まれる情報を詳細に分析し、関連情報を抽出可能。
- **ドメインの関連性の特定**: 証明書を共有するドメインを特定し、攻撃対象の関連組織やインフラストラクチャを発見。
- **脆弱性の特定**: 古いバージョンの TLS/SSL プロトコルを使用しているデバイスを特定。

**3. 事前準備と前提条件**

- Censys アカウントの作成 (無料アカウントでも利用可能)
- インターネット接続環境
- TLS/SSL 証明書に関する基本的な知識

**4. 基本的な使い方**

Censys の検索ボックスにキーワードを入力して検索します。

- **ドメイン名**: `domain:example.com` (example.com に関連する証明書を検索)
- **IP アドレス**: `ip:192.168.1.1` (特定の IP アドレスに関連する証明書を検索)
- **組織名**: `organization:"Example Company"` (Example Company に関連する証明書を検索)
- **Common Name (CN)**: `subject.cn:example.com` (証明書の Common Name が example.com である証明書を検索)
- **証明書フィンガープリント**: `fingerprint:"SHA256 fingerprint"` (特定のフィンガープリントを持つ証明書を検索)

**5. 実践的なテクニック**

- **関連ドメインの発見**: `domain:example.com AND NOT domain:example.com` (example.com と証明書を共有する別のドメインを検索)
- **ワイルドカード証明書の検索**: `subject.cn: "*.example.com"` (example.com のワイルドカード証明書を検索)
- **自己署名証明書の検索**: `validation.browser_trusted: false` (ブラウザによって信頼されていない自己署名証明書を検索)

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 関連ドメインやサブドメインを特定し、攻撃対象を拡大。
- **証明書管理**: 自社ドメインの証明書情報を監視し、不正な証明書の発行を検知。
- **フィッシング対策**: フィッシングサイトで使用されている証明書を特定し、早期にブロック。

**7. トラブルシューティング**

- **検索結果が多すぎる**: より具体的な検索クエリを使用する。フィルタリングオプションを活用する。
- **API 制限**: 無料アカウントの場合、API の利用に制限がある。有料アカウントへのアップグレードを検討する。
- **証明書の変更**: 証明書は定期的に更新されるため、最新の情報を確認する。

**8. まとめと次のステップ**

Censys は、証明書情報を利用して攻撃対象のインフラストラクチャを詳細に分析できるツールです。関連ドメインの発見や、脆弱性のあるデバイスの特定に役立ちます。次のステップとして、Shodan などの他の OSINT ツールと組み合わせ、より多角的な情報収集を目指しましょう。

#### Wayback Machine：過去の Web サイトのアーカイブ

**1. 概要と重要性**

Wayback Machine は、インターネットアーカイブが提供する Web サイトの過去のバージョンを閲覧できるサービスです。削除されたページ、古いコンテンツ、過去の Web サイト構造などを確認できます。攻撃対象の過去の情報を分析することで、機密情報の漏洩、脆弱性のあるコード、使用されていた技術スタックなどを発見できる可能性があります。

**2. 特徴と利点**

- **過去の Web サイトの閲覧**: 削除されたページや古いコンテンツを閲覧可能。
- **Web サイトの変更履歴**: Web サイトの過去のバージョンを比較し、変更履歴を確認可能。
- **情報漏洩の発見**: 過去に公開されていた機密情報や脆弱性のあるコードを発見可能。

**3. 事前準備と前提条件**

- インターネット接続環境
- Wayback Machine へのアクセス

**4. 基本的な使い方**

Wayback Machine の検索ボックスに URL を入力して検索します。カレンダーが表示され、過去の Web サイトのスナップショットが利用可能な日付がハイライトされます。日付をクリックすると、その時点の Web サイトのバージョンが表示されます。

**5. 実践的なテクニック**

- **robots.txt の過去のバージョン**: 過去の robots.txt を分析し、アクセス制限されていたディレクトリやファイルを発見。
- **JavaScript ファイルの過去のバージョン**: 過去の JavaScript ファイルを分析し、API キーや機密情報を発見。
- **削除されたページの復元**: 削除されたページを復元し、重要な情報を入手。

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 過去の脆弱性のあるコードや設定ファイルを発見し、攻撃経路を確立。
- **情報漏洩の調査**: 過去に公開されていた機密情報の漏洩を調査。
- **Web サイトの変更履歴の分析**: Web サイトの変更履歴を分析し、重要な変更点や脆弱性の導入時期を特定。

**7. トラブルシューティング**

- **アーカイブされていないページ**: Wayback Machine はすべての Web サイトをアーカイブしているわけではない。
- **コンテンツの不完全性**: アーカイブされたコンテンツが完全に復元されない場合がある。
- **Cookie やセッション**: 過去のセッションや Cookie は利用できない。

**8. まとめと次のステップ**

Wayback Machine は、過去の Web サイトの情報を収集し、攻撃対象の隠された側面を明らかにするのに役立つツールです。情報漏洩の調査や、過去の脆弱性の発見に役立ちます。次のステップとして、他の OSINT ツールと組み合わせ、より包括的な情報収集戦略を立てましょう。

#### Social Media Intelligence：SNS からの情報収集 (LinkedIn, Twitter)

**1. 概要と重要性**

Social Media Intelligence (SOCMINT) は、ソーシャルメディアプラットフォーム（LinkedIn、Twitter、Facebook など）から情報を収集・分析する手法です。従業員の氏名、役職、使用技術、企業文化、イベント情報など、攻撃対象に関するさまざまな情報を収集できます。これらの情報を基に、ソーシャルエンジニアリング攻撃や標的型攻撃の足がかりを築くことができます。

**2. 特徴と利点**

- **リアルタイムの情報**: ソーシャルメディアはリアルタイムの情報源であり、最新の情報を収集可能。
- **多種多様な情報**: 従業員、企業、製品、イベントなど、多種多様な情報を収集可能。
- **ソーシャルエンジニアリングの足がかり**: 従業員の情報を収集し、ソーシャルエンジニアリング攻撃の足がかりを築く。

**3. 事前準備と前提条件**

- ソーシャルメディアプラットフォームのアカウント (LinkedIn、Twitter など)
- インターネット接続環境
- ソーシャルメディアの利用に関する倫理的な配慮

**4. 基本的な使い方**

各ソーシャルメディアプラットフォームの検索機能を使用して情報を収集します。

- **LinkedIn**: 従業員の氏名、役職、スキル、所属グループなどを検索。
- **Twitter**: 企業アカウント、ハッシュタグ、キーワードなどを検索。
- **Facebook**: 企業ページ、イベント、グループなどを検索。

**5. 実践的なテクニック**

- **従業員情報の収集**: LinkedIn で従業員の氏名、役職、スキルを検索し、技術スタックや組織構造を把握。
- **企業情報の収集**: Twitter で企業アカウントをフォローし、最新のニュースやイベント情報を収集。
- **ハッシュタグの分析**: 特定のハッシュタグを分析し、関心のあるトピックやイベントに関する情報を収集。

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 従業員の情報を収集し、ソーシャルエンジニアリング攻撃を模擬。
- **脅威インテリジェンス**: ソーシャルメディア上の脅威情報を収集し、早期にリスクを軽減。
- **ブランド保護**: ソーシャルメディア上での自社ブランドに関する言及を監視し、風評被害を防止。

**7. トラブルシューティング**

- **プライバシー設定**: ソーシャルメディアのプライバシー設定により、情報収集が制限される場合がある。
- **偽アカウント**: 偽アカウントや誤った情報に注意する。
- **倫理的な問題**: 情報収集の際には、プライバシーを尊重し、倫理的な問題に配慮する。

**8. まとめと次のステップ**

Social Media Intelligence は、ソーシャルメディアプラットフォームから情報を収集し、攻撃対象の人間関係、企業文化、技術スタックなどを明らかにするのに役立つ手法です。ソーシャルエンジニアリング攻撃の対策や、ブランド保護に役立ちます。次のステップとして、他の OSINT ツールと組み合わせ、より包括的な情報収集戦略を立てましょう。

### Reconnaissance

Reconnaissance（偵察）とは、攻撃対象のネットワークやシステムに関する情報を積極的に収集する段階です。OSINT が公開情報を中心に収集するのに対し、Reconnaissance はより直接的な手法を用いて、より詳細な情報を取得します。

#### DNS 情報：ドメイン名、IP アドレス、ネームサーバーの特定

**1. 概要と重要性**

DNS（Domain Name System）情報は、ドメイン名と IP アドレスの対応関係や、ネームサーバーの情報など、ネットワークの基本的な構成要素に関する重要な情報を提供します。これらの情報を収集することで、攻撃対象のネットワークインフラストラクチャを理解し、攻撃対象を特定することができます。

**2. 特徴と利点**

- **ネットワーク構造の把握**: ドメイン名、IP アドレス、ネームサーバーの情報を収集し、ネットワーク構造を把握。
- **攻撃対象の特定**: サブドメインや関連ドメインを特定し、攻撃対象を拡大。
- **サービスの特定**: DNS レコードから、Web サーバー、メールサーバー、その他のサービスを特定。

**3. 事前準備と前提条件**

- ターミナルまたはコマンドプロンプト
- `nslookup`、`dig`などの DNSlookup ツール

**4. 基本的な使い方**

- **`nslookup`**:
  - `nslookup example.com` (example.com の IP アドレスを検索)
  - `nslookup -type=NS example.com` (example.com のネームサーバーを検索)
  - `nslookup -type=MX example.com` (example.com のメールエクスチェンジャー(MX)レコードを検索)
- **`dig`**:
  - `dig example.com` (example.com の A レコードを検索)
  - `dig NS example.com` (example.com のネームサーバーを検索)
  - `dig MX example.com` (example.com のメールエクスチェンジャー(MX)レコードを検索)
  - `dig AXFR example.com @ns1.example.com` (DNS Zone Transfer を試行)

**5. 実践的なテクニック**

- **サブドメインの発見**: DNS Zone Transfer を試行し、サブドメイン情報を取得。
- **ネームサーバーの特定**: ネームサーバー情報を収集し、ネットワーク管理者を特定。
- **SPF レコードの分析**: SPF レコードを分析し、メール送信元を偽装する攻撃を検知。

**6. 応用例とユースケース**

- **ペネトレーションテスト**: サブドメインを特定し、攻撃対象を拡大。
- **ネットワーク監査**: DNS 設定の誤りを検出し、セキュリティリスクを軽減。
- **スパム対策**: SPF レコードを分析し、スパムメールの送信元を特定。

**7. トラブルシューティング**

- **DNS サーバーへのアクセス拒否**: DNS サーバーが Zone Transfer を許可していない場合がある。
- **DNS レコードが存在しない**: 必要な DNS レコードが存在しない場合がある。
- **キャッシュされた情報**: DNS レコードはキャッシュされるため、最新の情報ではない場合がある。

**8. まとめと次のステップ**

DNS 情報は、ネットワーク構造を理解し、攻撃対象を特定するための重要な情報を提供します。 DNSlookup ツールを使いこなし、サブドメインの発見やネットワーク管理者の特定に役立てましょう。次のステップとして、Whois 情報やサブドメイン列挙ツールと組み合わせ、より詳細な情報収集を目指しましょう。

#### Whois 情報：ドメイン所有者情報の確認

**1. 概要と重要性**

Whois 情報は、ドメイン名の登録者情報（氏名、住所、電話番号、メールアドレスなど）を提供するデータベースです。Whois 情報を確認することで、ドメインの所有者を特定し、攻撃対象に関するより多くの情報を収集できます。

**2. 特徴と利点**

- **ドメイン所有者の特定**: ドメイン名の登録者情報を確認し、所有者を特定。
- **連絡先の入手**: 登録者の連絡先を入手し、ソーシャルエンジニアリング攻撃の足がかりを築く。
- **関連ドメインの発見**: 登録者の情報を基に、関連ドメインを発見。

**3. 事前準備と前提条件**

- ターミナルまたはコマンドプロンプト
- `whois`コマンド、または Web ベースの Whois 検索サービス

**4. 基本的な使い方**

- **`whois`コマンド**:
  - `whois example.com` (example.com の Whois 情報を検索)
- **Web ベースの Whois 検索サービス**:
  - [https://www.whois.com/whois/example.com](https://www.whois.com/whois/example.com) (example.com の Whois 情報を検索)

**5. 実践的なテクニック**

- **登録者の連絡先を収集**: 登録者の氏名、住所、電話番号、メールアドレスを収集し、ソーシャルエンジニアリング攻撃の足がかりを築く。
- **関連ドメインの発見**: 登録者の情報を基に、関連ドメインを発見し、攻撃対象を拡大。
- **Whois プライバシー保護の有無を確認**: Whois プライバシー保護サービスを利用している場合、個人情報は隠蔽される。

**6. 応用例とユースケース**

- **ペネトレーションテスト**: 登録者の情報を収集し、ソーシャルエンジニアリング攻撃を模擬。
- **ドメイン紛争の解決**: ドメインの所有者を特定し、紛争を解決。
- **フィッシングサイトの特定**: 悪意のあるドメインの登録者を特定し、フィッシングサイトを閉鎖。

**7. トラブルシューティング**

- **Whois プライバシー保護**: Whois プライバシー保護サービスにより、個人情報が隠蔽されている場合がある。
- **GDPR**: GDPR により、ヨーロッパの居住者の個人情報が制限されている場合がある。
- **情報が古い**: Whois 情報は古い場合があるため、最新の情報を確認する。

**8. まとめと次のステップ**

Whois 情報は、ドメインの所有者を特定し、攻撃対象に関するより多くの情報を収集するための貴重な情報源です。Whois コマンドや Web ベースの Whois 検索サービスを使いこなし、ソーシャルエンジニアリング攻撃の対策や、ドメイン紛争の解決に役立てましょう。次のステップとして、サブドメイン列挙ツールと組み合わせ、より詳細な情報収集を目指しましょう。

#### サブドメインの列挙：DNS Zone Transfer, Sublist3r, Amass

**1. 概要と重要性**

サブドメインの列挙とは、特定のドメインに関連するサブドメインを網羅的に発見するプロセスです。サブドメインは、メインドメインとは異なる Web サイトやサービスをホストしていることがあり、これらを特定することで、攻撃対象の範囲を拡大したり、脆弱性のある古いサービスを発見したりすることができます。

**2. 特徴と利点**

- **攻撃対象の拡大**: サブドメインを発見し、攻撃対象の範囲を拡大。
- **脆弱性のあるサービスの発見**: 古いサービスや設定ミスの発見につながる。
- **隠れた Web サイトの発見**: メインドメインからはリンクされていない Web サイトを発見。

**3. 事前準備と前提条件**

- ターミナルまたはコマンドプロンプト
- `Sublist3r`、`Amass`などのサブドメイン列挙ツール

**4. 基本的な使い方**

- **DNS Zone Transfer**: (前述の DNS 情報セクションを参照)
- **`Sublist3r`**:
  - `sublist3r -d example.com` (example.com のサブドメインを列挙)
- **`Amass`**:
  - `amass enum -d example.com` (example.com のサブドメインを列挙)

**5. 実践的なテクニック**

- **複数のツールを組み合わせる**: `Sublist3r`、`Amass`など、複数のツールを組み合わせて、より多くのサブドメインを発見。
- **ブルートフォース攻撃**: よく使われるサブドメイン名（`www`、`mail`、`admin`など）をブルートフォース攻撃で試す。
- **Virtual Host の特定**: 同じ IP アドレスで複数のドメインがホストされている場合、Virtual Host を特定。

**6. 応用例とユースケース**

- **ペネトレーションテスト**: サブドメインを特定し、攻撃対象を拡大。
- **アタックサーフェスの削減**: 不要なサブドメインを特定し、セキュリティリスクを軽減。
- **シャドー IT の発見**: 承認されていないサブドメインを発見し、シャドー IT のリスクを軽減。
