## 第 5 章：動的解析（DAST）：Web アプリケーションを実際に動かして脆弱性を探す

Web アプリケーションのセキュリティを確保するためには、静的解析（SAST）と動的解析（DAST）の両方が重要です。前章ではソースコードを静的に分析する SAST について学びましたが、本章では、実際にアプリケーションを動作させて脆弱性を検出する DAST について掘り下げていきます。

### 動的解析の基礎

**概要と重要性**

動的解析（Dynamic Application Security Testing, DAST）は、Web アプリケーションを実際に動作させて、外部からアクセス可能なインターフェースを通じて脆弱性を検出する手法です。 ブラックボックステストとも呼ばれ、ソースコードにアクセスすることなく、攻撃者の視点からセキュリティの弱点を洗い出すことができます。

**特徴と利点**

DAST の主な特徴は、実行環境での検証を行う点です。そのため、設定ミスや実行時のエラーによって発生する脆弱性も検出できます。 また、SAST では検出が難しい、認証・認可の不備やセッション管理の欠陥なども検出可能です。

- **実行環境での検証:** 実際に動作するアプリケーションに対してテストを行うため、より現実的な脅威に対する防御能力を評価できます。
- **網羅的な脆弱性検出:** コードの複雑さに関わらず、外部からアクセス可能な脆弱性を広範囲に検出できます。
- **ブラックボックステスト:** ソースコードが利用できない場合でも実施可能。

**Web アプリケーションの動作検証**

Web アプリケーションは、HTTP リクエストとレスポンスを通じてクライアントとサーバーが通信し、様々な機能を実行します。 DAST は、この通信を傍受し、意図的に不正なリクエストを送信したり、予期しないレスポンスを分析したりすることで、脆弱性を検出します。

**ファジング：不正な入力値を送り込む**

ファジングは、Web アプリケーションに大量のランダムな、あるいは意図的に不正な入力値を送り込み、予期せぬエラーやクラッシュを引き起こすかどうかをテストする手法です。 例えば、非常に長い文字列や特殊文字、数値のオーバーフローなどを入力し、アプリケーションの挙動を観察します。

**動的解析ツールの仕組みと種類**

DAST ツールは、Web アプリケーションに対するリクエストを自動的に生成し、そのレスポンスを分析することで脆弱性を検出します。 多くのツールは、以下の機能を備えています。

- **クローリング:** Web アプリケーションのリンクをたどり、テスト対象の URL を自動的に検出します。
- **スキャン:** 特定の脆弱性に対するテストケースを自動的に実行します。
- **レポート:** 検出された脆弱性の詳細な情報を提供します。

DAST ツールには、商用ツールとオープンソースツールがあり、それぞれ特徴があります。

- **商用ツール:** Burp Suite Professional, Acunetix, Netsparker など。高度な機能とサポートを提供します。
- **オープンソースツール:** OWASP ZAP など。無料で利用でき、カスタマイズも可能です。

**動的解析のメリットとデメリット**

**メリット:**

- 実行時の脆弱性を検出できる。
- 設定ミスや環境依存の問題を発見できる。
- ソースコードがなくても実施できる。

**デメリット:**

- テストに時間がかかる場合がある。
- 結果の解釈に専門知識が必要となる場合がある。
- テスト環境の構築が必要となる場合がある。

### 動的解析ツールの導入と設定

**Burp Suite Professional, OWASP ZAP, Acunetix, Netsparker などのツール**

DAST ツールは、Web アプリケーションの脆弱性を検出するための強力な武器となります。ここでは代表的なツールを紹介します。

- **Burp Suite Professional:** Web セキュリティエンジニアに最も広く利用されているツールの一つです。プロキシ、スキャナ、リピーターなど、豊富な機能を備えています。
- **OWASP ZAP (Zed Attack Proxy):** オープンソースの DAST ツールで、無料で利用できます。活発なコミュニティがあり、定期的にアップデートされています。
- **Acunetix:** 包括的な Web セキュリティスキャナで、高速かつ正確なスキャンが可能です。
- **Netsparker:** Dead Accurate Scanning™ という独自の技術により、誤検知を最小限に抑えることを特徴としています。

**スキャンの設定：クロール範囲、脆弱性チェック項目、認証情報**

DAST ツールを設定する際には、以下の点を考慮する必要があります。

- **クロール範囲:** テスト対象とする URL の範囲を指定します。Web アプリケーション全体を対象とするか、特定の機能に絞るかを決定します。
- **脆弱性チェック項目:** 検出したい脆弱性の種類を選択します。SQL インジェクション、XSS、CSRF など、優先順位の高い脆弱性からテストすると効果的です。
- **認証情報:** ログインが必要なページをテストする場合は、認証情報を設定します。

**例：Burp Suite Professional での設定**

1.  Burp Suite を起動し、プロキシの設定を行います（通常は 127.0.0.1:8080）。
2.  ブラウザでプロキシ設定を行い、Burp Suite を経由するようにします。
3.  Burp Suite の"Target"タブで、テスト対象の Web アプリケーションの URL を入力します。
4.  "Spider"タブで、Web アプリケーションをクロールし、URL を収集します。
5.  "Scanner"タブで、スキャン設定を行い、スキャンを開始します。

**自動スキャンの実行と結果の分析**

DAST ツールは、設定に基づいて自動的に Web アプリケーションをスキャンし、脆弱性を検出します。 スキャンが完了したら、結果を分析し、検出された脆弱性の詳細を確認します。

脆弱性レポートには、以下の情報が含まれていることが一般的です。

- 脆弱性の種類
- 影響度（高、中、低）
- 脆弱性が存在する URL
- 脆弱性の詳細な説明
- 推奨される修正方法

結果を分析する際には、以下の点に注意する必要があります。

- **誤検知:** DAST ツールは、誤って脆弱性を検出する場合があります。 検出された脆弱性が本当に存在するかどうかを検証する必要があります。
- **優先順位:** 検出された脆弱性の影響度に基づいて、修正の優先順位を決定します。 影響度の高い脆弱性から修正していくことが重要です。

### 動的解析の実践

**SQL インジェクション、XSS、CSRF、コマンドインジェクションなどの脆弱性検出**

DAST ツールは、様々な種類の脆弱性を検出できます。

- **SQL インジェクション:** Web アプリケーションがデータベースへのクエリを適切に処理していない場合に発生します。攻撃者は、悪意のある SQL コードを挿入することで、データベースの内容を改ざんしたり、情報を盗み出したりすることができます。
- **XSS (クロスサイトスクリプティング):** Web アプリケーションがユーザーからの入力を適切にエスケープしていない場合に発生します。攻撃者は、悪意のあるスクリプトを Web ページに埋め込み、他のユーザーのブラウザ上で実行させることができます。
- **CSRF (クロスサイトリクエストフォージェリ):** Web アプリケーションがユーザーの意図しないリクエストを実行してしまう脆弱性です。攻撃者は、ユーザーがログインしている Web サイトに対して、ユーザーに気づかれずにリクエストを送信し、アカウントの情報を変更したり、不正な操作を実行したりすることができます。
- **コマンドインジェクション:** Web アプリケーションがユーザーからの入力を OS コマンドとして実行してしまう脆弱性です。攻撃者は、悪意のあるコマンドを挿入することで、サーバーを制御したり、情報を盗み出したりすることができます。

**認証・認可の不備、セッション管理の欠陥**

認証・認可の不備やセッション管理の欠陥は、Web アプリケーションのセキュリティを大きく損なう可能性があります。

- **認証の不備:** 認証が不十分な場合、攻撃者は、正規のユーザーになりすまして Web アプリケーションにアクセスすることができます。 例えば、パスワードが平文で保存されていたり、ブルートフォースアタックに対して脆弱であったりする場合などがあります。
- **認可の不備:** 認可が不十分な場合、攻撃者は、本来アクセス権限のない機能やデータにアクセスすることができます。 例えば、管理者権限を持たないユーザーが管理者ページにアクセスできてしまう場合などがあります。
- **セッション管理の欠陥:** セッション管理に欠陥がある場合、攻撃者は、他のユーザーのセッションを乗っ取ることができます。 例えば、セッション ID が予測可能であったり、セッションタイムアウトが設定されていなかったりする場合などがあります。

**ファイルアップロードの脆弱性、ディレクトリトラバーサル**

ファイルアップロード機能やディレクトリトラバーサルは、Web アプリケーションのセキュリティにおいて特に注意すべき脆弱性です。

- **ファイルアップロードの脆弱性:** Web アプリケーションがアップロードされたファイルを適切に処理していない場合に発生します。攻撃者は、悪意のあるファイル（例えば、Web シェル）をアップロードし、サーバーを制御したり、情報を盗み出したりすることができます。
- **ディレクトリトラバーサル:** Web アプリケーションがユーザーからのファイルパス入力を適切に処理していない場合に発生します。攻撃者は、ファイルパスを操作することで、本来アクセスできないファイルにアクセスすることができます。

**API エンドポイントの脆弱性**

API エンドポイントは、Web アプリケーションの重要なインターフェースであり、多くの脆弱性が潜んでいる可能性があります。

- **認証・認可の不備:** API エンドポイントに対する認証・認可が不十分な場合、攻撃者は、不正な API リクエストを送信し、情報を盗み出したり、データを改ざんしたりすることができます。
- **入力値の検証不備:** API エンドポイントが受け取る入力値を適切に検証していない場合、攻撃者は、悪意のある入力値を送信し、SQL インジェクションや XSS などの攻撃を仕掛けることができます。
- **レート制限の欠如:** API エンドポイントにレート制限が設定されていない場合、攻撃者は、大量の API リクエストを送信し、サービスを停止させることができます（DoS 攻撃）。

### 実装例：Burp Suite を利用した SQL インジェクションの検出

**事前準備と前提条件**

- Burp Suite Professional がインストールされ、ライセンスが有効化されていること。
- 脆弱性のある Web アプリケーションが用意されていること（例：OWASP Juice Shop）。

**リクエストインターセプトとリクエストの改ざん**

Burp Suite のプロキシ機能を利用して、Web アプリケーションへのリクエストを傍受し、改ざんします。

1.  Burp Suite を起動し、プロキシ設定を行います。
2.  ブラウザでプロキシ設定を行い、Burp Suite を経由するようにします。
3.  Web アプリケーションの脆弱性のあるページにアクセスします（例：検索機能）。
4.  Burp Suite の"Proxy"タブで、リクエストが傍受されていることを確認します。
5.  傍受されたリクエストを右クリックし、"Send to Repeater"を選択します。

**SQL インジェクションペイロードの挿入**

Repeater タブで、リクエストを改ざんし、SQL インジェクションのペイロードを挿入します。

1.  Repeater タブで、パラメータ（例：検索キーワード）に SQL インジェクションのペイロードを挿入します。 例えば、`' OR '1'='1`というペイロードを挿入します。
2.  "Go"ボタンをクリックし、リクエストを送信します。
3.  レスポンスの内容を確認します。 もし SQL インジェクションが成功した場合、通常とは異なる結果が表示されるはずです。

**脆弱性レポートの作成と改善提案**

SQL インジェクションが検出された場合、脆弱性レポートを作成し、改善提案を行います。

1.  Burp Suite の"Scanner"タブで、脆弱性の詳細な情報を確認します。
2.  脆弱性レポートを作成します。レポートには、以下の情報を含める必要があります。
    - 脆弱性の種類（SQL インジェクション）
    - 影響度（高）
    - 脆弱性が存在する URL
    - リクエストとレスポンスの内容
    - 推奨される修正方法（入力値の検証、プリペアドステートメントの使用など）

**改善提案:**

- Web アプリケーションの入力値を適切に検証する。
- プリペアドステートメントを使用する。
- データベースの権限を最小限にする。
- Web アプリケーションファイアウォール（WAF）を導入する。

### トラブルシューティング

**問題:** スキャンが途中で止まってしまう。

**解決策:**

- クロール範囲を絞り、スキャン対象を減らす。
- スキャンのスレッド数を減らす。
- Web アプリケーションのサーバーの負荷状況を確認する。

**問題:** 誤検知が多い。

**解決策:**

- スキャンの設定を調整する。
- 検出された脆弱性を手動で検証する。
- DAST ツールの設定を最適化する（例：除外 URL の設定）。

**問題:** 認証が必要なページをスキャンできない。

**解決策:**

- DAST ツールに認証情報を設定する。
- セッション管理の設定を確認する。
- Cookie を正しく設定する。

### まとめと次のステップ

本章では、動的解析（DAST）の基礎から実践的なテクニックまでを学びました。 DAST は、Web アプリケーションのセキュリティを確保するために不可欠な手法であり、継続的に実施することが重要です。

次のステップとしては、以下のことを検討してください。

- DAST ツールを導入し、定期的に Web アプリケーションをスキャンする。
- 検出された脆弱性を修正し、セキュリティレベルを向上させる。
- ペネトレーションテストを依頼し、より高度なセキュリティ評価を行う。
- 継続的なセキュリティ教育を実施し、開発者や運用担当者のセキュリティ意識を高める。

DAST を効果的に活用することで、Web アプリケーションのセキュリティを大幅に向上させることができます。 ぜひ、本章で学んだ知識を活かして、安全な Web アプリケーションを開発・運用してください。
