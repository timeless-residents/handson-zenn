## 第 4 章：静的解析（SAST）：ソースコードから脆弱性を見つける

### 静的解析の基礎

#### ソースコードレビューの重要性

ソフトウェア開発において、セキュリティは後回しにされがちですが、早期段階でセキュリティを考慮することが重要です。特に、ソースコードレビューは、開発ライフサイクル全体で最もコスト効率の高いセキュリティ対策の一つです。ソースコードレビューは、単にコードの品質を向上させるだけでなく、潜在的な脆弱性やセキュリティリスクを特定し、未然に防ぐための強力な手段となります。

人間によるソースコードレビューは、経験豊富な開発者がコードを精査し、潜在的な問題点を見つけ出すプロセスです。これは、静的解析ツールでは検出しにくい、ビジネスロジックの欠陥や設計上の問題点を特定するのに役立ちます。しかし、人間によるレビューは時間と労力がかかり、大規模なプロジェクトでは現実的ではありません。

#### コーディング規約とセキュリティベストプラクティス

コーディング規約は、一貫性のあるコードを作成するためのルールセットです。規約に従うことで、コードの可読性が向上し、バグの発見が容易になります。セキュリティベストプラクティスは、安全なコードを書くためのガイドラインです。例えば、入力の検証、出力のエスケープ、暗号化の使用などが含まれます。

一般的なコーディング規約には、以下のものが含まれます。

- 命名規則：変数、関数、クラスなどの名前付けに関するルール。
- インデント：コードの構造を明確にするための空白の使用。
- コメント：コードの意図や機能を説明するための注釈。

セキュリティベストプラクティスには、以下のものが含まれます。

- 入力検証：ユーザーからの入力データを検証し、不正なデータを拒否する。
- 出力エスケープ：HTML、SQL、JavaScript などのコンテキストで安全な方法でデータを出力する。
- 認証と認可：ユーザーの身元を確認し、アクセス権を管理する。

#### 静的解析ツールの仕組みと種類

静的解析ツール（SAST: Static Application Security Testing）は、ソースコードを実行せずに分析し、潜在的な脆弱性やセキュリティリスクを検出するツールです。コンパイル前のソースコード、設定ファイル、ライブラリなどを解析対象とします。

静的解析ツールは、以下の仕組みで脆弱性を検出します。

1.  **構文解析:** ソースコードを構文木に変換し、コードの構造を理解します。
2.  **データフロー解析:** 変数の値がどのように伝播するかを追跡し、潜在的なデータの流れを分析します。
3.  **ルールベース解析:** 定義されたルールセットに基づいてコードをチェックし、脆弱性のパターンを検出します。
4.  **意味解析:** コードの意味を理解し、より複雑な脆弱性を検出します。

静的解析ツールは、商用ツールと OSS（オープンソースソフトウェア）ツールの 2 種類に大きく分類できます。

- **商用ツール:** Fortify SCA, Veracode, Checkmarx など。高機能で、詳細なレポートやサポートを提供します。
- **OSS ツール:** ESLint, PMD, FindBugs, SonarQube など。無償で利用でき、カスタマイズが可能です。

#### 静的解析のメリットとデメリット

**メリット:**

- **早期発見:** 開発の初期段階で脆弱性を発見できるため、修正コストを削減できます。
- **網羅性:** ソースコード全体を分析するため、人間が見落としがちな脆弱性も検出できます。
- **自動化:** CI/CD パイプラインに統合することで、自動的に脆弱性検査を実行できます。
- **教育効果:** 開発者は、検出された脆弱性を通じて、安全なコーディングプラクティスを学ぶことができます。

**デメリット:**

- **誤検知:** 実際には問題のないコードを脆弱性として報告する場合があります。
- **過検知:** 不要なアラートが多く、重要な脆弱性を見落とす可能性があります。
- **設定の複雑さ:** 適切なルールを設定し、ツールをチューニングする必要があります。
- **カバレッジの限界:** すべての種類の脆弱性を検出できるわけではありません。特にビジネスロジックの脆弱性は苦手です。

#### CI/CD パイプラインへの統合

**概要と重要性:**

- **自動化:** 手動での検査作業を削減できます。
- **早期フィードバック:** 開発者は、コードをコミットする前に脆弱性を知ることができます。
- **継続的なセキュリティ:** 常に最新のコードを検査できます。
- **品質の向上:** セキュリティだけでなく、コードの品質も向上します。

**事前準備と前提条件:**

**実践的なテクニック:**

- 通知：脆弱性が検出された場合、開発者に通知します。

**応用例とユースケース:**

**まとめと次のステップ:**

CI/CD パイプラインへの統合は、セキュリティを開発プロセスに組み込むための効果的な方法です。次のステップとして、CI/CD 環境に静的解析ツールを統合し、自動化されたセキュリティ検査を実現することをお勧めします。

### 静的解析の実践

#### SQL インジェクション、XSS、CSRF などの脆弱性検出

**概要と重要性:**

静的解析ツールは、SQL インジェクション、XSS、CSRF などの一般的な Web アプリケーションの脆弱性を検出できます。これらの脆弱性は、攻撃者が Web サイトやアプリケーションを乗っ取るために利用する可能性があります。

**特徴と利点:**

- **SQL インジェクション:** ユーザーからの入力データを検証せずに SQL クエリに埋め込むことによって発生します。攻撃者は、SQL クエリを操作して、データベースから機密情報を取得したり、データを変更したりすることができます。
- **XSS (クロスサイトスクリプティング):** ユーザーからの入力データをエスケープせずに Web ページに出力することによって発生します。攻撃者は、悪意のあるスクリプトを Web ページに埋め込み、他のユーザーのブラウザで実行させることができます。
- **CSRF (クロスサイトリクエストフォージェリ):** ユーザーが認証された状態で Web サイトにアクセスしているときに、攻撃者がユーザーになりすましてアクションを実行することによって発生します。

**事前準備と前提条件:**

- 静的解析ツールのインストールと設定
- 解析対象のソースコード

**基本的な使い方:**

静的解析ツールを実行し、レポートを確認します。

**実践的なテクニック:**

- SQL インジェクション：入力検証、プリペアドステートメントの使用
- XSS：出力エスケープ、コンテンツセキュリティポリシー (CSP) の使用
- CSRF：CSRF トークンの使用

**応用例とユースケース:**

- EC サイトのセキュリティ評価
- ブログシステムのセキュリティ評価
- オンラインバンキングシステムのセキュリティ評価

**トラブルシューティング:**

- 誤検知が多い場合、ルールの条件を緩和します。
- 脆弱性が見つからない場合、ルールのカバレッジを確認します。

**まとめと次のステップ:**

静的解析ツールは、一般的な Web アプリケーションの脆弱性を検出するための強力なツールです。次のステップとして、静的解析ツールを使用して、Web アプリケーションのセキュリティを評価し、脆弱性を修正することをお勧めします。

### 実装例：Python Flask アプリケーションの静的解析

#### Bandit を利用したセキュリティ脆弱性検査

**概要と重要性:**

Bandit は、Python 製のオープンソースの静的解析ツールです。Flask アプリケーションのセキュリティ脆弱性を検出するために使用できます。

**特徴と利点:**

- **Python に特化:** Python のコードに特化しており、Python の脆弱性を効率的に検出できます。
- **使いやすい:** コマンドラインから簡単に実行できます。
- **カスタマイズ可能:** ルールをカスタマイズしたり、独自のルールを作成したりできます。

**事前準備と前提条件:**

- Python のインストール
- Bandit のインストール (`pip install bandit`)
- Flask アプリケーションのソースコード

**基本的な使い方:**

1.  **Bandit の実行:** コマンドラインから、解析対象のディレクトリを指定して Bandit を実行します。

    ```bash
    bandit -r my_flask_app
    ```

2.  **レポートの確認:** Bandit は、検出された脆弱性に関するレポートを表示します。レポートには、脆弱性の種類、場所、および修正方法に関する情報が含まれます。

**実践的なテクニック:**

1.  **設定ファイルの作成:** Bandit の設定ファイルを作成して、ルールをカスタマイズします。

    ```yaml
    # bandit.yaml
    skips:
      - B101 # assertステートメントの検出をスキップ
    ```

2.  **CI/CD パイプラインへの統合:** Bandit を CI/CD パイプラインに統合して、自動的に脆弱性検査を実行します。

    ```yaml
    # .gitlab-ci.yml
    stages:
      - test

    bandit:
      image: python:3.9
      stage: test
      before_script:
        - pip install bandit
      script:
        - bandit -r my_flask_app
    ```

**応用例とユースケース:**

- Flask アプリケーションのセキュリティ評価
- Python ライブラリのセキュリティ評価

**トラブルシューティング:**

- Bandit が正しく実行されない場合、Python のバージョンや依存関係を確認します。
- 誤検知が多い場合、設定ファイルでルールを調整します。

**まとめと次のステップ:**

Bandit は、Flask アプリケーションのセキュリティ脆弱性を検出するための優れたツールです。次のステップとして、Bandit を導入し、アプリケーションのセキュリティを評価し、脆弱性を修正することをお勧めします。

#### 脆弱性レポートの作成と改善提案

**概要と重要性:**

Bandit の実行結果から、脆弱性レポートを作成し、改善提案を行うことが重要です。レポートは、開発チームが脆弱性を理解し、修正するための貴重な情報源となります。

**特徴と利点:**

- **脆弱性の明確化:** 脆弱性の種類、場所、および影響範囲を明確に記述します。
- **修正方法の提案:** 脆弱性を修正するための具体的な方法を提案します。
- **優先順位付け:** 脆弱性の重要度に基づいて優先順位を付けます。

**事前準備と前提条件:**

- Bandit のレポート
- プロジェクトのソースコード

**基本的な使い方:**

1.  **レポートの作成:** Bandit のレポートを基に、脆弱性レポートを作成します。レポートには、以下の情報を含めます。

    - 脆弱性の説明
    - 脆弱性の場所 (ファイル名、行番号)
    - 脆弱性の種類 (例：SQL インジェクション、XSS)
    - 脆弱性の重要度 (高、中、低)
    - 修正方法の提案

2.  **改善提案:** 脆弱性レポートに基づいて、開発チームに改善提案を行います。提案には、以下の情報を含めます。
    - 修正が必要なコードの箇所
    - 修正方法の具体的な手順
    - 修正後のコードの例

**実践的なテクニック:**

- 脆弱性管理ツールの使用
- チームでの協力
- 定期的なレビュー

**応用例とユースケース:**

- ソフトウェア開発チームのセキュリティワークフロー
- セキュリティ監査

**トラブルシューティング:**

- レポートの作成に時間がかかる場合、テンプレートを使用します。
- 改善提案が受け入れられない場合、根拠を明確に説明します。

**まとめと次のステップ:**

脆弱性レポートの作成と改善提案は、静的解析の結果を有効活用するための重要なステップです。次のステップとして、脆弱性管理ツールを導入し、チームでの協力体制を構築し、定期的なレビューを行うことをお勧めします。
