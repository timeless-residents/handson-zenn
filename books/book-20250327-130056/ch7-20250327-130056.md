## 第 6 章：手動ペネトレーションテスト：自動化ツールでは見つけられない脆弱性を見つける

### 手動ペネトレーションテストの重要性

**概要と重要性:**

ペネトレーションテスト（侵入テスト、Penetration Testing）は、システムやネットワークのセキュリティ脆弱性を評価するために行われる、認可された攻撃シミュレーションです。自動化ツールは効率的に既知の脆弱性を検出できますが、ビジネスロジックの欠陥や、複雑な連鎖によって発生する脆弱性、最新のゼロデイ脆弱性など、手動による検証でしか発見できないものが存在します。

**自動化ツールの限界と手動テストの必要性:**

自動化ツールは、脆弱性データベースに基づいてスキャンを行うため、未知の脆弱性や複雑なロジックのエラーを見つけることが苦手です。手動ペネトレーションテストでは、経験豊富なセキュリティエンジニアが、攻撃者の視点からシステムを深く理解し、様々なテクニックを駆使して脆弱性を探します。これにより、自動化ツールでは見落とされがちな潜在的なリスクを特定し、より強固なセキュリティ対策を講じることが可能になります。

**ペネトレーションテストの目的とスコープ定義:**

ペネトレーションテストの主な目的は、以下の通りです。

- システムのセキュリティ脆弱性を特定し、悪用されるリスクを評価する。
- セキュリティ対策の有効性を検証し、改善点を明らかにする。
- 組織のセキュリティ意識を高め、セキュリティ対策の強化を促進する。
- 法的および規制上の要件への準拠を支援する。

スコープ定義は、ペネトレーションテストの範囲と目的を明確にするために非常に重要です。スコープを明確に定義することで、テスト対象のシステム、ネットワーク、アプリケーション、およびテストの実施期間、許可される攻撃手法、テスト結果の報告方法などを決定します。スコープ定義は、テストの目的、予算、時間制約、および組織のリスク許容度に基づいて決定されます。

**テスト計画の作成とリスク評価:**

テスト計画は、ペネトレーションテストを効果的に実施するためのロードマップです。テスト計画には、以下の要素が含まれます。

- テストの目的とスコープ
- テスト対象のシステムとネットワーク
- テストの実施期間とスケジュール
- テストチームの役割と責任
- テストで使用するツールと手法
- テスト結果の報告方法
- リスク評価と軽減策

リスク評価は、ペネトレーションテスト中に発生する可能性のあるリスクを特定し、その影響を評価するプロセスです。リスク評価の結果に基づいて、適切な軽減策を講じることで、テストによるシステムへの影響を最小限に抑えることができます。例えば、本番環境に影響を与える可能性のある攻撃手法は、テスト環境でのみ実施する、バックアップを事前に取得する、などの対策を講じます。

### ペネトレーションテストのステップ

**情報収集：OSINT, Reconnaissance**

**概要と重要性:**

情報収集（Reconnaissance）は、ペネトレーションテストの最初のステップであり、攻撃対象に関する情報を可能な限り多く収集するプロセスです。収集した情報は、攻撃の成功率を高め、より効果的な脆弱性を見つけるために役立ちます。

**特徴と利点:**

- 攻撃対象の公開情報を収集することで、攻撃の足がかりを見つける。
- システムの構成やアーキテクチャを理解することで、脆弱性の発見に繋げる。
- 従業員の情報を収集することで、ソーシャルエンジニアリング攻撃の可能性を評価する。

**事前準備と前提条件:**

- OSINT（Open Source Intelligence）ツール：Shodan, Censys, theHarvester など
- ネットワークスキャナ：Nmap, Masscan など
- Web サイトクローラ：Burp Suite, OWASP ZAP など
- インターネット接続環境

**基本的な使い方:**

- OSINT ツールを使用して、攻撃対象のドメイン名、IP アドレス、組織情報などを収集する。
- ネットワークスキャナを使用して、攻撃対象のネットワーク構成、ポート情報、サービスバージョンなどを特定する。
- Web サイトクローラを使用して、攻撃対象の Web サイトの構造、ファイル、ディレクトリなどを分析する。

**実践的なテクニック:**

- Google Hacking（Google Dorking）：特定のキーワードや演算子を使用して、機密情報を検索する。
  - 例：`site:example.com filetype:pdf "password"`
- WHOIS lookup：ドメイン名の登録情報を確認し、所有者や連絡先を特定する。
- Shodan：インターネットに接続されたデバイスの情報を検索し、脆弱性のあるデバイスを特定する。

**応用例とユースケース:**

- 機密情報が公開されていないか確認する。
- 使用されているソフトウェアのバージョンを特定し、既知の脆弱性を調査する。
- 従業員のメールアドレスや SNS アカウントを収集し、ソーシャルエンジニアリング攻撃の可能性を評価する。

**トラブルシューティング:**

- 情報が古くなっている場合は、最新の情報を収集する。
- 情報源の信頼性を確認する。
- 収集した情報を整理し、分析しやすいように構造化する。

**まとめと次のステップ:**

情報収集は、ペネトレーションテストの成功に不可欠なステップです。収集した情報を基に、脆弱性分析を行い、攻撃の可能性を評価します。次のステップでは、脆弱性分析について詳しく解説します。

**脆弱性分析：静的解析、動的解析の結果分析**

**概要と重要性:**

脆弱性分析は、情報収集で得られた情報を基に、システムやアプリケーションに存在する脆弱性を特定するプロセスです。静的解析と動的解析という 2 つの主要な手法を組み合わせることで、より網羅的な脆弱性検出が可能になります。

**特徴と利点:**

- 静的解析：ソースコードを解析し、潜在的な脆弱性を検出する。
- 動的解析：実際にアプリケーションを実行し、脆弱性を悪用するテストを行う。
- 両方の手法を組み合わせることで、より多くの脆弱性を検出できる。

**事前準備と前提条件:**

- 静的解析ツール：SonarQube, Fortify, Checkmarx など
- 動的解析ツール：Burp Suite, OWASP ZAP, Nessus など
- ソースコード（静的解析の場合）
- テスト環境（動的解析の場合）

**基本的な使い方:**

- 静的解析ツールを使用して、ソースコードをスキャンし、脆弱性レポートを作成する。
- 動的解析ツールを使用して、Web アプリケーションに攻撃を仕掛け、脆弱性を検出する。

**実践的なテクニック:**

- OWASP Top 10 などの一般的な脆弱性カテゴリに基づいて、テストケースを作成する。
- ファジング（Fuzzing）：ランダムなデータを入力し、予期せぬエラーやクラッシュを引き起こすかどうかをテストする。
- 脆弱性スキャナの結果を詳細に分析し、誤検出（False Positive）を除外する。

**応用例とユースケース:**

- Web アプリケーションの SQL インジェクション、XSS、CSRF などの脆弱性を特定する。
- ネットワークサービスのバッファオーバーフロー、整数オーバーフローなどの脆弱性を特定する。
- OS コマンドインジェクションの脆弱性を特定する。

**トラブルシューティング:**

- 静的解析ツールの誤検出を減らすために、ルールを調整する。
- 動的解析ツールで検出された脆弱性を再現し、深刻度を評価する。
- 検出された脆弱性に対する適切な対策を検討する。

**まとめと次のステップ:**

脆弱性分析は、システムやアプリケーションのセキュリティを強化するために不可欠なステップです。検出された脆弱性は、次のステップで検証され、悪用可能かどうかを確認します。

**脆弱性検証：PoC (Proof of Concept) の作成**

**概要と重要性:**

脆弱性検証は、脆弱性分析で特定された脆弱性が実際に悪用可能であることを証明するプロセスです。PoC（Proof of Concept）を作成することで、脆弱性の深刻度を明確にし、対策の優先順位を決定するのに役立ちます。

**特徴と利点:**

- 脆弱性が実際に悪用可能であることを証明する。
- 脆弱性の影響範囲と深刻度を評価する。
- 対策の優先順位を決定する。

**事前準備と前提条件:**

- 脆弱性分析の結果
- PoC 作成に必要なツールとスキル（スクリプト言語、ネットワーク知識など）
- テスト環境

**基本的な使い方:**

- 脆弱性分析の結果に基づいて、攻撃シナリオを作成する。
- PoC を作成し、脆弱性を悪用する。
- 攻撃が成功した場合、その結果を記録する。

**実践的なテクニック:**

- Metasploit Framework などの攻撃フレームワークを使用して、PoC を作成する。
- カスタムスクリプトを作成して、特定の脆弱性を悪用する。
- 脆弱性を悪用するデモンストレーションビデオを作成する。

**応用例とユースケース:**

- SQL インジェクションの PoC を作成し、データベースから機密情報を窃取する。
- XSS の PoC を作成し、Cookie を盗み出す。
- OS コマンドインジェクションの PoC を作成し、システムコマンドを実行する。

**トラブルシューティング:**

- PoC が成功しない場合は、脆弱性分析の結果を再度確認する。
- PoC 作成に必要なツールとスキルが不足している場合は、学習する。
- テスト環境が適切に設定されていることを確認する。

**まとめと次のステップ:**

脆弱性検証は、脆弱性の深刻度を理解し、対策の必要性を明確にするために重要なステップです。検証結果は、レポート作成に役立ちます。

**レポート作成：脆弱性の詳細、影響範囲、対策案**

**概要と重要性:**

レポート作成は、ペネトレーションテストの結果をまとめた報告書を作成するプロセスです。レポートは、脆弱性の詳細、影響範囲、対策案を明確に記述し、組織がセキュリティリスクを理解し、適切な対策を講じるのに役立ちます。

**特徴と利点:**

- 脆弱性の詳細、影響範囲、対策案を明確に記述する。
- 組織がセキュリティリスクを理解し、適切な対策を講じるのに役立つ。
- 将来のセキュリティ対策の改善に役立つ。

**事前準備と前提条件:**

- 脆弱性分析の結果
- 脆弱性検証の結果
- レポート作成ツール（Word, Markdown など）
- セキュリティに関する専門知識

**基本的な使い方:**

- レポートのテンプレートを作成する。
- 脆弱性の詳細、影響範囲、対策案を記述する。
- レポートをレビューし、修正する。

**実践的なテクニック:**

- 脆弱性の深刻度に基づいて、優先順位を付ける。
- 具体的な対策案を提示する。
- 図やスクリーンショットを使用して、脆弱性を視覚的に説明する。

**応用例とユースケース:**

- Web アプリケーションの脆弱性レポートを作成し、開発チームに改善を促す。
- ネットワークの脆弱性レポートを作成し、システム管理者に改善を促す。
- セキュリティポリシーの改善に役立つレポートを作成する。

**トラブルシューティング:**

- レポートが分かりにくい場合は、表現を改善する。
- 対策案が現実的でない場合は、見直す。
- レポートに誤りがある場合は、修正する。

**まとめと次のステップ:**

レポート作成は、ペネトレーションテストの最終ステップであり、組織がセキュリティリスクを理解し、適切な対策を講じるために不可欠です。

### 代表的な攻撃手法

**SQL インジェクション**

SQL インジェクションは、Web アプリケーションがデータベースに SQL クエリを送信する際に、悪意のある SQL コードを挿入する攻撃手法です。これにより、攻撃者はデータベースの内容を読み取ったり、変更したり、削除したりすることができます。

- 対策：プリペアドステートメントの使用、入力値の検証とエスケープ処理。

**XSS (クロスサイトスクリプティング)**

XSS は、Web サイトに悪意のあるスクリプトを埋め込み、他のユーザーがそのページを閲覧した際にスクリプトを実行させる攻撃手法です。これにより、攻撃者はユーザーの Cookie を盗み出したり、Web サイトを改ざんしたりすることができます。

- 対策：入力値のエスケープ処理、Content Security Policy (CSP) の設定。

**CSRF (クロスサイトリクエストフォージェリ)**

CSRF は、ユーザーが認証された状態で Web サイトを閲覧している際に、攻撃者が別の Web サイトから不正なリクエストを送信する攻撃手法です。これにより、攻撃者はユーザーのアカウントを操作したり、個人情報を変更したりすることができます。

- 対策：トークンベースの対策、SameSite Cookie 属性の設定。

**コマンドインジェクション**

コマンドインジェクションは、Web アプリケーションが OS コマンドを実行する際に、悪意のあるコマンドを挿入する攻撃手法です。これにより、攻撃者はシステムを制御したり、機密情報を窃取したりすることができます。

- 対策：入力値の検証とエスケープ処理、コマンドの実行権限の制限。

**バッファオーバーフロー**

バッファオーバーフローは、プログラムがバッファにデータを書き込む際に、割り当てられた領域を超えてデータを書き込んでしまう脆弱性です。これにより、攻撃者はプログラムの実行を制御したり、システムをクラッシュさせたりすることができます。

- 対策：バッファサイズの検証、安全な関数（strncpy など）の使用。

**整数オーバーフロー**

整数オーバーフローは、整数型の変数が表現できる最大値を超えて値を格納しようとした際に発生する現象です。これにより、プログラムが予期せぬ動作をしたり、セキュリティ上の脆弱性が発生したりする可能性があります。

- 対策：入力値の検証、オーバーフローのチェック。

**クリックジャッキング**

クリックジャッキングは、Web サイト上に透明な iframe を重ねて表示し、ユーザーが意図しないボタンやリンクをクリックさせる攻撃手法です。これにより、攻撃者はユーザーのアカウントを操作したり、個人情報を窃取したりすることができます。

- 対策：X-Frame-Options ヘッダーの設定、フレームバスティングスクリプトの使用。

**セッションハイジャック**

セッションハイジャックは、攻撃者がユーザーのセッション ID を盗み出し、そのセッションを乗っ取る攻撃手法です。これにより、攻撃者はユーザーのアカウントを操作したり、機密情報を窃取したりすることができます。

- 対策：セッション ID の安全な管理、HTTPS の使用、セッションタイムアウトの設定。

**XXE (XML External Entity)**

XXE は、XML パーサーが外部エンティティを処理する際に発生する脆弱性です。これにより、攻撃者はファイルの内容を読み取ったり、サーバー側のリソースにアクセスしたりすることができます。

- 対策：外部エンティティの処理を無効にする、入力値の検証。

**SSRF (Server-Side Request Forgery)**

SSRF は、Web アプリケーションが外部リソースにリクエストを送信する際に、攻撃者がリクエスト先を制御する攻撃手法です。これにより、攻撃者は内部ネットワークにアクセスしたり、機密情報を窃取したりすることができます。

- 対策：入力値の検証、リクエスト先 URL の制限、ファイアウォールの設定。

### 実装例：クロスサイトスクリプティング（XSS）の検証

**概要と重要性:**

XSS は、Web アプリケーションの脆弱性の中でも特に一般的で、深刻な影響を与える可能性があります。ここでは、XSS の具体的な種類と検証方法について解説します。

**反射型 XSS、格納型 XSS、DOM Based XSS**

- **反射型 XSS (Reflected XSS):** ユーザーが送信したデータがそのまま Web ページに表示される場合に発生します。例えば、検索クエリが検索結果に表示されるような場合です。
- **格納型 XSS (Stored XSS):** ユーザーが送信したデータがデータベースなどに保存され、他のユーザーがそのデータを表示した際にスクリプトが実行される場合に発生します。例えば、掲示板の投稿やブログのコメントなどが該当します。
- **DOM Based XSS:** JavaScript が DOM (Document Object Model) を操作する際に、ユーザーの入力値が適切に処理されずにスクリプトが実行される場合に発生します。このタイプの XSS は、サーバー側のコードには影響を与えません。

**XSS ペイロードの作成と実行**

XSS ペイロードは、XSS 攻撃に使用するスクリプトのことです。以下に、一般的な XSS ペイロードの例を示します。

- `<script>alert('XSS')</script>`
- `<img src=x onerror=alert('XSS')>`
- `<a href="javascript:alert('XSS')">Click Me</a>`

これらのペイロードを Web アプリケーションの入力フィールドに入力し、スクリプトが実行されるかどうかを確認します。

**実践的なテクニック:**

- **反射型 XSS:**
  - 検索フォームに`<script>alert('XSS')</script>`を入力し、アラートが表示されるか確認する。
- **格納型 XSS:**
  - 掲示板の投稿に`<script>alert('XSS')</script>`を入力し、投稿が表示された際にアラートが表示されるか確認する。
- **DOM Based XSS:**
  - URL に特定のパラメータを設定し、JavaScript がそのパラメータを処理する際にスクリプトが実行されるか確認する。

**Content Security Policy (CSP) の回避**

Content Security Policy (CSP) は、Web ページが読み込むことができるリソースの制限を定義するセキュリティ機構です。CSP を回避するためには、以下のテクニックを使用できます。

- **nonce の悪用:** CSP で nonce が使用されている場合、正当な nonce を持つスクリプトタグを使用する。
- **unsafe-inline の悪用:** CSP で unsafe-inline が許可されている場合、インラインスクリプトを使用する。
- **unsafe-eval の悪用:** CSP で unsafe-eval が許可されている場合、eval 関数を使用する。

**実装例:**

1.  **反射型 XSS の検証:**

    ```html
    <!DOCTYPE html>
    <html>
      <head>
        <title>Reflected XSS Example</title>
      </head>
      <body>
        <h1>Search Results</h1>
        <p>
          You searched for:
          <?php echo $_GET['query']; ?>
        </p>
      </body>
    </html>
    ```

    上記のコードでは、GET パラメータ `query` の内容がそのまま Web ページに表示されます。攻撃者は、URL に以下のようなペイロードを追加することで XSS 攻撃を実行できます。

    ```
    http://example.com/search.php?query=<script>alert('XSS')</script>
    ```

2.  **格納型 XSS の検証:**

    ```html
    <!DOCTYPE html>
    <html>
    <head>
        <title>Stored XSS Example</title>
    </head>
    <body>
        <h1>Comments</h1>
        <?php
        // データベースからコメントを取得して表示
        foreach ($comments as $comment) {
            echo "<p>" . $comment['text'] . "</p>";
        }
        ?>
    </body>
    </html>
    ```

    上記のコードでは、データベースに保存されたコメントが Web ページに表示されます。攻撃者は、コメントに`<script>alert('XSS')</script>`を入力し、他のユーザーがそのコメントを表示した際に XSS 攻撃を実行できます。

### チートシート：ペネトレーションテストでよく使うコマンドとツール

| ツール/コマンド | 説明                                                         | 使用例                                                                                                  | 注意点                                                       |
| :-------------- | :----------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ | :----------------------------------------------------------- |
| Nmap            | ポートスキャン、サービスバージョンの特定                     | `nmap -sV -p 1-1000 example.com`                                                                        | 許可なくネットワークをスキャンすると法に触れる可能性がある。 |
| Burp Suite      | Web アプリケーションの脆弱性診断、リクエストの傍受と改ざん   | リクエストを傍受し、パラメータを改ざんして SQL インジェクションを試す。                                 | 有償版の機能が豊富。                                         |
| OWASP ZAP       | Web アプリケーションの脆弱性診断、Burp Suite の代替          | Web サイトをクロールし、脆弱性を自動検出する。                                                          | Burp Suite に比べて機能が少ない部分がある。                  |
| Metasploit      | 脆弱性を利用した攻撃、エクスプロイトの実行                   | 脆弱性のあるシステムに対してエクスプロイトを実行し、シェルを取得する。                                  | 悪用厳禁。                                                   |
| sqlmap          | SQL インジェクションの自動診断と悪用                         | `sqlmap -u "http://example.com/article.php?id=1"`                                                       | 脆弱性のある Web サイトでのみ使用。                          |
| XSSer           | XSS の自動診断と悪用                                         | `xsser -u "http://example.com/search.php?q=test"`                                                       | 脆弱性のある Web サイトでのみ使用。                          |
| Nikto           | Web サーバーの脆弱性診断、古いバージョンのソフトウェアの検出 | `nikto -h example.com`                                                                                  | 結果を鵜呑みにせず、手動で検証する。                         |
| curl            | HTTP リクエストの送信、Web ページの取得                      | `curl -I example.com` (ヘッダー情報を表示), `curl -X POST -d "param1=value1&param2=value2" example.com` | データの送信に使用頻度が高い                                 |
| wget            | ファイルのダウンロード、Web サイトのミラーリング             | `wget example.com/robots.txt`                                                                           | ネットワーク負荷に注意。                                     |
| netcat (nc)     | TCP/UDP 接続の確立、ポートリスニング                         | `nc -lvp 4444` (ポート 4444 でリッスン), `nc example.com 80` (80 番ポートに接続)                        | セキュリティ対策が施されている場合、接続できないことがある。 |
| Wireshark       | ネットワークパケットのキャプチャと分析                       | パケットをキャプチャし、HTTP リクエストやレスポンスの内容を確認する。                                   | 機密情報を含むパケットをキャプチャしないように注意。         |
| theHarvester    | ドメイン名、メールアドレス、サブドメインなどの情報を収集     | `theharvester -d example.com -l 50 -b google`                                                           | OSINT ツール。                                               |

この章では、手動ペネトレーションテストの重要性から、具体的な攻撃手法の実装例、そして便利なチートシートまでを解説しました。自動化ツールだけでは見つけられない脆弱性を見つけ出すために、ぜひ手動ペネトレーションテストを実践してみてください。
