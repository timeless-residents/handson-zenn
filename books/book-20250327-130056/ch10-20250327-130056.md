## 第 9 章：入力値検証のテスト：SQL インジェクション、XSS から身を守る

### 入力値検証の重要性

#### 概要と重要性

Web アプリケーションを安全に保つ上で、入力値検証は最も重要な対策の一つです。ユーザーからの入力、API からのデータ、データベースからの読み出しなど、アプリケーションが扱うすべてのデータは攻撃者にとって侵入経路となる可能性があります。入力値検証を怠ると、SQL インジェクション、XSS（クロスサイトスクリプティング）、コマンドインジェクションといった深刻な脆弱性を抱えることになり、個人情報の漏洩、データの改ざん、最悪の場合はサーバーの乗っ取りにつながる危険性があります。

#### 攻撃者の侵入経路：入力値の悪用

攻撃者は、アプリケーションが想定していない形式や内容のデータを送り込むことで、システムの脆弱性を悪用しようとします。例えば、ユーザー名入力欄に SQL 文を紛れ込ませたり、コメント欄に悪意のある JavaScript コードを埋め込んだりといった手法が考えられます。これらの攻撃は、入力値検証が不十分な場合に成功する可能性が高まります。

#### ブラックリスト方式とホワイトリスト方式

入力値検証には、主にブラックリスト方式とホワイトリスト方式の 2 種類があります。

- **ブラックリスト方式:** 特定の危険なパターンや文字列を禁止する方法です。例えば、SQL インジェクション対策として、`'`,`"`、`;`などの文字を禁止するなどが該当します。しかし、この方式は、攻撃者が巧妙にパターンを回避する可能性があるため、完全な防御は期待できません。
- **ホワイトリスト方式:** 許可する文字やパターンのみを定義し、それ以外の入力を拒否する方法です。例えば、ユーザー名に英数字のみを許可するなどが該当します。この方式は、ブラックリスト方式よりも安全性が高いと言えますが、許可するパターンを厳密に定義する必要があります。

#### エスケープ処理、サニタイズ処理

入力値検証には、エスケープ処理とサニタイズ処理という概念も重要です。

- **エスケープ処理:** 特殊文字を安全な形式に変換することで、意図しない動作を防ぎます。例えば、SQL インジェクション対策として、`'` を `'` に変換したり、XSS 対策として、`<` を `&lt;` に変換したりする処理が該当します。
- **サニタイズ処理:** 入力データから不要な部分を削除したり、許可された形式に変換したりする処理です。例えば、HTML タグを取り除いたり、特定の文字コードに変換したりする処理が該当します。

### 代表的な入力値検証の脆弱性

#### SQL インジェクション、XSS、コマンドインジェクション

入力値検証の不備によって発生する代表的な脆弱性として、SQL インジェクション、XSS（クロスサイトスクリプティング）、コマンドインジェクションが挙げられます。

- **SQL インジェクション:** ユーザーからの入力値を利用して SQL 文を生成する際に、悪意のある SQL 文が紛れ込むことで、データベースを不正に操作される脆弱性です。
- **XSS（クロスサイトスクリプティング）:** Web サイトに悪意のあるスクリプトを埋め込み、他のユーザーがその Web サイトを閲覧した際にスクリプトが実行されてしまう脆弱性です。
- **コマンドインジェクション:** ユーザーからの入力値を利用して OS コマンドを実行する際に、悪意のあるコマンドが紛れ込むことで、サーバーを不正に操作される脆弱性です。

#### CRLF インジェクション、LDAP インジェクション

上記以外にも、以下のような脆弱性が存在します。

- **CRLF インジェクション:** HTTP ヘッダに改行コード（CRLF）を挿入することで、HTTP レスポンスを改ざんしたり、不正な HTTP リクエストを送信させたりする脆弱性です。
- **LDAP インジェクション:** LDAP（Lightweight Directory Access Protocol）へのクエリに悪意のある文字列を挿入することで、認証を回避したり、情報を不正に取得したりする脆弱性です。

#### ファイルアップロードの脆弱性

ファイルアップロード機能も、入力値検証の不備によって脆弱性を抱える可能性があります。例えば、ファイル名に悪意のあるスクリプトを埋め込んだり、実行可能なファイルをアップロードさせたりすることで、サーバーを不正に操作される危険性があります。

### 実装例：SQL インジェクション対策

#### プリペアドステートメント、エスケープ処理

SQL インジェクション対策として最も効果的な方法は、プリペアドステートメントを利用することです。プリペアドステートメントは、SQL 文とパラメータを分離してデータベースに送信するため、悪意のある SQL 文が紛れ込む余地がありません。

以下は、PHP におけるプリペアドステートメントの例です。

```php
<?php
$servername = "localhost";
$username = "username";
$password = "password";
$dbname = "myDB";

try {
  $conn = new PDO("mysql:host=$servername;dbname=$dbname", $username, $password);
  // PDO エラーモードを例外に設定
  $conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

  // プリペアドステートメントの準備
  $stmt = $conn->prepare("SELECT id, firstname, lastname FROM MyGuests WHERE lastname=:lastname");
  $stmt->bindParam(':lastname', $lastname);

  // パラメータを設定して実行
  $lastname = $_POST['lastname']; // ユーザーからの入力
  $stmt->execute();

  // 結果を取得
  $result = $stmt->fetchAll(PDO::FETCH_ASSOC);

  foreach($result as $row) {
    echo "id: " . $row["id"]. " - Name: " . $row["firstname"]. " " . $row["lastname"]. "<br>";
  }

} catch(PDOException $e) {
  echo "Connection failed: " . $e->getMessage();
}
$conn = null;
?>
```

プリペアドステートメントが利用できない場合は、エスケープ処理を行う必要があります。データベースの種類に応じて、適切なエスケープ関数を使用してください。

以下は、MySQL におけるエスケープ処理の例です。

```php
<?php
$servername = "localhost";
$username = "username";
$password = "password";
$dbname = "myDB";

// 接続を確立
$conn = mysqli_connect($servername, $username, $password, $dbname);

// 接続を確認
if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}

// ユーザーからの入力
$lastname = $_POST['lastname'];

// エスケープ処理
$lastname = mysqli_real_escape_string($conn, $lastname);

// SQL文の作成
$sql = "SELECT id, firstname, lastname FROM MyGuests WHERE lastname = '" . $lastname . "'";

// クエリを実行
$result = mysqli_query($conn, $sql);

if (mysqli_num_rows($result) > 0) {
    // 結果を出力
    while($row = mysqli_fetch_assoc($result)) {
        echo "id: " . $row["id"]. " - Name: " . $row["firstname"]. " " . $row["lastname"]. "<br>";
    }
} else {
    echo "0 results";
}

// 接続を閉じる
mysqli_close($conn);
?>
```

#### ORM フレームワークの利用

ORM（Object-Relational Mapping）フレームワークを利用することで、SQL インジェクションのリスクを軽減することができます。ORM フレームワークは、データベースの操作をオブジェクト指向で行うことができ、内部でプリペアドステートメントやエスケープ処理を自動的に行うため、開発者が SQL インジェクションについて意識する必要が少なくなります。

例えば、Laravel という PHP フレームワークでは、Eloquent ORM を利用してデータベースを操作することができます。

```php
<?php

namespace App\Http\Controllers;

use App\Models\Guest;
use Illuminate\Http\Request;

class GuestController extends Controller
{
    public function show(Request $request)
    {
        // ユーザーからの入力
        $lastname = $request->input('lastname');

        // Eloquent ORMを使ってデータベースを検索
        $guests = Guest::where('lastname', $lastname)->get();

        // 結果をビューに渡す
        return view('guests.show', ['guests' => $guests]);
    }
}
```

#### SQL インジェクションのペネトレーションテスト

SQL インジェクション対策が正しく行われているかを確認するために、ペネトレーションテストを実施することが重要です。ペネトレーションテストとは、実際に攻撃者の視点に立って、システムの脆弱性を検証するテストのことです。

SQL インジェクションのペネトレーションテストでは、以下のような攻撃パターンを試してみます。

- `' OR '1'='1`
- `" OR "1"="1`
- `'; DROP TABLE users; --`

これらの攻撃パターンが成功した場合、SQL インジェクションの脆弱性が存在することになります。

**実務での具体的なユースケース:**

EC サイトの検索機能において、商品名を入力するフォームがあるとします。このフォームに入力された値が SQL 文に直接組み込まれると、攻撃者は悪意のある SQL 文を注入し、データベースから顧客情報を盗み出す可能性があります。

この脆弱性を防ぐためには、プリペアドステートメントを使用し、入力された商品名をパラメータとして渡すようにします。これにより、SQL 文とデータが分離され、SQL インジェクション攻撃を防ぐことができます。

**トラブルシューティング:**

- **エラーメッセージの表示:** SQL インジェクション攻撃が成功した場合、データベースからエラーメッセージが表示されることがあります。エラーメッセージには、データベースの構造に関する情報が含まれている場合があるため、本番環境ではエラーメッセージを表示しないように設定することが重要です。
- **ログの監視:** SQL インジェクション攻撃の兆候を検知するために、データベースのログを監視することが重要です。特に、エラーログや異常なクエリログに注意を払う必要があります。

**まとめと次のステップ:**

SQL インジェクションは、Web アプリケーションにおける最も深刻な脆弱性の一つです。プリペアドステートメント、エスケープ処理、ORM フレームワークの利用など、適切な対策を講じることで、SQL インジェクションのリスクを大幅に軽減することができます。

次のステップとしては、XSS（クロスサイトスクリプティング）対策について学習することをお勧めします。XSS もまた、Web アプリケーションにおける非常に一般的な脆弱性であり、SQL インジェクションと同様に、適切な対策が必要です。
