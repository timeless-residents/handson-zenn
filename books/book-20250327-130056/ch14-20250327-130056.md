## 第 13 章：モバイルアプリケーションセキュリティテスト：iOS, Android の脆弱性

モバイルアプリケーションは、現代社会において欠かせない存在です。しかし、その利便性の裏には、セキュリティ上のリスクが潜んでいます。本章では、モバイルアプリケーションのセキュリティテストに焦点を当て、iOS と Android における脆弱性と、それらに対する実践的な対策について解説します。

### モバイルアプリケーションセキュリティの基礎

#### モバイル OS のセキュリティアーキテクチャ

**概要と重要性:**

モバイル OS（iOS, Android）は、それぞれ独自のセキュリティアーキテクチャを持っています。これらのアーキテクチャを理解することは、効果的なセキュリティテストを行う上で不可欠です。iOS は、より閉鎖的な環境を提供し、アプリの実行環境やアクセス権限を厳格に管理します。一方、Android は、比較的オープンな環境であり、カスタマイズ性が高い反面、セキュリティリスクも高まります。

**特徴と利点:**

- **iOS:**

  - **サンドボックス:** 各アプリケーションは隔離された環境で実行され、他のアプリケーションやシステムリソースへのアクセスが制限されます。
  - **コード署名:** Apple による厳格なコード署名プロセスにより、悪意のあるアプリのインストールを防止します。
  - **App Transport Security (ATS):** HTTPS 通信を強制し、中間者攻撃を防ぎます。

- **Android:**
  - **パーミッションモデル:** アプリケーションは、ユーザーの許可を得てから特定の機能（カメラ、マイク、位置情報など）にアクセスする必要があります。
  - **Linux カーネルベース:** Linux のセキュリティ機能を利用し、プロセス間の隔離を行います。
  - **SafetyNet Attestation API:** デバイスの整合性を検証し、ルート化されたデバイスでのアプリの実行を制限します。

**事前準備と前提条件:**

- iOS/Android の最新のセキュリティガイドラインを理解しておきましょう。
- 各 OS のセキュリティアーキテクチャに関する公式ドキュメントを参照しましょう。

**基本的な使い方:**

- iOS の場合は、Xcode の Instruments ツールを利用して、アプリの挙動を監視し、セキュリティ上の問題を特定します。
- Android の場合は、Android Studio の Profiler ツールや、ADB コマンドを利用して、アプリのメモリ使用量、ネットワーク通信などを分析します。

**実践的なテクニック:**

- iOS の ATS 設定を確認し、HTTPS 通信が適切に強制されているかを確認します。
- Android のパーミッション設定を確認し、アプリが必要以上の権限を要求していないかを確認します。

**応用例とユースケース:**

- 金融系アプリでは、iOS のキーチェーンサービスを利用して、機密情報を安全に保管します。
- Android アプリでは、SafetyNet Attestation API を利用して、ルート化されたデバイスからのアクセスをブロックします。

**トラブルシューティング:**

- iOS アプリで ATS エラーが発生した場合、Info.plist ファイルで ATS 例外ドメインを設定する必要がある場合があります。
- Android アプリでパーミッションエラーが発生した場合、AndroidManifest.xml ファイルで必要なパーミッションが適切に宣言されているかを確認します。

**まとめと次のステップ:**

モバイル OS のセキュリティアーキテクチャを理解することは、安全なモバイルアプリケーションを開発するための第一歩です。次のステップでは、モバイルアプリケーション特有のセキュリティリスクについて詳しく見ていきましょう。

#### モバイルアプリケーションの特性とセキュリティリスク

**概要と重要性:**

モバイルアプリケーションは、デスクトップアプリケーションとは異なる特性を持っています。そのため、モバイルアプリケーション特有のセキュリティリスクを理解し、適切な対策を講じる必要があります。例えば、モバイルデバイスは紛失や盗難のリスクが高く、ローカルストレージに保存されたデータが漏洩する可能性があります。

**特徴と利点:**

- **持ち運びの容易さ:** 紛失や盗難のリスクが高い。
- **ネットワーク接続の不安定さ:** 公共 Wi-Fi などの安全でないネットワークを使用する可能性がある。
- **多様な入力方法:** タッチスクリーン、カメラ、マイクなど、攻撃対象となるインターフェースが多い。
- **バックグラウンド処理:** アプリケーションがバックグラウンドで動作している間に、セキュリティリスクが発生する可能性がある。

**事前準備と前提条件:**

- OWASP Mobile Security Project などのモバイルセキュリティに関する情報を収集しましょう。
- モバイルアプリケーションのアーキテクチャとデータフローを理解しましょう。

**基本的な使い方:**

- 静的解析ツール（SonarQube など）を使用して、ソースコードの脆弱性を検出します。
- 動的解析ツール（Burp Suite など）を使用して、実行中のアプリケーションの脆弱性を検出します。

**実践的なテクニック:**

- アプリケーションの入力検証を徹底し、SQL インジェクションやクロスサイトスクリプティング（XSS）などの攻撃を防ぎます。
- 機密情報は、ローカルストレージに平文で保存せず、暗号化して保存します。
- ネットワーク通信は、常に HTTPS を使用し、SSL Pinning を実装して、中間者攻撃を防ぎます。

**応用例とユースケース:**

- 銀行系アプリでは、多要素認証を導入し、アカウントの不正アクセスを防ぎます。
- ソーシャルメディアアプリでは、ユーザーのプライバシー設定を強化し、個人情報の漏洩を防ぎます。

**トラブルシューティング:**

- 静的解析ツールで検出された脆弱性は、修正の優先順位を付けて、順次修正します。
- 動的解析ツールで検出された脆弱性は、再現手順を確認し、根本原因を特定して修正します。

**まとめと次のステップ:**

モバイルアプリケーションの特性とセキュリティリスクを理解することは、安全なモバイルアプリケーションを開発するための重要な要素です。次のステップでは、モバイルアプリケーションの認証・認可について詳しく見ていきましょう。

#### モバイルアプリケーションの認証・認可

**概要と重要性:**

認証と認可は、モバイルアプリケーションのセキュリティにおいて非常に重要な役割を果たします。認証は、ユーザーが誰であるかを確認するプロセスであり、認可は、認証されたユーザーが何を行う権限を持っているかを決定するプロセスです。脆弱な認証・認可の実装は、アカウントの乗っ取りや不正アクセスにつながる可能性があります。

**特徴と利点:**

- **安全な認証:** 強力なパスワードポリシー、多要素認証、生体認証などを導入し、アカウントの不正アクセスを防ぎます。
- **適切な認可:** ユーザーのロールに基づいて、アクセス権限を適切に管理し、権限昇格攻撃を防ぎます。
- **セッション管理:** 安全なセッション管理を行い、セッションハイジャック攻撃を防ぎます。

**事前準備と前提条件:**

- OAuth 2.0 や OpenID Connect などの認証プロトコルを理解しましょう。
- JWT (JSON Web Token) の仕組みを理解しましょう。

**基本的な使い方:**

- ユーザー名とパスワードによる認証に加え、多要素認証を導入します。
- OAuth 2.0 を使用して、サードパーティのサービスへのアクセスを許可します。
- JWT を使用して、ユーザーの認証情報を安全に伝達します。

**実践的なテクニック:**

- パスワードは、ソルト付きハッシュで安全に保存します。
- セッション ID は、予測不可能なランダムな値を使用し、定期的にローテーションします。
- API エンドポイントへのアクセスは、認証されたユーザーのみに許可します。

**応用例とユースケース:**

- EC サイトでは、クレジットカード情報を安全に保管し、不正利用を防ぎます。
- ヘルスケアアプリでは、患者の個人情報を保護し、医療情報の漏洩を防ぎます。

**トラブルシューティング:**

- パスワードを忘れた場合のリカバリプロセスを安全に実装します。
- アカウントロックアウトポリシーを導入し、ブルートフォース攻撃を防ぎます。

**まとめと次のステップ:**

安全な認証・認可の実装は、モバイルアプリケーションのセキュリティを確保するための重要な要素です。次のステップでは、モバイルアプリケーションの脆弱性について詳しく見ていきましょう。

### モバイルアプリケーションの脆弱性

#### データ保存の脆弱性 (ローカルストレージ、キーチェーン)

**概要と重要性:**

モバイルアプリケーションは、ローカルストレージ（ファイル、データベースなど）やキーチェーンにデータを保存します。これらの場所に機密情報を平文で保存すると、デバイスが紛失・盗難された場合に情報漏洩のリスクが高まります。また、キーチェーンの不適切な使用は、攻撃者が機密情報にアクセスする可能性を生み出します。

**特徴と利点:**

- **ローカルストレージ:**
  - **ファイル:** 設定ファイル、ログファイル、一時ファイルなど、様々なデータを保存できます。
  - **データベース:** SQLite などのデータベースを使用して、構造化されたデータを保存できます。
- **キーチェーン:**
  - パスワード、証明書、秘密鍵などの機密情報を安全に保管できます。
  - ハードウェアセキュリティモジュール (HSM) を利用して、さらに安全性を高めることができます。

**事前準備と前提条件:**

- iOS のキーチェーンサービス、Android の Keystore System に関する知識が必要です。
- 暗号化アルゴリズム（AES など）に関する知識が必要です。

**基本的な使い方:**

- ローカルストレージに機密情報を保存する場合は、暗号化して保存します。
- キーチェーンを使用して、パスワードや秘密鍵などの機密情報を安全に保管します。

**実践的なテクニック:**

- 暗号化には、強力な暗号化アルゴリズム（AES-256 など）を使用します。
- 暗号化キーは、キーチェーンに安全に保管します。
- キーチェーンに保存する際には、適切なアクセス制御を設定します。

**実装例 (Android):**

```java
// 暗号化
public static String encrypt(String data, SecretKey secretKey) throws Exception {
    Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
    cipher.init(Cipher.ENCRYPT_MODE, secretKey);
    byte[] iv = cipher.getIV();
    byte[] encryptedData = cipher.doFinal(data.getBytes(StandardCharsets.UTF_8));

    // IVと暗号化されたデータを結合して返す
    byte[] combined = new byte[iv.length + encryptedData.length];
    System.arraycopy(iv, 0, combined, 0, iv.length);
    System.arraycopy(encryptedData, 0, combined, iv.length, encryptedData.length);

    return Base64.encodeToString(combined, Base64.DEFAULT);
}

// 復号化
public static String decrypt(String encryptedData, SecretKey secretKey) throws Exception {
    byte[] combined = Base64.decode(encryptedData, Base64.DEFAULT);
    byte[] iv = Arrays.copyOfRange(combined, 0, 16); // IVのサイズは16バイト (AES/CBC/PKCS5Paddingの場合)
    byte[] encryptedBytes = Arrays.copyOfRange(combined, 16, combined.length);

    Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
    cipher.init(Cipher.DECRYPT_MODE, secretKey, new IvParameterSpec(iv));
    byte[] decryptedBytes = cipher.doFinal(encryptedBytes);

    return new String(decryptedBytes, StandardCharsets.UTF_8);
}

// KeyStoreにSecretKeyを保存
public static void storeSecretKey(String alias, SecretKey secretKey, Context context) throws Exception {
    KeyStore keyStore = KeyStore.getInstance("AndroidKeyStore");
    keyStore.load(null);

    KeyStore.SecretKeyEntry secretKeyEntry = new KeyStore.SecretKeyEntry(secretKey);
    KeyProtection keyProtection = new KeyProtection.Builder(KeyProperties.PURPOSE_ENCRYPT | KeyProperties.PURPOSE_DECRYPT)
            .setBlockModes(KeyProperties.BLOCK_MODE_CBC)
            .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_PKCS7)
            .build();

    keyStore.setEntry(alias, secretKeyEntry, keyProtection);
    FileOutputStream fos = new FileOutputStream(new File(context.getFilesDir(), "keystore.jks"));
    keyStore.store(fos, "password".toCharArray()); // 強固なパスワードを設定
    fos.close();
}

// KeyStoreからSecretKeyを取得
public static SecretKey getSecretKey(String alias, Context context) throws Exception {
    KeyStore keyStore = KeyStore.getInstance("AndroidKeyStore");
    FileInputStream fis = new FileInputStream(new File(context.getFilesDir(), "keystore.jks"));
    keyStore.load(fis, "password".toCharArray());
    fis.close();

    KeyStore.SecretKeyEntry secretKeyEntry = (KeyStore.SecretKeyEntry) keyStore.getEntry(alias, null);
    return (SecretKey) secretKeyEntry.getSecretKey();
}

// SecretKeyを生成
public static SecretKey generateSecretKey() throws Exception {
    KeyGenerator keyGenerator = KeyGenerator.getInstance(KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore");
    keyGenerator.init(new KeyGenParameterSpec("alias", KeyProperties.PURPOSE_ENCRYPT | KeyProperties.PURPOSE_DECRYPT));
    return keyGenerator.generateKey();
}
```

**応用例とユースケース:**

- 金融系アプリでは、ユーザーの銀行口座情報を暗号化してローカルストレージに保存します。
- パスワード管理アプリでは、ユーザーのパスワードをキーチェーンに安全に保管します。

**トラブルシューティング:**

- 暗号化キーを紛失した場合、データの復号化は不可能になります。キーのバックアップを必ず作成してください。
- キーチェーンのアクセス制御を誤って設定した場合、他のアプリケーションが機密情報にアクセスできるようになる可能性があります。

**まとめと次のステップ:**

データ保存の脆弱性対策は、モバイルアプリケーションのセキュリティを確保するための重要な要素です。次のステップでは、通信の暗号化不備について詳しく見ていきましょう。

#### 通信の暗号化不備

**概要と重要性:**

モバイルアプリケーションとサーバー間の通信が暗号化されていない場合、中間者攻撃（Man-in-the-Middle attack）により、通信内容が盗聴・改竄される可能性があります。特に、機密情報（ユーザー名、パスワード、クレジットカード情報など）を送信する場合は、必ず暗号化通信を使用する必要があります。

**特徴と利点:**

- **HTTPS:** TLS/SSL プロトコルを使用して、通信を暗号化します。
- **SSL Pinning:** アプリケーションが信頼するサーバーの証明書を事前に組み込み、中間者攻撃を防ぎます。

**事前準備と前提条件:**

- HTTPS プロトコル、TLS/SSL 証明書に関する知識が必要です。
- SSL Pinning の実装方法を理解しましょう。

**基本的な使い方:**

- すべての通信に HTTPS を使用します。
- SSL Pinning を実装して、中間者攻撃を防ぎます。

**実践的なテクニック:**

- サーバーの証明書を定期的に更新します。
- SSL Pinning の設定を誤ると、アプリケーションがサーバーと通信できなくなる可能性があるため、慎重に設定します。

**実装例 (Android):**

```java
// SSL Pinningの実装例 (OkHttpを使用)
OkHttpClient.Builder builder = new OkHttpClient.Builder();
try {
    CertificateFactory cf = CertificateFactory.getInstance("X.509");
    InputStream certInputStream = context.getResources().openRawResource(R.raw.your_certificate); // 証明書をres/rawに配置
    Certificate ca = cf.generateCertificate(certInputStream);
    certInputStream.close();

    String keyStoreType = KeyStore.getDefaultType();
    KeyStore keyStore = KeyStore.getInstance(keyStoreType);
    keyStore.load(null, null);
    keyStore.setCertificateEntry("ca", ca);

    String tmfAlgorithm = TrustManagerFactory.getDefaultAlgorithm();
    TrustManagerFactory tmf = TrustManagerFactory.getInstance(tmfAlgorithm);
    tmf.init(keyStore);

    SSLContext sslContext = SSLContext.getInstance("TLS");
    sslContext.init(null, tmf.getTrustManagers(), null);

    builder.sslSocketFactory(sslContext.getSocketFactory(), (X509TrustManager) tmf.getTrustManagers()[0]);
} catch (Exception e) {
    e.printStackTrace();
}

OkHttpClient client = builder.build();
```

**応用例とユースケース:**

- オンラインバンキングアプリでは、SSL Pinning を実装し、中間者攻撃による不正送金を防ぎます。
- EC サイトでは、クレジットカード情報を安全に送信するために、HTTPS を使用します。

**トラブルシューティング:**

- SSL Pinning の設定を誤ると、証明書の検証に失敗し、アプリケーションがサーバーと通信できなくなることがあります。
- サーバーの証明書が期限切れになると、同様の問題が発生します。

**まとめと次のステップ:**

通信の暗号化不備対策は、モバイルアプリケーションのセキュリティを確保するための重要な要素です。次のステップでは、コード難読化の不備について詳しく見ていきましょう。

#### コード難読化の不備

**概要と重要性:**

モバイルアプリケーションのコードは、リバースエンジニアリングによって解析される可能性があります。コード難読化は、コードを解析しにくくすることで、リバースエンジニアリングを困難にする技術です。しかし、難読化が不十分な場合、コードは比較的容易に解析され、機密情報や脆弱性が露呈する可能性があります。

**特徴と利点:**

- **ProGuard (Android):** コードの最適化、縮小、難読化を行います。
- **DexGuard (Android):** ProGuard よりも強力な難読化機能を提供します。
- **Swift Obfuscator (iOS):** Swift コードの難読化を行います。

**事前準備と前提条件:**

- ProGuard、DexGuard、Swift Obfuscator などの難読化ツールに関する知識が必要です。
- リバースエンジニアリングに関する基本的な知識があると理解が深まります。

**基本的な使い方:**

- ProGuard を有効にし、適切な設定を行います。
- DexGuard を使用する場合は、高度な難読化オプションを設定します。
- Swift Obfuscator を使用して、Swift コードを難読化します。

**実践的なテクニック:**

- ProGuard の設定ファイル（proguard-rules.pro）を適切に設定し、必要なクラスやメソッドを難読化対象から除外します。
- DexGuard を使用する場合は、文字列暗号化、制御フロー難読化などの高度なオプションを有効にします。
- 難読化後もアプリケーションが正常に動作することを確認します。

**設定例 (Android ProGuard):**

```proguard
-keep class com.example.myapp.** { *; } # 特定のパッケージは保持
-keepclassmembers class com.example.myapp.MyClass {
   java.lang.String myMethod(java.lang.String); # 特定のメソッドは保持
}
-dontwarn  # 警告を無視
-optimizationpasses 5 # 最適化の回数
-allowaccessmodification # アクセス修飾子の変更を許可
```

**応用例とユースケース:**

- DRM (Digital Rights Management) を使用するアプリケーションでは、コード難読化を強化し、コンテンツの不正コピーを防ぎます。
- ゲームアプリケーションでは、コード難読化を強化し、チート行為を防ぎます。

**トラブルシューティング:**

- 難読化によって、アプリケーションがクラッシュしたり、正常に動作しなくなることがあります。
- ProGuard の設定を調整し、問題の原因となっているクラスやメソッドを難読化対象から除外します。

**まとめと次のステップ:**

コード難読化の不備対策は、モバイルアプリケーションのセキュリティを確保するための重要な要素です。次のステップでは、ルート化/ジェイルブレイク検知の不備について詳しく見ていきましょう。

#### ルート化/ジェイルブレイク検知の不備

**概要と重要性:**

ルート化（Android）またはジェイルブレイク（iOS）されたデバイスは、セキュリティが大幅に低下しており、悪意のある攻撃を受けやすくなっています。ルート化/ジェイルブレイク検知は、アプリケーションがルート化/ジェイルブレイクされたデバイスで実行されているかどうかを検出し、適切な対策を講じるための技術です。

**特徴と利点:**

- **セキュリティ強化:** ルート化/ジェイルブレイクされたデバイスでのアプリケーションの実行を制限することで、セキュリティリスクを軽減します。
- **不正利用防止:** ルート化/ジェイルブレイクされたデバイスでのチート行為や不正アクセスを防止します。

**事前準備と前提条件:**

- ルート化、ジェイルブレイクの仕組みに関する知識が必要です。
- ルート化/ジェイルブレイク検知の実装方法を理解しましょう。

**基本的な使い方:**

- ルート化/ジェイルブレイクされたデバイスの特定に必要なファイルの存在を確認します。
- スーパーユーザー権限（Android）の取得を試みます。
- Cydia（iOS）などの非公式アプリストアの存在を確認します。

**実践的なテクニック:**

- 複数の検知方法を組み合わせることで、検知精度を高めます。
- 検知ロジックを難読化し、攻撃者による回避を困難にします。
- 検知された場合、アプリケーションの機能を制限したり、警告メッセージを表示したりします。

**実装例 (Android):**

```java
public class RootUtil {

    public static boolean isDeviceRooted() {
        return checkRootMethod1() || checkRootMethod2() || checkRootMethod3();
    }

    private static boolean checkRootMethod1() {
        String buildTags = android.os.Build.TAGS;
        return buildTags != null && buildTags.contains("test-keys");
    }

    private static boolean checkRootMethod2() {
        String[] paths = { "/system/app/Superuser.apk", "/sbin/su", "/system/bin/su", "/system/xbin/su", "/data/local/xbin/su", "/data/local/bin/su", "/system/sd/xbin/su",
                "/system/bin/failsafe/su", "/data/local/su" };
        for (String path : paths) {
            if (new File(path).exists()) return true;
        }
        return false;
    }

    private static boolean checkRootMethod3() {
        Process process = null;
        try {
            process = Runtime.getRuntime().exec(new String[] { "/system/xbin/which", "su" });
            BufferedReader in = new BufferedReader(new InputStreamReader(process.getInputStream()));
            return in.readLine() != null;
        } catch (Throwable t) {
            return false;
        } finally {
            if (process != null) {
                try {
                    process.destroy();
                } catch (Exception e) {
                    // ignore
                }
            }
        }
    }
}
```

**応用例とユースケース:**

- オンラインゲームでは、ルート化/ジェイルブレイクされたデバイスからのアクセスをブロックし、チート行為を防ぎます。
- 金融系アプリでは、ルート化/ジェイルブレイクされたデバイスでのアプリケーションの実行を制限し、不正送金のリスクを軽減します。

**トラブルシューティング:**

- ルート化/ジェイルブレイク検知ロジックが誤って動作し、通常のデバイスでもアプリケーションが起動できなくなることがあります。
- 検知ロジックを調整し、誤検知を減らす必要があります。

**まとめと次のステップ:**

ルート化/ジェイルブレイク検知の不備対策は、モバイルアプリケーションのセキュリティを確保するための重要な要素です。次のセクションでは、実装例として、Android アプリケーションのセキュリティ対策について詳しく見ていきましょう。

### 実装例：Android アプリケーションのセキュリティ対策

#### Rooted/Jailbreak 検知

上記で説明した RootUtil クラスを参考に、以下のように実装します。

```java
// MainActivity.java
if (RootUtil.isDeviceRooted()) {
    // ルート化されたデバイスであることを検知
    Toast.makeText(this, "ルート化されたデバイスです", Toast.LENGTH_LONG).show();
    // アプリケーションの機能を制限するなどの対策を講じる
    finish(); // アプリケーションを終了する
```

#### SSL Pinning

上記で説明した OkHttp を使用した SSL Pinning の実装例を参考に、以下のように実装します。

```java
// MainActivity.java
OkHttpClient client = getUnsafeOkHttpClient(); // SSL Pinningを適用したOkHttpClientを取得

private static OkHttpClient getUnsafeOkHttpClient() {
    try {
        // 信頼された証明書を読み込む（自己署名証明書またはCA証明書）
        CertificateFactory cf = CertificateFactory.getInstance("X.509");
        InputStream caInput = new BufferedInputStream(context.getResources().openRawResource(R.raw.your_certificate)); // 証明書ファイル (your_certificate.crt) を res/raw フォルダに配置
        Certificate ca;
        try {
            ca = cf.generateCertificate(caInput);
            System.out.println("ca=" + ((X509Certificate) ca).getSubjectDN());
        } finally {
            caInput.close();
        }

        // 証明書を格納するKeyStoreを作成
        String keyStoreType = KeyStore.getDefaultType();
        KeyStore keyStore = KeyStore.getInstance(keyStoreType);
        keyStore.load(null, null);
        keyStore.setCertificateEntry("ca", ca);

        // KeyStoreを使用してTrustManagerFactoryを作成
        String tmfAlgorithm = TrustManagerFactory.getDefaultAlgorithm();
        TrustManagerFactory tmf = TrustManagerFactory.getInstance(tmfAlgorithm);
        tmf.init(keyStore);

        // カスタムTrustManagerを使用してSSLContextを作成
        SSLContext sslContext = SSLContext.getInstance("TLS");
        sslContext.init(null, tmf.getTrustManagers(), null);

        OkHttpClient.Builder builder = new OkHttpClient.Builder();
        builder.sslSocketFactory(sslContext.getSocketFactory(), (X509TrustManager) tmf.getTrustManagers()[0]);

        builder.hostnameVerifier((hostname, session) -> {
            // ホスト名を検証 (証明書に含まれるホスト名と一致するか)
            HostnameVerifier hv = HttpsURLConnection.getDefaultHostnameVerifier();
            return hv.verify("yourdomain.com", session); // 証明書のドメイン名を設定
        });

        return builder.build();
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

#### コード難読化 (ProGuard, DexGuard)

1.  **ProGuard の設定:**

    - `build.gradle (Module: app)` ファイルを編集し、`minifyEnabled true` と `proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'` を `buildTypes` の `release` ブロックに追加します。

    ```gradle
    android {
        buildTypes {
            release {
                minifyEnabled true
                proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
            }
        }
    }
    ```

    - `proguard-rules.pro` ファイルを編集し、アプリケーションの動作に必要なクラスやメソッドを保持するように設定します。

    ```proguard
    -keep class com.example.myapp.** { *; }
    -keepclassmembers class com.example.myapp.MyClass {
        java.lang.String myMethod(java.lang.String);
    }
    ```

2.  **DexGuard の使用:**

    - DexGuard は有料のツールですが、ProGuard よりも強力な難読化機能を提供します。
    - DexGuard のドキュメントに従って、プロジェクトに DexGuard を組み込み、高度な難読化オプションを設定します。
