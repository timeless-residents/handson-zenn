## 第12章 dAppバックエンド開発

dApp（分散型アプリケーション）のバックエンド開発は、従来のWebアプリケーション開発とは異なる側面があります。ブロックチェーンの特性を理解し、効率的にデータを扱い、ユーザー体験を向上させる必要があります。この章では、Node.js + ExpressによるAPI構築と、The Graphを利用した効率的なデータアクセスについて解説します。

### 12.1 Node.js + ExpressによるAPI構築

#### 12.1.1 概要と重要性

dAppのバックエンドは、フロントエンド（ユーザーインターフェース）とブロックチェーンの間の橋渡し役として機能します。ユーザーからのリクエストを受け付け、ブロックチェーン上のデータを取得・加工したり、トランザクションを生成・送信したりする役割を担います。Node.jsとExpressは、JavaScriptをサーバーサイドで実行するための強力なツールであり、高速な開発とスケーラビリティを実現します。

#### 12.1.2 特徴と利点

*   **高速な開発:** JavaScriptの知識を活かせるため、学習コストが低く、開発スピードを向上できます。
*   **豊富なライブラリ:** npm (Node Package Manager) を通じて、様々なライブラリを利用できます。
*   **スケーラビリティ:** イベントループによる非同期処理により、高負荷な環境でも効率的に動作します。
*   **クロスプラットフォーム:** Windows, macOS, Linuxなど、様々なOSで動作します。
*   **JSONデータの扱いやすさ:** JavaScriptをベースとしているため、JSON形式のデータをネイティブに扱うことができます。dAppで扱うデータはJSON形式であることが多いため、相性が良いです。

#### 12.1.3 事前準備と前提条件

*   **Node.jsとnpmのインストール:** 公式サイト(https://nodejs.org/ja/)から最新版をダウンロードし、インストールしてください。
*   **MongoDBのインストール:** MongoDBをローカル環境またはクラウド環境にインストールしてください。MongoDB Atlas (https://www.mongodb.com/atlas/database) を利用すると、簡単にクラウド上にMongoDBを構築できます。
*   **テキストエディタ/IDE:** Visual Studio Code, Sublime Text, Atomなど、お好みのテキストエディタまたはIDEを用意してください。

#### 12.1.4 基本的な使い方

まずは、プロジェクトのディレクトリを作成し、初期化します。

```bash
mkdir dApp-backend
cd dApp-backend
npm init -y
```

次に、必要なライブラリをインストールします。

```bash
npm install express mongoose cors dotenv
```

*   `express`: Webアプリケーションフレームワーク
*   `mongoose`: MongoDBのODM (Object-Document Mapper)
*   `cors`: Cross-Origin Resource Sharingを有効にするためのミドルウェア
*   `dotenv`: 環境変数を`.env`ファイルから読み込むためのライブラリ

`index.js`ファイルを作成し、以下のコードを記述します。

```javascript
const express = require('express');
const mongoose = require('mongoose');
const cors = require('cors');
const dotenv = require('dotenv');

dotenv.config();

const app = express();
const port = process.env.PORT || 3000;

// Middleware
app.use(cors());
app.use(express.json());

// MongoDB接続
mongoose.connect(process.env.MONGODB_URI, {
  useNewUrlParser: true,
  useUnifiedTopology: true,
})
.then(() => console.log('MongoDB connected'))
.catch(err => console.error('MongoDB connection error:', err));

// ルート定義 (後で詳細を記述)
app.get('/', (req, res) => {
  res.send('Hello, dApp Backend!');
});

// サーバー起動
app.listen(port, () => {
  console.log(`Server listening on port ${port}`);
});
```

`.env`ファイルを作成し、MongoDBの接続文字列を記述します。

```
PORT=3000
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-address>/<database>?retryWrites=true&w=majority
```

`<username>`, `<password>`, `<cluster-address>`, `<database>` は、ご自身のMongoDBの設定に合わせて変更してください。MongoDB Atlasを利用している場合は、Atlasのダッシュボードから接続文字列を取得できます。

#### 12.1.5 REST APIの設計と実装

dAppのバックエンドでは、主にREST APIを介してフロントエンドと通信します。以下のエンドポイントを例として、APIを設計してみましょう。

*   `GET /items`: アイテムの一覧を取得
*   `GET /items/:id`: 特定のアイテムを取得
*   `POST /items`: 新しいアイテムを作成
*   `PUT /items/:id`: 特定のアイテムを更新
*   `DELETE /items/:id`: 特定のアイテムを削除

MongoDBに接続し、スキーマとモデルを定義します。`models/Item.js`ファイルを作成し、以下のコードを記述します。

```javascript
const mongoose = require('mongoose');

const itemSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true
  },
  description: {
    type: String
  },
  price: {
    type: Number,
    required: true
  },
  imageUrl: {
    type: String
  }
});

module.exports = mongoose.model('Item', itemSchema);
```

次に、APIのエンドポイントを実装します。`index.js`に以下のコードを追加します。

```javascript
const Item = require('./models/Item');

// アイテムの一覧を取得
app.get('/items', async (req, res) => {
  try {
    const items = await Item.find();
    res.json(items);
  } catch (err) {
    res.status(500).json({ message: err.message });
  }
});

// 特定のアイテムを取得
app.get('/items/:id', async (req, res) => {
  try {
    const item = await Item.findById(req.params.id);
    if (!item) {
      return res.status(404).json({ message: 'Item not found' });
    }
    res.json(item);
  } catch (err) {
    res.status(500).json({ message: err.message });
  }
});

// 新しいアイテムを作成
app.post('/items', async (req, res) => {
  const item = new Item({
    name: req.body.name,
    description: req.body.description,
    price: req.body.price,
    imageUrl: req.body.imageUrl
  });

  try {
    const newItem = await item.save();
    res.status(201).json(newItem);
  } catch (err) {
    res.status(400).json({ message: err.message });
  }
});

// 特定のアイテムを更新
app.put('/items/:id', async (req, res) => {
  try {
    const item = await Item.findById(req.params.id);
    if (!item) {
      return res.status(404).json({ message: 'Item not found' });
    }

    item.name = req.body.name || item.name;
    item.description = req.body.description || item.description;
    item.price = req.body.price || item.price;
    item.imageUrl = req.body.imageUrl || item.imageUrl;

    const updatedItem = await item.save();
    res.json(updatedItem);
  } catch (err) {
    res.status(400).json({ message: err.message });
  }
});

// 特定のアイテムを削除
app.delete('/items/:id', async (req, res) => {
  try {
    const item = await Item.findById(req.params.id);
    if (!item) {
      return res.status(404).json({ message: 'Item not found' });
    }

    await item.remove();
    res.json({ message: 'Item deleted' });
  } catch (err) {
    res.status(500).json({ message: err.message });
  }
});
```

#### 12.1.6 データキャッシュ

ブロックチェーン上のデータは、取得に時間がかかる場合があります。頻繁にアクセスされるデータは、キャッシュに保存することで、パフォーマンスを向上させることができます。Redisなどのインメモリデータストアを利用すると、高速なキャッシュを実現できます。

```bash
npm install redis
```

`index.js`に以下のコードを追加します。

```javascript
const redis = require('redis');

const redisClient = redis.createClient({
  host: 'localhost', // Redisサーバーのアドレス
  port: 6379 // Redisのデフォルトポート
});

redisClient.on('connect', () => console.log('Redis connected'));
redisClient.on('error', (err) => console.error('Redis connection error:', err));

// アイテムの一覧を取得 (キャッシュあり)
app.get('/items', async (req, res) => {
  const cacheKey = 'items';

  redisClient.get(cacheKey, async (err, cachedData) => {
    if (err) console.error('Redis get error:', err);

    if (cachedData) {
      console.log('Data from cache');
      return res.json(JSON.parse(cachedData));
    } else {
      try {
        const items = await Item.find();
        redisClient.setex(cacheKey, 3600, JSON.stringify(items)); // 1時間キャッシュ
        console.log('Data from MongoDB');
        res.json(items);
      } catch (err) {
        res.status(500).json({ message: err.message });
      }
    }
  });
});
```

*   **CORSエラー:** `cors`ミドルウェアが正しく設定されているか確認してください。フロントエンドのオリジンが許可されているか確認してください。
*   **Redis接続エラー:** Redisサーバーが起動しているか確認してください。Redisの設定ファイルを確認してください。

### 12.2 The Graph

#### 12.2.1 概要と重要性

The Graphは、ブロックチェーン上のデータをインデックス化し、GraphQLを使って効率的にアクセスするための分散型プロトコルです。スマートコントラクトから発生するイベントやトランザクションを解析し、インデックスを作成することで、dApp開発者は複雑なクエリを高速に実行できます。

#### 12.2.2 特徴と利点

*   **効率的なデータアクセス:** GraphQLを使用することで、必要なデータだけを取得できます。
*   **高速なクエリ:** インデックス化されたデータにアクセスするため、高速なクエリが可能です。
*   **分散型ネットワーク:** 分散型ネットワーク上で動作するため、検閲耐性があります。
*   **オープンソース:** オープンソースプロジェクトであるため、コミュニティによるサポートが充実しています。
*   **豊富なエコシステム:** 様々なブロックチェーンに対応しており、dApp開発を支援するツールやサービスが豊富です。

#### 12.2.3 事前準備と前提条件

*   **Node.jsとnpmのインストール:**  前述のセクションと同様です。
*   **Graph CLIのインストール:** Graph CLI (Command Line Interface) をインストールします。

    ```bash
    npm install -g @graphprotocol/graph-cli
    ```
*   **Graph Nodeへのアクセス:** The GraphのホストされたサービスまたはローカルのGraph Nodeにアクセスできる環境を構築します。 ホストされたサービスは、https://thegraph.com/hosted-service/ で利用できます。 ローカルのGraph Nodeを構築する方法は、The Graphのドキュメントを参照してください。
*   **Ethereum開発の基礎知識:** スマートコントラクトやEthereumのイベントに関する基本的な知識が必要です。

#### 12.2.4 GraphQLによるデータアクセス

The Graphを利用する上で重要なのがGraphQLです。GraphQLは、APIのためのクエリ言語であり、クライアントが必要なデータだけを要求できるため、REST APIよりも効率的なデータアクセスが可能です。

例えば、以下のようなGraphQLクエリを記述することで、特定のアイテムの名前と価格を取得できます。

```graphql
query {
  items(where: { id: "0x..." }) {
    name
    price
  }
}
```

#### 12.2.5 subgraphの作成とデプロイ

The Graphを利用するには、まずsubgraphを作成する必要があります。subgraphは、ブロックチェーン上のデータをどのようにインデックス化するかを定義するものです。

1.  **subgraphの初期化:** Graph CLIを使って、subgraphプロジェクトを初期化します。

    ```bash
    graph init --from-contract <コントラクトアドレス> --network <ネットワーク> --contract-name <コントラクト名> <subgraph名>
    ```

    *   `<コントラクトアドレス>`: スマートコントラクトのアドレス
    *   `<ネットワーク>`: Ethereumネットワーク (mainnet, rinkeby, kovan, ropstenなど)
    *   `<コントラクト名>`: スマートコントラクトの名前
    *   `<subgraph名>`: subgraphの名前

2.  **スキーマの定義:** `schema.graphql`ファイルに、インデックス化するデータのスキーマを定義します。

    ```graphql
    type Item @entity {
      id: ID!
      name: String!
      description: String
      price: BigInt!
      imageUrl: String
    }
    ```

3.  **マニフェストファイルの編集:** `subgraph.yaml`ファイルに、データソースやイベントハンドラーなどを定義します。

    ```yaml
    specVersion: 0.0.5
    schema:
      file: ./schema.graphql
    dataSources:
      - kind: ethereum
        name: ItemContract
        network: rinkeby
        source:
          address: "0x..." # コントラクトアドレス
          abi: ItemContract
          startBlock: 12345678 # subgraphを開始するブロック番号
        mapping:
          kind: ethereum/events
          apiVersion: 0.0.7
          language: wasm/assemblyscript
          entities:
            - Item
          abis:
            - name: ItemContract
              file: ./abis/ItemContract.json # コントラクトのABI
          eventHandlers:
            - event: ItemCreated(uint256,string,string,uint256,string)
              handler: handleItemCreated
          file: ./src/mapping.ts # イベントハンドラーのコード
    ```

4.  **イベントハンドラーの記述:** `src/mapping.ts`ファイルに、スマートコントラクトのイベントが発生した際に実行されるコードを記述します。

    ```typescript
    import { ItemCreated } from "../generated/ItemContract/ItemContract";
    import { Item } from "../generated/schema";

    export function handleItemCreated(event: ItemCreated): void {
      let item = new Item(event.params.itemId.toString());
      item.name = event.params.name;
      item.description = event.params.description;
      item.price = event.params.price;
      item.imageUrl = event.params.imageUrl;
      item.save();
    }
    ```

5.  **subgraphのビルドとデプロイ:** Graph CLIを使って、subgraphをビルドし、デプロイします。

    ```bash
    graph codegen
    graph build
    graph deploy --node https://api.thegraph.com/deploy/ <ユーザー名>/<subgraph名>
    ```

    *   `<ユーザー名>`: The Graphのユーザー名
    *   `<subgraph名>`: subgraphの名前

    デプロイ先は、ホストされたサービスまたはローカルのGraph NodeのAPIエンドポイントを指定します。

#### 12.2.6 実践的なテクニック

*   **複数のデータソース:** 複数のスマートコントラクトからデータを取得できます。
*   **ブロック範囲指定:** 特定のブロック範囲のデータをインデックス化できます。
*   **カスタムロジック:** マッピング関数内でカスタムロジックを実装できます。

#### 12.2.7 応用例とユースケース

*   **NFTマーケットプレイス:** NFTの所有者や取引履歴を効率的に取得できます。
*   **DeFiアプリケーション:** トークンの残高や取引履歴、流動性プールなどの情報を取得できます。
*   **DAOガバナンス:** 提案や投票の情報を取得できます。

#### 12.2.8 トラブルシューティング
