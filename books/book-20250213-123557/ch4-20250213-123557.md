## 第4章 スマートコントラクトの実装：簡単なトークンコントラクト

この章では、ブロックチェーン技術の根幹をなすスマートコントラクトの中でも、最も基本的なトークンコントラクトの実装を通して、Solidityプログラミングの基礎とスマートコントラクト開発のワークフローを習得します。ERC-20トークンは、様々な分散型アプリケーション(DApps)やDeFi(分散型金融)プロジェクトの基盤として広く利用されており、その仕組みを理解することは、ブロックチェーン開発者として不可欠なスキルとなります。

### 4.1 ERC-20トークンの基礎

#### 概要と重要性

ERC-20は、Ethereumブロックチェーン上で代替可能なトークンを実装するための標準インターフェースです。代替可能とは、それぞれのトークンが等価であり、相互に交換可能であることを意味します。ERC-20トークンは、DApps内での支払い、ガバナンス、ポイントシステムなど、様々な用途に利用されています。ERC-20標準に準拠することで、異なるDApps間でのトークンの互換性が確保され、エコシステム全体の発展に貢献します。

#### 特徴と利点

ERC-20トークンの主な特徴と利点は以下の通りです。

*   **標準化されたインターフェース:** 全てのERC-20トークンは、同じ関数群を実装するため、異なるDApps間でシームレスな連携が可能です。
*   **高い互換性:** ERC-20標準に準拠することで、様々なウォレットや取引所でのサポートが期待できます。
*   **柔軟性:** ERC-20標準をベースに、独自の機能を追加することで、特定のニーズに合わせたトークンを開発できます。

#### ERC-20標準のインターフェース

ERC-20トークンは、以下の6つの必須関数と2つのイベントを実装する必要があります。

**関数:**

*   `totalSupply()`: トークンの総発行量を返します。
*   `balanceOf(address account)`: 指定されたアドレスが保有するトークン残高を返します。
*   `transfer(address recipient, uint256 amount)`: メッセージ送信者のアドレスから指定されたアドレスへ、指定された量のトークンを送信します。
*   `allowance(address owner, address spender)`: 指定されたオーナーのアドレスに対して、指定されたアドレスが引き出すことのできるトークン量を返します。
*   `approve(address spender, uint256 amount)`: 指定されたアドレスに対して、メッセージ送信者のアドレスから指定された量のトークンを引き出す許可を与えます。
*   `transferFrom(address sender, address recipient, uint256 amount)`: 指定されたアドレスから指定されたアドレスへ、指定された量のトークンを送信します。`approve`関数で事前に承認されている必要があります。

**イベント:**

*   `Transfer(address indexed from, address indexed to, uint256 value)`: トークンの転送時に発行されます。
*   `Approval(address indexed owner, address indexed spender, uint256 value)`: トークンの引き出し許可時に発行されます。

#### トークンの基本機能：totalSupply, balanceOf, transfer, allowance, approve, transferFrom

これらの関数は、ERC-20トークンの基本的な機能を担っています。

*   `totalSupply`: トークンエコノミー全体を把握するために重要な情報です。
*   `balanceOf`: ユーザーの残高を確認するために不可欠です。
*   `transfer`: トークンの基本的な送金機能を提供します。
*   `allowance`, `approve`, `transferFrom`: 別のコントラクトがユーザーの代わりにトークンを操作できるようにする仕組みを提供します。これは、DeFiプロトコルなどで頻繁に使用されます。

### 4.2 シンプルなERC-20トークンコントラクトの実装

#### 事前準備と前提条件

このセクションを始める前に、以下の準備が必要です。

*   Node.jsとnpm (または yarn)がインストールされていること。
*   Hardhatがインストールされていること。（`npm install -g hardhat`）
*   Solidityの基本的な知識があること。

#### コントラクトの骨格定義

まずは、Hardhatでプロジェクトを作成します。

```bash
mkdir my-token
cd my-token
npx hardhat
```

プロジェクト作成時に、"Create an empty hardhat.config.js"を選択します。

次に、`contracts`ディレクトリに`MyToken.sol`というファイルを作成し、コントラクトの骨格を定義します。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract MyToken is ERC20 {

    constructor(string memory name, string memory symbol) ERC20(name, symbol) {
        // 初期発行量を設定するロジック
    }

    // 追加の機能 (オプション)
}
```

ここでは、OpenZeppelinのERC20コントラクトを継承しています。OpenZeppelinは、セキュアなスマートコントラクトライブラリを提供しており、ERC-20の実装を最初から行う手間を省き、セキュリティリスクを軽減することができます。

#### 状態変数の定義 (totalSupply, balances, allowances)

OpenZeppelinのERC20コントラクトは、`_totalSupply`、`_balances`、`_allowances`といった状態変数を内部的に管理しています。これらの状態変数を直接操作する必要はありません。

#### 各関数の実装 (totalSupply, balanceOf, transfer, allowance, approve, transferFrom)

OpenZeppelinのERC20コントラクトを継承しているため、これらの関数は既に実装されています。必要に応じて、`_mint`関数や`_burn`関数をオーバーライドすることで、トークンの発行や焼却機能をカスタマイズできます。

例えば、コントラクトの作成時に初期発行量を設定するには、コンストラクタ内で`_mint`関数を呼び出します。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract MyToken is ERC20 {

    constructor(string memory name, string memory symbol, uint256 initialSupply) ERC20(name, symbol) {
        _mint(msg.sender, initialSupply);
    }

    // 追加の機能 (オプション)
}
```

この例では、コントラクトのデプロイ時に、デプロイヤーのアドレスに初期発行量(`initialSupply`)が割り当てられます。

#### イベントの発火 (Transfer, Approval)

OpenZeppelinのERC20コントラクトは、`transfer`、`approve`、`transferFrom`関数内で、それぞれ`Transfer`イベントと`Approval`イベントを適切に発行しています。そのため、追加でイベントを発行する必要はありません。

### 4.3 テストコードの作成と実行

#### Hardhatでのテスト環境設定

Hardhatは、スマートコントラクトのテスト、デプロイ、検証を容易にする開発環境です。Hardhatの設定ファイル(`hardhat.config.js`)を編集して、テスト環境を設定します。

```javascript
require("@nomicfoundation/hardhat-toolbox");

/** @type import('hardhat/config').HardhatUserConfig */
module.exports = {
  solidity: "0.8.9",
};
```

#### MochaとChaiを使ったテストコードの作成

`test`ディレクトリに`MyToken.test.js`というファイルを作成し、MochaとChaiを使ってテストコードを記述します。

```javascript
const { expect } = require("chai");
const { ethers } = require("hardhat");

describe("MyToken", function () {
  it("Should deploy with the correct name, symbol, and initial supply", async function () {
    const [owner] = await ethers.getSigners();

    const MyToken = await ethers.getContractFactory("MyToken");
    const initialSupply = ethers.utils.parseEther("1000"); // 1000トークン
    const myToken = await MyToken.deploy("MyToken", "MTK", initialSupply);
    await myToken.deployed();

    expect(await myToken.name()).to.equal("MyToken");
    expect(await myToken.symbol()).to.equal("MTK");
    expect(await myToken.totalSupply()).to.equal(initialSupply);
    expect(await myToken.balanceOf(owner.address)).to.equal(initialSupply);
  });

  it("Should transfer tokens between accounts", async function () {
    const [owner, addr1, addr2] = await ethers.getSigners();

    const MyToken = await ethers.getContractFactory("MyToken");
    const initialSupply = ethers.utils.parseEther("1000");
    const myToken = await MyToken.deploy("MyToken", "MTK", initialSupply);
    await myToken.deployed();

    const transferAmount = ethers.utils.parseEther("100");

    await myToken.transfer(addr1.address, transferAmount);
    expect(await myToken.balanceOf(owner.address)).to.equal(initialSupply.sub(transferAmount));
    expect(await myToken.balanceOf(addr1.address)).to.equal(transferAmount);

    await myToken.connect(addr1).transfer(addr2.address, transferAmount);
    expect(await myToken.balanceOf(addr1.address)).to.equal(0);
    expect(await myToken.balanceOf(addr2.address)).to.equal(transferAmount);
  });

  it("Should approve and transferFrom tokens", async function () {
    const [owner, spender, recipient] = await ethers.getSigners();

    const MyToken = await ethers.getContractFactory("MyToken");
    const initialSupply = ethers.utils.parseEther("1000");
    const myToken = await MyToken.deploy("MyToken", "MTK", initialSupply);
    await myToken.deployed();

    const approveAmount = ethers.utils.parseEther("100");
    const transferAmount = ethers.utils.parseEther("50");

    await myToken.approve(spender.address, approveAmount);
    expect(await myToken.allowance(owner.address, spender.address)).to.equal(approveAmount);

    await myToken.connect(spender).transferFrom(owner.address, recipient.address, transferAmount);
    expect(await myToken.balanceOf(owner.address)).to.equal(initialSupply.sub(transferAmount));
    expect(await myToken.balanceOf(recipient.address)).to.equal(transferAmount);
    expect(await myToken.allowance(owner.address, spender.address)).to.equal(approveAmount.sub(transferAmount));
  });
});
```

このテストコードは、以下の機能を確認します。

*   コントラクトが正しい名前、シンボル、初期発行量でデプロイされること。
*   トークンがアカウント間で正常に転送されること。
*   `approve`関数と`transferFrom`関数が正常に動作すること。

#### 各関数のテスト (transferのテスト、approve/transferFromのテスト)

上記のテストコードは、`transfer`関数と`approve/transferFrom`関数の基本的なテストをカバーしています。より詳細なテストを行う場合は、以下の点を考慮してください。

*   ゼロアドレスへの送金が失敗すること。
*   残高を超える量のトークンを送金しようとした場合に失敗すること。
*   `approve`関数で承認された量を超えるトークンを`transferFrom`関数で送金しようとした場合に失敗すること。

#### テストの実行

テストを実行するには、Hardhatのターミナルで以下のコマンドを実行します。

```bash
npx hardhat test
```

テストが全て成功すれば、コンソールに緑色のチェックマークが表示されます。

### 4.4 デプロイと検証

#### テストネットへのデプロイ

テストが完了したら、テストネットにコントラクトをデプロイします。テストネットは、実際の資金を使わずにスマートコントラクトをテストできる環境です。

Hardhatの設定ファイル(`hardhat.config.js`)に、テストネットの設定を追加します。

```javascript
require("@nomicfoundation/hardhat-toolbox");
require("dotenv").config(); // .envファイルから環境変数を読み込む

/** @type import('hardhat/config').HardhatUserConfig */
module.exports = {
  solidity: "0.8.9",
  networks: {
    goerli: { // Goerliテストネット
      url: process.env.GOERLI_URL || "", // InfuraなどのAPIエンドポイント
      accounts:
        process.env.PRIVATE_KEY !== undefined ? [process.env.PRIVATE_KEY] : [], // デプロイに使用する秘密鍵
    },
  },
};
```

`.env`ファイルを作成し、GoerliテストネットのAPIエンドポイントとデプロイに使用する秘密鍵を設定します。

```
GOERLI_URL=<あなたのInfuraエンドポイントなど>
PRIVATE_KEY=<あなたの秘密鍵>
```

**注意:** 秘密鍵は厳重に管理し、GitHubなどの公開リポジトリにコミットしないように注意してください。

デプロイスクリプト(`scripts/deploy.js`)を作成します。

```javascript
const { ethers } = require("hardhat");

async function main() {
  const MyToken = await ethers.getContractFactory("MyToken");
  const initialSupply = ethers.utils.parseEther("1000");
  const myToken = await MyToken.deploy("MyToken", "MTK", initialSupply);

  await myToken.deployed();

  console.log("MyToken deployed to:", myToken.address);
}

main()
  .then(() => process.exit(0))
  .catch((error) => {
    console.error(error);
    process.exit(1);
  });
```

デプロイスクリプトを実行します。

```bash
npx hardhat run scripts/deploy.js --network goerli
```

コントラクトのアドレスがコンソールに表示されます。

#### Etherscanでのコントラクト検証

コントラクトをEtherscanで検証することで、コントラクトのソースコードを公開し、誰でもコントラクトの動作を確認できるようになります。

HardhatのEtherscanプラグインをインストールします。

```bash
npm install --save-dev @nomiclabs/hardhat-etherscan
```

Hardhatの設定ファイル(`hardhat.config.js`)に、Etherscanの設定を追加します。

```javascript
require("@nomicfoundation/hardhat-toolbox");
require("@nomiclabs/hardhat-etherscan");
require("dotenv").config();

/** @type import('hardhat/config').HardhatUserConfig */
module.exports = {
  solidity: "0.8.9",
  networks: {
    goerli: {
      url: process.env.GOERLI_URL || "",
      accounts:
        process.env.PRIVATE_KEY !== undefined ? [process.env.PRIVATE_KEY] : [],
    },
  },
  etherscan: {
    apiKey: process.env.ETHERSCAN_API_KEY, // Etherscan APIキー
  },
};
```

`.env`ファイルに、Etherscan APIキーを設定します。

```
GOERLI_URL=<あなたのInfuraエンドポイントなど>
PRIVATE_KEY=<あなたの秘密鍵>
ETHERSCAN_API_KEY=<あなたのEtherscan APIキー>
```

コントラクトを検証します。

```bash
npx hardhat verify --network goerli <コントラクトのアドレス> "MyToken" "MTK" <初期発行量>
```

`<コントラクトのアドレス>`、`"MyToken"` (コントラクト名)、`"MTK"` (シンボル)、`<初期発行量>` を適切な値に置き換えてください。

検証が成功すると、Etherscanでコントラクトのソースコードを確認できるようになります。
