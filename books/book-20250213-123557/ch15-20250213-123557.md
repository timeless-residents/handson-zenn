## 第15章 NFT (Non-Fungible Token) 開発

NFT（Non-Fungible Token：非代替性トークン）は、デジタルアセットの所有権を証明する画期的な技術であり、アート、音楽、ゲーム、不動産など、様々な分野でその可能性が広がっています。この章では、NFT開発の基礎から応用までを網羅的に解説し、あなた自身がNFTの世界を切り開くための知識とスキルを習得することを目指します。

### 15.1 ERC-721とERC-1155

#### 15.1.1 ERC-721標準の解説

**概要と重要性**

ERC-721は、NFTの最も基本的な規格であり、唯一無二のトークンを表現するために設計されました。デジタルアートやコレクションアイテムなど、個別の価値を持つアセットの所有権を明確化する上で非常に重要な役割を果たします。

**特徴と利点**

*   **唯一性:** 各トークンは固有のIDを持ち、他のトークンと区別されます。
*   **不分割性:** トークンは分割できず、常に全体として扱われます。
*   **所有権:** トークンは特定のウォレットアドレスに紐づけられ、所有権を明確に示します。
*   **汎用性:** 様々なNFTマーケットプレイスやウォレットで広くサポートされています。

**事前準備と前提条件**

*   Solidityの基本的な知識
*   Ethereum開発環境 (Remix, Truffle, Hardhatなど) のセットアップ
*   Metamaskなどのウォレットの準備

**基本的な使い方**

ERC-721コントラクトの基本的な実装例を以下に示します。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
import "@openzeppelin/contracts/utils/Counters.sol";

contract MyNFT is ERC721 {
    using Counters for Counters.Counter;
    Counters.Counter private _tokenIds;

    constructor() ERC721("MyNFT", "MNFT") {}

    function mintNFT(address recipient, string memory tokenURI) public returns (uint256) {
        _tokenIds.increment();

        uint256 newItemId = _tokenIds.current();
        _mint(recipient, newItemId);
        _setTokenURI(newItemId, tokenURI);

        return newItemId;
    }

    function tokenURI(uint256 tokenId) public view override returns (string memory) {
        require(_exists(tokenId), "ERC721Metadata: URI query for nonexistent token");
        return super.tokenURI(tokenId);
    }
}
```

このコントラクトは、OpenZeppelinのERC721ライブラリを継承しており、以下の機能を提供します。

*   `mintNFT`: 新しいNFTをミント（発行）し、特定のウォレットに割り当てます。
*   `tokenURI`: トークンのメタデータ（画像、説明など）へのURIを返します。

**実践的なテクニック**

*   **メタデータURIの標準化:** NFTのメタデータは、JSON形式で記述され、IPFSなどの分散型ストレージに保存するのが一般的です。`tokenURI`関数は、このメタデータへのURIを返します。
*   **イベントの利用:** トークンのミントや譲渡などのイベントを監視し、アプリケーションに通知を送ることができます。
*   **コントラクトのアップグレード:** 必要に応じてコントラクトをアップグレードできるように、Proxyパターンなどを採用することを検討しましょう。

**応用例とユースケース**

*   **デジタルアート:** アーティストが自身の作品をNFTとして発行し、直接販売することができます。
*   **コレクションアイテム:** トレーディングカードやゲームアイテムなど、ユニークなデジタルアセットの所有権を証明できます。
*   **会員権:** 会員限定の特典やサービスを提供するNFTを発行することができます。

**トラブルシューティング**

*   **ガス代の高騰:** NFTのミントにはガス代がかかります。ガス代を最適化するために、コントラクトのコードを効率化したり、ガス代が安い時間帯にトランザクションを実行したりすることを検討しましょう。
*   **メタデータURIの永続性:** メタデータURIが変更されたり、アクセスできなくなったりすると、NFTの価値が損なわれる可能性があります。IPFSなどの分散型ストレージを利用することで、メタデータの永続性を確保しましょう。

**まとめと次のステップ**

ERC-721は、NFT開発の基礎となる重要な規格です。このセクションで学んだ知識を基に、実際にNFTを発行し、マーケットプレイスで販売してみることをお勧めします。次のステップでは、ERC-1155について学び、より高度なNFTの活用方法を探求しましょう。

#### 15.1.2 ERC-1155標準の解説

**概要と重要性**

ERC-1155は、複数の種類のトークン（代替可能トークンと非代替可能トークンの両方）を1つのコントラクトで管理できる規格です。ゲームアイテムやユーティリティトークンなど、複数の種類のアセットを効率的に管理する必要がある場合に非常に有効です。

**特徴と利点**

*   **マルチトークン:** 1つのコントラクトで複数の種類のトークンを管理できます。
*   **代替可能トークンと非代替可能トークンの両方をサポート:** 同じコントラクトで、ERC-20のような代替可能トークンとERC-721のような非代替可能トークンを扱うことができます。
*   **効率的なトランザクション:** 複数のトークンを1つのトランザクションで送受信できます。
*   **ガス代の最適化:** 複数のトークンをまとめて管理することで、ガス代を削減できます。

**事前準備と前提条件**

*   ERC-721の知識
*   Solidityの知識
*   Ethereum開発環境のセットアップ

**基本的な使い方**

ERC-1155コントラクトの基本的な実装例を以下に示します。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC1155/ERC1155.sol";
import "@openzeppelin/contracts/utils/Strings.sol";

contract MyMultiToken is ERC1155 {
    using Strings for uint256;

    // トークンIDのカウンター
    uint256 public nextTokenId = 1;

    constructor() ERC1155("ipfs://{id}.json") {} // メタデータURIのベース

    function mint(address account, uint256 id, uint256 amount, bytes memory data) public {
        _mint(account, id, amount, data);
    }

    // 新しいトークンタイプの作成
    function createToken(uint256 initialSupply, string memory metadataURI) public returns (uint256) {
        uint256 tokenId = nextTokenId;
        nextTokenId++;

        // メタデータURIの設定 (例: IPFS)
        _setURI(tokenId, metadataURI);

        // 初期供給量のミント
        _mint(msg.sender, tokenId, initialSupply, "");

        return tokenId;
    }

    // デフォルトのURIをtokenIdに基づいて動的に変更
    function uri(uint256 tokenId) public view override returns (string memory) {
        return string(abi.encodePacked("ipfs://", tokenId.toString(), ".json"));
    }

    function _setURI(uint256 tokenId, string memory metadataURI) internal {
       // ここでカスタムのURIを設定
    }
}
```

このコントラクトは、OpenZeppelinのERC1155ライブラリを継承しており、以下の機能を提供します。

*   `mint`: 指定されたアカウントに、指定されたIDのトークンを、指定された数量だけミント（発行）します。
*   `createToken`: 新しいトークンタイプを作成し、初期供給量をミントします。
*   `uri`: トークンのメタデータへのURIを返します。

**実践的なテクニック**

*   **バッチ処理:** 複数のトークンをまとめて送受信することで、ガス代を削減できます。
*   **メタデータのカスタマイズ:** 各トークンタイプごとに異なるメタデータを設定できます。
*   **ロイヤリティ設定:** NFTの二次販売時に、クリエイターにロイヤリティを支払うように設定できます。

**応用例とユースケース**

*   **ゲームアイテム:** ゲーム内の武器、防具、アイテムなどをERC-1155トークンとして表現し、プレイヤー間で取引できるようにします。
*   **ユーティリティトークン:** 特定のサービスやコンテンツへのアクセス権を付与するトークンを発行します。
*   **不動産:** 不動産の権利をトークン化し、分割所有や取引を容易にします。

**トラブルシューティング**

*   **セキュリティ:** ERC-1155コントラクトは、複雑なロジックを持つため、セキュリティ上の脆弱性が存在する可能性があります。コントラクトの監査を受けたり、セキュリティベストプラクティスに従うようにしましょう。
*   **メタデータの管理:** 複数のトークンタイプを管理する場合、メタデータの管理が煩雑になる可能性があります。メタデータ管理ツールを導入したり、APIを構築したりすることを検討しましょう。

**まとめと次のステップ**

ERC-1155は、NFTの可能性をさらに広げる強力な規格です。このセクションで学んだ知識を基に、実際にERC-1155コントラクトを実装し、様々なユースケースを試してみることをお勧めします。次のセクションでは、NFTのメタデータ設定について学び、より魅力的なNFTを作成しましょう。

#### 15.1.3 メタデータの設定 (IPFSとの連携)

**概要と重要性**

NFTのメタデータは、トークンの名前、説明、画像、属性など、NFTに関する様々な情報を含むJSON形式のデータです。メタデータは、NFTの価値や魅力を高める上で非常に重要な役割を果たします。IPFS（InterPlanetary File System）は、分散型のストレージシステムであり、NFTのメタデータを永続的に保存するために広く利用されています。

**特徴と利点**

*   **メタデータ:** NFTの属性、画像、説明などを記述します。
*   **IPFS:** 分散型ストレージシステムであり、データの永続性と可用性を保証します。
*   **NFTの価値向上:** 魅力的なメタデータは、NFTの価値を高めます。
*   **データの永続性:** IPFSに保存されたメタデータは、中央集権的なサーバーに依存せず、永続的に利用可能です。

**事前準備と前提条件**

*   IPFSの基本的な知識
*   IPFSクライアントのインストール (例: IPFS Desktop)
*   JSON形式の知識

**基本的な使い方**

1.  **メタデータJSONファイルの作成:**

    NFTのメタデータJSONファイルを作成します。以下は、メタデータJSONファイルの例です。

    ```json
    {
      "name": "My Awesome NFT",
      "description": "This is a unique NFT with a cool design.",
      "image": "ipfs://Qm...[ハッシュ値].../image.png",
      "attributes": [
        {
          "trait_type": "Background",
          "value": "Blue"
        },
        {
          "trait_type": "Character",
          "value": "Robot"
        }
      ]
    }
    ```

    `image`フィールドには、画像のIPFSハッシュを指定します。

2.  **IPFSへのアップロード:**

    IPFSクライアントを使用して、メタデータJSONファイルと画像をIPFSにアップロードします。

3.  **IPFSハッシュの取得:**

    IPFSへのアップロード後、ファイルと画像のIPFSハッシュを取得します。

4.  **コントラクトへの組み込み:**

    NFTコントラクトの`tokenURI`関数で、メタデータJSONファイルのIPFSハッシュを返します。

    ```solidity
    function tokenURI(uint256 tokenId) public view override returns (string memory) {
        require(_exists(tokenId), "ERC721Metadata: URI query for nonexistent token");
        string memory baseURI = "ipfs://";
        string memory metadataCID = "Qm...[ハッシュ値]..."; // メタデータJSONファイルのIPFSハッシュ
        string memory jsonExtension = ".json";
        return string(abi.encodePacked(baseURI, metadataCID, jsonExtension));
    }
    ```

**実践的なテクニック**

*   **IPFS Pinning:** IPFSにアップロードされたデータは、ノードが保持しなくなる可能性があります。Pinningサービスを利用することで、データを永続的にIPFSに保持することができます。
*   **Centralized Gateway:** IPFSへのアクセスが難しいユーザーのために、Centralized Gateway (例: Cloudflare IPFS Gateway) を利用することができます。

**応用例とユースケース**

*   **デジタルアート:** アーティストが作成したデジタルアート作品の情報をメタデータに記述し、IPFSに保存します。
*   **コレクションアイテム:** コレクションアイテムのレアリティや属性などの情報をメタデータに記述し、IPFSに保存します。

**トラブルシューティング**

*   **IPFSゲートウェイの問題:** IPFSゲートウェイがダウンしている場合、メタデータにアクセスできなくなる可能性があります。複数のゲートウェイを利用したり、ローカルIPFSノードを運用したりすることを検討しましょう。
*   **メタデータの更新:** メタデータを更新する必要がある場合、新しいメタデータJSONファイルをIPFSにアップロードし、コントラクトの`tokenURI`関数を更新する必要があります。

**まとめと次のステップ**

NFTのメタデータは、NFTの魅力を高める上で非常に重要な要素です。IPFSを利用することで、メタデータの永続性と可用性を確保することができます。次のセクションでは、NFTマーケットプレイスの開発について学び、NFTの販売と購入を可能にするプラットフォームを構築しましょう。

### 15.2 NFTマーケットプレイス開発

#### 15.2.1 NFTの販売と購入

**概要と重要性**

NFTマーケットプレイスは、NFTの売買を仲介するプラットフォームです。NFTの販売と購入は、NFTエコシステムの中核をなす機能であり、クリエイターが作品を収益化し、コレクターがNFTを収集するための重要な手段となります。

**特徴と利点**

*   **NFTの売買:** ユーザーはNFTを販売したり、購入したりできます。
*   **スマートコントラクト:** スマートコントラクトによって、安全かつ透明性の高い取引が実現されます。
*   **手数料:** マーケットプレイスは、取引手数料を徴収することで収益を得ます。
*   **検索とフィルタリング:** ユーザーは、様々な条件でNFTを検索したり、フィルタリングしたりできます。

**事前準備と前提条件**

*   ERC-721またはERC-1155コントラクトの実装
*   Webフロントエンド開発の知識 (React, Vue.jsなど)
*   バックエンド開発の知識 (Node.js, Pythonなど)
*   Ethereum開発環境のセットアップ

**基本的な使い方**

1.  **コントラクトの実装:**

    NFTの販売と購入を管理するスマートコントラクトを実装します。以下は、基本的なスマートコントラクトの例です。

    ```solidity
    // SPDX-License-Identifier: MIT
    pragma solidity ^0.8.0;

    import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
    import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

    contract NFTMarketplace is ReentrancyGuard {
        struct Listing {
            address seller;
            uint256 price;
            bool isListed;
        }

        mapping(address => mapping(uint256 => Listing)) public listings;
        address public owner;
        uint256 public feePercent;

        event ItemListed(address nftContract, uint256 tokenId, address seller, uint256 price);
        event ItemSold(address nftContract, uint256 tokenId, address seller, address buyer, uint256 price);
        event ItemCanceled(address nftContract, uint256 tokenId, address seller);

        constructor(uint256 _feePercent) {
            owner = msg.sender;
            feePercent = _feePercent;
        }

        modifier onlyOwner() {
            require(msg.sender == owner, "Only owner can call this function.");
            _;
        }

        function listItem(address nftContract, uint256 tokenId, uint256 price) public nonReentrant {
            require(price > 0, "Price must be greater than 0.");
            ERC721(nftContract).transferFrom(msg.sender, address(this), tokenId);
            listings[nftContract][tokenId] = Listing(msg.sender, price, true);

            emit ItemListed(nftContract, tokenId, msg.sender, price);
        }

        function buyItem(address nftContract, uint256 tokenId) public payable nonReentrant {
            Listing storage listing = listings[nftContract][tokenId];
            require(listing.isListed, "Item is not listed.");
            require(msg.value >= listing.price, "Not enough ETH sent.");

            uint256 fee = (listing.price * feePercent) / 100;
            uint256 sellerProceeds = listing.price - fee;

            listing.isListed = false;
            ERC721(nftContract).transferFrom(address(this), msg.sender, tokenId);
            payable(listing.seller).transfer(sellerProceeds);
            payable(owner).transfer(fee);

            emit ItemSold(nftContract, tokenId, listing.seller, msg.sender, listing.price);
        }

        function cancelListing(address nftContract, uint256 tokenId) public nonReentrant {
            Listing storage listing = listings[nftContract][tokenId];
            require(listing.seller == msg.sender, "You are not the seller.");
            require(listing.isListed, "Item is not listed.");

            listing.isListed = false;
            ERC721(nftContract).transferFrom(address(this), msg.sender, tokenId);

            emit ItemCanceled(nftContract, tokenId, msg.sender);
        }
    }
    ```

    このコントラクトは、以下の機能を提供します。

    *   `listItem`: NFTをマーケットプレイスに出品します。
    *   `buyItem`: NFTを購入します。
    *   `cancelListing`: 出品を取り下げます。

2.  **フロントエンドの開発:**

    ユーザーがNFTを検索、閲覧、購入できるWebフロントエンドを開発します。Web3ライブラリ (例: ethers.js, web3.js) を使用して、スマートコントラクトと連携します。

3.  **バックエンドの開発:**

    NFTのメタデータを取得したり、ユーザー情報を管理したりするためのバックエンドを開発します。

**実践的なテクニック**

*   **ガス代の最適化:** ガス代を最適化するために、コントラクトのコードを効率化したり、ガス代が安い時間帯にトランザクションを実行したりすることを検討しましょう。
*   **セキュリティ対策:** クロスサイトスクリプティング (XSS) やSQLインジェクションなどの脆弱性から保護するために、セキュリティ対策を徹底しましょう。

**応用例とユースケース**

*   **デジタルアートマーケットプレイス:** デジタルアート作品の売買に特化したマーケットプレイスを構築します。
*   **ゲームアイテムマーケットプレイス:** ゲーム内のアイテムの売買に特化したマーケットプレイスを構築します。

**トラブルシューティング**

*   **トランザクションの失敗:** トランザクションが失敗した場合、エラーメッセージを確認し、原因を特定して修正します。
*   **メタデータの取得:** メタデータが正しく取得できない場合、IPFSゲートウェイがダウンしている可能性があります。別のゲートウェイを試したり、ローカルIPFSノードを運用したりすることを検討しましょう。

**まとめと次のステップ**

NFTマーケットプレイスは、NFTエコシステムの重要な要素です。このセクションで学んだ知識を基に、実際にNFTマーケットプレイスを開発し、NFTの売買を促進しましょう。次のセクションでは、オークション機能について学び、NFTの販売方法の幅を広げましょう。

#### 15.2.2 オークション機能

**概要と重要性**

オークション機能は、NFTの販売方法の1つであり、入札を通じてNFTの価格を決定します。オークションは、人気のあるNFTや希少なNFTの販売に適しており、価格発見のメカニズムとしても機能します。

**特徴と利点**

*   **価格発見:** 入札を通じて、NFTの公正な価格を発見できます。
*   **競争:** 複数の入札者が競争することで、NFTの価格が上昇する可能性があります。
*   **興奮:** オークションは、入札者にとってエキサイティングな体験となります。
*   **柔軟性:** オークションの開始価格、期間、入札単位などを自由に設定できます。

**事前準備と前提条件**

*   NFTマーケットプレイスの知識
*   Solidityの知識
*   Ethereum開発環境のセットアップ

**基本的な使い方**

1.  **コントラクトの実装:**

    オークション機能を管理するスマートコントラクトを実装します。以下は、基本的なスマートコントラクトの例です。

    ```solidity
    // SPDX-License-Identifier: MIT
    pragma solidity ^0.8.0;

    import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
    import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

    contract NFTAuction is ReentrancyGuard {
        struct Auction {
            address nftContract;
            uint256 tokenId;
            address seller;
            uint256 startTime;
            uint256 endTime;
            uint256 startPrice;
            address highestBidder;
            uint256 highestBid;
            bool ended;
        }

        mapping(uint256 => Auction) public auctions;
        uint256 public nextAuctionId = 1;
        address public owner;

        event AuctionCreated(uint256 auctionId, address nftContract, uint256 tokenId, address seller, uint256 startTime, uint256 endTime, uint256 startPrice);
        event BidPlaced(uint256 auctionId, address bidder, uint256 amount);
        event AuctionEnded(uint256 auctionId, address winner, uint256 amount);
        event AuctionCanceled(uint256 auctionId);

        constructor() {
            owner = msg.sender;
        }

        modifier onlyOwner() {
            require(msg.sender == owner, "Only owner can call this function.");
            _;
        }

        function createAuction(address nftContract, uint256 tokenId, uint256 startTime, uint256 endTime, uint256 startPrice) public {
            require(startTime >= block.timestamp, "Start time must be in the future.");
            require(endTime > startTime, "End time must be after start time.");
            require(ERC721(nftContract).ownerOf(tokenId) == msg.sender, "You are not the owner of this NFT.");

            ERC721(nftContract).transferFrom(msg.sender, address(this), tokenId);

            auctions[nextAuctionId] = Auction(nftContract, tokenId, msg.sender, startTime, endTime, startPrice, address(0), 0, false);

            emit AuctionCreated(nextAuctionId, nftContract, tokenId, msg.sender, startTime, endTime, startPrice);
            nextAuctionId++;
        }

        function placeBid(uint256 auctionId) public payable nonReentrant {
            Auction storage auction = auctions[auctionId];

            require(block.timestamp >= auction.startTime, "Auction has not started yet.");
            require(block.timestamp <= auction.endTime, "Auction has ended.");
            require(auction.ended == false, "Auction has ended.");
            require(msg.value > auction.startPrice, "Bid must be greater than start price.");
            require(msg.value > auction.highestBid, "Bid must be greater than current highest bid.");

            if (auction.highestBidder != address(0)) {
                payable(auction.highestBidder).transfer(auction.highestBid);
            }

            auction.highestBidder = msg.sender;
            auction.highestBid = msg.value;

            emit BidPlaced(auctionId, msg.sender, msg.value);
        }

        function endAuction(uint256 auctionId) public nonReentrant {
            Auction storage auction = auctions[auctionId];
            require(block.timestamp > auction.endTime, "Auction has not ended yet.");
            require(auction.ended == false, "Auction has already ended.");

            auction.ended = true;

            if (auction.highestBidder != address(0)) {
                ERC721(auction.nftContract).transferFrom(address(this), auction.highestBidder, auction.tokenId);
                payable(auction.seller).transfer(auction.highestBid);
            } else {
                ERC721(auction.nftContract).transferFrom(address(this), auction.seller, auction.tokenId);
            }

            emit AuctionEnded(auctionId, auction.highestBidder, auction.highestBid);
        }

        function cancelAuction(uint256 auctionId) public nonReentrant {
            Auction storage auction = auctions[auctionId];
            require(auction.seller == msg.sender, "You are not the seller.");
            require(block.timestamp < auction.endTime, "Auction has already ended.");
            ERC721(auction.nftContract).transferFrom(address(this), auction.seller, auction.tokenId);

            emit AuctionCanceled(auctionId);
        }
    }
    ```

    このコントラクトは、以下の機能を提供します。

    *   `createAuction`: オークションを作成します。
    *   `placeBid`: 入札を行います。
    *   `endAuction`: オークションを終了します。
    *   `cancelAuction`: オークションをキャンセルします。

2.  **フロントエンドの開発:**

3.  **バックエンドの開発:**

    オークション情報を取得したり、ユーザー情報を管理したりするためのバックエンドを開発します。

**実践的なテクニック**

*   **タイマーの利用:** オークションの残り時間を表示するために、タイマーを利用します。

**応用例とユースケース**

**トラブルシューティング**

#### 15.2.3 ロイヤリティ設定

**概要と重要性**

ロイヤリティ設定は、NFTの二次販売時に、クリエイターに一定の割合の収益を支払う仕組みです。ロイヤリティは、クリエイターに継続的な収益をもたらし、創作活動を支援する上で非常に重要な役割を果たします。

**特徴と利点**

*   **クリエイターへの報酬:** 二次販売時に、クリエイターにロイヤリティが支払われます。
*   **創作活動の支援:** ロイヤリティは、クリエイターの創作活動を経済的に支援します。
*   **NFTの価値向上:** ロイヤリティ設定は、NFTの価値を高めます。
*   **長期的な関係:** クリエイターとコレクターの間に長期的な関係を築きます。

**事前準備と前提条件**

*   NFTマーケットプレイスの知識
*   Solidityの知識
*   Ethereum開発環境のセットアップ

**基本的な使い方**

1.  **コントラクトの実装:**

    ロイヤリティ設定を管理するスマートコントラクトを実装します。以下は、基本的なスマートコントラクトの例です。

    ```solidity
    // SPDX-License-Identifier: MIT
    pragma solidity ^0.8.0;

    import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
    import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

    contract NFTMarketplaceWithRoyalty is ReentrancyGuard {
        struct Listing {
            address seller;
            uint256 price;
            bool isListed;
        }

        mapping(address => mapping(uint256 => Listing)) public listings;
        address public owner;
        uint256 public feePercent;
        mapping(address => uint256) public royaltyFees; // NFTコントラクト => ロイヤリティの割合（%）
        mapping(address => address) public royaltyRecipients; // NFTコントラクト => ロイヤリティ受取人のアドレス

        event ItemListed(address nftContract, uint256 tokenId, address seller, uint256 price);
        event ItemSold(address nftContract, uint256 tokenId, address seller, address buyer, uint256 price);
        event ItemCanceled(address nftContract, uint256 tokenId, address seller);

        constructor(uint256 _feePercent) {
            owner = msg.sender;
            feePercent = _feePercent;
        }

        modifier onlyOwner() {
            require(msg.sender == owner, "Only owner can call this function.");
            _;
        }

        function listItem(address nftContract, uint256 tokenId, uint256 price) public nonReentrant {
            require(price > 0, "Price must be greater than 0.");
            ERC721(nftContract).transferFrom(msg.sender, address(this), tokenId);
            listings[nftContract][tokenId] = Listing(msg.sender, price, true);

            emit ItemListed(nftContract, tokenId, msg.sender, price);
        }

        function buyItem(address nftContract, uint256 tokenId) public payable nonReentrant {
            Listing storage listing = listings[nftContract][tokenId];
            require(listing.isListed, "Item is not listed.");
            require(msg.value >= listing.price, "Not enough ETH sent.");

            uint256 royaltyFee = (listing.price * royaltyFees[nftContract]) / 100; // ロイヤリティ計算
            uint256 fee = (listing.price * feePercent) / 100;
            uint256 sellerProceeds = listing.price - fee - royaltyFee;

            listing.isListed = false;
            ERC721(nftContract).transferFrom(address(this), msg.sender, tokenId);
            payable(listing.seller).transfer(sellerProceeds);
            payable(owner).transfer(fee);
            payable(royaltyRecipients[nftContract]).transfer(royaltyFee); // ロイヤリティの支払い

            emit ItemSold(nftContract, tokenId, listing.seller, msg.sender, listing.price);
        }

        function cancelListing(address nftContract, uint256 tokenId) public nonReentrant {
            Listing storage listing = listings[nftContract][tokenId];
            require(listing.seller == msg.sender, "You are not the seller.");
            require(listing.isListed, "Item is not listed.");

            listing.isListed = false;
            ERC721(nftContract).transferFrom(address(this), msg.sender, tokenId);

            emit ItemCanceled(nftContract, tokenId, msg.sender);
        }

        function setRoyalty(address nftContract, uint256 royaltyPercent, address recipient) public onlyOwner {
            require(royaltyPercent <= 100, "Royalty percent cannot be greater than 100.");
            royaltyFees[nftContract] = royaltyPercent;
            royaltyRecipients[nftContract] = recipient;
        }
    }
    ```

    このコントラクトは、以下の機能を提供します。

    *   `setRoyalty`: NFTコントラクトにロイヤリティを設定します。
    *   `buyItem`: NFTを購入する際に、ロイヤリティをクリエイターに支払います。

2.  **フロントエンドの開発:**

    ユーザーがロイヤリティを確認できるWebフロントエンドを開発します。Web3ライブラリを使用して、スマートコントラクトと連携します。

3.  **バックエンドの開発:**

    ロイヤリティ情報を取得したり、ユーザー情報を管理したりするためのバックエンドを開発します。
