## 13. スマートコントラクトのテストとデバッグ

スマートコントラクトは、一度デプロイされると変更が非常に難しく、バグが重大な経済的損失につながる可能性があります。そのため、開発プロセスにおいてテストとデバッグは極めて重要なステップです。本章では、スマートコントラクトの信頼性を高めるための様々なテスト手法とデバッグツールについて、具体的な例を交えながら解説します。

### 13.1 単体テスト - Hardhat, Foundry, Truffle

#### 13.1.1 概要と重要性

単体テストは、スマートコントラクトの個々の関数やモジュールが意図した通りに動作するかどうかを検証するテスト手法です。コントラクト全体の複雑さを分割し、個々のコンポーネントの正確性を保証することで、バグの早期発見と修正を可能にします。単体テストは、スマートコントラクト開発の初期段階で実施することが推奨されます。

#### 13.1.2 特徴と利点

*   **早期バグ発見:** 個々の関数レベルでテストを行うため、複雑なロジックに潜むバグを早期に発見できます。
*   **開発効率向上:** テスト駆動開発（TDD）を実践しやすくなり、リファクタリング時の安全性を高めます。
*   **コードの理解促進:** テストコードは、コントラクトの機能を理解するためのドキュメントとしても機能します。
*   **自動化による効率化:** テストを自動化することで、継続的なインテグレーション（CI）パイプラインに組み込み、開発プロセス全体を効率化できます。

#### 13.1.3 事前準備と前提条件

本セクションでは、代表的な開発環境である Hardhat, Foundry, Truffle を用いて説明します。それぞれの環境のインストールとプロジェクトの初期設定が完了していることを前提とします。

*   **Hardhat:** Node.js と npm (または yarn) がインストールされている必要があります。
*   **Foundry:** Rust がインストールされている必要があります。
*   **Truffle:** Node.js と npm がインストールされている必要があります。

#### 13.1.4 基本的な使い方

**Hardhat:**

1.  **プロジェクトの作成:**

    ```bash
    mkdir hardhat-test
    cd hardhat-test
    npm init -y
    npm install --save-dev hardhat @nomicfoundation/hardhat-toolbox
    npx hardhat
    ```

    指示に従って、基本的なHardhatプロジェクトをセットアップします。

2.  **コントラクトの作成 (contracts/SimpleStorage.sol):**

    ```solidity
    // SPDX-License-Identifier: MIT
    pragma solidity ^0.8.0;

    contract SimpleStorage {
        uint256 private storedData;

        function set(uint256 x) public {
            storedData = x;
        }

        function get() public view returns (uint256) {
            return storedData;
        }
    }
    ```

3.  **テストの作成 (test/SimpleStorage.js):**

    ```javascript
    const { expect } = require("chai");
    const { ethers } = require("hardhat");

    describe("SimpleStorage", function () {
        it("Should set and get the stored data", async function () {
            const SimpleStorage = await ethers.getContractFactory("SimpleStorage");
            const simpleStorage = await SimpleStorage.deploy();
            await simpleStorage.deployed();

            await simpleStorage.set(42);
            expect(await simpleStorage.get()).to.equal(42);
        });
    });
    ```

4.  **テストの実行:**

    ```bash
    npx hardhat test
    ```

**Foundry:**

1.  **Foundry のインストール:**

    ```bash
    curl -L https://foundry.paradigm.xyz | bash
    foundryup
    ```

2.  **プロジェクトの作成:**

    ```bash
    forge init foundry-test
    cd foundry-test
    ```

3.  **コントラクトの作成 (src/SimpleStorage.sol):**

    ```solidity
    // SPDX-License-Identifier: UNLICENSED
    pragma solidity ^0.8.0;

    contract SimpleStorage {
        uint256 public storedData;

        function set(uint256 x) public {
            storedData = x;
        }

        function get() public view returns (uint256) {
            return storedData;
        }
    }
    ```

4.  **テストの作成 (test/SimpleStorage.t.sol):**

    ```solidity
    // SPDX-License-Identifier: UNLICENSED
    pragma solidity ^0.8.0;

    import "forge-std/Test.sol";
    import "../src/SimpleStorage.sol";

    contract SimpleStorageTest is Test {
        SimpleStorage public simpleStorage;

        function setUp() public {
            simpleStorage = new SimpleStorage();
        }

        function testSetAndGet() public {
            simpleStorage.set(42);
            assertEq(simpleStorage.get(), 42);
        }
    }
    ```

5.  **テストの実行:**

    ```bash
    forge test
    ```

**Truffle:**

1.  **プロジェクトの作成:**

    ```bash
    mkdir truffle-test
    cd truffle-test
    npm install -g truffle
    truffle init
    ```

2.  **コントラクトの作成 (contracts/SimpleStorage.sol):**

    ```solidity
    pragma solidity ^0.8.0;

    contract SimpleStorage {
        uint256 private storedData;

        function set(uint256 x) public {
            storedData = x;
        }

        function get() public view returns (uint256) {
            return storedData;
        }
    }
    ```

3.  **マイグレーションファイルの作成 (migrations/1_deploy_simple_storage.js):**

    ```javascript
    const SimpleStorage = artifacts.require("SimpleStorage");

    module.exports = function (deployer) {
        deployer.deploy(SimpleStorage);
    };
    ```

4.  **テストの作成 (test/simple_storage.js):**

    ```javascript
    const SimpleStorage = artifacts.require("SimpleStorage");

    contract("SimpleStorage", (accounts) => {
        it("Should set and get the stored data", async () => {
            const simpleStorage = await SimpleStorage.deployed();

            await simpleStorage.set(42, { from: accounts[0] });
            const storedData = await simpleStorage.get();

            assert.equal(storedData, 42, "The stored data should be 42");
        });
    });
    ```

5.  **テストの実行:**

    ```bash
    truffle test
    ```

#### 13.1.5 実践的なテクニック

*   **モックの活用:** 外部コントラクトとの依存関係がある場合、モックコントラクトを使用して、外部コントラクトの動作をエミュレートします。これにより、外部コントラクトに依存せずに単体テストを実施できます。Hardhat, Foundry, Truffleにはモック作成を補助するライブラリや機能が備わっています。
*   **イベントの検証:** スマートコントラクトがイベントを発行する場合、テストでイベントが正しく発行されているか、またイベントに含まれるデータが正しいかを検証します。
*   **例外処理のテスト:** 関数が特定の条件下で例外をスローする場合、テストで例外が正しくスローされるか、また例外メッセージが正しいかを検証します。
*   **境界値テスト:** 関数の入力値として、最大値、最小値、ゼロなど、境界値に近い値をテストします。これにより、オーバーフローやアンダーフローなどの潜在的な問題を検出できます。
*   **テストカバレッジの確認:** テストカバレッジツールを使用して、コードのどの部分がテストされているかを確認します。カバレッジが低い箇所は、テストケースを追加する必要があります。

#### 13.1.6 応用例とユースケース

*   **ERC-20トークンのテスト:** トークンの発行、送金、残高の確認などの機能をテストします。
*   **DAOコントラクトのテスト:** 提案の作成、投票、実行などの機能をテストします。
*   **DeFiプロトコルのテスト:** スワップ、レンディング、ファーミングなどの機能をテストします。

#### 13.1.7 トラブルシューティング

*   **テストが失敗する場合:** エラーメッセージを注意深く確認し、コントラクトのロジックに誤りがないか、テストケースに誤りがないかを確認します。
*   **モックコントラクトが正しく動作しない場合:** モックコントラクトのインターフェースが、オリジナルのコントラクトと一致しているかを確認します。
*   **テストカバレッジが低い場合:** テストケースが不足している箇所を特定し、テストケースを追加します。

#### 13.1.8 まとめと次のステップ

単体テストは、スマートコントラクトの品質を保証するための重要なステップです。Hardhat, Foundry, Truffleなどのツールを活用し、体系的なテストを実施することで、バグの早期発見と修正が可能になります。次のステップとして、ファジングやデバッグツールについて学習し、テストプロセスをさらに強化しましょう。

### 13.2 ファジング - Echidna, Harvey

#### 13.2.1 概要と重要性

ファジングは、プログラムにランダムな、または予期しない入力を大量に与え、予期しない動作やクラッシュを引き起こすかどうかをテストする手法です。スマートコントラクトにおいては、単体テストでは見つけにくい、複雑な条件が組み合わさった場合に発生する潜在的な脆弱性を発見するために非常に有効です。

#### 13.2.2 特徴と利点

*   **自動的なテスト:** 開発者が事前にテストケースを定義する必要がなく、ツールが自動的にランダムな入力を生成してテストを実行します。
*   **隠れた脆弱性の発見:** 単体テストでは見落としがちな、複雑な条件が組み合わさった場合に発生する脆弱性を発見できます。
*   **網羅的なテスト:** 大量の入力を試すことで、コントラクトの様々な動作を網羅的にテストできます。
*   **形式検証との連携:** ファジングで見つかった問題点を、形式検証ツールでより詳細に解析することで、脆弱性の根本原因を特定できます。

#### 13.2.3 事前準備と前提条件

*   **Echidna:** Nix パッケージマネージャーがインストールされている必要があります。
*   **Harvey:** Rust がインストールされている必要があります。

#### 13.2.4 基本的な使い方

**Echidna:**

1.  **Echidna のインストール:**

    ```bash
    nix-env -iA nixpkgs.crytic-compile nixpkgs.echidna
    ```

2.  **コントラクトの準備:**

    先ほどの `SimpleStorage.sol` をそのまま使用できます。

3.  **プロパティファイルの作成 (echidna.config.yaml):**

    Echidnaは、コントラクトが満たすべき不変条件（インバリアント）を定義した設定ファイルに基づいて動作します。

    ```yaml
    test_mode: assertion
    contract: SimpleStorage
    properties:
      - "storedDataAlwaysPositive": "storedData >= 0"
    ```

    ここでは、「storedDataは常に0以上である」という不変条件を定義しています。

4.  **Echidna の実行:**

    ```bash
    echidna SimpleStorage.sol --config echidna.config.yaml
    ```

    Echidnaは、`SimpleStorage.sol`を解析し、ランダムな入力を生成して`storedData >= 0`という不変条件が破られないかをテストします。

**Harvey:**

1. **Harvey のインストール:**
   ```bash
   cargo install harvey
   ```

2. **コントラクトの準備:**
    先ほどの `SimpleStorage.sol` をそのまま使用できます。

3. **Harvey の実行:**
   Harveyは、Solidityコードを解析し、自動的にプロパティを生成してテストを実行します。

   ```bash
   harvey SimpleStorage.sol
   ```

   Harveyは、`SimpleStorage.sol`を解析し、ランダムな入力を生成してコントラクトの様々なプロパティをテストします。

#### 13.2.5 実践的なテクニック

*   **複雑なプロパティの定義:** コントラクトの複雑なロジックを反映した、より高度な不変条件を定義します。例えば、トークンコントラクトの場合、「総供給量は常に一定である」という不変条件を定義できます。
*   **カスタムジェネレーターの作成:** 標準のランダム入力だけでなく、コントラクトの特性に合わせたカスタムの入力ジェネレーターを作成します。例えば、特定の範囲の値を集中的にテストする場合などに有効です。
*   **テストカバレッジの監視:** ファジングツールでテストカバレッジを監視し、十分なカバレッジが得られていない箇所は、プロパティや入力ジェネレーターを調整します。

#### 13.2.6 応用例とユースケース

*   **算術オーバーフローの検出:** 非常に大きな数値を入力し、算術オーバーフローが発生しないかをテストします。
*   **アクセス制御の脆弱性の検出:** 権限のないユーザーが、管理者権限が必要な関数を実行できないかをテストします。
*   **再入可能性攻撃の検出:** 外部コントラクトへのコールバックを利用して、再入可能性攻撃が発生しないかをテストします。

#### 13.2.7 トラブルシューティング

*   **Echidna の実行に失敗する場合:** Nix パッケージが正しくインストールされているか、プロパティファイルの構文に誤りがないかを確認します。
*   **Harvey の実行に失敗する場合:** Rust 環境が正しく設定されているか、コントラクトの構文に誤りがないかを確認します。
*   **テストに時間がかかりすぎる場合:** プロパティの定義を見直し、テスト対象を絞り込むことで、テスト時間を短縮できます。

#### 13.2.8 まとめと次のステップ

ファジングは、スマートコントラクトの潜在的な脆弱性を発見するための強力なツールです。Echidna や Harvey などのツールを活用し、単体テストでは見つけにくいバグを早期に発見し、スマートコントラクトの安全性を高めましょう。次のステップとして、デバッグツールについて学習し、発見されたバグの根本原因を効率的に特定する方法を習得しましょう。

### 13.3 デバッグツール - Remix, Tenderly

#### 13.3.1 概要と重要性

デバッグツールは、スマートコントラクトの実行中に発生する問題を特定し、解決するためのツールです。トランザクションの実行履歴、変数の中身、コントラクトの状態などを可視化することで、バグの根本原因を効率的に特定できます。

#### 13.3.2 特徴と利点

*   **トランザクションの追跡:** トランザクションの実行履歴を詳細に追跡し、どの関数が実行されたか、どのイベントが発行されたかなどを確認できます。
*   **変数と状態の可視化:** コントラクトの変数や状態をリアルタイムに可視化し、バグの原因となっている変数の変化を特定できます。
*   **ステップ実行:** コードを一行ずつ実行し、変数の変化を詳細に観察できます。
*   **ブレークポイントの設定:** 特定の行で実行を一時停止し、その時点での変数や状態を確認できます。
*   **リモートデバッグ:** ローカル環境だけでなく、テストネットやメインネットにデプロイされたコントラクトをデバッグできます。

#### 13.3.3 事前準備と前提条件

*   **Remix:** Webブラウザがあればすぐに利用できます。
*   **Tenderly:** アカウント登録が必要です。

#### 13.3.4 基本的な使い方

**Remix:**

1.  **Remix IDE の起動:**

    [https://remix.ethereum.org/](https://remix.ethereum.org/) にアクセスします。

2.  **コントラクトの作成:**

    左側のサイドバーにある "File explorers" アイコンをクリックし、新しいファイルを作成します（例: `SimpleStorage.sol`）。

3.  **コントラクトの記述:**

    先ほどの `SimpleStorage.sol` をそのまま記述します。

4.  **コンパイル:**

    左側のサイドバーにある "Solidity compiler" アイコンをクリックし、コントラクトをコンパイルします。

5.  **デプロイと実行:**

    左側のサイドバーにある "Deploy & Run Transactions" アイコンをクリックし、コントラクトをデプロイします。デプロイ後、`set`関数や`get`関数を呼び出すことができます。

6.  **デバッグ:**

    トランザクションが完了すると、Remixの下部にトランザクションの詳細が表示されます。"Debug"ボタンをクリックすると、デバッガーが起動し、トランザクションの実行履歴や変数の状態を確認できます。

**Tenderly:**

1.  **Tenderly アカウントの作成:**

    [https://tenderly.co/](https://tenderly.co/) にアクセスし、アカウントを作成します。

2.  **プロジェクトの作成:**

    Tenderly ダッシュボードで、新しいプロジェクトを作成します。

3.  **コントラクトのアップロード:**

    プロジェクトにコントラクトをアップロードします。

4.  **トランザクションのインポート:**

    デバッグしたいトランザクションをインポートします。トランザクションハッシュを入力するか、Tenderly Web3 Provider を使用して、実行中のトランザクションを自動的にインポートできます。

5.  **デバッグ:**

    トランザクションの詳細ページで、トランザクションの実行履歴、変数の状態、ガス消費量などを確認できます。ステップ実行やブレークポイントの設定も可能です。

#### 13.3.5 実践的なテクニック

*   **ログの活用:** `console.log` を使用して、コントラクトの実行中に重要な変数の値を記録します。Remix や Tenderly などのデバッグツールでログを確認することで、より詳細なデバッグが可能です。
*   **カスタムエラーメッセージの利用:** `require` ステートメントでカスタムのエラーメッセージを指定することで、エラーが発生した場合に、より具体的な原因を特定できます。
*   **テストネットでのデバッグ:** メインネットでデバッグを行う前に、テストネットで十分にデバッグを行い、問題を解決しておくことが重要です。

#### 13.3.6 応用例とユースケース

*   **ガス消費量の最適化:** ガス消費量の多い関数を特定し、コードを最適化することで、ガス消費量を削減できます。
*   **セキュリティ脆弱性の特定:** コントラクトの脆弱性を悪用したトランザクションを分析し、脆弱性の根本原因を特定できます。
*   **スマートコントラクトの挙動の理解:** 複雑なスマートコントラクトの挙動を詳細に分析し、コントラクトの設計や実装を改善できます。

#### 13.3.7 トラブルシューティング

*   **Remix でトランザクションが実行できない場合:** ブラウザのキャッシュをクリアし、Remix を再起動します。MetaMask などのウォレットが正しく設定されているか確認します。
*   **Tenderly でトランザクションがインポートできない場合:** トランザクションハッシュが正しいか確認します。Tenderly Web3 Provider が正しく設定されているか確認します。
*   **デバッグ中にエラーが発生した場合:** エラーメッセージを注意深く確認し、コントラクトのロジックに誤りがないかを確認します。

#### 13.3.8 まとめと次のステップ

デバッグツールは、スマートコントラクトのバグを特定し、解決するための不可欠なツールです。Remix や Tenderly などのツールを活用し、効率的なデバッグを行い、スマートコントラクトの品質を高めましょう。次のステップとして、形式検証ツールについて学習し、スマートコントラクトの安全性をさらに向上させる方法を習得しましょう。
