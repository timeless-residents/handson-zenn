## 16. RPA とローコード/ノーコード開発：市民開発者の育成

### 16.1 ローコード/ノーコードプラットフォームの活用

#### 16.1.1 概要と重要性

RPA（Robotic Process Automation）が業務効率化に大きく貢献する一方で、その導入や運用には専門的な知識やスキルが必要となるケースが多く、IT 部門に負荷が集中しがちです。そこで注目されるのが、ローコード/ノーコード（LCNC）開発プラットフォームです。

LCNC プラットフォームは、プログラミングの知識が少ないビジネスユーザーでも、直感的なインターフェースを通じてアプリケーションや自動化プロセスを構築できるツールです。RPA と LCNC を組み合わせることで、現場の担当者が自ら業務の自動化を推進し、より迅速かつ柔軟な対応が可能になります。

このセクションでは、LCNC プラットフォームを活用した現場主導の自動化について、具体的な方法論や注意点などを解説します。

#### 16.1.2 特徴と利点

LCNC プラットフォームは、以下の様な特徴と利点を持っています。

- **開発期間の短縮:** ビジュアルなインターフェースと豊富なテンプレートを活用することで、従来の開発手法に比べて大幅に開発期間を短縮できます。
- **専門知識不要:** コーディングが不要、または最小限で済むため、IT 部門だけでなく、業務に精通した現場担当者が自ら自動化プロセスを構築できます。
- **変更への柔軟性:** ドラッグ＆ドロップ操作で容易にプロセスを修正できるため、ビジネス環境の変化に迅速に対応できます。
- **コスト削減:** 外部の IT ベンダーに頼らず、内製化を進めることで開発コストや運用コストを削減できます。
- **開発生産性の向上:** IT 部門のリソースをより高度なタスクに集中させ、組織全体の開発生産性を向上させます。

#### 16.1.3 事前準備と前提条件

LCNC プラットフォームを導入する前に、以下の点について検討しておく必要があります。

1.  **対象業務の選定:** 自動化に適した業務プロセスを特定します。定型的な繰り返し作業、データ入力、レポート作成などが適しています。
2.  **プラットフォームの選定:** 組織のニーズに合った LCNC プラットフォームを選定します。無料トライアル期間などを活用し、実際に触ってみることをお勧めします。
3.  **セキュリティ要件の確認:** 機密情報や個人情報を取り扱う場合は、プラットフォームのセキュリティ機能を十分に確認する必要があります。
4.  **データ連携の確認:** 既存システムとの連携が必要な場合は、プラットフォームの連携機能を確認します。API 連携やデータベース連携が可能かどうかを確認しましょう。
5.  **開発環境の準備:** LCNC プラットフォームをインストールし、開発に必要なアカウントを作成します。

#### 16.1.4 基本的な使い方

ここでは、例として、一般的な LCNC プラットフォーム（例えば Microsoft Power Automate）を使用した簡単な自動化フローの作成手順を説明します。

1.  **プラットフォームへのログイン:** LCNC プラットフォームにログインし、新しいフローを作成します。
2.  **トリガーの選択:** フローを開始するトリガーを選択します。例えば、「新しいメールが届いたとき」や「特定のスプレッドシートが更新されたとき」などが選択できます。
3.  **アクションの追加:** トリガーに続いて実行するアクションを追加します。例えば、「メールの内容を特定のフォルダに保存する」、「スプレッドシートのデータをデータベースに登録する」などが選択できます。
4.  **条件分岐の設定:** 必要に応じて、条件分岐を設定します。例えば、「メールの件名に特定のキーワードが含まれている場合にのみ、特定のアクションを実行する」といった条件を設定できます。
5.  **フローのテスト:** 作成したフローをテストし、正常に動作することを確認します。
6.  **フローの公開:** テストが完了したら、フローを公開し、実際に運用を開始します。

**具体的な例：メール添付ファイルの自動保存**

Power Automate を使用し、特定のメールアドレスから届いたメールの添付ファイルを、OneDrive の特定のフォルダに自動的に保存するフローを作成します。

```
#Power Automateフローの例
トリガー：新しいメールが届いたとき（Outlook 365）
    条件：送信者のメールアドレスが"example@example.com"である
        アクション：添付ファイルの保存（OneDrive for Business）
            ファイル名：メールの件名
            保存先フォルダ："指定のフォルダパス"
```

#### 16.1.5 実践的なテクニック

LCNC プラットフォームをより効果的に活用するための実践的なテクニックを紹介します。

- **変数と式の活用:** 変数や式を活用することで、より複雑な条件分岐やデータ処理を実現できます。例えば、日付の計算や文字列の操作などを行うことができます。
- **カスタムコネクタの作成:** 標準で提供されているコネクタ以外に、独自の API を呼び出すカスタムコネクタを作成することで、連携範囲を広げることができます。
- **エラーハンドリングの実装:** エラーが発生した場合の処理を実装することで、フローの安定性を高めることができます。例えば、エラーが発生した場合に、管理者に通知メールを送信するなどの処理を実装できます。
- **ログ出力の実装:** フローの実行状況を記録するログ出力を実装することで、問題発生時の原因究明を容易にすることができます。

**具体的な例：日付の計算**

例えば、締め切り日が毎月月末の場合、Power Automate で締め切り日を自動的に計算する式は次のようになります。

```
#Power Automateの式
addDays(startOfMonth(utcNow(),'yyyy-MM-dd'),-1)
```

この式は、現在月の月初から 1 日引くことで、前月の月末を計算します。

#### 16.1.6 応用例とユースケース

LCNC プラットフォームは、様々な業務に活用できます。以下に、具体的な応用例とユースケースを紹介します。

- **経費精算の自動化:** 経費申請書の情報を自動的に読み取り、承認ワークフローを開始する。
- **顧客管理システムのデータ連携:** 顧客情報を自動的に顧客管理システムに登録する。
- **在庫管理システムのデータ更新:** 在庫情報を自動的に在庫管理システムに更新する。
- **ソーシャルメディアのモニタリング:** 特定のキーワードを含む投稿を自動的に収集し、分析する。
- **ヘルプデスク業務の効率化:** 問い合わせ内容を自動的に分類し、適切な担当者に割り当てる。

**具体的なユースケース：請求書処理の自動化**

企業では、日々大量の請求書が届きます。これらの請求書を LCNC プラットフォームと OCR（Optical Character Recognition）技術を組み合わせることで、自動的に処理することができます。

1.  請求書がメールで届く
2.  Power Automate がメールを監視
3.  OCR 機能で請求書の内容を読み取り
4.  読み取ったデータを会計システムに入力
5.  承認ワークフローを開始

#### 16.1.7 トラブルシューティング

LCNC プラットフォームの利用中に発生する可能性のあるトラブルと、その解決策を紹介します。

- **フローが正常に動作しない:** フローの設定を見直し、トリガーやアクションが正しく設定されているかを確認します。
- **データ連携がうまくいかない:** API キーや接続情報が正しいかを確認します。また、API の仕様変更がないかを確認します。
- **エラーが発生した場合:** エラーメッセージを確認し、原因を特定します。必要に応じて、ログ出力を参照します。
- **パフォーマンスが低い:** フローの処理内容を見直し、不要な処理を削除します。また、トリガーの頻度を調整します。

#### 16.2.1 概要と重要性

RPA や LCNC の導入効果を最大化するためには、IT 部門だけでなく、現場の担当者（市民開発者）が自ら自動化を推進できる環境を整備することが重要です。市民開発者を育成することで、IT 部門の負担を軽減し、組織全体の開発生産性を向上させることができます。

このセクションでは、市民開発者を育成するためのトレーニングプログラムやサポート体制について解説します。

#### 16.2.2 特徴と利点

市民開発者の育成には、以下の様な特徴と利点があります。

- **現場ニーズへの迅速な対応:** 業務に精通した現場担当者が自ら自動化プロセスを構築するため、現場ニーズに迅速かつ柔軟に対応できます。
- **IT 部門の負担軽減:** IT 部門のリソースをより高度なタスクに集中させることができます。
- **イノベーションの促進:** 現場担当者のアイデアを具現化しやすくなり、組織全体のイノベーションを促進します。
- **従業員のスキルアップ:** LCNC プラットフォームの利用を通じて、従業員の IT スキルを向上させることができます。
- **ビジネスと IT の連携強化:** 市民開発者の育成を通じて、ビジネス部門と IT 部門の連携を強化することができます。

#### 16.2.3 事前準備と前提条件

5.  **評価指標の設定:** 市民開発者の育成効果を評価するための指標を設定します。例えば、自動化された業務プロセスの数や、削減された作業時間などを指標とすることができます。

- **バージョン管理の実施:** 自動化プロセスの変更履歴を管理します。

- セキュリティ：機密情報を取り扱う場合は、適切なセキュリティ対策を講じる。

### 16.3 ガバナンスとセキュリティの確保

#### 16.3.1 概要と重要性

RPA や LCNC の導入が拡大するにつれて、ガバナンスとセキュリティの重要性が増しています。適切なガバナンス体制が確立されていない場合、野良ロボットやシャドー IT が発生し、セキュリティリスクや運用コストの増加につながる可能性があります。

このセクションでは、RPA と LCNC の導入におけるガバナンスとセキュリティの確保について、具体的な対策を解説します。

#### 16.3.2 特徴と利点

適切なガバナンスとセキュリティ体制を構築することで、以下の様な特徴と利点があります。

- **セキュリティリスクの軽減:** 不正アクセスや情報漏洩のリスクを軽減できます。
- **コンプライアンスの遵守:** 法規制や内部規定を遵守できます。
- **運用コストの削減:** 野良ロボットやシャドー IT を防止し、運用コストを削減できます。
- **自動化プロセスの品質向上:** 自動化プロセスの品質を維持し、安定的な運用を実現できます。
- **監査対応の円滑化:** 監査対応を円滑に進めることができます。

#### 16.3.3 事前準備と前提条件

ガバナンスとセキュリティ体制を構築する前に、以下の点について検討しておく必要があります。

1.  **リスクアセスメントの実施:** RPA や LCNC の導入に伴うリスクを洗い出し、リスクレベルを評価します。
2.  **ポリシーと手順の策定:** セキュリティポリシー、開発ガイドライン、運用手順などを策定します。
3.  **役割と責任の明確化:** ガバナンス体制における各役割の責任を明確にします。
4.  **アクセス制御の強化:** 自動化プロセスやデータに対するアクセス制御を強化します。
5.  **監視体制の構築:** 自動化プロセスの実行状況を監視し、異常を検知するための体制を構築します。

#### 16.3.4 ガバナンス体制の構築

RPA と LCNC のガバナンス体制は、以下の要素で構成されます。

1.  **組織構造:** ガバナンスを統括する組織を設置します。例えば、RPA 推進室や自動化センターなどを設置します。
2.  **役割と責任:** 各役割の責任を明確にします。例えば、RPA アーキテクト、RPA 開発者、RPA 運用担当者、情報セキュリティ担当者などの役割を定義します。
3.  **ポリシーと手順:** セキュリティポリシー、開発ガイドライン、運用手順などを策定します。
4.  **プロセス:** 自動化プロセスのライフサイクル全体（計画、設計、開発、テスト、運用、保守）を管理するプロセスを定義します。
5.  **ツール:** 自動化プロセスを管理するためのツールを導入します。例えば、RPA 管理ツール、バージョン管理ツール、セキュリティ監視ツールなどを導入します。

**ガバナンス体制の例**

- **RPA 推進室:** RPA 戦略の策定、ガバナンス体制の構築、市民開発者の育成などを担当します。
- **RPA アーキテクト:** 自動化プロセスの設計、標準化、技術支援などを担当します。
- **RPA 開発者:** 自動化プロセスの開発、テストなどを担当します。
- **RPA 運用担当者:** 自動化プロセスの運用、監視、保守などを担当します。
- **情報セキュリティ担当者:** セキュリティポリシーの策定、セキュリティ対策の実施などを担当します。

#### 16.3.5 セキュリティ対策

RPA と LCNC のセキュリティ対策は、以下の様な要素で構成されます。

1.  **認証と認可:** 自動化プロセスやデータに対するアクセス制御を強化します。多要素認証の導入、最小権限の原則の適用、ロールベースアクセス制御などが有効です。
2.  **データの暗号化:** 機密情報や個人情報を取り扱う場合は、データの暗号化を実施します。
3.  **脆弱性対策:** LCNC プラットフォームや RPA ツールに存在する脆弱性を特定し、対策を実施します。
4.  **インシデント管理:** セキュリティインシデントが発生した場合の対応手順を整備します。
5.  **監査ログの記録:** 自動化プロセスの実行状況を記録し、監査に備えます。

**具体的なセキュリティ対策**

- パスワードポリシー：強力なパスワードの設定を義務付け、定期的なパスワード変更を推奨する。
- 多要素認証：LCNC プラットフォームへのログインに多要素認証を導入する。
- アクセス制御：自動化プロセスやデータに対するアクセス権を最小限に絞る。
- データ暗号化：機密データや個人情報を暗号化して保存する。
- 脆弱性スキャン：定期的に LCNC プラットフォームの脆弱性スキャンを実施する。
- 監査ログ：自動化プロセスの実行履歴を記録し、不正アクセスを検知する。

#### 16.3.6 監視体制の構築

自動化プロセスの実行状況を監視し、異常を検知するための体制を構築します。

- **ログ監視:** 自動化プロセスのログを監視し、エラーや異常な動作を検知します。
- **パフォーマンス監視:** 自動化プロセスのパフォーマンスを監視し、ボトルネックを特定します。
- **セキュリティ監視:** セキュリティインシデントを検知するための監視システムを導入します。
- **アラート:** 異常を検知した場合に、関係者に自動的に通知するアラートを設定します。

#### 16.3.7 監査対応

自動化プロセスが法令や内部規定を遵守していることを確認するために、定期的な監査を実施します。

- **監査計画の策定:** 監査の目的、範囲、スケジュールなどを定めた監査計画を策定します。
- **監査証拠の収集:** 自動化プロセスの設計書、開発ドキュメント、テスト結果、運用ログなどを収集します。
- **監査の実施:** 収集した証拠に基づいて、自動化プロセスが法令や内部規定を遵守しているかを確認します。
- **監査報告書の作成:** 監査結果をまとめた監査報告書を作成します。
- **改善計画の策定:** 監査で指摘された問題点を改善するための計画を策定します。
