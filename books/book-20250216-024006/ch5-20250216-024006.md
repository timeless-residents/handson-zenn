## 第5章：データ変換とマッピング

### 5.1 データ形式の変換：JSON, XML, CSV, Protocol Buffers

#### 5.1.1 概要と重要性

データ変換は、異なるシステム間でデータをやり取りする際に不可欠なプロセスです。システムごとにデータの表現形式が異なるため、互換性を保つためには適切な形式に変換する必要があります。この章では、Web APIで一般的なJSON、レガシーシステムでよく利用されるXML、データ分析で利用されるCSV、そしてgRPCで利用されるProtocol Buffersといった主要なデータ形式の変換について解説します。

#### 5.1.2 特徴と利点

*   **JSON (JavaScript Object Notation):** 軽量で人間にも読みやすく、Web APIの標準的な形式として広く利用されています。
*   **XML (eXtensible Markup Language):** 構造化されたデータを表現するのに適しており、柔軟なデータ構造を定義できます。
*   **CSV (Comma Separated Values):** シンプルなテキスト形式で、表形式のデータを効率的に表現できます。
*   **Protocol Buffers:** Googleが開発したバイナリ形式で、効率的なデータシリアライズとデシリアライズが可能です。gRPCなどのパフォーマンスが重要な場面で利用されます。

#### 5.1.3 事前準備と前提条件

このセクションでは、各データ形式を扱うために必要なツールやライブラリについて説明します。

*   **JSON:** 多くのプログラミング言語に標準ライブラリが用意されています。Pythonであれば`json`モジュール、JavaScriptであれば`JSON.parse()`や`JSON.stringify()`を使用します。
*   **XML:** Pythonでは`xml.etree.ElementTree`、Javaでは`javax.xml.parsers`といったライブラリを使用します。
*   **CSV:** Pythonでは`csv`モジュール、Javaでは`org.apache.commons.csv`を使用します。
*   **Protocol Buffers:** `protoc`コンパイラと、各言語に対応したProtocol Buffersライブラリが必要です。

#### 5.1.4 基本的な使い方

各データ形式の基本的な使い方をコード例とともに示します。

**JSONの例（Python）:**

```python
import json

data = {
    "name": "Taro Yamada",
    "age": 30,
    "city": "Tokyo"
}

# JSONへのエンコード
json_data = json.dumps(data)
print(json_data)

# JSONからのデコード
decoded_data = json.loads(json_data)
print(decoded_data["name"])
```

**XMLの例（Python）:**

```python
import xml.etree.ElementTree as ET

root = ET.Element("root")
person = ET.SubElement(root, "person")
name = ET.SubElement(person, "name")
name.text = "Hanako Tanaka"
age = ET.SubElement(person, "age")
age.text = "25"

tree = ET.ElementTree(root)
ET.dump(root) # XMLを出力
```

**CSVの例（Python）:**

```python
import csv

data = [
    ["Name", "Age", "City"],
    ["Ken Sato", "40", "Osaka"],
    ["Yumi Suzuki", "28", "Kyoto"]
]

with open("data.csv", "w", newline="") as csvfile:
    writer = csv.writer(csvfile)
    writer.writerows(data)
```

**Protocol Buffersの例（Python）：**

まず、`.proto`ファイルを定義します。（例：`person.proto`）

```protobuf
syntax = "proto3";

message Person {
  string name = 1;
  int32 id = 2;
  string email = 3;
}
```

次に、`protoc`コンパイラでPythonコードを生成します。

```bash
protoc --python_out=. person.proto
```

生成された`person_pb2.py`を使って、Protocol Buffersのメッセージを作成します。

```python
import person_pb2

person = person_pb2.Person()
person.name = "Jiro Nakamura"
person.id = 123
person.email = "jiro@example.com"

# シリアライズ
serialized_data = person.SerializeToString()

# デシリアライズ
new_person = person_pb2.Person()
new_person.ParseFromString(serialized_data)

print(new_person.name)
```

#### 5.1.5 実践的なテクニック

*   **JSON:** `json.dumps()`の`indent`パラメータで、JSONを整形して見やすくすることができます。
*   **XML:** `xml.etree.ElementTree`でXMLを扱う場合、XPathを使って特定の要素を効率的に検索できます。
*   **CSV:** `csv.DictReader`や`csv.DictWriter`を使うと、ヘッダー行を利用して辞書形式でデータを読み書きできます。
*   **Protocol Buffers:** 大量のデータを扱う場合は、gzip圧縮などを組み合わせてデータサイズを削減することを検討してください。

#### 5.1.6 応用例とユースケース

*   **Web API:** JSON形式でAPIリクエストとレスポンスを処理する。
*   **設定ファイル:** XMLやJSON形式でアプリケーションの設定を記述する。
*   **データ分析:** CSV形式でデータをエクスポートし、分析ツールで処理する。
*   **マイクロサービス:** Protocol BuffersとgRPCを使って、サービス間の通信を効率化する。
*   **レガシーシステム連携:** レガシーシステムからXML形式でデータを受け取り、JSON形式に変換して新しいシステムに連携する。

#### 5.1.7 トラブルシューティング

*   **JSON:** エンコード/デコード時にUnicodeEncodeErrorが発生する場合は、`ensure_ascii=False`を指定します。
*   **XML:** XMLの構造が複雑な場合、XPathの記述が難しくなることがあります。
*   **CSV:** CSVファイルに改行文字が含まれている場合、正しく読み込めないことがあります。`newline=''`を指定して回避します。
*   **Protocol Buffers:** `.proto`ファイルの定義と、生成されたコードのバージョンが一致しない場合、エラーが発生することがあります。

### 5.2 データマッピング：フィールド変換、データ整形

#### 5.2.1 概要と重要性

データマッピングとは、あるデータソースのデータを別のデータソースの構造や形式に合わせて変換するプロセスのことです。異なるシステム間でデータを統合したり、データを特定の要件に合わせて整形したりする際に不可欠です。フィールド名の変更、データ型の変換、値の変換などが含まれます。

#### 5.2.2 特徴と利点

*   **データ統合:** 異なるシステムからのデータを統一された形式で利用できるようになります。
*   **データ品質向上:** データのエラーを修正したり、欠損値を補完したりすることで、データの品質を向上させることができます。
*   **ビジネスロジックの適用:** データの変換時にビジネスルールを適用することで、データの整合性を保つことができます。
*   **柔軟性:** データソースの変更に柔軟に対応できます。

#### 5.2.3 事前準備と前提条件

*   **データソースの理解:** データソースの構造、データ型、データの意味を理解する必要があります。
*   **ターゲットの定義:** 変換後のデータ構造、データ型、データの形式を定義する必要があります。
*   **データマッピングツールの選択:** 適切なデータマッピングツールまたはライブラリを選択する必要があります。

#### 5.2.4 基本的な使い方

**データマッピングツールの活用:**

様々なデータマッピングツールが存在します。オープンソースのものはもちろん、商用ツールも多数存在します。ここでは、Pythonの`pandas`ライブラリを使った簡単なデータマッピングの例を示します。

```python
import pandas as pd

# データフレームの作成
data = {
    'old_name': ['Alice', 'Bob', 'Charlie'],
    'old_age': [25, 30, 35]
}
df = pd.DataFrame(data)

# フィールド名の変更
df = df.rename(columns={'old_name': 'name', 'old_age': 'age'})

# データ型の変換
df['age'] = df['age'].astype(str)

print(df)
```

**カスタムスクリプトによるデータ変換:**

より複雑な変換が必要な場合は、カスタムスクリプトを使用します。

```python
def transform_data(data):
    transformed_data = []
    for item in data:
        new_item = {
            'full_name': item['first_name'] + ' ' + item['last_name'],
            'age_in_months': item['age'] * 12
        }
        transformed_data.append(new_item)
    return transformed_data

data = [
    {'first_name': 'Alice', 'last_name': 'Smith', 'age': 25},
    {'first_name': 'Bob', 'last_name': 'Johnson', 'age': 30}
]

transformed_data = transform_data(data)
print(transformed_data)
```

*   **変換ルールの明確化:** 変換ルールを明確に定義し、ドキュメント化します。
*   **テストデータの作成:** 変換処理を検証するためのテストデータを作成します。

### 5.3 データ検証：スキーマバリデーション、カスタムバリデーション

#### 5.3.1 概要と重要性

データ検証は、データが期待される形式と内容を持っていることを確認するプロセスです。データの整合性を保ち、エラーを早期に発見するために不可欠です。スキーマバリデーションとカスタムバリデーションの2つの主要なアプローチがあります。

#### 5.3.2 特徴と利点

*   **データ品質の向上:** 無効なデータを排除し、データ品質を向上させます。
*   **エラーの早期発見:** データ処理の初期段階でエラーを発見し、後続の処理への影響を軽減します。
*   **システムの安定性:** 無効なデータによるシステムのクラッシュや誤動作を防ぎます。
*   **セキュリティの強化:** 悪意のあるデータによるセキュリティリスクを軽減します。

#### 5.3.3 事前準備と前提条件

*   **データ形式の理解:** 検証対象のデータ形式（JSON, XML, CSVなど）を理解する必要があります。
*   **スキーマの定義:** スキーマバリデーションを行う場合は、スキーマを定義する必要があります。
*   **検証ルールの定義:** カスタムバリデーションを行う場合は、検証ルールを定義する必要があります。
*   **検証ツールの選択:** 適切な検証ツールまたはライブラリを選択する必要があります。

#### 5.3.4 基本的な使い方

**スキーマバリデーション：JSON Schema**

JSON Schemaは、JSONデータの構造を記述するための標準的な形式です。Pythonの`jsonschema`ライブラリを使ってJSON Schemaバリデーションを行う例を示します。

```python
import jsonschema
from jsonschema import validate

# JSON Schemaの定義
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer", "minimum": 0},
        "city": {"type": "string"}
    },
    "required": ["name", "age"]
}

# 検証対象のJSONデータ
data = {
    "name": "Alice",
    "age": 30,
    "city": "New York"
}

# バリデーションの実行
try:
    validate(instance=data, schema=schema)
    print("Valid JSON")
except jsonschema.exceptions.ValidationError as e:
    print("Invalid JSON:", e)
```

**スキーマバリデーション：XML Schema**

XML Schemaは、XMLデータの構造を記述するための標準的な形式です。Pythonの`lxml`ライブラリを使ってXML Schemaバリデーションを行う例を示します。

```python
from lxml import etree

# XML Schemaの読み込み
xmlschema_doc = etree.parse("schema.xsd") # schema.xsdはXML Schemaファイル
xmlschema = etree.XMLSchema(xmlschema_doc)

# 検証対象のXMLデータの読み込み
xml_doc = etree.parse("data.xml") # data.xmlはXMLデータファイル

# バリデーションの実行
try:
    xmlschema.assertValid(xml_doc)
    print("Valid XML")
except etree.DocumentInvalid as e:
    print("Invalid XML:", e)
```

**カスタムバリデーション:**

ビジネスロジックに基づいたカスタムバリデーションを行う例を示します。

```python
def validate_data(data):
    errors = []
    if not isinstance(data['age'], int):
        errors.append("Age must be an integer")
    if data['age'] < 0:
        errors.append("Age must be non-negative")
    if not data['email'].endswith("@example.com"):
        errors.append("Email must end with @example.com")
    return errors

data = {
    "name": "Bob",
    "age": -5,
    "email": "bob@invalid.com"
}

errors = validate_data(data)
if errors:
    print("Validation errors:", errors)
else:
    print("Data is valid")
```
