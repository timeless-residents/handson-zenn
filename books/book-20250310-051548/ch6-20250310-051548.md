## 第6章：Elasticsearchクエリ徹底解説：検索パフォーマンスを最大化するクエリ設計

この章では、Elasticsearchの心臓部とも言えるクエリDSL（Domain Specific Language）を徹底的に解説します。Elasticsearchのクエリは、シンプルなキーワード検索から、複雑なデータ分析まで、あらゆる検索ニーズに対応できる柔軟性を持っています。しかし、その柔軟性ゆえに、適切なクエリ設計はパフォーマンスに大きな影響を与えます。

本章では、ElasticsearchのクエリDSLの基本から応用までを網羅し、検索パフォーマンスを最大化するためのクエリ設計を習得することを目指します。初心者の方にも理解しやすいように段階的に説明し、実務で役立つ具体的なユースケースを交えながら解説します。

### 6.1 ElasticsearchクエリDSLの基本：Match Query、Term Query、Range Query

#### 6.1.1 概要と重要性

ElasticsearchのクエリDSLは、JSON形式で記述され、Elasticsearchにどのようなデータを検索してほしいかを指示します。その中でも`Match Query`、`Term Query`、`Range Query`は、最も基本的なクエリであり、これらを理解することは、複雑なクエリを構築するための基礎となります。

*   **Match Query:** テキストに対して全文検索を行うためのクエリです。Elasticsearchは、インデックス時にテキストを解析し、トークンと呼ばれる単語の集合に分割します。Match Queryは、このトークンと一致するドキュメントを検索します。
*   **Term Query:** 特定のフィールドに対して、指定された値と完全に一致するドキュメントを検索するためのクエリです。全文検索とは異なり、解析は行われません。
*   **Range Query:** 数値型や日付型のフィールドに対して、指定された範囲内の値を持つドキュメントを検索するためのクエリです。

これらのクエリを使いこなすことで、シンプルな検索から高度な絞り込みまで、様々な検索ニーズに対応できます。

#### 6.1.2 特徴と利点

*   **Match Query:**
    *   **利点:** 自然言語による検索が可能。あいまい検索、フレーズ検索など、様々なオプションが利用可能。
    *   **注意点:** テキストフィールドに対してのみ有効。パフォーマンスは、インデックスのサイズや解析設定に依存。
*   **Term Query:**
    *   **利点:** 正確な値による検索が可能。パフォーマンスが高い。
    *   **注意点:** 大文字小文字の区別、全角半角の区別がある。テキストフィールドに対して使用する場合は、`keyword`フィールドを使用する必要がある。
*   **Range Query:**
    *   **利点:** 数値や日付の範囲指定が可能。
    *   **注意点:** 不等号(`gt`, `gte`, `lt`, `lte`)の指定を間違えないこと。

#### 6.1.3 事前準備と前提条件

Elasticsearchがインストールされ、基本的な操作ができることが前提となります。また、サンプルデータとして、以下のような書籍情報を格納した`books`インデックスを作成します。

POST /books/_bulk

#### 6.1.4 基本的な使い方

**Match Queryの例：**

```json
GET /books/_search
{
  "query": {
    "match": {
      "title": "Elasticsearch"
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch"という単語が含まれるドキュメントを検索します。

**Term Queryの例：**

```json
GET /books/_search
{
  "query": {
    "term": {
      "author": "John Doe"
    }
  }
}
```

このクエリは、`author`フィールドが"John Doe"と完全に一致するドキュメントを検索します。

**Range Queryの例：**

```json
GET /books/_search
{
  "query": {
    "range": {
      "price": {
        "gte": 3500,
        "lte": 4000
      }
    }
  }
}
```

このクエリは、`price`フィールドが3500以上4000以下のドキュメントを検索します。

#### 6.1.5 実践的なテクニック

*   **Match Queryのフレーズ検索:**

```json
GET /books/_search
{
  "query": {
    "match_phrase": {
      "title": "Elasticsearch実践"
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch実践"というフレーズが含まれるドキュメントを検索します。

*   **Term Queryでの複数条件指定:**

Term Queryでは、`terms`を使用することで、複数の条件を指定できます。

```json
GET /books/_search
{
  "query": {
    "terms": {
      "author": ["John Doe", "Jane Smith"]
    }
  }
}
```

このクエリは、`author`フィールドが"John Doe"または"Jane Smith"であるドキュメントを検索します。

*   **Range Queryでの日付範囲指定:**

```json
GET /books/_search
{
  "query": {
    "range": {
      "publication_date": {
        "gte": "2023-01-01",
        "lte": "2023-03-31"
      }
    }
  }
}
```

このクエリは、`publication_date`フィールドが2023年1月1日から2023年3月31日までのドキュメントを検索します。

#### 6.1.6 応用例とユースケース

*   **ECサイトでの商品検索:**  `Match Query`で商品名やキーワードを検索し、`Range Query`で価格帯を絞り込む。
*   **ログ分析:**  `Term Query`で特定のログレベル（ERROR, WARN, INFO）を検索し、`Range Query`で時間範囲を絞り込む。
*   **ドキュメント検索:**  `Match Query`でドキュメントのコンテンツを検索し、`Term Query`で作成者や更新日を絞り込む。

#### 6.1.7 トラブルシューティング

*   **Match Queryで検索結果が意図しないものになる:** インデックスの解析設定を確認し、トークナイザーやフィルターが適切に設定されているか確認する。
*   **Term Queryで検索結果が0件になる:** 大文字小文字、全角半角の区別、空白などに注意し、検索条件が完全に一致しているか確認する。`keyword`フィールドを使用しているか確認する。
*   **Range Queryで期待する範囲外の結果が返ってくる:** 不等号(`gt`, `gte`, `lt`, `lte`)の指定が正しいか確認する。日付型の場合は、フォーマットが一致しているか確認する。

#### 6.1.8 まとめと次のステップ

このセクションでは、Elasticsearchの基本的なクエリである`Match Query`、`Term Query`、`Range Query`について解説しました。これらのクエリを理解することで、Elasticsearchを使った検索の基礎を習得できます。

次のセクションでは、これらのクエリを組み合わせて、より複雑な検索を行うための`Boolean Query`と`Boosting Query`について解説します。

### 6.2 複合クエリ：Boolean Query、Boosting Query

#### 6.2.1 概要と重要性

`Boolean Query`と`Boosting Query`は、複数のクエリを組み合わせて、より複雑な検索条件を表現するためのクエリです。`Boolean Query`は、`AND`、`OR`、`NOT`などの論理演算子を使ってクエリを組み合わせ、`Boosting Query`は、特定のクエリの結果に重み付けをして、関連性の高いドキュメントを上位に表示することができます。

これらのクエリを使いこなすことで、より高度な検索ニーズに対応し、ユーザーエクスペリエンスを向上させることができます。

#### 6.2.2 特徴と利点

*   **Boolean Query:**
    *   **利点:** 複数の条件を自由に組み合わせることが可能。柔軟な検索ロジックを構築できる。
    *   **注意点:** 複雑な条件を記述すると、パフォーマンスが低下する可能性がある。
*   **Boosting Query:**
    *   **利点:** 特定の条件を満たすドキュメントの関連性を高めることができる。検索結果のランキングを調整できる。
    *   **注意点:** 重み付けの値を適切に設定する必要がある。

#### 6.2.3 事前準備と前提条件

前セクションと同様に、Elasticsearchがインストールされ、基本的な操作ができることが前提となります。また、前セクションで作成した`books`インデックスを使用します。

#### 6.2.4 基本的な使い方

**Boolean Queryの例：**

```json
GET /books/_search
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "Elasticsearch" } },
        { "term": { "author": "John Doe" } }
      ]
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch"が含まれ、かつ`author`フィールドが"John Doe"と完全に一致するドキュメントを検索します。`must`は、すべての条件を満たす必要があることを意味します（`AND`条件）。

```json
GET /books/_search
{
  "query": {
    "bool": {
      "should": [
        { "match": { "title": "Elasticsearch" } },
        { "match": { "title": "Kafka" } }
      ],
      "minimum_should_match": 1
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch"または"Kafka"が含まれるドキュメントを検索します。`should`は、いずれかの条件を満たせばよいことを意味します（`OR`条件）。`minimum_should_match`は、`should`句の条件のうち、最低いくつを満たす必要があるかを指定します。

```json
GET /books/_search
{
  "query": {
    "bool": {
      "must_not": [
        { "term": { "author": "John Doe" } }
      ]
    }
  }
}
```

このクエリは、`author`フィールドが"John Doe"と完全に一致しないドキュメントを検索します。`must_not`は、指定された条件を満たさない必要があることを意味します（`NOT`条件）。

**Boosting Queryの例：**

```json
GET /books/_search
{
  "query": {
    "boosting": {
      "positive": {
        "match": {
          "title": "Elasticsearch"
        }
      },
      "negative": {
        "match": {
          "author": "John Doe"
        }
      },
      "negative_boost": 0.2
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch"が含まれるドキュメントを検索し、`author`フィールドが"John Doe"であるドキュメントの関連性を`0.2`倍に減らします。`positive`は、検索対象となるメインのクエリを、`negative`は、関連性を減らすクエリを、`negative_boost`は、関連性を減らす割合を指定します。

#### 6.2.5 実践的なテクニック

*   **Boolean Queryでのフィルター:**

`filter`句を使用すると、検索結果に影響を与えずに、ドキュメントを絞り込むことができます。`filter`句は、スコアリングに影響を与えないため、パフォーマンスが高いという特徴があります。

```json
GET /books/_search
{
  "query": {
    "bool": {
      "must": {
        "match": {
          "title": "Elasticsearch"
        }
      },
      "filter": {
        "range": {
          "price": {
            "gte": 3000
          }
        }
      }
    }
  }
}
```

このクエリは、`title`フィールドに"Elasticsearch"が含まれ、かつ`price`フィールドが3000以上のドキュメントを検索します。

*   **Boosting Queryでの関連性調整:**

`negative_boost`の値を調整することで、検索結果のランキングを細かく制御できます。値を大きくすると、`negative`句に一致するドキュメントの関連性が大きく下がり、値を小さくすると、関連性の下がり幅が小さくなります。

#### 6.2.6 応用例とユースケース

*   **ECサイトでの高度な商品検索:** `Boolean Query`で複数のキーワード検索を行い、`Boosting Query`で特定のブランドやカテゴリの商品を優先的に表示する。
*   **ブログ記事の検索:** `Boolean Query`で記事のタイトルと本文を検索し、`Boosting Query`で最新の記事を優先的に表示する。
*   **社内ドキュメント検索:** `Boolean Query`でキーワード検索を行い、`Boosting Query`で自分の部署のドキュメントを優先的に表示する。

#### 6.2.7 トラブルシューティング

*   **Boolean Queryで検索結果が意図しないものになる:** `must`、`should`、`must_not`句の組み合わせが正しいか確認する。`minimum_should_match`の値が適切か確認する。
*   **Boosting Queryで関連性の調整がうまくいかない:** `negative_boost`の値を調整する。`positive`句と`negative`句のクエリが適切か確認する。

#### 6.2.8 まとめと次のステップ

このセクションでは、複数のクエリを組み合わせて、より複雑な検索条件を表現するための`Boolean Query`と`Boosting Query`について解説しました。これらのクエリを使いこなすことで、高度な検索ニーズに対応し、ユーザーエクスペリエンスを向上させることができます。

次のセクションでは、集計処理を行うための`Aggregations`について解説します。

### 6.3 集計処理：Aggregationsによるデータ分析

#### 6.3.1 概要と重要性

Elasticsearchの`Aggregations`は、検索結果に基づいてデータの集計、分析を行うための機能です。`Aggregations`を使用することで、平均値、最大値、最小値、件数などの基本的な統計情報を取得したり、特定のフィールドの値ごとの件数を集計したり、ヒストグラムを作成したりすることができます。

`Aggregations`は、データの可視化、傾向分析、異常検知など、様々な用途に活用できます。

#### 6.3.2 特徴と利点

*   **柔軟性:** 様々な種類の集計処理に対応しており、複雑なデータ分析も可能。
*   **リアルタイム性:** 検索と同時に集計処理を行うため、リアルタイムなデータ分析が可能。
*   **パフォーマンス:** 大量のデータに対しても、効率的な集計処理が可能。

#### 6.3.3 事前準備と前提条件

前セクションと同様に、Elasticsearchがインストールされ、基本的な操作ができることが前提となります。また、前セクションで作成した`books`インデックスを使用します。

#### 6.3.4 基本的な使い方

**Metrics Aggregationの例：**

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "average_price": {
      "avg": {
        "field": "price"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の価格の平均値を計算します。`size: 0`を指定することで、検索結果は返さず、集計結果のみを取得できます。`avg`は、平均値を計算する集計タイプを指定します。

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "max_price": {
      "max": {
        "field": "price"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の価格の最大値を計算します。`max`は、最大値を計算する集計タイプを指定します。

**Bucket Aggregationの例：**

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "authors": {
      "terms": {
        "field": "author"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の著者ごとの件数を集計します。`terms`は、特定のフィールドの値ごとの件数を集計する集計タイプを指定します。

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "price_ranges": {
      "range": {
        "field": "price",
        "ranges": [
          { "to": 3500 },
          { "from": 3500, "to": 4000 },
          { "from": 4000 }
        ]
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の価格を、3500円未満、3500円以上4000円未満、4000円以上の3つの範囲に分割し、それぞれの範囲に含まれる書籍の件数を集計します。`range`は、指定された範囲ごとの件数を集計する集計タイプを指定します。

#### 6.3.5 実践的なテクニック

*   **Nested Aggregation:**

`Aggregations`の中に`Aggregations`をネストすることで、より複雑な集計処理を行うことができます。

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "authors": {
      "terms": {
        "field": "author"
      },
      "aggs": {
        "average_price": {
          "avg": {
            "field": "price"
          }
        }
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の著者ごとの件数を集計し、さらに著者ごとに書籍の価格の平均値を計算します。

*   **Date Histogram Aggregation:**

日付型のフィールドに対して、指定された間隔でヒストグラムを作成することができます。

```json
GET /books/_search
{
  "size": 0,
  "aggs": {
    "publications_over_time": {
      "date_histogram": {
        "field": "publication_date",
        "calendar_interval": "month",
        "format": "yyyy-MM"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の出版日を月ごとに集計し、ヒストグラムを作成します。

#### 6.3.6 応用例とユースケース

*   **ECサイトでの売上分析:**  商品カテゴリごとの売上金額、時間帯ごとの売上件数などを集計し、売上傾向を分析する。
*   **ログ分析:**  ログレベルごとの件数、エラー発生時間帯などを集計し、システムの状態を監視する。
*   **Webサイトのアクセス解析:**  アクセス元、アクセス時間帯、ページビュー数などを集計し、Webサイトの利用状況を分析する。

#### 6.3.7 トラブルシューティング

*   **Aggregationsの結果が意図しないものになる:**  集計対象のフィールドのデータ型が正しいか確認する。集計タイプが適切か確認する。
*   **Aggregationsのパフォーマンスが悪い:**  集計対象のデータ量を減らす。Nested Aggregationの使用を避ける。

#### 6.3.8 まとめと次のステップ

このセクションでは、Elasticsearchの`Aggregations`について解説しました。`Aggregations`を使用することで、検索結果に基づいてデータの集計、分析を行うことができます。

次のセクションでは、`Groovy Script`と`Painless Script`を使ったスクリプトクエリについて解説します。

### 6.4 スクリプトクエリ：Groovy Script、Painless Script

#### 6.4.1 概要と重要性

Elasticsearchのスクリプトクエリは、ElasticsearchのクエリDSLでは表現できない複雑なロジックを、スクリプト言語を用いて記述するための機能です。`Groovy Script`と`Painless Script`は、Elasticsearchで利用できるスクリプト言語であり、ドキュメントのフィールドの値に基づいて複雑な計算を行ったり、条件分岐を行ったりすることができます。

スクリプトクエリは、高度な検索ニーズに対応するために不可欠な機能です。

#### 6.4.2 特徴と利点

*   **柔軟性:**  ElasticsearchのクエリDSLでは表現できない複雑なロジックを記述できる。
*   **拡張性:**  Elasticsearchの機能を拡張できる。

#### 6.4.3 事前準備と前提条件

Elasticsearchの設定ファイル (`elasticsearch.yml`) を編集し、スクリプトの実行を許可する必要があります。ただし、`Groovy Script`はセキュリティ上の理由からデフォルトで無効化されています。`Painless Script`はデフォルトで有効化されています。

**重要:** `Groovy Script`の利用は非推奨です。代わりに、セキュリティとパフォーマンスに優れた`Painless Script`を使用することを強く推奨します。

**elasticsearch.ymlの設定例：**

```yaml
script.engine.painless.inline.update: true
script.engine.painless.inline.search: true
```

この設定は、`Painless Script`のインラインでの更新と検索を許可します。

また、前セクションと同様に、Elasticsearchがインストールされ、基本的な操作ができることが前提となります。また、前セクションで作成した`books`インデックスを使用します。

#### 6.4.4 基本的な使い方

**Painless Scriptの例：**

```json
GET /books/_search
{
  "query": {
    "script": {
      "script": {
        "source": "doc['price'].value * 1.1",
        "lang": "painless"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の価格に1.1をかけた値を計算します。`script`は、スクリプトクエリを指定します。`source`は、スクリプトのソースコードを指定します。`lang`は、スクリプト言語を指定します。

```json
GET /books/_search
{
  "query": {
    "script": {
      "script": {
        "source": "doc['publication_date'].value.getYear() == 2023",
        "lang": "painless"
      }
    }
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の出版年が2023年であるかどうかを判定します。

#### 6.4.5 実践的なテクニック

*   **Script Fields:**

スクリプトを使って、ドキュメントに存在しないフィールドを計算し、検索結果に含めることができます。

```json
GET /books/_search
{
  "script_fields": {
    "discounted_price": {
      "script": {
        "source": "doc['price'].value * (1 - params.discount)",
        "lang": "painless",
        "params": {
          "discount": 0.2
        }
      }
    }
  }
  ,
  "query": {
    "match_all": {}
  }
}
```

このクエリは、`books`インデックスに格納されている書籍の価格から20%割引した値を計算し、`discounted_price`というフィールドとして検索結果に含めます。`script_fields`は、スクリプトを使って計算されたフィールドを指定します。`params`は、スクリプトに渡すパラメータを指定します。`match_all`クエリは、すべてのドキュメントを検索します。

*   **Update APIでのスクリプトの使用:**

スクリプトを使って、ドキュメントのフィールドの値を更新することができます。

```json
POST /books/_update/1
{
  "script": {
    "source": "ctx._source.price = params.new_price",
    "lang": "painless",
    "params": {
      "new_price": 4000
    }
  }
}
```

このリクエストは、`books`インデックスのIDが1のドキュメントの`price`フィールドの値を4000に更新します。`ctx._source`は、ドキュメントのソースコードを表します。

#### 6.4.6 応用例とユースケース

*   **動的なランキング:** ユーザーの行動履歴や属性に基づいて、検索結果のランキングを動的に調整する。
*   **不正検知:** 特定の条件を満たすトランザクションを検知する。
*   **データの変換と加工:** ドキュメントのフィールドの値を変換したり、加工したりする。

#### 6.4.7 トラブルシューティング

*   **スクリプトの実行に失敗する:**  スクリプトの構文が正しいか確認する。スクリプトの実行に必要な権限があるか確認する。
*   **スクリプトのパフォーマンスが悪い:**  スクリプトの処理内容を最適化する。キャッシュを利用する。
