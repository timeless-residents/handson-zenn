## 第2章：環境構築：5分で始めるEES - 最小構成から始める高速セットアップ

Elasticsearch Service (EES) を利用することで、Elasticsearch の環境構築にかかる時間と手間を大幅に削減できます。本章では、EES を利用したクイックスタートから、オンプレミス環境へのインストール、クラスタ構成の基礎、そして構築時の注意点まで、幅広く解説します。最小構成から始めることで、Elasticsearch の基本を理解しながら、段階的に環境を拡張していくことができます。

### 2.1 Elasticsearch Service (Elastic Cloud) を利用したクイックスタート

#### 概要と重要性

Elastic Cloud は、Elastic 社が提供するマネージド Elasticsearch サービスです。インフラの管理や設定を気にすることなく、すぐに Elasticsearch を使い始めることができます。開発環境のプロトタイプ作成から本番環境まで、幅広い用途に対応可能です。

#### 特徴と利点

* **迅速なデプロイ:** 数クリックで Elasticsearch クラスタを起動できます。
* **自動スケーリング:** トラフィックの増減に合わせて、自動的にリソースをスケールアップ/ダウンします。
* **マネージドサービス:** インフラの管理、バックアップ、アップグレードなどを Elastic 社が代行します。
* **統合:** Kibana、Logstash、Beats などの Elastic Stack のツールとシームレスに連携できます。
* **セキュリティ:** 堅牢なセキュリティ機能が組み込まれています。

#### 事前準備と前提条件

* Elastic Cloud アカウントが必要です。無料でトライアルアカウントを作成できます。 ([https://www.elastic.co/cloud/elasticsearch-service/signup](https://www.elastic.co/cloud/elasticsearch-service/signup))
* クレジットカード情報の登録が必要です (トライアル期間終了後、自動的に課金されることはありません)。

#### 基本的な使い方

1. **Elastic Cloud にログイン:** Elastic Cloud のウェブサイトにアクセスし、アカウントでログインします。
2. **デプロイの作成:** ダッシュボードから "Create deployment" をクリックします。
3. **デプロイ設定:** Elasticsearch のバージョン、リージョン、ハードウェア構成などを選択します。最初は最小構成（"Development" テンプレートなど）を選択することをおすすめします。
4. **デプロイの作成:** 設定を確認し、"Create deployment" をクリックします。
5. **Elasticsearch と Kibana へのアクセス:** デプロイが完了すると、Elasticsearch のエンドポイントと Kibana の URL が表示されます。Kibana を利用してデータの投入や検索を行うことができます。

#### 実践的なテクニック

* **API キーの生成:** セキュリティを強化するために、Elasticsearch にアクセスするための API キーを生成しましょう。Elastic Cloud のダッシュボードから "Security" > "API keys" に移動し、新しい API キーを作成します。
* **インデックステンプレートの利用:** インデックステンプレートを使用すると、インデックスの作成時にデフォルトのマッピングや設定を適用できます。Kibana の "Stack Management" > "Index Management" > "Index Templates" から作成できます。
* **アラートのセットアップ:** 重要なイベントが発生した場合に通知を受け取れるように、アラートを設定しましょう。Kibana の "Stack Management" > "Alerting" から設定できます。

#### 応用例とユースケース

* **ログ分析:** アプリケーションやシステムのログを収集し、リアルタイムに分析します。
* **セキュリティ分析:** セキュリティイベントを収集し、異常なアクティビティを検出します。
* **検索エンジン:** ウェブサイトやアプリケーションに検索機能を追加します。
* **ビジネスインテリジェンス:** データを可視化し、ビジネスのトレンドを分析します。

#### トラブルシューティング

* **Elasticsearch に接続できない:** Elasticsearch のエンドポイントが正しいか、ファイアウォールでアクセスが許可されているかを確認してください。
* **Kibana にアクセスできない:** Kibana の URL が正しいか、Elasticsearch が正常に動作しているかを確認してください。
* **データがインデックスされない:** マッピングが正しく設定されているか、データ形式が Elasticsearch でサポートされているかを確認してください。

#### まとめと次のステップ

Elastic Cloud を利用することで、非常に簡単に Elasticsearch の環境を構築し、利用を開始できます。次のステップとして、Kibana を使ってデータの可視化や検索を試したり、Logstash や Beats を使ってデータの収集パイプラインを構築したりしてみましょう。

### 2.2 オンプレミス環境へのインストールと設定

#### 概要と重要性

Elasticsearch をオンプレミス環境にインストールすることで、データの制御やカスタマイズの自由度が高まります。特定のセキュリティ要件やコンプライアンス要件がある場合に適しています。

#### 特徴と利点

* **データの制御:** データを自社のインフラに保持し、アクセス制御を厳密に管理できます。
* **カスタマイズ:** Elasticsearch の設定を自由にカスタマイズできます。
* **オフライン環境:** インターネット接続がない環境でも Elasticsearch を利用できます。
* **パフォーマンス:** ネットワーク遅延を最小限に抑え、最適なパフォーマンスを実現できます。

#### 事前準備と前提条件

* Java Development Kit (JDK) 8 以降がインストールされている必要があります。
* Linux, macOS, Windows などのオペレーティングシステムが必要です。
* 十分なディスク容量、メモリ、CPU リソースが必要です。

#### 基本的な使い方

1. **Elasticsearch のダウンロード:** Elastic 社のウェブサイトから Elasticsearch の最新バージョンをダウンロードします。 ([https://www.elastic.co/downloads/elasticsearch](https://www.elastic.co/downloads/elasticsearch))
2. **ファイルの展開:** ダウンロードしたファイルを適切なディレクトリに展開します。
3. **設定ファイルの編集:** `config/elasticsearch.yml` ファイルを編集し、クラスタ名、ノード名、ネットワーク設定などを設定します。
4. **Elasticsearch の起動:** ターミナルから Elasticsearch を起動します。

```bash
cd <elasticsearch_directory>
./bin/elasticsearch
```

5. **動作確認:** ブラウザまたは curl コマンドで Elasticsearch のエンドポイントにアクセスし、動作確認を行います。

```bash
curl -X GET "http://localhost:9200"
```

#### 実践的なテクニック

* **JVM オプションの設定:** `config/jvm.options` ファイルを編集し、JVM のヒープサイズを設定します。パフォーマンスを最適化するために、適切なヒープサイズを設定することが重要です。
* **プラグインのインストール:** Elasticsearch の機能を拡張するために、プラグインをインストールします。`./bin/elasticsearch-plugin` コマンドを使用します。

```bash
./bin/elasticsearch-plugin install <plugin_name>
```

* **ロギング設定:** `config/log4j2.properties` ファイルを編集し、ロギング設定をカスタマイズします。
* **systemd による管理:** Elasticsearch を systemd サービスとして登録することで、起動/停止/再起動を容易に管理できます。

#### 応用例とユースケース

* **社内検索:** 社内ドキュメントやデータを検索するための検索エンジンを構築します。
* **モニタリング:** システムのメトリクスやログを収集し、リアルタイムにモニタリングします。
* **機械学習:** 機械学習モデルを Elasticsearch に統合し、予測分析や異常検知を行います。

#### トラブルシューティング

* **Elasticsearch が起動しない:** エラーログを確認し、設定ファイルに誤りがないか、必要なリソースが不足していないかを確認してください。
* **OutOfMemoryError が発生する:** JVM のヒープサイズを増やすか、データのインデックス方法を最適化してください。
* **クラスタが正常に動作しない:** ネットワーク設定、ファイアウォール設定、ノード間の通信設定を確認してください。

#### まとめと次のステップ

オンプレミス環境へのインストールは、Elasticsearch を深く理解するための良い機会となります。次のステップとして、Elasticsearch の設定をより深く理解し、パフォーマンスを最適化するためのチューニングを試してみましょう。

### 2.3 Elasticsearchクラスタ構成の基礎

#### 概要と重要性

Elasticsearch クラスタは、複数のノードで構成され、高可用性、スケーラビリティ、パフォーマンスを実現します。クラスタ構成を理解することで、最適な環境を構築し、運用することができます。

#### 特徴と利点

* **高可用性:** 複数のノードでデータをレプリケーションすることで、ノード障害時にもデータを保護できます。
* **スケーラビリティ:** ノードを追加することで、データの容量や検索処理能力をスケールアップできます。
* **パフォーマンス:** データを複数のノードに分散することで、検索処理を並列化し、パフォーマンスを向上させます。

#### 事前準備と前提条件

* Elasticsearch がインストールされた複数のサーバーが必要です。
* ネットワーク設定が正しく設定されている必要があります。
* 各ノードの `config/elasticsearch.yml` ファイルを編集する必要があります。

#### 基本的な使い方

1. **クラスタ名の設定:** すべてのノードの `config/elasticsearch.yml` ファイルで、同じクラスタ名を指定します。

```yaml
cluster.name: my-cluster
```

2. **ノード名の設定:** 各ノードの `config/elasticsearch.yml` ファイルで、異なるノード名を指定します。

```yaml
node.name: node-1
```

3. **ネットワーク設定:** 各ノードの `config/elasticsearch.yml` ファイルで、ネットワーク設定を指定します。

```yaml
network.host: 0.0.0.0
http.port: 9200
discovery.seed_hosts: ["node-1", "node-2", "node-3"]
cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]
```

4. **Elasticsearch の起動:** すべてのノードで Elasticsearch を起動します。

#### 実践的なテクニック

* **マスターノードの選定:** マスターノードはクラスタの状態を管理します。安定したマスターノードを選定することが重要です。
* **データノードの追加:** データノードはデータの格納と検索を行います。データの容量や検索処理能力に合わせて、データノードを追加します。
* **コーディネートノードの追加:** コーディネートノードはクライアントからのリクエストを受け付け、他のノードに分散します。大規模なクラスタでは、コーディネートノードを追加することで、パフォーマンスを向上させることができます。
* **ホット/ウォーム/コールドアーキテクチャ:** データのアクセス頻度に応じて、異なるハードウェア構成のノードにデータを格納します。

#### 応用例とユースケース

* **大規模ログ分析:** 大量のログデータを複数のノードに分散し、高速に分析します。
* **eコマース検索:** 大量の製品データを複数のノードに分散し、高速な検索を提供します。
* **地理空間検索:** 地理空間データを複数のノードに分散し、高速な地理空間検索を提供します。

#### トラブルシューティング

* **ノードがクラスタに参加しない:** ネットワーク設定、ファイアウォール設定、ノード間の通信設定を確認してください。
* **クラスタの状態が不安定:** マスターノードの選定、ネットワーク設定、ハードウェアリソースを確認してください。
* **検索パフォーマンスが低い:** データのマッピング、クエリの最適化、ハードウェアリソースを確認してください。

#### まとめと次のステップ

クラスタ構成を理解することで、Elasticsearch の能力を最大限に引き出すことができます。次のステップとして、クラスタの監視、バックアップ、リカバリなどの運用管理について学習しましょう。

### 2.4 構築時の注意点と初期設定

#### 概要と重要性

Elasticsearch を構築する際には、いくつかの注意点があります。初期設定を正しく行うことで、パフォーマンス、セキュリティ、安定性を向上させることができます。

#### 特徴と利点

* **パフォーマンス向上:** 適切なハードウェアリソース、JVM 設定、インデックス設定を行うことで、検索パフォーマンスを向上させることができます。
* **セキュリティ強化:** アクセス制御、認証、暗号化などのセキュリティ機能を設定することで、データを保護することができます。
* **安定性向上:** バックアップ、リカバリ、監視などの運用管理機能を設定することで、クラスタの安定性を向上させることができます。

#### 事前準備と前提条件

* Elasticsearch がインストールされている必要があります。
* Elasticsearch の設定ファイル `config/elasticsearch.yml` を編集する必要があります。

#### 基本的な使い方

1. **セキュリティ設定:**

   * **認証:** ユーザー名とパスワードによる認証を有効にします。
   * **ロールベースアクセス制御 (RBAC):** ユーザーに適切なロールを割り当てることで、アクセス権を制限します。
   * **TLS/SSL 暗号化:** Elasticsearch とクライアント間の通信を暗号化します。

2. **リソース設定:**

   * **ヒープサイズ:** JVM のヒープサイズを適切に設定します。通常、物理メモリの半分程度に設定します。
   * **ファイル記述子:** ファイル記述子の最大数を増やします。
   * **スワップ:** スワップを無効化または最小化します。

3. **インデックス設定:**

   * **シャード数:** インデックスのシャード数を適切に設定します。シャード数を増やすことで、検索処理を並列化し、パフォーマンスを向上させることができます。
   * **レプリカ数:** インデックスのレプリカ数を適切に設定します。レプリカ数を増やすことで、高可用性を実現できます。
   * **リフレッシュ間隔:** インデックスのリフレッシュ間隔を調整します。リフレッシュ間隔を長くすることで、インデックス処理の負荷を軽減できます。

4. **ディスク設定:**

   * **SSD の利用:** 可能であれば、SSD を利用することで、IO パフォーマンスを向上させることができます。
   * **ディスクアレイの利用:** RAID 構成のディスクアレイを利用することで、高可用性を実現できます。

#### 実践的なテクニック

* **テンプレートの利用:** インデックステンプレートを使用すると、インデックスの作成時にデフォルトの設定を適用できます。
* **監視ツールの導入:** Elasticsearch の状態を監視するためのツールを導入します。Elastic 社が提供する Monitoring やサードパーティ製のツールを利用できます。
* **バックアップとリカバリ:** 定期的にバックアップを行い、障害発生時にデータをリカバリできるように準備します。Snapshot and Restore API を利用できます。
* **バージョンアップ:** 最新バージョンに定期的にアップデートします。最新バージョンには、パフォーマンス改善、セキュリティ修正、新機能が含まれています。

#### 応用例とユースケース

* **セキュリティログ分析:** 大量のセキュリティログを収集し、リアルタイムに分析します。適切なセキュリティ設定を行うことで、セキュリティインシデントを早期に検知できます。
* **金融取引分析:** 大量の金融取引データを収集し、不正取引を検知します。適切なインデックス設定を行うことで、高速な分析を実現できます。

#### トラブルシューティング

* **パフォーマンスが低い:** ハードウェアリソース、JVM 設定、インデックス設定、クエリの最適化を確認してください。
* **セキュリティに関する問題が発生:** アクセス制御、認証、暗号化設定を確認してください。
* **データが消失:** バックアップとリカバリ手順を確認し、リカバリを試みてください。

#### まとめと次のステップ

初期設定を正しく行うことで、Elasticsearch の能力を最大限に引き出し、安定した環境を構築できます。次のステップとして、運用管理、監視、バックアップ、リカバリなどの高度なトピックについて学習しましょう。また、Elasticsearch の最新情報を常にキャッチアップし、ベストプラクティスを実践することで、より効率的な運用が可能になります。
