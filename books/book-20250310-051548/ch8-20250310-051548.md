## 第8章：運用監視：Elasticsearchクラスタの健康状態を維持

Elasticsearchクラスタを安定的に運用するためには、継続的な監視と適切な対応が不可欠です。本章では、Elastic Stack Monitoringを活用した監視、異常検知と自動通知のためのアラート設定、Elasticsearchログの解析、そしてデータの保護と災害対策のためのバックアップとリストアについて、実践的な内容を交えながら解説します。

### 8.1 Elastic Stack Monitoringによる監視

**1. 概要と重要性**

Elastic Stack Monitoringは、Elasticsearchクラスタの状態を可視化し、パフォーマンスボトルネックや異常を早期に発見するための強力なツールです。クラスタの健全性を維持し、障害を未然に防ぐためには、モニタリングの導入と適切な設定が不可欠です。

**2. 特徴と利点**

*   **リアルタイム監視:** CPU使用率、メモリ使用量、ディスクI/O、検索・インデックス作成のスループットなど、重要なメトリクスをリアルタイムに監視できます。
*   **ダッシュボード:** 豊富な可視化ダッシュボードが用意されており、クラスタの状態を直感的に把握できます。
*   **履歴分析:** 過去のデータを参照し、傾向分析や問題の原因特定に役立てられます。
*   **アラート統合:** Monitoringで検知した異常を、メールやSlackなどの通知チャネルに連携できます。

**3. 事前準備と前提条件**

*   ElasticsearchとKibanaがインストールされていること。
*   Elastic Stack Monitoring機能が有効になっていること (デフォルトで有効になっていることが多いですが、`xpack.monitoring.enabled: true` が `elasticsearch.yml` に設定されているか確認してください)。
*   `kibana.yml`に以下の設定がされているか確認してください (`setup.username`と`setup.password`はElasticsearchの`kibana_system`ユーザーの認証情報に置き換えてください)。
    ```yaml
    xpack.monitoring.ui.container.elasticsearch.hosts: ["http://localhost:9200"]
    elasticsearch.username: "kibana_system"
    elasticsearch.password: "YOUR_KIBANA_SYSTEM_PASSWORD"
    ```

**4. 基本的な使い方**

Kibanaの左側のメニューから「Monitoring」を選択すると、Elasticsearchクラスタの概要が表示されます。ここでは、クラスタ全体、ノード、インデックスごとの詳細な情報を確認できます。

*   **クラスタ概要:** クラスタのステータス、ノード数、インデックス数、シャード数、ディスク使用量などが表示されます。
*   **ノード詳細:** 各ノードのCPU使用率、メモリ使用量、ディスクI/O、JVMの状況などが表示されます。
*   **インデックス詳細:** 各インデックスのドキュメント数、サイズ、検索・インデックス作成のスループットなどが表示されます。

**5. 実践的なテクニック**

*   **カスタムダッシュボードの作成:** 独自のニーズに合わせて、カスタムダッシュボードを作成できます。KibanaのVisualize機能を使用して、特定のメトリクスをグラフ化したり、複数のメトリクスを組み合わせたりできます。
*   **アラートの設定:** 特定のメトリクスが閾値を超えた場合にアラートを発行するように設定できます (アラート設定については後述)。
*   **APIによるモニタリング:** Monitoring APIを使用して、プログラムからメトリクスを取得できます。これにより、外部のモニタリングシステムとの連携が容易になります。

**6. 応用例とユースケース**

*   **パフォーマンスボトルネックの特定:** CPU使用率の高いノードや、ディスクI/Oがボトルネックになっているノードを特定し、改善策を検討します。
*   **インデックス作成速度の低下:** インデックス作成速度が低下している原因を特定し、設定を最適化します。
*   **ディスク容量の逼迫:** ディスク使用量が逼迫しているインデックスを特定し、データ削除やインデックスローテーションなどの対策を講じます。

**7. トラブルシューティング**

*   **Monitoringデータが表示されない:** Elasticsearchの設定 (`elasticsearch.yml`) で `xpack.monitoring.enabled: true` が設定されているか確認してください。また、Kibanaの設定 (`kibana.yml`) で Elasticsearchへの接続設定が正しく設定されているか確認してください。
*   **パフォーマンスへの影響:** MonitoringはElasticsearchクラスタに負荷をかける可能性があります。負荷が高い場合は、`xpack.monitoring.collection.interval` を調整して、データ収集間隔を長くすることを検討してください。

**8. まとめと次のステップ**

Elastic Stack Monitoringは、Elasticsearchクラスタの健康状態を維持するための強力なツールです。基本的な使い方を理解し、カスタムダッシュボードやアラート設定を駆使することで、より効果的なモニタリングを実現できます。次のステップとして、アラート設定について詳しく学びましょう。

### 8.2 アラート設定：異常検知と自動通知

**1. 概要と重要性**

アラート設定は、Elasticsearchクラスタで発生する可能性のある問題を早期に検知し、自動的に通知するための重要な機能です。適切なアラートを設定することで、人的ミスや障害による影響を最小限に抑えることができます。

**2. 特徴と利点**

*   **多様なアラート条件:** CPU使用率、メモリ使用量、ディスク使用量、検索エラー率など、様々なメトリクスに基づいてアラートを設定できます。
*   **閾値設定:** メトリクスの値が特定の閾値を超えた場合にアラートを発行するように設定できます。
*   **通知チャネル:** メール、Slack、PagerDutyなど、様々な通知チャネルにアラートを送信できます。
*   **自動修復:** アラートに基づいて、自動的に問題を修復するスクリプトを実行できます (高度な設定)。

**3. 事前準備と前提条件**

*   ElasticsearchとKibanaがインストールされていること。
*   Elastic Stack Monitoring機能が有効になっていること。
*   通知チャネル (メール、Slackなど) の設定が完了していること。

**4. 基本的な使い方**

Kibanaの左側のメニューから「Stack Management」-> 「Rules and Connectors」を選択します。ここで、アラートルールを作成し、通知コネクタを設定できます。

1.  **ルールタイプの選択:** 監視対象のデータソース (Elasticsearchインデックス、APM、Uptimeなど) を選択します。Monitoring で収集されたメトリクスに基づいてアラートを設定する場合は、「Metrics threshold」を選択します。
2.  **ルールの定義:** アラート条件 (CPU使用率が80%を超える、など) を設定します。
3.  **アクションの定義:** アラートがトリガーされた場合に実行するアクション (メール送信、Slack通知など) を設定します。

**例：CPU使用率が80%を超えた場合にメールで通知するアラート**

1.  Kibanaで「Stack Management」-> 「Rules and Connectors」に移動します。
2.  「Create rule」をクリックし、「Metrics threshold」を選択します。
3.  「Name」にアラート名 (例：CPU High Usage) を入力します。
4.  「Index」に `metricbeat-*` を指定します（Metricbeatで監視データを収集している場合）。
5.  「Field」に `system.cpu.user.pct` を指定します。
6.  「Threshold」に `is above` を選択し、`0.8` (80%) を入力します。
7.  「Run every」に実行間隔 (例：1 minute) を設定します。
8.  「Then」セクションで、「Add action」をクリックし、「Email」を選択します。事前にEmailコネクタを設定しておく必要があります。
9.  件名と本文をカスタマイズし、「Create rule」をクリックします。

**5. 実践的なテクニック**

*   **複数の条件を組み合わせたアラート:** 複数のメトリクスを組み合わせたアラートを設定することで、より精度の高い異常検知を実現できます。
*   **アラートの優先度設定:** アラートの重要度に応じて、優先度を設定できます。優先度の高いアラートは、担当者にエスカレーションするように設定できます。
*   **アラートの抑制:** 短期間に大量のアラートが発生した場合、アラートの抑制を設定することで、不要な通知を防ぐことができます。

**6. 応用例とユースケース**

*   **Elasticsearchノードのダウン:** Elasticsearchノードがダウンした場合にアラートを発行し、担当者に通知します。
*   **ディスク容量の逼迫:** ディスク容量が逼迫した場合にアラートを発行し、データ削除やインデックスローテーションなどの対策を促します。
*   **検索エラー率の増加:** 検索エラー率が急増した場合にアラートを発行し、原因を調査します。

**7. トラブルシューティング**

*   **アラートが発行されない:** アラート条件が正しく設定されているか確認してください。また、監視対象のメトリクスが正しく収集されているか確認してください。
*   **アラートが大量に発行される:** アラート条件が厳しすぎる可能性があります。閾値を調整するか、アラートの抑制を設定してください。
*   **通知が届かない:** 通知チャネルの設定が正しく設定されているか確認してください。また、スパムフィルタに誤って分類されていないか確認してください。

**8. まとめと次のステップ**

アラート設定は、Elasticsearchクラスタの安定運用に不可欠な要素です。適切なアラートを設定することで、潜在的な問題を早期に検知し、迅速に対応できます。次のステップとして、Elasticsearchログの解析について学びましょう。

### 8.3 ログ分析：Elasticsearchログの解析

**1. 概要と重要性**

Elasticsearchのログは、クラスタの動作状況やエラーに関する重要な情報を提供します。ログを解析することで、問題の原因特定やパフォーマンス改善に役立てることができます。

**2. 特徴と利点**

*   **問題の早期発見:** エラーログや警告ログを分析することで、潜在的な問題を早期に発見できます。
*   **原因の特定:** ログを分析することで、問題の原因を特定し、解決策を見つけ出すことができます。
*   **パフォーマンス改善:** ログを分析することで、パフォーマンスボトルネックを特定し、設定を最適化できます。
*   **セキュリティ監査:** ログを分析することで、セキュリティイベントを検出し、不正アクセスを防止できます。

**3. 事前準備と前提条件**

*   ElasticsearchとKibanaがインストールされていること。
*   Elasticsearchのログが適切に設定され、収集されていること。
*   Filebeatなどのログ転送ツールが設定されていること。

**4. 基本的な使い方**

KibanaのDiscover機能を使用して、Elasticsearchのログを検索および分析できます。

1.  Kibanaで「Discover」を選択します。
2.  ログが格納されているインデックスパターンを選択します (例：`filebeat-*`)。
3.  検索クエリを入力して、特定のログを検索します (例：`error`、`warn`、`exception`)。
4.  タイムラインを使用して、特定の時間範囲のログを絞り込みます。
5.  ログのフィールドを展開して、詳細な情報を確認します。

**例：エラーログを検索する**

KibanaのDiscover画面で、検索バーに `error` と入力し、Enterキーを押します。これにより、エラーログを含むすべてのログが表示されます。

**5. 実践的なテクニック**

*   **ログレベルによるフィルタリング:** ログレベル (TRACE, DEBUG, INFO, WARN, ERROR, FATAL) を使用して、ログをフィルタリングできます。
*   **キーワード検索:** 特定のキーワード (例：`OutOfMemoryError`、`Connection refused`) を使用して、ログを検索できます。
*   **集計:** 特定のフィールド (例：`node.name`、`component`) でログを集計し、傾向分析を行うことができます。
*   **可視化:** ログデータをグラフ化し、視覚的に分析できます。

**6. 応用例とユースケース**

*   **OutOfMemoryErrorの調査:** `OutOfMemoryError` が発生した場合、ログを分析して、メモリリークの原因を特定し、JVMの設定を調整します。
*   **Connection refusedの調査:** `Connection refused` が発生した場合、ログを分析して、ネットワーク接続の問題を特定し、ファイアウォールやネットワーク設定を修正します。
*   **Slow logの分析:** `Slow log` を分析して、パフォーマンスの低いクエリを特定し、クエリを最適化します。

**7. トラブルシューティング**

*   **ログが表示されない:** Elasticsearchのログ設定が正しく設定されているか確認してください。また、Filebeatなどのログ転送ツールの設定が正しく設定されているか確認してください。
*   **ログが多すぎる:** ログレベルを調整して、不要なログの出力を抑制してください。
*   **ログが読みにくい:** ログフォーマットを調整して、読みやすくしてください。

**8. まとめと次のステップ**

Elasticsearchのログ解析は、クラスタの安定運用に不可欠なスキルです。ログを分析することで、問題を早期に発見し、迅速に対応できます。次のステップとして、バックアップとリストアについて学びましょう。

### 8.4 バックアップとリストア：データの保護と災害対策

**1. 概要と重要性**

Elasticsearchに格納されたデータは、ビジネスにとって非常に重要な資産です。データの損失を防ぐために、定期的なバックアップと、万が一の事態に備えたリストア手順の確立が不可欠です。

**2. 特徴と利点**

*   **データ保護:** データの損失を防ぎ、事業継続性を確保できます。
*   **災害対策:** 自然災害や人的ミスによるデータ損失から保護できます。
*   **容易な復旧:** 障害発生時に、迅速にデータを復旧できます。
*   **柔軟なバックアップ戦略:** フルバックアップ、差分バックアップ、増分バックアップなど、様々なバックアップ戦略を選択できます。

**3. 事前準備と前提条件**

*   Elasticsearchがインストールされていること。
*   バックアップ先のストレージ (ローカルディスク、NFS、S3など) が準備されていること。
*   Elasticsearchの `elasticsearch.yml` に、バックアップリポジトリの設定が追加されていること。

**4. 基本的な使い方**

Elasticsearchは、Snapshot APIを使用して、バックアップとリストアを管理します。

1.  **リポジトリの登録:** バックアップ先のストレージをリポジトリとして登録します。

    ```bash
    PUT _snapshot/my_backup_repo
    {
      "type": "fs",
      "settings": {
        "location": "/path/to/backup/location",
        "compress": true
      }
    }
    ```

    *   `type`: リポジトリのタイプ (例：`fs`, `s3`, `azure`, `gcs`)
    *   `settings`: リポジトリの設定 (タイプによって異なります)

    **S3へのバックアップ例:**

    ```bash
    PUT _snapshot/my_s3_backup_repo
    {
      "type": "s3",
      "settings": {
        "bucket": "my-s3-bucket",
        "region": "us-west-2",
        "base_path": "elasticsearch_backups",
        "client": "default"  # S3クライアント名（省略可能）
      }
    }
    ```

    S3を使用するには、`elasticsearch-plugin install repository-s3` でプラグインをインストールし、`elasticsearch.yml` に認証情報を設定する必要があります。
    ```yaml
    cloud.aws.access_key: YOUR_AWS_ACCESS_KEY
    cloud.aws.secret_key: YOUR_AWS_SECRET_KEY
    ```

2.  **スナップショットの作成:** バックアップを作成します。

    ```bash
    PUT _snapshot/my_backup_repo/snapshot_1
    {
      "indices": "index1,index2",
      "ignore_unavailable": true,
      "include_global_state": true
    }
    ```

    *   `indices`: バックアップするインデックス (カンマ区切りで複数指定可能)
    *   `ignore_unavailable`: 存在しないインデックスを無視するかどうか
    *   `include_global_state`: クラスタ状態 (設定、テンプレートなど) を含めるかどうか

3.  **スナップショットのリストア:** バックアップからデータを復元します。

    ```bash
    POST _snapshot/my_backup_repo/snapshot_1/_restore
    {
      "indices": "index1,index2",
      "rename_pattern": "index(.*)",
      "rename_replacement": "restored_index$1",
      "ignore_unavailable": true,
      "include_global_state": true
    }
    ```

    *   `indices`: リストアするインデックス (カンマ区切りで複数指定可能)
    *   `rename_pattern`: インデックス名を変更するための正規表現パターン
    *   `rename_replacement`: インデックス名を変更するための置換文字列
    *   `ignore_unavailable`: 存在しないインデックスを無視するかどうか
    *   `include_global_state`: クラスタ状態 (設定、テンプレートなど) を含めるかどうか

**5. 実践的なテクニック**

*   **定期的なバックアップ:** cronなどのスケジューラを使用して、定期的にバックアップを作成します。
*   **自動バックアップスクリプト:** バックアップとリストアを自動化するスクリプトを作成します。
*   **バックアップの検証:** 定期的にバックアップからデータをリストアし、データの整合性を検証します。
*   **インデックスライフサイクル管理 (ILM) との連携:** ILMを使用して、古いインデックスを自動的にバックアップし、削除できます。

**6. 応用例とユースケース**

*   **システム障害からの復旧:** ハードウェア障害やソフトウェア障害が発生した場合、バックアップからデータをリストアし、システムを復旧します。
*   **データ移行:** 新しいハードウェアや新しいクラスタにデータを移行する際に、バックアップとリストアを使用します。
*   **テスト環境の構築:** 本番環境のデータをバックアップからリストアし、テスト環境を構築します。

**7. トラブルシューティング**

*   **リポジトリの登録に失敗する:** Elasticsearchのアクセス権限が不足している可能性があります。適切なアクセス権限を設定してください。
*   **スナップショットの作成に失敗する:** Elasticsearchクラスタに十分なリソース (CPU、メモリ、ディスクI/O) がない可能性があります。リソースを増強するか、バックアップのタイミングを調整してください。
*   **スナップショットのリストアに失敗する:** リストア先のインデックスが既に存在する場合、リストアは失敗します。インデックスを削除するか、`rename_pattern` と `rename_replacement` を使用して、インデックス名を変更してください。

**8. まとめと次のステップ**

バックアップとリストアは、Elasticsearchクラスタのデータを保護し、災害に備えるための重要なプロセスです。適切なバックアップ戦略を策定し、定期的なバックアップとリストアの検証を行うことで、安心してElasticsearchクラスタを運用できます。

本章では、Elasticsearchクラスタの運用監視に必要な主要な要素について解説しました。これらの知識を活用し、安定したElasticsearch環境を構築・維持してください。
