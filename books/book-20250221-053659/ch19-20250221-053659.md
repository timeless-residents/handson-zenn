## 第19章：トラブルシューティング

Sitecore開発は、時に複雑な問題を抱えることがあります。この章では、開発環境と本番環境の両方で発生しやすいトラブルとその解決策について、実践的なテクニックを交えながら解説します。また、Sitecore Supportやコミュニティといった頼りになるリソースの活用方法についても詳しく説明します。

### 19.1. 開発環境でのトラブルシューティング

開発環境は、新しい機能のテストや既存機能の修正を行うための実験場です。しかし、設定ミスやコードの不具合によって様々な問題が発生することがあります。ここでは、開発環境でよく遭遇する3つの問題とその解決策を見ていきましょう。

#### 19.1.1. コンポーネントが表示されない

**概要と重要性**

Sitecoreのページに意図したコンポーネントが表示されない場合、コンテンツ作成者はもちろん、開発者にとっても大きな問題です。表示されない原因を特定し、迅速に解決することが、開発効率とコンテンツの品質を維持するために重要となります。

**特徴と利点**

コンポーネントが表示されない問題の原因は多岐にわたります。しかし、System.Web.Cachingやイベントキューが原因の場合、アプリケーションプールを再起動するとすぐに解消する場合があります。
System.Web.Cachingやイベントキューに問題があるかどうか切り分けるためにもまずアプリケーションプールを再起動してみましょう。

**事前準備と前提条件**

* Sitecore インスタンスへのアクセス権
* Sitecore Content Editorへのアクセス権
* 開発環境の Sitecore インスタンス

**基本的な使い方**

1. **Content Editor での確認:**
   * コンポーネントが配置されているページにアクセスし、Presentation Details でコンポーネントが正しくアサインされているかを確認します。
   * レイアウト、プレースホルダー、データソースの設定を確認します。
   * コンポーネントの可視性ルール (Experience Optimization) が設定されている場合は、現在のユーザーやコンテキストでコンポーネントが表示される条件を満たしているかを確認します。

2. **コードの確認:**
   * コンポーネントの Rendering ファイル (cshtml や aspx) にエラーがないかを確認します。
   * データソースからデータを取得するロジックにエラーがないかを確認します。
   * 必要に応じて、デバッガを使用してコードを実行し、問題を特定します。

**実践的なテクニック**

* **レイアウトの確認:** コンポーネントが配置されているレイアウトファイル (`.cshtml` または `.aspx`) を確認し、プレースホルダーが正しく定義されているかを確認します。

   ```html
   @Html.Sitecore().Placeholder("main")
   ```

   上記のように、`@Html.Sitecore().Placeholder("プレースホルダー名")` が存在し、コンポーネントがそのプレースホルダーに配置されていることを確認します。

* **データソースの確認:** コンポーネントがデータソースを使用している場合、データソースアイテムが正しく設定されているかを確認します。データソースアイテムが存在しない、または必要なフィールドが空の場合、コンポーネントは何も表示しない可能性があります。

   ```csharp
   // データソースアイテムからテキストを取得する例
   @Model.DataSourceItem["Text"]
   ```

* **Sitecore ログの確認:** Sitecore のログファイル (`/App_Data/logs`) を確認し、エラーメッセージや警告メッセージがないかを確認します。ログには、コンポーネントが表示されない原因に関する情報が含まれている場合があります。

**応用例とユースケース**

例えば、特定のユーザーグループに対してのみ表示されるコンポーネントを実装する場合、Experience Optimization を使用して可視性ルールを設定します。

```csharp
// ユーザーが特定のロールに属している場合にのみコンポーネントを表示する例
@if (Sitecore.Context.User.IsInRole("extranet\\Administrators"))
{
    @Html.Sitecore().Rendering("ComponentName")
}
```

**トラブルシューティング**

* **キャッシュのクリア:** Sitecore のキャッシュが原因でコンポーネントが表示されない場合があります。Sitecore Control Panel からキャッシュをクリアしてみてください。

   ```
   /sitecore/admin/cache.aspx
   ```

* **ブラウザのキャッシュのクリア:** ブラウザのキャッシュも、古いバージョンのコンポーネントを表示する原因となることがあります。ブラウザのキャッシュをクリアしてみてください。
* **Sitecoreアプリケーションプールの再起動:** アプリケーションプールの再起動をすることで解決する場合があります。

**まとめと次のステップ**

コンポーネントが表示されない問題は、設定ミス、コードの不具合、キャッシュの問題など、様々な原因が考えられます。まずは基本的な確認を行い、ログやデバッガを使用して問題を特定し、解決策を適用してください。もし問題が解決しない場合は、Sitecore Support やコミュニティに助けを求めることも検討しましょう。

次のステップとしては、コンポーネントの表示に関するパフォーマンスの問題に対処する方法を学ぶことをお勧めします。

#### 19.1.2. データが取得できない

**概要と重要性**

Sitecore コンポーネントがデータソースからデータを取得できない場合、Web サイトのコンテンツが正しく表示されず、ユーザーエクスペリエンスに悪影響を与えます。データの取得エラーを迅速に特定し、解決することが重要です。

**特徴と利点**

データ取得エラーの原因は、データソースの設定ミス、コードの不具合、データベースの問題など、様々です。問題の原因を特定し、適切な解決策を適用することで、Web サイトの信頼性と品質を向上させることができます。

**事前準備と前提条件**

* Sitecore インスタンスへのアクセス権
* Sitecore Content Editorへのアクセス権
* データソースが設定された Sitecore コンポーネント

**基本的な使い方**

1. **データソースの設定確認:**
   * Content Editor で、コンポーネントのデータソースが正しく設定されているかを確認します。
   * データソースアイテムが存在し、必要なフィールドにデータが入力されているかを確認します。
   * データソースのパスが正しいかを確認します。

2. **コードの確認:**
   * コンポーネントの Rendering ファイルで、データソースからデータを取得するコードにエラーがないかを確認します。
   * Sitecore API を使用してデータを取得している場合、API の使用方法が正しいかを確認します。

**実践的なテクニック**

* **Sitecore API の使用例:**

   ```csharp
   @using Sitecore.Data.Items
   @using Sitecore.Web.UI.WebControls

   @if (Model.DataSource != null)
   {
       Item dataSourceItem = Sitecore.Context.Database.GetItem(Model.DataSource);
       if (dataSourceItem != null)
       {
           <p>タイトル: @Html.Sitecore().Field("Title", dataSourceItem)</p>
           <p>テキスト: @Html.Sitecore().Field("Text", dataSourceItem)</p>
       }
       else
       {
           <p>データソースアイテムが見つかりません。</p>
       }
   }
   else
   {
       <p>データソースが設定されていません。</p>
   }
   ```

   上記コードでは、`Sitecore.Context.Database.GetItem(Model.DataSource)` を使用してデータソースアイテムを取得しています。データソースアイテムが存在しない場合、エラーメッセージを表示します。

* **LinkField の使用例:**

   ```csharp
   @using Sitecore.Data.Fields
   @using Sitecore.Links

   @if (Model.DataSource != null)
   {
       Item dataSourceItem = Sitecore.Context.Database.GetItem(Model.DataSource);
       if (dataSourceItem != null)
       {
           LinkField linkField = dataSourceItem.Fields["Link"];
           if (linkField != null && linkField.TargetItem != null)
           {
               string url = LinkManager.GetItemUrl(linkField.TargetItem);
               <a href="@url">@linkField.TargetItem["Title"]</a>
           }
       }
   }
   ```

   上記コードでは、LinkField を使用してリンクを取得しています。`LinkManager.GetItemUrl()` を使用して、リンクの URL を取得します。

**応用例とユースケース**

* **リレーションシップの実装:** Sitecore のリレーションシップ機能を使用して、複数のアイテム間の関連性を定義し、データを取得することができます。
* **検索の実装:** Sitecore の検索機能を使用して、特定の条件に一致するアイテムを検索し、データを取得することができます。

**トラブルシューティング**

* **データベース接続の確認:** Sitecore がデータベースに接続できることを確認します。データベースサーバーが起動しているか、接続文字列が正しいかなどを確認します。
* **インデックスの再構築:** Sitecore のインデックスが破損している場合、データが正しく取得できないことがあります。インデックスを再構築してみてください。

   ```
   /sitecore/admin/rebuild.aspx
   ```

* **ログの確認:** Sitecore のログファイル (`/App_Data/logs`) を確認し、データ取得に関するエラーメッセージがないかを確認します。

**まとめと次のステップ**

データが取得できない問題は、データソースの設定ミス、コードの不具合、データベースの問題など、様々な原因が考えられます。まずは基本的な確認を行い、Sitecore API やログを使用して問題を特定し、解決策を適用してください。もし問題が解決しない場合は、Sitecore Support やコミュニティに助けを求めることも検討しましょう。

次のステップとしては、Sitecore のパフォーマンスを最適化する方法を学ぶことをお勧めします。

#### 19.1.3. エクスペリエンスエディタが正常に動作しない

**概要と重要性**

エクスペリエンスエディタは、コンテンツ作成者がページを編集し、コンテンツをプレビューするための重要なツールです。エクスペリエンスエディタが正常に動作しない場合、コンテンツ作成者はコンテンツを編集できなくなり、Web サイトの更新が滞る可能性があります。

**特徴と利点**

エクスペリエンスエディタの問題は、設定ミス、コードの不具合、ブラウザの問題など、様々な原因が考えられます。問題を特定し、解決することで、コンテンツ作成者はスムーズにコンテンツを編集できるようになり、Web サイトの品質と更新頻度を向上させることができます。

**事前準備と前提条件**

* Sitecore インスタンスへのアクセス権
* Sitecore Content Editorへのアクセス権
* エクスペリエンスエディタが有効になっている Sitecore ページ

**基本的な使い方**

1. **エクスペリエンスエディタの起動:**
   * Content Editor で、編集したいページを開きます。
   * 「表示」タブの「エクスペリエンスエディタ」ボタンをクリックします。

2. **エクスペリエンスエディタの操作:**
   * コンポーネントをクリックして選択し、編集可能なフィールドを変更します。
   * コンポーネントをドラッグアンドドロップして、ページのレイアウトを変更します。
   * コンテンツをプレビューし、変更内容を確認します。

**実践的なテクニック**

* **編集モードの切り替え:** エクスペリエンスエディタには、編集モードとプレビューモードがあります。編集モードでは、コンポーネントの編集やレイアウトの変更ができます。プレビューモードでは、コンテンツがどのように表示されるかを確認できます。

* **デバイスプレビュー:** エクスペリエンスエディタでは、様々なデバイス (デスクトップ、タブレット、モバイル) でのコンテンツの表示をプレビューできます。

* **バージョン管理:** エクスペリエンスエディタで変更した内容は、自動的にバージョン管理されます。必要に応じて、以前のバージョンに戻すことができます。

**応用例とユースケース**

* **パーソナライズの実装:** エクスペリエンスエディタを使用して、特定のユーザーセグメントに対してパーソナライズされたコンテンツを表示することができます。
* **A/B テストの実装:** エクスペリエンスエディタを使用して、A/B テストを実施し、どのコンテンツがより効果的かを検証することができます。

**トラブルシューティング**

* **ブラウザの互換性の確認:** エクスペリエンスエディタは、特定のブラウザでのみ正常に動作する場合があります。互換性のあるブラウザを使用しているかを確認します。
* **JavaScript エラーの確認:** ブラウザの開発者ツールを開き、JavaScript エラーがないかを確認します。JavaScript エラーは、エクスペリエンスエディタの動作を妨げることがあります。
* **Sitecore ログの確認:** Sitecore のログファイル (`/App_Data/logs`) を確認し、エクスペリエンスエディタに関するエラーメッセージがないかを確認します。

**まとめと次のステップ**

エクスペリエンスエディタが正常に動作しない問題は、設定ミス、コードの不具合、ブラウザの問題など、様々な原因が考えられます。まずは基本的な確認を行い、ブラウザの開発者ツールや Sitecore ログを使用して問題を特定し、解決策を適用してください。もし問題が解決しない場合は、Sitecore Support やコミュニティに助けを求めることも検討しましょう。

### 19.2. 本番環境でのトラブルシューティング

本番環境は、実際にユーザーが利用するWebサイトが稼働している環境です。ここでは、本番環境でよく遭遇する問題とその解決策を見ていきましょう。

#### 19.2.1. パフォーマンスの問題

**概要と重要性**

Webサイトのパフォーマンスは、ユーザーエクスペリエンスに直接影響します。ページの読み込みが遅い、応答が遅いなどのパフォーマンスの問題は、ユーザーの離脱率を高め、ビジネスに悪影響を与える可能性があります。

**特徴と利点**

パフォーマンスの問題は、様々な原因で発生します。データベースのクエリの最適化、キャッシュの活用、画像の最適化など、様々なテクニックを使用してパフォーマンスを改善することができます。

**事前準備と前提条件**

* 本番環境へのアクセス権
* Sitecore インスタンスへのアクセス権
* パフォーマンス監視ツール (例: New Relic, Dynatrace)

**基本的な使い方**

1. **パフォーマンス監視ツールの導入:** パフォーマンス監視ツールを導入し、Webサイトのパフォーマンスを継続的に監視します。
2. **ボトルネックの特定:** パフォーマンス監視ツールを使用して、パフォーマンスのボトルネックとなっている箇所を特定します。
3. **最適化:** ボトルネックとなっている箇所を最適化します。

**実践的なテクニック**

* **データベースのクエリの最適化:** データベースのクエリが遅い場合、クエリを最適化することでパフォーマンスを改善することができます。

   * インデックスの追加
   * クエリの書き換え
   * 不要なデータの取得を避ける

* **キャッシュの活用:** キャッシュを活用することで、データベースへのアクセスを減らし、パフォーマンスを改善することができます。

   * Sitecore のデータキャッシュ
   * HTML キャッシュ
   * ブラウザキャッシュ

* **画像の最適化:** 画像のサイズが大きい場合、画像を最適化することでページの読み込み時間を短縮することができます。

   * 画像の圧縮
   * 画像の形式の変更 (例: PNG から JPEG)
   * レスポンシブ画像の採用

**応用例とユースケース**

* **CDN の導入:** CDN (コンテンツデリバリーネットワーク) を導入することで、Webサイトのコンテンツを世界中のサーバーに分散し、ユーザーの場所に応じて最適なサーバーからコンテンツを配信することができます。
* **ロードバランサーの導入:** ロードバランサーを導入することで、複数のサーバーにトラフィックを分散し、単一のサーバーへの負荷を軽減することができます。

**トラブルシューティング**

* **Sitecore ログの確認:** Sitecore のログファイル (`/App_Data/logs`) を確認し、パフォーマンスに関するエラーメッセージがないかを確認します。
* **サーバーのリソース使用率の確認:** サーバーの CPU、メモリ、ディスクの使用率を確認します。リソースが不足している場合、サーバーのスケールアップを検討します。

**まとめと次のステップ**

パフォーマンスの問題は、様々な原因で発生します。パフォーマンス監視ツールを使用してボトルネックを特定し、データベースのクエリの最適化、キャッシュの活用、画像の最適化など、様々なテクニックを使用してパフォーマンスを改善してください。

次のステップとしては、Sitecore のセキュリティを強化する方法を学ぶことをお勧めします。

#### 19.2.2. セキュリティの問題

**概要と重要性**

Webサイトのセキュリティは、ユーザーの個人情報や企業の機密情報を保護するために非常に重要です。セキュリティの問題が発生すると、Webサイトが改ざんされたり、個人情報が漏洩したりする可能性があります。

**特徴と利点**

Sitecore は、様々なセキュリティ機能を提供しています。これらの機能を活用することで、Webサイトのセキュリティを強化することができます。

**事前準備と前提条件**

* 本番環境へのアクセス権
* Sitecore インスタンスへのアクセス権
* Web アプリケーションファイアウォール (WAF)

**基本的な使い方**

1. **セキュリティアップデートの適用:** Sitecore のセキュリティアップデートを定期的に適用し、脆弱性を修正します。
2. **パスワードポリシーの設定:** 強力なパスワードポリシーを設定し、ユーザーに安全なパスワードを使用するように促します。
3. **アクセス権の管理:** ユーザーのアクセス権を適切に管理し、不要なアクセスを制限します。

**実践的なテクニック**

* **XSS 対策:** XSS (クロスサイトスクリプティング) 攻撃を防ぐために、入力値を適切にエスケープします。

   ```csharp
   @Html.Encode(Model.Title)
   ```

* **SQL インジェクション対策:** SQL インジェクション攻撃を防ぐために、パラメーター化されたクエリを使用します。

   ```csharp
   // パラメーター化されたクエリの例
   SqlCommand command = new SqlCommand("SELECT * FROM Items WHERE ID = @ID");
   command.Parameters.AddWithValue("@ID", itemId);
   ```

* **CSRF 対策:** CSRF (クロスサイトリクエストフォージェリ) 攻撃を防ぐために、トークンを使用します。

   ```html
   @Html.AntiForgeryToken()
   ```

**応用例とユースケース**

* **Web アプリケーションファイアウォール (WAF) の導入:** WAF を導入することで、Webサイトへの悪意のあるトラフィックを検出し、ブロックすることができます。
* **侵入検知システム (IDS) の導入:** IDS を導入することで、Webサイトへの不正アクセスを検出し、アラートを発することができます。

**トラブルシューティング**

* **セキュリティスキャンの実施:** 定期的にセキュリティスキャンを実施し、Webサイトの脆弱性を検出します。
* **ログの監視:** Webサイトのログを監視し、不正なアクティビティがないかを確認します。

**まとめと次のステップ**

セキュリティの問題は、ユーザーの個人情報や企業の機密情報を保護するために非常に重要です。セキュリティアップデートの適用、パスワードポリシーの設定、アクセス権の管理など、様々なテクニックを使用して Webサイトのセキュリティを強化してください。

次のステップとしては、Sitecore Support やコミュニティを活用する方法を学ぶことをお勧めします。

#### 19.2.3. エラーログの分析

**概要と重要性**

エラーログは、Webサイトで発生したエラーに関する情報が記録されたファイルです。エラーログを分析することで、問題の原因を特定し、Webサイトの品質を向上させることができます。

**特徴と利点**

エラーログには、エラーが発生した日時、エラーの種類、エラーが発生した箇所などの情報が含まれています。これらの情報を分析することで、問題の原因を特定し、迅速に解決することができます。

**事前準備と前提条件**

* 本番環境へのアクセス権
* Sitecore インスタンスへのアクセス権
* エラーログファイル (`/App_Data/logs`)

**基本的な使い方**

1. **エラーログファイルの確認:** エラーログファイル (`/App_Data/logs`) を開き、エラーメッセージを確認します。
2. **エラーメッセージの分析:** エラーメッセージを分析し、エラーの原因を特定します。
3. **解決策の適用:** エラーの原因に基づいて、適切な解決策を適用します。

**実践的なテクニック**

* **ログレベルの調整:** Sitecore のログレベルを調整することで、エラーログに記録される情報の量を制御することができます。

   * `DEBUG`: 詳細な情報を記録します。開発環境でのデバッグに役立ちます。
   * `INFO`: 一般的な情報を記録します。
   * `WARN`: 警告メッセージを記録します。
   * `ERROR`: エラーメッセージを記録します。
   * `FATAL`: 致命的なエラーメッセージを記録します。

* **ログローテーションの設定:** ログローテーションを設定することで、エラーログファイルが肥大化するのを防ぐことができます。

**応用例とユースケース**

* **エラー監視ツールの導入:** エラー監視ツールを導入することで、エラーログを自動的に分析し、エラーが発生した場合にアラートを発することができます。
* **ログ分析サービスの利用:** ログ分析サービスを利用することで、大量のエラーログを効率的に分析し、問題の原因を特定することができます。

**トラブルシューティング**

* **エラーメッセージの意味の理解:** エラーメッセージの意味を理解することが、問題解決の第一歩です。Sitecore のドキュメントやコミュニティフォーラムなどを参照し、エラーメッセージの意味を調べてみてください。
* **再現性の確認:** エラーが再現可能かどうかを確認します。再現可能なエラーは、デバッグが容易です。

**まとめと次のステップ**

エラーログの分析は、Webサイトで発生した問題の原因を特定し、Webサイトの品質を向上させるために非常に重要です。エラーログファイルを定期的に確認し、エラーメッセージを分析し、適切な解決策を適用してください。
