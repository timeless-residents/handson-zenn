## 第1章：XM Cloud の概要と開発環境構築

### 1.1. XM Cloud とは？ - 最新のヘッドレスCMSアーキテクチャ

#### 概要と重要性

デジタルエクスペリエンスは、現代のビジネスにおいて顧客とのエンゲージメントを深め、ブランドロイヤリティを構築するための最重要要素の一つです。XM Cloudは、Sitecoreが提供する最新のSaaS型ヘッドレスCMSであり、コンテンツの作成、管理、そしてあらゆるチャネルへの配信を効率化し、パーソナライズされた顧客体験を実現するための強力なツールです。

従来のCMSとは異なり、XM Cloudはヘッドレスアーキテクチャを採用しています。これは、コンテンツの保存と管理を行うバックエンド（ヘッド）と、コンテンツを表示するフロントエンドを分離することを意味します。これにより、開発者は任意のフロントエンド技術（React, Angular, Vue.jsなど）を使用して、Webサイト、モバイルアプリ、IoTデバイスなど、多様なチャネルにコンテンツを柔軟に配信できます。

#### 特徴と利点

XM Cloudの主要な特徴と利点は以下の通りです。

*   **SaaS型:** インフラの管理やメンテナンスが不要で、常に最新の機能を利用できます。これにより、IT部門は運用負荷を軽減し、より戦略的な業務に集中できます。
*   **ヘッドレスアーキテクチャ:** コンテンツをチャネルに依存せずに管理できるため、将来的なチャネル拡張にも柔軟に対応できます。
*   **コンポーザブルエクスペリエンスプラットフォーム:**  豊富なAPIと統合機能により、他のマーケティングツールやシステムとの連携が容易です。これにより、顧客データの統合、パーソナライズされたコンテンツの配信、効果測定などがスムーズに行えます。
*   **Sitecore Experience Edge:** グローバルに分散されたCDNを通じて、高速かつ信頼性の高いコンテンツ配信を実現します。
*   **直感的なインターフェース:** コンテンツ作成者にとって使いやすいインターフェースを提供し、コンテンツの作成、編集、プレビューを効率的に行えます。
*   **パーソナライズ機能:** Sitecore Experience Platform (XP) と連携することで、顧客データに基づいた高度なパーソナライズされたコンテンツ配信が可能です。

#### コンポーザブルエクスペリエンスプラットフォームとしてのXM Cloud

XM Cloudは、単なるCMSではなく、コンポーザブルエクスペリエンスプラットフォーム（Composable Experience Platform, CXP）としての側面も持ち合わせています。これは、さまざまなマーケティングテクノロジーを組み合わせ、顧客のニーズに合わせて最適なエクスペリエンスを構築できることを意味します。

具体的には、以下のような要素を組み合わせて利用できます。

*   **CMS (XM Cloud):** コンテンツの作成、管理、配信
*   **CDP (Customer Data Platform):** 顧客データの収集、統合、分析
*   **DAM (Digital Asset Management):** 画像、動画、ドキュメントなどのデジタルアセット管理
*   **Personalization Engine:** パーソナライズされたコンテンツの配信
*   **Analytics:** 効果測定と改善

これらの要素を組み合わせることで、顧客一人ひとりに最適化されたエクスペリエンスを提供し、コンバージョン率の向上、顧客ロイヤリティの強化、ビジネス成果の最大化に貢献できます。

#### SaaS 型 CMS の利点とオンプレミス環境との違い

XM CloudはSaaS型CMSであるため、従来のオンプレミス環境と比較して多くの利点があります。

| 特徴             | SaaS型 (XM Cloud)                               | オンプレミス                                    |
| ---------------- | -------------------------------------------------- | ------------------------------------------------- |
| インフラ         | Sitecoreが管理                                 | ユーザーが管理                                |
| メンテナンス     | Sitecoreが実施                                 | ユーザーが実施                                |
| アップグレード     | 自動的に実施                                     | ユーザーが計画・実施                            |
| 初期費用         | 低い（サブスクリプションモデル）                      | 高い（サーバー、ソフトウェアライセンスなど）        |
| スケーラビリティ | 簡単かつ迅速                                      | 時間とコストがかかる                              |
| セキュリティ     | Sitecoreが責任を持つ                             | ユーザーが責任を持つ                             |
| 最新機能         | 常に最新の機能を利用可能                             | アップグレードが必要                             |

SaaS型CMSは、インフラの管理やメンテナンスの負担を軽減し、常に最新の機能を利用できるため、ビジネスの俊敏性を高めることができます。

#### 実務での具体的なユースケース

*   **グローバル企業の多言語サイト管理:** XM Cloudは多言語サイトの管理を効率化し、各地域のユーザーに合わせたコンテンツを提供できます。
*   **eコマースサイトのコンテンツマーケティング:** 商品情報、ブログ記事、動画などのコンテンツを柔軟に作成・配信し、顧客エンゲージメントを高めることができます。
*   **パーソナライズされたニュースサイト:** 顧客の興味関心に基づいてパーソナライズされたニュース記事を提供し、ユーザーの滞在時間を伸ばすことができます。
*   **金融機関の顧客ポータル:** 顧客一人ひとりのニーズに合わせた情報を提供し、顧客満足度を高めることができます。

#### まとめと次のステップ

XM Cloudは、最新のヘッドレスアーキテクチャを採用したSaaS型CMSであり、コンテンツの作成、管理、配信を効率化し、パーソナライズされた顧客体験を実現するための強力なツールです。次のセクションでは、XM Cloudを利用するために必要なアカウントとライセンスの準備について解説します。

### 1.2. 必要なアカウントとライセンスの準備

#### 概要と重要性

XM Cloudを利用するためには、いくつかの必要なアカウントとライセンスを取得する必要があります。これらは、Sitecore Cloud Portalへのアクセス、XM Cloud Deploy環境の設定、およびGitHubリポジトリとの連携に必要となります。

#### 事前準備と前提条件

*   有効なメールアドレス
*   クレジットカード情報（ライセンス購入の場合）
*   GitHubアカウント（無料プランでも可）

#### Sitecore Cloud Portal のアカウント作成とライセンス取得

1.  **Sitecore Cloud Portalへのアクセス:** Sitecoreの公式ウェブサイトからCloud Portalにアクセスします。通常、営業担当者またはパートナー経由で招待されるか、トライアル版を申し込むことができます。

2.  **アカウントの作成:** 必要な情報（氏名、メールアドレス、会社名など）を入力してアカウントを作成します。

3.  **メール認証:** 登録したメールアドレスに送信される認証メールに記載されたリンクをクリックして、アカウントを有効化します。

4.  **ライセンスの取得:** Cloud Portalにログインし、必要なXM Cloudライセンスを購入またはアクティベートします。トライアル版の場合は、トライアル期間と利用可能な機能を確認します。

#### XM Cloud Deploy アカウントの作成

XM Cloud Deployは、XM Cloudのデプロイメントパイプラインを管理するためのサービスです。通常、Sitecore Cloud Portalから自動的にプロビジョニングされますが、必要に応じて手動で作成することもできます。

1.  **Cloud Portalにログイン:** 作成したアカウントでCloud Portalにログインします。
2.  **XM Cloud Deployへのアクセス:** Cloud Portal内のXM CloudセクションからXM Cloud Deployにアクセスします。
3.  **アカウントの確認:** XM Cloud Deployに自動的にアカウントが作成されていることを確認します。もし作成されていない場合は、Sitecoreサポートに問い合わせてください。

#### GitHub アカウントの準備

XM CloudプロジェクトはGitHubリポジトリと連携して管理されます。そのため、GitHubアカウントが必要です。

1.  **GitHubウェブサイトへのアクセス:** GitHubの公式ウェブサイト（[https://github.com/](https://github.com/)）にアクセスします。
2.  **アカウントの作成:** 必要な情報（ユーザー名、メールアドレス、パスワード）を入力してアカウントを作成します。無料プランでもXM Cloudプロジェクトの管理には十分です。
3.  **SSHキーの設定（推奨）:** GitHubとの連携をより安全に行うために、SSHキーを設定することを推奨します。設定方法はGitHubのドキュメントを参照してください。

#### 実践的なテクニック

*   **ライセンスの有効期限管理:** Sitecore Cloud Portalでライセンスの有効期限を定期的に確認し、期限切れにならないように注意してください。
*   **GitHub Two-Factor Authentication (2FA) の有効化:** GitHubアカウントのセキュリティを強化するために、Two-Factor Authenticationを有効にすることを強く推奨します。

#### トラブルシューティング

*   **アカウント作成時のエラー:** 入力した情報が正しいか確認してください。また、メールアドレスがすでに登録されていないか確認してください。
*   **ライセンスのアクティベーションエラー:** Sitecoreサポートに問い合わせてください。
*   **XM Cloud Deployへのアクセスエラー:** Sitecore Cloud PortalからXM Cloud Deployへのアクセス権限があるか確認してください。

#### まとめと次のステップ

### 1.3. 開発環境のセットアップ

#### 概要と重要性

XM Cloudアプリケーションの開発には、適切な開発環境のセットアップが不可欠です。このセクションでは、必要なソフトウェアのインストールと設定について詳しく解説します。

#### 事前準備と前提条件

*   OS: Windows 10/11, macOS, Linux
*   インターネット接続

#### Node.js と npm (または yarn) のインストール

Node.jsは、JavaScriptの実行環境であり、XM Cloud開発に必要なツールやライブラリをインストールするために使用されます。npm (Node Package Manager) または yarn は、Node.jsのパッケージ管理ツールです。

1.  **Node.jsのダウンロード:** Node.jsの公式ウェブサイト（[https://nodejs.org/](https://nodejs.org/)）から、お使いのOSに合ったインストーラーをダウンロードします。LTS (Long Term Support) 版を推奨します。

2.  **Node.jsのインストール:** ダウンロードしたインストーラーを実行し、画面の指示に従ってNode.jsをインストールします。インストール時に、npm (または yarn) も自動的にインストールされます。

3.  **Node.jsとnpmのバージョン確認:** コマンドプロンプトまたはターミナルを開き、以下のコマンドを実行して、Node.jsとnpmが正しくインストールされていることを確認します。

    ```bash
    node -v
    npm -v
    ```

    バージョン番号が表示されれば、インストールは成功です。

4.  **yarnのインストール (npmを使用する場合):** yarnを使用する場合は、以下のコマンドを実行してyarnをグローバルにインストールします。

    ```bash
    npm install -g yarn
    ```

    yarnのバージョンを確認するには、以下のコマンドを実行します。

    ```bash
    yarn -v
    ```

#### Sitecore CLI のインストールと初期設定

Sitecore CLI (Command Line Interface) は、XM Cloudプロジェクトの作成、デプロイメント、およびその他の管理タスクを実行するためのコマンドラインツールです。

1.  **Sitecore CLIのインストール:** コマンドプロンプトまたはターミナルを開き、以下のコマンドを実行してSitecore CLIをグローバルにインストールします。

    ```bash
    npm install -g @sitecore/cli
    ```

2.  **Sitecore CLIのバージョン確認:** 以下のコマンドを実行して、Sitecore CLIが正しくインストールされていることを確認します。

    ```bash
    sitecore --version
    ```

    バージョン番号が表示されれば、インストールは成功です。

3.  **Sitecore CLIのログイン:** Sitecore CLIを使用してXM Cloudにログインします。以下のコマンドを実行し、ブラウザが開いたら、Sitecore Cloud Portalのアカウントでログインします。

    ```bash
    sitecore login
    ```

    ログインが成功すると、認証情報がローカルに保存されます。

4.  **プラグインのインストール:** XM Cloud開発に必要なプラグインをインストールします。

    ```bash
    sitecore plugin add @sitecore/cli-xmcloud
    ```

    XM Cloud Pluginがインストールされているか確認します。

    ```bash
    sitecore plugin list
    ```

#### Docker Desktop のインストールと設定

Docker Desktopは、コンテナ型の仮想環境を提供し、XM Cloudアプリケーションのローカル開発を支援します。

1.  **Docker Desktopのダウンロード:** Docker Desktopの公式ウェブサイト（[https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)）から、お使いのOSに合ったインストーラーをダウンロードします。

2.  **Docker Desktopのインストール:** ダウンロードしたインストーラーを実行し、画面の指示に従ってDocker Desktopをインストールします。

3.  **Docker Desktopの起動:** インストールが完了したら、Docker Desktopを起動します。初回起動時には、管理者権限が必要となる場合があります。

4.  **Docker Desktopの設定:** Docker Desktopの設定を変更し、必要なリソース（メモリ、CPUなど）を割り当てます。特に、メモリの割り当てはXM Cloudアプリケーションのパフォーマンスに影響するため、十分に確保することを推奨します。通常、4GB以上のメモリを割り当てることを推奨します。

5.  **Docker Desktopの動作確認:** コマンドプロンプトまたはターミナルを開き、以下のコマンドを実行して、Docker Desktopが正しく動作していることを確認します。

    ```bash
    docker version
    docker ps
    ```

    バージョン情報が表示され、コンテナが実行されていれば、Docker Desktopは正しく動作しています。

#### 実践的なテクニック

*   **Node.jsのバージョン管理:** nvm (Node Version Manager) を使用して、複数のNode.jsバージョンを簡単に切り替えることができます。

    ```bash
    nvm install 16
    nvm use 16
    ```

*   **Docker Desktopのトラブルシューティング:** Docker Desktopが起動しない場合や、コンテナの実行に問題がある場合は、Docker Desktopのログを確認してください。

#### トラブルシューティング

*   **Sitecore CLIのインストールエラー:** npmのキャッシュをクリアしてから再度インストールしてみてください。

    ```bash
    npm cache clean -f
    npm install -g @sitecore/cli
    ```

*   **Docker Desktopの起動エラー:** Docker Desktopに必要な仮想化機能が有効になっているか確認してください。Windowsの場合は、Hyper-Vが有効になっていることを確認してください。macOSの場合は、Virtualization.Frameworkが有効になっていることを確認してください。

#### まとめと次のステップ

このセクションでは、XM Cloudアプリケーションの開発に必要な開発環境のセットアップについて解説しました。次のセクションでは、Sitecore CLIを使用してXM Cloudプロジェクトを作成し、初期化する方法について解説します。

### 1.4. プロジェクトの作成と初期化

#### 概要と重要性

開発環境のセットアップが完了したら、Sitecore CLIを使用してXM Cloudプロジェクトを作成し、初期化します。このプロセスでは、必要なファイルとディレクトリが生成され、開発を開始するための基本的な構造が確立されます。

#### 事前準備と前提条件

*   開発環境のセットアップが完了していること（Node.js, npm, Sitecore CLI, Docker Desktop）
*   GitHubアカウントが準備できていること

#### Sitecore CLI を使った XM Cloud プロジェクトの初期化

1.  **プロジェクトの作成:** コマンドプロンプトまたはターミナルを開き、プロジェクトを作成するディレクトリに移動します。以下のコマンドを実行して、XM Cloudプロジェクトを作成します。`<プロジェクト名>` は、プロジェクトの名前です。

    ```bash
    sitecore xmcloud init <プロジェクト名>
    ```

    このコマンドを実行すると、いくつかの質問が表示されます。

    *   **Template:** テンプレートを選択します。`nextjs` を選択することを推奨します。
    *   **Project name:** プロジェクト名を入力します。
    *   **Solution path:** ソリューションのパスを入力します。通常はデフォルトの `.` で問題ありません。
    *   **Sitecore Hostname:** Sitecoreのホスト名を入力します。トライアル環境の場合は、デフォルトの `xmcloudcm.localhost` で問題ありません。
    *   **Admin password:** Sitecoreの管理者パスワードを入力します。

2.  **プロジェクトの初期化:** プロジェクトの作成が完了したら、プロジェクトのディレクトリに移動し、以下のコマンドを実行してプロジェクトを初期化します。

    ```bash
    cd <プロジェクト名>
    npm install
    ```

    このコマンドは、プロジェクトに必要なすべてのnpmパッケージをインストールします。

3.  **Dockerコンテナの起動:** プロジェクトの初期化が完了したら、以下のコマンドを実行してDockerコンテナを起動します。

    ```bash
    docker-compose up -d
    ```

    このコマンドは、必要なすべてのDockerコンテナをバックグラウンドで起動します。初回起動時には、イメージのダウンロードに時間がかかる場合があります。

4.  **Sitecoreの起動確認:** Dockerコンテナの起動が完了したら、ブラウザを開き、`https://xmcloudcm.localhost/sitecore` にアクセスします。Sitecoreのログイン画面が表示されれば、プロジェクトの初期化は成功です。

#### GitHub リポジトリの作成と連携

1.  **GitHubリポジトリの作成:** GitHubのウェブサイトにアクセスし、新しいリポジトリを作成します。リポジトリの名前は、プロジェクト名と同じにすることを推奨します。

    *   **Repository name:** リポジトリの名前を入力します。
    *   **Description:** リポジトリの説明を入力します（オプション）。
    *   **Public/Private:** リポジトリの公開範囲を選択します。
    *   **Initialize this repository with a README:** チェックを外します。
    *   **Add .gitignore:** `Node` を選択します。
    *   **Choose a license:** ライセンスを選択します（オプション）。

2.  **ローカルリポジトリの初期化:** プロジェクトのディレクトリで、以下のコマンドを実行してローカルリポジトリを初期化します。

    ```bash
    git init
    ```

3.  **.gitignoreファイルの作成:** プロジェクトのディレクトリに、`.gitignore` ファイルを作成し、以下の内容を追加します。

    ```
    node_modules/
    .env
    ```

    これにより、`node_modules` ディレクトリと `.env` ファイルがGitHubリポジトリにコミットされるのを防ぎます。

4.  **ファイルの追加とコミット:** 以下のコマンドを実行して、プロジェクトのファイルをローカルリポジトリに追加し、コミットします。

    ```bash
    git add .
    git commit -m "Initial commit"
    ```

5.  **リモートリポジトリとの連携:** 以下のコマンドを実行して、ローカルリポジトリをGitHubのリモートリポジトリに連携します。`<GitHubのユーザー名>` はGitHubのユーザー名、`<リポジトリ名>` はリポジトリの名前です。

    ```bash
    git remote add origin https://github.com/<GitHubのユーザー名>/<リポジトリ名>.git
    git branch -M main
    git push -u origin main
    ```

    これにより、ローカルリポジトリの変更がGitHubのリモートリポジトリにプッシュされます。

#### 実践的なテクニック

*   **`.env` ファイルの管理:** 環境変数を `.env` ファイルに保存し、Gitで管理しないようにしてください。`.env` ファイルは、`.gitignore` ファイルに追加することを推奨します。
*   **ブランチ戦略:** 開発、ステージング、本番環境に対応したブランチ戦略を採用することを推奨します。例えば、`develop` ブランチで開発を行い、`main` ブランチにマージしてリリースすることができます。
*   **CI/CDパイプラインの構築:** GitHub ActionsなどのCI/CDツールを使用して、自動的なビルド、テスト、デプロイメントパイプラインを構築することを推奨します。

#### トラブルシューティング

*   **`docker-compose up -d` コマンドのエラー:** Docker Desktopが正しく起動しているか確認してください。また、必要なDockerイメージがダウンロードされているか確認してください。
*   **GitHubへのプッシュエラー:** GitHubのリモートリポジトリのURLが正しいか確認してください。また、GitHubアカウントの認証情報が正しいか確認してください。
