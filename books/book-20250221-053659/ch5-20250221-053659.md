## 第5章：コンポーネント開発の基本

この章では、ReactとSitecoreを組み合わせたコンポーネント開発の基礎を解説します。再利用可能で保守性の高いコンポーネントを設計・実装するための原則、Sitecoreとの統合方法、コンテンツ編集やテストの方法まで、実践的な知識を習得することを目指します。

### 5.1. React コンポーネントの設計と実装

#### 5.1.1. 概要と重要性

Reactコンポーネントは、UIを構築するための基本的な構成要素です。再利用可能なコンポーネントを設計することで、開発効率が向上し、アプリケーション全体の保守性が高まります。

#### 5.1.2. 特徴と利点

*   **再利用性:** 同じコンポーネントを複数の場所で使用できます。
*   **モジュール性:** コンポーネントごとに独立した機能を提供します。
*   **保守性:** 変更の影響範囲を局所化できます。
*   **テスト容易性:** コンポーネント単位でテストできます。

#### 5.1.3. 事前準備と前提条件

*   Node.jsとnpm（またはyarn）がインストールされていること。
*   基本的なJavaScript（ES6+）の知識があること。
*   Reactの基本的な概念（コンポーネント、props、state）を理解していること。

#### 5.1.4. 基本的な使い方

Reactコンポーネントは、関数コンポーネントまたはクラスコンポーネントとして定義できます。

**関数コンポーネント（Hooksを使用）**

```javascript
import React, { useState } from 'react';

function MyComponent(props) {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>Hello, {props.name}!</h1>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

export default MyComponent;
```

**クラスコンポーネント（非推奨だがレガシーコードでよく見られる）**

```javascript
import React from 'react';

class MyComponent extends React.Component {
  constructor(props) {
    super(props);
    this.state = {
      count: 0
    };
  }

  handleClick = () => {
    this.setState({ count: this.state.count + 1 });
  }

  render() {
    return (
      <div>
        <h1>Hello, {this.props.name}!</h1>
        <p>Count: {this.state.count}</p>
        <button onClick={this.handleClick}>Increment</button>
      </div>
    );
  }
}

export default MyComponent;
```

#### 5.1.5. 実践的なテクニック

*   **propsの型定義:** TypeScriptを使用してpropsの型を定義することで、コンポーネントの誤用を防ぎます。

```typescript
interface MyComponentProps {
  name: string;
}

function MyComponent(props: MyComponentProps) {
  // ...
}
```

*   **コンポーネントの分割:** 大きなコンポーネントは、より小さなコンポーネントに分割することで、再利用性と保守性を高めます。
*   **Styled ComponentsまたはCSS Modules:**  コンポーネント固有のスタイルを定義することで、スタイルの衝突を防ぎます。

```javascript
// Styled Componentsの例
import styled from 'styled-components';

const StyledButton = styled.button`
  background-color: blue;
  color: white;
  padding: 10px 20px;
  border: none;
  cursor: pointer;
`;

function MyComponent(props) {
  return (
    <div>
      <StyledButton onClick={props.onClick}>{props.children}</StyledButton>
    </div>
  );
}
```

#### 5.1.6. 応用例とユースケース

*   **ボタンコンポーネント:** 様々なスタイルやサイズのボタンを定義し、アプリケーション全体で再利用します。
*   **入力フォームコンポーネント:** テキスト入力、セレクトボックス、チェックボックスなどの入力フィールドを統一的に管理します。
*   **カードコンポーネント:** 商品情報や記事の概要を表示するために使用します。

#### 5.1.7. トラブルシューティング

*   **Propsが正しく渡されていない:** 親コンポーネントから子コンポーネントにpropsが正しく渡されているか確認します。TypeScriptを使用していれば、型チェックでエラーを発見できます。
*   **Stateが正しく更新されない:** `setState`またはuseStateのsetter関数を使用する際に、イミュータブルな方法で状態を更新する必要があります。オブジェクトや配列を直接変更せず、スプレッド構文などを使用します。
*   **パフォーマンスの問題:** 不要な再レンダリングが発生していないか確認します。`React.memo`や`useMemo`、`useCallback`などのHooksを使用して最適化します。

#### 5.1.8. まとめと次のステップ

Reactコンポーネントの設計と実装は、高品質なUIを構築するための基礎です。props、state、イベントハンドリングを理解し、再利用可能なコンポーネントを作成するスキルを磨きましょう。次のステップでは、これらのコンポーネントをSitecoreと統合する方法を学びます。

### 5.2. Sitecore コンポーネントの作成

#### 5.2.1. 概要と重要性

Sitecoreコンポーネントは、コンテンツを動的に表示するための重要な要素です。ReactコンポーネントをSitecoreコンポーネントとして統合することで、柔軟なコンテンツ管理とリッチなUIを両立できます。

#### 5.2.2. 特徴と利点

*   **コンテンツの柔軟性:** SitecoreのCMS機能を使用して、コンテンツを柔軟に管理できます。
*   **パーソナライズ:** Sitecoreのパーソナライズ機能を使用して、ユーザーに合わせたコンテンツを表示できます。
*   **A/Bテスト:** SitecoreのA/Bテスト機能を使用して、異なるコンテンツのパフォーマンスを比較できます。

#### 5.2.3. 事前準備と前提条件

*   Sitecoreインスタンスが稼働していること。
*   Sitecore JavaScript Rendering SDK (JSS) がインストールされていること。
*   JSSアプリケーションが設定されていること。
*   Sitecoreの基本的な知識（テンプレート、アイテム、レイアウト）があること。

#### 5.2.4. 基本的な使い方

1.  **Sitecore Content Editor でレンダリング定義を作成:**
    *   Sitecore Content Editorを開き、`/sitecore/layout/Renderings` 配下に新しいレンダリングアイテムを作成します。
    *   レンダリングアイテムの種類として、`Controller rendering` または `View rendering` を選択します。JSSを使用する場合は、`Rendering` を選択し、`Component Name` にReactコンポーネントの名前（ファイル名）を設定します。
    *   `Data Source Template` フィールドに、データソーステンプレートを指定します。

2.  **データソーステンプレートの作成:**
    *   Sitecore Content Editorを開き、`/sitecore/templates/User Defined` 配下に新しいテンプレートを作成します。
    *   テンプレートに、Reactコンポーネントで表示するコンテンツに必要なフィールドを追加します。例：`Title (Single-Line Text)`、`Description (Multi-Line Text)`、`Image (Image)`。

3.  **React コンポーネントと Sitecore コンポーネントの紐付け:**
    *   JSSアプリケーションのReactコンポーネントファイル（例：`MyComponent.tsx`）を作成または編集します。
    *   `@sitecore-jss/sitecore-jss-react` パッケージから `Text`、`Image` などのフィールドレンダリングコンポーネントをインポートします。
    *   データソースから取得したコンテンツを、これらのフィールドレンダリングコンポーネントを使用して表示します。

```typescript
import React from 'react';
import { Text, Image, Field } from '@sitecore-jss/sitecore-jss-react';

interface MyComponentProps {
  fields: {
    Title: Field<string>;
    Description: Field<string>;
    Image: Field<{
      src: string;
      alt: string;
    }>;
  };
}

function MyComponent(props: MyComponentProps) {
  return (
    <div>
      <h2><Text field={props.fields.Title} /></h2>
      <p><Text field={props.fields.Description} /></p>
      <Image field={props.fields.Image} />
    </div>
  );
}

export default MyComponent;
```

#### 5.2.5. 実践的なテクニック

*   **GraphQL を使用したデータ取得:** Sitecore GraphQL API を使用して、必要なデータのみを取得することで、パフォーマンスを向上させます。

```graphql
query MyComponentQuery($contextItem: String!) {
  item(path: $contextItem, language: "en") {
    Title: field(fieldName: "Title") {
      value
    }
    Description: field(fieldName: "Description") {
      value
    }
    Image: field(fieldName: "Image") {
      value {
        src
        alt
      }
    }
  }
}
```

*   **Layout Service Context:**  `useSitecoreContext` Hookを使用して、Sitecoreのコンテキスト情報（言語、編集モードなど）を取得し、コンポーネントの動作を制御します。

```typescript
import { useSitecoreContext } from '@sitecore-jss/sitecore-jss-react';

function MyComponent(props: MyComponentProps) {
  const { sitecoreContext } = useSitecoreContext();
  const isExperienceEditor = sitecoreContext.pageState === 'edit';

  return (
    <div>
      <h2><Text field={props.fields.Title} editable={isExperienceEditor} /></h2>
      {/* エクスペリエンスエディタで編集可能な場合のみ editable を true にする */}
    </div>
  );
}
```

#### 5.2.6. 応用例とユースケース

*   **ニュースリストコンポーネント:** Sitecoreのニュース記事をリスト形式で表示します。
*   **カルーセルコンポーネント:** Sitecoreの画像をカルーセル形式で表示します。
*   **フォームコンポーネント:** Sitecore Formsを使用して、フォームを作成し、Reactコンポーネントとして表示します。

#### 5.2.7. トラブルシューティング

*   **コンポーネントが表示されない:**
    *   Sitecore Content Editorでレンダリング定義が正しく設定されているか確認します。
    *   Reactコンポーネントが正しく実装され、エラーが発生していないか確認します。
    *   JSSアプリケーションの設定ファイル (`sitecore.config`) が正しいか確認します。
*   **データが表示されない:**
    *   データソーステンプレートに、必要なフィールドが含まれているか確認します。
    *   Reactコンポーネントで、データソースから正しくデータを取得しているか確認します。
    *   Sitecore GraphQL API が正しく設定されているか確認します。
*   **エクスペリエンスエディタで編集できない:**
    *   Reactコンポーネントで、`editable` プロパティを適切に設定しているか確認します。
    *   Sitecoreの編集モードが有効になっているか確認します。

#### 5.2.8. まとめと次のステップ

Sitecoreコンポーネントの作成は、Sitecoreの強力なコンテンツ管理機能とReactの柔軟なUI開発能力を組み合わせるための鍵です。レンダリング定義、データソーステンプレート、Reactコンポーネントの連携を理解し、様々なコンポーネントを作成するスキルを磨きましょう。次のステップでは、フィールドエディタとエクスペリエンスエディタの利用方法を学びます。

### 5.3. フィールドエディタとエクスペリエンスエディタの利用

#### 5.3.1. 概要と重要性

フィールドエディタとエクスペリエンスエディタは、Sitecoreのコンテンツ編集機能の中核を担います。これらのツールを使いこなすことで、コンテンツ作成者は直感的かつ効率的にコンテンツを編集し、レイアウトを調整できます。

#### 5.3.2. 特徴と利点

*   **直感的な編集:** WYSIWYGエディタで、視覚的にコンテンツを編集できます。
*   **リアルタイムプレビュー:** 編集内容をリアルタイムで確認できます。
*   **ドラッグ＆ドロップ:** コンポーネントをドラッグ＆ドロップで配置できます。
*   **パーソナライズ編集:** 特定のユーザーセグメント向けのコンテンツを編集できます。
*   **バージョン管理:** コンテンツの変更履歴を管理できます。

#### 5.3.3. 事前準備と前提条件

*   Sitecoreインスタンスが稼働していること。
*   Sitecore Content Editorとエクスペリエンスエディタへのアクセス権があること。
*   Sitecoreコンポーネントが作成済みであること。

#### 5.3.4. 基本的な使い方

1.  **フィールドエディタを使用したコンテンツの編集:**
    *   Sitecore Content Editorで、コンテンツアイテムを開きます。
    *   各フィールドの値を編集します。
    *   保存ボタンをクリックして変更を保存します。

2.  **エクスペリエンスエディタでのコンポーネントの配置とカスタマイズ:**
    *   エクスペリエンスエディタを開き、編集したいページを選択します。
    *   コンポーネントを追加するには、ツールボックスからコンポーネントをドラッグ＆ドロップします。
    *   コンポーネントをカスタマイズするには、コンポーネントを選択し、サイドバーのプロパティを編集します。
    *   ページを保存して変更を反映します。

3.  **プレースホルダーの設定と利用:**
    *   Sitecore Content Editorで、レイアウト定義を開きます。
    *   プレースホルダーを追加するには、`<sc:Placeholder>` タグを使用します。
        *   `<sc:Placeholder Key="main" runat="server" />`
    *   エクスペリエンスエディタで、プレースホルダーにコンポーネントを配置できます。

#### 5.3.5. 実践的なテクニック

*   **Placeholder Settings:**  プレースホルダーに配置できるコンポーネントを制限します。
    *   `/sitecore/layout/Placeholder Settings` 配下に設定アイテムを作成します。
    *   `Allowed Controls` フィールドに、許可するコンポーネントを指定します。
*   **Partial Designs:**  再利用可能なレイアウトセクションを作成します。
    *   `/sitecore/layout/Partial Designs` 配下に Partial Design アイテムを作成します。
    *   コンポーネントを配置し、レイアウトを定義します。
    *   ページに Partial Design をアタッチします。
*   **Personalization Rules:**  特定のユーザーセグメントに異なるコンテンツを表示します。
    *   エクスペリエンスエディタで、コンポーネントを選択し、`Personalize` ボタンをクリックします。
    *   ルールを設定し、異なるコンテンツを設定します。

#### 5.3.6. 応用例とユースケース

*   **ランディングページの作成:**  エクスペリエンスエディタを使用して、様々なコンポーネントを組み合わせ、魅力的なランディングページを作成します。
*   **コンテンツのパーソナライズ:**  ユーザーの行動履歴や属性に基づいて、コンテンツをパーソナライズします。
*   **キャンペーンの実施:**  A/Bテスト機能を使用して、異なるコンテンツのパフォーマンスを比較し、最適なコンテンツを特定します。

#### 5.3.7. トラブルシューティング

*   **コンポーネントがツールボックスに表示されない:**
    *   レンダリング定義が正しく設定されているか確認します。
    *   `Allowed Controls` 設定で、コンポーネントが許可されているか確認します。
*   **コンポーネントがエクスペリエンスエディタで編集できない:**
    *   `editable` プロパティが正しく設定されているか確認します。
    *   Sitecoreの編集モードが有効になっているか確認します。
*   **プレースホルダーにコンポーネントを配置できない:**
    *   プレースホルダーが正しく定義されているか確認します。
    *   `Allowed Controls` 設定で、コンポーネントが許可されているか確認します。

#### 5.3.8. まとめと次のステップ

フィールドエディタとエクスペリエンスエディタは、コンテンツ作成者にとって強力なツールです。これらのツールを使いこなすことで、コンテンツの作成、編集、パーソナライズを効率的に行うことができます。次のステップでは、コンポーネントのバリデーションとテストの方法を学びます。

### 5.4. コンポーネントのバリデーションとテスト

#### 5.4.1. 概要と重要性

コンポーネントのバリデーションとテストは、アプリケーションの品質を保証するために不可欠です。TypeScriptを使用した型チェック、JestとReact Testing Libraryを使用したユニットテスト、E2Eテストの導入により、コンポーネントの信頼性を高めることができます。

#### 5.4.2. 特徴と利点

*   **早期エラー発見:** 型チェックやユニットテストにより、開発段階でエラーを発見できます。
*   **リファクタリングの安全性:** テストスイートがあることで、リファクタリング時のバグ混入を防ぎます。
*   **品質保証:** バリデーションとテストにより、アプリケーションの品質を保証します。
*   **自動化:** テストを自動化することで、継続的な品質チェックが可能になります。

#### 5.4.3. 事前準備と前提条件

*   Node.jsとnpm（またはyarn）がインストールされていること。
*   TypeScriptの基本的な知識があること。
*   JestとReact Testing Libraryがインストールされていること。
*   E2Eテストフレームワーク（例：Cypress）がインストールされていること。

#### 5.4.4. 基本的な使い方

1.  **TypeScript を使用した型チェック:**
    *   `tsconfig.json` ファイルを設定し、TypeScriptコンパイラを有効にします。
    *   インターフェースを使用して、propsとstateの型を定義します。

```typescript
interface MyComponentProps {
  name: string;
  age: number;
}

function MyComponent(props: MyComponentProps) {
  return (
    <div>
      <h1>Hello, {props.name}!</h1>
      <p>Age: {props.age}</p>
    </div>
  );
}
```

2.  **Jest と React Testing Library を使用したユニットテスト:**
    *   Jestを設定し、React Testing Libraryをインストールします。
    *   コンポーネントの動作をテストするテストケースを作成します。

```javascript
import React from 'react';
import { render, screen } from '@testing-library/react';
import MyComponent from './MyComponent';

test('renders MyComponent with props', () => {
  render(<MyComponent name="John" age={30} />);
  const headingElement = screen.getByText(/Hello, John!/i);
  const ageElement = screen.getByText(/Age: 30/i);
  expect(headingElement).toBeInTheDocument();
  expect(ageElement).toBeInTheDocument();
});
```

3.  **E2E テストの導入:**
    *   CypressなどのE2Eテストフレームワークをインストールします。
    *   実際のブラウザ環境で、アプリケーション全体の動作をテストするテストケースを作成します。

```javascript
// cypress/integration/my_component.spec.js
describe('MyComponent E2E Test', () => {
  it('visits the page and verifies the component', () => {
    cy.visit('/my-page'); // アプリケーションのURL
    cy.contains('Hello, John!').should('be.visible');
    cy.contains('Age: 30').should('be.visible');
  });
});
```

#### 5.4.5. 実践的なテクニック

*   **テスト駆動開発 (TDD):**  テストケースを先に作成し、テストが成功するようにコンポーネントを実装します。
*   **モックの利用:**  外部APIや依存関係をモックすることで、コンポーネントの独立性を保ちます。
*   **カバレッジレポート:**  テストカバレッジツールを使用して、テストされていないコードを特定します。

#### 5.4.6. 応用例とユースケース

*   **フォームのバリデーション:**  入力フィールドのバリデーションルールをテストします。
*   **APIとの連携:**  APIからのデータ取得と表示をテストします。
*   **ユーザーインタラクション:**  ボタンクリックやフォーム送信などのユーザーインタラクションをテストします。

#### 5.4.7. トラブルシューティング

*   **テストが失敗する:**
    *   コンポーネントの動作が期待どおりであるか確認します。
    *   テストケースが正しく記述されているか確認します。
    *   モックが正しく設定されているか確認します。
*   **カバレッジが低い:**
    *   テストケースを追加し、コードの網羅率を高めます。
    *   条件分岐や例外処理など、テストされていない部分を重点的にテストします。

#### 5.4.8. まとめと次のステップ

コンポーネントのバリデーションとテストは、高品質なアプリケーションを開発するために不可欠です。TypeScriptを使用した型チェック、JestとReact Testing Libraryを使用したユニットテスト、E2Eテストを導入し、コンポーネントの信頼性を高めましょう。
