## 第2章 Sitecore SXA Starter JSSプロジェクトの構築

この章では、Sitecore Experience Accelerator (SXA) と Sitecore JavaScript Services (JSS) を組み合わせて、スケーラブルでメンテナンス性の高いプロジェクトを構築する方法を解説します。SXAの強力なドラッグ＆ドロップ機能とJSSの柔軟性を組み合わせることで、フロントエンド開発の効率を大幅に向上させることができます。初心者の方にも分かりやすいように、基本的な概念から応用的なテクニックまで、段階的に説明していきます。

### 2.1. JSS アプリケーションの構成

#### 概要と重要性

JSSアプリケーションの構成は、プロジェクトの基盤となる部分です。適切な構成を行うことで、開発効率の向上、コードの再利用性の向上、テストの容易性の向上など、様々なメリットが得られます。特にSXA環境下では、SXAの機能とJSSのアーキテクチャを調和させることが重要になります。

#### 特徴と利点

*   **コンポーネントベースのアーキテクチャ:** JSSはコンポーネントベースで構築されており、UIを小さな再利用可能な部品に分割できます。
*   **疎結合:** JSSアプリケーションはSitecoreインスタンスから疎結合であるため、フロントエンド開発者はSitecoreのデプロイサイクルに依存せずに作業できます。
*   **ヘッドレスCMS:** JSSはヘッドレスCMSとして機能するため、様々なチャネル（ウェブサイト、モバイルアプリ、IoTデバイスなど）にコンテンツを配信できます。
*   **開発効率の向上:** 既存のJavaScriptフレームワーク（React, Angular, Vue.js）を活用できるため、開発者は使い慣れたツールと技術で開発できます。

#### 事前準備と前提条件

*   Sitecoreインスタンスのインストールと構成（SXAとJSSモジュールを含む）
*   Node.jsとnpm (または yarn) のインストール
*   Sitecore CLIのインストール (`npm install -g @sitecore/cli`)
*   JSS CLIのインストール (`npm install -g @sitecore/jss-cli`)
*   JavaScriptの開発経験 (React, Angular, Vue.js いずれか)

#### 基本的な使い方

1.  **JSSアプリケーションの作成:**

    まず、JSS CLIを使用して新しいアプリケーションを作成します。

    ```bash
    jss create my-sxa-jss-app react -t sitecore-sxa-react
    ```

    `-t sitecore-sxa-react`は、SXA対応のReactテンプレートを指定するオプションです。AngularやVue.jsを選択する場合は、テンプレート名を適宜変更してください。

2.  **Sitecoreへの接続:**

    JSSアプリケーションをSitecoreインスタンスに接続します。`sitecore/config/config.json` ファイルを編集し、SitecoreインスタンスのURL、APIキー、デプロイパスなどを設定します。

    ```json
    {
      "sitecore": {
        "instanceUri": "https://your-sitecore-instance.local",
        "apiKey": "{YOUR-API-KEY}",
        "deploySecret": "your-deploy-secret"
      }
    }
    ```

    `YOUR-API-KEY`は、Sitecoreで作成したAPIキーのIDに置き換えてください。`your-deploy-secret` は、任意に設定したデプロイメントシークレットです。

3.  **Sitecoreへのデプロイ:**

    JSSアプリケーションをSitecoreにデプロイします。

    ```bash
    jss deploy app -c -d
    ```

    `-c` オプションはコンテンツアイテムをデプロイし、`-d` オプションは定義アイテム（レイアウト、テンプレートなど）をデプロイします。

4.  **SXAサイトの設定:**

    Sitecore Content Editorで、新しいSXAサイトを作成し、JSSヘッドレスサイトと統合します。SitecoreのSXAサイト設定で、`Headless Site Grouping`を設定し、作成したJSSアプリケーションに関連付けます。

#### 実践的なテクニック

*   **環境変数の活用:** `config.json`の値を直接編集する代わりに、環境変数を使用することをお勧めします。これにより、異なる環境（開発、ステージング、本番）で異なる設定を簡単に管理できます。`.env`ファイルを作成し、環境変数を定義します。

    ```
    SITECORE_INSTANCE_URI=https://your-sitecore-instance.local
    SITECORE_API_KEY={YOUR-API-KEY}
    SITECORE_DEPLOY_SECRET=your-deploy-secret
    ```

    `config.json`で環境変数を参照します。

    ```json
    {
      "sitecore": {
        "instanceUri": "${process.env.SITECORE_INSTANCE_URI}",
        "apiKey": "${process.env.SITECORE_API_KEY}",
        "deploySecret": "${process.env.SITECORE_DEPLOY_SECRET}"
      }
    }
    ```

*   **JSSレイアウトサービスの設定:** SXAでは、JSSレイアウトサービスを使用してコンテンツをレンダリングします。レイアウトサービスの設定を確認し、必要なフィールドが含まれていることを確認します。Sitecore Content Editorで、`/sitecore/system/Modules/Layout Service`以下にレイアウトサービスの設定アイテムがあります。

#### 応用例とユースケース

*   **多言語サイトの構築:** JSSは多言語サイトを簡単に構築できます。Sitecoreで言語を追加し、JSSアプリケーションでi18nライブラリ（例: i18next）を使用してコンテンツを翻訳します。
*   **パーソナライズの適用:** Sitecoreのパーソナライズ機能をJSSアプリケーションに統合できます。レイアウトサービスからパーソナライズされたコンテンツを取得し、JSSコンポーネントで適切にレンダリングします。

#### トラブルシューティング

*   **デプロイエラー:** デプロイエラーが発生した場合は、Sitecoreのログファイルを確認し、エラーの原因を特定します。よくある原因としては、APIキーが無効である、デプロイメントシークレットが一致しない、Sitecoreインスタンスに接続できないなどが挙げられます。
*   **レイアウトサービスのエラー:** レイアウトサービスがコンテンツを返さない場合は、Sitecoreのアイテムにレイアウトが割り当てられているか、レイアウトサービスの設定が正しいかを確認します。

#### まとめと次のステップ

JSSアプリケーションの構成は、Sitecore SXA + JSSプロジェクトの成功に不可欠です。適切な構成を行うことで、開発効率を向上させ、スケーラブルなアプリケーションを構築できます。次のステップでは、テーマの構造とカスタマイズについて詳しく解説します。

### 2.2. テーマの構造とカスタマイズ

#### 概要と重要性

テーマは、アプリケーションの見た目と操作性を定義する要素です。SXAでは、テーマを使用してサイト全体のスタイルを管理し、一貫性のあるブランドエクスペリエンスを提供します。JSSアプリケーションとSXAテーマを適切に統合することで、デザインの柔軟性とメンテナンス性を向上させることができます。

#### 特徴と利点

*   **視覚的な一貫性:** テーマを使用することで、サイト全体のスタイルを一貫させることができます。
*   **再利用性:** テーマは複数のサイトで再利用できます。
*   **カスタマイズ性:** テーマは簡単にカスタマイズできます。
*   **SXAとの統合:** SXAのグリッドシステム、コンポーネントスタイル、テーマ設定をJSSアプリケーションで活用できます。

#### 事前準備と前提条件

*   JSSアプリケーションの構築（上記セクションを参照）
*   SXAテーマの基本的な理解 (Grid system, Styling)
*   CSSまたはSCSSの知識

#### 基本的な使い方

1.  **SXAテーマの作成:**

    Sitecore Content Editorで、`/sitecore/content/{Your Tenant}/{Your Site}/Presentation/Themes`以下に新しいテーマを作成します。

2.  **JSSアプリケーションへのテーマの適用:**

    JSSアプリケーションの`src/sxastyles`ディレクトリに、テーマに関連するCSSまたはSCSSファイルを配置します。

    例えば、`src/sxastyles/main.scss`を作成し、SXAテーマのスタイルをインポートします。

    ```scss
    @import './themes/my-custom-theme/styles'; // カスタムテーマのスタイルをインポート
    // 他の必要なスタイル
    ```

3.  **JSSコンポーネントへのスタイルの適用:**

    JSSコンポーネントで、クラス名を使用してスタイルを適用します。SXAのデフォルトスタイル、またはカスタムテーマで定義したスタイルを使用できます。

    ```jsx
    // React component example
    import React from 'react';

    const MyComponent = (props) => {
      return (
        <div className="component my-custom-class">
          <h1>{props.fields.heading.value}</h1>
          <p>{props.fields.text.value}</p>
        </div>
      );
    };

    export default MyComponent;
    ```

    この例では、`component` と `my-custom-class` というクラス名を適用しています。`component` はSXAのデフォルトスタイルを、`my-custom-class` はカスタムテーマで定義したスタイルを適用するために使用できます。

#### 実践的なテクニック

*   **CSS Modulesの活用:** CSS Modulesを使用すると、コンポーネントレベルでスタイルをスコープ化できます。これにより、スタイルの衝突を回避し、コンポーネントの再利用性を向上させることができます。

    ```javascript
    // MyComponent.module.scss
    .heading {
      font-size: 24px;
      color: blue;
    }

    .text {
      font-size: 16px;
    }
    ```

    ```jsx
    // React component example
    import React from 'react';
    import styles from './MyComponent.module.scss';

    const MyComponent = (props) => {
      return (
        <div className="component">
          <h1 className={styles.heading}>{props.fields.heading.value}</h1>
          <p className={styles.text}>{props.fields.text.value}</p>
        </div>
      );
    };

    export default MyComponent;
    ```

*   **SXA Grid Systemの活用:** SXAのグリッドシステムをJSSコンポーネントで使用することで、レスポンシブなレイアウトを簡単に実現できます。SXAのグリッドシステムは、CSSクラス名を使用して列と行を定義します。

    ```jsx
    // React component example
    import React from 'react';

    const MyComponent = (props) => {
      return (
        <div className="row">
          <div className="col-md-6">
            <h1>{props.fields.heading.value}</h1>
          </div>
          <div className="col-md-6">
            <p>{props.fields.text.value}</p>
          </div>
        </div>
      );
    };

    export default MyComponent;
    ```

*   **テーマ設定の活用:** SXAのテーマ設定を使用すると、色、フォント、間隔などのスタイル変数を定義し、テーマ全体で一貫性を保つことができます。JSSアプリケーションでテーマ設定の値を取得し、コンポーネントのスタイルに適用することができます。

    テーマ設定の値は、JSSレイアウトサービスから取得できます。

#### 応用例とユースケース

*   **ブランドガイドラインの適用:** ブランドガイドラインに基づいて、カスタムテーマを作成し、サイト全体のスタイルを統一します。
*   **テーマの切り替え:** 複数のテーマを作成し、ユーザーが選択できるようにすることで、パーソナライズされたエクスペリエンスを提供します。
*   **コンポーネントライブラリの構築:** 再利用可能なコンポーネントライブラリを作成し、テーマを適用することで、開発効率を向上させます。

#### トラブルシューティング

*   **スタイルの衝突:** スタイルの衝突が発生した場合は、CSS ModulesまたはBEM (Block, Element, Modifier) などの命名規則を使用して、スタイルをスコープ化します。
*   **テーマが適用されない:** テーマがJSSアプリケーションに正しく適用されない場合は、`src/sxastyles/main.scss`ファイルが正しく設定されているか、JSSアプリケーションがSitecoreに正しくデプロイされているかを確認します。

#### まとめと次のステップ

テーマの構造とカスタマイズは、Sitecore SXA + JSSプロジェクトの重要な要素です。適切なテーマ構造を設計し、カスタマイズすることで、魅力的で一貫性のあるユーザーエクスペリエンスを提供できます。次のステップでは、コンポーネント開発と応用について詳しく解説します。

### 2.3. コンポーネント開発と応用

#### 概要と重要性

コンポーネントは、JSSアプリケーションの基本的な構成要素です。コンポーネントを適切に設計することで、コードの再利用性を向上させ、アプリケーションのメンテナンス性を高めることができます。SXA環境下では、SXAのレンダリング機能とJSSコンポーネントを効果的に組み合わせることが重要になります。

#### 特徴と利点

*   **再利用性:** コンポーネントは複数の場所で再利用できます。
*   **モジュール性:** コンポーネントは独立して開発およびテストできます。
*   **保守性:** コンポーネントの変更は他の部分に影響を与えません。
*   **SXAとの統合:** SXAのPlaceholdersを使用して、JSSコンポーネントをページに配置できます。

#### 事前準備と前提条件

*   JSSアプリケーションの構築（上記セクションを参照）
*   JavaScriptフレームワークの知識 (React, Angular, Vue.js いずれか)
*   SXA Placeholdersの理解

#### 基本的な使い方

1.  **コンポーネントの作成:**

    JSSアプリケーションの`src/components`ディレクトリに、新しいコンポーネントを作成します。

    ```jsx
    // React component example (src/components/MyComponent.jsx)
    import React from 'react';
    import { Text } from '@sitecore-jss/sitecore-jss-react';

    const MyComponent = (props) => {
      return (
        <div className="component">
          <h1><Text field={props.fields.heading} /></h1>
          <p><Text field={props.fields.text} /></p>
        </div>
      );
    };

    export default MyComponent;
    ```

    この例では、`MyComponent`というReactコンポーネントを作成しています。`@sitecore-jss/sitecore-jss-react`の`Text`コンポーネントを使用して、Sitecoreから取得したテキストフィールドを表示しています。

2.  **Sitecoreでのコンポーネントの登録:**

    Sitecore Content Editorで、`/sitecore/layout/Renderings/Project/{Your Project}/JSS`以下に新しいレンダリングアイテムを作成します。`Component Name`フィールドに、JSSコンポーネントの名前（例: `MyComponent`）を入力します。

3.  **Sitecoreでのコンポーネントの定義:**

    Sitecore Content Editorで、`/sitecore/templates/Project/{Your Project}/JSS`以下に新しいテンプレートを作成します。このテンプレートは、コンポーネントのデータ構造を定義します。テンプレートに、必要なフィールド（例: `Heading`, `Text`）を追加します。

4.  **コンポーネントの配置:**

    Sitecore Experience Editorで、ページにコンポーネントを配置します。SXAのPlaceholdersを使用して、コンポーネントを配置する場所を指定します。

#### 実践的なテクニック

*   **フィールドエディターの活用:** JSS Editing Hostを使用すると、Sitecore Experience EditorでJSSコンポーネントのフィールドを直接編集できます。これにより、コンテンツ作成者はコードを変更せずにコンテンツを更新できます。
*   **GraphQLの使用:** GraphQLを使用して、必要なデータのみを効率的に取得できます。JSSレイアウトサービスをGraphQLで拡張し、カスタムクエリを定義します。
*   **SSR (Server-Side Rendering) の実装:** SSRを実装することで、SEOを向上させ、初期ロード時間を短縮できます。JSSアプリケーションをサーバーサイドでレンダリングし、HTMLをクライアントに送信します。

#### 応用例とユースケース

*   **フォームの作成:** JSSとFormikなどのフォームライブラリを使用して、カスタムフォームを作成します。Sitecoreでフォームデータを保存し、ワークフローをトリガーします。
*   **コンテンツ検索の実装:** Sitecore Content Search APIを使用して、JSSコンポーネントでコンテンツを検索します。検索結果をページに表示し、フィルターやソートなどの機能を追加します。
*   **API連携:** JSSコンポーネントで外部APIを呼び出し、データを表示します。天気予報、株価情報、ソーシャルメディアのフィードなどを表示できます。

#### トラブルシューティング

*   **コンポーネントが表示されない:** コンポーネントがページに表示されない場合は、Sitecoreでコンポーネントが正しく登録されているか、プレースホルダーが正しいか、JSSアプリケーションがSitecoreに正しくデプロイされているかを確認します。
*   **フィールドの値が表示されない:** フィールドの値が表示されない場合は、Sitecoreのアイテムにフィールドの値が入力されているか、JSSコンポーネントでフィールドが正しく参照されているかを確認します。

#### まとめと次のステップ

コンポーネント開発と応用は、Sitecore SXA + JSSプロジェクトの中核となる部分です。コンポーネントを適切に設計し、SXAの機能と組み合わせることで、柔軟でスケーラブルなアプリケーションを構築できます。次のステップでは、初期データのインポートと設定について詳しく解説します。

### 2.4. 初期データのインポートと設定

#### 概要と重要性

初期データの設定は、Sitecoreプロジェクトの立ち上げ時に不可欠な作業です。コンテンツ構造、設定、基本コンテンツなどを効率的にインポートすることで、開発者はすぐにアプリケーションの構築に取り掛かることができます。特にJSSとSXAを組み合わせたプロジェクトでは、コンテンツ、レイアウト、テンプレートなどを一括で管理し、デプロイする必要があります。

#### 特徴と利点

*   **効率的な初期設定:** 大量のコンテンツや設定を効率的にインポートできます。
*   **一貫性の維持:** 複数の環境で一貫したデータを維持できます。
*   **自動化:** データインポートプロセスを自動化できます。
*   **バージョン管理:** データインポートの履歴をバージョン管理できます。

#### 事前準備と前提条件

*   JSSアプリケーションの構築（上記セクションを参照）
*   Sitecore Items as Resources (SiRi)の理解
*   Sitecore CLIの知識
*   JSON形式のデータファイルの準備

#### 基本的な使い方

1.  **データファイルの作成:**

    インポートするデータをJSON形式で記述したファイルを作成します。このファイルには、Sitecoreのアイテムの構造、フィールドの値、レイアウト情報などが含まれます。

    ```json
    // example_data.json
    [
      {
        "name": "HomePage",
        "template": "{YOUR-HOMEPAGE-TEMPLATE-ID}",
        "fields": {
          "Title": {
            "value": "Welcome to our Site!"
          },
          "Body": {
            "value": "<p>This is the homepage.</p>"
          }
        }
      },
      {
        "name": "AboutUsPage",
        "template": "{YOUR-ABOUTUS-TEMPLATE-ID}",
        "fields": {
          "Title": {
            "value": "About Us"
          },
          "Body": {
            "value": "<p>Learn more about our company.</p>"
          }
        }
      }
    ]
    ```

    `{YOUR-HOMEPAGE-TEMPLATE-ID}`と`{YOUR-ABOUTUS-TEMPLATE-ID}`は、Sitecoreで作成したテンプレートのIDに置き換えてください。

2.  **Sitecore CLIを使用したデータインポート:**

    Sitecore CLIを使用して、JSONファイルをSitecoreにインポートします。

    ```bash
    sitecore import --path ./example_data.json --rootItemPath /sitecore/content/{Your Tenant}/{Your Site}/Home
    ```

    `--path` オプションは、JSONファイルのパスを指定します。`--rootItemPath` オプションは、データのインポート先となるSitecoreのアイテムのパスを指定します。`{Your Tenant}` と `{Your Site}` は、適切なテナントとサイトの名前に置き換えてください。

3.  **JSSアプリケーションのデプロイ:**

    データインポート後、JSSアプリケーションをSitecoreにデプロイして、新しいコンテンツを表示します。

    ```bash
    jss deploy app -c -d
    ```

#### 実践的なテクニック

*   **SiRi (Sitecore Items as Resources) の活用:** SiRiを使用すると、Sitecoreのアイテムをコードとして管理できます。これにより、アイテムの変更をバージョン管理システムにコミットし、複数の環境で一貫性を保つことができます。
*   **PowerShellスクリプトの使用:** 複雑なデータ変換やカスタムロジックが必要な場合は、PowerShellスクリプトを使用してデータインポートを自動化します。
*   **データ検証の実施:** データインポート前に、データが正しい形式であることを確認します。これにより、エラーを防ぎ、データの整合性を保つことができます。

#### 応用例とユースケース

*   **多言語コンテンツのインポート:** 複数の言語でコンテンツをインポートし、多言語サイトを構築します。
*   **設定データのインポート:** サイトの設定データ（APIキー、接続文字列など）をインポートし、アプリケーションを構成します。
*   **サンプルのコンテンツの提供:** デモやトレーニング用に、サンプルのコンテンツをインポートします。

#### トラブルシューティング

*   **インポートエラー:** インポートエラーが発生した場合は、Sitecoreのログファイルを確認し、エラーの原因を特定します。よくある原因としては、JSONファイルの形式が不正である、必須フィールドが欠落している、アイテムのパスが無効であるなどが挙げられます。
*   **データが正しく表示されない:** データがSitecoreにインポートされた後、JSSアプリケーションで正しく表示されない場合は、レイアウトサービスの設定、JSSコンポーネントのコード、Sitecoreのアイテムのフィールド値などを確認します。

#### まとめと次のステップ

初期データのインポートと設定は、Sitecore SXA + JSSプロジェクトの初期段階で重要な作業です。効率的なデータインポートプロセスを確立することで、開発者はすぐにアプリケーションの構築に取り掛かることができます。次のステップでは、フェデレーテッドエクスペリエンスとマイクロフロントエンドについて詳しく解説します。

### 2.5. フェデレーテッドエクスペリエンスとマイクロフロントエンド

#### 概要と重要性

フェデレーテッドエクスペリエンスとマイクロフロントエンドは、大規模なウェブアプリケーションを構築するためのアーキテクチャパターンです。これらのパターンを使用することで、複数のチームが独立して開発およびデプロイできる小さなアプリケーション（マイクロフロントエンド）を統合し、単一のユーザーエクスペリエンスを提供できます。Sitecore SXA + JSS環境では、これらのパターンを使用して、複雑なサイトを管理しやすいモジュールに分割し、開発効率を向上させることができます。

#### 特徴と利点

*   **独立した開発:** 複数のチームが独立してマイクロフロントエンドを開発およびデプロイできます。
*   **技術的多様性:** マイクロフロントエンドは異なる技術スタックで構築できます。
*   **スケーラビリティ:** マイクロフロントエンドは個別にスケーリングできます。
*   **保守性:** マイクロフロントエンドは個別に保守できます。
*   **漸進的なアップグレード:** マイクロフロントエンドを段階的にアップグレードできます。

#### 事前準備と前提条件

*   JSSアプリケーションの構築（上記セクションを参照）
*   マイクロフロントエンドアーキテクチャの理解
*   モジュールフェデレーションの知識
*   Dockerの知識 (オプション)

#### 基本的な使い方

1.  **マイクロフロントエンドの定義:**

    アプリケーションをマイクロフロントエンドに分割します。各マイクロフロントエンドは、特定のビジネス機能またはドメインを担当します。例えば、製品カタログ、カート、チェックアウトなどを個別のマイクロフロントエンドとして定義できます。

2.  **マイクロフロントエンドの開発:**

    各マイクロフロントエンドを独立して開発します。異なる技術スタックを使用できますが、ユーザーエクスペリエンスの一貫性を保つように注意してください。

3.  **マイクロフロントエンドの統合:**

    複数の方法でマイクロフロントエンドを統合できます。

    *   **ビルド時の統合:** すべてのマイクロフロントエンドを1つのアプリケーションにビルドします。
    *   **実行時の統合:** 実行時にマイクロフロントエンドを動的にロードします。

    **モジュールフェデレーション:** webpackのモジュールフェデレーション機能を使用すると、実行時にマイクロフロントエンドを動的にロードできます。

    ```javascript
    // webpack.config.js (マイクロフロントエンドの設定)
    const ModuleFederationPlugin = require("webpack/lib/container/ModuleFederationPlugin");

    module.exports = {
      // ...
      plugins: [
        new ModuleFederationPlugin({
          name: "MyMicroFrontend",
          filename: "remoteEntry.js",
          exposes: {
            "./MyComponent": "./src/MyComponent",
          },
          shared: ["react", "react-dom"],
        }),
      ],
    };
    ```

    ```javascript
    // webpack.config.js (ホストアプリケーションの設定)
    const ModuleFederationPlugin = require("webpack/lib/container/ModuleFederationPlugin");

    module.exports = {
      // ...
      plugins: [
        new ModuleFederationPlugin({
          name: "HostApp",
          remotes: {
            "MyMicroFrontend": "MyMicroFrontend@http://localhost:3001/remoteEntry.js",
          },
          shared: ["react", "react-dom"],
        }),
      ],
    };
    ```

4.  **Sitecoreとの統合:**

    Sitecoreで、各マイクロフロントエンドに対応するレンダリングアイテムを作成します。JSSコンポーネントを使用して、マイクロフロントエンドをページに配置します。

#### 実践的なテクニック

*   **Single SPAの使用:** Single SPAは、複数のJavaScriptフレームワークで構築されたマイクロフロントエンドを統合するためのフレームワークです。
*   **Iframeの使用:** Iframeを使用して、マイクロフロントエンドを分離し、独立性を高めることができます。
*   **カスタムイベントの使用:** マイクロフロントエンド間で通信するために、カスタムイベントを使用します。

#### 応用例とユースケース

*   **大規模なeコマースサイト:** 製品カタログ、カート、チェックアウトなどの機能を個別のマイクロフロントエンドとして実装します。
*   **複雑なエンタープライズアプリケーション:** ダッシュボード、レポート、設定などの機能を個別のマイクロフロントエンドとして実装します。

#### トラブルシューティング

*   **マイクロフロントエンドがロードされない:** マイクロフロントエンドがロードされない場合は、ネットワーク接続、モジュールフェデレーションの設定、ホストアプリケーションの設定などを確認します。
*   **スタイルの衝突:** スタイルの衝突が発生した場合は、CSS ModulesまたはShadow DOMを使用して、スタイルをスコープ化します。

#### まとめと次のステップ

フェデレーテッドエクスペリエンスとマイクロフロントエンドは、大規模で複雑なウェブアプリケーションを構築するための強力なアーキテクチャパターンです。これらのパターンを使用することで、開発効率を向上させ、アプリケーションのスケーラビリティと保守性を高めることができます。
