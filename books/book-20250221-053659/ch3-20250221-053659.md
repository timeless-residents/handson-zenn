## 第3章：Next.js フロントエンドの基礎

### 3.1. Next.js プロジェクトの構成とファイル

**概要と重要性**

Next.js は、React をベースとしたフルスタックの JavaScript フレームワークで、サーバーサイドレンダリング、静的サイト生成、API ルーティングといった機能を提供します。プロジェクトの構造を理解することは、効率的な開発と保守性の高いアプリケーション構築の基礎となります。特に `pages`, `components`, `public` ディレクトリ、そして `_app.js` と `_document.js` は Next.js プロジェクトの中核を担っています。

**特徴と利点**

Next.js のプロジェクト構造は、規約に基づいた設計となっており、開発者が共通の理解を持ちやすく、チーム開発を円滑に進めることができます。ディレクトリ構造を理解することで、コードの整理、機能の分離、テストの容易化につながります。

**事前準備と前提条件**

*   Node.js と npm (または yarn) がインストールされていること
*   Next.js の基本的な知識 (インストール、プロジェクトの作成など)

**基本的な使い方**

Next.js プロジェクトを作成すると、以下のようなディレクトリ構造が生成されます。

```
my-next-app/
├── .next/          # Next.js が自動生成するファイル (通常は編集しない)
├── components/    # React コンポーネントを配置するディレクトリ
├── pages/         # ページとなる React コンポーネントを配置するディレクトリ
├── public/        # 静的アセット (画像、フォントなど) を配置するディレクトリ
├── styles/        # CSS モジュールを配置するディレクトリ
├── package.json   # プロジェクトの設定ファイル
└── next.config.js # Next.js の設定ファイル
```

*   **`pages` ディレクトリ:**
    *   `pages` ディレクトリ内の JavaScript ファイルは、自動的にルートとして扱われます。
    *   例えば、`pages/index.js` は `/` ルート、`pages/about.js` は `/about` ルートに対応します。
    *   `pages/api` ディレクトリを作成すると、API エンドポイントを作成できます。

*   **`components` ディレクトリ:**
    *   再利用可能な React コンポーネントを配置するディレクトリです。
    *   UI 要素、ロジック、共通機能などをコンポーネントとして作成し、`pages` ディレクトリ内のファイルからインポートして使用します。

*   **`public` ディレクトリ:**
    *   画像、フォント、robots.txt などの静的アセットを配置するディレクトリです。
    *   これらのアセットは、アプリケーションのルートから直接アクセスできます (例: `/images/logo.png`)。

*   **`_app.js`:**
    *   すべてのページに共通のレイアウトや初期化処理を適用するために使用されます。
    *   グローバルな CSS をインポートしたり、Context API を使用したり、ページ遷移時の処理を記述したりできます。

*   **`_document.js`:**
    *   `<html>`、`<head>`、`<body>` タグといったドキュメント全体をカスタマイズするために使用されます。
    *   メタタグの追加、フォントのプリロード、スタイルシートの適用など、高度なカスタマイズが必要な場合に利用します。

**実践的なテクニック**

*   **`_app.js` でグローバル CSS をインポートする:**

    ```javascript
    // pages/_app.js
    import '../styles/global.css';

    function MyApp({ Component, pageProps }) {
      return <Component {...pageProps} />;
    }

    export default MyApp;
    ```

*   **`public` ディレクトリに画像を配置し、`next/image` コンポーネントで最適化して表示する:**

    ```jsx
    // components/MyComponent.js
    import Image from 'next/image';

    function MyComponent() {
      return (
        <Image
          src="/images/my-image.jpg"
          alt="My Image"
          width={500}
          height={300}
        />
      );
    }

    export default MyComponent;
    ```

*   **`_document.js` でカスタムフォントをプリロードする:**

    ```javascript
    // pages/_document.js
    import Document, { Html, Head, Main, NextScript } from 'next/document';

    class MyDocument extends Document {
      render() {
        return (
          <Html>
            <Head>
              <link
                rel="preload"
                href="/fonts/MyFont.woff2"
                as="font"
                crossOrigin="anonymous"
              />
            </Head>
            <body>
              <Main />
              <NextScript />
            </body>
          </Html>
        );
      }
    }

    export default MyDocument;
    ```

**応用例とユースケース**

*   **複数のレイアウトを `_app.js` で切り替える:**
    *   `pages` ディレクトリに`Layout`コンポーネントを持つページと持たないページで異なるレイアウトを適用できます。認証が必要なページとそうでないページでレイアウトを切り替える場合などに有効です。

*   **カスタムのエラーページを作成する:**
    *   `pages/_error.js` を作成することで、カスタムのエラーページを表示できます。

**トラブルシューティング**

*   **`_app.js` や `_document.js` の変更が反映されない:**
    *   Next.js サーバーを再起動する必要があります。
*   **静的アセットにアクセスできない:**
    *   `public` ディレクトリに正しく配置されているか確認してください。パスの指定も間違っていないか確認しましょう。

**まとめと次のステップ**

Next.js プロジェクトの構造を理解することで、効率的な開発が可能になります。特に `pages`, `components`, `public` ディレクトリの役割と、`_app.js` および `_document.js` のカスタマイズは重要です。次は、これらの知識を活かして、Sitecore Context を利用したデータ取得に進みましょう。

### 3.2. Sitecore Context の利用

**概要と重要性**

Sitecore Context は、Headless 環境において、現在のリクエストに関するさまざまな情報を提供するオブジェクトです。これには、現在表示されているアイテムの情報、言語、サイト、編集モードなどが含まれます。Next.js アプリケーションで Sitecore Context を利用することで、コンテンツ編集者が Sitecore で行った変更をリアルタイムに反映させたり、パーソナライズされたコンテンツを表示したりすることが可能になります。

**特徴と利点**

*   **リアルタイムプレビュー:** Sitecore の Experience Editor での編集内容が即座に Next.js アプリケーションに反映されます。
*   **コンテキストアウェアネス:** 現在のユーザー、デバイス、場所などのコンテキストに基づいてコンテンツを調整できます。
*   **パーソナライズ:** ユーザーの行動履歴やプロファイルに基づいてコンテンツをパーソナライズできます。
*   **多言語対応:** 言語設定に基づいて適切なコンテンツを表示できます。

**事前準備と前提条件**

*   Sitecore がインストールされ、Headless Rendering Engine が設定されていること
*   Next.js プロジェクトが作成済みであること
*   `@sitecore-jss/sitecore-jss-nextjs` パッケージがインストールされていること

```bash
npm install @sitecore-jss/sitecore-jss-nextjs
```

**基本的な使い方**

Sitecore Context は、`useSitecoreContext` フックを通じてアクセスできます。

```javascript
// pages/index.js
import { useSitecoreContext } from '@sitecore-jss/sitecore-jss-nextjs';

function HomePage() {
  const { sitecoreContext, sitecoreContext: { route } } = useSitecoreContext();

  if (!sitecoreContext) {
    return <div>Loading Sitecore Context...</div>;
  }

  return (
    <div>
      <h1>{route?.fields?.title?.value}</h1>
      <p>Language: {sitecoreContext.language}</p>
      <p>Is Experience Editor: {sitecoreContext.pageState === 'edit' ? 'Yes' : 'No'}</p>
    </div>
  );
}

export default HomePage;
```

上記のコードでは、`useSitecoreContext` フックを使用して `sitecoreContext` オブジェクトを取得しています。このオブジェクトには、現在のコンテキストに関するさまざまな情報が含まれています。

*   `sitecoreContext.language`: 現在の言語
*   `sitecoreContext.pageState`: ページの状態 (normal, preview, edit)
*   `route`: 現在のルートアイテムの情報 (フィールドを含む)

**データの取得と表示**

Sitecore Context を利用して、Sitecore に登録されたコンテンツを取得し、Next.js アプリケーションに表示することができます。

```javascript
// components/MyComponent.js
import { useSitecoreContext } from '@sitecore-jss/sitecore-jss-nextjs';

function MyComponent() {
  const { route } = useSitecoreContext();

  if (!route) {
    return <div>Loading...</div>;
  }

  const title = route?.fields?.title?.value || 'No Title';
  const description = route?.fields?.description?.value || 'No Description';

  return (
    <div>
      <h2>{title}</h2>
      <p>{description}</p>
    </div>
  );
}

export default MyComponent;
```

上記のコードでは、`route` オブジェクトから `title` と `description` フィールドの値を取得し、表示しています。

**実践的なテクニック**

*   **Experience Editor でのプレビュー:** `sitecoreContext.pageState === 'edit'` を使用して、Experience Editor でのプレビュー時のみ表示するコンテンツを制御できます。

    ```javascript
    // components/MyComponent.js
    import { useSitecoreContext } from '@sitecore-jss/sitecore-jss-nextjs';

    function MyComponent() {
      const { sitecoreContext } = useSitecoreContext();

      return (
        <div>
          {sitecoreContext.pageState === 'edit' && (
            <div style={{ backgroundColor: 'yellow' }}>
              This is a preview message!
            </div>
          )}
          {/* その他のコンテンツ */}
        </div>
      );
    }

    export default MyComponent;
    ```

*   **多言語対応:** `sitecoreContext.language` を使用して、言語ごとに異なるコンテンツを表示できます。

    ```javascript
    // components/MyComponent.js
    import { useSitecoreContext } from '@sitecore-jss/sitecore-jss-nextjs';

    const translations = {
      'en': {
        title: 'Hello',
        description: 'This is a description.'
      },
      'ja': {
        title: 'こんにちは',
        description: 'これは説明です。'
      }
    };

    function MyComponent() {
      const { sitecoreContext } = useSitecoreContext();
      const lang = sitecoreContext.language || 'en';
      const text = translations[lang];

      return (
        <div>
          <h2>{text.title}</h2>
          <p>{text.description}</p>
        </div>
      );
    }

    export default MyComponent;
    ```

**応用例とユースケース**

*   **パーソナライズされたコンテンツの表示:**
    *   Sitecore Experience Platform (XP) のパーソナライズ機能を活用して、ユーザーの行動履歴やプロファイルに基づいてコンテンツを動的に変更できます。例えば、特定のキャンペーンに参加したユーザーにのみ特別なバナーを表示したり、特定の製品を購入したユーザーにおすすめの関連製品を表示したりできます。

*   **A/B テストの実施:**
    *   Sitecore の A/B テスト機能を活用して、異なるコンテンツのバージョンを異なるユーザーに表示し、どちらのバージョンがより効果的かを検証できます。

**トラブルシューティング**

*   **`useSitecoreContext` が `undefined` を返す:**
    *   `SitecoreContextFactory` でコンテキストプロバイダーが適切にラップされているか確認してください。`_app.js` が適切に設定されているか確認が必要です。
*   **Experience Editor での変更が反映されない:**
    *   Sitecore と Next.js アプリケーション間の接続設定 (API キー、Endpoint URL など) が正しいか確認してください。キャッシュが影響している可能性もあるので、キャッシュをクリアしてみましょう。

**まとめと次のステップ**

Sitecore Context を利用することで、Next.js アプリケーションは Sitecore の強力な機能を活用し、パーソナライズされた、コンテキストアウェアなエクスペリエンスを提供できます。次は、ルーティングとページ作成について学びましょう。

### 3.3. ルーティングとページ作成

**概要と重要性**

Next.js のルーティングシステムは、`pages` ディレクトリ内のファイルに基づいて自動的に生成されます。ダイナミックルーティングを使用すると、パラメータを含む URL パスに対応したページを作成できます。Sitecore コンテンツに対応したページを作成し、リンクコンポーネントを実装することで、ユーザーがシームレスにコンテンツを閲覧できる、魅力的な Web サイトを構築できます。

**特徴と利点**

*   **ファイルシステムベースのルーティング:** 開発者はファイルを作成するだけで、対応するルートが自動的に生成されます。
*   **ダイナミックルーティング:** パラメータを含む URL パスに対応したページを柔軟に作成できます。
*   **Sitecore コンテンツとの統合:** Sitecore のコンテンツ構造を反映したルーティングを実装できます。
*   **SEO に有利:** Next.js のサーバーサイドレンダリング (SSR) 機能により、検索エンジンに最適化されたサイトを構築できます。

**事前準備と前提条件**

*   Next.js プロジェクトが作成済みであること
*   Sitecore Context が利用できる状態であること
*   Sitecore にコンテンツが登録されていること

**基本的な使い方**

*   **静的なルーティング:**
    *   `pages` ディレクトリに JavaScript ファイルを作成するだけで、対応するルートが生成されます。

    ```javascript
    // pages/contact.js
    function ContactPage() {
      return (
        <div>
          <h1>Contact Us</h1>
          <p>Contact information...</p>
        </div>
      );
    }

    export default ContactPage;
    ```

    上記のコードは、`/contact` ルートに対応します。

*   **ダイナミックルーティング:**
    *   `pages` ディレクトリに `[param].js` という名前のファイルを作成することで、ダイナミックルートを作成できます。

    ```javascript
    // pages/posts/[id].js
    import { useRouter } from 'next/router';

    function PostPage() {
      const router = useRouter();
      const { id } = router.query;

      return (
        <div>
          <h1>Post ID: {id}</h1>
          <p>Post content...</p>
        </div>
      );
    }

    export default PostPage;
    ```

    上記のコードは、`/posts/123` のようなルートに対応します。`useRouter` フックを使用すると、URL パラメータ (`id` など) にアクセスできます。

**Sitecore コンテンツに対応したページの作成**

Sitecore のコンテンツ構造を Next.js のルーティングに反映させるためには、`getStaticPaths` と `getStaticProps` を使用します。

```javascript
// pages/posts/[id].js
import { useRouter } from 'next/router';
import { useSitecoreContext, SitecorePageProps } from '@sitecore-jss/sitecore-jss-nextjs';
import { GetStaticPaths, GetStaticProps } from 'next';
import { sitecoreRouteService } from 'lib/sitecore-route-service'; // 適切な場所に配置してください。
import { getSitecoreContext } from 'lib/sitecore-context'; // 適切な場所に配置してください。

interface Props extends SitecorePageProps {}

function PostPage({ ...props }: Props) {
  const { route } = useSitecoreContext();
  const router = useRouter();
  const { id } = router.query;

  if (!route) {
      return <div>Loading...</div>
  }

  return (
    <div>
      <h1>{route?.fields?.title?.value}</h1>
      <p>Post ID: {id}</p>
      <p>{route?.fields?.content?.value}</p>
    </div>
  );
}

export const getStaticPaths: GetStaticPaths = async () => {
    // Sitecore から全ての記事のパスを取得
    const paths = await sitecoreRouteService.fetchPaths();

    return {
        paths,
        fallback: 'blocking', // or 'true' for incremental static regeneration
    };
};

export const getStaticProps: GetStaticProps<Props> = async (context) => {
    // パスから Sitecore のデータを取得
    const sitecoreContext = await getSitecoreContext(context);

    return {
        props: { ...sitecoreContext },
        revalidate: 60, // Optional: Enable Incremental Static Regeneration
    };
};

export default PostPage;
```

**解説**

*   **`getStaticPaths`:**
    *   ビルド時に生成するページのパスを定義します。
    *   Sitecore からすべての記事のパスを取得し、`paths` 配列として返します。
    *   `fallback: 'blocking'` を設定することで、ビルド時に存在しないパスへのアクセスがあった場合、動的にページを生成します。
*   **`getStaticProps`:**
    *   各ページに必要なデータを取得します。
    *   `context.params.id` を使用して、現在の記事の ID を取得し、Sitecore から対応するデータを取得します。

**リンクコンポーネントの実装**

`next/link` コンポーネントを使用すると、クライアントサイドでページ遷移を行うことができます。

```javascript
// components/MyLink.js
import Link from 'next/link';

function MyLink({ href, children }) {
  return (
    <Link href={href}>
      <a>{children}</a>
    </Link>
  );
}

export default MyLink;
```

上記のコンポーネントを使用すると、ページ遷移時にリロードが発生せず、スムーズなユーザーエクスペリエンスを提供できます。

**実践的なテクニック**

*   **複数のパラメータを含むダイナミックルート:**
    *   `pages/products/[category]/[id].js` のように、複数のパラメータを含むダイナミックルートを作成できます。

*   **キャッチオールルート:**
    *   `pages/docs/[...slug].js` のように、キャッチオールルートを作成できます。これにより、`/docs/a/b/c` のような任意の深さのパスに対応できます。

**応用例とユースケース**

*   **ブログサイト:**
    *   記事のカテゴリ、記事 ID をパラメータとして持つダイナミックルートを作成し、Sitecore に登録されたブログ記事を表示できます。

*   **e コマースサイト:**
    *   製品カテゴリ、製品 ID をパラメータとして持つダイナミックルートを作成し、Sitecore に登録された製品情報を表示できます。

**トラブルシューティング**

*   **ダイナミックルートが正しく動作しない:**
    *   `getStaticPaths` と `getStaticProps` の設定が正しいか確認してください。
    *   `fallback` の設定も適切かどうか確認してください。

**まとめと次のステップ**

Next.js のルーティングシステムと Sitecore コンテンツを組み合わせることで、柔軟でスケーラブルな Web サイトを構築できます。次は、Headless サービスの構成について学びましょう。

### 3.4. Headless サービスの構成

**概要と重要性**

Headless サービスは、Sitecore がコンテンツを配信し、Next.js アプリケーションがコンテンツを表示するための基盤となります。Headless Rendering Engine の設定、GraphQL エンドポイントの設定、API キーの設定は、Headless サービスを正しく構成するために不可欠です。

**特徴と利点**

*   **コンテンツとプレゼンテーションの分離:** Sitecore はコンテンツの管理に専念し、Next.js アプリケーションはプレゼンテーションに専念できます。
*   **柔軟性とスケーラビリティ:** フロントエンドとバックエンドを独立して開発・デプロイできます。
*   **パフォーマンスの向上:** Next.js のサーバーサイドレンダリング (SSR) と静的サイト生成 (SSG) 機能により、高速な Web サイトを構築できます。
*   **API 主導:** GraphQL を使用して必要なデータのみを取得できるため、パフォーマンスが向上します。

**事前準備と前提条件**

*   Sitecore がインストールされ、Headless Rendering Engine がインストールされていること
*   Next.js プロジェクトが作成済みであること
*   Sitecore と Next.js アプリケーション間のネットワーク接続が確立されていること

**Headless Rendering Engine の設定**

1.  **Sitecore に Headless Rendering Engine をインストールする:**
    *   Sitecore Experience Platform (XP) または Experience Commerce (XC) に、Headless Rendering Engine をインストールします。
    *   Sitecore Marketplace から適切なパッケージをダウンロードし、インストールガイドに従ってインストールしてください。

2.  **Rendering Host の設定:**
    *   Sitecore で、Next.js アプリケーションをホストする Rendering Host を設定します。
    *   Rendering Host の URL、API キー、サイト名などを設定します。

**GraphQL エンドポイントの設定**

1.  **GraphQL エンドポイントの有効化:**
    *   Sitecore で GraphQL エンドポイントを有効にします。
    *   `\App_Config\Modules\GraphQL\実行環境\GraphQL` の `config` ファイルを有効化します。

2.  **GraphQL エンドポイントの URL を確認する:**
    *   GraphQL エンドポイントの URL を確認します。通常、`[SitecoreInstance]/sitecore/api/graph/edge` のような形式になります。

**API キーの設定**

1.  **API キーの作成:**
    *   Sitecore で API キーを作成します。
    *   API キーの名前、有効期限、アクセス許可などを設定します。
    *   Next.js アプリケーションが Sitecore のコンテンツにアクセスするために必要な権限を付与します。

2.  **API キーの保存:**
    *   API キーを安全な場所に保存します。
    *   環境変数や設定ファイルに API キーを保存し、ソースコードに直接記述しないようにしてください。

**基本的な使い方**

1.  **環境変数の設定:**

    ```bash
    NEXT_PUBLIC_SITECORE_API_HOST=https://your-sitecore-instance
    NEXT_PUBLIC_SITECORE_API_KEY=your-api-key
    NEXT_PUBLIC_SITECORE_SITE_NAME=your-site-name
    NEXT_PUBLIC_GRAPHQL_ENDPOINT=/sitecore/api/graph/edge
    ```

2.  **Sitecore 接続設定ファイルの作成 (例: `lib/config.ts`):**

    ```typescript
    // lib/config.ts
    export const config = {
        sitecoreApiHost: process.env.NEXT_PUBLIC_SITECORE_API_HOST || '',
        sitecoreApiKey: process.env.NEXT_PUBLIC_SITECORE_API_KEY || '',
        sitecoreSiteName: process.env.NEXT_PUBLIC_SITECORE_SITE_NAME || 'JssNextWeb',
        graphQLEndpoint: process.env.NEXT_PUBLIC_SITECORE_API_HOST + process.env.NEXT_PUBLIC_GRAPHQL_ENDPOINT,
    };
    ```

3.  **GraphQL クエリの実行:**

    ```typescript
    // lib/graphql-client.ts
    import { GraphQLClient } from 'graphql-request';
    import { config } from './config';

    const graphQLClient = new GraphQLClient(config.graphQLEndpoint, {
        headers: {
            'sc_apikey': config.sitecoreApiKey,
        },
    });

    export default graphQLClient;
    ```

**実践的なテクニック**

*   **環境変数を利用した設定:**
    *   環境変数を使用して、開発環境、ステージング環境、本番環境で異なる設定を適用できます。
    *   `.env` ファイルや CI/CD パイプラインで環境変数を設定します。

*   **設定ファイルのバージョン管理:**
    *   設定ファイルをバージョン管理システム (Git など) で管理し、設定の変更履歴を追跡できるようにします。

**応用例とユースケース**

*   **多段階環境への対応:**
    *   開発環境、ステージング環境、本番環境ごとに異なる Sitecore インスタンスと接続するように設定できます。

*   **コンテンツ配信ネットワーク (CDN) の利用:**
    *   CDN を使用して、静的アセットや API レスポンスをキャッシュし、パフォーマンスを向上させることができます。

**トラブルシューティング**

*   **API キーが無効:**
    *   API キーが正しく設定されているか、有効期限が切れていないか確認してください。
    *   API キーに必要なアクセス許可が付与されているか確認してください。

*   **GraphQL エンドポイントにアクセスできない:**
    *   GraphQL エンドポイントの URL が正しいか確認してください。
    *   Sitecore と Next.js アプリケーション間のネットワーク接続が確立されているか確認してください。

**まとめと次のステップ**

Headless サービスの構成は、Sitecore と Next.js アプリケーションを連携させるための重要なステップです。Headless Rendering Engine、GraphQL エンドポイント、API キーを正しく設定することで、コンテンツ編集者と開発者が協力して、魅力的な Web サイトを構築できます。これまでの知識を活かし、更なるNext.jsとSitecoreの連携による高度なコンテンツエクスペリエンスの構築に挑戦しましょう。
