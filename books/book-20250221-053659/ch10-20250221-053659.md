## 第10章：多言語サイトの構築

多言語サイトの構築は、グローバル展開を目指す企業にとって不可欠です。より多くの顧客にリーチし、エンゲージメントを高めるためには、ユーザーが快適にコンテンツを利用できる環境を提供する必要があります。この章では、Sitecore を活用して多言語サイトを構築するための実践的な方法を解説します。ヘッドレス環境での多言語対応から、SEO対策まで、網羅的にカバーします。

### 10.1. Sitecore の多言語機能の概要

#### 概要と重要性

Sitecore は、多言語サイトを構築するための強力な機能を標準で備えています。これにより、複数の言語でコンテンツを管理し、ユーザーの言語設定に基づいて適切なコンテンツを表示することができます。多言語対応は、グローバルビジネスを展開する上で、ブランドの認知度向上、顧客満足度の向上、そして最終的にはコンバージョン率の向上に貢献します。

#### 特徴と利点

* **言語バージョニング:** 同じアイテムに対して、異なる言語バージョンのコンテンツを保持できます。
* **言語フォールバック:** 特定の言語でコンテンツが存在しない場合、デフォルト言語のコンテンツを表示できます。
* **Sitecore Dictionary:** 翻訳テキストを一元管理し、再利用を促進します。
* **多言語URL:** 各言語に対して固有のURLを設定できます。
* **コンテンツ編集の効率化:** 言語バージョンを並行して編集できます。
* **SEO対策:** `hreflang`属性などを活用し、検索エンジンに多言語サイトの構造を正しく伝えることができます。

#### 事前準備と前提条件

* Sitecore インスタンスが稼働していること
* Sitecore Content Editor へのアクセス権があること
* 多言語対応が必要なサイトの要件定義が完了していること
* 翻訳を担当するチームまたは翻訳サービスとの連携体制が整っていること

#### 基本的な使い方

**1. 言語の追加と設定:**

Sitecore Control Panel > System > Languages にアクセスし、「Add」ボタンをクリックして新しい言語を追加します。言語コード（例: `ja-JP`）と表示名を入力し、必要に応じて書字方向 (Left-to-Right, Right-to-Left) を設定します。

**2. コンテンツの翻訳とローカライズ:**

Content Editor で、翻訳したいアイテムを選択し、「Versions」タブの「Add Version」をクリックします。追加したい言語を選択し、「OK」をクリックします。新しい言語バージョンのアイテムが作成されるので、コンテンツを翻訳し、ローカライズを行います。ローカライズとは、コンテンツを特定の地域や文化に合わせて調整することです（例: 日付の形式、通貨、単位など）。

**3. 言語切り替え機能の実装:**

最も簡単な方法は、Sitecore 標準の `LanguageSwitcher` コントロールを使用することです。Layout Details で、サブレイアウトまたはレンダリングに `LanguageSwitcher` コントロールを追加します。必要に応じて、表示される言語リストのスタイルを調整します。

```csharp
// Razor View (.cshtml) の例
@using Sitecore.Mvc
@using Sitecore.Globalization

<ul>
    @foreach (var language in Sitecore.Context.Database.GetLanguages())
    {
        <li>
            <a href="@Html.Sitecore().Link(Sitecore.Context.Item, new { language = language.Name })">
                @language.CultureInfo.DisplayName
            </a>
        </li>
    }
</ul>
```

#### 実践的なテクニック

* **言語フォールバックの設定:** 特定の言語でコンテンツが見つからない場合に、別の言語のコンテンツを表示するように設定できます。これは、Sitecore Control Panel > System > Languages で、言語の「Fallback Language」を設定することで実現できます。
* **共有フィールドの活用:** すべての言語で同じ値を共有するフィールドは、「Shared」属性をTrueに設定します。これにより、翻訳の手間を省き、コンテンツの一貫性を保つことができます。
* **翻訳ワークフローの導入:** コンテンツの翻訳プロセスを管理するために、Sitecore のワークフロー機能を活用します。これにより、翻訳の品質を確保し、承認プロセスを効率化できます。

#### 応用例とユースケース

* **グローバル企業の製品カタログ:** 複数の言語で製品情報を管理し、各地域のユーザーに最適化された情報を提供します。
* **多言語対応のEコマースサイト:** 複数の言語と通貨に対応し、グローバルな顧客にシームレスなショッピング体験を提供します。
* **国際イベントのウェブサイト:** イベント情報を複数の言語で提供し、世界中の参加者を集めます。

#### トラブルシューティング

* **言語切り替えが機能しない:** キャッシュの問題が考えられます。Sitecore 管理画面からキャッシュをクリアしてみてください。
* **翻訳したコンテンツが表示されない:** 言語バージョンが正しく公開されているか確認してください。また、言語フォールバックの設定も確認してください。
* **`LanguageSwitcher` コントロールのスタイルが崩れる:** CSS を調整して、デザインを修正してください。

#### まとめと次のステップ

Sitecore の多言語機能は、グローバルサイトを構築するための強力なツールです。言語の追加と設定、コンテンツの翻訳とローカライズ、そして言語切り替え機能の実装を通じて、多言語サイトの基礎を構築することができます。次のステップとして、Headless 環境での多言語対応、Sitecore Dictionary の活用、そして多言語 SEO 対策について学習しましょう。

### 10.2. Headless 環境での多言語対応

#### 概要と重要性

Headless CMS 環境では、コンテンツを配信するフロントエンドが Sitecore のプレゼンテーション層から分離されています。そのため、従来の Sitecore の多言語機能に加えて、言語コンテキストを適切に管理し、フロントエンドに言語固有のコンテンツを配信する必要があります。Headless 環境での多言語対応は、柔軟性とパフォーマンスに優れたグローバルサイトを構築するために不可欠です。

#### 特徴と利点

* **柔軟性の向上:** フロントエンド技術の自由度が高まり、様々なデバイスやチャネルに対応できます。
* **パフォーマンスの最適化:** フロントエンドを最適化することで、高速な表示速度を実現できます。
* **API ベースの連携:** Sitecore Content Management API (CM API) や GraphQL を利用して、多言語コンテンツを効率的に取得できます。
* **スケーラビリティの向上:** フロントエンドとバックエンドを分離することで、スケーラビリティを向上させることができます。

#### 事前準備と前提条件

* Sitecore Headless Services がインストールされ、設定されていること
* フロントエンドフレームワーク（例: React, Angular, Vue.js）が設定されていること
* Sitecore CM API または GraphQL が利用可能な状態であること
* フロントエンドとバックエンド間のデータ連携が確立されていること

#### 基本的な使い方

**1. 言語コンテキストの管理:**

フロントエンドで現在の言語を認識し、Sitecore に適切な言語コンテキストを渡す必要があります。これは、URL パス、クッキー、またはブラウザの `Accept-Language` ヘッダーなどを利用して実現できます。

**2. 言語固有のコンテンツの表示:**

Sitecore CM API または GraphQL を利用して、現在の言語に基づいてコンテンツを取得し、フロントエンドに表示します。`language` パラメータを使用して、特定の言語のコンテンツをリクエストします。

**3. 言語切り替えコンポーネントの実装:**

フロントエンドで言語を切り替えるためのコンポーネントを実装します。このコンポーネントは、現在の言語を変更し、Sitecore から新しい言語のコンテンツをロードする必要があります。

```javascript
// React の例
import React, { useState, useEffect } from 'react';
import { fetchSitecoreData } from './api';

function LanguageSwitcher() {
  const [currentLanguage, setCurrentLanguage] = useState('en');
  const [content, setContent] = useState({});

  useEffect(() => {
    async function fetchData() {
      const data = await fetchSitecoreData(currentLanguage);
      setContent(data);
    }
    fetchData();
  }, [currentLanguage]);

  const handleLanguageChange = (language) => {
    setCurrentLanguage(language);
  };

  return (
    <div>
      <button onClick={() => handleLanguageChange('en')}>English</button>
      <button onClick={() => handleLanguageChange('ja-JP')}>日本語</button>
      <h1>{content.title}</h1>
      <p>{content.description}</p>
    </div>
  );
}

export default LanguageSwitcher;

// api.js (例)
async function fetchSitecoreData(language) {
  const endpoint = `https://your-sitecore-instance/sitecore/api/layout/render/jss?item=/&sc_apikey=your-api-key&sc_lang=${language}`;
  const response = await fetch(endpoint);
  const data = await response.json();
  return {
    title: data.sitecore.route.fields.Title.value,
    description: data.sitecore.route.fields.Description.value,
  };
}
```

#### 実践的なテクニック

* **Sitecore Context を利用:** Headless Services で提供される `SitecoreContext` を利用して、現在の言語を取得し、コンテンツをレンダリングします。
* **GraphQL を活用:** GraphQL を利用することで、必要なコンテンツだけを効率的に取得できます。
* **キャッシュ戦略の最適化:** フロントエンドとバックエンドの両方でキャッシュを効果的に利用することで、パフォーマンスを向上させることができます。
* **SSR (Server-Side Rendering) の検討:** SEO のために、SSR を導入することを検討してください。

#### 応用例とユースケース

* **多言語対応の SPA (Single Page Application):** React, Angular, Vue.js などの SPA フレームワークを使用して、高速でインタラクティブな多言語サイトを構築します。
* **モバイルアプリとの連携:** Sitecore をコンテンツバックエンドとして利用し、複数の言語に対応したモバイルアプリを開発します。
* **IoT デバイスへのコンテンツ配信:** Sitecore から様々な言語のコンテンツを IoT デバイスに配信します。

#### トラブルシューティング

* **言語コンテキストが正しく設定されない:** URL パス、クッキー、または `Accept-Language` ヘッダーが正しく設定されているか確認してください。
* **言語固有のコンテンツが表示されない:** Sitecore CM API または GraphQL リクエストが正しい言語で実行されているか確認してください。
* **パフォーマンスが悪い:** キャッシュ戦略を見直し、フロントエンドとバックエンドの両方で最適化を行ってください。

#### まとめと次のステップ

Headless 環境での多言語対応は、従来の Sitecore 環境とは異なるアプローチが必要です。言語コンテキストの管理、言語固有のコンテンツの表示、そして言語切り替えコンポーネントの実装を通じて、柔軟で高性能な多言語サイトを構築することができます。次のステップとして、Sitecore Dictionary の活用と多言語 SEO 対策について学習しましょう。

### 10.3. Sitecore Dictionary の活用

#### 概要と重要性

Sitecore Dictionary は、ウェブサイトで使用されるテキストラベル、メッセージ、ボタンテキストなどの翻訳テキストを一元的に管理するための機能です。これにより、コンテンツエディターはテキストを直接翻訳する必要がなくなり、翻訳者は翻訳テキストの管理に集中できます。Sitecore Dictionary の活用は、多言語サイトの翻訳プロセスを効率化し、コンテンツの一貫性を保つために重要です。

#### 特徴と利点

* **翻訳テキストの一元管理:** すべての翻訳テキストを一つの場所で管理できます。
* **翻訳の再利用:** 同じテキストを複数の場所で使用する場合、一度翻訳すれば再利用できます。
* **ワークフローの効率化:** 翻訳者はテキストの翻訳に集中でき、コンテンツエディターはコンテンツの作成に集中できます。
* **多言語対応の簡略化:** テキストの翻訳を簡単に追加・更新できます。
* **コンテンツの一貫性:** ウェブサイト全体で同じテキストを使用することで、コンテンツの一貫性を保つことができます。

#### 事前準備と前提条件

* Sitecore インスタンスが稼働していること
* Sitecore Content Editor へのアクセス権があること
* 多言語対応が必要なサイトの要件定義が完了していること
* 翻訳を担当するチームまたは翻訳サービスとの連携体制が整っていること

#### 基本的な使い方

**1. Sitecore Dictionary の概要と設定:**

Sitecore Content Editor で、`/sitecore/system/Settings/Dictionary` にアクセスします。ここに、翻訳テキストのエントリーを作成します。各エントリーは、キーと、各言語の翻訳値を持つアイテムです。

**2. 翻訳テキストの管理:**

新しい辞書エントリを作成するには、`/sitecore/system/Settings/Dictionary` を右クリックし、「Insert」>「Dictionary entry」を選択します。エントリーの名前（キー）を入力し、必要に応じて「Phrase」フィールドにデフォルト言語のテキストを入力します。

各言語の翻訳を追加するには、エントリーを選択し、「Versions」タブで「Add Version」をクリックして、言語を選択します。選択した言語のバージョンが作成されるので、「Phrase」フィールドに翻訳を入力します。

**3. 言語固有のテキストの表示:**

Sitecore レイアウトで、`Translate` ヘルパーメソッドを使用して、辞書エントリのテキストを表示します。

```csharp
// Razor View (.cshtml) の例
@using Sitecore.Mvc
@using Sitecore.Globalization

<p>@Html.Sitecore().Translate("YourDictionaryEntryKey")</p>
```

または、 Sitecore XP 10.3 以降では、 Experience Accelerator (SXA) の `{{Translate:YourDictionaryEntryKey}}` を使用することもできます。

#### 実践的なテクニック

* **辞書エントリの整理:** 辞書エントリをカテゴリ別に整理するために、フォルダを作成します。
* **プレースホルダーの使用:** 動的な値を表示するために、プレースホルダーを使用します（例: `Hello, {0}!`, ここで `{0}` は、コードで置き換えられる変数です）。
* **翻訳ワークフローの統合:** 辞書エントリの翻訳プロセスを Sitecore のワークフローと統合します。
* **Sitecore CLI を活用:** Sitecore CLI を使用して、辞書エントリをプログラムで管理します。

#### 応用例とユースケース

* **多言語対応のフォーム:** フォームのラベル、エラーメッセージ、ボタンテキストなどを Sitecore Dictionary で管理します。
* **多言語対応のナビゲーション:** ナビゲーションメニューのテキストを Sitecore Dictionary で管理します。
* **多言語対応のメールテンプレート:** メールテンプレートのテキストを Sitecore Dictionary で管理します。

#### トラブルシューティング

* **翻訳テキストが表示されない:** 辞書エントリが存在し、正しいキーが使用されているか確認してください。また、言語バージョンが正しく公開されているか確認してください。
* **翻訳テキストがキャッシュされている:** Sitecore 管理画面からキャッシュをクリアしてみてください。
* **辞書エントリのキーが重複している:** キーが重複しないように、命名規則に従ってください。

#### まとめと次のステップ

Sitecore Dictionary は、多言語サイトの翻訳プロセスを効率化し、コンテンツの一貫性を保つために不可欠なツールです。辞書エントリの作成、翻訳テキストの管理、そして `Translate` ヘルパーメソッドの使用を通じて、多言語対応を簡略化することができます。次のステップとして、多言語 SEO 対策について学習しましょう。

### 10.4. 多言語SEO対策

#### 概要と重要性

多言語サイトの SEO 対策は、検索エンジンがウェブサイトの構造とコンテンツを正しく理解し、各言語のユーザーに適切なページを表示するために不可欠です。適切な SEO 対策を行うことで、検索エンジンのランキングを向上させ、より多くのターゲットオーディエンスにリーチすることができます。

#### 特徴と利点

* **検索エンジンのランキング向上:** 適切な SEO 対策を行うことで、検索エンジンのランキングを向上させることができます。
* **ターゲットオーディエンスへのリーチ拡大:** 各言語のユーザーに適切なページを表示することで、ターゲットオーディエンスへのリーチを拡大することができます。
* **ウェブサイトのトラフィック増加:** 検索エンジンからのトラフィックを増加させることができます。
* **コンバージョン率の向上:** 適切なコンテンツとローカライゼーションを提供することで、コンバージョン率を向上させることができます。
* **国際的なブランド認知度の向上:** 多言語サイトを通じて、国際的なブランド認知度を向上させることができます。

#### 事前準備と前提条件

* Sitecore インスタンスが稼働していること
* 多言語サイトが構築されていること
* 各言語のキーワード調査が完了していること
* Google Search Console などの SEO ツールが設定されていること
* 多言語 SEO の基本的な知識があること

#### 基本的な使い方

**1. `hreflang` 属性の設定:**

`hreflang` 属性は、検索エンジンにウェブページの言語と地域を伝えるための HTML 属性です。`hreflang` 属性を正しく設定することで、検索エンジンは各言語のユーザーに適切なページを表示することができます。

`hreflang` 属性は、以下の3つの方法で設定できます。

* **HTML `<head>` セクション:** 各ページの `<head>` セクションに、関連するページの `hreflang` 属性を追加します。

```html
<link rel="alternate" href="https://example.com/en/" hreflang="en" />
<link rel="alternate" href="https://example.com/ja/" hreflang="ja-JP" />
<link rel="alternate" href="https://example.com/fr/" hreflang="fr-FR" />
```

* **HTTP ヘッダー:** HTTP ヘッダーを使用して、`hreflang` 属性を設定します。これは、PDF などの HTML 以外のファイルに `hreflang` 属性を設定する場合に便利です。
* **サイトマップ:** サイトマップに `hreflang` 属性を追加します。

Sitecore で `hreflang` 属性を自動的に設定するには、レイアウトに以下のコードを追加します。

```csharp
// Razor View (.cshtml) の例
@using Sitecore.Mvc
@using Sitecore.Globalization
@using Sitecore.Links

@{
    var languages = Sitecore.Context.Database.GetLanguages();
    foreach (var language in languages)
    {
        var options = new UrlOptions { LanguageEmbedding = LanguageEmbedding.Always };
        var url = LinkManager.GetItemUrl(Sitecore.Context.Item, options);

        <link rel="alternate" href="@url" hreflang="@language.Name" />
    }
}
```

**2. 多言語サイトマップの作成:**

多言語サイトマップは、ウェブサイトのすべてのページと、各ページの言語バージョンを検索エンジンに伝えるための XML ファイルです。多言語サイトマップを作成することで、検索エンジンはウェブサイトの構造を正しく理解し、各言語のユーザーに適切なページを表示することができます。

Sitecore で多言語サイトマップを自動的に生成するには、Sitecore Marketplace で利用可能なサードパーティのモジュールを使用するか、カスタムコードを記述する必要があります。

**3. 言語固有の URL の設定:**

各言語に対して固有の URL を設定することで、検索エンジンはウェブページの言語をより正確に理解することができます。言語固有の URL を設定する方法は、いくつかあります。

* **サブドメイン:** 各言語に対して異なるサブドメインを使用します（例: `en.example.com`, `ja.example.com`, `fr.example.com`）。
* **サブディレクトリ:** 各言語に対して異なるサブディレクトリを使用します（例: `example.com/en/`, `example.com/ja/`, `example.com/fr/`）。
* **URL パラメーター:** URL パラメーターを使用して、言語を指定します（例: `example.com?lang=en`, `example.com?lang=ja`, `example.com?lang=fr`）。

最も推奨される方法は、サブディレクトリを使用することです。

Sitecore で言語固有の URL を設定するには、`LinkManager` の設定を調整する必要があります。`LinkManager` の設定は、`/sitecore/linkManager` にあります。`LinkManager` の設定で、`languageEmbedding` 属性を `always` に設定します。

```xml
<linkManager defaultProvider="default">
  <providers>
    <add name="default" type="Sitecore.Links.LinkProvider, Sitecore.Kernel">
      <languageEmbedding>always</languageEmbedding>
    </add>
  </providers>
</linkManager>
```

#### 実践的なテクニック

* **キーワード調査:** 各言語でターゲットオーディエンスが検索するキーワードを調査します。
* **コンテンツのローカライゼーション:** コンテンツを単に翻訳するだけでなく、文化的な違いや地域的なニュアンスを考慮してローカライズします。
* **内部リンクの最適化:** 内部リンクを最適化することで、検索エンジンがウェブサイトの構造を理解しやすくします。
* **モバイル対応:** モバイルデバイスでの表示を最適化します。
* **表示速度の最適化:** ウェブサイトの表示速度を最適化します。
* **Google Search Console の活用:** Google Search Console を使用して、ウェブサイトの SEO パフォーマンスを監視し、改善点を見つけます。

#### 応用例とユースケース

* **多言語対応のブログ:** 各言語でブログ記事を作成し、SEO 対策を行います。
* **多言語対応のニュースサイト:** 各言語でニュース記事を作成し、SEO 対策を行います。
* **多言語対応の製品レビューサイト:** 各言語で製品レビューを作成し、SEO 対策を行います。

#### トラブルシューティング

* **`hreflang` 属性が正しく設定されていない:** `hreflang` 属性の設定を確認し、エラーがないか確認します。Google Search Console を使用して、`hreflang` 属性のエラーを検出することもできます。
* **多言語サイトマップが正しく生成されていない:** 多言語サイトマップが正しく生成されているか確認し、エラーがないか確認します。
* **検索エンジンのランキングが向上しない:** キーワード調査、コンテンツのローカライゼーション、内部リンクの最適化、モバイル対応、表示速度の最適化など、他の SEO 対策も行っているか確認します。

#### まとめと次のステップ

多言語 SEO 対策は、グローバルサイトを成功させるために不可欠です。`hreflang` 属性の設定、多言語サイトマップの作成、そして言語固有の URL の設定を通じて、検索エンジンにウェブサイトの構造とコンテンツを正しく伝え、各言語のユーザーに適切なページを表示することができます。定期的に SEO パフォーマンスを監視し、改善点を見つけて、ウェブサイトのトラフィックとコンバージョン率を向上させましょう。
