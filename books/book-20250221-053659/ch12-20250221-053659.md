## 第12章：サーチ機能の実装

Webサイトにおいて、サーチ機能はユーザーエクスペリエンスを大きく左右する重要な要素です。特にSitecoreのような複雑なコンテンツ構造を持つCMSにおいては、効果的なサーチ機能の実装が不可欠となります。本章では、Sitecoreにおけるサーチ機能の実装方法を、Content Search APIとHeadless環境でのSearch APIの利用を中心に解説します。カスタム検索コンポーネントの作成からSEO対策まで、実践的なテクニックを段階的に習得し、ユーザーが求める情報を迅速かつ正確に提供できるWebサイトを構築しましょう。

### 12.1. Sitecore Content Search API の概要

#### 12.1.1. 概要と重要性

Sitecore Content Search APIは、Sitecoreのコンテンツリポジトリに格納された情報を検索するための強力なツールです。アイテム名、コンテンツ、メタデータなど、さまざまな条件で情報を検索できます。効果的なサーチ機能は、ユーザーが目的の情報に素早くアクセスできるだけでなく、Webサイト全体のナビゲーションを改善し、エンゲージメントを高める上で重要な役割を果たします。

#### 12.1.2. 特徴と利点

*   **柔軟なクエリ:** LINQやPredicateBuilderを使用して、複雑な検索条件を記述できます。
*   **高いパフォーマンス:** インデックスを利用することで、高速な検索を実現します。
*   **カスタマイズ性:** 検索結果のフィルタリング、ソート、ページネーションなど、様々なカスタマイズが可能です。
*   **拡張性:** さまざまな検索エンジン（Solr, Azure Searchなど）に対応し、ニーズに合わせて柔軟に選択できます。

#### 12.1.3. 事前準備と前提条件

*   Sitecoreインスタンスが稼働していること。
*   SolrまたはAzure Searchなどの検索エンジンが設定されていること。
*   適切なインデックスが作成されていること。

#### 12.1.4. 基本的な使い方

まず、`Sitecore.ContentSearch`名前空間をインポートします。

```csharp
using Sitecore.ContentSearch;
using Sitecore.ContentSearch.Linq;
```

次に、検索インデックスを取得します。

```csharp
var index = ContentSearchManager.GetIndex("sitecore_web_index"); // 例：webデータベースのインデックス
```

LINQを使用して検索クエリを作成し、実行します。

```csharp
using (var context = index.CreateSearchContext())
{
    var results = context.GetQueryable<SearchResultItem>()
        .Where(i => i.Content.Contains("キーワード"))
        .Take(10) // 上位10件を取得
        .ToList();

    foreach (var result in results)
    {
        Console.WriteLine(result.Title);
    }
}
```

#### 12.1.5. 実践的なテクニック

*   **PredicateBuilderの利用:** 複雑な検索条件を動的に構築できます。

```csharp
using Sitecore.ContentSearch.Linq.Utilities;
using System.Linq.Expressions;

// PredicateBuilder を使用して OR 条件を動的に追加
Expression<Func<SearchResultItem, bool>> predicate = PredicateBuilder.False<SearchResultItem>();
predicate = predicate.Or(i => i.Title.Contains("キーワード1"));
predicate = predicate.Or(i => i.Content.Contains("キーワード2"));

using (var context = index.CreateSearchContext())
{
    var results = context.GetQueryable<SearchResultItem>()
        .Where(predicate)
        .ToList();
}
```

*   **フィールド検索:** 特定のフィールドに絞って検索します。

```csharp
var results = context.GetQueryable<SearchResultItem>()
    .Where(i => i["FieldName"].Contains("キーワード")) // FieldName はフィールド名
    .ToList();
```

*   **ブースト:** 特定の条件に一致するアイテムの検索結果順位を上げます。

```csharp
var results = context.GetQueryable<SearchResultItem>()
    .Where(i => i.TemplateName == "Article").Boost(1.2f) // Article テンプレートのアイテムをブースト
    .ToList();
```

#### 12.1.6. 応用例とユースケース

*   **FAQ検索:** FAQアイテムのコンテンツを検索し、関連する質問と回答を表示します。
*   **製品検索:** 製品名、カテゴリ、説明などのフィールドを検索し、該当する製品を表示します。
*   **コンテンツ検索:** サイト全体のコンテンツを検索し、関連するページを表示します。
*   **高度なフィルタリング:** ファセット検索を利用して、カテゴリ、価格帯、色などの条件で検索結果を絞り込みます。

#### 12.1.7. トラブルシューティング

*   **検索結果が期待通りでない場合:**
    *   インデックスが最新の状態であることを確認してください。
    *   クエリが正しいことを確認してください。
    *   SolrまたはAzure Searchのログを確認して、エラーがないか確認してください。
*   **パフォーマンスが悪い場合:**
    *   適切なインデックスが設定されていることを確認してください。
    *   クエリを最適化してください。
    *   検索エンジンのリソースを増やすことを検討してください。

#### 12.1.8. まとめと次のステップ

Sitecore Content Search APIは、Sitecoreのコンテンツを検索するための強力なツールです。基本的な使い方から実践的なテクニックまで習得することで、ユーザーエクスペリエンスを向上させるサーチ機能を実装できます。次のステップとして、検索結果の表示方法のカスタマイズや、検索パフォーマンスの最適化について学習することをお勧めします。

### 12.2. Headless 環境でのサーチ機能の実装

#### 12.2.1. 概要と重要性

Headless Sitecore環境では、コンテンツの配信と表示が分離されています。そのため、Sitecore Content Search APIを直接利用する代わりに、Sitecore Search APIまたは外部の検索サービスを利用する必要があります。Headless環境におけるサーチ機能は、フロントエンド技術に依存せず、APIを通じて検索結果を取得できるため、柔軟な開発が可能になります。

#### 12.2.2. 特徴と利点

*   **フロントエンド技術に依存しない:** React, Angular, Vue.jsなど、あらゆるフロントエンドフレームワークで利用できます。
*   **柔軟なAPI:** RESTful APIを通じて検索を実行し、JSON形式で結果を取得できます。
*   **高いスケーラビリティ:** 外部の検索サービスを利用することで、大規模なWebサイトにも対応できます。

#### 12.2.3. 事前準備と前提条件

*   Headless Sitecore環境が構築されていること。
*   Sitecore Search APIまたは外部の検索サービスが設定されていること。
*   APIキーまたは認証情報が設定されていること。

#### 12.2.4. Sitecore Search API の利用

Sitecore Search APIは、Sitecore XP 10.3以降で利用可能な、SaaS型の検索サービスです。

まず、APIキーを取得し、APIエンドポイントを確認します。

次に、APIリクエストを送信します。

```javascript
// JavaScript (fetch APIを使用)
const apiKey = 'YOUR_API_KEY';
const endpoint = 'YOUR_API_ENDPOINT';
const searchTerm = 'キーワード';

fetch(`${endpoint}/search?q=${searchTerm}`, {
    method: 'GET',
    headers: {
        'X-API-Key': apiKey,
        'Content-Type': 'application/json'
    }
})
.then(response => response.json())
.then(data => {
    // 検索結果を処理
    console.log(data);
})
.catch(error => {
    console.error('Error:', error);
});
```

#### 12.2.5. 検索クエリの作成

検索クエリは、APIのエンドポイントにパラメータとして渡します。主なパラメータは以下の通りです。

*   `q`: 検索キーワード
*   `fq`: フィルタリング条件 (例: `template:Article`)
*   `sort`: ソート条件 (例: `date desc`)
*   `start`: ページネーションの開始位置
*   `rows`: ページあたりの表示件数

#### 12.2.6. 検索結果の表示

APIから返されたJSONデータを解析し、フロントエンドで適切に表示します。

```javascript
// JavaScript (JSONデータの例)
const searchResults = [
    {
        "title": "記事のタイトル1",
        "url": "/article1",
        "summary": "記事の概要1"
    },
    {
        "title": "記事のタイトル2",
        "url": "/article2",
        "summary": "記事の概要2"
    }
];

// Reactコンポーネントの例
function SearchResultsComponent({ results }) {
    return (
        <ul>
            {results.map(result => (
                <li key={result.url}>
                    <a href={result.url}>{result.title}</a>
                    <p>{result.summary}</p>
                </li>
            ))}
        </ul>
    );
}
```

#### 12.2.7. 応用例とユースケース

*   **SPA (Single Page Application) での検索:** React, Angular, Vue.jsなどのフレームワークで構築されたSPAで、リアルタイムな検索結果を表示します。
*   **モバイルアプリでの検索:** ネイティブアプリまたはハイブリッドアプリからAPIを呼び出し、検索結果を表示します。
*   **チャットボットとの連携:** チャットボットからAPIを呼び出し、ユーザーの質問に対する回答を検索します。

#### 12.2.8. トラブルシューティング

*   **APIリクエストが失敗する場合:**
    *   APIキーが正しいことを確認してください。
    *   APIエンドポイントが正しいことを確認してください。
    *   ネットワーク接続を確認してください。
*   **検索結果が期待通りでない場合:**
    *   クエリパラメータが正しいことを確認してください。
    *   インデックスが最新の状態であることを確認してください。
    *   検索エンジンのログを確認して、エラーがないか確認してください。

#### 12.2.9. まとめと次のステップ

Headless環境でのサーチ機能は、フロントエンド技術に依存せず、柔軟な開発が可能です。Sitecore Search APIを利用することで、容易にサーチ機能を実装できます。次のステップとして、検索結果の表示方法のカスタマイズや、検索パフォーマンスの最適化について学習することをお勧めします。また、AlgoliaやElasticsearchなどの外部検索サービスとの連携も検討してみましょう。

### 12.3. カスタム検索コンポーネントの作成

#### 12.3.1. 概要と重要性

Sitecoreの標準検索コンポーネントは、基本的な検索機能を提供しますが、要件によってはカスタマイズが必要です。カスタム検索コンポーネントを作成することで、検索フォームのデザイン、検索結果の表示方法、フィルタリングやソートなど、Webサイトのブランドイメージやユーザーニーズに合わせた独自の検索エクスペリエンスを提供できます。

#### 12.3.2. 特徴と利点

*   **デザインの自由度:** Webサイトのデザインに合わせて、検索フォームや検索結果の表示を自由にカスタマイズできます。
*   **高度な機能:** フィルタリング、ソート、ページネーションなど、高度な検索機能を追加できます。
*   **パフォーマンスの最適化:** クエリの最適化やキャッシュの利用など、検索パフォーマンスを向上させるためのチューニングが可能です。

#### 12.3.3. 事前準備と前提条件

*   Sitecoreインスタンスが稼働していること。
*   Visual Studioなどの開発環境が設定されていること。
*   Sitecore開発の基本的な知識があること。

#### 12.3.5. 検索結果のフィルタリングとソート

検索結果のフィルタリングとソートは、Content Search APIのクエリに条件を追加することで実現できます。

```csharp
// フィルタリングの例 (テンプレートでフィルタリング)
var results = context.GetQueryable<SearchResultItem>()
    .Where(i => i.TemplateName == "Article")
    .ToList();

// ソートの例 (日付で降順ソート)
var results = context.GetQueryable<SearchResultItem>()
    .OrderByDescending(i => i.Created)
    .ToList();
```

#### 12.3.6. ページネーションの実装

ページネーションは、検索結果を複数のページに分割して表示するための機能です。

```csharp
// ページネーションの例
int pageSize = 10; // 1ページあたりの表示件数
int pageNumber = 1; // 現在のページ番号

if (Request.QueryString["page"] != null)
{
    int.TryParse(Request.QueryString["page"], out pageNumber);
}

var results = context.GetQueryable<SearchResultItem>()
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize)
    .ToList();

// 総件数を取得
int totalCount = context.GetQueryable<SearchResultItem>().Count();

// ページネーション情報をビューに渡す
ViewBag.PageSize = pageSize;
ViewBag.PageNumber = pageNumber;
ViewBag.TotalCount = totalCount;
```

ビューでページネーションリンクを表示します。

```html
// Razorビューの例
@if (ViewBag.TotalCount > ViewBag.PageSize)
{
    int totalPages = (int)Math.Ceiling((double)ViewBag.TotalCount / ViewBag.PageSize);

    <div class="pagination">
        @for (int i = 1; i <= totalPages; i++)
        {
            <a href="?q=@Request.QueryString["q"]&page=@i" class="@(ViewBag.PageNumber == i ? "active" : "")">@i</a>
        }
    </div>
}
```

### 12.4. SEO 対策としてのサーチ機能

#### 12.4.1. 概要と重要性

サーチ機能は、ユーザーがWebサイト内のコンテンツを見つけやすくするだけでなく、SEO（Search Engine Optimization）にも貢献します。検索エンジンは、Webサイトの構造、コンテンツの品質、ユーザーエクスペリエンスを評価し、検索順位を決定します。効果的なサーチ機能を実装することで、検索エンジンがWebサイトをクロールしやすくなり、インデックスの作成を促進し、検索順位の向上に繋がります。

#### 12.4.2. 特徴と利点

*   **クローラビリティの向上:** 検索エンジンがWebサイト内のコンテンツをクロールしやすくなります。
*   **インデックス作成の促進:** 検索エンジンがWebサイトのインデックスを効率的に作成できます。
*   **キーワードの最適化:** 検索キーワードに基づいてコンテンツを表示することで、キーワードの関連性を高めます。
*   **ユーザーエンゲージメントの向上:** ユーザーが求める情報に素早くアクセスできるため、Webサイトの滞在時間や回遊率が向上します。

#### 12.4.3. 事前準備と前提条件

*   Webサイトが検索エンジンに登録されていること。
*   Google Search Consoleなどのツールが設定されていること。
*   Webサイトの構造が最適化されていること。

#### 12.4.4. 検索エンジンのクローラー向けの設定

*   **robots.txt:** 検索エンジンのクローラーに、クロールを許可または拒否するディレクトリやファイルを指定します。検索結果ページが大量に生成される場合、クローラーの負荷を軽減するために、robots.txtで検索結果ページをクロールしないように設定することを検討してください。ただし、重要な検索結果ページはクロールさせるように注意が必要です。

```
User-agent: *
Disallow: /search-results/
```

*   **sitemap.xml:** Webサイトの構造を検索エンジンに伝えるためのXMLファイルです。sitemap.xmlに検索結果ページを含めることは推奨されません。なぜなら、検索結果ページは動的に生成されるため、内容が頻繁に変わる可能性があり、検索エンジンのインデックス作成に悪影響を与える可能性があるからです。重要なページへのリンクをsitemap.xmlに含めるようにしましょう。

#### 12.4.5. 検索結果ページの最適化

*   **URLの最適化:** 検索結果ページのURLは、SEOに配慮した構造にする必要があります。キーワードを含める、分かりやすい構造にする、動的なパラメータを避けるなどの対策が必要です。

```
// 悪い例:
/search?q=キーワード&page=1

// 良い例:
/search/キーワード/page/1
```

*   **タイトルタグの最適化:** 検索結果ページのタイトルタグは、検索キーワードとWebサイトのブランド名を含めるようにします。

```html
<title>キーワードの検索結果 | Webサイト名</title>
```

*   **メタディスクリプションの最適化:** 検索結果ページのメタディスクリプションは、検索結果の概要を説明し、ユーザーにクリックを促すように記述します。

```html
<meta name="description" content="キーワードに関する検索結果を表示しています。詳細はこちらをご覧ください。" />
```

*   **コンテンツの最適化:** 検索結果ページには、検索キーワードに関連するコンテンツを表示するようにします。検索結果の一覧だけでなく、検索キーワードに関する簡単な説明や、関連するコンテンツへのリンクを含めることも効果的です。

#### 12.4.6. 応用例とユースケース

*   **ナレッジベースの検索:** ナレッジベースの記事を検索し、FAQやトラブルシューティングに関する情報を提供します。
*   **Eコマースサイトの検索:** 製品名、カテゴリ、ブランドなどの条件で製品を検索し、購買意欲を高めます。
*   **コンテンツマーケティングサイトの検索:** ブログ記事、ホワイトペーパー、ケーススタディなどを検索し、リードジェネレーションに貢献します。

#### 12.4.7. トラブルシューティング

*   **検索結果ページが検索エンジンにインデックスされない場合:**
    *   robots.txtで検索結果ページがクロール拒否されていないか確認してください。
    *   sitemap.xmlに検索結果ページが含まれていないか確認してください。
    *   Google Search Consoleでインデックス登録をリクエストしてください。
*   **検索結果ページの順位が低い場合:**
    *   キーワードの最適化が十分に行われているか確認してください。
    *   コンテンツの品質が低い可能性があるので、内容を改善してください。
    *   被リンクが少ない可能性があるので、被リンクを増やすための施策を実施してください。

#### 12.4.8. まとめと次のステップ

サーチ機能は、ユーザーエクスペリエンスを向上させるだけでなく、SEOにも貢献します。検索エンジンのクローラー向けの設定や、検索結果ページの最適化を行うことで、検索エンジンがWebサイトをクロールしやすくなり、インデックスの作成を促進し、検索順位の向上に繋がります。次のステップとして、検索エンジンのアルゴリズムの変更に対応するために、定期的にSEO対策を見直すことをお勧めします。また、ユーザーの検索行動を分析し、検索キーワードやコンテンツを最適化することも重要です。
