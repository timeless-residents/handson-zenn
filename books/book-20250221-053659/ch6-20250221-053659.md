## 第6章：データ取得と GraphQL

### 6.1. GraphQL の基礎

**概要と重要性**

GraphQL は、Facebook によって開発された API のためのクエリ言語であり、クライアントが必要なデータだけを要求できるという特徴を持っています。従来の REST API と比較して、GraphQL はオーバーフェッチングやアンダーフェッチングの問題を解決し、より効率的なデータ取得を実現します。Sitecore JSS (JavaScript Services) 環境においても、GraphQL は重要な役割を果たしており、柔軟かつ効率的なデータ取得手段を提供します。

**特徴と利点**

*   **必要なデータのみを取得**: クライアントは、必要なフィールドのみを明示的に要求できるため、不要なデータの転送を削減できます。
*   **単一のエンドポイント**: 複数の REST API エンドポイントを呼び出す代わりに、単一の GraphQL エンドポイントを使用して複数のリソースを取得できます。
*   **スキーマ駆動**: GraphQL は、API の型システムを定義するスキーマに基づいており、クライアントは利用可能なデータ構造を容易に理解できます。
*   **強力な型システム**: 型システムにより、クエリの検証とエラー検出が容易になります。
*   **イントロスペクション**: クライアントは、API のスキーマを自己探索できるため、ドキュメントの作成や保守が容易になります。

**クエリ、ミューテーション、サブスクリプションの基本**

GraphQL には、主に以下の3つの操作タイプがあります。

*   **クエリ (Query)**: データの取得に使用します。REST API の GET リクエストに相当します。
*   **ミューテーション (Mutation)**: データの変更 (作成、更新、削除) に使用します。REST API の POST, PUT, DELETE リクエストに相当します。
*   **サブスクリプション (Subscription)**: リアルタイムのデータ更新を受信するために使用します。WebSocket などを利用します。

以下にそれぞれの例を示します。

**クエリの例:**

```graphql
query {
  item(path: "/sitecore/content/Home") {
    id
    name
    title {
      value
    }
  }
}
```

このクエリは、`/sitecore/content/Home` パスにあるアイテムの `id`、`name`、および `title` フィールドの値を取得します。

**ミューテーションの例:**

```graphql
mutation {
  updateItem(
    id: "{11111111-1111-1111-1111-111111111111}"
    fields: [
      {
        name: "Title"
        value: "新しいタイトル"
      }
    ]
  ) {
    id
    name
    title {
      value
    }
  }
}
```

このミューテーションは、ID `{11111111-1111-1111-1111-111111111111}` のアイテムの `Title` フィールドを "新しいタイトル" に更新します。

**GraphQL Playground の利用**

GraphQL Playground は、GraphQL API を探索し、クエリを実行するための強力なツールです。ブラウザ上で動作し、スキーマの探索、クエリの作成、実行、結果の表示を簡単に行うことができます。

通常、Sitecore GraphQL エンドポイントにアクセスできる状態で、`/[sitecore instance URL]/sitecore/api/graph/playground` にアクセスすることでGraphQL Playground を利用できます。例えば、ローカル開発環境の場合、`http://your-sitecore-instance.local/sitecore/api/graph/playground` のようなURLになります。

GraphQL Playground では、以下の機能が利用できます。

*   **スキーマエクスプローラ**: 利用可能な型とフィールドを探索できます。
*   **自動補完**: クエリの作成を支援します。
*   **リアルタイムエラーチェック**: クエリの構文エラーを即座に検出します。
*   **クエリ履歴**: 過去に実行したクエリを再利用できます。
*   **レスポンス表示**: クエリの結果を整形された JSON 形式で表示します。

**まとめと次のステップ**

このセクションでは、GraphQL の基本的な概念と利点、およびクエリ、ミューテーション、サブスクリプションの基本的な使い方を学びました。また、GraphQL Playground を使用して API を探索する方法についても説明しました。次のセクションでは、Sitecore GraphQL API の利用方法について詳しく解説します。

### 6.2. Sitecore GraphQL API の利用

**概要と重要性**

Sitecore GraphQL API は、Sitecore のコンテンツを柔軟かつ効率的に取得するための強力なツールです。従来の Sitecore API (Item API, Service API) に比べて、GraphQL は必要なデータのみを取得できるため、パフォーマンスの向上に貢献します。また、スキーマ駆動であるため、クライアントは利用可能なデータ構造を容易に理解できます。

**特徴と利点**

*   **コンテンツ検索 API (Content Search API)**: Sitecore のインデックスを使用してコンテンツを検索できます。これにより、高速かつ柔軟な検索が可能になります。
*   **Sitecore コンテキスト API (Sitecore Context API)**: 現在の Sitecore コンテキスト (サイト、言語、デバイスなど) にアクセスできます。
*   **柔軟なクエリ**: クライアントは、必要なフィールドのみを明示的に要求できるため、オーバーフェッチングの問題を解決できます。
*   **スキーマ駆動**: GraphQL スキーマは、Sitecore のテンプレート構造を反映しており、クライアントは利用可能なデータ構造を容易に理解できます。

**事前準備と前提条件**

*   Sitecore インスタンスが稼働していること。
*   GraphQL エンドポイントが有効になっていること。 (デフォルトでは有効になっています)
*   適切な認証設定が完了していること。 (匿名アクセスを許可するか、API キーを設定するか)

**Sitecore GraphQL エンドポイントの設定**

Sitecore GraphQL エンドポイントは、通常、`/[sitecore instance URL]/sitecore/api/graph/items/master` のような URL でアクセスできます。`master` はデータベース名を示しており、`web` データベースにアクセスする場合は、`/[sitecore instance URL]/sitecore/api/graph/items/web` となります。

エンドポイントの設定は、Sitecore の設定ファイル (`Sitecore.config` など) で管理されています。必要に応じて、エンドポイントの URL、認証設定、およびその他のオプションをカスタマイズできます。

**Content Search API と Sitecore Context API の利用**

**Content Search API**: Sitecore のインデックスを使用してコンテンツを検索するために使用します。以下に例を示します。

```graphql
query {
  search(
    index: "sitecore_master_index"
    first: 10
    query: "Title:検索キーワード"
  ) {
    total
    results {
      item {
        id
        name
        title {
          value
        }
        url
      }
    }
  }
}
```

このクエリは、`sitecore_master_index` インデックスで、`Title` フィールドに "検索キーワード" を含むアイテムを検索し、最初の 10 件の結果を返します。結果には、アイテムの `id`、`name`、`title`、および `url` が含まれます。

**Sitecore Context API**: 現在の Sitecore コンテキストにアクセスするために使用します。以下に例を示します。

```graphql
query {
  context {
    site {
      name
    }
    language {
      name
    }
  }
}
```

このクエリは、現在のサイト名と言語名を取得します。

**GraphQL クエリの作成と実行**

GraphQL クエリは、GraphQL Playground などのツールを使用して作成および実行できます。クエリを作成する際には、以下の点に注意してください。

*   **必要なフィールドのみを選択**: 不要なフィールドを選択すると、パフォーマンスが低下する可能性があります。
*   **適切なフィルタリング**: 必要なデータのみを抽出するために、適切なフィルタリング条件を設定します。
*   **リレーションシップの解決**: 関連するアイテムを取得するために、リレーションシップを適切に解決します。

**実践的なテクニック**

*   **エイリアス**: 同じフィールドを複数回取得する場合、エイリアスを使用すると、レスポンスの構造を明確にすることができます。

    ```graphql
    query {
      home: item(path: "/sitecore/content/Home") {
        id
        name
      }
      about: item(path: "/sitecore/content/Home/About") {
        id
        name
      }
    }
    ```

*   **フラグメント**: 複数のクエリで共通のフィールドセットを使用する場合、フラグメントを使用すると、コードの重複を避けることができます。

    ```graphql
    fragment ItemFields on Item {
      id
      name
      title {
        value
      }
    }

    query {
      item(path: "/sitecore/content/Home") {
        ...ItemFields
      }
    }
    ```

*   **変数**: クエリに変数を使用すると、クエリを動的にすることができます。

    ```graphql
    query getItem($path: String!) {
      item(path: $path) {
        id
        name
      }
    }

    # 変数の値: { "path": "/sitecore/content/Home" }
    ```

**応用例とユースケース**

*   **コンテンツの一覧表示**: カテゴリやタグに基づいてコンテンツを一覧表示する。
*   **コンテンツの詳細表示**: 特定のアイテムの詳細情報を表示する。
*   **検索機能の実装**: Sitecore のインデックスを使用してコンテンツを検索する。
*   **多言語サイトの構築**: Sitecore の多言語機能を活用して、複数の言語でコンテンツを表示する。
*   **パーソナライズ**: Sitecore のパーソナライズ機能を活用して、ユーザーに合わせたコンテンツを表示する。

**トラブルシューティング**

*   **認証エラー**: GraphQL エンドポイントへのアクセスに必要な認証情報が不足している可能性があります。API キーが正しく設定されているか、または匿名アクセスが許可されているか確認してください。
*   **クエリのエラー**: GraphQL クエリに構文エラーまたは論理エラーがある可能性があります。GraphQL Playground を使用してクエリを検証し、エラーメッセージを確認してください。
*   **パフォーマンスの問題**: クエリが過剰なデータを要求しているか、またはインデックスが最適化されていない可能性があります。必要なフィールドのみを選択し、インデックスを最適化してください。
*   ** CORS (Cross-Origin Resource Sharing) エラー**:  異なるドメインから GraphQL エンドポイントにアクセスする場合、CORS エラーが発生する可能性があります。Sitecore 側の設定で、アクセスを許可するドメインを明示的に指定する必要があります。

**まとめと次のステップ**

### 6.3. JSS GraphQL クエリの作成

**概要と重要性**

Sitecore JSS (JavaScript Services) で GraphQL を使用することで、フロントエンドアプリケーションから Sitecore のデータを効率的に取得できます。JSS 環境では、GraphQL クエリは、コンポーネントのデータソースとして機能し、動的なコンテンツ表示を実現します。

**特徴と利点**

*   **コンポーネント駆動開発**: GraphQL クエリは、コンポーネントごとに定義できるため、コンポーネント駆動開発に適しています。
*   **柔軟なデータ取得**: 必要なデータのみを取得できるため、パフォーマンスの向上に貢献します。
*   **型安全性**: GraphQL スキーマは、データの型を定義するため、型安全性を高めることができます。
*   **スキーマ共有**: GraphQL スキーマは、フロントエンドとバックエンドで共有できるため、開発効率が向上します。

**事前準備と前提条件**

*   Sitecore JSS アプリケーションがセットアップされていること。
*   GraphQL エンドポイントが有効になっていること。
*   JSS アプリケーションから GraphQL エンドポイントにアクセスできること。

**Sitecore データを取得するための GraphQL クエリの設計**

GraphQL クエリを設計する際には、以下の点を考慮してください。

*   **コンポーネントの要件**: コンポーネントが表示するために必要なデータを特定します。
*   **Sitecore のテンプレート構造**: Sitecore のテンプレート構造を理解し、必要なフィールドを特定します。
*   **パフォーマンス**: 不要なフィールドを選択しないように、パフォーマンスを考慮します。

**必要なフィールドの選択とフィルタリング**

GraphQL クエリでは、必要なフィールドのみを明示的に選択できます。これにより、不要なデータの転送を削減し、パフォーマンスを向上させることができます。

また、フィルタリング条件を使用することで、必要なデータのみを抽出できます。

**例:**

```graphql
query {
  item(path: "/sitecore/content/Home") {
    id
    name
    title {
      value
    }
    children {
      results {
        item {
          id
          name
          templateName
        }
      }
    }
  }
}
```

このクエリは、`/sitecore/content/Home` パスにあるアイテムの `id`、`name`、`title`、および子アイテムの `id`、`name`、`templateName` を取得します。

**リレーションシップの解決**

Sitecore では、アイテム間のリレーションシップが定義されている場合があります。GraphQL クエリでは、これらのリレーションシップを解決し、関連するアイテムを取得できます。

**例:**

```graphql
query {
  item(path: "/sitecore/content/Home") {
    id
    name
    relatedArticles {
      results {
        item {
          id
          name
          title {
            value
          }
        }
      }
    }
  }
}
```

このクエリは、`/sitecore/content/Home` パスにあるアイテムに関連付けられた記事を取得します。`relatedArticles` は、リレーションシップフィールド (例えば、Link Field) を表します。

**実践的なテクニック**

*   **JSS コンポーネントに GraphQL クエリを埋め込む**: JSS コンポーネントの定義ファイルに GraphQL クエリを埋め込むことで、コンポーネントがデータを取得する方法を定義できます。
*   **GraphQL コードジェネレーション**: GraphQL スキーマから TypeScript の型を自動生成することで、型安全性を高めることができます。これにより、コンポーネント内でデータにアクセスする際に、タイプセーフなコードを書くことができます。
*   **データマッピング**: GraphQL から取得したデータを、コンポーネントが期待する形式にマッピングします。

**応用例とユースケース**

*   **コンテンツドリブンなナビゲーション**: Sitecore のコンテンツ構造に基づいて、動的なナビゲーションメニューを生成する。
*   **関連コンテンツの表示**: ユーザーが閲覧しているコンテンツに関連するコンテンツを表示する。
*   **検索結果の表示**: Sitecore の検索機能を使用して、検索結果を表示する。
*   **フォームの送信**: フォームデータを Sitecore に送信する。 (ミューテーションを使用)

**トラブルシューティング**

*   **GraphQL クエリのエラー**: クエリの構文エラーや論理エラーをチェックします。GraphQL Playground を使用してクエリを検証します。
*   **データの欠落**: 必要なフィールドが GraphQL クエリで選択されているか確認します。また、Sitecore のアイテムにデータが設定されているか確認します。
*   **パフォーマンスの問題**: クエリが過剰なデータを要求していないか確認します。インデックスが最適化されているか確認します。
*   **JSS アプリケーションの設定**: JSS アプリケーションが GraphQL エンドポイントに正しく接続されているか確認します。

**まとめと次のステップ**

このセクションでは、JSS GraphQL クエリの作成方法について学びました。コンポーネントの要件に基づいてクエリを設計し、必要なフィールドを選択し、リレーションシップを解決する方法について説明しました。次のセクションでは、Next.js での GraphQL クエリの実行方法について詳しく解説します。

### 6.4. Next.js での GraphQL クエリの実行

**概要と重要性**

Next.js は、React ベースのフレームワークであり、サーバーサイドレンダリング (SSR) や静的サイト生成 (SSG) などの機能を提供します。Next.js で GraphQL を使用することで、高性能で SEO に最適化された JSS アプリケーションを構築できます。

**特徴と利点**

*   **サーバーサイドレンダリング (SSR)**: サーバーサイドで HTML を生成するため、SEO に有利です。
*   **静的サイト生成 (SSG)**: ビルド時に HTML を生成するため、高速なパフォーマンスを実現できます。
*   **クライアントサイドレンダリング (CSR)**: クライアントサイドでデータを取得し、レンダリングできます。
*   **API ルート**: Next.js の API ルートを使用して、バックエンド処理を実装できます。

**事前準備と前提条件**

*   Next.js プロジェクトがセットアップされていること。
*   GraphQL エンドポイントが利用可能であること。
*   `graphql-request` ライブラリがインストールされていること。 (`npm install graphql-request` または `yarn add graphql-request`)

**`graphql-request` ライブラリの利用**

`graphql-request` は、GraphQL API にリクエストを送信するための軽量な HTTP クライアントです。使いやすく、Promise ベースであるため、非同期処理を容易に扱うことができます。

**基本的な使い方:**

```javascript
import { GraphQLClient, gql } from 'graphql-request';

const endpoint = 'http://your-sitecore-instance.local/sitecore/api/graph/items/master';

const graphQLClient = new GraphQLClient(endpoint);

const query = gql`
  query {
    item(path: "/sitecore/content/Home") {
      id
      name
      title {
        value
      }
    }
  }
`;

async function fetchData() {
  try {
    const data = await graphQLClient.request(query);
    console.log(data);
    return data;
  } catch (error) {
    console.error('GraphQL Error:', error);
    return null;
  }
}

export default fetchData;
```

このコードは、`graphql-request` ライブラリを使用して、指定された GraphQL エンドポイントにクエリを送信し、結果をコンソールに出力します。

**Server-Side Rendering (SSR) と Client-Side Rendering (CSR) の選択**

Next.js では、SSR、SSG、および CSR のいずれかを選択できます。

*   **SSR**: `getServerSideProps` 関数を使用します。リクエストごとにサーバーサイドでデータを取得し、HTML を生成します。SEO に最適ですが、パフォーマンスに影響を与える可能性があります。
*   **SSG**: `getStaticProps` 関数を使用します。ビルド時にデータを取得し、HTML を生成します。高速なパフォーマンスを実現できますが、動的なコンテンツには適していません。`getStaticPaths` 関数と組み合わせて動的なルーティングも可能です。
*   **CSR**: `useEffect` フックを使用します。クライアントサイドでデータを取得し、レンダリングします。インタラクティブなコンテンツに適していますが、SEO には不利です。

**SSR の例:**

```javascript
import { GraphQLClient, gql } from 'graphql-request';

const endpoint = 'http://your-sitecore-instance.local/sitecore/api/graph/items/master';

const graphQLClient = new GraphQLClient(endpoint);

const query = gql`
  query {
    item(path: "/sitecore/content/Home") {
      id
      name
      title {
        value
      }
    }
  }
`;

export async function getServerSideProps() {
  try {
    const data = await graphQLClient.request(query);
    return {
      props: {
        data,
      },
    };
  } catch (error) {
    console.error('GraphQL Error:', error);
    return {
      props: {
        error: 'Failed to fetch data',
      },
    };
  }
}

function HomePage({ data, error }) {
  if (error) {
    return <div>Error: {error}</div>;
  }

  if (!data) {
    return <div>Loading...</div>;
  }

  return (
    <div>
      <h1>{data.item.title.value}</h1>
      <p>{data.item.name}</p>
    </div>
  );
}

export default HomePage;
```

このコードは、`getServerSideProps` 関数を使用して、サーバーサイドでデータを取得し、`HomePage` コンポーネントに渡します。

**エラーハンドリングとデータの表示**

GraphQL クエリの実行中にエラーが発生する可能性があります。エラーハンドリングを適切に行い、ユーザーにわかりやすいエラーメッセージを表示することが重要です。

**例:**

```javascript
import { GraphQLClient, gql } from 'graphql-request';
import { useState, useEffect } from 'react';

const endpoint = 'http://your-sitecore-instance.local/sitecore/api/graph/items/master';

const graphQLClient = new GraphQLClient(endpoint);

const query = gql`
  query {
    item(path: "/sitecore/content/Home") {
      id
      name
      title {
        value
      }
    }
  }
`;

function HomePage() {
  const [data, setData] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    async function fetchData() {
      try {
        const result = await graphQLClient.request(query);
        setData(result);
        setLoading(false);
      } catch (e) {
        setError(e.message);
        setLoading(false);
      }
    }

    fetchData();
  }, []);

  if (loading) {
    return <div>Loading...</div>;
  }

  if (error) {
    return <div>Error: {error}</div>;
  }

  return (
    <div>
      <h1>{data.item.title.value}</h1>
      <p>{data.item.name}</p>
    </div>
  );
}

export default HomePage;
```

このコードは、`useState` フックを使用して、データの状態を管理し、`useEffect` フックを使用して、コンポーネントのマウント時にデータを取得します。エラーが発生した場合は、エラーメッセージを表示します。

**応用例とユースケース**

*   **ダイナミックルーティング**: Sitecore のコンテンツ構造に基づいて、動的なルーティングを実装する。
*   **コンテンツのプレビュー**: Sitecore のプレビュー機能を活用して、コンテンツの変更をリアルタイムで確認する。
*   **ヘッドレスコマース**: Sitecore Commerce と連携して、ヘッドレスコマースサイトを構築する。

**トラブルシューティング**

*   **CORS エラー**: 異なるドメインから GraphQL エンドポイントにアクセスする場合、CORS エラーが発生する可能性があります。Sitecore 側の設定で、アクセスを許可するドメインを明示的に指定する必要があります。
*   **認証エラー**: GraphQL エンドポイントへのアクセスに必要な認証情報が不足している可能性があります。API キーが正しく設定されているか、または匿名アクセスが許可されているか確認してください。
*   **パフォーマンスの問題**: クエリが過剰なデータを要求しているか、またはインデックスが最適化されていない可能性があります。必要なフィールドのみを選択し、インデックスを最適化してください。
*   **Next.js の設定**: Next.js の設定が正しく行われているか確認します。特に、環境変数が正しく設定されているか確認します。
