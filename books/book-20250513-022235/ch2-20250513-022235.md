## 第 2 章：開発環境構築：最高のスタートダッシュを切るために

プログラミングの世界では、開発環境の構築は、家を建てる際の基礎工事と同じくらい重要です。しっかりとした基礎があってこそ、安定した開発、効率的なテスト、そしてスムーズなデプロイが可能になります。本章では、Salesforce 開発における最高のスタートダッシュを切るために必要な環境構築について、基礎から実践的なテクニックまで網羅的に解説します。

### 2.1 Salesforce 組織の基礎：エディション、Sandbox、Developer Edition

#### 2.1.1 概要と重要性

Salesforce での開発を始めるにあたって、まず理解しておくべきは Salesforce 組織（以下、組織）の種類です。組織とは、Salesforce のデータや設定、コードなどが格納される場所であり、開発、テスト、本番運用といった目的に応じて異なる種類が存在します。組織の選択を誤ると、開発効率が低下したり、本番環境に影響を与えてしまう可能性があります。

#### 2.1.2 特徴と利点

Salesforce には様々なエディションがありますが、ここでは開発に関連性の高いエディションと組織の種類に焦点を当てます。

- **エディション:**
  - **Professional Edition:** 小規模企業向けの基本的なエディション。開発機能は限定的です。
  - **Enterprise Edition:** 中規模企業向けの標準的なエディション。Sandbox が利用可能になり、本格的な開発が可能になります。
  - **Unlimited Edition:** 大規模企業向けの最上位エディション。豊富な機能と手厚いサポートが提供されます。
- **組織の種類:**
  - **本番組織 (Production Org):** 実際にビジネスで使用する組織。顧客データやビジネスロジックが格納されています。
  - **Sandbox:** 本番組織のコピー環境。開発やテスト、トレーニングなどに使用します。Sandbox にはいくつかの種類があります。
    - **Developer Sandbox:** 開発者向けの無料 Sandbox。ストレージ容量が少ないですが、基本的な開発には十分です。
    - **Developer Pro Sandbox:** Developer Sandbox よりもストレージ容量が多い Sandbox。より複雑な開発に適しています。
    - **Partial Data Sandbox:** 本番環境の一部のデータ（例えば、過去数ヶ月分のデータ）をコピーした Sandbox。統合テストやユーザ受け入れテスト（UAT）などに使用します。
    - **Full Sandbox:** 本番環境のすべてのデータと設定をコピーした Sandbox。本番環境に近い環境でテストを行いたい場合に適しています。
  - **Developer Edition:** 開発者向けの無料組織。Sandbox として利用できます。本番組織とは異なり、開発専用の環境です。

#### 2.1.3 事前準備と前提条件

- Salesforce アカウントが必要です。まだお持ちでない場合は、[Salesforce Developer Edition](https://developer.salesforce.com/signup) から無料で登録できます。
- Sandbox の種類と特徴を理解し、開発目的に合った Sandbox を選択してください。

#### 2.1.4 基本的な使い方

1.  **Developer Edition の取得:** 上記リンクから登録し、ログインします。
2.  **Sandbox の作成 (Enterprise Edition 以上):**
    - 本番組織にログインします。
    - [設定] -> [Sandbox] を選択します。
    - [新しい Sandbox] ボタンをクリックします。
    - Sandbox 名、説明、Sandbox の種類を選択し、[作成] をクリックします。
    - Sandbox の作成には時間がかかる場合があります。完了するとメールで通知されます。

#### 2.1.5 実践的なテクニック

- **Sandbox のリフレッシュ:** Sandbox を定期的にリフレッシュすることで、本番環境との乖離を防ぎ、常に最新の状態を保つことができます。特に、Full Sandbox はデータのコピーに時間がかかるため、計画的にリフレッシュする必要があります。
- **Sandbox 戦略の策定:** 開発チーム全体で Sandbox の利用方法を統一し、Sandbox の利用目的、リフレッシュ頻度、データマスキングの方針などを明確にすることで、開発効率を向上させることができます。
- **データマスキング:** Sandbox に機密情報が含まれる場合、データマスキングを行うことで、個人情報保護のコンプライアンスを遵守することができます。

#### 2.1.6 応用例とユースケース

- **新規機能開発:** Developer Sandbox で新機能を開発し、単体テストを行います。
- **統合テスト:** Partial Data Sandbox で複数の機能を連携させた統合テストを行います。
- **ユーザ受け入れテスト（UAT):** Full Sandbox でエンドユーザーにテストしてもらい、フィードバックを得ます。
- **トレーニング:** Developer Sandbox で新しい Salesforce ユーザーにトレーニングを実施します。

#### 2.1.7 トラブルシューティング

- **Sandbox の作成に失敗する場合:** 本番組織のリソースが不足している可能性があります。Sandbox の種類を変更したり、リフレッシュ頻度を減らすことを検討してください。
- **Sandbox のデータが古い場合:** Sandbox がリフレッシュされていない可能性があります。Sandbox をリフレッシュしてください。

#### 2.1.8 まとめと次のステップ

Salesforce 開発における組織の基礎を理解することは、安定した開発環境を構築するための第一歩です。次のステップでは、Salesforce CLI と DX について学び、モダンな開発ワークフローを確立しましょう。

### 2.2 Salesforce CLI と DX：モダンな開発ワークフロー

#### 2.2.1 概要と重要性

Salesforce CLI (Command Line Interface) は、Salesforce 組織とのインタラクションをコマンドラインから行うための強力なツールです。Salesforce DX (Developer Experience) は、Salesforce 開発におけるベストプラクティスをまとめたもので、ソース管理、チーム開発、自動化されたテスト、継続的インテグレーションなどを促進します。Salesforce CLI と DX を組み合わせることで、モダンな開発ワークフローを実現し、開発効率と品質を大幅に向上させることができます。

#### 2.2.2 特徴と利点

- **Salesforce CLI:**
  - **コマンドラインからの操作:** GUI を介さずに、組織へのログイン、メタデータの取得、Apex コードのデプロイなどを実行できます。
  - **スクリプトによる自動化:** 繰り返し行う作業をスクリプト化し、自動化することができます。
  - **バージョン管理システムとの連携:** Git などのバージョン管理システムと連携し、ソースコードの管理を効率化できます。
- **Salesforce DX:**
  - **ソース駆動開発:** 全てのメタデータをソースコードとして管理し、バージョン管理システムで追跡します。
  - **スクラッチ組織:** 短期間の開発やテストのために、使い捨ての Salesforce 組織を簡単に作成できます。
  - **継続的インテグレーション:** コードの変更を自動的にビルド、テスト、デプロイするプロセスを構築できます。

#### 2.2.3 事前準備と前提条件

- **Node.js と npm:** Salesforce CLI は Node.js で動作します。Node.js と npm (Node Package Manager) をインストールしてください。[Node.js 公式サイト](https://nodejs.org/en/) からダウンロードできます。
- **Salesforce CLI のインストール:** コマンドプロンプトまたはターミナルで以下のコマンドを実行します。

  ```bash
  npm install -g sfdx-cli
  ```

- **Git:** ソースコードのバージョン管理に Git を使用します。Git をインストールしてください。[Git 公式サイト](https://git-scm.com/) からダウンロードできます。

#### 2.2.4 基本的な使い方

1.  **Salesforce CLI のバージョン確認:** 以下のコマンドを実行して、Salesforce CLI が正しくインストールされているか確認します。

    ```bash
    sfdx version
    ```

2.  **組織への認証:** 以下のコマンドを実行して、Salesforce 組織に認証します。

    ```bash
    sfdx auth:web:login -d -a MyDevOrg
    ```

    `-d` はデフォルトの組織として設定することを意味し、`-a` は組織のエイリアス（MyDevOrg）を指定します。

3.  **プロジェクトの作成:** 以下のコマンドを実行して、Salesforce DX プロジェクトを作成します。

    ```bash
    sfdx force:project:create -n MyProject
    cd MyProject
    ```

    `-n` はプロジェクト名を指定します。

4.  **メタデータの取得:** 以下のコマンドを実行して、組織からメタデータを取得します。

    ```bash
    sfdx force:source:retrieve -m ApexClass,VisualforcePage -u MyDevOrg
    ```

    `-m` は取得するメタデータの種類を指定し、`-u` は組織のエイリアスを指定します。

5.  **メタデータのデプロイ:** 以下のコマンドを実行して、メタデータを組織にデプロイします。

    ```bash
    sfdx force:source:push -u MyDevOrg
    ```

#### 2.2.5 実践的なテクニック

- **エイリアスの活用:** 複数の組織を扱う場合、エイリアスを設定することで、コマンド実行時に組織を簡単に指定できます。
- **環境変数の設定:** API キーやパスワードなどの機密情報を環境変数として設定することで、ソースコードに直接記述することを避けることができます。
- **Git ブランチ戦略:** Git のブランチ戦略を策定し、機能開発、バグ修正、リリースなどの目的別にブランチを使い分けることで、コードの管理を効率化できます。
- **継続的インテグレーション (CI):** Jenkins、GitHub Actions、GitLab CI などの CI ツールを利用して、コードの変更を自動的にビルド、テスト、デプロイするプロセスを構築できます。

#### 2.2.6 応用例とユースケース

- **スクラッチ組織の自動作成:** 開発に必要な設定が施されたスクラッチ組織を、スクリプトで自動的に作成することができます。
- **データローダーの自動化:** Salesforce CLI を使ってデータローダーを操作し、データのインポート、エクスポート、更新を自動化することができます。
- **テストの自動実行:** Apex テストを Salesforce CLI から実行し、テスト結果を自動的にレポートすることができます。
- **リリース管理:** Salesforce CLI を使ってリリースパッケージを作成し、本番環境へのデプロイを自動化することができます。

#### 2.2.7 トラブルシューティング

- **コマンドが実行できない場合:** Salesforce CLI が正しくインストールされているか、パスが設定されているか確認してください。
- **認証に失敗する場合:** 組織のログイン情報が正しいか確認してください。
- **メタデータの取得/デプロイに失敗する場合:** メタデータの種類や名前が正しいか確認してください。

#### 2.2.8 まとめと次のステップ

Salesforce CLI と DX を習得することで、開発ワークフローを大幅に改善することができます。次のステップでは、VS Code の最強設定について学び、生産性をさらに向上させましょう。

### 2.3 VS Code 最強設定：生産性を爆上げする拡張機能

#### 2.3.1 概要と重要性

Visual Studio Code (VS Code) は、軽量でありながら強力なテキストエディタであり、Salesforce 開発者にとって非常に重要なツールです。VS Code に適切な拡張機能をインストールし、設定を最適化することで、コードの記述、デバッグ、テストなどを効率的に行うことができます。本セクションでは、Salesforce 開発における VS Code の最強設定について解説します。

#### 2.3.2 特徴と利点

- **軽量で高速:** 起動が速く、動作が軽快です。
- **豊富な拡張機能:** 様々な拡張機能が提供されており、Salesforce 開発に必要な機能を簡単に追加できます。
- **強力なデバッグ機能:** Apex コードのデバッグを GUI で行うことができます。
- **Git との連携:** Git の操作を VS Code から簡単に行うことができます。
- **カスタマイズ性:** テーマ、フォント、キーバインドなど、様々な設定をカスタマイズできます。

#### 2.3.3 事前準備と前提条件

- **VS Code のインストール:** [VS Code 公式サイト](https://code.visualstudio.com/) から VS Code をダウンロードし、インストールしてください。
- **Salesforce DX プロジェクト:** Salesforce DX プロジェクトを作成済みであることを前提とします。

#### 2.3.4 基本的な使い方

1.  **Salesforce Extension Pack のインストール:** VS Code の拡張機能マーケットプレイスで「Salesforce Extension Pack」を検索し、インストールします。この拡張機能パックには、以下の拡張機能が含まれています。

    - **Salesforce CLI Integration:** Salesforce CLI との統合を可能にします。
    - **Apex:** Apex コードのシンタックスハイライト、コード補完、デバッグ機能を提供します。
    - **Visualforce:** Visualforce ページのシンタックスハイライト、コード補完機能を提供します。
    - **Lightning Web Components:** Lightning Web Components (LWC) のシンタックスハイライト、コード補完機能を提供します。
    - **SOQL:** SOQL クエリのシンタックスハイライト、コード補完機能を提供します。

2.  **プロジェクトのオープン:** VS Code で Salesforce DX プロジェクトのフォルダを開きます。

3.  **組織への認証:** VS Code のターミナルで以下のコマンドを実行して、Salesforce 組織に認証します。

    ```bash
    sfdx auth:web:login -d -a MyDevOrg
    ```

4.  **メタデータの取得:** VS Code のコマンドパレット（`Ctrl+Shift+P` または `Cmd+Shift+P`）を開き、「SFDX: Retrieve Source in Manifest from Org」を選択し、`package.xml` ファイルに基づいてメタデータを取得します。`package.xml` ファイルは、取得したいメタデータの種類と名前を記述した XML ファイルです。

5.  **メタデータのデプロイ:** VS Code のコマンドパレットを開き、「SFDX: Deploy Source to Org」を選択し、メタデータを組織にデプロイします。

#### 2.3.5 実践的なテクニック

- **設定のカスタマイズ:** VS Code の設定 (`settings.json`) をカスタマイズすることで、開発環境をさらに快適にすることができます。例えば、以下の設定は、コードの自動保存、タブのサイズ、フォントの設定などを変更するものです。

  ```json
  {
    "files.autoSave": "afterDelay",
    "editor.tabSize": 2,
    "editor.fontFamily": "Fira Code",
    "editor.fontLigatures": true,
    "workbench.colorTheme": "Dracula"
  }
  ```

  `Fira Code` はプログラミングフォントで、複数の文字を組み合わせて記号のように表示する機能（リガチャ）をサポートしています。

- **スニペットの活用:** スニペットを作成することで、よく使うコードを簡単に挿入できます。VS Code のコマンドパレットを開き、「Preferences: Configure User Snippets」を選択し、言語（例えば、Apex）を選択してスニペットを定義します。

  ```json
  {
    "Apex Class Template": {
      "prefix": "apexclass",
      "body": ["public class ${1:ClassName} {", "  ${2}", "}"],
      "description": "Apex Class Template"
    }
  }
  ```

  このスニペットは、`apexclass` と入力すると、Apex クラスのテンプレートを挿入します。

- **デバッグ:** Apex コードのデバッグを行うには、以下の手順に従います。
  1.  VS Code のデバッグビューを開き、[構成の追加...] をクリックします。
  2.  「Apex」を選択します。
  3.  `launch.json` ファイルが作成されます。このファイルには、デバッグの設定が記述されています。
  4.  ブレークポイントを設定し、デバッグを開始します。

#### 2.3.6 応用例とユースケース

- **LWC 開発:** Lightning Web Components (LWC) の開発において、Salesforce Extension Pack は非常に役立ちます。LWC の作成、デプロイ、テストなどを簡単に行うことができます。
- **Apex 開発:** Apex コードの作成、デバッグ、テストなどを効率的に行うことができます。特に、デバッグ機能は、複雑なロジックを理解するのに役立ちます。
- **SOQL クエリの実行:** SOQL クエリを実行し、結果を VS Code で確認することができます。

#### 2.3.7 トラブルシューティング

- **拡張機能が動作しない場合:** VS Code を再起動するか、拡張機能を再インストールしてみてください。
- **デバッグができない場合:** `launch.json` ファイルの設定が正しいか確認してください。
- **Salesforce CLI のコマンドが実行できない場合:** Salesforce CLI が正しくインストールされているか、パスが設定されているか確認してください。

#### 2.3.8 まとめと次のステップ

VS Code と適切な拡張機能を活用することで、Salesforce 開発の生産性を大幅に向上させることができます。本章で学んだ知識を活かし、より効率的で高品質な Salesforce 開発を目指しましょう。

本章では、Salesforce 開発における環境構築について、組織の基礎から Salesforce CLI、VS Code の最強設定まで、幅広く解説しました。これらのツールやテクニックを習得することで、開発効率を向上させ、より高品質なアプリケーションを開発することができます。
