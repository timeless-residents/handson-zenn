## 第 8 章：Lightning Web Components：モダンな UI 開発

Salesforce 開発の世界へようこそ。この章では、Lightning Web Components (LWC) という、Salesforce プラットフォームにおけるモダンな UI 開発の要となる技術を深く掘り下げていきます。LWC は、標準の Web 標準に基づいて構築されており、パフォーマンス、セキュリティ、そして開発効率において優れた特徴を備えています。この章を通して、LWC の基本から応用までを習得し、Salesforce の UI 開発における強力な武器を手に入れましょう。

### 8.1 LWC の基本：HTML、JavaScript、CSS

#### 8.1.1 概要と重要性

LWC は、ウェブ標準に基づいた軽量なフレームワークであり、カスタム要素 (Custom Elements) を使用して、再利用可能な UI コンポーネントを構築できます。従来の Aura Components と比較して、パフォーマンスが大幅に向上し、開発者がより効率的に UI を構築できるため、Salesforce 開発における標準的な UI 開発手法となりつつあります。

#### 8.1.2 特徴と利点

- **パフォーマンス:** ウェブ標準をネイティブに利用することで、ブラウザのパフォーマンスを最大限に引き出すことができます。
- **標準準拠:** HTML、JavaScript、CSS といったウェブ標準に基づいているため、既存のウェブ開発スキルを活用しやすいです。
- **セキュリティ:** Salesforce の Lightning Security Best Practices に準拠しており、安全な UI を構築できます。
- **再利用性:** コンポーネントを再利用することで、開発時間を短縮し、コードの保守性を向上させることができます。
- **相互運用性:** Aura Components との相互運用が可能であり、段階的な移行が可能です。

#### 8.1.3 事前準備と前提条件

- **Salesforce 組織:** LWC を開発およびデプロイできる Salesforce 組織（Developer Edition 推奨）が必要です。
- **Salesforce CLI:** Salesforce CLI（Command Line Interface）をインストールし、組織への接続設定を完了させてください。
- **Visual Studio Code (VS Code):** 推奨のエディタです。Salesforce Extension Pack for VS Code をインストールすると、LWC 開発が効率化されます。
- **基本的なウェブ開発知識:** HTML、JavaScript、CSS の基本的な知識が必要です。

#### 8.1.4 基本的な使い方

LWC コンポーネントは、以下の 3 つのファイルで構成されます。

- **HTML ファイル:** コンポーネントの構造を定義します。
- **JavaScript ファイル:** コンポーネントのロジックを記述します。
- **CSS ファイル:** コンポーネントのスタイルを定義します。

**簡単な LWC コンポーネントの例:**

**myComponent.html**

```html
<template>
  <h1>Hello, {greeting}!</h1>
  <lightning-input
    label="Name"
    value="{greeting}"
    onchange="{handleInputChange}"
  ></lightning-input>
</template>
```

**myComponent.js**

```javascript
import { LightningElement, track } from "lwc";

export default class MyComponent extends LightningElement {
  @track greeting = "World";

  handleInputChange(event) {
    this.greeting = event.target.value;
  }
}
```

**myComponent.css**

```css
h1 {
  color: blue;
}
```

**解説:**

- `@track`: `greeting`プロパティをリアクティブにするデコレーターです。この値が変更されると、UI が自動的に更新されます。
- `lightning-input`: Salesforce 提供の基本コンポーネントで、入力フィールドを簡単に作成できます。
- `onchange`: 入力フィールドの値が変更されたときに`handleInputChange`メソッドを呼び出すイベントハンドラーです。

**デプロイと表示:**

1.  VS Code で新しい LWC プロジェクトを作成します (SFDX: Create Project with Manifest)。
2.  上記のファイルを`force-app/main/default/lwc/myComponent`ディレクトリに作成します。
3.  `sfdx force:source:push`コマンドを使用して、コンポーネントを Salesforce 組織にデプロイします。
4.  Lightning App Builder で、コンポーネントをページに追加します。

#### 8.1.5 実践的なテクニック

- **Data Binding:** JavaScript プロパティと HTML テンプレートの間でデータを双方向にバインドします。
- **イベントハンドリング:** ユーザー操作や他のコンポーネントからのイベントに応答します。
- **Conditional Rendering:** 特定の条件に基づいて、UI の一部を表示または非表示にします。
- **Iteration:** 配列のデータを繰り返し表示します。

**例：条件付きレンダリングと繰り返し**

**myListComponent.html**

```html
<template>
  <template if:true="{hasItems}">
    <ul>
      <template for:each="{items}" for:item="item">
        <li key="{item.id}">{item.name}</li>
      </template>
    </ul>
  </template>
  <template if:false="{hasItems}">
    <p>No items found.</p>
  </template>
</template>
```

**myListComponent.js**

```javascript
import { LightningElement, track } from "lwc";

export default class MyListComponent extends LightningElement {
  @track items = [
    { id: 1, name: "Item 1" },
    { id: 2, name: "Item 2" },
    { id: 3, name: "Item 3" },
  ];

  get hasItems() {
    return this.items.length > 0;
  }
}
```

#### 8.1.6 応用例とユースケース

- **カスタムレコード編集フォーム:** Salesforce の標準フォームを拡張し、カスタムの入力バリデーションやロジックを追加します。
- **データ可視化コンポーネント:** グラフやチャートを使用して、データを視覚的に表現します。
- **カスタム検索コンポーネント:** 高度な検索機能を提供し、ユーザーが目的のデータをすばやく見つけられるようにします。
- **ステップ付きプロセスの UI:** 複雑なプロセスを複数のステップに分割し、ユーザーを段階的にガイドします。

#### 8.1.7 トラブルシューティング

- **コンポーネントが表示されない:** JavaScript ファイルのエラーや、メタデータファイルの設定ミスが原因である可能性があります。ブラウザの開発者ツールでエラーを確認し、Salesforce CLI を使用してメタデータを再デプロイしてください。
- **データバインディングが機能しない:** `@track`デコレーターが正しく使用されているか、プロパティ名が HTML テンプレートと JavaScript ファイルで一致しているかを確認してください。
- **イベントハンドラーが呼び出されない:** イベント名が正しく指定されているか、ハンドラーメソッドが JavaScript ファイルに定義されているかを確認してください。

#### 8.1.8 まとめと次のステップ

LWC の基本を理解することで、Salesforce の UI 開発の可能性が大きく広がります。次のステップとして、Salesforce Lightning Design System (SLDS) を活用して、より洗練された UI を構築することをお勧めします。また、公式ドキュメントや Trailhead モジュールを活用して、LWC のより高度な機能を習得しましょう。

### 8.2 APEX コントローラーとの連携：データ取得と操作

#### 8.2.1 概要と重要性

LWC はクライアントサイドの UI フレームワークであるため、データの取得や操作にはサーバーサイドの APEX コントローラーとの連携が不可欠です。APEX コントローラーを使用することで、Salesforce のデータベースにアクセスし、複雑なビジネスロジックを実行することができます。

#### 8.2.2 特徴と利点

- **セキュリティ:** APEX コントローラーは、Salesforce のセキュリティモデルに基づいて実行されるため、安全なデータアクセスを提供します。
- **トランザクション制御:** APEX コントローラー内でトランザクションを開始およびコミットすることで、データの整合性を維持することができます。
- **パフォーマンス:** SOQL クエリの最適化や、バルク処理など、APEX のパフォーマンスチューニング技術を活用できます。
- **ビジネスロジック:** APEX で複雑なビジネスロジックを実装し、LWC から呼び出すことで、UI の肥大化を防ぎ、保守性を向上させることができます。

#### 8.2.3 事前準備と前提条件

- **APEX の基本的な知識:** APEX クラスの作成、SOQL クエリの実行、DML 操作の実行など、APEX の基本的な知識が必要です。
- **組織の API バージョン:** 使用する APEX クラスの API バージョンが、LWC コンポーネントでサポートされていることを確認してください。

#### 8.2.4 基本的な使い方

1.  **APEX クラスの作成:** `@AuraEnabled`アノテーションを付与したメソッドを作成し、LWC から呼び出し可能にします。`cacheable=true`オプションを指定することで、クライアントサイドのキャッシュを利用できます。
2.  **JavaScript でのインポート:** `import`ステートメントを使用して、APEX メソッドを LWC コンポーネントにインポートします。
3.  **APEX メソッドの呼び出し:** `@wire`アダプターまたは`imperative apex`メソッドを使用して、APEX メソッドを呼び出します。
4.  **データの処理:** APEX メソッドから返されたデータを、JavaScript で処理し、UI に表示します。

**例：APEX コントローラーからデータを取得する**

**MyController.cls (APEX)**

```java
public class MyController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccounts() {
        return [SELECT Id, Name FROM Account LIMIT 10];
    }
}
```

**myAccountList.js (LWC)**

```javascript
import { LightningElement, wire } from "lwc";
import getAccounts from "@salesforce/apex/MyController.getAccounts";

export default class MyAccountList extends LightningElement {
  @wire(getAccounts) accounts;

  get hasAccounts() {
    return this.accounts.data && this.accounts.data.length > 0;
  }

  get error() {
    return this.accounts.error;
  }
}
```

**myAccountList.html (LWC)**

```html
<template>
  <template if:true="{hasAccounts}">
    <ul>
      <template for:each="{accounts.data}" for:item="account">
        <li key="{account.Id}">{account.Name}</li>
      </template>
    </ul>
  </template>
  <template if:true="{error}">
    <p>Error: {error}</p>
  </template>
  <template if:false="{hasAccounts}">
    <p>No accounts found.</p>
  </template>
</template>
```

**解説:**

- `@AuraEnabled(cacheable=true)`: `getAccounts`メソッドを LWC から呼び出し可能にし、クライアントサイドのキャッシュを有効にします。
- `@wire(getAccounts) accounts`: `getAccounts`メソッドの結果を`accounts`プロパティにバインドします。
- `accounts.data`: APEX メソッドから返されたデータが含まれます。
- `accounts.error`: APEX メソッドの実行中にエラーが発生した場合、エラー情報が含まれます。

**Imperative Apex:**

`@wire`アダプターの代わりに、JavaScript から直接 APEX メソッドを呼び出すこともできます。

```javascript
import { LightningElement } from "lwc";
import getAccounts from "@salesforce/apex/MyController.getAccounts";

export default class MyAccountList extends LightningElement {
  accounts;
  error;

  connectedCallback() {
    getAccounts()
      .then((result) => {
        this.accounts = result;
      })
      .catch((error) => {
        this.error = error;
      });
  }

  get hasAccounts() {
    return this.accounts && this.accounts.length > 0;
  }
}
```

#### 8.2.5 実践的なテクニック

- **パラメータの受け渡し:** LWC から APEX メソッドにパラメータを渡すことができます。
- **エラーハンドリング:** APEX メソッドの実行中に発生したエラーを適切に処理し、ユーザーに分かりやすいメッセージを表示します。
- **バルク処理:** 複数のレコードを一度に処理することで、パフォーマンスを向上させることができます。
- **非同期処理:** 時間がかかる処理を非同期的に実行することで、UI の応答性を維持することができます。

**例：パラメータの受け渡しとエラーハンドリング**

**MyController.cls (APEX)**

```java
public class MyController {
    @AuraEnabled
    public static Account getAccount(Id accountId) {
        try {
            return [SELECT Id, Name FROM Account WHERE Id = :accountId];
        } catch (Exception e) {
            throw new AuraHandledException('Account not found: ' + e.getMessage());
        }
    }
}
```

**myAccountDetail.js (LWC)**

```javascript
import { LightningElement, api, wire } from "lwc";
import getAccount from "@salesforce/apex/MyController.getAccount";
import { getRecord } from "lightning/uiRecordApi";

export default class MyAccountDetail extends LightningElement {
  @api recordId; // Lightning App Builderから渡されるAccountId

  @wire(getAccount, { accountId: "$recordId" })
  account;

  get accountName() {
    return this.account.data ? this.account.data.Name : "Loading...";
  }

  get error() {
    return this.account.error ? this.account.error.body.message : "";
  }
}
```

#### 8.2.6 応用例とユースケース

- **カスタムレコード作成/編集フォーム:** APEX コントローラーを使用して、複雑な入力バリデーションやビジネスロジックを実行します。
- **データインポート/エクスポート:** APEX コントローラーを使用して、CSV ファイルなどのデータを Salesforce にインポートしたり、Salesforce のデータを外部システムにエクスポートしたりします。
- **バッチ処理:** APEX バッチジョブを LWC から起動し、大量のデータを非同期的に処理します。
- **Web サービス連携:** APEX コントローラーを使用して、外部 Web サービスと連携し、データを取得または更新します。

#### 8.2.7 トラブルシューティング

- **APEX メソッドが呼び出せない:** APEX クラスとメソッドが`@AuraEnabled`アノテーションで正しく設定されているか、LWC の JavaScript ファイルで正しくインポートされているかを確認してください。
- **APEX メソッドからエラーが返される:** APEX クラスのログを確認し、エラーの原因を特定してください。必要に応じて、`try-catch`ブロックを使用して、エラーを適切に処理してください。
- **データが更新されない:** DML 操作が正しく実行されているか、必要なフィールドの権限があるかを確認してください。

#### 8.2.8 まとめと次のステップ

APEX コントローラーとの連携は、LWC の可能性を最大限に引き出すために不可欠です。次のステップとして、Salesforce の標準データサービス (Lightning Data Service) を活用して、より効率的なデータアクセスを実現することをお勧めします。また、非同期処理やバルク処理など、APEX のパフォーマンスチューニング技術を習得し、LWC のパフォーマンスを向上させましょう。

### 8.3 コンポーネント間通信：イベントと属性

#### 8.3.1 概要と重要性

LWC で複雑な UI を構築する場合、複数のコンポーネントを連携させる必要があります。コンポーネント間通信は、親コンポーネントと子コンポーネント間、または兄弟コンポーネント間でデータを共有したり、イベントをトリガーしたりするために使用されます。

#### 8.3.2 特徴と利点

- **疎結合:** コンポーネント間の依存関係を最小限に抑え、保守性を向上させることができます。
- **再利用性:** コンポーネントを独立して開発およびテストできるため、再利用性が向上します。
- **拡張性:** 新しいコンポーネントを簡単に追加または変更できるため、システムの拡張性が向上します。
- **明確なインターフェース:** コンポーネント間の通信方法が明確に定義されているため、コードの可読性が向上します。

#### 8.3.3 事前準備と前提条件

- **LWC の基本的な知識:** LWC コンポーネントの作成、HTML テンプレートの記述、JavaScript ファイルの記述など、LWC の基本的な知識が必要です。
- **イベントの概念:** イベントの発行、リスニング、ハンドリングなど、イベントの基本的な概念を理解している必要があります。

#### 8.3.4 基本的な使い方

LWC コンポーネント間通信には、主に以下の 2 つの方法があります。

- **属性 (Properties):** 親コンポーネントから子コンポーネントへデータを渡すために使用されます。
- **イベント (Events):** 子コンポーネントから親コンポーネントへ、または兄弟コンポーネント間で通知を送るために使用されます。

**属性によるデータ渡し (親から子へ):**

**parentComponent.html**

```html
<template>
  <c-child-component message="{parentMessage}"></c-child-component>
</template>
```

**parentComponent.js**

```javascript
import { LightningElement } from "lwc";

export default class ParentComponent extends LightningElement {
  parentMessage = "Hello from parent!";
}
```

**childComponent.html**

```html
<template>
  <p>{message}</p>
</template>
```

**childComponent.js**

```javascript
import { LightningElement, api } from "lwc";

export default class ChildComponent extends LightningElement {
  @api message;
}
```

**解説:**

- `@api`: `message`プロパティをパブリックにし、親コンポーネントから値を設定できるようにします。
- `{parentMessage}`: 親コンポーネントの`parentMessage`プロパティの値を、子コンポーネントの`message`プロパティにバインドします。

**イベントによる通知 (子から親へ):**

**childComponent.html**

```html
<template>
  <lightning-button
    label="Send Message"
    onclick="{handleClick}"
  ></lightning-button>
</template>
```

**childComponent.js**

```javascript
import { LightningElement, api } from "lwc";

export default class ChildComponent extends LightningElement {
  handleClick() {
    const event = new CustomEvent("message", {
      detail: "Hello from child!",
    });
    this.dispatchEvent(event);
  }
}
```

**parentComponent.html**

```html
<template>
  <c-child-component onmessage="{handleMessage}"></c-child-component>
  <p>Message from child: {messageFromChild}</p>
</template>
```

**parentComponent.js**

```javascript
import { LightningElement } from "lwc";

export default class ParentComponent extends LightningElement {
  messageFromChild = "";

  handleMessage(event) {
    this.messageFromChild = event.detail;
  }
}
```

**解説:**

- `CustomEvent`: カスタムイベントを作成します。`detail`プロパティに、親コンポーネントに渡したいデータを設定します。
- `this.dispatchEvent(event)`: イベントを発行します。
- `onmessage`: 子コンポーネントから発行された`message`イベントをリスニングし、`handleMessage`メソッドを呼び出します。
- `event.detail`: イベントに含まれるデータにアクセスします。

#### 8.3.5 実践的なテクニック

- **イベントバブルリング:** イベントは、DOM ツリーを上方向に伝播します。
- **イベント合成:** 複数のイベントを組み合わせて、より複雑なイベントを作成することができます。
- **pubsub モジュール:** コンポーネント間で直接イベントをやり取りするための PubSub モジュールを使用できます（ただし、Salesforce 公式の提供ではありません）。より複雑なコンポーネント間通信に対応できます。
- **Lightning Message Service (LMS):** Visualforce, Aura Component, LWC の間で、より強力なコンポーネント間通信を提供します。

**Pubsub を使ったコンポーネント間通信 (兄弟コンポーネント間):**
※Pubsub は Salesforce 公式のものではありません。サードパーティのライブラリとして提供されています。
利用時はセキュリティリスクを十分に考慮してください。

**pubsub.js (LWC)**

```javascript
const listeners = {};

function subscribe(eventName, callback, thisArg) {
  if (!listeners[eventName]) {
    listeners[eventName] = [];
  }
  listeners[eventName].push({ callback, thisArg });
}

function unsubscribe(eventName, callback, thisArg) {
  if (listeners[eventName]) {
    listeners[eventName] = listeners[eventName].filter(
      (listener) =>
        listener.callback !== callback || listener.thisArg !== thisArg
    );
  }
}

function publish(eventName, payload) {
  if (listeners[eventName]) {
    listeners[eventName].forEach((listener) => {
      listener.callback.call(listener.thisArg, payload);
    });
  }
}

export { subscribe, unsubscribe, publish };
```

**componentA.js (LWC)**

```javascript
import { LightningElement } from "lwc";
import { publish } from "c/pubsub";

export default class ComponentA extends LightningElement {
  handleClick() {
    publish("myEvent", { message: "Hello from Component A" });
  }
}
```

**componentB.js (LWC)**

```javascript
import { LightningElement, connectedCallback } from "lwc";
import { subscribe, unsubscribe } from "c/pubsub";

export default class ComponentB extends LightningElement {
  message = "";

  connectedCallback() {
    subscribe("myEvent", this.handleMyEvent, this);
  }

  disconnectedCallback() {
    unsubscribe("myEvent", this.handleMyEvent, this);
  }

  handleMyEvent(payload) {
    this.message = payload.message;
  }
}
```

#### 8.3.6 応用例とユースケース

- **マスター/ディテール:** マスターコンポーネントで選択されたレコードの詳細を、ディテールコンポーネントに表示します。
- **検索:** 検索コンポーネントで入力された検索条件に基づいて、結果リストコンポーネントを更新します。
- **ウィザード:** 複数のステップからなるウィザードを、各ステップを個別のコンポーネントとして実装し、コンポーネント間通信を使用してステップ間のナビゲーションを制御します。
- **グローバルイベント:** アプリケーション全体で共有されるイベントを使用して、コンポーネント間で通知を送ります。

#### 8.3.7 トラブルシューティング

- **イベントが伝播しない:** イベントが正しい要素からディスパッチされているか、イベントハンドラーが正しい要素に登録されているかを確認してください。
- **データが正しく渡されない:** 属性名が親コンポーネントと子コンポーネントで一致しているか、データ型が正しく変換されているかを確認してください。
- **pubsub が機能しない:** pubsub モジュールが正しくインポートされているか、イベント名が一致しているかを確認してください。

#### 8.3.8 まとめと次のステップ

コンポーネント間通信をマスターすることで、より複雑で柔軟な LWC アプリケーションを構築することができます。次のステップとして、Lightning Message Service (LMS) を活用して、Visualforce ページや Aura コンポーネントとの連携を強化することをお勧めします。また、より高度なイベント処理やデータバインディングのテクニックを習得し、LWC のアーキテクチャを深く理解しましょう。

この章を通して、LWC の基本から応用までを学びました。LWC は、Salesforce の UI 開発における強力なツールであり、ウェブ標準に基づいたモダンな開発を可能にします。今後も LWC を活用して、より優れた Salesforce アプリケーションを開発してください。
