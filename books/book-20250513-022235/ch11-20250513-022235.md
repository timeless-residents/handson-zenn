## 第 11 章：イベント駆動アーキテクチャ：リアルタイム連携を実現

イベント駆動アーキテクチャ（EDA）は、コンポーネントがイベントの発生と応答によって疎結合で連携するアーキテクチャパターンです。リアルタイム性の高いシステム構築に不可欠であり、変化に強く、スケーラブルなシステムを実現できます。本章では、Salesforce プラットフォーム上で EDA を実現するための主要な機能、Platform Events、Change Data Capture (CDC)、イベントバスとメッセージングについて、実践的な視点から解説します。

### 11.1 Platform Events の活用：Publish-Subscribe パターン

#### 11.1.1 概要と重要性

Platform Events は、Salesforce 内で発生したイベントを、アプリケーション内外の購読者（Subscriber）に対してほぼリアルタイムで配信する機能です。Publish-Subscribe (Pub/Sub) パターンを Salesforce 上で実現し、異なる Salesforce 組織や外部システムとの連携を容易にします。これにより、注文受付、在庫更新、顧客情報変更といったビジネスイベントをトリガーにして、様々な処理を非同期的に実行できるようになります。例えば、新しいリードが作成された際に、マーケティングオートメーションツールに自動的に連携し、ウェルカムメールを送信する、といった連携が可能です。

#### 11.1.2 特徴と利点

- **疎結合**: イベントの発行者（Publisher）は、イベントの購読者を意識する必要がありません。
- **リアルタイム性**: イベントはほぼリアルタイムで配信されます。
- **拡張性**: 購読者の追加・削除が容易で、システム全体の拡張が容易です。
- **信頼性**: Salesforce プラットフォームの信頼性を活用し、イベントの配信が保証されます（配信保証レベルによる）。
- **ガバナ制限**: Platform Events の使用には、Salesforce のガバナ制限が適用されます。特に、公開イベントの数やイベントサイズに注意が必要です。

#### 11.1.3 事前準備と前提条件

- Developer Edition または Enterprise Edition 以上の Salesforce 組織
- イベントを作成するための「API Enabled」権限
- Apex 開発の基本的な知識 (イベントトリガー、Apex クラス)
- (任意) CometD クライアントや Streaming API の知識 (外部システム連携の場合)

#### 11.1.4 基本的な使い方

**1. Platform Event オブジェクトの定義:**

まず、Salesforce のセットアップから「プラットフォームイベント」を検索し、新しい Platform Event オブジェクトを作成します。イベント名、API 参照名、およびイベントに含めるカスタムフィールドを定義します。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PlatformEvent xmlns="http://soap.sforce.com/2006/04/metadata">
    <eventType>HighVolume</eventType>
    <label>Order Created</label>
    <pluralLabel>Order Createds</pluralLabel>
    <publishBehavior>PublishAfterCommit</publishBehavior>
    <fields>
        <fullName>OrderId__c</fullName>
        <label>Order Id</label>
        <required>true</required>
        <type>Text</type>
        <unique>false</unique>
    </fields>
    <fields>
        <fullName>CustomerId__c</fullName>
        <label>Customer Id</label>
        <required>false</required>
        <type>Text</type>
        <unique>false</unique>
    </fields>
</PlatformEvent>
```

**2. イベントの発行 (Apex):**

Apex トリガー、Apex クラス、またはフローから、Platform Event を発行します。

```java
Order_Created__e event = new Order_Created__e(OrderId__c = '12345', CustomerId__c = 'ABCDE');
List<Database.SaveResult> results = EventBus.publish(event);

for (Database.SaveResult result : results) {
    if (result.isSuccess()) {
        System.debug('Successfully published event with ID: ' + result.getId());
    } else {
        for (Database.Error error : result.getErrors()) {
            System.debug('Error returned: ' + error.getStatusCode() + ' - ' + error.getMessage());
        }
    }
}
```

**3. イベントの購読 (Apex トリガー):**

Platform Event を購読するには、Apex トリガーを作成します。トリガーは、特定の Platform Event が発生したときに自動的に実行されます。

```java
trigger OrderCreatedTrigger on Order_Created__e (after insert) {
    for (Order_Created__e event : Trigger.new) {
        System.debug('Order Created Event Received: OrderId = ' + event.OrderId__c + ', CustomerId = ' + event.CustomerId__c);
        // ここで必要なビジネスロジックを実行
        // 例: 顧客情報の更新、在庫更新など
    }
}
```

**4. イベントの購読 (フロー):**

フローでも Platform Event を購読できます。レコードトリガーフローを使用し、Platform Event オブジェクトを指定して、イベント発生時にフローを実行します。ノーコードでイベント駆動処理を実現できます。

**5. イベントの購読 (外部システム):**

CometD クライアントや Streaming API を使用して、外部システムから Platform Event を購読できます。これにより、Salesforce で発生したイベントを、Java、Python、Node.js などの様々な言語で記述されたアプリケーションで処理できます。

#### 11.1.5 実践的なテクニック

- **バッチ処理**: 大量の Platform Events を効率的に処理するために、Apex トリガー内でバッチ処理を実装します。`Database.executeBatch`メソッドを使用します。
- **エラー処理**: イベント処理中に発生したエラーを適切に処理するために、try-catch ブロックを使用し、エラーログを記録します。
- **非同期処理**: 時間のかかる処理は、`@future`アノテーションを使用して非同期的に実行します。これにより、Platform Event の配信遅延を防ぎ、システム全体のパフォーマンスを向上させます。
- **トランザクション制御**: `PublishAfterCommit`オプションを使用することで、イベントはトランザクションが正常にコミットされた後にのみ公開されます。

#### 11.1.6 応用例とユースケース

- **顧客サポート**: 顧客からの問い合わせがあった際に、Platform Event を発行し、関連するチームに通知する。
- **在庫管理**: 製品の在庫数が少なくなった際に、Platform Event を発行し、在庫補充担当者に通知する。
- **不正検知**: 不正な取引が検出された際に、Platform Event を発行し、セキュリティ担当者に通知する。
- **IoT 連携**: IoT デバイスから送られてくるデータを Platform Events として Salesforce に送信し、リアルタイムな分析やアクションを実行する。

#### 11.1.7 トラブルシューティング

- **イベントが配信されない**: Platform Event オブジェクトの「Publish Behavior」の設定を確認してください。API バージョンが正しいか確認してください。トリガーが有効になっているか確認してください。ガバナ制限に達していないか確認してください。
- **トリガーが正しく動作しない**: トリガーコードにエラーがないか確認してください。SOQL クエリのガバナ制限を超えていないか確認してください。
- **外部システムとの連携がうまくいかない**: CometD クライアントの設定を確認してください。Streaming API の接続が確立されているか確認してください。

#### 11.1.8 まとめと次のステップ

Platform Events は、Salesforce 内外のシステムをリアルタイムに連携させるための強力なツールです。本セクションで学んだ知識を基に、実際に Platform Event オブジェクトを作成し、イベントの発行と購読を試してみてください。次のステップとして、外部システムとの連携や、より複雑なイベント駆動処理の実装に挑戦してみてください。

### 11.2 Change Data Capture (CDC)：データ変更のリアルタイム通知

#### 11.2.1 概要と重要性

Change Data Capture (CDC) は、Salesforce のデータ（レコード）の変更をほぼリアルタイムで外部システムに通知する機能です。従来のポーリング処理と比較して、より効率的でリアルタイム性の高いデータ連携を実現します。例えば、顧客情報が更新された際に、顧客データウェアハウスに自動的に反映したり、マーケティングオートメーションツールに連携して、顧客セグメントを更新したりすることが可能です。

#### 11.2.2 特徴と利点

- **リアルタイム性**: データ変更はほぼリアルタイムで通知されます。
- **効率性**: ポーリング処理が不要になり、システムリソースを節約できます。
- **信頼性**: Salesforce プラットフォームの信頼性を活用し、データ変更の通知が保証されます。
- **柔軟性**: 外部システムは、データ変更の通知を購読することで、必要な情報を取得できます。
- **設定の簡便さ**: ポイント＆クリックの設定で、簡単に CDC を有効にできます。

#### 11.2.3 事前準備と前提条件

- Developer Edition または Enterprise Edition 以上の Salesforce 組織
- CDC を有効にするオブジェクトに対する「参照」および「すべて変更」権限
- (任意) CometD クライアントや Streaming API の知識 (外部システム連携の場合)

#### 11.2.4 基本的な使い方

**1. CDC の有効化:**

Salesforce のセットアップから「変更データキャプチャ」を検索し、CDC を有効にするオブジェクトを選択します。

**2. データ変更イベントの購読 (Apex トリガー):**

`ChangeEventHeader`オブジェクトを介して、データ変更イベントの情報を取得できます。

```java
trigger AccountChangeTrigger on AccountChangeEvent (after insert) {
    for (AccountChangeEvent event : Trigger.new) {
        ChangeEventHeader header = event.ChangeEventHeader;
        String changeType = header.changeType;
        Id recordId = header.recordIds[0];

        System.debug('Account Change Event Received: ChangeType = ' + changeType + ', RecordId = ' + recordId);

        // ここで必要なビジネスロジックを実行
        // 例: 顧客データウェアハウスへのデータ同期
    }
}
```

**3. データ変更イベントの購読 (外部システム):**

CometD クライアントや Streaming API を使用して、外部システムからデータ変更イベントを購読できます。


#### 11.2.5 実践的なテクニック

- **フィルタリング**: 購読するデータ変更イベントを絞り込むために、SOQL クエリを使用します。
- **バッチ処理**: 大量のデータ変更イベントを効率的に処理するために、Apex トリガー内でバッチ処理を実装します。
- **エラー処理**: イベント処理中に発生したエラーを適切に処理するために、try-catch ブロックを使用し、エラーログを記録します。
- **データ変換**: 外部システムに連携する前に、データ形式を変換する必要がある場合があります。Apex でデータ変換ロジックを実装します。

#### 11.2.6 応用例とユースケース

- **データウェアハウス同期**: Salesforce のデータを、データウェアハウスにリアルタイムに同期する。
- **マーケティングオートメーション**: 顧客情報の変更をトリガーにして、マーケティングキャンペーンを自動化する。
- **サプライチェーン管理**: 製品の在庫状況の変更をサプライチェーンシステムにリアルタイムに連携する。
- **データ監査**: データ変更履歴を記録し、監査証跡として利用する。

#### 11.2.7 トラブルシューティング

- **データ変更イベントが配信されない**: CDC が有効になっているか確認してください。トリガーが有効になっているか確認してください。
- **トリガーが正しく動作しない**: トリガーコードにエラーがないか確認してください。SOQL クエリのガバナ制限を超えていないか確認してください。
- **外部システムとの連携がうまくいかない**: CometD クライアントの設定を確認してください。Streaming API の接続が確立されているか確認してください。

#### 11.2.8 まとめと次のステップ

CDC は、Salesforce のデータ変更をリアルタイムに外部システムに通知するための強力な機能です。本セクションで学んだ知識を基に、実際に CDC を有効にし、データ変更イベントの購読を試してみてください。次のステップとして、外部システムとの連携や、より複雑なデータ連携処理の実装に挑戦してみてください。

### 11.3 イベントバスとメッセージング：マイクロサービス連携

#### 11.3.1 概要と重要性

イベントバスは、複数のアプリケーションやマイクロサービス間でイベントを交換するための共通基盤です。Salesforce では、Platform Events と Pub/Sub API がイベントバスとしての役割を果たし、Salesforce 内部だけでなく、外部のマイクロサービスとの連携を可能にします。これにより、システム全体の疎結合性を高め、独立した開発・デプロイを促進し、スケーラビリティと柔軟性を向上させることができます。

#### 11.3.2 特徴と利点

- **疎結合**: マイクロサービスは、他のマイクロサービスを直接呼び出す必要がなく、イベントを介して間接的に連携できます。
- **非同期処理**: イベント駆動型であるため、マイクロサービスは非同期的に処理を実行できます。
- **拡張性**: 新しいマイクロサービスを容易に追加でき、既存のマイクロサービスに影響を与えることなく、システム全体を拡張できます。
- **柔軟性**: マイクロサービスは、様々なプログラミング言語や技術を使用して開発できます。
- **監視性**: イベントバスを監視することで、システム全体の動作状況を把握できます。

#### 11.3.3 事前準備と前提条件

- Developer Edition または Enterprise Edition 以上の Salesforce 組織
- Platform Events の基本的な知識
- (任意) メッセージキュー（例：RabbitMQ、Kafka）の知識 (外部システム連携の場合)
- (任意) API Gateway の知識 (マイクロサービス連携の場合)

#### 11.3.4 基本的な使い方

**1. Platform Events の定義:**

Platform Events を、マイクロサービス間で交換するイベントのスキーマとして定義します。

**2. イベントの発行 (Salesforce):**

Apex トリガー、Apex クラス、またはフローから、Platform Event を発行します。

**3. イベントの購読 (Salesforce):**

Apex トリガーまたはフローを使用して、Salesforce 内部のマイクロサービスが Platform Event を購読します。

**4. イベントの購読 (外部マイクロサービス):**

- **方法 1: CometD クライアントまたは Streaming API**: 外部マイクロサービスが、CometD クライアントまたは Streaming API を使用して、Platform Event を購読します。
- **方法 2: メッセージキュー**: Platform Event をメッセージキュー（例：RabbitMQ、Kafka）に転送し、外部マイクロサービスがメッセージキューからイベントを購読します。

#### 11.3.5 実践的なテクニック

- **イベントのルーティング**: イベントバス上で、特定のイベントを特定のマイクロサービスにルーティングするための仕組みを実装します。
- **イベントの変換**: イベントの形式を、マイクロサービスが理解できる形式に変換します。
- **エラー処理**: イベント処理中に発生したエラーを適切に処理し、エラーログを記録します。
- **メッセージの永続化**: メッセージキューを使用して、イベントを永続化し、システムの信頼性を向上させます。
- **API Gateway**: API Gateway を使用して、マイクロサービスへのアクセスを制御し、セキュリティを強化します。

#### 11.3.6 応用例とユースケース

- **注文処理**: 注文受付マイクロサービス、在庫管理マイクロサービス、決済処理マイクロサービスを、イベントバスを介して連携させる。
- **顧客管理**: 顧客情報管理マイクロサービス、マーケティングマイクロサービス、サポートマイクロサービスを、イベントバスを介して連携させる。
- **IoT プラットフォーム**: IoT デバイスから送られてくるデータを、イベントバスを介して様々なマイクロサービスに配信し、分析やアクションを実行する。

#### 11.3.7 トラブルシューティング

- **イベントが配信されない**: Platform Event オブジェクトの設定を確認してください。API バージョンが正しいか確認してください。トリガーが有効になっているか確認してください。CometD クライアントまたは Streaming API の設定を確認してください。
- **トリガーが正しく動作しない**: トリガーコードにエラーがないか確認してください。SOQL クエリのガバナ制限を超えていないか確認してください。
- **マイクロサービス間の連携がうまくいかない**: イベントのルーティング設定を確認してください。イベントの形式が正しいか確認してください。メッセージキューの設定を確認してください。

#### 11.3.8 まとめと次のステップ

イベントバスとメッセージングは、マイクロサービスアーキテクチャを Salesforce 上で実現するための重要な要素です。本セクションで学んだ知識を基に、実際に Platform Events を使用して、マイクロサービス間の連携を試してみてください。次のステップとして、メッセージキューや API Gateway などの外部サービスとの連携や、より複雑なマイクロサービスアーキテクチャの設計に挑戦してみてください。

この章では、イベント駆動アーキテクチャの基本概念から、Salesforce プラットフォームにおける具体的な実装方法、そしてマイクロサービスとの連携までを網羅的に解説しました。これらの知識を活用することで、よりリアルタイムで、スケーラブルで、変化に強いシステムを構築できるようになるでしょう。
