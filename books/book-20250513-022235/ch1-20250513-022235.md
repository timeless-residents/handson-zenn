# 第 1 章：Salesforce 開発の羅針盤 - 今、なぜ Salesforce なのか？

## 1.1 デジタルトランスフォーメーションと Salesforce

### 1.1.1 概要と重要性

現代のビジネス環境において、デジタルトランスフォーメーション（DX）は、企業が競争力を維持し、成長を続けるための不可欠な要素となりました。DX とは、単なる IT ツールの導入ではなく、組織、プロセス、ビジネスモデル全体をデジタル技術によって変革し、顧客体験を向上させることです。

Salesforce は、この DX を推進するための強力なプラットフォームとして、世界中の企業に採用されています。顧客関係管理（CRM）の枠を超え、マーケティング、セールス、サービス、コマース、分析といったビジネスのあらゆる側面を統合し、顧客中心のビジネス運営を支援します。Salesforce を理解することは、DX 時代のビジネスパーソンにとって、必須のスキルと言えるでしょう。

### 1.1.2 特徴と利点

Salesforce が DX を推進する上で持つ特徴と利点は以下の通りです。

- **顧客中心のプラットフォーム:** 顧客データを一元管理し、360 度の顧客ビューを提供することで、よりパーソナライズされた顧客体験を実現します。
- **柔軟性と拡張性:** アプリケーションのカスタマイズや拡張が容易であり、企業のニーズに合わせて柔軟に対応できます。AppExchange を通じて、豊富なサードパーティ製アプリケーションを利用することも可能です。
- **クラウドベース:** インフラストラクチャの管理が不要であり、迅速な導入とスケーラビリティを実現します。場所やデバイスに依存せず、どこからでもアクセス可能です。
- **ローコード/ノーコード開発:** Visualforce や Apex といった従来の開発言語に加え、Lightning コンポーネントや Flow Builder といったローコード/ノーコード開発ツールを提供し、開発の迅速化とコスト削減に貢献します。
- **AI 搭載:** Einstein AI による予測分析、パーソナライズされたレコメンデーション、自動化されたタスクなど、AI を活用した高度なビジネスインテリジェンスを提供します。
- **セキュリティ:** 強固なセキュリティ機能を備え、顧客データの保護とコンプライアンスを支援します。

### 1.1.3 事前準備と前提条件

Salesforce の学習を始めるにあたり、以下の準備をしておくとスムーズに進めることができます。

- **Trailhead アカウントの作成:** Salesforce の公式学習プラットフォームである Trailhead で無料アカウントを作成します。Trailhead は、インタラクティブなモジュールやプロジェクトを通じて、Salesforce の知識とスキルを習得できる優れた学習リソースです。
  - [Trailhead: The fun way to learn Salesforce](https://trailhead.salesforce.com/ja)
- **無料の開発組織（Developer Edition）の取得:** Salesforce の開発やテストを行うための無料の開発組織を取得します。開発組織は、Sandbox 環境と異なり、永続的に利用することができます。
- **Salesforce の基本的な用語の理解:** Salesforce の主要な用語（オブジェクト、項目、レコード、アプリケーションなど）を理解しておくと、より効率的に学習を進めることができます。
- **プログラミングの基礎知識:** 必ずしも必須ではありませんが、HTML、CSS、JavaScript、Java などのプログラミングの基礎知識があると、Salesforce 開発の理解が深まります。

### 1.1.4 基本的な使い方

Salesforce を使い始めるための基本的な手順を説明します。

1.  **Salesforce へのログイン:** 取得した開発組織にログインします。URL、ユーザー名、パスワードを入力してログインしてください。
2.  **オブジェクトの確認:** Sales アプリケーションを開き、取引先、取引先責任者、商談などの標準オブジェクトを確認します。これらのオブジェクトは、ビジネスにおける主要なエンティティを表します。
3.  **レコードの作成:** 取引先オブジェクトで新しい取引先レコードを作成します。取引先名、住所、電話番号などの情報を入力して保存します。
4.  **リストビューのカスタマイズ:** 取引先オブジェクトのリストビューをカスタマイズして、表示する項目を変更します。たとえば、業種や売上高などの項目を追加して、取引先を絞り込みやすくすることができます。
5.  **レポートの作成:** レポートビルダーを使用して、取引先に関するレポートを作成します。たとえば、業種別の取引先数や、売上高別の取引先数などを集計することができます。

```
// Apexコード例: 新しい取引先レコードを作成する
Account acc = new Account(Name = 'Test Account', Industry = 'Technology');
insert acc;

System.debug('新しい取引先レコードが作成されました: ' + acc.Id);
```

### 1.1.5 実践的なテクニック

Salesforce をより効果的に活用するための実践的なテクニックを紹介します。

- **入力規則の設定:** データ品質を維持するために、入力規則を設定します。たとえば、必須項目を設定したり、特定の形式でデータを入力するように制限したりすることができます。
  - 設定例：取引先の電話番号が必須項目であることを設定します。
- **ワークフローの自動化:** ワークフロールールを使用して、特定の条件が満たされた場合に自動的にタスクを作成したり、メールを送信したりすることができます。
  - 設定例：商談が成立した場合に、担当者にタスクを自動的に割り当てるワークフロールールを設定します。
- **カスタム項目の作成:** 標準オブジェクトに、企業のニーズに合わせてカスタム項目を追加します。たとえば、顧客の満足度を評価するためのアンケート結果を保存するカスタム項目を作成することができます。
  - 注意点：カスタム項目を作成する際には、API 参照名が組織全体で一意である必要があります。
- **Lightning Flow の利用:** Lightning Flow Builder を使用して、複雑なビジネスプロセスを自動化します。画面フロー、自動起動フロー、レコードトリガーフローなど、さまざまな種類のフローを作成できます。
  - ユースケース：顧客からの問い合わせがあった場合に、担当者を自動的に割り当て、対応状況を追跡するフローを作成します。
- **AppExchange の活用:** AppExchange から、Salesforce の機能を拡張するさまざまなアプリケーションをインストールします。
  - 例：メールマーケティングツール、ドキュメント生成ツール、プロジェクト管理ツールなど。

### 1.1.6 応用例とユースケース

Salesforce は、様々な業界や業務で活用されています。以下にいくつかの応用例とユースケースを紹介します。

- **営業支援:** 営業担当者が顧客情報を一元的に管理し、商談の進捗状況を追跡することで、営業効率を向上させます。
- **顧客サービス:** 顧客からの問い合わせを効率的に処理し、迅速かつ適切なサポートを提供することで、顧客満足度を向上させます。
- **マーケティング:** 顧客の行動履歴に基づいて、パーソナライズされたマーケティングキャンペーンを実施し、コンバージョン率を向上させます。
- **e コマース:** オンラインストアと Salesforce を連携させ、顧客の購買履歴や嗜好に基づいて、パーソナライズされた商品レコメンデーションを提供します。
- **非営利団体:** 寄付者管理、ボランティア管理、プログラム管理など、非営利団体の運営を効率化します。

### 1.1.7 トラブルシューティング

Salesforce の使用中に発生する可能性のある一般的な問題と、その解決策を紹介します。

- **ログインできない:** ユーザー名またはパスワードが間違っている可能性があります。パスワードをリセットするか、Salesforce 管理者に問い合わせてください。
- **データが表示されない:** 権限設定が不適切である可能性があります。Salesforce 管理者に権限を確認してもらうか、必要な権限を付与してもらってください。
- **エラーメッセージが表示される:** エラーメッセージの内容を確認し、指示に従って問題を解決してください。エラーメッセージが理解できない場合は、Salesforce のドキュメントを参照するか、コミュニティフォーラムで質問してください。
- **ワークフローが正常に動作しない:** ワークフロールールの条件やアクションが正しく設定されているか確認してください。デバッグログを確認することで、ワークフローの実行状況を把握することができます。
- **Lightning Flow が期待通りに動作しない:** Flow Builder でフローをデバッグし、エラー箇所を特定してください。変数の値や条件分岐が正しく設定されているか確認してください。

## 1.3 Salesforce 開発の全体像：ローコードからフルコードまで

### 1.3.1 概要と重要性

Salesforce 開発は、ローコード（Low-Code）からフルコード（Full-Code）まで、幅広いアプローチを提供しています。企業は、ビジネス要件や開発リソースに応じて、最適な開発手法を選択することができます。このセクションでは、Salesforce 開発の全体像を把握し、ローコードとフルコードのそれぞれの特徴、利点、適切なユースケースを理解することで、より効果的な開発戦略を立てることができるようになります。また、それぞれの開発手法を組み合わせることで、より高度なソリューションを実現する方法についても解説します。

### 1.3.2 特徴と利点

Salesforce 開発には、主に以下の３つのアプローチがあります。

1.  **宣言型開発（ローコード/ノーコード）:** コーディングをほとんど、または全く行わずに、GUI ベースのツールを使用してアプリケーションを開発します。
    - **利点:** 開発速度が速く、プログラミングスキルがなくても開発できます。ビジネスユーザーや Salesforce 管理者でも、アプリケーションを開発・変更することができます。
2.  **コードによるカスタマイズ（フルコード）:** Apex、Visualforce、Lightning Web Components などのプログラミング言語を使用して、アプリケーションを開発します。
    - **利点:** 複雑なビジネスロジックや高度なカスタマイズに対応できます。標準機能では実現できない要件を満たすことができます。
3.  **ハイブリッド開発:** 宣言型開発とコードによるカスタマイズを組み合わせて、アプリケーションを開発します。
    - **利点:** 両方の利点を活用し、開発速度と柔軟性を両立させることができます。要件に応じて、最適な開発手法を選択することができます。

### 1.3.3 事前準備と前提条件

Salesforce 開発を始めるにあたり、以下の準備をしておくとスムーズに進めることができます。

- **Salesforce の基本的な知識:** Salesforce の主要なオブジェクト、項目、レコード、アプリケーションなどの概念を理解している必要があります。
- **Trailhead アカウントの作成:** Salesforce の公式学習プラットフォームである Trailhead で無料アカウントを作成します。
- **無料の開発組織（Developer Edition）の取得:** Salesforce の開発やテストを行うための無料の開発組織を取得します。
- **開発環境の構築:** ローコード開発の場合は、Salesforce の GUI ベースの開発ツールを使用します。フルコード開発の場合は、Visual Studio Code などの IDE と Salesforce CLI をインストールし、開発環境を構築します。
- **Git の知識:** バージョン管理ツールである Git の基本的な使い方を理解しておくと、複数人での開発やコードの管理に役立ちます。

### 1.3.4 ローコード開発

ローコード開発は、Salesforce のプラットフォーム上で、コーディングをほとんど行わずにアプリケーションを開発する手法です。主に以下のツールを使用します。

- **Lightning App Builder:** ドラッグ＆ドロップ操作で、アプリケーションの UI を構築します。コンポーネントを配置したり、プロパティを設定したりすることで、簡単に画面を作成できます。
- **Flow Builder:** ビジュアルなインターフェースで、ビジネスプロセスを自動化します。画面フロー、自動起動フロー、レコードトリガーフローなど、様々な種類のフローを作成できます。
- **Process Builder:** ワークフロールールよりも複雑なビジネスプロセスを自動化します。複数の条件分岐やアクションを設定できます。
- **Workflow Rules:** 特定の条件が満たされた場合に、自動的にタスクを作成したり、メールを送信したりします。
- **Validation Rules:** データ品質を維持するために、入力規則を設定します。必須項目を設定したり、特定の形式でデータを入力するように制限したりすることができます。

```
// 例：Flow Builderで、取引先が作成されたときに自動的にタスクを作成するフローを作成する
// 1. Flow Builderを開き、新しいレコードトリガーフローを作成する
// 2. オブジェクトに「取引先」を選択し、「レコードが作成されたとき」にトリガーするように設定する
// 3. 「要素」タブから「レコードを作成」要素を追加する
// 4. 「レコードを作成」要素の設定で、オブジェクトに「タスク」を選択し、必要な項目（件名、期日、担当者など）を設定する
// 5. フローを保存して有効化する
```

### 1.3.5 フルコード開発

フルコード開発は、Apex、Visualforce、Lightning Web Components などのプログラミング言語を使用して、アプリケーションを開発する手法です。主に以下の技術を使用します。

- **Apex:** Salesforce プラットフォーム上で実行されるオブジェクト指向のプログラミング言語です。ビジネスロジックの実装、カスタム API の作成、データベース操作などに使用されます。
- **Visualforce:** Salesforce の UI を構築するためのマークアップ言語です。カスタムページ、カスタムコンポーネント、カスタムコントローラなどを作成できます。
- **Lightning Web Components (LWC):** 最新の Web 標準に基づいた UI フレームワークです。高速で再利用可能な UI コンポーネントを作成できます。JavaScript、HTML、CSS を使用して開発します。
- **SOQL (Salesforce Object Query Language):** Salesforce のデータベースからデータを取得するためのクエリ言語です。
- **DML (Data Manipulation Language):** Salesforce のデータベースにデータを挿入、更新、削除するための言語です。

```java
// Apexコード例: 新しい取引先レコードを作成し、関連するタスクを作成する
Account acc = new Account(Name = 'Test Account', Industry = 'Technology');
insert acc;

Task task = new Task(Subject = 'Follow Up', ActivityDate = Date.today().addDays(7), WhatId = acc.Id);
insert task;

System.debug('新しい取引先レコードとタスクが作成されました。');
```

### 1.3.6 ハイブリッド開発

ハイブリッド開発は、ローコードとフルコードを組み合わせて、アプリケーションを開発する手法です。例えば、Lightning App Builder で UI を構築し、Flow Builder でビジネスプロセスを自動化し、Apex で複雑なビジネスロジックを実装することができます。

ハイブリッド開発のメリットは、開発速度と柔軟性を両立できることです。簡単なカスタマイズはローコードで、複雑なカスタマイズはフルコードで行うことで、効率的に開発を進めることができます。

```
// 例：Flow Builderで、Apexアクションを呼び出す
// 1. Flow Builderを開き、フローを作成する
// 2. 「要素」タブから「Apexアクション」要素を追加する
// 3. 「Apexアクション」要素の設定で、呼び出すApexクラスとメソッドを選択する
// 4. Apexクラスで、必要なビジネスロジックを実装する
// 5. フローを保存して有効化する
```

### 1.3.7 適切なユースケース

ローコード、フルコード、ハイブリッド開発のそれぞれに適したユースケースを以下に示します。

- **ローコード:**
  - 簡単なデータ入力フォームの作成
  - 承認ワークフローの自動化
  - レポートやダッシュボードの作成
  - ビジネスユーザー向けの簡単なアプリケーション開発
- **フルコード:**
  - 複雑なビジネスロジックの実装
  - 他のシステムとのインテグレーション
  - 高度な UI のカスタマイズ
  - Salesforce の標準機能では実現できない要件の実現
- **ハイブリッド開発:**
  - 標準機能とカスタム機能を組み合わせたアプリケーション開発
  - 開発速度と柔軟性を両立させたい場合
  - 要件が複雑で、ローコードだけでは実現できない場合

### 1.3.8 トラブルシューティング

Salesforce 開発において、発生する可能性のある問題と、その解決策を紹介します。

- **ローコード開発の問題:**
  - 機能が制限されているため、要件を満たせない場合がある。
  - 複雑なビジネスロジックを実装できない。
  - デバッグが難しい場合がある。
  - 解決策：フルコード開発に切り替えるか、ハイブリッド開発を検討する。
- **フルコード開発の問題:**
  - 開発に時間がかかる。
  - プログラミングスキルが必要。
  - バグが発生しやすい。
  - 解決策：ローコード開発を最大限に活用し、必要な部分だけフルコードで開発する。
- **ハイブリッド開発の問題:**
  - ローコードとフルコードの連携が難しい場合がある。
  - 両方の知識が必要。
  - 解決策：Salesforce のドキュメントをよく読み、ベストプラクティスに従って開発する。
