## 第 10 章：API 連携：Salesforce をハブとするシステム連携

### 10.1 REST API と SOAP API：適切な API の選択

**1. 概要と重要性**

Salesforce は、REST API と SOAP API という 2 つの主要な API を提供しており、システム連携の中核を担います。これらの API は、Salesforce に格納されたデータや機能を外部システムから安全に利用するためのインターフェースです。適切な API を選択することは、連携のパフォーマンス、セキュリティ、開発効率に大きく影響するため、非常に重要です。連携要件に合わせて最適な API を選択することで、スムーズで効率的なシステム連携を実現できます。

**2. 特徴と利点**

| API タイプ | 特徴                                                                                                                                                                                                                                                                                                      | 利点                                                                                                                                                                                    |
| :--------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REST API   | - Representational State Transfer (REST) アーキテクチャに基づいている - HTTP メソッド（GET, POST, PUT, DELETE）を使用 - JSON 形式でデータを交換 - 軽量で高速 - 開発の容易さ - モバイルアプリケーションや Web アプリケーションとの連携に適している - Salesforce Lightning プラットフォームとの親和性が高い | - シンプルで理解しやすい - 開発コストを抑えられる - パフォーマンスが高い - 標準的な HTTP ライブラリを使用できる - 多くのプログラミング言語でサポートされている - スケーラビリティが高い |
| SOAP API   | - Simple Object Access Protocol (SOAP) アーキテクチャに基づいている - XML 形式でデータを交換 - WSDL (Web Services Description Language) を使用して API を記述 - 複雑なエンタープライズシステムとの連携に適している - より高いセキュリティ機能を提供                                                       | - トランザクション管理やセキュリティ機能が充実している - 信頼性が高い - 古くからエンタープライズシステムで利用されている実績がある - より複雑な連携要件に対応可能                       |

**3. 事前準備と前提条件**

- Salesforce 開発者アカウントの取得：無料の開発者アカウントを取得し、API 連携に必要な権限を設定します。
- API クライアントツールの準備：Postman などの API クライアントツールをインストールします。
- Salesforce 組織の API 利用設定の確認：Salesforce 組織で API が有効になっていることを確認します。

**4. 基本的な使い方**

**REST API の利用例（データの取得）**

以下の例では、アカウントオブジェクトのレコードを REST API で取得する方法を示します。

```bash
# APIエンドポイント
ENDPOINT="https://your-instance.salesforce.com/services/data/v58.0/sobjects/Account/001xxxxxxxxxxxxxxx"

# アクセストークン
ACCESS_TOKEN="your_access_token"

# HTTPリクエスト
curl -H "Authorization: Bearer $ACCESS_TOKEN" $ENDPOINT
```

**SOAP API の利用例（データの更新）**

以下の例では、SOAP API を用いてアカウントオブジェクトのレコードを更新する方法を示します。SOAP API の利用には、WSDL ファイルが必要です。

```xml
<!-- SOAPリクエスト -->
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" xmlns:urn="urn:partner.soap.sforce.com">
   <soapenv:Header>
      <urn:SessionHeader>
         <urn:sessionId>your_session_id</urn:sessionId>
      </urn:SessionHeader>
   </soapenv:Header>
   <soapenv:Body>
      <urn:update>
         <urn:sObjects>
            <sf:type xmlns:sf="urn:sobject.partner.soap.sforce.com">Account</sf:type>
            <sf:Id xmlns:sf="urn:sobject.partner.soap.sforce.com">001xxxxxxxxxxxxxxx</sf:Id>
            <sf:Name xmlns:sf="urn:sobject.partner.soap.sforce.com">Updated Account Name</sf:Name>
         </urn:sObjects>
      </urn:update>
   </soapenv:Body>
</soapenv:Envelope>
```

**5. 実践的なテクニック**

- **バルク API の活用：** 大量のデータを処理する場合、REST API のバルク API や SOAP API のバルク API を利用することで、パフォーマンスを向上させることができます。
- **複合 API の利用：** 複数の API コールを 1 つのリクエストにまとめることで、ネットワークのオーバーヘッドを削減し、処理速度を向上させることができます。
- **メタデータ API の利用：** Salesforce の組織設定やカスタムオブジェクトの定義などを操作する場合、メタデータ API を利用します。
- **Streaming API の利用：** リアルタイムにデータを連携する場合、Streaming API を利用します。

**6. 応用例とユースケース**

- **e コマースシステムとの連携：** e コマースプラットフォームから Salesforce に顧客データや注文データを連携し、マーケティングや顧客サポートに活用します。REST API が適しています。
- **ERP システムとの連携：** ERP システムから Salesforce に会計データや在庫データを連携し、営業活動や顧客管理に活用します。SOAP API または MuleSoft などの連携ツールが適しています。
- **マーケティングオートメーションツールとの連携：** マーケティングオートメーションツールから Salesforce にキャンペーンデータやリードデータを連携し、営業活動の効率化を図ります。REST API が適しています。
- **BI ツールとの連携：** Salesforce のデータを BI ツールに連携し、分析やレポート作成に活用します。REST API が適しています。
- **レガシーシステムとの連携:** 既存のレガシーシステムと Salesforce を連携させ、データの一元管理や業務プロセスの自動化を実現します。SOAP API や MuleSoft のような柔軟な連携プラットフォームが適しています。

**7. トラブルシューティング**

- **API コール制限：** Salesforce には API コールの制限があります。制限を超えないように、バルク API や複合 API の利用を検討してください。
- **認証エラー：** アクセストークンやセッション ID が正しいことを確認してください。
- **データ型の不一致：** API で送受信するデータの型が Salesforce のデータ型と一致していることを確認してください。
- **アクセス権限：** API を実行するユーザーに、必要なオブジェクトやフィールドへのアクセス権限があることを確認してください。
- **API バージョン：** API のバージョンが、Salesforce 組織でサポートされているバージョンであることを確認してください。古いバージョンの API を使用すると、予期せぬエラーが発生する可能性があります。

**8. まとめと次のステップ**

REST API と SOAP API は、Salesforce をハブとしたシステム連携の基盤です。それぞれの API の特徴を理解し、連携要件に最適な API を選択することが重要です。次のステップでは、OAuth 2.0 認証について学び、API 連携のセキュリティを強化しましょう。

### 10.2 OAuth 2.0 認証：セキュリティと認可

**1. 概要と重要性**

OAuth 2.0 は、Salesforce API へのセキュアなアクセスを実現するための業界標準の認証プロトコルです。ユーザー名とパスワードを直接共有することなく、外部アプリケーションが Salesforce のデータにアクセスすることを許可します。セキュリティの強化だけでなく、認可の仕組みを提供することで、アプリケーションがアクセスできるリソースを制限できます。

**2. 特徴と利点**

- **セキュリティ：** ユーザーの認証情報を直接共有する必要がないため、セキュリティリスクを軽減できます。
- **認可：** アプリケーションが必要なリソースへのアクセスのみを許可し、不要なアクセスを防ぐことができます。
- **標準化：** 業界標準のプロトコルであるため、多くのプログラミング言語やフレームワークでサポートされています。
- **委譲：** ユーザーの代わりにアプリケーションがリソースにアクセスすることを許可できます。
- **柔軟性:** さまざまなグラントタイプ（認証フロー）をサポートしており、アプリケーションの要件に合わせて最適なフローを選択できます。

**3. 事前準備と前提条件**

- **Salesforce 接続アプリケーションの作成：** Salesforce 組織で接続アプリケーションを作成し、OAuth 2.0 の設定を行います。
- **コールバック URL の設定：** 認証後にリダイレクトされるコールバック URL を設定します。
- **クライアント ID とクライアントシークレットの取得：** 接続アプリケーションからクライアント ID とクライアントシークレットを取得します。

**4. 基本的な使い方**

**OAuth 2.0 フローの例（Web サーバーフロー）**

1.  **認証リクエスト：** ユーザーを Salesforce の認証エンドポイントにリダイレクトします。

    ```
    https://login.salesforce.com/services/oauth2/authorize?
    response_type=code&
    client_id=YOUR_CLIENT_ID&
    redirect_uri=YOUR_CALLBACK_URL
    ```

2.  **認証と認可：** ユーザーが Salesforce で認証し、アプリケーションへのアクセスを許可します。

3.  **認証コードの取得：** Salesforce が認証コードをコールバック URL に付与してリダイレクトします。

4.  **アクセストークンのリクエスト：** 認証コードを使用して、アクセストークンをリクエストします。

    ```bash
    curl -X POST \
      https://login.salesforce.com/services/oauth2/token \
      -H 'Content-Type: application/x-www-form-urlencoded' \
      -d 'grant_type=authorization_code&client_id=YOUR_CLIENT_ID&client_secret=YOUR_CLIENT_SECRET&redirect_uri=YOUR_CALLBACK_URL&code=YOUR_AUTHORIZATION_CODE'
    ```

5.  **アクセストークンの取得：** Salesforce がアクセストークンとリフレッシュトークンを返却します。

6.  **API リクエスト：** アクセストークンを使用して、Salesforce API にアクセスします。

    ```bash
    curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" https://your-instance.salesforce.com/services/data/v58.0/sobjects/Account
    ```

**5. 実践的なテクニック**

- **リフレッシュトークンの利用：** アクセストークンの有効期限が切れた場合、リフレッシュトークンを使用して新しいアクセストークンを取得します。
- **スコープの設定：** 接続アプリケーションに適切なスコープを設定し、必要なリソースへのアクセスのみを許可します。
- **PKCE (Proof Key for Code Exchange) の利用：** 公開クライアント（モバイルアプリケーションなど）で OAuth 2.0 フローを使用する場合、PKCE を利用してセキュリティを強化します。
- **JWT (JSON Web Token) ベアラートークンの利用：** サーバー間の認証に JWT ベアラートークンを利用することで、ユーザーの介入なしに Salesforce API にアクセスできます。
- **OAuth 2.0 ポリシー:** Salesforce 組織で OAuth 2.0 ポリシーを設定し、接続アプリケーションのセキュリティを管理します。例えば、IP 制限やセッションタイムアウトを設定できます。

**6. 応用例とユースケース**

- **モバイルアプリケーションからの Salesforce へのアクセス：** モバイルアプリケーションから Salesforce のデータにアクセスする場合、OAuth 2.0 フローを利用して安全に認証します。
- **Web アプリケーションからの Salesforce へのアクセス：** Web アプリケーションから Salesforce のデータにアクセスする場合、OAuth 2.0 フローを利用して安全に認証します。
- **サーバー間連携：** サーバー間で Salesforce のデータを連携する場合、JWT ベアラートークンを利用して認証します。
- **サードパーティアプリケーションとの連携：** サードパーティアプリケーションから Salesforce のデータにアクセスする場合、OAuth 2.0 フローを利用して安全に認証します。

**7. トラブルシューティング**

- **コールバック URL のエラー：** コールバック URL が接続アプリケーションで設定されている URL と一致していることを確認してください。
- **スコープのエラー：** API にアクセスするために必要なスコープが接続アプリケーションに設定されていることを確認してください。
- **アクセストークンの有効期限切れ：** リフレッシュトークンを使用して新しいアクセストークンを取得してください。
- **接続アプリケーションのブロック：** Salesforce 管理者が接続アプリケーションをブロックしている場合、管理者にお問い合わせください。
- **CORS (Cross-Origin Resource Sharing) エラー:** JavaScript から Salesforce API にアクセスする場合、CORS の設定を確認してください。Salesforce 組織で CORS の設定を有効にする必要があります。

**8. まとめと次のステップ**

OAuth 2.0 は、Salesforce API へのセキュアなアクセスを実現するための重要な認証プロトコルです。OAuth 2.0 フローを理解し、適切に設定することで、アプリケーションのセキュリティを強化できます。次のステップでは、API Gateway や MuleSoft などの連携ツールについて学び、外部システムとの連携をさらに発展させましょう。

### 10.3 外部システムとの連携：API Gateway、MuleSoft

**1. 概要と重要性**

Salesforce をハブとして外部システムと連携する際、API Gateway や MuleSoft などの連携ツールを利用することで、連携の複雑さを軽減し、セキュリティと管理性を向上させることができます。これらのツールは、複数のシステム間のデータフローを仲介し、変換、ルーティング、セキュリティポリシーの適用などの機能を提供します。

**2. 特徴と利点**

| ツール      | 特徴                                                                                                                                                                                                                                                         | 利点                                                                                                                                                                             |
| :---------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API Gateway | - API の集中管理 - セキュリティポリシーの適用 - トラフィック管理 - API のモニタリング - API のバージョン管理 - 認証・認可機能の提供 - レート制限、スロットリング機能の提供                                                                                   | - API のセキュリティを強化できる - API のパフォーマンスを向上できる - API の管理を効率化できる - API の利用状況を可視化できる - API の変更を容易にできる                         |
| MuleSoft    | - エンタープライズサービスバス (ESB) - あらゆるシステムとの連携を可能にする - データ変換、ルーティング、オーケストレーション機能の提供 - 事前構築済みのコネクタの利用 - ローコード開発環境の提供 - API の作成・管理 - さまざまなプロトコルやデータ形式に対応 | - 複雑な連携要件に対応できる - 開発コストを削減できる - 連携の柔軟性を高めることができる - 異なるシステム間のデータ形式の違いを吸収できる - 既存のシステムを変更せずに連携できる |

**3. 事前準備と前提条件**

- **API Gateway の選定と設定：** Amazon API Gateway、Azure API Management、Google Cloud API Gateway などの API Gateway を選定し、設定します。
- **MuleSoft Anypoint Platform のアカウント作成：** MuleSoft Anypoint Platform のアカウントを作成し、開発環境を構築します。
- **Salesforce コネクタの設定：** API Gateway または MuleSoft で Salesforce コネクタを設定し、Salesforce への接続を確立します。
- **連携要件の明確化：** 連携するシステム、データ形式、変換ルールなどを明確にします。

**4. 基本的な使い方**

**API Gateway の利用例（API の公開）**

1.  Salesforce API を API Gateway に登録します。
2.  API Gateway で認証・認可の設定を行います。
3.  API Gateway でレート制限やスロットリングの設定を行います。
4.  API Gateway のエンドポイントを公開し、外部システムからアクセスできるようにします。

**MuleSoft の利用例（データ連携）**

1.  MuleSoft Anypoint Studio でデータ連携フローを作成します。
2.  Salesforce コネクタと連携先のシステムコネクタを設定します。
3.  データ変換、ルーティング、オーケストレーションロジックを実装します。
4.  Mule アプリケーションをデプロイし、データ連携を開始します。

**5. 実践的なテクニック**

- **API Gateway でのセキュリティポリシーの適用：** API Gateway で IP 制限、レート制限、認証・認可などのセキュリティポリシーを適用し、API への不正アクセスを防ぎます。
- **MuleSoft でのデータ変換：** MuleSoft DataWeave を使用して、異なるシステム間のデータ形式を変換します。
- **API Gateway での API のバージョン管理：** API Gateway で API のバージョン管理を行い、API の変更による影響を最小限に抑えます。
- **MuleSoft でのエラー処理：** MuleSoft でエラーハンドリングを設定し、データ連携中に発生するエラーを適切に処理します。
- **API Gateway での API のモニタリング：** API Gateway で API の利用状況をモニタリングし、パフォーマンスの問題を早期に発見します。
- **MuleSoft でのトランザクション管理：** 複数のシステムにわたるトランザクションを MuleSoft で管理し、データの整合性を保ちます。

**6. 応用例とユースケース**

- **マイクロサービスアーキテクチャ：** Salesforce をバックエンドとして、マイクロサービスアーキテクチャを構築する場合、API Gateway を利用してマイクロサービスへのアクセスを管理します。
- **ハイブリッドクラウド連携：** オンプレミスシステムとクラウドシステムを連携する場合、MuleSoft を利用してデータ連携フローを構築します。
- **B2B 連携：** ビジネスパートナーとのデータ連携を行う場合、API Gateway を利用して API を公開し、安全なデータ交換を実現します。
- **IoT プラットフォームとの連携：** IoT デバイスから収集したデータを Salesforce に連携する場合、MuleSoft を利用してデータ変換とルーティングを行います。
- **レガシーシステムのリプレース：** レガシーシステムを段階的にリプレースする場合、MuleSoft を利用してレガシーシステムと新しいシステムを並行稼働させ、データ連携を維持します。

**7. トラブルシューティング**

- **API Gateway の設定ミス：** API Gateway の設定が正しいことを確認してください。特に、認証・認可の設定、レート制限の設定、CORS の設定などを確認してください。
- **MuleSoft コネクタの設定ミス：** Salesforce コネクタと連携先のシステムコネクタの設定が正しいことを確認してください。特に、接続情報、認証情報、データ形式などを確認してください。
- **データ変換のエラー：** MuleSoft DataWeave のスクリプトにエラーがないことを確認してください。
- **ネットワークの問題：** API Gateway または MuleSoft から Salesforce へのネットワーク接続が確立されていることを確認してください。
- **タイムアウト：** API Gateway または MuleSoft のタイムアウト設定が適切であることを確認してください。
- **スループット制限:** Salesforce 側の API 利用制限に引っかかっていないか確認してください。bulk API など、制限を回避できる API の利用を検討しましょう。

**8. まとめと次のステップ**

API Gateway や MuleSoft などの連携ツールを利用することで、Salesforce をハブとした外部システムとの連携をより効率的に、安全に管理できます。これらのツールを活用することで、複雑な連携要件にも対応でき、ビジネスの俊敏性を向上させることができます。次のステップでは、連携したデータの品質を維持するためのデータガバナンスについて学びましょう。
