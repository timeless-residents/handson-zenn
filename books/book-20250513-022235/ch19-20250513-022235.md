## 第 19 章：トラブルシューティング：問題解決のための実践的アプローチ

Salesforce 開発において、エラーは避けられないものです。しかし、エラーを恐れる必要はありません。エラーは、システムをより深く理解し、スキルを向上させるための貴重な機会です。この章では、Salesforce 開発における一般的な問題を解決するための実践的なアプローチを学びます。デバッグツール、エラーメッセージの解読、そしてコミュニティの活用方法について、具体的な例を交えながら解説していきます。

### 19.1 デバッグツール：Developer Console、Apex Debugger

Salesforce 開発におけるデバッグは、問題を特定し解決するための最も重要なスキルの一つです。Developer Console と Apex Debugger は、そのための強力な武器となります。

#### 19.1.1 概要と重要性

Developer Console は、Salesforce 環境内で実行されるすべての処理をリアルタイムで監視できるブラウザベースのツールです。Apex Debugger は、ローカル IDE（例：VS Code）で Apex コードをステップ実行し、変数の中身を確認できるデバッグツールです。これらを使いこなすことで、コードの実行フローを詳細に追跡し、バグの根本原因を特定することができます。

#### 19.1.2 特徴と利点

**Developer Console:**

- **リアルタイム監視:** DML 操作、SOQL クエリ、Apex コードの実行など、あらゆる処理をリアルタイムで監視できます。
- **ログレベルの調整:** ログレベルを調整することで、必要な情報だけを効率的に収集できます。
- **SOQL クエリ実行:** SOQL クエリを直接実行し、結果をすぐに確認できます。
- **匿名 Apex 実行:** ちょっとしたテストコードやデータの修正などを匿名 Apex で実行できます。

**Apex Debugger:**

- **ステップ実行:** コードを一行ずつ実行し、変数の値をリアルタイムで確認できます。
- **ブレークポイント設定:** 特定の行にブレークポイントを設定し、実行を一時停止させることができます。
- **変数監視:** 特定の変数を監視し、その値の変化を追跡できます。

#### 19.1.3 事前準備と前提条件

**Developer Console:** 特に追加の設定は不要です。Salesforce 組織にログインし、設定メニューから「Developer Console」を選択するだけです。

**Apex Debugger:**

- **Visual Studio Code (VS Code)のインストール:** VS Code をインストールします。（他の IDE でも可）
- **Salesforce Extension Pack のインストール:** VS Code Marketplace から Salesforce Extension Pack をインストールします。
- **Salesforce CLI のインストールと設定:** Salesforce CLI をインストールし、Salesforce 組織に接続します。
- **「デバッグ」パーミッションの付与:** デバッグしたいユーザーに「デバッグ Apex」システム権限を付与します。

#### 19.1.4 基本的な使い方

**Developer Console:**

1.  Salesforce 組織にログインし、設定メニューから「Developer Console」を開きます。
2.  「Debug」メニューから「Change Log Levels」を選択し、ログレベルを設定します（例：Apex Code を FINEST に設定）。
3.  コードを実行し、「Logs」タブでログを確認します。
4.  ログをフィルタリングして、必要な情報を見つけます（例：キーワード検索）。

**Apex Debugger:**

1.  VS Code で Apex クラスファイルを開きます。
2.  デバッグしたい行にブレークポイントを設定します（行番号の左側をクリック）。
3.  VS Code のデバッグパネルを開き、「Launch Apex Debugger」を選択します。
4.  Salesforce 組織のユーザー名、パスワード、セキュリティトークンを入力し、接続します。
5.  コードを実行すると、ブレークポイントで実行が一時停止し、変数の値を調べることができます。

#### 19.1.5 実践的なテクニック

- **ログレベルの使い分け:** 開発中はログレベルを上げて詳細な情報を取得し、本番環境ではログレベルを下げてパフォーマンスへの影響を最小限に抑えます。
- **System.debug()の活用:** コードの重要なポイントに`System.debug()`を追加し、変数の値や処理の進捗状況を確認します。
- **ログフィルタリング:** Developer Console のフィルタリング機能を活用し、必要な情報だけを効率的に抽出します。
- **チェックポイント:** 長い処理時間が発生している箇所にチェックポイントを設定し、実行時間を確認します。

#### 19.1.6 応用例とユースケース

- **SOQL クエリのパフォーマンス改善:** Developer Console で SOQL クエリの実行時間を計測し、インデックスの追加やクエリの最適化を行います。
- **トリガーのエラー解決:** Apex Debugger でトリガーをステップ実行し、エラーが発生する原因を特定します。
- **非同期処理のデバッグ:** Future メソッドや Queueable Apex をデバッグし、非同期処理における問題点を解決します。
- **プラットフォームイベントのデバッグ:** Developer Console でプラットフォームイベントの送受信状況を確認し、イベント駆動アーキテクチャにおける問題を解決します。

#### 19.1.7 トラブルシューティング

- **Developer Console が開かない:** ブラウザのキャッシュをクリアするか、別のブラウザで試してみてください。
- **Apex Debugger が接続できない:** Salesforce CLI のバージョンが最新であることを確認し、組織への接続設定を再確認してください。
- **ログが多すぎて必要な情報が見つからない:** ログレベルを調整するか、フィルタリング機能を活用してください。
- **Apex Debugger で変数の値が表示されない:** 変数がスコープ内に存在するか、可視性が適切であることを確認してください。

#### 19.1.8 まとめと次のステップ

Developer Console と Apex Debugger は、Salesforce 開発における強力なデバッグツールです。これらのツールを使いこなすことで、コードの実行フローを詳細に追跡し、バグの根本原因を特定することができます。次に、エラーメッセージの解読方法について学びましょう。

### 19.2 エラーメッセージの解読：一般的なエラーとその解決策

エラーメッセージは、問題を解決するための手がかりとなる重要な情報です。エラーメッセージを正しく解釈し、適切な対応を行うことで、効率的に問題を解決できます。

#### 19.2.1 概要と重要性

Salesforce のエラーメッセージは、一見すると難解に見えるかもしれませんが、その構造を理解することで、問題の所在を特定しやすくなります。エラーメッセージには、エラーの種類、発生場所、関連する情報などが含まれています。これらの情報を分析することで、迅速かつ正確に問題を解決できます。

#### 19.2.2 特徴と利点

- **エラーの種類の特定:** エラーメッセージは、発生したエラーの種類を明確に示します（例：SOQL クエリのエラー、DML 操作のエラー、ガバナ制限のエラー）。
- **発生場所の特定:** エラーメッセージは、エラーが発生した場所（クラス、トリガー、Visualforce ページなど）を示します。
- **関連情報の提供:** エラーメッセージは、エラーの原因に関する追加情報を提供します（例：無効な SOQL クエリ、必須フィールドの未入力）。

#### 19.2.3 事前準備と前提条件

Salesforce 開発の基本的な知識（Apex、SOQL、DML など）が必要です。また、Developer Console や Apex Debugger などのデバッグツールを使用できることが望ましいです。

#### 19.2.4 基本的な使い方

1.  エラーメッセージを注意深く読みます。
2.  エラーの種類、発生場所、関連情報を特定します。
3.  エラーメッセージに基づいて、問題を解決するための仮説を立てます。
4.  Developer Console や Apex Debugger などのデバッグツールを使用して、仮説を検証します。
5.  問題を解決するためのコード修正または設定変更を行います。
6.  修正後、再度コードを実行し、エラーが解消されたことを確認します。

#### 19.2.5 実践的なテクニック

- **エラーメッセージの分割:** 長いエラーメッセージは、複数の部分に分割して、それぞれの意味を理解します。
- **キーワード検索:** エラーメッセージに含まれるキーワード（例：INVALID_FIELD、REQUIRED_FIELD_MISSING）を検索エンジンで検索し、関連情報を収集します。
- **ログの確認:** Developer Console でログを確認し、エラーが発生するまでの処理の流れを追跡します。

#### 19.2.6 応用例とユースケース

**例 1：SOQL クエリのエラー**

エラーメッセージ: `INVALID_FIELD: field 'InvalidField' does not exist on object 'Account'`

解決策: SOQL クエリで指定したフィールド名が、Account オブジェクトに存在するかどうかを確認します。スペルミスがないか、API 参照名が正しいかを確認します。

**例 2：DML 操作のエラー**

エラーメッセージ: `REQUIRED_FIELD_MISSING: Required fields are missing: [Name]`

解決策: Account オブジェクトの Name フィールドが必須フィールドであることを確認します。レコードを作成または更新する際に、Name フィールドに値を設定するようにコードを修正します。

**例 3：ガバナ制限のエラー**

エラーメッセージ: `System.LimitException: Apex CPU time limit exceeded.`

解決策: コードの最適化を行い、CPU 時間制限を超えないようにします。不要な処理を削除したり、SOQL クエリを効率化したり、Bulk API を使用したりするなどの対策を検討します。

#### 19.2.7 トラブルシューティング

- **エラーメッセージの意味が分からない:** Salesforce のドキュメントやオンラインフォーラムでエラーメッセージを検索し、関連情報を収集します。
- **エラーが発生場所が特定できない:** Developer Console でログを確認し、エラーが発生するまでの処理の流れを追跡します。
- **エラーが解決しない:** 問題を解決するための仮説を立て、デバッグツールで検証します。それでも解決しない場合は、Salesforce コミュニティで質問することを検討します。

#### 19.2.8 まとめと次のステップ

エラーメッセージの解読は、Salesforce 開発における重要なスキルです。エラーメッセージを正しく解釈し、適切な対応を行うことで、効率的に問題を解決できます。次に、Salesforce コミュニティとサポートの活用方法について学びましょう。

### 19.3 コミュニティとサポート：Salesforce Developer Forum、Stack Overflow

Salesforce 開発で問題に直面した際、コミュニティやサポートは貴重なリソースとなります。Salesforce Developer Forum や Stack Overflow などのコミュニティを活用することで、他の開発者の知識や経験を共有し、問題を解決することができます。

#### 19.3.1 概要と重要性

Salesforce は、活発な開発者コミュニティと充実したサポート体制を持っています。これらのリソースを活用することで、自力では解決できない問題も解決できる可能性があります。特に、Salesforce Developer Forum と Stack Overflow は、多くの開発者が知識や経験を共有する場として、非常に有用です。

#### 19.3.2 特徴と利点

**Salesforce Developer Forum:**

- **Salesforce 公式コミュニティ:** Salesforce が公式に運営するコミュニティであり、Salesforce に関するあらゆる質問や相談が可能です。
- **エキスパートの参加:** Salesforce の社員や MVP（Most Valuable Professional）などのエキスパートが参加しており、専門的なアドバイスを得ることができます。
- **豊富な情報:** 過去の質問や回答がアーカイブされており、同様の問題に対する解決策を見つけることができます。

**Stack Overflow:**

- **大規模な Q&A サイト:** プログラミングに関するあらゆる質問や回答が集まる世界最大級の Q&A サイトです。
- **タグによる分類:** Salesforce に関する質問には「salesforce」タグが付けられており、関連する質問を簡単に見つけることができます。
- **評価システム:** 回答に対する評価システムがあり、信頼性の高い回答を見つけることができます。

#### 19.3.3 事前準備と前提条件

Salesforce Developer Forum と Stack Overflow のアカウントが必要です。また、問題の内容を明確に説明できる能力が必要です。

#### 19.3.4 基本的な使い方

**Salesforce Developer Forum:**

1.  Salesforce Developer Forum にアクセスし、アカウントを作成またはログインします。
2.  検索機能を使用して、同様の問題に対する質問や回答を検索します。
3.  質問がない場合は、新しい質問を投稿します。質問の内容を明確に説明し、エラーメッセージやコードの抜粋などを添付します。
4.  回答を待ちます。回答があった場合は、内容を理解し、問題を解決するためのヒントを得ます。

**Stack Overflow:**

1.  Stack Overflow にアクセスし、アカウントを作成またはログインします。
2.  検索機能を使用して、同様の問題に対する質問や回答を検索します。
3.  質問がない場合は、新しい質問を投稿します。質問の内容を明確に説明し、「salesforce」タグを付けます。
4.  回答を待ちます。回答に対する評価を確認し、信頼性の高い回答を参考にします。

#### 19.3.5 実践的なテクニック

- **質問の書き方:** 質問の内容を明確に説明し、エラーメッセージやコードの抜粋などを添付します。質問のタイトルは、問題を簡潔に表すようにします。
- **検索のコツ:** 検索キーワードを工夫することで、より適切な質問や回答を見つけることができます。エラーメッセージに含まれるキーワードや、問題に関連するオブジェクト名などを活用します。
- **回答の評価:** Stack Overflow では、回答に対する評価システムがあります。評価の高い回答は、信頼性が高い可能性が高いです。

#### 19.3.6 応用例とユースケース

- **Salesforce API に関する質問:** Salesforce API の使い方や制限に関する質問を投稿し、エキスパートのアドバイスを得ます。
- **Apex コードのエラー解決:** Apex コードのエラーに関する質問を投稿し、他の開発者の助けを借ります。
- **Visualforce ページの問題解決:** Visualforce ページのデザインやロジックに関する質問を投稿し、解決策を見つけます。
- **Lightning Web Components (LWC)に関する質問:** LWC の構成や実装に関する質問を投稿し、コミュニティの知恵を借ります。

#### 19.3.7 トラブルシューティング

- **質問に回答がない:** 質問の内容が不明確であったり、情報が不足している可能性があります。質問を修正し、より詳細な情報を提供するようにします。
- **質問が重複している:** 過去に同様の質問が投稿されている可能性があります。検索機能を使用して、過去の質問や回答を検索します。
- **回答が理解できない:** 回答の内容が難解であったり、専門的な知識が必要な場合があります。回答者に質問し、内容を明確にしてもらうようにします。

#### 19.3.8 まとめと次のステップ

Salesforce Developer Forum や Stack Overflow などのコミュニティは、Salesforce 開発における貴重なリソースです。これらのコミュニティを活用することで、他の開発者の知識や経験を共有し、問題を解決することができます。

この章では、Salesforce 開発におけるトラブルシューティングの基本的なアプローチについて学びました。デバッグツール、エラーメッセージの解読、そしてコミュニティの活用方法を習得することで、より効率的に問題を解決し、Salesforce 開発スキルを向上させることができます。
