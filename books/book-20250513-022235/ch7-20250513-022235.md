## 第 7 章：Flow Builder 実践：ノーコード自動化の限界を超える

### 7.1 Flow Builder の基本：画面フロー、自動起動フロー、レコードトリガーフロー

#### 7.1.1 概要と重要性

Flow Builder は、Salesforce の強力な自動化ツールであり、コーディングなしでビジネスプロセスを構築できます。画面フローはユーザーインターフェースを通じて情報を収集・表示し、自動起動フローは特定のスケジュールやイベントに基づいてバックグラウンドで動作します。レコードトリガーフローは、レコードの作成、更新、削除などの変更時に自動的に実行されます。これらを理解し活用することで、Salesforce の可能性を最大限に引き出し、業務効率を飛躍的に向上させることが可能になります。

#### 7.1.2 特徴と利点

- **画面フロー:**
  - 対話的なユーザーエクスペリエンスを提供。
  - ガイダンス付きのプロセスを構築可能。
  - 顧客対応、データ収集、承認プロセスなどに適している。
- **自動起動フロー:**
  - バックグラウンドで自動的にタスクを実行。
  - スケジュール、プラットフォームイベント、REST API など様々なトリガーに対応。
  - データ更新、メール送信、外部システム連携などに活用できる。
- **レコードトリガーフロー:**
  - レコードの変更に基づいてリアルタイムにアクションを実行。
  - レコードの整合性維持、関連レコードの自動更新、通知送信などに最適。
  - コーディング不要でビジネスロジックを実装できるため、開発コストを削減。

#### 7.1.3 事前準備と前提条件

- Salesforce 組織へのアクセス権（システム管理者権限推奨）。
- Flow Builder の基本的な概念の理解（変数、決定、ループなど）。
- 自動化したいビジネスプロセスの明確化。

#### 7.1.4 基本的な使い方

**画面フローの作成:**

1.  **Flow Builder を開く:** 設定 > フロー > 新規フロー をクリック。
2.  **フローの種類を選択:** 「画面フロー」を選択。
3.  **要素を配置:** ドラッグ＆ドロップで画面、アクション、決定などの要素を配置。
4.  **要素を接続:** コネクタを使って要素間を接続し、フローのロジックを定義。
5.  **画面の設定:** 画面要素で入力項目や表示項目を設定。
6.  **アクションの設定:** アクション要素でレコードの作成、更新、メール送信などを設定。
7.  **決定の設定:** 決定要素で条件に基づいてフローの分岐を設定。
8.  **フローを保存して有効化:** フローに名前を付けて保存し、有効化。

**例：リード作成画面フロー**

このフローは、リード情報を入力する画面を表示し、入力された情報を基にリードレコードを作成します。

- **画面要素:** 氏名、会社名、メールアドレス、電話番号の入力項目を配置。
- **レコード作成要素:** 画面で入力された情報を基にリードレコードを作成。
- **接続:** 画面要素からレコード作成要素へ接続。

**自動起動フローの作成:**

1.  **Flow Builder を開く:** 設定 > フロー > 新規フロー をクリック。
2.  **フローの種類を選択:** 「自動起動フロー」を選択。
3.  **トリガーを選択:** スケジュール、プラットフォームイベント、レコードの変更など、フローを起動するトリガーを選択。
4.  **要素を配置:** アクション、決定、ループなどの要素を配置。
5.  **要素を接続:** コネクタを使って要素間を接続し、フローのロジックを定義。
6.  **フローを保存して有効化:** フローに名前を付けて保存し、有効化。

**例：毎日午前 9 時に未完了のタスクをメールで通知するフロー**

- **スケジュールトリガー:** 毎日午前 9 時にフローを実行するように設定。
- **レコードを取得要素:** 未完了のタスクレコードを取得。
- **ループ要素:** 取得したタスクレコードをループ処理。
- **メール送信要素:** ループ内の各タスクに対してメールを送信。
- **接続:** スケジュールトリガーからレコードを取得要素、ループ要素、メール送信要素へと接続。

**レコードトリガーフローの作成:**

1.  **Flow Builder を開く:** 設定 > フロー > 新規フロー をクリック。
2.  **フローの種類を選択:** 「レコードトリガーフロー」を選択。
3.  **トリガーを設定:** オブジェクト、トリガー条件（作成、更新、削除）、実行タイミング（レコードの保存前または後）を設定。
4.  **要素を配置:** アクション、決定、レコードの更新などの要素を配置。
5.  **要素を接続:** コネクタを使って要素間を接続し、フローのロジックを定義。
6.  **フローを保存して有効化:** フローに名前を付けて保存し、有効化。

**例：商談が成立した場合に、関連する取引先に「顧客」とフラグを立てるフロー**

- **トリガー:** 商談オブジェクト、更新時、成立 (Closed Won) にトリガー。
- **レコードを更新要素:** トリガーとなった商談に関連する取引先のカスタム項目（例：顧客フラグ）を更新。
- **接続:** トリガーからレコードを更新要素へ接続。

#### 7.1.5 実践的なテクニック

- **変数の活用:** データを一時的に保存し、フロー全体で共有するために変数を使用。
- **コレクションの活用:** 複数のレコードをまとめて処理するためにコレクション変数を使用。
- **決定要素の活用:** 条件に基づいてフローを分岐させるために決定要素を使用。
- **ループ要素の活用:** 複数のレコードを繰り返し処理するためにループ要素を使用。
- **エラーハンドリング:** エラーが発生した場合に備えて、エラーハンドリングを設定。

#### 7.1.6 応用例とユースケース

- **営業部門:** リードの自動割り当て、商談の承認プロセス、見積書の自動生成。
- **サービス部門:** ケースのエスカレーション、ナレッジ記事の推奨、顧客満足度調査。
- **マーケティング部門:** キャンペーンの自動化、リードのナーチャリング、セグメントメールの送信。
- **人事部門:** 入社手続きの自動化、従業員のオンボーディング、パフォーマンス評価。

#### 7.1.7 トラブルシューティング

- **フローが正しく実行されない:** デバッグログを確認し、エラーの原因を特定。
- **フローがパフォーマンスに影響を与える:** 不要な処理を削除し、パフォーマンスを最適化。
- **フローが複雑になりすぎた:** サブフローを使用して、フローをモジュール化。

#### 7.1.8 まとめと次のステップ

Flow Builder の基本を理解し、画面フロー、自動起動フロー、レコードトリガーフローを使いこなせるようになりました。次は、より高度なテクニックを習得し、複雑なビジネスプロセスを自動化することを目指しましょう。

### 7.2 高度な Flow テクニック：カスタム Apex アクション、サブフロー、エラーハンドリング

#### 7.2.1 概要と重要性

Flow Builder は強力なツールですが、標準機能だけでは対応できない要件も存在します。カスタム Apex アクションを使用することで、独自のロジックを Flow に組み込むことができ、サブフローを使用することで、複雑なフローをモジュール化し、再利用性を高めることができます。また、エラーハンドリングを適切に行うことで、フローの安定性を向上させ、予期せぬエラーによる中断を防ぐことができます。

#### 7.2.2 特徴と利点

- **カスタム Apex アクション:**
  - 標準機能では実現できない複雑な処理を実装可能。
  - 外部システムとの連携、高度なデータ操作、独自のビジネスロジックなどを実現。
  - Flow の柔軟性を大幅に向上させ、開発者の可能性を広げる。
- **サブフロー:**
  - フローのモジュール化により、複雑なフローを管理しやすくする。
  - 同じロジックを複数のフローで再利用できるため、開発効率を向上させる。
  - フローの可読性を高め、メンテナンスを容易にする。
- **エラーハンドリング:**
  - フローの実行中に発生するエラーを適切に処理し、予期せぬ中断を防ぐ。
  - エラーログを記録し、問題の原因を特定するのに役立つ。
  - ユーザーに適切なエラーメッセージを表示し、操作をガイドする。

#### 7.2.3 事前準備と前提条件

- 7.1 節の内容を理解していること。
- Apex の基本的な知識（カスタム Apex アクションを利用する場合）。
- 開発環境 (Developer Edition) または Sandbox 環境での作業を推奨。

#### 7.2.4 基本的な使い方

**カスタム Apex アクションの作成と利用:**

1.  **Apex クラスの作成:** `InvocableMethod` アノテーションを使用して、Flow から呼び出せるメソッドを定義。

    ```java
    public class MyApexAction {
        @InvocableMethod(label='文字列を大文字に変換' description='入力文字列を大文字に変換します')
        public static List<String> toUpperCase(List<String> inputStrings) {
            List<String> results = new List<String>();
            for (String s : inputStrings) {
                results.add(s.toUpperCase());
            }
            return results;
        }
    }
    ```

2.  **Flow で Apex アクションを呼び出す:** Flow Builder でアクション要素を追加し、Apex アクションを選択。作成した Apex クラスのメソッドが表示されるので選択し、入力パラメータと出力パラメータを定義。

**サブフローの作成と利用:**

1.  **サブフローの作成:** 通常のフローと同様に、サブフローを作成。サブフローは、独立したフローとして保存される。
2.  **メインフローでサブフローを呼び出す:** メインフローでサブフロー要素を追加し、作成したサブフローを選択。サブフローへの入力パラメータとサブフローからの出力パラメータを定義。

**エラーハンドリングの設定:**

1.  **フォルトパスの設定:** フロー要素にエラーが発生した場合に実行されるパス（フォルトパス）を設定。
2.  **エラー処理要素の配置:** フォルトパスにエラーメッセージの表示、エラーログの記録、管理者に通知メールを送信するなどの要素を配置。
3.  **`$Flow.FaultMessage` 変数の利用:** エラーが発生した要素、エラーメッセージなどの情報を取得し、エラー処理に活用。

#### 7.2.5 実践的なテクニック

- **カスタム Apex アクションによる外部システム連携:** Apex を使用して外部 API を呼び出し、Flow で取得したデータを外部システムに送信したり、外部システムからデータを取得したりする。
- **動的なサブフローの呼び出し:** フローの実行時に条件に基づいて異なるサブフローを呼び出す。
- **try-catch ブロックによるエラーハンドリング:** Apex アクション内で try-catch ブロックを使用し、より詳細なエラーハンドリングを行う。
- **カスタム例外の利用:** 特定のエラー条件が発生した場合に、カスタム例外をスローし、Flow で例外をキャッチして処理する。
- **プラットフォームイベントを使った非同期処理:** 時間のかかる処理を非同期で実行するために、プラットフォームイベントをトリガーとする自動起動フローを利用する。カスタム Apex アクションからプラットフォームイベントを発行し、自動起動フローでイベントを処理する。

#### 7.2.6 応用例とユースケース

- **顧客データの暗号化:** 顧客の個人情報を保護するために、カスタム Apex アクションでデータを暗号化し、データベースに保存する。
- **複雑な税計算:** 標準機能では対応できない複雑な税計算を、カスタム Apex アクションで実装し、見積書や請求書に適用する。
- **承認プロセスのカスタマイズ:** 標準の承認プロセスでは対応できない独自の承認ルールを、Flow とカスタム Apex アクションを組み合わせて実現する。
- **外部システムのデータ検証:** 外部システムから取り込んだデータを Flow で検証し、エラーがあった場合は、エラーログを記録し、担当者に通知する。

#### 7.2.7 トラブルシューティング

- **カスタム Apex アクションが正しく動作しない:** Apex クラスのデバッグログを確認し、エラーの原因を特定する。
- **サブフローが正しく呼び出されない:** サブフローの入力パラメータと出力パラメータが正しく定義されているか確認する。
- **エラーハンドリングが機能しない:** フォルトパスが正しく設定されているか、エラー処理要素が正しく設定されているか確認する。
- **`$Flow.FaultMessage` が空:** エラーが発生した要素が `$Flow.FaultMessage` に対応しているか確認する。対応していない場合は、別の方法でエラー情報を取得する必要がある。

#### 7.2.8 まとめと次のステップ

カスタム Apex アクション、サブフロー、エラーハンドリングを習得することで、Flow Builder の可能性をさらに広げることができました。次は、より高度な設計原則とパフォーマンス最適化について学び、より効率的で安定した Flow を構築することを目指しましょう。

### 7.3 Flow ベストプラクティス：設計原則とパフォーマンス最適化

#### 7.3.1 概要と重要性

Flow Builder を効果的に活用するためには、適切な設計原則に従い、パフォーマンスを最適化することが不可欠です。設計原則を無視すると、フローが複雑になりすぎ、メンテナンスが困難になる可能性があります。また、パフォーマンスが低いと、ユーザーエクスペリエンスが低下し、業務効率にも悪影響を及ぼします。

#### 7.3.2 特徴と利点

- **明確な設計原則:**
  - フローの構造をシンプルにし、可読性を高める。
  - フローの再利用性を高め、開発効率を向上させる。
  - フローのメンテナンスを容易にする。
- **パフォーマンス最適化:**
  - フローの実行時間を短縮し、ユーザーエクスペリエンスを向上させる。
  - システムリソースの消費を抑え、Salesforce 組織全体のパフォーマンスを向上させる。
  - ガバナ制限に抵触するリスクを低減する。

#### 7.3.3 事前準備と前提条件

- 7.1 節、7.2 節の内容を理解していること。
- 設計原則とパフォーマンス最適化の基本的な知識。
- 開発環境 (Developer Edition) または Sandbox 環境での作業を推奨。

#### 7.3.4 設計原則

- **Single Responsibility Principle (SRP):** 各フローは、単一の明確な責任を持つべきです。複数の役割を担うフローは、複雑になりやすく、メンテナンスが困難になります。
- **Don't Repeat Yourself (DRY):** 同じロジックを複数のフローで繰り返さないように、サブフローを活用し、再利用性を高めましょう。
- **Keep It Simple, Stupid (KISS):** フローはできる限りシンプルに保ちましょう。複雑なロジックは、カスタム Apex アクションに委譲することを検討してください。
- **Explicit is better than implicit:** 変数や要素の名前は、その目的を明確に表すように命名しましょう。コメントを適切に追加し、フローのロジックを説明しましょう。
- **Design for Failure:** エラーが発生する可能性を考慮し、エラーハンドリングを適切に設定しましょう。
- **Bulkification:** 大量のレコードを処理する場合、ループ内でレコードを操作するのではなく、Bulkification（一括処理）を意識しましょう。カスタム Apex アクションを作成し、`List<SObject>` を引数として渡すことで、一括処理を実現できます。

#### 7.3.5 パフォーマンス最適化

- **SOQL クエリの最適化:**

  - 必要な項目のみを取得する。
  - インデックスを活用する。
  - SOQL クエリの数を最小限に抑える。
  - `FOR UPDATE` を使用しない（必要な場合を除く）。

- **ループの最適化:**

  - ループ内で SOQL クエリを実行しない。
  - ループ内で DML 操作を実行しない。
  - コレクション変数を使用し、ループの外で DML 操作を実行する。

- **DML 操作の最適化:**

  - Bulk DML 操作を使用する。
  - 不要な DML 操作を避ける。
  - ロック競合を避けるために、DML 操作の実行順序を考慮する。

- **変数の最適化:**

  - 不要な変数を削除する。
  - 変数のスコープを最小限にする。
  - コレクション変数のサイズを制限する。

- ** governor limits:** Salesforce のガバナ制限を超えないように注意する。SOQL クエリ数、DML 操作数、CPU 時間、ヒープサイズなどの制限を確認し、フローの設計に反映する。
- **デバッグログの活用:** デバッグログを有効にして、フローの実行時間やリソース消費量を確認する。パフォーマンスボトルネックを特定し、最適化を行う。

#### 7.3.6 実践的なテクニック

- **SOQL クエリの最適化例:**

  ```java
  // 非効率なSOQLクエリ
  List<Account> accounts = [SELECT Id, Name, Industry, CreatedDate FROM Account WHERE Industry = 'Technology'];

  // 効率的なSOQLクエリ (必要な項目のみを取得)
  List<Account> accounts = [SELECT Id, Name FROM Account WHERE Industry = 'Technology'];
  ```

- **ループの最適化例:**

  ```java
  // 非効率なループ
  List<Contact> contacts = [SELECT Id, AccountId FROM Contact WHERE AccountId IN :accountIds];
  for (Contact c : contacts) {
      Account a = [SELECT Id, Name FROM Account WHERE Id = :c.AccountId]; // ループ内でSOQLクエリ
      // ...
  }

  // 効率的なループ (Mapを使用)
  Map<Id, Account> accountMap = new Map<Id, Account>([SELECT Id, Name FROM Account WHERE Id IN :accountIds]);
  for (Contact c : contacts) {
      Account a = accountMap.get(c.AccountId); // Mapから取得
      // ...
  }
  ```

- **DML 操作の最適化例:**

  ```java
  // 非効率なDML操作 (ループ内で更新)
  List<Account> accountsToUpdate = new List<Account>();
  for (Account a : accounts) {
      a.Description = 'Updated Description';
      update a; // ループ内でDML操作
  }

  // 効率的なDML操作 (一括更新)
  List<Account> accountsToUpdate = new List<Account>();
  for (Account a : accounts) {
      a.Description = 'Updated Description';
      accountsToUpdate.add(a);
  }
  update accountsToUpdate; // 一括更新
  ```

#### 7.3.7 応用例とユースケース

- **大規模データ移行:** 大量のデータを移行する際、Bulk API やカスタム Apex アクションを活用し、パフォーマンスを最適化する。
- **リアルタイムデータ更新:** レコードの変更に基づいてリアルタイムにデータを更新する際、トリガーフローのパフォーマンスを最適化し、システム全体の負荷を軽減する。
- **複雑なビジネスロジック:** 複雑なビジネスロジックを実装する際、フローをモジュール化し、カスタム Apex アクションを活用し、パフォーマンスを最適化する。

#### 7.3.8 トラブルシューティング

- **フローの実行時間が長い:** デバッグログを確認し、パフォーマンスボトルネックを特定する。SOQL クエリ、ループ、DML 操作などを最適化する。
- **ガバナ制限に抵触する:** SOQL クエリ数、DML 操作数、CPU 時間、ヒープサイズなどの制限を確認し、フローの設計を見直す。
- **フローが正しく動作しない:** デバッグログを確認し、エラーの原因を特定する。変数、要素、コネクタなどの設定を確認する。

#### 7.3.9 まとめと次のステップ

Flow の設計原則とパフォーマンス最適化を理解することで、より効率的で安定した Flow を構築できるようになりました。今後は、より複雑なビジネスプロセスを自動化し、Salesforce の可能性を最大限に引き出すことを目指しましょう。また、定期的にフローを見直し、改善を続けることが重要です。
