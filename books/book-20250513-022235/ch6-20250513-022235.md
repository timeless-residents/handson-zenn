## 第 6 章：SOQL と SOSL：データベースを自在に操る

Salesforce のデータは、ビジネスの根幹をなす貴重な情報源です。この章では、SOQL (Salesforce Object Query Language) と SOSL (Salesforce Object Search Language) という 2 つの強力なツールを駆使して、そのデータを効率的に取り出し、活用する方法を学びます。SOQL は、データベースに対する SQL に似たクエリ言語であり、特定の条件に合致するレコードを抽出するために使用されます。一方、SOSL は全文検索に特化した言語で、複数のオブジェクトにまたがるデータ検索を効率的に行うことができます。これらの言語をマスターすることで、Salesforce のデータを自在に操り、より深い洞察を得て、ビジネスを加速させることができます。

### 6.1 SOQL の基本：SELECT、WHERE、ORDER BY、LIMIT

#### 概要と重要性

SOQL は、Salesforce データベースから特定の条件を満たすレコードを効率的に取得するためのクエリ言語です。SQL と似た構文を持ちますが、Salesforce のデータモデルに合わせて最適化されています。レポートの作成、データ移行、API 連携など、Salesforce における様々なデータ操作の基盤となります。SOQL を習得することで、必要な情報をピンポイントで取得し、業務効率を大幅に向上させることができます。

#### 特徴と利点

- **SQL に似た構文:** SQL の知識があれば、比較的容易に習得できます。
- **強力なフィルタリング:** `WHERE`句を使用することで、詳細な条件を指定してレコードを抽出できます。
- **ソート機能:** `ORDER BY`句を使用することで、取得したデータを特定のフィールドでソートできます。
- **レコード数制限:** `LIMIT`句を使用することで、取得するレコード数を制限できます。
- **ガバナ制限対応:** Salesforce のガバナ制限を意識した設計になっているため、大量データに対するクエリも安全に実行できます。

#### 事前準備と前提条件

- Salesforce 組織へのアクセス権が必要です。
- Developer Edition など、開発環境が推奨されます。
- Query Editor (Developer Console または VS Code の Salesforce 拡張機能) などのツールがあると便利です。

#### 基本的な使い方

**1. SELECT:**

取得するフィールドを指定します。

```sql
SELECT Id, Name, AccountId FROM Contact
```

このクエリは、Contact オブジェクトの Id、Name、AccountId のフィールドをすべて取得します。

**2. WHERE:**

検索条件を指定します。

```sql
SELECT Id, Name FROM Account WHERE Industry = 'Technology' AND AnnualRevenue > 1000000
```

このクエリは、Industry が'Technology'であり、AnnualRevenue が 100 万を超える Account オブジェクトを取得します。

**3. ORDER BY:**

取得したデータのソート順を指定します。

```sql
SELECT Id, Name FROM Opportunity ORDER BY CloseDate DESC, Amount ASC
```

このクエリは、Opportunity オブジェクトを CloseDate の降順、Amount の昇順でソートします。`DESC`は降順、`ASC`は昇順を意味します（デフォルトは昇順です）。

**4. LIMIT:**

取得するレコード数を制限します。

```sql
SELECT Id, Name FROM Account LIMIT 10
```

このクエリは、Account オブジェクトを最大 10 件まで取得します。

#### 実践的なテクニック

- **サブクエリ:** 別のクエリの結果を条件として使用できます。

  ```sql
  SELECT Id, Name FROM Contact WHERE AccountId IN (SELECT Id FROM Account WHERE Industry = 'Technology')
  ```

  このクエリは、Industry が'Technology'である Account に関連する Contact オブジェクトを取得します。

- **集計関数:** `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`などの集計関数を使用できます。

  ```sql
  SELECT COUNT(Id), SUM(Amount) FROM Opportunity WHERE StageName = 'Closed Won'
  ```

  このクエリは、StageName が'Closed Won'である Opportunity の件数と Amount の合計を計算します。

- **Relationship Query:** 親オブジェクトや子オブジェクトのフィールドを直接参照できます。

  ```sql
  SELECT Id, Name, Account.Name FROM Contact
  ```

  このクエリは、Contact オブジェクトの Id、Name、および関連する Account オブジェクトの Name を取得します。

- **SOQL for Relationships:** 子オブジェクトに対するクエリ（リレーションシップ名を使用）。

  ```sql
  SELECT Id, Name, (SELECT Id, Subject FROM Cases) FROM Account
  ```

  このクエリは、Account オブジェクトの Id、Name、および関連する Case オブジェクトの Id、Subject を取得します。

#### 応用例とユースケース

- **レポート作成:** 特定の条件を満たすデータを抽出して、レポートを作成します。
- **データ移行:** ある Salesforce 組織から別の Salesforce 組織へデータを移行する際に、SOQL でデータを抽出し、API を通じて移行します。
- **API 連携:** 外部システムから Salesforce のデータを取得するために、SOQL を使用します。
- **カスタムアプリケーション開発:** Apex コードや Lightning Web Components から SOQL を使用し、アプリケーションに必要なデータを取得します。
- **データ品質チェック:** 特定の条件を満たさないレコードを SOQL で抽出し、データ品質を改善します。
  例：
  ```sql
  SELECT Id, Name, Phone, Email FROM Lead WHERE Phone = null OR Email = null
  ```
  このクエリは電話番号またはメールアドレスが空白のリードを抽出します。

#### トラブルシューティング

- **SOQL クエリのガバナ制限:** SOQL クエリの実行には、クエリの複雑さや取得するレコード数に応じてガバナ制限が適用されます。制限を超えないように、クエリを最適化したり、`LIMIT`句を使用したりする必要があります。
- **エラーメッセージの解釈:** SOQL クエリのエラーメッセージは、詳細な情報を提供してくれます。エラーメッセージを注意深く読み、原因を特定して修正することが重要です。
- **パフォーマンスの問題:** 大量のデータを扱う場合、SOQL クエリのパフォーマンスが問題になることがあります。インデックスの使用、フィルタリング条件の最適化、サブクエリの回避など、パフォーマンスを向上させるためのテクニックがあります。
- **SOSL との混同:** SOQL は構造化データに対するクエリ、SOSL は全文検索です。目的によって使い分けましょう。

#### まとめと次のステップ

SOQL は、Salesforce のデータを効果的に活用するための強力なツールです。基本的な構文から実践的なテクニックまで、このセクションで学んだ知識を活かして、SOQL を自在に操り、ビジネスを加速させましょう。次のステップとして、実際に様々なクエリを作成し、実行してみることをお勧めします。また、Salesforce の公式ドキュメントやオンラインコミュニティを活用して、SOQL に関する知識を深めていきましょう。

### 6.2 SOSL の活用：全文検索と効率的なデータ検索

#### 概要と重要性

SOSL は、Salesforce 組織内の複数のオブジェクトにまたがるデータを、全文検索によって効率的に検索するための言語です。SOQL が特定のオブジェクトに対するクエリに特化しているのに対し、SOSL は組織全体を対象とした検索に強みを発揮します。顧客の名前、商品名、契約内容など、あいまいなキーワードから必要な情報を迅速に見つけ出すことができます。

#### 特徴と利点

- **全文検索:** キーワードに基づいて、関連性の高いレコードを検索できます。
- **複数オブジェクト検索:** 複数のオブジェクトを同時に検索できます。
- **高速検索:** 大量のデータに対しても、高速な検索が可能です。
- **DML 操作との連携:** 検索結果に基づいて、DML 操作 (Insert, Update, Delete) を実行できます。

#### 事前準備と前提条件

- Salesforce 組織へのアクセス権が必要です。
- Developer Edition など、開発環境が推奨されます。
- Query Editor (Developer Console または VS Code の Salesforce 拡張機能) などのツールがあると便利です。

#### 基本的な使い方

```sosl
FIND {keyword} IN ALL FIELDS RETURNING Account (Id, Name), Contact (Id, Name, Email)
```

- `FIND {keyword}`: 検索するキーワードを指定します。
- `IN ALL FIELDS`: 全てのフィールドを検索対象とします。特定のフィールドを指定することも可能です (`IN NAME FIELDS`, `IN EMAIL FIELDS`など)。
- `RETURNING`: 検索結果として返すオブジェクトとそのフィールドを指定します。

#### 実践的なテクニック

- **ワイルドカード:** `*` や `?` などのワイルドカードを使用して、あいまいなキーワードを検索できます。

  ```sosl
  FIND {John*} IN ALL FIELDS RETURNING Contact (Id, Name, Email)
  ```

  このクエリは、"John" で始まる名前の Contact オブジェクトを検索します。

- **日付検索:** 特定の日付範囲で検索できます。

  ```sosl
  FIND {CloseDate > LAST_MONTH} IN ALL FIELDS RETURNING Opportunity (Id, Name, CloseDate)
  ```

  このクエリは、過去 1 ヶ月以内にクローズされた Opportunity オブジェクトを検索します。

- **ロケール指定:** 検索対象のロケールを指定することで、より正確な検索結果を得ることができます。

  ```sosl
  FIND {キーワード} IN ALL FIELDS WITH LANGUAGE = 'ja_JP' RETURNING Account (Id, Name)
  ```

- **WITH DATA CATEGORY** : データカテゴリに基づいて検索を絞り込むことができます。これは、ナレッジ記事などの分類に特に役立ちます。
  ```sosl
  FIND {keyword} IN ALL FIELDS RETURNING KnowledgeArticleVersion (Id, Title, Summary) WITH DATA CATEGORY 'Products__c/Electronics__c'
  ```

#### 応用例とユースケース

- **顧客サポート:** 顧客からの問い合わせ内容に基づいて、関連するアカウント、連絡先、ケースなどを検索します。
- **営業活動:** 顧客名、商品名、取引先担当者名などを検索し、営業活動に必要な情報を迅速に収集します。
- **ナレッジ管理:** ナレッジ記事をキーワードで検索し、問題解決を支援します。
- **重複レコードの検出:** 顧客名やメールアドレスなどのキーワードで検索し、重複レコードを検出してマージします。
- **グローバル検索機能の拡張:** 標準のグローバル検索機能を SOSL で拡張し、より高度な検索機能を提供します。

  例：取引先の住所の一部を使って検索する。（標準のグローバル検索では難しいケース）

  ```sosl
  FIND {東京都渋谷区} IN ALL FIELDS RETURNING Account (Id, Name, BillingStreet, BillingCity)
  ```

#### トラブルシューティング

- **SOSL クエリのガバナ制限:** SOSL クエリの実行にも、SOQL と同様にガバナ制限が適用されます。制限を超えないように、検索範囲を絞ったり、`LIMIT`句を使用したりする必要があります。
- **検索結果が期待どおりにならない場合:** キーワードのスペルミス、検索対象フィールドの指定ミス、データのインデックス不足などが原因として考えられます。キーワードを修正したり、検索対象フィールドを再検討したり、Salesforce のサポートに問い合わせたりして、原因を特定し、解決策を見つけましょう。
- **パフォーマンスの問題:** 大量のデータを扱う場合、SOSL クエリのパフォーマンスが問題になることがあります。検索範囲を絞ったり、インデックスの使用を検討したり、キャッシュを活用したりすることで、パフォーマンスを向上させることができます。
- **セキュリティ:** 検索結果に機密情報が含まれる可能性があるため、アクセス権限を適切に設定する必要があります。

#### まとめと次のステップ

SOSL は、Salesforce 組織内のデータを効率的に検索するための強力なツールです。全文検索の基本から実践的なテクニックまで、このセクションで学んだ知識を活かして、SOSL を自在に操り、ビジネスを加速させましょう。次のステップとして、実際に様々な検索クエリを作成し、実行してみることをお勧めします。また、Salesforce の公式ドキュメントやオンラインコミュニティを活用して、SOSL に関する知識を深めていきましょう。特に、SOSL Developer Guide は非常に役立ちます。

### 6.3 大規模データセットのクエリ：パフォーマンス最適化

#### 概要と重要性

Salesforce 組織に蓄積されるデータ量が増加するにつれて、SOQL クエリのパフォーマンスが重要な課題となります。大規模なデータセットに対する非効率なクエリは、実行時間の増加、ガバナ制限の超過、そして最終的にはアプリケーションのパフォーマンス低下につながる可能性があります。このセクションでは、大規模データセットに対する SOQL クエリのパフォーマンスを最適化するためのテクニックについて解説します。

#### 特徴と利点

- **クエリ実行時間の短縮:** パフォーマンス最適化により、クエリの実行時間を大幅に短縮できます。
- **ガバナ制限の回避:** 効率的なクエリは、ガバナ制限を超過するリスクを軽減します。
- **アプリケーションのパフォーマンス向上:** 高速なクエリは、アプリケーション全体のパフォーマンスを向上させます。
- **スケーラビリティの向上:** 大規模データセットに対応できるクエリは、組織のスケーラビリティを向上させます。

#### 事前準備と前提条件

- Salesforce 組織へのアクセス権が必要です。
- Developer Edition など、開発環境が推奨されます。
- 大規模なデータセットを持つ Salesforce 組織 (Sandbox 環境など) があると、パフォーマンスの違いを実感できます。
- Query Plan ツール (Developer Console の Query Plan) を利用できる環境が望ましいです。

#### 基本的な考え方

SOQL クエリのパフォーマンスを最適化するには、以下の基本的な考え方を理解しておくことが重要です。

1.  **インデックスの活用:** インデックスは、データベース内のデータを高速に検索するための仕組みです。SOQL クエリでは、インデックスが適切に使用されるように、クエリを記述する必要があります。
2.  **フィルタリング条件の最適化:** フィルタリング条件 (`WHERE`句) は、クエリのパフォーマンスに大きな影響を与えます。インデックスが使用されるように、適切な条件を指定する必要があります。
3.  **不要なデータの取得を避ける:** クエリで取得するフィールドは、必要最小限に絞り込む必要があります。不要なフィールドを取得すると、クエリの実行時間が増加します。
4.  **ガバナ制限を意識する:** SOQL クエリの実行には、様々なガバナ制限が適用されます。制限を超えないように、クエリを最適化する必要があります。
5.  **SOQL Query Optimizer (Query Plan) を活用する:** Salesforce は、SOQL クエリの実行計画を分析するためのツールを提供しています。このツールを活用することで、クエリのボトルネックを特定し、改善することができます。

#### 実践的なテクニック

- **インデックス付きのフィールドを使用:** `WHERE`句で使用するフィールドには、インデックスが付いていることを確認します。標準のインデックスだけでなく、カスタムインデックスも利用できます。

  ```sql
  SELECT Id, Name FROM Account WHERE Industry = 'Technology'
  ```

  この例では、Industry フィールドにインデックスが付いている場合、クエリのパフォーマンスが向上します。Salesforce に問い合わせて、どのフィールドにインデックスが設定されているか確認しましょう。

- **選択リストフィールドの使用を避ける:** 選択リストフィールドは、インデックスが効率的に使用されない場合があります。可能であれば、他のフィールドを使用してフィルタリング条件を指定します。

- **複合インデックスの活用:** 複数のフィールドを組み合わせた複合インデックスを使用することで、より効率的な検索が可能です。

  ```sql
  SELECT Id, Name FROM Account WHERE Industry = 'Technology' AND AnnualRevenue > 1000000
  ```

  この例では、Industry と AnnualRevenue の複合インデックスを作成することで、クエリのパフォーマンスが向上します。

- **NOT EQUAL (!=, <>) や NOT LIKE の使用を避ける:** これらの演算子は、インデックスを使用しないため、パフォーマンスが低下する可能性があります。可能であれば、他の演算子を使用して条件を書き換えます。

- **リストのサイズを最適化する:** `IN` 演算子を使用する場合、リストのサイズをできるだけ小さくします。リストのサイズが大きい場合、パフォーマンスが低下する可能性があります。

- **SOQL For Loops:** 大量のレコードを処理する場合、SOQL For Loops を使用することで、ガバナ制限を超過するリスクを軽減できます。

  ```apex
  for (Account acc : [SELECT Id, Name FROM Account WHERE Industry = 'Technology']) {
      // 処理
  }
  ```

- **Query Plan の活用:** Developer Console の Query Plan を利用して、クエリの実行計画を確認し、ボトルネックを特定します。Query Plan は、インデックスが使用されているかどうか、どのフィールドがボトルネックになっているかなどの情報を提供してくれます。

  - **Full Table Scan を避ける:** Query Plan で Full Table Scan が表示されている場合は、インデックスが使用されていません。インデックス付きのフィールドを使用するようにクエリを修正する必要があります。
  - **Filter Factors を確認する:** Filter Factors は、クエリによって絞り込まれるレコードの割合を示します。Filter Factors が低いほど、クエリのパフォーマンスが向上します。

- **Bulk API の利用:** 大量のデータを処理する場合、SOQL クエリではなく、Bulk API を使用することを検討します。Bulk API は、非同期で大量のデータを処理するための API であり、SOQL クエリよりも効率的にデータを処理できます。

#### 応用例とユースケース

- **大規模な取引先データのレポート作成:** 数百万件の取引先データから、特定の条件を満たすデータを抽出してレポートを作成する場合、パフォーマンス最適化が不可欠です。
- **顧客サポートシステムの検索機能の改善:** 顧客からの問い合わせ内容に基づいて、関連する情報を検索する際、高速な検索機能が求められます。
- **データ移行プロジェクトにおけるデータ抽出:** 大量のデータを別のシステムに移行する際、効率的なデータ抽出が必要となります。

#### トラブルシューティング

- **クエリがタイムアウトする場合:** クエリの複雑さ、データ量、インデックスの不足などが原因として考えられます。クエリを簡素化したり、インデックスを追加したり、`LIMIT`句を使用したりして、タイムアウトを回避します。
- **ガバナ制限に違反する場合:** クエリの複雑さ、取得するレコード数、実行回数などが原因として考えられます。クエリを最適化したり、SOQL For Loops を使用したり、Bulk API を使用したりして、ガバナ制限違反を回避します。
- **パフォーマンスが改善しない場合:** クエリプランを詳細に分析し、ボトルネックとなっている箇所を特定します。必要に応じて、Salesforce のサポートに問い合わせて、専門家のアドバイスを求めることも検討しましょう。

#### まとめと次のステップ

大規模データセットに対する SOQL クエリのパフォーマンス最適化は、Salesforce アプリケーションのパフォーマンスとスケーラビリティを向上させるために不可欠です。インデックスの活用、フィルタリング条件の最適化、Query Plan の分析など、このセクションで学んだテクニックを実践することで、より効率的なクエリを記述し、ビジネスを加速させることができます。次のステップとして、実際の Salesforce 組織でクエリを実行し、パフォーマンスを計測してみることをお勧めします。また、Salesforce の公式ドキュメントやオンラインコミュニティを活用して、パフォーマンス最適化に関する知識を深めていきましょう。
