# 第2章：Webpackセットアップ：開発環境構築のファーストステップ

この章では、Webpack を使用した開発環境構築の最初のステップを解説します。Webpack は現代のフロントエンド開発において不可欠なツールであり、JavaScript、CSS、画像などのアセットを効率的にバンドルし、最適化するために使用されます。この章では、プロジェクトの初期化から開発サーバーのセットアップ、そして簡単なアプリケーションのバンドルまで、具体的な手順を解説します。

### 2.1 プロジェクトの初期化：npm/yarnを使ったプロジェクト作成

#### 1. 概要と重要性

プロジェクトの初期化は、開発の基礎となる部分です。`npm` または `yarn` を使用してプロジェクトを作成し、必要なパッケージを管理するための基盤を築きます。これにより、プロジェクトの依存関係を明確にし、バージョン管理を容易にすることで、開発の安定性と再現性を高めます。

#### 2. 基本的な使い方

まず、プロジェクトを作成するディレクトリを作成し、そのディレクトリに移動します。

```bash
mkdir webpack-project
cd webpack-project
```

次に、`npm` または `yarn` を使用してプロジェクトを初期化します。

**npm の場合:**

```bash
npm init -y
```

**yarn の場合:**

```bash
yarn init -y
```

`-y` オプションは、質問をすべてデフォルトで回答し、`package.json` を自動生成します。

#### 3. 実践的なテクニック

`package.json` は、プロジェクトに関するメタデータと依存関係を記述する重要なファイルです。初期化後、`package.json` を確認し、プロジェクト名、バージョン、説明などを必要に応じて編集します。

```json
{
  "name": "webpack-project",
  "version": "1.0.0",
  "description": "My first Webpack project",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "Your Name",
  "license": "ISC"
}
```

#### 4. 応用例とユースケース

実務では、Git リポジトリと連携してプロジェクトを管理することが一般的です。`.gitignore` ファイルを作成し、`node_modules` ディレクトリなど、バージョン管理から除外すべきファイルを指定します。

```
node_modules/
dist/
```

#### 5. トラブルシューティング

*   **`npm init` または `yarn init` が実行できない場合:** Node.js と npm または yarn が正しくインストールされているか確認してください。
*   **`package.json` が生成されない場合:**  パーミッションの問題や、すでに同名のファイルが存在する可能性があります。

#### 6. まとめと次のステップ

これで、プロジェクトの初期化が完了しました。次のステップでは、Webpack をインストールします。

### 2.2 Webpackのインストール：ローカルインストールとグローバルインストール

#### 1. 概要と重要性

Webpack は、プロジェクトの依存関係を解決し、アセットをバンドルするためのツールです。ローカルインストールとグローバルインストールの選択肢がありますが、通常はローカルインストールを推奨します。

#### 2. 基本的な使い方

**ローカルインストール:**

ローカルインストールは、プロジェクトごとに特定のバージョンの Webpack を使用するために推奨される方法です。

```bash
npm install webpack webpack-cli --save-dev
# または
yarn add webpack webpack-cli --dev
```

`--save-dev` または `--dev` オプションは、Webpack を開発依存関係としてインストールすることを意味します。これにより、本番環境には不要な開発ツールが分離されます。

**グローバルインストール:**

```bash
npm install -g webpack webpack-cli
# または
yarn global add webpack webpack-cli
```

グローバルインストールは、システム全体で同じバージョンの Webpack を使用する場合に便利ですが、プロジェクトごとに異なるバージョンを使用する必要がある場合には問題が発生する可能性があります。

#### 3. 実践的なテクニック

ローカルインストールされた Webpack は、`node_modules/.bin` ディレクトリに格納されます。`package.json` の `scripts` セクションにコマンドを追加することで、簡単に実行できます。

```json
{
  "scripts": {
    "build": "webpack"
  }
}
```

これにより、`npm run build` または `yarn build` コマンドを実行することで、Webpack を実行できます。

#### 4. 応用例とユースケース

チームで開発を行う場合、ローカルインストールされた Webpack を使用することで、メンバー間で同じバージョンの Webpack を共有できます。これにより、環境の違いによる問題を回避できます。

#### 5. トラブルシューティング

*   **`webpack` コマンドが見つからない場合:** ローカルインストールされている場合は、`node_modules/.bin` ディレクトリが PATH 環境変数に追加されているか確認してください。通常は、`npm run` または `yarn` を使用して実行することで、自動的に解決されます。
*   **グローバルインストールされた Webpack が期待通りに動作しない場合:** ローカルインストールされた Webpack と競合している可能性があります。グローバルインストールされた Webpack をアンインストールし、ローカルインストールを使用することを検討してください。

#### 6. まとめと次のステップ

Webpack のインストールが完了しました。次のステップでは、Webpack の設定ファイルを作成します。

### 2.3 Webpack設定ファイルの作成：`webpack.config.js` の基本構造

#### 1. 概要と重要性

`webpack.config.js` は、Webpack の動作をカスタマイズするための設定ファイルです。エントリーポイント、出力設定、ローダー、プラグインなどを定義します。

#### 2. 基本的な使い方

プロジェクトのルートディレクトリに `webpack.config.js` ファイルを作成します。

```javascript
// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  mode: 'development' // または 'production'
};
```

*   `entry`: バンドルのエントリーポイントとなるファイルを指定します。
*   `output`: バンドルされたファイルの出力先とファイル名を指定します。
*   `mode`: Webpack の動作モードを指定します。`development` は開発環境向け、`production` は本番環境向けの設定を行います。

#### 3. 実践的なテクニック

Webpack は、様々なローダーとプラグインをサポートしています。ローダーは、JavaScript 以外のファイル（CSS、画像など）を JavaScript に変換するために使用されます。プラグインは、バンドルの最適化や環境変数の設定など、様々なタスクを実行するために使用されます。

例えば、CSS ファイルをバンドルするために、`css-loader` と `style-loader` を使用できます。

```bash
npm install css-loader style-loader --save-dev
# または
yarn add css-loader style-loader --dev
```

`webpack.config.js` を次のように変更します。

```javascript
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
  mode: 'development'
};
```

*   `module.rules`: ファイルの種類に応じて適用するローダーを定義します。`test` は、適用するファイルの種類を正規表現で指定します。`use` は、適用するローダーを配列で指定します。

#### 4. 応用例とユースケース

React プロジェクトの場合、Babel を使用して JSX を JavaScript に変換する必要があります。`@babel/core`、`@babel/preset-env`、`@babel/preset-react`、`babel-loader` をインストールします。

```bash
npm install @babel/core @babel/preset-env @babel/preset-react babel-loader --save-dev
# または
yarn add @babel/core @babel/preset-env @babel/preset-react babel-loader --dev
```

`webpack.config.js` を次のように変更します。

```javascript
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env', '@babel/preset-react'],
          },
        },
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
  mode: 'development'
};
```

#### 5. トラブルシューティング

*   **`webpack` コマンドを実行しても何も起こらない場合:** `webpack.config.js` の設定が正しいか確認してください。特に、エントリーポイントと出力設定が正しいか確認してください。
*   **ローダーが正しく動作しない場合:** ローダーのインストールと設定が正しいか確認してください。`module.rules` の `test` と `use` が正しいか確認してください。
*   **"Module not found" エラーが発生する場合:**  モジュールが正しくインストールされているか、パスが間違っていないか確認してください。

#### 6. まとめと次のステップ

`webpack.config.js` の作成が完了しました。次のステップでは、開発サーバーを導入します。

### 2.4 開発サーバーの導入：webpack-dev-serverの設定

#### 1. 概要と重要性

`webpack-dev-server` は、開発中にリアルタイムでコードの変更を反映させるための開発サーバーです。コードを保存すると自動的にリロードされるため、開発効率が大幅に向上します。

#### 2. 基本的な使い方

`webpack-dev-server` をインストールします。

```bash
npm install webpack-dev-server --save-dev
# または
yarn add webpack-dev-server --dev
```

`package.json` の `scripts` セクションに、開発サーバーを起動するためのコマンドを追加します。

```json
{
  "scripts": {
    "build": "webpack",
    "start": "webpack-dev-server --mode development --open"
  }
}
```

`--open` オプションは、開発サーバーを起動すると自動的にブラウザで開くことを意味します。

#### 3. 実践的なテクニック

`webpack-dev-server` は、様々なオプションをサポートしています。例えば、ポート番号を変更したり、Hot Module Replacement (HMR) を有効にしたりすることができます。

`webpack.config.js` に `devServer` オプションを追加します。

```javascript
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env', '@babel/preset-react'],
          },
        },
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
  mode: 'development',
  devServer: {
    port: 3000, // ポート番号を変更
    hot: true, // HMR を有効化
    static: { // 静的ファイルを提供するディレクトリを指定
      directory: path.join(__dirname, 'public'),
    },
  },
};
```

*   `port`: 開発サーバーのポート番号を指定します。
*   `hot`: Hot Module Replacement (HMR) を有効化します。HMR は、アプリケーション全体をリロードせずに、変更されたモジュールだけを更新する機能です。
*   `static`: 静的ファイルを提供するディレクトリを指定します。

#### 4. 応用例とユースケース

API エンドポイントをモックするために、`devServer` の `proxy` オプションを使用できます。

```javascript
devServer: {
  port: 3000,
  hot: true,
  proxy: {
    '/api': 'http://localhost:8080', // /api へのリクエストを localhost:8080 にプロキシ
  },
},
```

#### 5. トラブルシューティング

*   **開発サーバーが起動しない場合:** ポート番号が他のプロセスで使用されていないか確認してください。
*   **HMR が動作しない場合:** HMR を有効にするための設定が正しいか確認してください。アプリケーションのコードも HMR に対応している必要があります。
*   **"Cannot GET /" エラーが発生する場合:** `devServer` の `static` オプションが正しく設定されているか確認してください。`index.html` ファイルが静的ファイルを提供するディレクトリに存在するか確認してください。

#### 6. まとめと次のステップ

開発サーバーの導入が完了しました。次のステップでは、簡単な JavaScript アプリケーションをバンドルして表示します。

### 2.5 動作確認：簡単なJavaScriptアプリケーションをバンドルして表示

#### 1. 概要と重要性

Webpack の設定が正しく行われているかを検証するために、簡単な JavaScript アプリケーションを作成し、バンドルして表示します。

#### 2. 基本的な使い方

`src` ディレクトリに `index.js` ファイルを作成します。

```javascript
// src/index.js
import './style.css'; // CSS ファイルをインポート

const element = document.createElement('h1');
element.textContent = 'Hello, Webpack!';
document.body.appendChild(element);
```

`src` ディレクトリに `style.css` ファイルを作成します。

```css
/* src/style.css */
body {
  background-color: #f0f0f0;
  text-align: center;
  padding: 20px;
}

h1 {
  color: blue;
}
```

`public` ディレクトリに `index.html` ファイルを作成します。

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8">
    <title>Webpack Example</title>
  </head>
  <body>
    <script src="bundle.js"></script>
  </body>
</html>
```

`npm run build` または `yarn build` コマンドを実行して、`bundle.js` ファイルを生成します。

`npm start` または `yarn start` コマンドを実行して、開発サーバーを起動し、ブラウザで `index.html` を開きます。

#### 3. 実践的なテクニック

Webpack は、`html-webpack-plugin` を使用して、自動的に `index.html` ファイルを生成し、バンドルされた JavaScript ファイルを挿入することができます。

```bash
npm install html-webpack-plugin --save-dev
# または
yarn add html-webpack-plugin --dev
```

`webpack.config.js` を次のように変更します。

```javascript
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env', '@babel/preset-react'],
          },
        },
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
  mode: 'development',
  devServer: {
    port: 3000,
    hot: true,
    static: {
      directory: path.join(__dirname, 'public'),
    },
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './public/index.html', // テンプレートとなる HTML ファイル
    }),
  ],
};
```

#### 4. 応用例とユースケース

複数のエントリーポイントと出力設定を持つアプリケーションを構築する場合、`webpack.config.js` を適切に設定する必要があります。

#### 5. トラブルシューティング

*   **ブラウザに何も表示されない場合:** `bundle.js` が正しく生成されているか、`index.html` から `bundle.js` が正しく参照されているか確認してください。
*   **CSS が適用されない場合:** `css-loader` と `style-loader` が正しく設定されているか確認してください。`import './style.css'` が `index.js` に記述されているか確認してください。
*   **JavaScript エラーが発生する場合:** ブラウザのコンソールでエラーメッセージを確認し、コードを修正してください。

簡単な JavaScript アプリケーションをバンドルして表示することができました。次のステップでは、よくあるエラーとその解決策について学びます。

### 2.6 トラブルシューティング：よくあるエラーと解決策

#### 1. 概要と重要性

Webpack を使用していると、様々なエラーに遭遇する可能性があります。これらのエラーを解決するための知識は、スムーズな開発のために不可欠です。

#### 2. よくあるエラーとその解決策

*   **"Module not found" エラー:**
    *   **原因:** モジュールがインストールされていないか、パスが間違っている。
    *   **解決策:** `npm install` または `yarn add` コマンドを実行して、モジュールをインストールする。パスが正しいか確認する。
*   **"Cannot GET /" エラー:**
    *   **原因:** 開発サーバーの設定が正しくない。`index.html` ファイルが提供されていない。
    *   **解決策:** `devServer` の `static` オプションが正しく設定されているか確認する。`index.html` ファイルが静的ファイルを提供するディレクトリに存在するか確認する。
*   **ローダーが正しく動作しない:**
    *   **原因:** ローダーのインストールまたは設定が正しくない。
    *   **解決策:** ローダーが正しくインストールされているか確認する。`webpack.config.js` の `module.rules` の `test` と `use` が正しいか確認する。
*   **JavaScript エラーが発生する:**
    *   **原因:** コードにエラーがある。
    *   **解決策:** ブラウザのコンソールでエラーメッセージを確認し、コードを修正する。
*   **Webpack のバージョンに関するエラー:**
    *   **原因:** プロジェクトの依存関係と Webpack のバージョンが互換性がない。
    *   **解決策:** `package.json` で Webpack と関連パッケージのバージョンを確認し、互換性のあるバージョンに更新する。

#### 3. 実践的なテクニック

エラーメッセージをよく読み、原因を特定することが重要です。エラーメッセージには、エラーが発生したファイル名、行番号、エラーの種類などが含まれています。

#### 4. 応用例とユースケース

Stack Overflow や GitHub Issues などのコミュニティで、同じようなエラーが発生している人がいないか検索してみるのも有効です。

#### 5. まとめと次のステップ

この章では、Webpack の基本的なセットアップ方法と、よくあるエラーとその解決策について学びました。次のステップでは、より高度な Webpack の機能について学びます。
