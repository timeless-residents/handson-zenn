## 付録

### 付録A：Webpack設定ファイルのサンプル集

#### 1. 概要と重要性

Webpackの設定ファイルは、プロジェクトのビルドプロセスを定義する中心的な要素です。様々な設定オプションを組み合わせることで、JavaScript、CSS、画像、フォントなど、あらゆるアセットを効率的にバンドルできます。この付録では、さまざまなユースケースに対応できるWebpack設定ファイルのサンプルを提供し、設定の理解を深め、プロジェクトへの適用を容易にすることを目的とします。

#### 2. 基本的な使い方

Webpackの設定ファイルは通常`webpack.config.js`という名前でプロジェクトのルートディレクトリに配置されます。基本的な構造は以下の通りです。

```javascript
const path = require('path');

module.exports = {
  entry: './src/index.js', // エントリーポイント
  output: {
    path: path.resolve(__dirname, 'dist'), // 出力ディレクトリ
    filename: 'bundle.js' // 出力ファイル名
  },
  mode: 'development', // モード (development, production, none)
};
```

*   **`entry`**: バンドルの起点となるJavaScriptファイル。
*   **`output`**: バンドルされたファイルの出力先とファイル名を指定。`path`は絶対パスで指定する必要がある。
*   **`mode`**: Webpackの動作モード。`development`は開発用、`production`は本番環境用、`none`は最適化を行わない。

#### 3. 実践的なテクニック

**3.1 Babelの設定:** ES6+のコードを古いブラウザでも動作するように変換するには、Babelローダーを使用します。

```javascript
module.exports = {
  // ... (entry, output, mode)
  module: {
    rules: [
      {
        test: /\.js$/, // .jsファイルに適用
        exclude: /node_modules/, // node_modulesを除外
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env'] // Babelプリセット
          }
        }
      }
    ]
  }
};
```

*   `@babel/preset-env`: 最新のJavaScript構文を、ターゲットブラウザに合わせて自動的に変換します。

**3.2 CSSのバンドル:** CSSファイルをJavaScriptにバンドルするには、`style-loader`と`css-loader`を使用します。

```javascript
module.exports = {
  // ... (entry, output, mode, module)
  module: {
    rules: [
      // ... (babel-loader)
      {
        test: /\.css$/, // .cssファイルに適用
        use: [
          'style-loader', // スタイルをDOMに挿入
          'css-loader' // CSSファイルを読み込み
        ]
      }
    ]
  }
};
```

**3.3 Sass/SCSSのバンドル:** Sass/SCSSファイルをバンドルするには、`sass-loader`を追加します。

```javascript
module.exports = {
  // ... (entry, output, mode, module)
  module: {
    rules: [
      // ... (babel-loader, css-loader)
      {
        test: /\.s[ac]ss$/i, // .scssまたは.sassファイルに適用
        use: [
          "style-loader",
          "css-loader",
          "sass-loader",
        ],
      },
    ]
  }
};
```

**3.4 画像ファイルの処理:** 画像ファイルをバンドルするには、`file-loader`または`url-loader`を使用します。

```javascript
module.exports = {
  // ... (entry, output, mode, module)
  module: {
    rules: [
      // ... (babel-loader, css-loader, sass-loader)
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: 'asset/resource',
      },
    ]
  }
};
```

*   `type: 'asset/resource'`：画像ファイルを出力ディレクトリにコピーし、URLを生成します。`asset/inline`を指定すると、Data URLとして埋め込むことができます。
*   `url-loader`は、指定されたサイズ以下の画像をData URLとして埋め込み、それ以上のサイズの場合は`file-loader`のようにファイルをコピーします。

#### 4. 応用例とユースケース

**4.1 複数のエントリーポイント:** 複数のJavaScriptファイルをそれぞれバンドルする場合。

```javascript
module.exports = {
  entry: {
    main: './src/index.js',
    another: './src/another.js'
  },
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].bundle.js' // [name]はエントリーポイント名に置き換えられる
  },
  // ...
};
```

**4.2 コード分割:** 大規模なアプリケーションで、初期ロード時間を短縮するために、コードを分割します。

```javascript
module.exports = {
  // ... (entry, output, mode, module)
  optimization: {
    splitChunks: {
      chunks: 'all', // すべてのチャンクを分割
    },
  },
};
```

**4.3 環境変数の利用:** 環境変数に応じて設定を変更します。

```javascript
const webpack = require('webpack');

module.exports = (env) => {
  return {
    // ... (entry, output, mode, module)
    plugins: [
      new webpack.DefinePlugin({
        'process.env.NODE_ENV': JSON.stringify(env.NODE_ENV || 'development')
      })
    ]
  };
};
```

*   コマンドラインで`webpack --env NODE_ENV=production`のように指定できます。

#### 5. トラブルシューティング

*   **エラー:** "Module not found: Error: Can't resolve '...' in '...'": 指定されたモジュールが見つからない。`npm install`で必要なパッケージがインストールされているか確認。
*   **エラー:** "Invalid configuration object. Webpack has been initialised using a configuration object that does not match the API schema.": 設定ファイルに誤りがある。設定ファイルの構文やオプションが正しいか確認。Webpackのバージョンと設定オプションが一致しているかも確認。
*   **パフォーマンス:** ビルドが遅い。`mode: 'production'`でビルドを行う、または`webpack-bundle-analyzer`でボトルネックを特定し最適化を行う。

#### 6. まとめと次のステップ

このセクションでは、Webpackの設定ファイルの基本から応用までを幅広くカバーしました。今後は、Webpackのドキュメントやコミュニティの情報を参考に、さらに高度な設定やカスタマイズに挑戦してみてください。

### 付録B：Webpack関連ツールとライブラリ

#### 1. 概要と重要性

Webpackは強力なモジュールバンドラーですが、その機能を拡張し、開発ワークフローを効率化するためのツールやライブラリが多数存在します。この付録では、特に役立つWebpack関連ツールとライブラリを紹介します。

#### 2. 基本的な使い方

これらのツールやライブラリは、通常`npm install`でインストールし、Webpackの設定ファイルで設定または使用します。

#### 3. 実践的なテクニック

**3.1 webpack-dev-server:** リアルタイムリロード機能を備えた開発サーバー。

```javascript
// webpack.config.js
module.exports = {
  // ...
  devServer: {
    static: './dist', // 静的ファイルの提供元
    hot: true, // ホットリロードを有効化
  },
};
```

```bash
npm install webpack-dev-server --save-dev
```

*   `webpack serve`コマンドで起動します。`hot: true`を設定すると、コード変更時にブラウザが自動的にリロードされます。

**3.2 webpack-bundle-analyzer:** バンドルサイズの分析ツール。

```javascript
// webpack.config.js
const BundleAnalyzerPlugin = require('webpack-bundle-analyzer').BundleAnalyzerPlugin;

module.exports = {
  // ...
  plugins: [
    new BundleAnalyzerPlugin()
  ]
};
```

```bash
npm install webpack-bundle-analyzer --save-dev
```

*   ビルド時にバンドルサイズのレポートを生成し、どのモジュールがバンドルサイズに影響を与えているかを視覚的に確認できます。

**3.3 html-webpack-plugin:** HTMLファイルを自動生成し、バンドルされたJavaScriptファイルを自動的に挿入するプラグイン。

```javascript
// webpack.config.js
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // ...
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html' // テンプレートファイル
    })
  ]
};
```

```bash
npm install html-webpack-plugin --save-dev
```

*   バンドルされたJavaScriptファイルのパスをHTMLファイルに手動で記述する必要がなくなります。

**3.4 mini-css-extract-plugin:** CSSを別ファイルとして抽出するプラグイン。

```javascript
// webpack.config.js
const MiniCssExtractPlugin = require("mini-css-extract-plugin");

module.exports = {
  // ...
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [MiniCssExtractPlugin.loader, "css-loader"],
      },
    ],
  },
  plugins: [new MiniCssExtractPlugin()],
};
```

```bash
npm install mini-css-extract-plugin --save-dev
```

*   CSSが別ファイルとして抽出されるため、ブラウザでのキャッシュが有効になり、パフォーマンスが向上します。

**3.5 clean-webpack-plugin:** ビルド前に出力ディレクトリをクリーンアップするプラグイン。

```javascript
// webpack.config.js
const { CleanWebpackPlugin } = require('clean-webpack-plugin');

module.exports = {
  // ...
  plugins: [
    new CleanWebpackPlugin(),
  ],
};
```

```bash
npm install clean-webpack-plugin --save-dev
```

*   以前のビルドで生成された不要なファイルを削除し、出力ディレクトリを常に最新の状態に保ちます。

#### 4. 応用例とユースケース

*   **webpack-merge:** 開発環境用と本番環境用の設定ファイルをマージする。
*   **copy-webpack-plugin:** 静的ファイルをコピーする。
*   **terser-webpack-plugin:** JavaScriptコードを最適化（minify）する。

#### 5. トラブルシューティング

*   プラグインのバージョンがWebpackのバージョンと互換性がない場合、エラーが発生することがあります。パッケージのバージョンを確認し、必要に応じてアップデートまたはダウングレードしてください。
*   設定ファイルの記述ミスや、必要なパッケージがインストールされていない場合も、エラーの原因となります。エラーメッセージをよく読み、問題を特定してください。

#### 6. まとめと次のステップ

Webpack関連ツールとライブラリを活用することで、開発効率を大幅に向上させることができます。それぞれのツールやライブラリのドキュメントをよく読み、プロジェクトに最適な組み合わせを見つけてください。
