## 第 7 章: AI エージェントの計画と実行 - タスク自動化

AI エージェントが持つ可能性を最大限に引き出すためには、計画的な行動と効率的なタスク実行が不可欠です。本章では、AI エージェントが複雑なタスクを自動化するための計画立案、実行、そして複数エージェント間の連携について、具体的な例を交えながら解説します。

### 7.1. 行動計画の基本 - ゴール指向プランニング

#### 7.1.1. 概要と重要性

ゴール指向プランニングとは、AI エージェントが特定の目標を達成するために、一連の行動計画を自動的に生成する技術です。これは、人間が問題を解決する際に手順を考えるプロセスに似ており、AI エージェントが自律的に複雑なタスクをこなすための基盤となります。

なぜ重要なのでしょうか？ 従来の手法では、開発者がタスクごとに詳細な手順をプログラムする必要がありましたが、ゴール指向プランニングを用いることで、エージェントは自ら状況を分析し、最適な行動計画を導き出すことができます。これにより、変化する環境への適応性が向上し、より複雑なタスクの自動化が可能になります。

#### 7.1.2. 特徴と利点

- **柔軟性:** ゴール指向プランニングは、環境の変化や新しい目標に対して柔軟に対応できます。
- **自律性:** エージェントは、事前に定義されたルールだけでなく、自らの判断で行動を選択できます。
- **効率性:** 計画段階で最適な行動経路を探索するため、無駄な行動を減らすことができます。
- **説明可能性:** 生成された計画は人間が理解しやすい形式で表現できるため、エージェントの行動理由を把握できます。

#### 7.1.3. 事前準備と前提条件

ゴール指向プランニングを実装するためには、以下の準備が必要です。

1.  **ドメイン知識の定義:** エージェントが行動する世界のルール（例えば、移動可能な場所、操作可能なオブジェクトなど）を定義する必要があります。これは、特定の形式（PDDL など）で記述されます。
2.  **初期状態の定義:** エージェントがタスクを開始する時点の状態（例えば、エージェントの初期位置、オブジェクトの状態など）を定義します。
3.  **目標状態の定義:** エージェントが達成すべき状態（例えば、特定の場所に到達、特定のオブジェクトを操作など）を定義します。
4.  **プランニングエンジンの選択:** 様々なプランニングエンジン（Fast Downward, Pyperplan など）が存在します。タスクの複雑さや性能要件に応じて適切なエンジンを選択します。

#### 7.1.4. 基本的な使い方

ここでは、シンプルな例として、エージェントが部屋からオフィスへ移動する計画を立てることを考えます。PDDL（Planning Domain Definition Language）を用いて、問題を定義します。

**ドメイン定義 (domain.pddl):**

```pddl
(define (domain office-world)
  (:requirements :strips)
  (:predicates (at ?x) (connected ?x ?y))

  (:action move
    :parameters (?from ?to)
    :precondition (and (at ?from) (connected ?from ?to))
    :effect (and (at ?to) (not (at ?from)))
  )
)
```

このドメイン定義は、エージェントが場所 `?x` にいることを示す `(at ?x)` と、場所 `?x` と `?y` が接続されていることを示す `(connected ?x ?y)` という述語を定義しています。`move` アクションは、ある場所から別の場所に移動するためのアクションです。

**問題定義 (problem.pddl):**

```pddl
(define (problem go-to-office)
  (:domain office-world)
  (:init (at room) (connected room hallway) (connected hallway office))
  (:goal (at office))
)
```

この問題定義は、初期状態としてエージェントが `room` におり、`room` が `hallway` に接続され、`hallway` が `office` に接続されていることを示しています。目標状態は、エージェントが `office` にいることです。

Python で`pyperplan`を使ってこの問題を解く例を示します。

```python
from pyperplan import Planner
import os

# PDDLファイルを同じディレクトリに置く
domain_file = os.path.join(os.getcwd(), "domain.pddl")
problem_file = os.path.join(os.getcwd(), "problem.pddl")

# Plannerを初期化し、問題を解く
planner = Planner()
plan = planner.solve(domain_file, problem_file)

if plan:
    print("Plan found:")
    for action in plan:
        print(action)
else:
    print("No plan found.")
```

このコードを実行すると、`move room hallway` と `move hallway office` という行動計画が出力されるはずです。

#### 7.1.5. 実践的なテクニック

- **抽象化:** 複雑なタスクをより単純なサブタスクに分解することで、プランニングの効率を向上させます。
- **制約の追加:** 実行不可能な行動を事前に排除することで、プランニングの探索空間を削減します。
- **ヒューリスティクスの利用:** 最適な行動計画を効率的に見つけるためのヒューリスティクス関数を導入します。
- **プランの再利用:** 過去に生成された計画を修正して新しいタスクに適用することで、プランニング時間を短縮します。

#### 7.1.6. 応用例とユースケース

- **ロボット制御:** ロボットが特定の場所に移動したり、オブジェクトを操作したりする計画を自動的に生成します。
- **ゲーム AI:** キャラクターがゲーム内の目標を達成するための戦略を立案します。
- **サプライチェーン管理:** 製品の輸送経路や在庫管理の計画を最適化します。
- **タスク管理:** 複数のタスクを効率的に実行するためのスケジュールを生成します。

#### 7.1.7. トラブルシューティング

- **プランニングが完了しない:** ドメイン定義や問題定義に誤りがないか確認します。制約が厳しすぎる場合や、目標が達成不可能な場合も考えられます。
- **生成された計画が非効率:** ヒューリスティクス関数を改善するか、より適切なプランニングエンジンを選択します。
- **環境の変化に対応できない:** 環境の変化を検知し、計画を再生成するメカニズムを導入します。

#### 7.1.8. まとめと次のステップ

ゴール指向プランニングは、AI エージェントが自律的にタスクを実行するための強力なツールです。次は、プランニングに基づいて生成された行動を実際に実行するタスク自動化について学びます。

### 7.2. タスク自動化 - ロボティック・プロセス・オートメーション(RPA)

#### 7.2.1. 概要と重要性

ロボティック・プロセス・オートメーション（RPA）は、人間が行う定型的な作業をソフトウェアロボットが代行する技術です。AI エージェントの文脈では、ゴール指向プランニングによって生成された行動計画を実行するために、RPA が重要な役割を果たします。

RPA は、特に反復的でルールに基づいたタスクを自動化するのに適しています。例えば、Web サイトからのデータ収集、請求書の処理、顧客情報の更新などが挙げられます。AI エージェントと RPA を組み合わせることで、より複雑なタスクをエンドツーエンドで自動化することが可能になります。

#### 7.2.2. 特徴と利点

- **効率性の向上:** 人手による作業を削減し、処理速度を向上させます。
- **コスト削減:** 人件費を削減し、業務効率を向上させることで、全体的なコストを削減します。
- **精度の向上:** 人為的なミスを減らし、正確なデータ処理を可能にします。
- **可用性の向上:** 24 時間 365 日稼働できるため、いつでもタスクを実行できます。
- **スケーラビリティ:** 必要に応じてロボットの数を増減できるため、柔軟な対応が可能です。

#### 7.2.3. 事前準備と前提条件

RPA を導入するためには、以下の準備が必要です。

1.  **RPA ツールの選定:** UiPath, Automation Anywhere, Blue Prism など、様々な RPA ツールが存在します。要件に応じて適切なツールを選択します。
2.  **自動化対象タスクの選定:** 自動化に適したタスク（反復的、ルールに基づいたタスク）を選定します。
3.  **プロセスの分析:** 自動化対象タスクのプロセスを詳細に分析し、手順を明確化します。
4.  **ロボットの開発:** RPA ツールを用いて、分析したプロセスを自動化するロボットを開発します。
5.  **テストとデバッグ:** 開発したロボットが正しく動作するかテストし、必要に応じて修正します。
6.  **デプロイと監視:** ロボットを本番環境にデプロイし、正常に稼働しているか監視します。

#### 7.2.4. 基本的な使い方

ここでは、UiPath を用いて、Web サイトからデータを収集する簡単なロボットを作成する例を示します。

1.  **UiPath Studio の起動:** UiPath Studio を起動し、新しいプロジェクトを作成します。
2.  **アクティビティの追加:** デザイン画面に、`Open Browser` アクティビティを追加し、Web サイトの URL を設定します。
3.  **データ抽出:** `Data Scraping` ウィザードを用いて、Web サイトから抽出するデータを指定します。
4.  **データの保存:** `Write CSV` アクティビティを追加し、抽出したデータを CSV ファイルに保存します。

**UiPath のワークフロー例:**

- **Open Browser:** ブラウザを開き、指定された URL にアクセスします。
  - `URL`: "https://www.example.com"
- **Data Scraping:** Web サイトから指定されたデータを抽出します。
  - `Selector`: "CSS セレクタ"
  - `Attribute`: "テキスト"
- **Write CSV:** 抽出したデータを CSV ファイルに書き込みます。
  - `FilePath`: "output.csv"
  - `Append`: False

#### 7.2.5. 実践的なテクニック

- **例外処理:** ロボットが予期せぬエラーに遭遇した場合の処理を記述します。
- **ログ記録:** ロボットの動作状況を記録し、トラブルシューティングに役立てます。
- **パラメータ化:** ロボットの設定を外部ファイルから読み込むことで、柔軟性を高めます。
- **オーケストレーション:** 複数のロボットを連携させて、より複雑なタスクを自動化します。

#### 7.2.6. 応用例とユースケース

- **請求書処理:** スキャンされた請求書からデータを抽出し、会計システムに登録します。
- **顧客サポート:** FAQ に基づいて顧客からの問い合わせに自動で回答します。
- **在庫管理:** 在庫データを定期的に更新し、発注を自動化します。
- **人事管理:** 従業員の入社・退社手続きを自動化します。

#### 7.2.7. トラブルシューティング

- **ロボットがエラーで停止する:** エラーメッセージを確認し、原因を特定します。例外処理が適切に記述されているか確認します。
- **データが正しく抽出されない:** Web サイトの構造が変更された可能性があります。セレクタを修正します。
- **ロボットの動作が遅い:** 不要なアクティビティを削除するか、処理方法を改善します。

#### 7.2.8. まとめと次のステップ

RPA は、AI エージェントが行動計画を実行するための強力な手段です。次は、複数の AI エージェントが協調・競争しながらタスクをこなすマルチエージェントシステムについて学びます。

### 7.3. マルチエージェントシステム - 協調と競争

#### 7.3.1. 概要と重要性

マルチエージェントシステム（MAS）は、複数の自律的なエージェントが相互作用しながら、共通の目標を達成したり、個々の目標を追求したりするシステムです。これらのエージェントは、情報を交換し、互いの行動を調整し、時には競い合いながら、複雑な問題を解決します。

MAS は、単一のエージェントでは解決できないような大規模で複雑な問題に取り組むのに適しています。例えば、交通流の最適化、分散型電源システムの制御、サプライチェーンの最適化などが挙げられます。

#### 7.3.2. 特徴と利点

- **分散性:** 問題解決の責任を複数のエージェントに分散することで、システム全体の頑健性を高めます。
- **並列性:** 複数のエージェントが同時に行動できるため、処理速度を向上させます。
- **適応性:** 環境の変化に応じて、エージェントが自律的に行動を調整します。
- **拡張性:** 必要に応じてエージェントの数を増減できるため、柔軟な対応が可能です。

#### 7.3.3. 事前準備と前提条件

MAS を構築するためには、以下の準備が必要です。

1.  **エージェントの設計:** エージェントの役割、能力、行動ルールを定義します。
2.  **通信メカニズムの設計:** エージェント間の情報交換方法（メッセージング、共有メモリなど）を決定します。
3.  **協調メカニズムの設計:** エージェントが互いに協力するためのルールやプロトコルを定義します。
4.  **競合解決メカニズムの設計:** エージェント間で競合が発生した場合の解決方法を定義します。
5.  **シミュレーション環境の構築:** エージェントの行動をシミュレーションするための環境を構築します。

#### 7.3.4. 基本的な使い方

ここでは、Python の`mesa`ライブラリを用いて、簡単なマルチエージェントシミュレーションを作成する例を示します。

```python
from mesa import Agent, Model
from mesa.space import Grid
from mesa.time import RandomActivation

class SimpleAgent(Agent):
    def __init__(self, unique_id, model):
        super().__init__(unique_id, model)

    def step(self):
        # ランダムな方向に移動
        possible_steps = self.model.grid.get_neighborhood(
            self.pos, moore=True, include_center=False
        )
        new_position = self.random.choice(possible_steps)
        self.model.grid.move_agent(self, new_position)

class SimpleModel(Model):
    def __init__(self, N, width, height):
        self.num_agents = N
        self.grid = Grid(width, height, torus=True)
        self.schedule = RandomActivation(self)

        # エージェントの作成
        for i in range(self.num_agents):
            a = SimpleAgent(i, self)
            self.schedule.add(a)
            # ランダムな場所に配置
            x = self.random.randrange(self.grid.width)
            y = self.random.randrange(self.grid.height)
            self.grid.place_agent(a, (x, y))

    def step(self):
        self.schedule.step()

# モデルの実行
model = SimpleModel(10, 10, 10)
for i in range(10):
    model.step()
```

このコードは、ランダムに動き回るエージェントのシミュレーションです。`SimpleAgent` クラスはエージェントの行動を定義し、`SimpleModel` クラスはシミュレーション環境を定義します。

#### 7.3.5. 実践的なテクニック

- **強化学習:** エージェントが経験を通じて最適な行動を学習する能力を与えます。
- **ゲーム理論:** エージェント間の戦略的な相互作用をモデル化し、最適な戦略を導き出します。
- **オークション理論:** リソースの割り当てを効率的に行うためのオークションメカニズムを設計します。
- **社会シミュレーション:** 人間の行動や社会現象をモデル化し、予測や意思決定に役立てます。

#### 7.3.6. 応用例とユースケース

- **交通流の最適化:** 複数のエージェントが交通状況を監視し、最適なルートを提案します。
- **分散型電源システムの制御:** 複数のエージェントが電力需要を予測し、発電量を調整します。
- **サプライチェーンの最適化:** 複数のエージェントが在庫状況を監視し、最適な発注量を決定します。
- **災害対応:** 複数のエージェントが被災状況を把握し、救援活動を調整します。

#### 7.3.7. トラブルシューティング

- **エージェントが互いに衝突する:** 衝突回避のためのルールを導入します。
- **システムが不安定になる:** エージェント間の相互作用を調整し、フィードバックループを安定化させます。
- **シミュレーションが現実と乖離する:** モデルのパラメータを調整するか、より複雑なモデルを構築します。

#### 7.3.8. まとめと次のステップ

マルチエージェントシステムは、AI エージェントが複雑な問題を解決するための強力なパラダイムです。本章で学んだ知識を基に、現実世界の様々な問題に MAS を適用してみてください。
