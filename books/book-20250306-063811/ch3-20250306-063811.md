## 第3章：センサーネットワークの構築：無線通信技術の基礎と応用

センサーネットワークは、IoT（Internet of Things）の中核を担う技術であり、環境モニタリング、スマート農業、スマートシティなど、様々な分野で活用されています。本章では、センサーネットワークを構築する上で不可欠な無線通信技術に焦点を当て、その基礎から応用までを丁寧に解説します。特に、Wi-Fi、Bluetooth、LoRaWAN、Sigfox、NB-IoTといった代表的な無線通信プロトコルについて、それぞれの特徴、利点、具体的な活用方法を詳しく見ていきましょう。

### 3.1 無線通信プロトコルの基礎：Wi-Fi、Bluetooth、LoRaWAN、Sigfox、NB-IoT

#### 3.1.1 概要と重要性

センサーネットワークは、複数のセンサーノードが相互に通信し、収集したデータを集約して処理するシステムです。これらのノード間の通信には、無線通信技術が不可欠であり、様々なプロトコルが利用されています。それぞれのプロトコルは、通信距離、データレート、消費電力、ネットワーク構成などにおいて異なる特性を持ち、用途に応じて最適なプロトコルを選択する必要があります。

このセクションでは、センサーネットワークでよく利用される代表的な無線通信プロトコルであるWi-Fi、Bluetooth、LoRaWAN、Sigfox、NB-IoTについて、それぞれの特徴を比較し、どのような場合にどのプロトコルを選択すべきかを理解することを目的とします。

#### 3.1.2 特徴と利点

*   **Wi-Fi (IEEE 802.11)**

    *   **特徴:** 高いデータレート、広い普及率、比較的短い通信距離。
    *   **利点:** 既存のWi-Fiインフラを活用可能、スマートフォンやPCとの連携が容易、動画などの大容量データ伝送に適している。
    *   **用途例:** 家庭内のスマート家電、工場内の設備監視、オフィス環境のセンサーネットワーク。
*   **Bluetooth (IEEE 802.15.1)**

    *   **特徴:** 近距離無線通信、省電力、比較的低いデータレート。
    *   **利点:** ペアリングによる簡単な接続、省電力設計、ウェアラブルデバイスやスマートフォンとの連携に最適。
    *   **用途例:** スマートウォッチ、ヘルスケアデバイス、ビーコンを用いた位置情報サービス。
*   **LoRaWAN**

    *   **特徴:** 長距離無線通信、超低消費電力、低データレート。
    *   **利点:** 数キロメートル以上の通信距離、バッテリー駆動で長期間動作、広範囲に分散したセンサーネットワークに最適。
    *   **用途例:** スマート農業、環境モニタリング、スマートメーター、駐車場管理。
*   **Sigfox**

    *   **特徴:** 長距離無線通信、超低消費電力、非常に低いデータレート。
    *   **利点:** グローバルなネットワークカバレッジ、低コスト、シンプルなデバイス設計、低頻度のデータ伝送に最適。
    *   **用途例:** アセットトラッキング、リモートメーター、農業における土壌湿度モニタリング。
*   **NB-IoT (Narrowband IoT)**

    *   **特徴:** 長距離無線通信、低消費電力、既存のモバイルネットワークを利用。
    *   **利点:** 広範囲なネットワークカバレッジ、セルラーネットワークのインフラを利用可能、信頼性の高い通信。
    *   **用途例:** スマートメーター、駐車場管理、スマートシティにおけるインフラ監視。

#### 3.1.3 事前準備と前提条件

各プロトコルを利用するためには、それぞれのプロトコルに対応したハードウェア（センサーノード、ゲートウェイなど）とソフトウェア（開発環境、ライブラリなど）が必要です。

*   **Wi-Fi:** Wi-Fiモジュール（ESP32など）、Wi-Fiルーター。
*   **Bluetooth:** Bluetoothモジュール（ESP32、nRF52など）、スマートフォンまたはPC。
*   **LoRaWAN:** LoRaWANモジュール（Semtech SX1276など）、LoRaWANゲートウェイ、LoRaWANネットワークサーバー（The Things Networkなど）。
*   **Sigfox:** Sigfoxモジュール、Sigfoxネットワークへのサブスクリプション。
*   **NB-IoT:** NB-IoTモジュール、セルラーネットワークへのアクセス。

開発環境としては、Arduino IDE、PlatformIO、MicroPythonなどが利用できます。

#### 3.1.4 基本的な使い方

各プロトコルの基本的な使い方は、それぞれのモジュールや開発環境によって異なりますが、共通する手順としては、

1.  ハードウェアのセットアップ：センサーノード、ゲートウェイなどの接続、電源供給。
2.  ソフトウェアの開発：プロトコルに対応したライブラリを利用して、データ収集、送信処理を記述。
3.  ネットワークの設定：ゲートウェイの設定、ネットワークサーバーへの登録。
4.  テスト：データが正しく送信、受信されるかを確認。

といった流れになります。

以下は、ESP32を使ったWi-Fi通信の簡単なコード例です。

```arduino
#include <WiFi.h>

const char* ssid = "your_SSID";
const char* password = "your_PASSWORD";

void setup() {
  Serial.begin(115200);
  delay(10);

  Serial.println("Connecting to WiFi");
  WiFi.begin(ssid, password);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("");
  Serial.println("WiFi connected");
  Serial.println("IP address: ");
  Serial.println(WiFi.localIP());
}

void loop() {
  // ここにセンサーデータの読み取りと送信処理を記述
  Serial.println("Sending data...");
  delay(5000); // 5秒ごとにデータを送信
}
```

#### 3.1.5 実践的なテクニック

*   **Wi-Fi:** Wi-Fi Directによるノード間の直接通信、MQTTプロトコルによるデータ送受信。
*   **Bluetooth:** BLE (Bluetooth Low Energy) による省電力化、iBeacon/Eddystoneによるビーコン技術。
*   **LoRaWAN:** ADR (Adaptive Data Rate) によるデータレートの最適化、OTAA (Over-The-Air Activation) によるセキュアなデバイス認証。
*   **Sigfox:** データの圧縮によるデータ送信量の削減、Sigfox Cloud APIによるデータ処理。
*   **NB-IoT:** PSM (Power Saving Mode) による超低消費電力化、eDRX (extended Discontinuous Reception) による受信待機時間の最適化。

#### 3.1.6 応用例とユースケース

*   **スマート農業:** LoRaWANまたはSigfoxを用いて、広大な農地の土壌湿度、温度、日照量などをモニタリングし、灌漑や施肥の最適化に役立てる。
*   **スマートシティ:** NB-IoTを用いて、街灯の点灯状況、ゴミ箱の満杯状況、交通量などをモニタリングし、効率的な都市管理を実現する。
*   **ヘルスケア:** Bluetoothを用いて、ウェアラブルデバイスから心拍数、血圧などのバイタルデータを収集し、健康管理や遠隔医療に役立てる。
*   **アセットトラッキング:** SigfoxまたはLoRaWANを用いて、物流コンテナや建設機械の位置情報を追跡し、盗難防止や効率的な運用に役立てる。
*   **環境モニタリング:** LoRaWANを用いて、河川の水位、大気汚染物質の濃度などをモニタリングし、防災や環境保護に役立てる。

#### 3.1.7 トラブルシューティング

*   **Wi-Fi:** 接続が不安定な場合、ルーターとの距離を近づける、チャンネルを変更する、ファームウェアをアップデートする。
*   **Bluetooth:** ペアリングがうまくいかない場合、デバイスの電源を入れ直す、ペアリング情報を削除する、他のBluetoothデバイスとの干渉を避ける。
*   **LoRaWAN:** データが送信されない場合、ゲートウェイとの距離を確認する、アンテナの向きを調整する、電波干渉を避ける。
*   **Sigfox:** 接続が確立しない場合、Sigfoxネットワークのカバーエリア内にあるかを確認する、アンテナの向きを調整する。
*   **NB-IoT:** 接続が不安定な場合、セルラーネットワークの電波状況を確認する、APN設定を確認する。

### 3.2 LoRaWANによる長距離・省電力ネットワーク構築

#### 3.2.1 概要と重要性

LoRaWAN（Long Range Wide Area Network）は、長距離通信と省電力を両立した無線通信プロトコルであり、特に広範囲に分散したセンサーネットワークの構築に最適なソリューションです。スマート農業、環境モニタリング、スマートシティなど、様々な分野でその有用性が実証されています。

このセクションでは、LoRaWANの技術的な詳細、ネットワークアーキテクチャ、具体的な実装方法について詳しく解説し、読者が実際にLoRaWANネットワークを構築し、活用できるようになることを目指します。

#### 3.2.2 特徴と利点

*   **長距離通信:** 数キロメートル以上の通信距離を実現し、広範囲なエリアをカバーできます。
*   **超低消費電力:** バッテリー駆動で数年間動作可能であり、メンテナンスコストを削減できます。
*   **双方向通信:** デバイスからゲートウェイへのアップリンクだけでなく、ゲートウェイからデバイスへのダウンリンクも可能です。
*   **アダプティブデータレート（ADR）:** ネットワーク状況に応じてデータレートを自動的に調整し、通信の信頼性を高めます。
*   **セキュリティ:** AES暗号化によるデータの保護、デバイス認証による不正アクセス防止。
*   **スケーラビリティ:** 大量のデバイスをネットワークに接続可能であり、大規模なセンサーネットワークに適しています。

#### 3.2.3 事前準備と前提条件

LoRaWANネットワークを構築するためには、以下のハードウェアとソフトウェアが必要です。

*   **LoRaWANエンドノード:** センサー、マイコン、LoRaWANモジュール（Semtech SX1276/1278など）を搭載したデバイス。
*   **LoRaWANゲートウェイ:** エンドノードからのデータを受信し、ネットワークサーバーに転送するデバイス。
*   **LoRaWANネットワークサーバー:** ゲートウェイからのデータを受信し、アプリケーションサーバーに転送するソフトウェア。
*   **アプリケーションサーバー:** ネットワークサーバーからのデータを受信し、処理、保存、可視化するソフトウェア。

また、LoRaWANネットワークを利用するためには、ネットワークサーバーへの登録が必要です。代表的なネットワークサーバーとしては、The Things Network (TTN)、ChirpStackなどがあります。

#### 3.2.4 基本的な使い方

LoRaWANエンドノードを開発するための基本的な手順は以下の通りです。

1.  **ハードウェアのセットアップ:** LoRaWANモジュールをマイコンに接続し、センサーを接続します。
2.  **ソフトウェアの開発:** LoRaWANライブラリ（LMIC、LoRaMAC-nodeなど）を利用して、デバイスのアクティベーション、データ送信処理を記述します。
3.  **ネットワークサーバーへの登録:** デバイスのDevEUI、AppEUI、AppKeyをネットワークサーバーに登録します。
4.  **テスト:** データがゲートウェイ経由でネットワークサーバーに正常に送信されるかを確認します。

以下は、Arduino IDEとLMICライブラリを使ったLoRaWANエンドノードの簡単なコード例です。

```arduino
#include <lmic.h>
#include <hal/hal.h>

// LoRaWAN NwkSKey, network session key
static const PROGMEM u1_t NWKSKEY[16] = { /* 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 */ };

// LoRaWAN AppSKey, application session key
static const u1_t PROGMEM APPSKEY[16] = { /* 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 */ };

// LoRaWAN end-device address (DevAddr)
static const u4_t DEVADDR = 0x00000000 ; // Replace with your DevAddr, e.g. 01234567

// These callbacks are only used in over-the-air activation, so they are
// left empty here (we cannot leave them out completely unless
// DISABLE_JOIN is defined in config.h, otherwise the linker will complain
void os_getArtEui (u1_t* buf) { }
void os_getDevEui (u1_t* buf) { }
void os_getDevKey (u1_t* buf) { }

static osjob_t sendjob;

// Schedule TX every this many seconds (might become longer due to duty
// cycle limitations).
const unsigned TX_INTERVAL = 60;

// Pin mapping
const lmic_pinmap lmic_pins = {
    .nss = 10,
    .rxtx = LMIC_UNUSED_PIN,
    .rst = 9,
    .dio = {2, 6, 7},
};

void onEvent (ev_t ev) {
    Serial.print(os_getTime());
    Serial.print(": ");
    switch(ev) {
        case EV_SCAN_TIMEOUT:
            Serial.println(F("EV_SCAN_TIMEOUT"));
            break;
        case EV_BEACON_FOUND:
            Serial.println(F("EV_BEACON_FOUND"));
            break;
        case EV_BEACON_MISSED:
            Serial.println(F("EV_BEACON_MISSED"));
            break;
        case EV_BEACON_LOST:
            Serial.println(F("EV_BEACON_LOST"));
            break;
        case EV_TXCOMPLETE:
            Serial.println(F("EV_TXCOMPLETE (includes waiting for RX windows)"));
            if (LMIC.txrxFlags & TXRX_ACK)
              Serial.println(F("Received ack"));
            if (LMIC.dataLen) {
              Serial.print(F("Received "));
              Serial.print(LMIC.dataLen);
              Serial.println(F(" bytes of payload"));
            }
            // Schedule next transmission
            os_setTimedCallback(&sendjob, os_getTime()+sec2osticks(TX_INTERVAL), do_send);
            break;
        case EV_LOST_TSYNC:
            Serial.println(F("EV_LOST_TSYNC"));
            break;
        case EV_RESET:
            Serial.println(F("EV_RESET"));
            break;
        case EV_RXCOMPLETE:
            // Data received in ping slot
            Serial.println(F("EV_RXCOMPLETE"));
            break;
        case EV_LINK_DEAD:
            Serial.println(F("EV_LINK_DEAD"));
            break;
        case EV_LINK_ALIVE:
            Serial.println(F("EV_LINK_ALIVE"));
            break;
         default:
            Serial.print(F("Unknown event: "));
            Serial.println((unsigned) ev);
            break;
    }
}

void do_send(osjob_t* job){
    // Check if there is not a current TX/RX job running
    if (LMIC.opmode & OP_TXRXPEND) {
        Serial.println(F("OP_TXRXPEND, not sending"));
    } else {
        // Prepare upstream data transmission at the next possible time.
        LMIC_setTxData2(1, "Hello World!", sizeof("Hello World!")-1, 0);
        Serial.println(F("Packet queued"));
    }
    // Next TX is scheduled after TX_COMPLETE event.
}

void setup() {
    Serial.begin(115200);
    Serial.println(F("Starting"));

    #ifdef VCC_ENABLE
    // For pin 15 testing
    pinMode(15,OUTPUT);
    digitalWrite(15,HIGH);
    delay(100);
    digitalWrite(15,LOW);
    #endif

    // LMIC init
    os_init();
    // Reset the MAC state. Session and pending data transfers will be discarded.
    LMIC_reset();

    // Set static session parameters. Instead of dynamically establishing a
    // session by joining the network, precomputed session parameters are be
    // provided.
    #ifdef PROGMEM
    LMIC_setNwkSKey((u1_t*)PGM_P(&NWKSKEY));
    LMIC_setAppSKey((u1_t*)PGM_P(&APPSKEY));
    #else
    LMIC_setNwkSKey((u1_t*)&NWKSKEY);
    LMIC_setAppSKey((u1_t*)&APPSKEY);
    #endif
    LMIC_setDevAddr(DEVADDR);

    // Disable link check validation
    LMIC_setLinkCheckMode(0);

    // TTN uses SF9 for its first down link window.
    LMIC.dn2Dr = DR_SF9;

    // Set data rate and transmit power for uplink (note: txpow seems to be ignored by the library)
    LMIC_setDrTxpow(DR_SF7,14);

    // Schedule a first transmission
    os_setTimedCallback(&sendjob, os_getTime()+sec2osticks(TX_INTERVAL), do_send);
}

void loop() {
    os_runloop_once();
}
```

**注意点:**

*   `NWKSKEY`, `APPSKEY`, `DEVADDR`は、The Things Networkなどのネットワークサーバーで生成された値を設定する必要があります。
*   `lmic_pins` は、LoRaWANモジュールとマイコンのピン接続に合わせて設定する必要があります。
*   利用する周波数帯域（868MHz、915MHzなど）に合わせて、LMICライブラリのコンフィグレーションファイルを修正する必要があります。

#### 3.2.5 実践的なテクニック

*   **アダプティブデータレート（ADR）:** ADRを有効にすることで、ネットワーク状況に応じて最適なデータレートを自動的に選択し、通信の信頼性を高めることができます。
*   **オーバーザエアアクティベーション（OTAA）:** OTAAを利用することで、デバイスをセキュアにネットワークに登録できます。
*   **ダウンリンク:** ゲートウェイからデバイスにデータを送信することで、デバイスの設定変更や制御を行うことができます。
*   **省電力化:** Deep Sleepモードを活用することで、デバイスの消費電力を大幅に削減できます。

#### 3.2.6 応用例とユースケース

*   **スマート農業:** 広大な農地の土壌水分量、温度、湿度などのデータを収集し、灌漑や施肥の最適化に役立てる。
*   **環境モニタリング:** 河川の水位、大気汚染物質の濃度などのデータを収集し、防災や環境保護に役立てる。
*   **スマートシティ:** 街灯の点灯状況、ゴミ箱の満杯状況などのデータを収集し、都市の効率的な管理に役立てる。
*   **アセットトラッキング:** 物流コンテナ、建設機械などの位置情報を追跡し、盗難防止や効率的な運用に役立てる。
*   **スマートメーター:** 電気、ガス、水道の使用量を遠隔で計測し、検針業務の効率化やエネルギー消費の最適化に役立てる。

#### 3.2.7 トラブルシューティング

*   **データが送信されない:**
    *   ゲートウェイとの距離が遠すぎる可能性があります。
    *   アンテナの向きが適切でない可能性があります。
    *   電波干渉が発生している可能性があります。
    *   ネットワークサーバーへの登録情報が間違っている可能性があります。
*   **ADRが正常に機能しない:**
    *   デバイスのファームウェアが最新でない可能性があります。
    *   ネットワークサーバーの設定が誤っている可能性があります。
*   **バッテリーの消耗が早い:**
    *   送信間隔が短すぎる可能性があります。
    *   Deep Sleepモードが正しく設定されていない可能性があります。
    *   電波状況が悪い可能性があります。

### 3.3 Bluetooth Meshによる大規模ネットワーク構築

#### 3.3.1 概要と重要性

Bluetooth Meshは、Bluetooth Low Energy (BLE) をベースにしたメッシュネットワーク技術であり、従来のBluetoothの短距離通信の弱点を克服し、大規模なネットワークを構築することを可能にします。スマートホーム、スマートビルディング、産業用オートメーションなど、広範囲にわたるデバイスを相互接続する必要がある場合に最適なソリューションです。

このセクションでは、Bluetooth Meshの基本的な概念、ネットワークアーキテクチャ、具体的な実装方法について詳しく解説し、読者が実際にBluetooth Meshネットワークを構築し、活用できるようになることを目指します。

#### 3.3.2 特徴と利点

*   **メッシュネットワーク:** デバイス同士が中継しあうことで、通信範囲を大幅に拡大できます。
*   **自己修復機能:** 一部のデバイスが故障しても、他の経路を通じて通信を維持できます。
*   **管理機能:** 大規模なネットワークでも、デバイスの管理、設定変更、ファームウェアアップデートなどを効率的に行うことができます。
*   **省電力:** BLEをベースにしているため、バッテリー駆動のデバイスでも長期間動作可能です。
*   **セキュリティ:** 暗号化、認証、アクセス制御などのセキュリティ機能が組み込まれています。
*   **相互運用性:** Bluetooth SIGによって標準化されているため、異なるメーカーのデバイス間でも相互運用が可能です。

#### 3.3.3 事前準備と前提条件

Bluetooth Meshネットワークを構築するためには、以下のハードウェアとソフトウェアが必要です。

*   **Bluetooth Mesh対応デバイス:** Bluetooth Mesh機能を搭載したマイコン、モジュール（Nordic Semiconductor nRF52シリーズ、Silicon Labs EFR32シリーズなど）を搭載したデバイス。
*   **Bluetooth Meshプロビジョナー:** Bluetooth Meshネットワークにデバイスを追加するためのデバイス（スマートフォンアプリ、専用のプロビジョニングツールなど）。
*   **Bluetooth Meshネットワーク:** 相互接続されたBluetooth Mesh対応デバイスの集合。

開発環境としては、Nordic SemiconductorのnRF5 SDK for Mesh、Silicon LabsのSimplicity Studioなどが利用できます。

#### 3.3.4 基本的な使い方

Bluetooth Meshネットワークを構築するための基本的な手順は以下の通りです。

1.  **プロビジョニング:** Bluetooth Meshプロビジョナーを使用して、新しいデバイスをBluetooth Meshネットワークに追加します。
2.  **設定:** Bluetooth Meshプロビジョナーを使用して、デバイスの動作に必要な設定を行います（パブリッシュアドレス、サブスクライブアドレス、モデル設定など）。
3.  **メッセージの送受信:** Bluetooth Meshネットワーク内のデバイス間でメッセージを送受信します。

**1. プロビジョニング:**

*   スマートフォンアプリ（nRF Meshなど）を使用して、新しいデバイスをBluetooth Meshネットワークに追加します。
*   アプリは、デバイスを認証し、ネットワークキー、アプリケーションキーなどの必要な情報をデバイスに安全に転送します。

**2. 設定:**

*   スマートフォンアプリを使用して、デバイスの動作に必要な設定を行います。
*   例えば、ライトデバイスの場合、オン/オフ状態をパブリッシュするアドレス、オン/オフ状態の変化をサブスクライブするアドレスなどを設定します。

*   他のデバイスから、ライトデバイスにオン/オフ状態を変更するメッセージを送信します。

### 3.4 セキュリティ対策：暗号化、認証、アクセス制御

#### 3.4.1 概要と重要性

センサーネットワークは、様々な環境で利用され、機密性の高い情報を取り扱うこともあります。そのため、セキュリティ対策は非常に重要であり、データの盗聴、改ざん、不正アクセスなどを防止する必要があります。

#### 3.4.2 特徴と利点

適切なセキュリティ対策を講じることで、以下の利点が得られます。

*   **データの保護:** センサーデータや制御データを盗聴、改ざんから保護し、情報の機密性、完全性を維持します。

#### 3.4.3 事前準備と前提条件

セキュリティ対策を実装するためには、以下の要素が必要です。

*   **セキュリティポリシー:** ネットワーク全体におけるセキュリティに関するルール、方針を明確に定義します。
*   **暗号化技術:** データを暗号化するためのアルゴリズム、プロトコル（AES、TLS/SSLなど）を理解し、適切に選択、実装します。
*   **認証技術:** デバイスやユーザーを認証するための方法（パスワード、デジタル証明書、生体認証など）を理解し、適切に選択、実装します。
*   **アクセス制御技術:** リソースへのアクセス権限を制御するための方法（役割ベースアクセス制御、属性ベースアクセス制御など）を理解し、適切に選択、実装します。
*   **脆弱性対策:** ソフトウェア、ハードウェアの脆弱性を特定し、修正するためのプロセスを確立します。

#### 3.4.4 基本的な使い方

センサーネットワークにおけるセキュリティ対策の基本的な要素は以下の通りです。

1.  **暗号化:**
    *   センサーノードとゲートウェイ間の通信、ゲートウェイとネットワークサーバー間の通信など、すべての通信経路でデータを暗号化します。
    *   AES (Advanced Encryption Standard) などの強力な暗号化アルゴリズムを使用します。
    *   TLS/SSL (Transport Layer Security/Secure Sockets Layer) などのセキュアな通信プロトコルを使用します。
2.  **認証:**
    *   センサーノード、ゲートウェイ、ユーザーなどを認証し、許可されていないデバイスやユーザーからのアクセスを防止します。
    *   パスワード、デジタル証明書、二要素認証などの方法を使用します。
    *   LoRaWANのOTAA (Over-The-Air Activation) など、セキュアなデバイス認証メカニズムを使用します。
3.  **アクセス制御:**
    *   リソース（センサーデータ、制御コマンドなど）へのアクセス権限を制御し、許可されたユーザーのみが特定の操作を実行できるようにします。
    *   役割ベースアクセス制御 (RBAC: Role-Based Access Control)、属性ベースアクセス制御 (ABAC: Attribute-Based Access Control) などの方法を使用します。

以下は、PythonとPyCryptodomeライブラリを使ったAES暗号化の簡単なコード例です。

```python
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes
from Crypto.Util.Padding import pad, unpad
import base64

def encrypt(plaintext, key):
    """AESを使ってデータを暗号化する"""
    cipher = AES.new(key, AES.MODE_CBC)
    ct_bytes = cipher.encrypt(pad(plaintext.encode('utf-8'), AES.block_size))
    iv = base64.b64encode(cipher.iv).decode('utf-8')
    ct = base64.b64encode(ct_bytes).decode('utf-8')
    return iv, ct

def decrypt(iv, ciphertext, key):
    """AESを使ってデータを復号化する"""
    iv = base64.b64decode(iv)
    ct = base64.b64decode(ciphertext)
    cipher = AES.new(key, AES.MODE_CBC, iv=iv)
    pt = unpad(cipher.decrypt(ct), AES.block_size)
    return pt.decode('utf-8')

# 例
key = get_random_bytes(16)  # AES-128の場合
plaintext = "This is a secret message."

iv, ciphertext = encrypt(plaintext, key)
decrypted_text = decrypt(iv, ciphertext, key)

print(f"Plaintext: {plaintext}")
print(f"Ciphertext: {ciphertext}")
print(f"Decrypted text: {decrypted_text}")
```

**注意点:**

*   暗号鍵は安全に管理する必要があります。
*   脆弱な暗号化アルゴリズムやプロトコルを使用しないように注意する必要があります。
*   定期的に暗号鍵をローテーションすることをお勧めします。

#### 3.4.5 実践的なテクニック

*   **セキュアブート:** 起動時にファームウェアの正当性を検証し、不正なファームウェアの実行を防止します。
