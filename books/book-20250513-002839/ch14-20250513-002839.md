# 第 14 章：カスタムアプリケーション開発：ローコードで実現するビジネスソリューション

## 14.1 App Engine Studio (AES) の概要と使い方

### 概要と重要性

App Engine Studio (AES) は、ServiceNow プラットフォーム上でローコードアプリケーション開発を可能にする強力なツールです。従来のコーディング中心の開発と比較して、AES は直感的で視覚的なインターフェースを提供し、ビジネスユーザーや市民開発者が迅速かつ容易にカスタムアプリケーションを作成、デプロイ、管理できるようにします。これは、ビジネスニーズへの迅速な対応、開発コストの削減、IT 部門への依存度低減に大きく貢献します。AES を活用することで、組織は競争力を高め、イノベーションを加速することができます。

### 特徴と利点

AES の主な特徴と利点は以下の通りです。

- **ローコード開発:** 最小限のコーディングでアプリケーションを構築できます。
- **直感的なインターフェース:** ドラッグ＆ドロップ操作で、簡単に UI、データモデル、ワークフローを設計できます。
- **迅速な開発:** 標準コンポーネントの再利用により、開発期間を大幅に短縮できます。
- **コラボレーション:** 複数人で同時に開発作業を進めることができます。
- **スケーラビリティ:** ServiceNow プラットフォームの堅牢なインフラストラクチャ上で動作するため、高いスケーラビリティと信頼性を確保できます。
- **統合:** ServiceNow の既存の機能やデータと容易に統合できます。
- **モバイル対応:** 開発したアプリケーションは自動的にモバイル対応となり、どこからでもアクセスできます。

### 事前準備と前提条件

AES を使用する前に、以下の準備が必要です。

- **ServiceNow インスタンス:** 開発用の ServiceNow インスタンスが必要です。
- **App Engine Studio プラグイン:** ServiceNow Store から App Engine Studio プラグインをインストールする必要があります。
- **ロール:** `app_engine_studio_user`ロールが付与されている必要があります。このロールがない場合、システム管理者に依頼して付与してもらいます。

プラグインのインストールとロールの付与が完了したら、ナビゲーションメニューから「App Engine Studio」を検索してアクセスできます。

### 基本的な使い方

AES の基本的な使い方は以下の通りです。

1.  **アプリケーションの作成:** AES にアクセスし、「+ Create App」ボタンをクリックして、新しいアプリケーションを作成します。アプリケーション名、説明、アイコンなどを設定します。
2.  **データモデルの設計:** データモデルは、アプリケーションで使用するデータを定義します。「Data」タブから新しいテーブルを作成し、必要なフィールド（テキスト、数値、日付など）を追加します。
3.  **UI の設計:** UI は、ユーザーがアプリケーションと対話するためのインターフェースです。「Experience」タブから UI Builder を開き、ドラッグ＆ドロップでフォーム、リスト、ダッシュボードなどを設計します。
4.  **ワークフローの設計:** ワークフローは、アプリケーションのビジネスロジックを定義します。「Automation」タブから Flow Designer を開き、トリガー、アクション、条件などを設定して、自動化されたプロセスを構築します。
5.  **テストとデプロイ:** アプリケーションが完成したら、テストを行い、問題がないことを確認します。その後、「Publish」ボタンをクリックして、アプリケーションをデプロイします。

**コードスニペット (データモデルの作成):**

新しいテーブルを作成するには、以下のスクリプトを使用できます (バックグラウンドスクリプトで実行):

```javascript
var gr = new GlideRecord("sys_db_object");
gr.initialize();
gr.name = "u_my_custom_table"; // テーブル名 (u_ プレフィックスはカスタムテーブルを示します)
gr.label = "My Custom Table"; // テーブルラベル
gr.insert();
```

**設定例 (UI Builder):**

UI Builder でフォームを作成する場合、フォームコンポーネントをキャンバスにドラッグし、データソースとして先ほど作成したテーブルを選択します。フィールドをフォームに追加し、ラベルや表示形式をカスタマイズします。

### 実践的なテクニック

AES を効果的に活用するための実践的なテクニックをいくつか紹介します。

- **標準コンポーネントの活用:** ServiceNow には、多くの標準コンポーネントが用意されています。これらのコンポーネントを再利用することで、開発時間を大幅に短縮できます。
- **カスタムコンポーネントの作成:** 標準コンポーネントでは実現できない独自の機能が必要な場合は、カスタムコンポーネントを作成できます。
- **テンプレートの利用:** テンプレートを利用することで、アプリケーションの基本構造を素早く構築できます。
- **バージョン管理:** アプリケーションの変更履歴を管理するために、バージョン管理システム（Git など）を導入することをお勧めします。
- **テスト駆動開発 (TDD):** テストコードを先に記述し、それに合わせて実装を行うことで、品質の高いアプリケーションを開発できます。

**コードスニペット (クライアントスクリプト):**

UI の動作をカスタマイズするために、クライアントスクリプトを使用できます。例えば、フィールドの値に基づいて別のフィールドを非表示にするには、以下のスクリプトを使用します:

```javascript
function onChange(control, oldValue, newValue, isLoading, isTemplate) {
  if (isLoading || newValue === "") {
    return;
  }

  // 例： 'priority' フィールドの値が '1' の場合、'assignment_group' フィールドを非表示にする
  if (newValue == "1") {
    g_form.setDisplay("assignment_group", false);
  } else {
    g_form.setDisplay("assignment_group", true);
  }
}
```

### 応用例とユースケース

AES を活用したカスタムアプリケーションの応用例とユースケースをいくつか紹介します。

- **設備管理:** 設備の貸し出し、返却、メンテナンスなどを管理するアプリケーション。
- **イベント管理:** イベントの登録、参加者管理、アンケートなどを管理するアプリケーション。
- **顧客管理:** 顧客情報の管理、顧客とのコミュニケーション履歴の記録、顧客からの問い合わせ対応などを管理するアプリケーション。
- **従業員オンボーディング:** 新入社員の入社手続き、研修、IT アカウントの発行などを自動化するアプリケーション。
- **リスク管理:** リスクの特定、評価、対応計画の策定、進捗状況の追跡などを管理するアプリケーション。

これらの例はほんの一例であり、AES を活用することで、組織のあらゆる業務プロセスをデジタル化し、効率化することができます。

### トラブルシューティング

AES の使用中に発生する可能性のある一般的な問題とその解決策を以下に示します。

- **アプリケーションが正常に動作しない:** エラーログを確認し、問題の原因を特定します。デバッグツールを使用して、コードをステップごとに実行し、変数の値を検証します。
- **UI が表示されない:** UI Builder の設定を確認し、必要なコンポーネントが正しく配置されていることを確認します。クライアントスクリプトのエラーがないか確認します。
- **ワークフローが実行されない:** Flow Designer の設定を確認し、トリガー条件が正しく設定されていることを確認します。ワークフローの実行履歴を確認し、エラーが発生している箇所を特定します。
- **権限エラー:** 必要なロールが付与されていることを確認します。テーブルやフィールドへのアクセス権限が正しく設定されていることを確認します。

**注意点:**

- AES はローコード開発ツールですが、完全にコーディングが不要というわけではありません。複雑な要件を実現するためには、JavaScript などのプログラミングスキルが必要になる場合があります。
- アプリケーションを開発する前に、要件を明確に定義し、設計をしっかりと行うことが重要です。
- 開発したアプリケーションは、必ずテストを行い、問題がないことを確認してからデプロイしてください。

AES は、ビジネスニーズに迅速に対応し、イノベーションを加速するための強力なツールです。この記事で紹介した知識とテクニックを活用して、独自のカスタムアプリケーションを開発し、ビジネスの課題を解決してください。次のステップとして、ServiceNow のドキュメントやトレーニングコースを受講し、AES に関する知識をさらに深めることをお勧めします。

## 14.2 カスタムアプリケーションの開発事例：承認ワークフロー、プロジェクト管理、ナレッジ管理

### 承認ワークフローのカスタムアプリケーション

#### 概要と重要性

組織内のあらゆるプロセスにおいて、承認ワークフローは不可欠です。購買申請、休暇申請、経費精算など、様々な業務プロセスで承認が必要となります。カスタムの承認ワークフローアプリケーションを作成することで、これらのプロセスを効率化し、可視性を高め、コンプライアンスを遵守することができます。

#### 特徴と利点

- **プロセスの標準化:** 承認プロセスを標準化し、担当者や部署によるばらつきをなくします。
- **迅速な承認:** 承認プロセスを自動化し、承認時間を短縮します。
- **可視性の向上:** 承認状況をリアルタイムで把握できます。
- **コンプライアンスの遵守:** 監査証跡を保持し、コンプライアンス要件を満たすことができます。
- **カスタマイズ性:** 組織のニーズに合わせて承認プロセスをカスタマイズできます。

#### 事前準備と前提条件

- ServiceNow インスタンス
- App Engine Studio プラグイン
- 承認ワークフローに必要なデータモデルの設計（例：申請テーブル、承認者テーブルなど）

#### 基本的な使い方

1.  **データモデルの作成:** 申請テーブルを作成し、申請に必要なフィールド（申請者、申請日、申請内容、承認者、承認ステータスなど）を追加します。
2.  **UI の設計:** 申請フォームと承認フォームを UI Builder で作成します。申請フォームには、申請内容を入力するためのフィールドを配置し、承認フォームには、承認/却下ボタンとコメント欄を配置します。
3.  **ワークフローの設計:** Flow Designer で承認ワークフローを設計します。ワークフローは、申請の作成、承認者への通知、承認/却下処理、申請ステータスの更新などのステップで構成されます。

**コードスニペット (Flow Designer):**

承認ワークフローの例として、申請が作成された際に承認者にメール通知を送信するフローを以下に示します。

```
Flow: Approval Request Workflow

Trigger:
  - Record Created (Table: Your Request Table)

Actions:
  1. Lookup Record (Approval Group)
  2. Send Email
     - To: Approval Group's Email Address
     - Subject: Approval Request for [Request Number]
     - Body:
       "A new approval request has been submitted. Please review and approve/reject."

  3. Update Record (Request Record)
     - Approval Status: Pending
```

#### 実践的なテクニック

- **条件付き承認:** 申請金額や申請内容に基づいて、承認者を動的に変更します。
- **エスカレーション:** 承認者が一定期間内に承認しない場合、上位の承認者にエスカレーションします。
- **委任:** 承認者が不在の場合、別の担当者に承認を委任します。
- **複数承認:** 複数の承認者の承認が必要な場合、全ての承認が得られるまで申請を保留します。

#### 応用例とユースケース

- **購買申請:** 購買申請の承認ワークフローを自動化します。
- **休暇申請:** 従業員の休暇申請を承認するワークフローを自動化します。
- **経費精算:** 経費精算の承認ワークフローを自動化します。
- **変更申請:** システム変更の承認ワークフローを自動化します。

#### トラブルシューティング

- **メール通知が送信されない:** メールサーバーの設定を確認します。Flow Designer のメールアクションの設定を確認します。
- **承認者が表示されない:** データモデルの設定を確認します。UI Builder のフォームの設定を確認します。
- **ワークフローが正常に動作しない:** Flow Designer の実行履歴を確認し、エラーが発生している箇所を特定します。

#### まとめと次のステップ

カスタムの承認ワークフローアプリケーションを作成することで、業務プロセスを効率化し、可視性を高め、コンプライアンスを遵守することができます。次のステップとして、組織の具体的なニーズに合わせて承認ワークフローをカスタマイズし、テストを行い、デプロイしてください。

### プロジェクト管理のカスタムアプリケーション

#### 概要と重要性

プロジェクト管理は、計画、実行、監視、および制御を含む、時間とリソースを制約された目標を達成するための体系的なプロセスです。カスタムのプロジェクト管理アプリケーションを作成することで、プロジェクトの進捗状況を追跡し、リソースを効率的に割り当て、リスクを管理することができます。

#### 特徴と利点

- **プロジェクトの可視化:** プロジェクトの進捗状況をリアルタイムで把握できます。
- **リソースの最適化:** リソースの割り当てを効率的に行い、リソースの過不足を解消します。
- **リスク管理:** リスクを早期に特定し、対応計画を策定します。
- **コラボレーションの促進:** 関係者間のコミュニケーションを円滑にし、協力関係を強化します。
- **レポート作成の効率化:** プロジェクトの進捗状況に関するレポートを容易に作成できます。

#### 事前準備と前提条件

- ServiceNow インスタンス
- App Engine Studio プラグイン
- プロジェクト管理に必要なデータモデルの設計（例：プロジェクトテーブル、タスクテーブル、リソーステーブルなど）

#### 基本的な使い方

1.  **データモデルの作成:** プロジェクトテーブル、タスクテーブル、リソーステーブルを作成し、それぞれのテーブルに必要なフィールド（プロジェクト名、タスク名、担当者、開始日、終了日、ステータスなど）を追加します。
2.  **UI の設計:** プロジェクトダッシュボード、タスクリスト、リソースガントチャートなどを UI Builder で作成します。
3.  **ワークフローの設計:** Flow Designer でプロジェクトの進捗状況を自動的に更新するワークフローを設計します。

**コードスニペット (スクリプトインクルード):**

プロジェクトのステータスを自動的に更新するスクリプトインクルードの例を以下に示します。

```javascript
var ProjectStatusUpdater = Class.create();
ProjectStatusUpdater.prototype = {
  initialize: function (project_id) {
    this.project_id = project_id;
  },

  updateProjectStatus: function () {
    var gr = new GlideRecord("pm_project");
    if (gr.get(this.project_id)) {
      var taskGr = new GlideAggregate("pm_project_task");
      taskGr.addQuery("project", this.project_id);
      taskGr.addAggregate("COUNT", "sys_id");
      taskGr.query();
      var totalTasks = 0;
      if (taskGr.next()) {
        totalTasks = taskGr.getAggregate("COUNT", "sys_id");
      }

      taskGr = new GlideAggregate("pm_project_task");
      taskGr.addQuery("project", this.project_id);
      taskGr.addQuery("state", "COMPLETE"); // 例：タスクの状態が「完了」の場合
      taskGr.addAggregate("COUNT", "sys_id");
      taskGr.query();
      var completedTasks = 0;
      if (taskGr.next()) {
        completedTasks = taskGr.getAggregate("COUNT", "sys_id");
      }

      var progressPercentage =
        totalTasks > 0 ? (completedTasks / totalTasks) * 100 : 0;
      gr.setValue("progress", progressPercentage); // プロジェクトの進捗率を更新
      gr.update();
    }
  },

  type: "ProjectStatusUpdater",
};
```

#### 実践的なテクニック

- **ガントチャート:** プロジェクトのタスクを視覚的に表現するガントチャートを作成します。
- **クリティカルパス:** プロジェクトの完了に最も影響を与えるタスクのシーケンスを特定します。
- **リソース平準化:** リソースの負荷を均等化し、リソースの過剰な割り当てを避けます。
- **リスク評価:** リスクの発生確率と影響度を評価し、優先順位を付けます。

#### 応用例とユースケース

- **ソフトウェア開発プロジェクト:** ソフトウェア開発プロジェクトの管理に活用します。
- **建設プロジェクト:** 建設プロジェクトの管理に活用します。
- **マーケティングキャンペーン:** マーケティングキャンペーンの管理に活用します。
- **イベント企画:** イベント企画の管理に活用します。

#### トラブルシューティング

- **ガントチャートが正しく表示されない:** ガントチャートの設定を確認します。タスクの依存関係が正しく設定されていることを確認します。
- **リソースの割り当てがうまくいかない:** リソースの可用性を確認します。リソースのスキルとタスクの要件が一致していることを確認します。
- **リスクが早期に特定できない:** リスク管理プロセスを見直します。関係者からのフィードバックを収集します。

#### まとめと次のステップ

カスタムのプロジェクト管理アプリケーションを作成することで、プロジェクトの可視性を高め、リソースを効率的に割り当て、リスクを管理することができます。次のステップとして、組織の具体的なニーズに合わせてプロジェクト管理アプリケーションをカスタマイズし、テストを行い、デプロイしてください。

### ナレッジ管理のカスタムアプリケーション

#### 概要と重要性

ナレッジ管理は、組織の知識を収集、整理、共有、および活用するための体系的なプロセスです。カスタムのナレッジ管理アプリケーションを作成することで、従業員が容易に知識にアクセスし、共有し、活用できるようになり、組織全体の生産性向上に貢献します。

#### 特徴と利点

- **知識の集約:** 組織全体の知識を一元的に管理します。
- **容易なアクセス:** 従業員が容易に知識にアクセスできるようにします。
- **知識の共有:** 従業員が知識を共有し、協力関係を促進します。
- **検索性の向上:** 必要な情報を迅速に見つけられるようにします。
- **ナレッジベースの構築:** 組織の知識資産を構築し、長期的に活用できるようにします。

#### 事前準備と前提条件

- ServiceNow インスタンス
- App Engine Studio プラグイン
- ナレッジ管理に必要なデータモデルの設計（例：ナレッジ記事テーブル、カテゴリテーブル、キーワードテーブルなど）

#### 基本的な使い方

1.  **データモデルの作成:** ナレッジ記事テーブル、カテゴリテーブル、キーワードテーブルを作成し、それぞれのテーブルに必要なフィールド（記事タイトル、記事内容、カテゴリ、キーワード、公開日、最終更新日など）を追加します。
2.  **UI の設計:** ナレッジ記事の作成フォーム、検索ページ、記事詳細ページなどを UI Builder で作成します。
3.  **ワークフローの設計:** Flow Designer でナレッジ記事の承認ワークフローを設計します。

**コードスニペット (REST API):**

外部システムからナレッジ記事を検索するための REST API エンドポイントを以下に示します。

```javascript
// スクリプトインクルード (REST Message):
var KnowledgeSearchAPI = Class.create();
KnowledgeSearchAPI.prototype = {
  process: function () {
    var searchTerm = this.getParameter("term");
    var response = [];

    var gr = new GlideRecord("kb_knowledge");
    gr.addQuery("short_description", "CONTAINS", searchTerm); // 例：記事のタイトルにキーワードが含まれているか検索
    gr.query();

    while (gr.next()) {
      response.push({
        sys_id: gr.getValue("sys_id"),
        title: gr.getValue("short_description"),
        content: gr.getValue("text"), // 例：記事の内容
      });
    }

    return JSON.stringify(response);
  },

  type: "KnowledgeSearchAPI",
};
```

#### 実践的なテクニック

- **カテゴリ構造:** ナレッジ記事を体系的に整理するためのカテゴリ構造を設計します。
- **キーワード:** 検索性を向上させるために、適切なキーワードを設定します。
- **レーティングとコメント:** ユーザーがナレッジ記事を評価し、コメントできるようにします。
- **FAQ:** よくある質問とその回答をまとめて FAQ を作成します。
- **検索エンジン最適化 (SEO):** ナレッジ記事が検索エンジンで上位表示されるように最適化します。

#### 応用例とユースケース

- **IT サポート:** IT サポートに関するナレッジベースを構築します。
- **人事:** 人事に関するナレッジベースを構築します。
- **顧客サービス:** 顧客サービスに関するナレッジベースを構築します。
- **製品ドキュメント:** 製品ドキュメントをナレッジベースとして公開します。

#### トラブルシューティング

- **検索結果が正確でない:** キーワードを見直します。カテゴリ構造を見直します。検索エンジンの設定を確認します。
- **ナレッジ記事の作成が促進されない:** ナレッジ記事の作成を奨励するインセンティブを導入します。ナレッジ記事の作成プロセスを簡素化します。
- **ナレッジ記事が古い:** ナレッジ記事の定期的なレビューと更新を行います。

#### まとめと次のステップ

カスタムのナレッジ管理アプリケーションを作成することで、従業員が容易に知識にアクセスし、共有し、活用できるようになり、組織全体の生産性向上に貢献します。次のステップとして、組織の具体的なニーズに合わせてナレッジ管理アプリケーションをカスタマイズし、テストを行い、デプロイしてください。

## 14.3 ServiceNow Store への公開：収益化のチャンス

### ServiceNow Store の概要と登録方法

#### 概要と重要性

ServiceNow Store は、ServiceNow プラットフォーム上で動作するアプリケーション、インテグレーション、およびソリューションを販売、配布するための公式マーケットプレイスです。自社で開発したカスタムアプリケーションを ServiceNow Store に公開することで、ServiceNow ユーザー全体にリーチし、収益化の機会を得ることができます。これは、開発コストの回収、ブランド認知度の向上、そして新たなビジネスチャンスの創出につながります。

#### 特徴と利点

- **幅広いリーチ:** 世界中の ServiceNow ユーザーにアプリケーションを提供できます。
- **収益化の機会:** アプリケーションを販売することで収益を得ることができます。
- **ブランド認知度の向上:** ServiceNow Store に掲載されることで、ブランドの認知度を高めることができます。
- **マーケティングサポート:** ServiceNow からマーケティングサポートを受けることができます。
- **セキュリティと品質:** ServiceNow Store に掲載されるアプリケーションは、厳格なセキュリティと品質基準を満たす必要があります。

#### 事前準備と前提条件

- **ServiceNow パートナープログラムへの参加:** ServiceNow Store にアプリケーションを公開するには、ServiceNow パートナープログラムに参加する必要があります。パートナープログラムには、無料の Developer Program と、有料の Technology Partner Program があります。
- **開発したアプリケーション:** ServiceNow プラットフォーム上で動作するカスタムアプリケーションが必要です。
- **ServiceNow Store アカウント:** ServiceNow Store にアクセスするためのアカウントが必要です。
- **ビジネスプラン:** アプリケーションの価格設定、マーケティング戦略、サポート体制などをまとめたビジネスプランが必要です。

#### ServiceNow Store への登録方法

1.  **ServiceNow パートナープログラムへの参加:** ServiceNow パートナープログラムに申し込みます。
2.  **ServiceNow Store アカウントの作成:** ServiceNow Store にアクセスするためのアカウントを作成します。
3.  **アプリケーションの準備:** アプリケーションを ServiceNow インスタンスからエクスポートし、必要なドキュメント（ユーザーガイド、リリースノートなど）を準備します。
4.  **リスティングの作成:** ServiceNow Store にログインし、アプリケーションのリスティングを作成します。リスティングには、アプリケーション名、説明、価格、スクリーンショット、ビデオなどを記載します。
5.  **審査:** ServiceNow による審査を受けます。審査では、アプリケーションの機能、セキュリティ、品質などが評価されます。
6.  **公開:** 審査に合格したら、アプリケーションを ServiceNow Store に公開します。

**注意点:**

- ServiceNow Store に掲載されるアプリケーションは、ServiceNow の厳格なセキュリティと品質基準を満たす必要があります。
- アプリケーションのリスティングは、正確かつ魅力的な内容で記述する必要があります。
- アプリケーションのサポート体制を整えておくことが重要です。

### アプリケーションのパッケージングと公開

#### 概要と重要性

アプリケーションを ServiceNow Store に公開する前に、適切な形式でパッケージングする必要があります。パッケージングとは、アプリケーションとその関連ファイルを一つのファイルにまとめる作業です。適切なパッケージングは、アプリケーションのインストールとアップグレードを容易にし、ユーザーエクスペリエンスを向上させます。

#### パッケージングの手順

1.  **アプリケーションのスコープ:** アプリケーションがスコープアプリケーションであることを確認します。スコープアプリケーションは、グローバルスコープアプリケーションと比較して、名前空間の衝突を回避し、安全な開発環境を提供します。
2.  **アプリケーションの完全性:** アプリケーションが依存する全てのコンポーネント（スクリプトインクルード、ビジネスルール、UI アクションなど）が含まれていることを確認します。
3.  **アップデートセットのエクスポート:** アプリケーションをアップデートセットとしてエクスポートします。アップデートセットには、アプリケーションとその関連ファイルが含まれています。
4.  **アップデートセットの検証:** エクスポートされたアップデートセットを別の ServiceNow インスタンスにインポートし、アプリケーションが正常に動作することを確認します。
5.  **アプリケーションのドキュメント化:** アプリケーションの使用方法、設定方法、トラブルシューティングなどを説明するドキュメントを作成します。
6.  **アプリケーションのテスト:** アプリケーションを徹底的にテストし、バグやセキュリティ上の脆弱性がないことを確認します。

#### 公開の手順

1.  **ServiceNow Store へのログイン:** ServiceNow Store にログインします。
2.  **アプリケーションのアップロード:** パッケージングされたアプリケーション（アップデートセット）とドキュメントを ServiceNow Store にアップロードします。
3.  **リスティング情報の入力:** アプリケーション名、説明、価格、カテゴリ、キーワードなどのリスティング情報を入力します。
4.  **スクリーンショットとビデオの追加:** アプリケーションのスクリーンショットとビデオを追加します。
5.  **価格設定:** アプリケーションの価格を設定します。無料、有料、またはサブスクリプションモデルを選択できます。
6.  **審査の申請:** ServiceNow による審査を申請します。
7.  **公開:** 審査に合格したら、アプリケーションを ServiceNow Store に公開します。

**コードスニペット (アップデートセットのエクスポート):**

ServiceNow インスタンスからアップデートセットをエクスポートするには、以下の手順を実行します。

1.  System Update Sets > Local Update Sets に移動します。
2.  エクスポートするアップデートセットを選択します。
3.  "Export to XML" ボタンをクリックして、アップデートセットを XML ファイルとしてダウンロードします。

**注意点:**

- アップデートセットは、アプリケーションの全てのコンポーネントが含まれている必要があります。
- アプリケーションのドキュメントは、分かりやすく、正確である必要があります。
- アプリケーションのテストは、徹底的に行い、バグやセキュリティ上の脆弱性がないことを確認する必要があります。

### マーケティングとサポート

#### 概要と重要性

アプリケーションを ServiceNow Store に公開した後、マーケティングとサポートは成功に不可欠です。効果的なマーケティングは、アプリケーションの認知度を高め、ダウンロード数を増やします。質の高いサポートは、顧客満足度を高め、長期的な顧客関係を構築します。

#### マーケティング戦略

- **ServiceNow Store 内での最適化:** アプリケーションのリスティングを最適化し、検索結果で上位表示されるようにします。キーワード、説明、スクリーンショット、ビデオなどを効果的に活用します。
- **ソーシャルメディア:** ソーシャルメディア（LinkedIn、Twitter など）を活用し、アプリケーションに関する情報を発信します。
- **ブログ:** アプリケーションに関するブログ記事を投稿し、ターゲットオーディエンスにリーチします。
- **ServiceNow コミュニティ:** ServiceNow コミュニティに参加し、アプリケーションに関する質問に答えたり、情報を共有したりします。
- **Web サイト:** 自社の Web サイトにアプリケーションに関する情報を掲載します。
- **ServiceNow イベント:** ServiceNow のイベントに参加し、アプリケーションを紹介します。
- **プレスリリース:** アプリケーションのリリースをプレスリリースとして発表します。

#### サポート体制

- **ドキュメント:** アプリケーションの使用方法、設定方法、トラブルシューティングなどを説明するドキュメントを提供します。
- **FAQ:** よくある質問とその回答をまとめた FAQ を提供します。
- **メールサポート:** ユーザーからの問い合わせにメールで対応します。
- **電話サポート:** ユーザーからの問い合わせに電話で対応します。
- **ServiceNow コミュニティ:** ServiceNow コミュニティでユーザーからの質問に答えたり、問題を解決したりします。
- **アップデート:** アプリケーションのバグ修正、機能改善、セキュリティアップデートなどを定期的に提供します。

**コードスニペット (ServiceNow コミュニティでのサポート):**

ServiceNow コミュニティでユーザーからの質問に答える例を以下に示します。

1.  ServiceNow コミュニティにアクセスします。
2.  アプリケーションに関する質問を検索します。
3.  質問に答えたり、問題を解決したりします。
4.  必要に応じて、ドキュメントや FAQ へのリンクを提供します。

**注意点:**

- マーケティング戦略は、ターゲットオーディエンスに合わせて調整する必要があります。
- サポート体制は、迅速かつ効果的である必要があります。
- ユーザーからのフィードバックを積極的に収集し、アプリケーションの改善に役立てる必要があります。

### まとめ

カスタムアプリケーションを開発し、ServiceNow Store に公開することは、組織にとって収益化の機会とブランド認知度の向上につながります。この章で説明した手順とベストプラクティスに従って、成功を収めてください。ServiceNow のローコード開発プラットフォームを活用し、ビジネスの課題を解決する革新的なアプリケーションを開発し、世界中の ServiceNow ユーザーに提供しましょう。
