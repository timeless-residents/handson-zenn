## 第 13 章：DevOps 実践：開発ライフサイクルを加速する

### 13.1 ServiceNow DevOps の概要とメリット

**概要と重要性**

現代のソフトウェア開発は、ビジネスの要求に応えるために、より迅速かつ頻繁なリリースが求められています。この要求に応えるための開発手法が DevOps です。DevOps は、開発チームと運用チームが連携し、ソフトウェア開発ライフサイクル全体を自動化・効率化することで、開発スピードの向上、品質の向上、リスクの軽減を実現します。

ServiceNow DevOps は、ServiceNow プラットフォーム上で DevOps を実現するためのソリューションです。ServiceNow の持つワークフロー自動化、ITSM（IT サービスマネジメント）の機能と、アジャイル開発、CI/CD（継続的インテグレーション/継続的デリバリー）、IaC（Infrastructure as Code）などの DevOps プラクティスを統合することで、より効率的な開発ライフサイクルを構築できます。

**特徴と利点**

ServiceNow DevOps の主な特徴と利点は以下の通りです。

- **アジャイル開発との統合:** アジャイル開発で定義されたストーリーやタスクを ServiceNow で管理し、開発プロセス全体を可視化します。これにより、進捗状況の把握や課題の早期発見が容易になります。
- **CI/CD パイプラインの自動化:** GitHub、Jenkins などの DevOps ツールと連携し、コードのコミットからデプロイまでのプロセスを自動化します。これにより、手作業によるミスを減らし、リリースサイクルを短縮できます。
- **IaC による環境構築の自動化:** Terraform、Ansible などの IaC ツールと連携し、インフラストラクチャのプロビジョニングや構成管理を自動化します。これにより、環境構築にかかる時間を短縮し、環境の一貫性を保つことができます。
- **変更管理の自動化:** ServiceNow DevOps Change Management を活用することで、変更要求の承認プロセスを自動化し、変更に伴うリスクを軽減します。
- **構成管理データベース（CMDB）との連携:** ServiceNow CMDB と連携することで、インフラストラクチャやアプリケーションの構成情報を一元管理し、変更による影響を正確に把握することができます。

ServiceNow DevOps を利用することで、開発スピードの向上、ソフトウェア品質の向上、インフラコストの削減、リスクの軽減など、多くのメリットを享受できます。

**事前準備と前提条件**

ServiceNow DevOps を利用するためには、以下の準備が必要です。

- **ServiceNow インスタンス:** ServiceNow のサブスクリプションが必要です。
- **DevOps プラグインの有効化:** ServiceNow ストアから DevOps プラグインをインストールし、有効化する必要があります。
- **DevOps ツールの準備:** GitHub、Jenkins、Terraform、Ansible などの DevOps ツールをインストールし、設定する必要があります。
- **ServiceNow ユーザーの権限設定:** DevOps ツールとの連携に必要な ServiceNow ユーザーの権限を設定する必要があります。
- **API キーの設定:** DevOps ツールと ServiceNow 間の認証に必要な API キーを設定する必要があります。

**基本的な使い方**

ServiceNow DevOps の基本的な使い方は以下の通りです。

1.  **アジャイル開発:** ServiceNow Agile Development モジュールを使用して、アジャイル開発のストーリーやタスクを管理します。
2.  **CI/CD パイプラインの定義:** ServiceNow DevOps CI/CD モジュールを使用して、CI/CD パイプラインを定義します。
3.  **IaC スクリプトの作成:** Terraform または Ansible を使用して、インフラストラクチャの定義と構成管理のためのスクリプトを作成します。
4.  **DevOps ツールとの連携設定:** ServiceNow と GitHub、Jenkins、Terraform、Ansible などの DevOps ツールとの連携を設定します。
5.  **パイプラインの実行:** コードのコミットをトリガーとして、CI/CD パイプラインを実行します。
6.  **デプロイの監視:** ServiceNow DevOps Monitoring モジュールを使用して、デプロイの状況を監視します。
7.  **問題の解決:** 問題が発生した場合、ServiceNow Incident Management モジュールを使用して、インシデントを管理し、解決します。

**実践的なテクニック**

- **パイプラインの最適化:** CI/CD パイプラインの各ステップにかかる時間を分析し、ボトルネックを特定して改善します。キャッシュの利用、並列処理、テストの最適化などを検討しましょう。
- **セキュリティテストの自動化:** 静的コード解析ツールや脆弱性スキャンツールを CI/CD パイプラインに組み込み、セキュリティ上の問題を早期に発見します。
- **テスト環境の自動構築:** IaC を活用して、テスト環境を自動的に構築・破棄することで、テスト環境の管理コストを削減し、テストの並列実行を可能にします。
- **ロールバック戦略の確立:** デプロイに失敗した場合に、迅速にロールバックできるような仕組みを構築します。
- **モニタリングの強化:** アプリケーションのパフォーマンスやインフラストラクチャの状態をリアルタイムで監視し、異常を早期に検知できるような体制を整えます。ServiceNow Event Management や外部のモニタリングツールとの連携を検討しましょう。

**応用例とユースケース**

- **金融機関におけるコンプライアンス対応:** 金融機関では、厳格なコンプライアンス要件を満たす必要があります。ServiceNow DevOps Change Management を活用することで、変更プロセスの監査証跡を確保し、コンプライアンス要件への準拠を支援します。
- **小売業における e コマースサイトの改善:** 小売業では、季節変動やキャンペーンに応じて、e コマースサイトを頻繁に更新する必要があります。ServiceNow DevOps CI/CD モジュールを活用することで、リリースサイクルを短縮し、顧客ニーズに迅速に対応できます。
- **製造業における IoT プラットフォームの構築:** 製造業では、IoT プラットフォームを構築し、工場内のデータを収集・分析する必要があります。ServiceNow DevOps IaC モジュールを活用することで、IoT プラットフォームのインフラストラクチャを迅速かつ効率的にプロビジョニングできます。
- **エンタープライズ企業における大規模システムの移行:** 大規模なシステムを移行する際、ServiceNow DevOps を使用することで、移行プロセスを効率化し、リスクを軽減できます。変更管理、テスト自動化、環境構築の自動化などの機能が役立ちます。

**トラブルシューティング**

- **API 連携エラー:** ServiceNow と DevOps ツール間の API 連携がうまくいかない場合は、API キーの設定、ユーザーの権限設定、ネットワーク設定などを確認してください。
- **パイプラインの実行エラー:** CI/CD パイプラインの実行中にエラーが発生した場合は、ログを確認し、エラーの原因を特定してください。エラーメッセージから解決策を見つけるか、関連するドキュメントを参照してください。
- **デプロイの失敗:** デプロイに失敗した場合は、ログを確認し、原因を特定してください。ロールバック戦略に基づいて、迅速にロールバックを実行してください。
- **環境構築のエラー:** IaC スクリプトの実行中にエラーが発生した場合は、スクリプトの構文や設定、Terraform/Ansible のバージョンなどを確認してください。
- **ServiceNow DevOps プラグインのエラー:** ServiceNow DevOps プラグインに問題が発生した場合は、ServiceNow のドキュメントやサポートを参照してください。

**まとめと次のステップ**

ServiceNow DevOps は、開発ライフサイクルを加速し、ビジネス価値を最大化するための強力なソリューションです。本セクションでは、ServiceNow DevOps の概要、メリット、基本的な使い方、実践的なテクニック、応用例、トラブルシューティングについて解説しました。

次のステップとしては、実際に ServiceNow DevOps を導入し、CI/CD パイプラインを構築し、IaC による環境構築の自動化を試してみることをお勧めします。ServiceNow のドキュメントやトレーニングコースを活用して、ServiceNow DevOps の知識を深めることも重要です。

### 13.2 CI/CD パイプラインの構築：GitHub、Jenkins、ServiceNow 連携

**概要と重要性**

CI/CD（継続的インテグレーション/継続的デリバリー）パイプラインは、ソフトウェア開発における変更を自動的にビルド、テスト、デプロイするためのプロセスです。これにより、開発者は頻繁にコードを統合し、変更を迅速にリリースできるようになります。GitHub、Jenkins、ServiceNow を連携させることで、開発からデプロイまでの一連のプロセスを自動化し、開発サイクルを大幅に短縮できます。

**特徴と利点**

- **開発スピードの向上:** コードの変更が自動的にビルド、テスト、デプロイされるため、手作業によるリリース作業が不要になり、開発スピードが向上します。
- **品質の向上:** 自動テストをパイプラインに組み込むことで、バグを早期に発見し、ソフトウェア品質を向上させることができます。
- **リスクの軽減:** 自動デプロイにより、手作業によるミスを減らし、デプロイに伴うリスクを軽減できます。
- **フィードバックループの短縮:** 変更が迅速にリリースされるため、ユーザーからのフィードバックを早期に収集し、製品の改善に役立てることができます。
- **DevOps 文化の醸成:** 開発チームと運用チームが連携し、自動化されたプロセスを通じて協力することで、DevOps 文化を醸成することができます。

**事前準備と前提条件**

- **GitHub アカウント:** ソースコードを管理するための GitHub アカウントが必要です。リポジトリを作成しておきましょう。
- **Jenkins サーバー:** ビルドとテストを自動化するための Jenkins サーバーが必要です。Jenkins をインストールし、基本的な設定を済ませておきましょう。
- **ServiceNow インスタンス:** ServiceNow のサブスクリプションが必要です。
- **ServiceNow DevOps プラグイン:** ServiceNow ストアから DevOps プラグインをインストールし、有効化する必要があります。
- **GitHub プラグイン（Jenkins）:** Jenkins に GitHub プラグインをインストールし、GitHub アカウントとの連携を設定する必要があります。
- **ServiceNow Spoke（Integration Hub）:** ServiceNow Integration Hub に ServiceNow Spoke をインストールします。
- **ServiceNow ユーザーの権限設定:** Jenkins から ServiceNow にアクセスするためのユーザーアカウントを作成し、必要な権限を付与する必要があります（itil ロールなど）。

**基本的な使い方**

1.  **GitHub リポジトリの作成:** ソースコードを管理するための GitHub リポジトリを作成します。
2.  **Jenkins ジョブの作成:** GitHub リポジトリを監視し、コードが変更されたときに自動的にビルドとテストを実行する Jenkins ジョブを作成します。
3.  **ServiceNow へのデプロイ設定:** Jenkins ジョブに、ServiceNow へのデプロイ処理を追加します。ServiceNow Spoke を利用して、Update Set のインポートとコミットを自動化します。
4.  **パイプラインの実行:** GitHub リポジトリにコードをコミットすると、Jenkins ジョブが自動的に実行され、ビルド、テスト、デプロイが行われます。
5.  **ServiceNow での確認:** ServiceNow で Update Set が正常にインポート、コミットされていることを確認します。

**実践的なテクニック**

- **GitHub Webhooks の利用:** GitHub Webhooks を使用することで、コードがコミットされたときに、Jenkins ジョブを自動的にトリガーできます。
- **Jenkinsfile の利用:** Jenkinsfile を使用することで、パイプラインの定義をコードとして管理できます。これにより、パイプラインのバージョン管理や再利用が容易になります。
- **Docker コンテナの利用:** Docker コンテナを使用することで、ビルド環境を再現性高く構築できます。これにより、環境による差異をなくし、より安定したビルドを実現できます。
- **自動テストの強化:** ユニットテスト、結合テスト、E2E テストなど、様々な種類の自動テストをパイプラインに組み込むことで、ソフトウェア品質を向上させることができます。SonarQube などのコード品質分析ツールとの連携も有効です。
- **ServiceNow DevOps Change Management との連携:** ServiceNow DevOps Change Management と連携することで、変更要求の承認プロセスを自動化し、変更に伴うリスクを軽減できます。
- **承認ゲートの追加:** デプロイ前に承認を必要とするステップをパイプラインに追加することで、重要な変更をより慎重に管理できます。

**応用例とユースケース**

- **エンタープライズアプリケーションの継続的なデリバリー:** エンタープライズアプリケーションの継続的なデリバリーを実現するために、GitHub、Jenkins、ServiceNow を連携させた CI/CD パイプラインを構築します。
- **ServiceNow アプリケーションの自動デプロイ:** ServiceNow アプリケーションの Update Set を、GitHub でバージョン管理し、Jenkins で自動的にデプロイするパイプラインを構築します。
- **パッチ適用プロセスの自動化:** セキュリティパッチやバグフィックスを自動的に適用するパイプラインを構築します。

**コードスニペットと設定例**

**Jenkinsfile 例:**

```groovy
pipeline {
    agent any
    stages {
        stage('Checkout') {
            steps {
                git 'https://github.com/your-org/your-repo.git'
            }
        }
        stage('Build') {
            steps {
                sh 'mvn clean install' // 例: Mavenプロジェクトの場合
            }
        }
        stage('Test') {
            steps {
                sh 'mvn test' // 例: Mavenプロジェクトの場合
            }
        }
        stage('Deploy to ServiceNow') {
            steps {
                script {
                    // ServiceNow Spokeを利用してUpdate Setをインポート、コミット
                    def serviceNowResult = invokeServiceNow(
                        connectionAlias: 'your_servicenow_connection',
                        table: 'sys_update_set',
                        operation: 'importUpdateSet',
                        payload: readFile('path/to/your/update_set.xml')
                    )

                    if (serviceNowResult.success) {
                        echo "Update Set imported successfully"

                        def commitResult = invokeServiceNow(
                            connectionAlias: 'your_servicenow_connection',
                            table: 'sys_update_set',
                            operation: 'commitUpdateSet',
                            sys_id: serviceNowResult.sys_id
                        )

                        if (commitResult.success) {
                            echo "Update Set committed successfully"
                        } else {
                            error "Failed to commit Update Set: ${commitResult.error}"
                        }
                    } else {
                        error "Failed to import Update Set: ${serviceNowResult.error}"
                    }
                }
            }
        }
    }
}
```

**ServiceNow Spoke の設定例:**

1.  Integration Hub で ServiceNow Spoke を有効化します。
2.  必要なアクション（Update Set のインポート、コミットなど）を選択し、設定します。
3.  Jenkins から ServiceNow にアクセスするための接続情報を設定します。

**トラブルシューティング**

- **GitHub との連携エラー:** GitHub プラグインの設定、GitHub アカウントの認証情報、リポジトリの URL などを確認してください。
- **Jenkins ジョブの実行エラー:** ログを確認し、エラーの原因を特定してください。
- **ServiceNow との連携エラー:** ServiceNow Spoke の設定、ServiceNow ユーザーの権限、API キーなどを確認してください。
- **Update Set のインポート/コミットエラー:** Update Set の形式、内容、依存関係などを確認してください。
- **Jenkins から ServiceNow への接続エラー:** ファイアウォールの設定、ネットワークの設定などを確認してください。

**まとめと次のステップ**

GitHub、Jenkins、ServiceNow を連携させた CI/CD パイプラインを構築することで、開発サイクルを大幅に短縮し、ソフトウェア品質を向上させることができます。本セクションでは、CI/CD パイプラインの構築方法、実践的なテクニック、応用例、トラブルシューティングについて解説しました。

次のステップとしては、実際に CI/CD パイプラインを構築し、自動テストを組み込み、ServiceNow DevOps Change Management との連携を試してみることをお勧めします。

### 13.3 IaC による環境構築の自動化：Terraform、Ansible、ServiceNow 連携

**概要と重要性**

IaC (Infrastructure as Code)とは、インフラストラクチャをコードとして記述し、自動的にプロビジョニングおよび管理するプラクティスです。Terraform と Ansible は、IaC を実現するための強力なツールであり、ServiceNow と連携することで、環境構築の自動化、構成管理の一貫性、そして変更管理プロセスの効率化を実現できます。

**特徴と利点**

- **環境構築の自動化:** Terraform と Ansible を使用することで、手動での設定作業を減らし、迅速かつ一貫性のある環境構築を実現できます。
- **構成管理の一貫性:** コードとしてインフラストラクチャを定義することで、環境間の差異をなくし、一貫性のある構成を維持できます。
- **バージョン管理:** インフラストラクチャの構成をコードとしてバージョン管理することで、変更履歴を追跡し、必要に応じてロールバックできます。
- **可視性の向上:** ServiceNow CMDB と連携することで、インフラストラクチャの構成情報を一元管理し、可視性を向上させることができます。
- **DevOps プロセスの加速:** 環境構築の自動化により、開発チームは迅速にテスト環境や本番環境をプロビジョニングできるようになり、DevOps プロセスを加速できます。
- **コスト削減:** 環境構築にかかる時間と労力を削減し、人的ミスを減らすことで、コストを削減できます。

**事前準備と前提条件**

- **Terraform のインストール:** Terraform をダウンロードし、インストールする必要があります。Terraform のバージョンは最新版を使うことを推奨します。
- **Ansible のインストール:** Ansible をダウンロードし、インストールする必要があります。 Ansible のバージョンも最新版を使うことを推奨します。
- **ServiceNow インスタンス:** ServiceNow のサブスクリプションが必要です。
- **ServiceNow CMDB:** ServiceNow CMDB が構成されている必要があります。
- **ServiceNow DevOps プラグイン:** ServiceNow ストアから DevOps プラグインをインストールし、有効化する必要があります。
- **ServiceNow ユーザーの権限設定:** Terraform/Ansible から ServiceNow にアクセスするためのユーザーアカウントを作成し、必要な権限を付与する必要があります（cmdb_read, cmdb_write ロールなど）。
- **Terraform プロバイダー/Ansible モジュールのインストール:** Terraform で ServiceNow を操作するためには、ServiceNow Terraform プロバイダーをインストールする必要があります。同様に、Ansible で ServiceNow を操作するためには、ServiceNow Ansible モジュールをインストールする必要があります。

**基本的な使い方**

1.  **Terraform の設定ファイルの作成:** Terraform の設定ファイル（`.tf`ファイル）を作成し、プロビジョニングするインフラストラクチャを記述します。
2.  **Ansible Playbook の作成:** Ansible Playbook を作成し、構成管理のタスクを定義します。
3.  **Terraform の初期化:** `terraform init`コマンドを実行し、Terraform プロバイダーをダウンロードし、初期化します。
4.  **Terraform のプラン作成:** `terraform plan`コマンドを実行し、実行計画を作成します。
5.  **Terraform の適用:** `terraform apply`コマンドを実行し、インフラストラクチャをプロビジョニングします。
6.  **Ansible Playbook の実行:** `ansible-playbook`コマンドを実行し、構成管理タスクを実行します。
7.  **ServiceNow CMDB との連携:** Terraform/Ansible から ServiceNow CMDB に情報を登録し、構成情報を一元管理します。

**実践的なテクニック**

- **モジュール化:** Terraform のモジュールを使用することで、コードの再利用性を高め、複雑さを軽減できます。
- **変数と出力:** Terraform の変数を使用することで、設定値を外部から変更できるようにし、柔軟性を高めます。Terraform の出力を使用することで、プロビジョニングされたリソースの情報を他のツールに連携できます。
- **リモートステートの利用:** Terraform のリモートステートを使用することで、状態ファイルを安全に管理し、チームでの共同作業を容易にします。
- **冪等性の確保:** Ansible Playbook は冪等性を持つように設計し、繰り返し実行しても同じ結果になるようにします。
- **ロールの利用:** Ansible ロールを使用することで、コードの構造化と再利用を促進します。
- **プロビジョナーの活用:** Terraform のプロビジョナーを活用することで、リソース作成後の初期設定を自動化できます。Ansible をプロビジョナーとして使用することも可能です。
- **GitOps:** インフラストラクチャの変更を Git リポジトリにコミットし、自動的に適用する GitOps の手法を導入することで、変更管理をより厳密に行うことができます。

**応用例とユースケース**

- **クラウド環境の自動プロビジョニング:** AWS、Azure、GCP などのクラウド環境に、仮想マシン、ネットワーク、ストレージなどのリソースを自動的にプロビジョニングします。
- **Kubernetes クラスタの構築:** Kubernetes クラスタを自動的に構築し、構成します。
- **データベースサーバーの構築:** データベースサーバーを自動的に構築し、構成します。
- **アプリケーション環境の構築:** アプリケーションに必要な Web サーバー、アプリケーションサーバー、データベースなどを自動的に構築し、構成します。
- **ServiceNow 開発/テスト環境の構築:** ServiceNow の開発/テスト環境を Terraform/Ansible で自動的に構築することで、開発チームが迅速に環境を利用できるようになります。

```yaml
---
- hosts: all
  become: true
  tasks:
    - name: Install Apache
      apt:
        name: apache2
        state: present

    - name: Start Apache
      service:
        name: apache2
        state: started
        enabled: yes
```

**トラブルシューティング**

- **Terraform の実行エラー:** Terraform の設定ファイルに誤りがないか、必要なプロバイダーがインストールされているかを確認してください。ログを確認し、エラーの原因を特定してください。
- **Ansible Playbook の実行エラー:** Ansible Playbook の構文に誤りがないか、必要なモジュールがインストールされているかを確認してください。ログを確認し、エラーの原因を特定してください。
- **ServiceNow との連携エラー:** ServiceNow ユーザーの権限、API キー、ネットワーク設定などを確認してください。
- **CMDB への登録エラー:** CMDB のスキーマ、データ型、必須フィールドなどを確認してください。
- **Terraform/Ansible から ServiceNow への接続エラー:** ファイアウォールの設定、ネットワークの設定などを確認してください。
