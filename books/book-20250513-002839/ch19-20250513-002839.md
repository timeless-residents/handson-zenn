# 第 19 章：ServiceNow の未来：最新トレンドと展望

ServiceNow は、その進化を止めることなく、常に最新技術を取り入れ、プラットフォームとしての価値を高め続けています。本章では、ServiceNow の未来を形作る主要なトレンドである、AI と機械学習の進化、ローコード/ノーコード開発の普及、そしてクラウドネイティブアーキテクチャへの移行について、深く掘り下げて解説します。これらのトレンドを理解し、活用することで、読者の皆様は ServiceNow の可能性を最大限に引き出し、ビジネスの成長を加速させることができるでしょう。

## 19.1 AI、機械学習の進化

### 19.1.1 概要と重要性

AI（人工知能）と機械学習（ML）は、ServiceNow の未来において最も重要な要素の一つです。これまで手動で行っていた作業を自動化し、より高度な分析に基づいた意思決定を支援することで、業務効率を飛躍的に向上させます。自然言語処理(NLP)の進化により、人間が普段使う言葉でシステムと対話できるようになり、機械学習による自動化範囲の拡大は、定型業務を劇的に削減します。そして、予測分析は、潜在的な問題を事前に特定し、最適な対応策を講じることを可能にし、プロアクティブな問題解決を支援します。

### 19.1.2 特徴と利点

- **自然言語処理(NLP)の高度化:** 人間の言葉を理解し、意図を正確に解釈することで、ServiceNow との対話がより自然になります。
- **機械学習による自動化範囲の拡大:** 過去のデータに基づいて学習し、繰り返しのタスクや判断を自動化することで、人的リソースをより戦略的な業務に集中させることができます。
- **予測分析による意思決定支援:** 大量のデータを分析し、将来のトレンドやリスクを予測することで、よりデータに基づいた意思決定を支援します。

### 19.1.3 事前準備と前提条件

- ServiceNow インスタンスへの AI Search プラグインのインストールと設定
- 機械学習モデルの学習に必要な十分な量のデータの準備
- AI Search、Virtual Agent、Predictive Intelligence などの各機能の有効化

### 19.1.4 基本的な使い方

**AI Search の設定:**

1.  ServiceNow インスタンスにログインし、「AI Search」モジュールにアクセスします。
2.  検索ソースの設定を行い、検索対象となるテーブルやフィールドを定義します。
3.  同義語やストップワードの設定を行い、検索結果の精度を向上させます。

**Virtual Agent の設定:**

1.  「Virtual Agent」モジュールにアクセスし、会話型のインターフェースを作成します。
2.  自然言語理解(NLU)モデルをトレーニングし、ユーザーの意図を正確に解釈できるようにします。
3.  トピックを作成し、ユーザーが Virtual Agent を通じて実行できるタスクを定義します。

**Predictive Intelligence の設定:**

1.  「Predictive Intelligence」モジュールにアクセスし、予測モデルを作成します。
2.  学習データを選択し、モデルのトレーニングを行います。
3.  予測結果に基づいて、アクションをトリガーするように設定します。

```javascript
// スクリプト例: インシデントの重大度を予測する
(function () {
  var incident = new GlideRecord("incident");
  incident.get(current.sys_id);

  var prediction = sn_ml.Predictor.predict(
    "incident_severity_predictor",
    incident
  );

  if (prediction.confidence > 0.8) {
    incident.setValue("urgency", prediction.predictedValue);
    incident.update();
  }
})();
```

### 19.1.5 実践的なテクニック

- **NLU モデルの継続的な改善:** ユーザーのフィードバックを基に、NLU モデルを定期的にトレーニングし、精度を向上させます。
- **カスタム予測モデルの作成:** 標準の予測モデルだけでなく、ビジネスニーズに合わせて独自の予測モデルを作成します。
- **AI Search のファセット検索の活用:** 検索結果を絞り込むためのファセットを定義し、ユーザーがより迅速に目的の情報にたどり着けるようにします。

### 19.1.6 応用例とユースケース

- **IT サービスデスク:** Virtual Agent による自動応答、AI Search によるナレッジベースの検索、Predictive Intelligence によるインシデントの優先度付け
- **人事:** Virtual Agent による FAQ 対応、AI Search による社内ドキュメントの検索、Predictive Intelligence による離職リスクの予測
- **顧客サービス:** Virtual Agent による顧客対応、AI Search による顧客データの検索、Predictive Intelligence による顧客満足度の予測

### 19.1.7 トラブルシューティング

- **NLU モデルの精度が低い:** 学習データの不足、不適切な NLU モデルの選択、トレーニング不足などが原因として考えられます。より多くのデータでモデルをトレーニングし、適切な NLU モデルを選択し、定期的にモデルを改善することが重要です。
- **AI Search の検索結果が期待通りでない:** 検索ソースの設定が誤っている、同義語やストップワードの設定が不十分などが原因として考えられます。検索ソースの設定を見直し、同義語やストップワードを適切に設定することで、検索結果の精度を向上させることができます。
- **予測モデルの精度が低い:** 学習データの偏り、不適切な特徴量の選択、モデルの複雑さなどが原因として考えられます。学習データの偏りを解消し、適切な特徴量を選択し、モデルのパラメータを調整することで、予測モデルの精度を向上させることができます。

### 19.1.8 まとめと次のステップ

AI と機械学習は、ServiceNow の可能性を大きく広げる強力なツールです。本セクションで解説した内容を参考に、AI Search、Virtual Agent、Predictive Intelligence などの機能を活用し、業務効率の向上、意思決定の支援、そして顧客体験の向上を実現してください。次のステップとしては、ServiceNow の AI と機械学習に関する最新情報を常にキャッチアップし、積極的に新しい機能や技術を試していくことをお勧めします。

## 19.2 ローコード/ノーコード開発の普及

### 19.2.1 概要と重要性

ローコード/ノーコード開発は、プログラミングの知識が少ないビジネスユーザーでも、アプリケーションを開発できる環境を提供します。これにより、IT 部門の負担を軽減し、ビジネス部門が自らニーズに合ったアプリケーションを迅速に開発できるようになります。市民開発者の増加は、アプリケーション開発の民主化を促進し、ビジネス部門主導の開発は、よりビジネスニーズに合致したアプリケーションを生み出すことを可能にします。

### 19.2.2 特徴と利点

- **市民開発者の増加:** プログラミングの知識が少ないビジネスユーザーでも、アプリケーションを開発できるようになります。
- **アプリケーション開発の民主化:** IT 部門だけでなく、ビジネス部門もアプリケーション開発に参加できるようになります。
- **ビジネス部門主導の開発:** ビジネスニーズに合致したアプリケーションを迅速に開発できます。
- **開発コストの削減:** 従来の開発手法に比べて、開発コストを大幅に削減できます。
- **開発期間の短縮:** 迅速なプロトタイピングと反復開発により、開発期間を短縮できます。

### 19.2.3 事前準備と前提条件

- ServiceNow Platform App Engine の有効化
- アプリケーション開発に関する基本的な知識（データモデリング、ワークフロー設計など）
- 開発環境の準備（開発インスタンスの作成など）

### 19.2.4 基本的な使い方

**アプリケーションの作成:**

1.  ServiceNow インスタンスにログインし、「Platform App Engine」モジュールにアクセスします。
2.  「Create Application」をクリックし、新しいアプリケーションを作成します。
3.  アプリケーション名、説明、スコープなどを設定します。

**テーブルの作成:**

1.  アプリケーションナビゲーターで、「Data」 -> 「Tables」を選択します。
2.  「New」をクリックし、新しいテーブルを作成します。
3.  テーブル名、ラベル、カラムなどを定義します。

**フォームの作成:**

1.  アプリケーションナビゲーターで、「Forms」 -> 「Form Layout」を選択します。
2.  フォームに追加するフィールドを選択し、レイアウトを調整します。

**ワークフローの作成:**

1.  アプリケーションナビゲーターで、「Process Automation」 -> 「Flow Designer」を選択します。
2.  「New」をクリックし、新しいフローを作成します。
3.  トリガー、アクション、条件などを設定し、ワークフローを定義します。

```javascript
// スクリプト例: レコードの作成時に自動的に値を設定する
(function executeRule(current, previous /*null when async*/) {
  current.u_assigned_group = "Service Desk";
  current.u_priority = "P3";
})(current, previous);
```

### 19.2.5 実践的なテクニック

- **再利用可能なコンポーネントの作成:** 共通の機能を持つコンポーネントを再利用可能なように作成し、開発効率を向上させます。
- **テスト駆動開発の実践:** テストケースを事前に作成し、テストに合格するコードを開発することで、品質の高いアプリケーションを開発します。
- **バージョン管理の活用:** Git などのバージョン管理ツールを活用し、コードの変更履歴を管理し、共同開発を円滑に進めます。

### 19.2.6 応用例とユースケース

- **シンプルな承認ワークフロー:** 休暇申請、経費精算などの簡単な承認ワークフローをノーコードで構築します。
- **カスタムレポートダッシュボード:** ビジネスユーザーが必要な情報を簡単に把握できるカスタムレポートダッシュボードを作成します。
- **顧客フィードバック収集アプリ:** 顧客からのフィードバックを収集し、分析するためのモバイルアプリをローコードで開発します。
- **ナレッジ共有プラットフォーム:** 社内のナレッジを共有し、検索できるプラットフォームを構築します。

### 19.2.7 トラブルシューティング

- **パフォーマンスの問題:** 大量のデータを扱う場合や、複雑なワークフローを実行する場合に、パフォーマンスの問題が発生することがあります。インデックスの最適化、クエリの改善、ワークフローの分割などにより、パフォーマンスを改善できます。
- **セキュリティの問題:** ローコード/ノーコード開発では、セキュリティに関する知識が不足している開発者がアプリケーションを開発することがあります。適切なアクセス制御、入力検証、データ暗号化などにより、セキュリティを確保する必要があります。
- **ガバナンスの問題:** 市民開発者が自由にアプリケーションを開発すると、システム全体の整合性が損なわれる可能性があります。開発ガイドラインの策定、レビュープロセスの導入、承認プロセスの設定などにより、ガバナンスを強化する必要があります。

### 19.2.8 まとめと次のステップ

ローコード/ノーコード開発は、ServiceNow の可能性をさらに広げる重要な要素です。本セクションで解説した内容を参考に、Platform App Engine を活用し、ビジネスニーズに合ったアプリケーションを迅速に開発してください。次のステップとしては、ServiceNow のローコード/ノーコード開発に関する最新情報を常にキャッチアップし、積極的に新しい機能や技術を試していくことをお勧めします。また、市民開発者を育成するためのトレーニングプログラムを導入することも有効です。

## 19.3 クラウドネイティブアーキテクチャへの移行

### 19.3.1 概要と重要性

クラウドネイティブアーキテクチャは、コンテナ化、マイクロサービス、DevOps などの技術を活用し、クラウド環境に最適化されたアプリケーションを構築するための設計思想です。ServiceNow をクラウドネイティブアーキテクチャに移行することで、スケーラビリティ、可用性、開発速度を向上させることができます。コンテナ化とマイクロサービスは、アプリケーションを独立した小さな単位に分割し、それぞれを独立してデプロイ、スケーリング、管理することを可能にします。これにより、システム全体の一部に障害が発生した場合でも、他の部分には影響を与えずに運用を継続できます。また、開発チームは、それぞれのマイクロサービスに集中して開発を進めることができるため、開発速度が向上します。

### 19.3.2 特徴と利点

- **コンテナ化、マイクロサービス:** アプリケーションを独立した小さな単位に分割し、それぞれを独立してデプロイ、スケーリング、管理できます。
- **スケーラビリティ、可用性の向上:** 需要に応じて自動的にリソースを拡張し、システム全体の可用性を高めることができます。
- **開発速度の向上:** 各チームが独立して開発を進めることができるため、開発速度が向上します。
- **柔軟性と移植性の向上:** さまざまなクラウド環境やオンプレミス環境に柔軟に対応できます。
- **コスト削減:** リソースの効率的な利用により、インフラコストを削減できます。

### 19.3.3 事前準備と前提条件

- Kubernetes などのコンテナオーケストレーションツールの知識
- Docker などのコンテナ技術の知識
- ServiceNow の API に関する知識
- クラウド環境の準備（AWS、Azure、GCP など）

### 19.3.4 基本的な使い方

**コンテナ化:**

1.  ServiceNow の機能を API として公開します。
2.  Docker を使用して、API を呼び出すマイクロサービスをコンテナ化します。
3.  Docker Hub などのコンテナレジストリにコンテナイメージをプッシュします。

**マイクロサービス化:**

1.  アプリケーションを機能ごとに分割し、それぞれの機能をマイクロサービスとして実装します。
2.  各マイクロサービスを独立してデプロイ、スケーリング、管理できるようにします。
3.  API Gateway を使用して、マイクロサービスへのアクセスを制御します。

**Kubernetes によるオーケストレーション:**

1.  Kubernetes クラスタを構築します。
2.  コンテナイメージを Kubernetes にデプロイします。
3.  Kubernetes を使用して、コンテナのデプロイ、スケーリング、管理を自動化します。

```yaml
# Kubernetes Deploymentの例
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-servicenow-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-servicenow-app
  template:
    metadata:
      labels:
        app: my-servicenow-app
    spec:
      containers:
        - name: my-servicenow-app
          image: your-docker-hub-account/my-servicenow-app:latest
          ports:
            - containerPort: 8080
```

### 19.3.5 実践的なテクニック

- **API 優先設計:** すべての機能を API として公開し、API を介して相互に連携するように設計します。
- **継続的インテグレーション/継続的デリバリー(CI/CD)パイプラインの構築:** コードの変更を自動的にテスト、ビルド、デプロイするための CI/CD パイプラインを構築します。
- **モニタリングとロギング:** システム全体のパフォーマンスを監視し、問題が発生した場合に迅速に対応できるように、モニタリングとロギングの仕組みを導入します。

### 19.3.6 応用例とユースケース

- **大規模なインシデント管理システム:** 大量のインシデントを効率的に処理できる、スケーラブルなインシデント管理システムを構築します。
- **グローバルなサービスカタログ:** 世界中のユーザーが利用できる、可用性の高いサービスカタログを構築します。
- **リアルタイム分析ダッシュボード:** リアルタイムでデータを分析し、可視化できるダッシュボードを構築します。

### 19.3.7 トラブルシューティング

- **コンテナ間の通信の問題:** コンテナ間のネットワーク設定が誤っている場合や、ファイアウォールが通信をブロックしている場合に、通信の問題が発生することがあります。ネットワーク設定を見直し、ファイアウォールルールを適切に設定することで、問題を解決できます。
- **スケーリングの問題:** リソースの不足、設定の誤り、アプリケーションのボトルネックなどが原因で、スケーリングがうまくいかないことがあります。リソースを増強し、設定を見直し、アプリケーションのボトルネックを解消することで、スケーリングの問題を解決できます。
- **セキュリティの問題:** コンテナイメージに脆弱性がある場合や、API の認証が不十分な場合に、セキュリティの問題が発生することがあります。コンテナイメージを定期的にスキャンし、API の認証を強化することで、セキュリティを確保する必要があります。

### 19.3.8 まとめと次のステップ

クラウドネイティブアーキテクチャへの移行は、ServiceNow のパフォーマンス、スケーラビリティ、可用性を大幅に向上させるための重要なステップです。本セクションで解説した内容を参考に、コンテナ化、マイクロサービス、Kubernetes などの技術を活用し、クラウド環境に最適化されたアプリケーションを構築してください。次のステップとしては、ServiceNow のクラウドネイティブアーキテクチャに関する最新情報を常にキャッチアップし、積極的に新しい機能や技術を試していくことをお勧めします。また、DevOps プラクティスを導入し、開発、テスト、デプロイの自動化を進めることも有効です。
