## 第 10 章：セキュリティ対策：安全な ServiceNow 環境の構築

ServiceNow は企業の重要な情報を扱うプラットフォームであるため、適切なセキュリティ対策は不可欠です。この章では、安全な ServiceNow 環境を構築するためのアクセス制御、データ暗号化、脆弱性対策について解説します。初心者から上級者まで、幅広い読者が理解できるように、実践的なコードスニペットや設定例を交えながら、段階的に説明していきます。

### 10.1 アクセス制御：ACL、ロール、グループの設定

#### 概要と重要性

アクセス制御は、ServiceNow 環境におけるセキュリティの根幹をなすものです。誰がどのデータにアクセスできるか、どのような操作を実行できるかを厳密に管理することで、不正アクセスや情報漏洩のリスクを軽減できます。ACL（Access Control List）、ロール、グループを適切に設定することで、最小権限の原則に基づいた安全な環境を構築できます。

#### 特徴と利点

- **ACL:** データへのアクセスを制御するルールを定義します。テーブル、レコード、フィールドレベルで細かくアクセス権を制御できます。
- **ロール:** ユーザーに特定の権限を付与するための集合体です。ロールを割り当てることで、ユーザーは特定のモジュールや機能にアクセスできるようになります。
- **グループ:** ユーザーを論理的にまとめるための単位です。グループにロールを割り当てることで、グループに所属するすべてのユーザーに同じ権限を付与できます。

これらの要素を組み合わせることで、組織の構造や業務プロセスに合わせた柔軟なアクセス制御を実現できます。

#### 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限が必要です。
- 組織の役割と責任範囲を明確にしておく必要があります。
- 各ユーザーの職務内容と必要なアクセス権を把握しておく必要があります。

#### 基本的な使い方

**1. ACL ルールの設計と実装**

ACL ルールは、`テーブル.フィールド.操作` のような形式で定義されます。例えば、`incident.number.read` はインシデントテーブルのナンバーフィールドへの読み取りアクセスを制御します。

```javascript
// 例：インシデントテーブルのナンバーフィールドへの読み取りアクセスを制限するACLルール
(function () {
  // 現在のユーザーがサポートグループに所属しているか確認
  if (gs.getUser().isMemberOf("Service Desk")) {
    answer = true;
  } else {
    answer = false;
  }
})();
```

**設定手順:**

1.  ServiceNow にログインし、「システムセキュリティ」>「ACL」に移動します。
2.  「新規」ボタンをクリックして新しい ACL ルールを作成します。
3.  テーブル、フィールド、操作（読み取り、書き込み、作成、削除など）を選択します。
4.  「Requires role」や「Advanced」スクリプトを使用して、詳細なアクセス条件を定義します。
5.  「送信」ボタンをクリックしてルールを保存します。

**2. ロールとグループの適切な割り当て**

ロールは、ユーザーに特定の権限を付与するために使用されます。ServiceNow には、`itil`、`admin`、`snc_internal`などの標準ロールが用意されていますが、必要に応じてカスタムロールを作成することもできます。

**設定手順:**

1.  ServiceNow にログインし、「ユーザー管理」>「ロール」に移動します。
2.  既存のロールを選択するか、「新規」ボタンをクリックして新しいロールを作成します。
3.  ロールにアクセス権を付与するモジュールや機能を選択します。
4.  「関連リスト」>「ロールを付与されたユーザー」で、ロールをユーザーに割り当てます。
5.  必要に応じて、ロールをグループに割り当てます。

**3. 最小権限の原則**

最小権限の原則とは、ユーザーに必要最小限の権限のみを付与するという考え方です。不要な権限を付与すると、誤操作や不正アクセスのリスクが高まります。ロールとグループを適切に管理し、ユーザーの職務内容に合わせて必要な権限のみを付与するように心がけましょう。

#### 実践的なテクニック

- **スクリプトによる動的なアクセス制御:** ACL ルールの「Advanced」スクリプトを使用すると、ユーザーの属性や状況に応じてアクセス権を動的に制御できます。
- **ロール継承:** 複数のロールを組み合わせて、ユーザーに複合的な権限を付与できます。
- **グループの階層化:** グループを階層化することで、大規模な組織におけるアクセス制御を効率的に管理できます。

#### 応用例とユースケース

- **インシデント管理:** サポートグループのメンバーのみがインシデントを閲覧・編集できるようにする。
- **変更管理:** 承認者のみが変更リクエストを承認できるようにする。
- **ナレッジ管理:** 特定の部署のメンバーのみがナレッジ記事を作成・編集できるようにする。

#### トラブルシューティング

- **アクセス拒否が発生した場合:** ACL ルールとロールの割り当てを確認し、必要な権限が付与されているか確認します。
- **予期しないアクセス権が付与されている場合:** ロールの継承関係を確認し、不要なロールが割り当てられていないか確認します。
- **スクリプトエラーが発生した場合:** スクリプト構文を確認し、エラーメッセージを参考に修正します。

#### まとめと次のステップ

アクセス制御は、ServiceNow 環境のセキュリティを確保するための重要な要素です。ACL ルール、ロール、グループを適切に設定し、最小権限の原則を遵守することで、安全な環境を構築できます。次のステップとして、データ暗号化について学習しましょう。

### 10.2 データ暗号化：機密データの保護

#### 概要と重要性

データ暗号化は、ServiceNow 環境に保存されている機密データを保護するための重要な手段です。暗号化することで、不正アクセスが発生した場合でも、データの内容を読み取られるリスクを軽減できます。ServiceNow では、フィールドレベル暗号化とデータベース暗号化の 2 つの方法でデータを暗号化できます。

#### 特徴と利点

- **フィールドレベル暗号化:** 特定のフィールドに格納されたデータを暗号化します。クレジットカード番号や社会保障番号などの機密データを保護するのに適しています。
- **データベース暗号化:** データベース全体を暗号化します。広範囲なデータを保護するのに適していますが、パフォーマンスに影響を与える可能性があります。
- **キー管理:** 暗号化に使用するキーを安全に管理するための仕組みです。キーが漏洩すると、暗号化されたデータも漏洩する可能性があるため、適切なキー管理が重要です。

#### 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限が必要です。
- 暗号化対象となるデータを特定しておく必要があります。
- 暗号化に使用するキー管理方法を決定しておく必要があります。

#### 基本的な使い方

**1. フィールドレベル暗号化**

フィールドレベル暗号化を使用すると、特定のフィールドに格納されたデータを暗号化できます。

**設定手順:**

1.  ServiceNow にログインし、「システム定義」>「辞書」に移動します。
2.  暗号化するフィールドを選択します。
3.  「属性」フィールドに、`encryption_type=glide_encryption` を追加します。
4.  「更新」ボタンをクリックして変更を保存します。
5.  暗号化キーを作成し、フィールドに割り当てます。

**例:**

```
// ユーザーテーブルの電話番号フィールドを暗号化する
属性: encryption_type=glide_encryption
```

**2. データベース暗号化**

データベース暗号化を使用すると、データベース全体を暗号化できます。

**設定手順:**

1.  ServiceNow サポートに連絡して、データベース暗号化を有効にしてもらいます。
2.  暗号化キーを作成し、データベースに割り当てます。

**注意:** データベース暗号化は、パフォーマンスに影響を与える可能性があるため、事前に十分なテストが必要です。

**3. キー管理**

暗号化に使用するキーを安全に管理することが重要です。ServiceNow では、以下の方法でキーを管理できます。

- **ローカルキー管理:** ServiceNow インスタンスにキーを保存します。
- **外部キー管理:** 外部のキー管理システムにキーを保存します。

外部キー管理を使用すると、キーのセキュリティを向上させることができます。

#### 実践的なテクニック

- **暗号化されたデータの検索:** 暗号化されたデータでも、特定の条件で検索できるように、トークン化などの技術を使用できます。
- **暗号化されたデータのマスキング:** 暗号化されたデータを表示する際に、一部をマスキングすることで、機密情報を保護できます。

#### 応用例とユースケース

- **人事管理:** 従業員の個人情報を暗号化する。
- **顧客管理:** 顧客のクレジットカード情報を暗号化する。
- **医療情報管理:** 患者の医療情報を暗号化する。

#### トラブルシューティング

- **暗号化されたデータが正しく表示されない場合:** 暗号化キーが正しく設定されているか確認します。
- **パフォーマンスが低下した場合:** データベース暗号化の影響を調査し、必要に応じてチューニングを行います。
- **キーが紛失した場合:** バックアップからキーを復元するか、新しいキーを作成してデータを再暗号化します。

#### まとめと次のステップ

データ暗号化は、ServiceNow 環境に保存されている機密データを保護するための重要な手段です。フィールドレベル暗号化とデータベース暗号化を適切に活用し、キー管理を徹底することで、安全な環境を構築できます。次のステップとして、脆弱性対策について学習しましょう。

### 10.3 脆弱性対策：定期的なセキュリティチェックとアップデート

#### 概要と重要性

ServiceNow 環境は、常に最新のセキュリティ脅威にさらされています。脆弱性対策は、これらの脅威から ServiceNow 環境を保護するための重要な活動です。ServiceNow セキュリティアドバイザリの確認、定期的な脆弱性スキャン、最新パッチの適用を行うことで、セキュリティリスクを軽減できます。

#### 特徴と利点

- **ServiceNow セキュリティアドバイザリ:** ServiceNow が公開するセキュリティに関する情報です。脆弱性に関する情報や対応策が記載されています。
- **定期的な脆弱性スキャン:** ServiceNow 環境に存在する脆弱性を検出するためのスキャンです。
- **最新パッチの適用:** 脆弱性を修正するためのソフトウェアアップデートです。

これらの活動を定期的に行うことで、ServiceNow 環境のセキュリティレベルを維持できます。

#### 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限が必要です。
- 脆弱性スキャンツールを準備しておく必要があります。
- パッチ適用計画を立てておく必要があります。

#### 基本的な使い方

**1. ServiceNow セキュリティアドバイザリの確認**

ServiceNow セキュリティアドバイザリは、ServiceNow サポートポータルで確認できます。

**確認手順:**

1.  ServiceNow サポートポータルにログインします。
2.  「セキュリティアドバイザリ」を検索します。
3.  最新のアドバイザリを確認し、影響を受けるモジュールやバージョンを確認します。
4.  アドバイザリに記載されている対応策を実施します。

**2. 定期的な脆弱性スキャン**

脆弱性スキャンツールを使用すると、ServiceNow 環境に存在する脆弱性を検出できます。

**スキャン手順:**

1.  脆弱性スキャンツールをインストールし、設定します。
2.  ServiceNow インスタンスに対してスキャンを実行します。
3.  スキャン結果を確認し、検出された脆弱性を特定します。
4.  脆弱性に対応するための対策を実施します。

**3. 最新パッチの適用**

ServiceNow は、定期的に新しいパッチをリリースします。これらのパッチには、脆弱性の修正が含まれています。

**適用手順:**

1.  ServiceNow インスタンスにログインします。
2.  「システムアップデート」>「利用可能なアップグレード」に移動します。
3.  利用可能なパッチを確認し、適用します。
4.  パッチ適用後、正常に動作するかテストします。

**注意:** パッチ適用前に、必ずバックアップを作成してください。

#### 実践的なテクニック

- **自動化された脆弱性スキャン:** 脆弱性スキャンを自動化することで、定期的なチェックを効率的に行うことができます。
- **パッチ適用テスト環境:** 本番環境にパッチを適用する前に、テスト環境で動作確認を行うことで、予期せぬ問題を防ぐことができます。

#### 応用例とユースケース

- **コンプライアンス対応:** PCI DSS や HIPAA などのコンプライアンス要件を満たすために、定期的な脆弱性対策を実施する。
- **リスク管理:** 脆弱性スキャン結果に基づいて、セキュリティリスクを評価し、優先順位をつけて対策を実施する。

#### トラブルシューティング

- **パッチ適用後に問題が発生した場合:** バックアップからロールバックするか、ServiceNow サポートに問い合わせます。
- **脆弱性スキャンツールが正常に動作しない場合:** ツールベンダーに問い合わせるか、別のツールを試します。
- **セキュリティアドバイザリの内容が理解できない場合:** ServiceNow サポートに問い合わせます。

#### まとめと次のステップ

脆弱性対策は、ServiceNow 環境を最新のセキュリティ脅威から保護するために不可欠です。ServiceNow セキュリティアドバイザリの確認、定期的な脆弱性スキャン、最新パッチの適用を継続的に行うことで、安全な環境を維持できます。この章で学んだことを実践し、ServiceNow 環境のセキュリティを強化しましょう。
