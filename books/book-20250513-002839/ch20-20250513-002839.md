## 第 20 章：現場で役立つ Tips 集：ServiceNow カスタマイズの裏技

### 20.1 スクリプトデバッグの秘訣：効果的なログ出力、変数監視

**概要と重要性**

ServiceNow のカスタマイズは強力ですが、複雑なスクリプトを書くほど、デバッグの重要性が増します。効果的なデバッグ手法を知っているかどうかで、開発効率は劇的に変わります。このセクションでは、ログ出力と変数監視のテクニックを深掘りし、効率的なデバッグを実現するための秘訣を伝授します。

**特徴と利点**

効果的なログ出力と変数監視は、以下の点で大きな利点をもたらします。

- **問題の早期発見:** 潜在的なバグを早期に発見し、深刻な問題に発展するのを防ぎます。
- **原因特定の迅速化:** エラーが発生した場合、原因を迅速に特定し、解決までの時間を短縮します。
- **コードの理解促進:** スクリプトの実行過程を可視化し、コードの理解を深めます。
- **開発効率の向上:** デバッグ作業の効率を向上させ、全体的な開発時間を短縮します。

**事前準備と前提条件**

- ServiceNow インスタンスへのアクセス権
- ServiceNow スクリプトの基本的な知識（特にサーバーサイドスクリプト）
- スクリプトエディタの使用経験

**基本的な使い方**

1.  **GlideSystem の gs.log()の活用:**

    `gs.log()`は、ServiceNow で最も基本的なログ出力関数です。スクリプトの実行中に特定の情報をログに記録するために使用します。

    ```javascript
    gs.log("スクリプトが開始されました");
    var user = gs.getUser();
    gs.log("現在のユーザー: " + user.getName());
    ```

    ログは、ServiceNow インスタンスの**System Logs > System Log > All**で確認できます。

2.  **スクリプトデバッガの応用:**

    ServiceNow には、スクリプトデバッガが組み込まれています。ブレークポイントを設定し、スクリプトの実行を一時停止し、変数の値をステップごとに確認できます。

    - **ブレークポイントの設定:** スクリプトエディタで、一時停止させたい行の左側をクリックしてブレークポイントを設定します。
    - **デバッグの開始:** スクリプトを実行するアクション（例：ビジネスルールの実行、クライアントスクリプトの実行）を行います。
    - **変数の確認:** デバッガウィンドウで、スコープ内の変数の値をリアルタイムで確認します。

3.  **変数の中身を可視化するテクニック:**

    - **JSON.stringify()の使用:** オブジェクトや配列の内容を文字列としてログに出力できます。複雑なデータ構造のデバッグに役立ちます。

      ```javascript
      var gr = new GlideRecord("incident");
      gr.get("sys_id", "YOUR_INCIDENT_SYS_ID"); // 例としてインシデントのsys_idを指定
      gs.log("インシデントレコードの内容: " + JSON.stringify(gr.getValues()));
      ```

    - **カスタムログテーブルの作成:** より複雑なデバッグ情報を記録するために、カスタムのログテーブルを作成し、スクリプトからデータを書き込むことができます。これは、`gs.log()`では追跡しきれない詳細な情報を記録するのに役立ちます。

**実践的なテクニック**

- **条件付きログ出力:** 特定の条件が満たされた場合にのみログを出力することで、ノイズを減らし、重要な情報に集中できます。

  ```javascript
  var priority = gr.getValue("priority");
  if (priority == "1") {
    gs.log("緊急度の高いインシデント: " + gr.number);
  }
  ```

- **スクリプトインクルードのデバッグ:** スクリプトインクルードをデバッグする場合は、直接呼び出すテストスクリプトを作成し、デバッガを使用するのが効果的です。

- **本番環境でのログ出力の抑制:** 本番環境では、ログ出力を最小限に抑えるか、完全に無効にすることを推奨します。`gs.getProperty()`を使用して、ログ出力の有効/無効を制御するプロパティを作成できます。

  ```javascript
  if (gs.getProperty("my.script.debug") == "true") {
    gs.log("デバッグメッセージ");
  }
  ```

**応用例とユースケース**

- **ビジネスルール:** ビジネスルールが期待どおりに動作しない場合、`gs.log()`を使用して、変数の値、条件の評価結果、実行されたコードパスを記録し、問題を特定します。

- **クライアントスクリプト:** クライアントスクリプトでエラーが発生した場合、ブラウザのコンソール（F12）と`gs.info()` (サーバ側ログ)を組み合わせて、問題の原因を特定します。

- **ワークフロー:** ワークフローが想定通りに進まない場合、ワークフローログと`gs.log()`をワークフローアクティビティに追加して、ワークフローの実行パスと変数の値を追跡します。

**トラブルシューティング**

- **ログが表示されない:** ログレベルが適切に設定されているか、ログがフィルタリングされていないか確認してください。
- **デバッガが機能しない:** 必要な権限があるか、スクリプトが正しく実行されているか確認してください。
- **大量のログが出力される:** 条件付きログ出力を活用し、必要な情報のみを記録するようにしてください。

**まとめと次のステップ**

効果的なログ出力と変数監視は、ServiceNow スクリプトのデバッグに不可欠なスキルです。`gs.log()`、スクリプトデバッガ、`JSON.stringify()`などのツールを駆使し、問題解決能力を向上させましょう。次のステップとして、カスタムログテーブルの作成や、本番環境でのログ出力管理について学習することをお勧めします。

### 20.2 パフォーマンスチューニングの落とし穴：インデックス、クエリ最適化

**概要と重要性**

ServiceNow のパフォーマンスは、ユーザーエクスペリエンスに直接影響します。遅い応答時間は、ユーザーの不満を招き、生産性を低下させます。このセクションでは、インデックス設計とクエリ最適化の重要性を解説し、パフォーマンスチューニングの落とし穴を回避するための実践的なテクニックを紹介します。

**特徴と利点**

適切なパフォーマンスチューニングは、以下の点で大きな利点をもたらします。

- **応答時間の短縮:** ユーザーエクスペリエンスを向上させ、生産性を高めます。
- **システムリソースの効率的な利用:** サーバーの負荷を軽減し、システム全体の安定性を向上させます。
- **スケーラビリティの向上:** 大規模なデータやユーザー数に対応できるようになります。
- **コスト削減:** ハードウェアへの投資を抑え、運用コストを削減します。

**事前準備と前提条件**

- ServiceNow インスタンスへの管理者権限
- GlideRecord クエリの基本的な知識
- SQL の基本的な知識（特にクエリプランの理解）
- Performance Analytics モジュールの知識 (あれば尚可)

**基本的な使い方**

1.  **インデックス設計のアンチパターン:**

    - **過剰なインデックス:** 不要なインデックスは、データベースの書き込みパフォーマンスを低下させる可能性があります。必要なインデックスのみを作成するように心がけましょう。
    - **インデックスの順番:** 複合インデックスでは、最もカーディナリティの高い（一意性の高い）列を最初に配置することが重要です。
    - **計算フィールドのインデックス:** 計算フィールドにインデックスを作成することは、通常推奨されません。パフォーマンスが大幅に低下する可能性があります。

2.  **クエリの実行計画の確認:**

    ServiceNow では、クエリの実行計画を直接確認する機能はありません。しかし、システムログで実行されたクエリとその実行時間を分析することで、ボトルネックを特定できます。Performance Analytics モジュールを利用すれば、クエリの実行状況を可視化できます。

3.  **パフォーマンス改善のためのツール:**

    - **Database Index Health:** ServiceNow には、推奨されるインデックスを確認するツールが用意されています。**System Diagnostics > DB Index Health** からアクセスできます。
    - **Performance Analytics:** 特定のトランザクションのパフォーマンスを分析し、ボトルネックを特定できます。
    - **Transaction Log:** 遅いトランザクションを特定し、詳細な情報を確認できます。

**実践的なテクニック**

- **GlideRecord の最適化:**

  - **`addQuery()`と`addEncodedQuery()`の使い分け:** 単純なクエリには`addQuery()`、複雑なクエリには`addEncodedQuery()`を使用します。`addEncodedQuery()`は、クエリ文字列をキャッシュするため、パフォーマンスが向上する可能性があります。

    ```javascript
    // 例：addQuery()
    var gr = new GlideRecord("incident");
    gr.addQuery("category", "hardware");
    gr.query();

    // 例：addEncodedQuery()
    var gr = new GlideRecord("incident");
    gr.addEncodedQuery("category=hardware^priority=1");
    gr.query();
    ```

  - **`setLimit()`の使用:** 必要なレコード数のみを取得するように、`setLimit()`を使用します。

    ```javascript
    var gr = new GlideRecord("incident");
    gr.addQuery("active", true);
    gr.setLimit(10); // 最大10件のレコードを取得
    gr.query();
    ```

  - **`setDisplayValue(false)`の使用:** 表示値を必要としない場合は、`setDisplayValue(false)`を使用することで、パフォーマンスを向上させることができます。

    ```javascript
    var gr = new GlideRecord("incident");
    gr.setDisplayValue(false);
    gr.get("sys_id", "YOUR_INCIDENT_SYS_ID");
    ```

- **リストビューの最適化:**

  - **表示する列の数を最小限にする:** 必要な列のみを表示するように設定します。
  - **参照フィールドの表示値を避ける:** 参照フィールドの表示値を表示する代わりに、sys_id を表示するように設定します。
  - **クライアントサイドスクリプトの最適化:** リストビューで使用するクライアントサイドスクリプトを最適化し、不要な処理を減らします。

- **レポートの最適化:**

  - **適切な集計方法を選択する:** 集計方法がパフォーマンスに大きな影響を与える可能性があります。
  - **レポートのフィルタを最適化する:** 複雑なフィルタは、パフォーマンスを低下させる可能性があります。
  - **レポートのスケジュール実行を検討する:** リアルタイムでレポートを生成する必要がない場合は、スケジュール実行を検討します。

**応用例とユースケース**

- **インシデント管理:** インシデントのリストビューの応答時間を短縮するために、インデックス設計とクエリを最適化します。
- **サービスカタログ:** サービスカタログアイテムの検索パフォーマンスを向上させるために、適切なインデックスを作成し、クエリを最適化します。
- **レポート:** 大量のデータを集計するレポートの実行時間を短縮するために、集計方法とフィルタを最適化します。

**トラブルシューティング**

- **クエリが遅い:** クエリの実行計画を確認し、インデックスが正しく使用されているか確認します。
- **リストビューの応答が遅い:** 表示する列の数、クライアントサイドスクリプト、サーバーサイドスクリプトを最適化します。
- **システム全体のパフォーマンスが低下している:** システムログを確認し、ボトルネックを特定します。

**まとめと次のステップ**

パフォーマンスチューニングは、ServiceNow のパフォーマンスを維持するために継続的に行う必要があります。インデックス設計、クエリ最適化、リストビューの最適化などのテクニックを駆使し、ユーザーエクスペリエンスを向上させましょう。次のステップとして、Performance Analytics モジュールを活用したパフォーマンス監視や、カスタムアプリケーションのパフォーマンスチューニングについて学習することをお勧めします。

### 20.3 トラブルシューティング事例集：よくあるエラーと解決策

**概要と重要性**

ServiceNow のカスタマイズを行う上で、エラーは避けられません。しかし、よくあるエラーとその解決策を知っていることで、迅速な問題解決が可能になります。このセクションでは、現場でよく遭遇するエラーと、その解決策を具体的な事例とともに紹介します。

**特徴と利点**

トラブルシューティング事例集を活用することで、以下の利点があります。

- **問題解決時間の短縮:** 類似のエラーに遭遇した場合、解決策をすぐに参照できます。
- **エラーの再発防止:** エラーの原因を理解することで、同様のエラーの再発を防ぎます。
- **ServiceNow の理解促進:** エラーの解決を通じて、ServiceNow の内部構造や動作原理を理解できます。
- **開発効率の向上:** エラーに費やす時間を削減し、より創造的な開発に集中できます。

**事前準備と前提条件**

- ServiceNow インスタンスへのアクセス権
- ServiceNow スクリプトの基本的な知識
- エラーメッセージの読解力
- 問題解決に対する論理的思考力

**トラブルシューティング事例集**

1.  **ビジネスルールが動かない**

    - **原因:**

      - ビジネスルールの実行条件が満たされていない。
      - ビジネスルールの実行順序が正しくない。
      - スクリプトにエラーがある。
      - ビジネスルールが無効になっている。

    - **解決策:**

      1.  ビジネスルールの実行条件を確認します。
      2.  ビジネスルールの実行順序を確認します。
      3.  スクリプトをデバッグし、エラーを修正します。`gs.log()`を活用し、条件分岐や変数の中身を確認しましょう。
      4.  ビジネスルールが有効になっていることを確認します。
      5.  ビジネスルールの実行ログ（**System Logs > Events**）を確認し、エラーメッセージがないか確認します。

    - **ユースケース:** インシデントの優先度が「緊急」になった場合に、担当グループを自動的に割り当てるビジネスルールが動かない。→ 優先度変更時の条件と、グループ割り当てのスクリプトを確認します。
    - **例:**

      ```javascript
      // ビジネスルールの例 (before insert or update)
      (function executeRule(current, previous /*null when async*/) {
        // 条件：優先度が変更され、かつ緊急になった場合
        if (current.priority.changesTo(1)) {
          // 担当グループを設定
          current.assignment_group = "YOUR_GROUP_SYS_ID"; // 担当グループのsys_id
        }
      })(current, previous);
      ```

2.  **クライアントスクリプトがエラーになる**

    - **原因:**

      - スクリプトに構文エラーがある。
      - 存在しないフィールドや関数を参照している。
      - DOM 操作が正しくない。
      - スクリプトが特定のブラウザで動作しない。

    - **解決策:**

      1.  ブラウザの開発者ツール（F12）を開き、コンソールに表示されるエラーメッセージを確認します。
      2.  スクリプトの構文エラーを修正します。
      3.  参照しているフィールドや関数が存在することを確認します。
      4.  DOM 操作が正しく行われていることを確認します。
      5.  異なるブラウザでスクリプトをテストします。
      6.  `g_form`オブジェクトのメソッド (`getValue()`, `setValue()`, `addInfoMessage()`など) を正しく使用しているか確認します。

    - **ユースケース:** フォームのロード時に特定のフィールドを非表示にするクライアントスクリプトがエラーになる。→ ブラウザの開発者ツールでエラーメッセージを確認し、フィールド名が正しいか、DOM 操作が正しく行われているか確認します。
    - **例:**

      ```javascript
      // クライアントスクリプトの例 (onLoad)
      function onLoad() {
        // フィールドを非表示にする
        g_form.setDisplay("YOUR_FIELD_NAME", false);
      }
      ```

3.  **ワークフローが想定通りに進まない**

    - **原因:**

      - ワークフローの条件が満たされていない。
      - ワークフローのトランジションが正しく設定されていない。
      - アクティビティのスクリプトにエラーがある。
      - ワークフローが中断されている。

    - **解決策:**

      1.  ワークフローログを確認し、ワークフローの実行パスを追跡します。
      2.  ワークフローの条件とトランジションを確認します。
      3.  アクティビティのスクリプトをデバッグし、エラーを修正します。
      4.  ワークフローが中断されていないことを確認します。
      5.  ワークフローコンテキストで変数の値を確認します。 (アクティビティの出力変数が正しく設定されているかなど)

    - **ユースケース:** 承認リクエストが承認者に送信されない。→ ワークフローログを確認し、承認アクティビティの条件が満たされているか、承認者が正しく設定されているか確認します。
    - **例:**

      ```javascript
      // ワークフローアクティビティのスクリプト例
      (function execute(inputs, outputs) {
        // 承認者を設定
        outputs.approver = "YOUR_USER_SYS_ID"; // 承認者のsys_id
      })(inputs, outputs);
      ```

4.  **統合がうまくいかない**

    - **原因:**
      - ネットワーク接続の問題
      - API エンドポイントの誤り
      - 認証情報の誤り
      - データ形式の不一致
      - スロットリング（レート制限）による制限
    - **解決策:**
      1. ネットワーク接続を確認します。ping コマンドや traceroute コマンドを使用し、疎通性を確認します。
      2. API エンドポイント、認証情報、データ形式が正しいことを確認します。ServiceNow のログ（System Logs > Integration）や統合先のシステムのログを調査します。
      3. 認証方式 (Basic 認証、OAuth 2.0 など) が正しく設定されていることを確認します。
      4. データ変換スクリプトをデバッグし、データ形式の不一致を修正します。`JSON.stringify()`を使用してデータの状態をログに出力すると、問題箇所の特定に役立ちます。
      5. API の使用頻度が統合先のシステムのスロットリング制限を超えていないか確認します。レート制限を超えないように、リクエストの間隔を調整します。
    - **ユースケース:** 外部のチケット管理システムとの連携で、ServiceNow のインシデント情報を送信できない。→ ネットワーク接続、API エンドポイント、認証情報、データ形式が正しいことを確認します。
    - **例:**
      ```javascript
      // REST API コールの例 (アウトバウンド)
      var r = new RESTMessage("YOUR_REST_ENDPOINT", "post");
      r.setRequestBody(JSON.stringify(data));
      var response = r.execute();
      if (response.getStatusCode() != 200) {
        gs.log(
          "APIエラー: " + response.getStatusCode() + " - " + response.getBody()
        );
      }
      ```

**トラブルシューティングの注意点**

- **エラーメッセージをよく読む:** エラーメッセージは、問題解決のヒントとなる情報を含んでいます。
- **問題を切り分ける:** 問題を特定するために、関連する要素を一つずつ切り分けて検証します。
- **再現性を確認する:** 問題が再現可能であることを確認することで、解決策の検証が容易になります。
- **ドキュメントを参照する:** ServiceNow の公式ドキュメントやコミュニティフォーラムには、多くのトラブルシューティング情報が掲載されています。

**まとめと次のステップ**

トラブルシューティングは、ServiceNow のカスタマイズにおいて不可欠なスキルです。このセクションで紹介した事例集を参考に、エラーに迅速に対応し、問題解決能力を向上させましょう。次のステップとして、ServiceNow のデバッグツールやログ分析ツールについて学習することをお勧めします。

### 20.4 カスタマイズのアンチパターン：避けるべき設計、実装

**概要と重要性**

ServiceNow のカスタマイズは、ビジネス要件に合わせた柔軟なシステム構築を可能にしますが、誤った設計や実装は、パフォーマンスの低下、アップグレードの困難化、システムの不安定化といった問題を引き起こす可能性があります。このセクションでは、避けるべきカスタマイズのアンチパターンを解説し、持続可能なシステム構築のためのベストプラクティスを紹介します。

**特徴と利点**

アンチパターンを回避することで、以下の利点があります。

- **パフォーマンスの向上:** 不要な処理を削減し、システムの応答時間を短縮します。
- **アップグレードの容易化:** 標準機能を活用し、アップグレード時の影響を最小限に抑えます。
- **システムの安定化:** バグの発生を抑制し、システムの信頼性を高めます。
- **メンテナンス性の向上:** コードの可読性を高め、メンテナンスコストを削減します。
- **開発効率の向上:** 標準機能を活用し、開発時間を短縮します。

**事前準備と前提条件**

- ServiceNow インスタンスへのアクセス権
- ServiceNow スクリプトの基本的な知識
- ServiceNow のアーキテクチャに関する理解
- 設計原則の知識（SOLID 原則など）

**カスタマイズのアンチパターン**

1.  **過剰なカスタマイズ**

    - **概要:** 標準機能で実現可能な要件を、スクラッチで開発してしまうこと。
    - **問題点:**

      - 開発コストの増加
      - メンテナンスコストの増加
      - アップグレード時の問題発生リスクの増加
      - 標準機能の恩恵を受けられない

    - **解決策:**

      1.  要件を詳細に分析し、標準機能で実現可能な範囲を検討します。
      2.  標準機能を最大限に活用し、必要な部分のみをカスタマイズします。
      3.  ServiceNow Store で提供されているアプリケーションやインテグレーションを検討します。

    - **ユースケース:** 承認ワークフローをスクラッチで開発してしまう。→ 標準の承認エンジンを活用し、カスタマイズが必要な部分のみをスクリプトで補完します。

2.  **標準機能を無視した独自開発**

    - **概要:** ServiceNow が提供する API や拡張ポイントを使用せずに、直接データベースを操作したり、内部構造に依存したスクリプトを記述すること。
    - **問題点:**

      - アップグレード時の互換性問題の発生
      - システムの不安定化
      - セキュリティリスクの増加
      - パフォーマンスの低下

    - **解決策:**

      1.  ServiceNow が提供する API や拡張ポイントを積極的に活用します。
      2.  直接データベースを操作する代わりに、GlideRecord API を使用します。
      3.  内部構造に依存したスクリプトを記述する代わりに、イベント駆動型のアーキテクチャを採用します。

    - **ユースケース:** 直接データベースを更新するビジネスルールを記述してしまう。→ GlideRecord API を使用してレコードを更新します。

3.  **アップグレードを考慮しない設計**

    - **概要:** ServiceNow のアップグレード時に、カスタマイズが問題なく動作することを考慮せずに設計・開発すること。
    - **問題点:**

      - アップグレード時の動作検証コストの増加
      - アップグレード後のシステム停止時間の長期化
      - カスタマイズの修正作業の発生
      - アップグレード自体が困難になる

    - **解決策:**

      1.  アップグレードの影響を受けにくい設計を採用します。
      2.  標準機能を活用し、カスタマイズ範囲を最小限に抑えます。
      3.  アップグレード前には、テスト環境で十分な動作検証を行います。
      4.  ServiceNow のアップグレードドキュメントをよく読み、変更点や非推奨になった API を確認します。

    - **ユースケース:** アップグレードによって非推奨になった API を使用しているスクリプト。→ 最新の API に置き換えます。

4.  **ハードコードされた値の使用**

    - **概要:** スクリプトや設定に、直接値を埋め込んでしまうこと (例: グループの sys_id, API のエンドポイント)。
    - **問題点:**

      - 環境が変わった場合に修正が必要になる
      - 可読性が悪くなる
      - 変更が困難になる

    - **解決策:**

      1.  システムプロパティを使用して設定値を管理します。`gs.getProperty('YOUR_PROPERTY_NAME')`で取得できます。
      2.  参照テーブルを使用して値を管理します。 (例: ロケーションテーブル)
      3.  設定可能なオプションとして UI を提供します。

    - **ユースケース:** スクリプトに直接グループの sys_id を埋め込んでしまっている。→ システムプロパティにグループの sys_id を格納し、スクリプトから参照します。

5.  **複雑すぎるスクリプト**

    - **概要:** 複雑で読みにくいスクリプトを書くこと。
    - **問題点:**
      - メンテナンスが困難になる
      - バグが発生しやすくなる
      - パフォーマンスが悪化する可能性がある
    - **解決策:**
      1. スクリプトを小さく分割し、関数化します。
      2. 適切なコメントを追加します。
      3. 変数名を意味のあるものにします。
      4. スクリプトインクルードを活用して、再利用可能なコードを作成します。
    - **ユースケース:** 複数の条件分岐がネストされた複雑なビジネスルール。→ スクリプトを関数に分割し、可読性を向上させます。

**アンチパターン回避のためのベストプラクティス**

- **標準機能を理解する:** ServiceNow の標準機能を深く理解し、最大限に活用します。
- **設計原則に従う:** SOLID 原則などの設計原則に従い、保守性の高いコードを記述します。
- **コードレビューを実施する:** コードレビューを通じて、アンチパターンを早期に発見します。
- **ドキュメントを整備する:** カスタマイズの内容や設計思想をドキュメントに残します。
- **継続的に学習する:** ServiceNow の最新情報やベストプラクティスを継続的に学習します。

**まとめと次のステップ**

アンチパターンを回避することは、ServiceNow の持続可能なシステム構築のために不可欠です。標準機能を理解し、設計原則に従い、コードレビューを実施することで、より良いカスタマイズを実現しましょう。次のステップとして、ServiceNow のアーキテクチャや設計パターンについて学習することをお勧めします。

### 20.5 現場で役立つショートカットキー：開発効率アップ

**概要と重要性**

ServiceNow の開発効率は、日々の作業に大きく影響します。ショートカットキーをマスターすることで、マウス操作の回数を減らし、キーボードから手を離すことなく、より迅速にタスクを完了できます。このセクションでは、現場で役立つショートカットキーを紹介し、開発効率を向上させるためのヒントを提供します。

**特徴と利点**

ショートカットキーを活用することで、以下の利点があります。

- **作業時間の短縮:** マウス操作の回数を減らし、タスク完了までの時間を短縮します。
- **集中力の向上:** キーボードから手を離すことなく作業できるため、集中力が向上します。
- **疲労軽減:** マウス操作による身体的な疲労を軽減します。
- **生産性の向上:** 全体的な開発効率が向上し、より多くのタスクをこなせるようになります。

**事前準備と前提条件**

- ServiceNow インスタンスへのアクセス権
- キーボード操作の基本的な知識
- ショートカットキーを覚えるための意欲

**ショートカットキー**

以下に示すのは、ServiceNow でよく使用されるショートカットキーの例です。環境やブラウザによって異なる場合があるのでご注意ください。

1.  **スクリプトエディタのショートカット**

    | ショートカットキー（Windows/Linux） | ショートカットキー（macOS） | 説明                                              |
    | ----------------------------------- | --------------------------- | ------------------------------------------------- |
    | Ctrl + Space                        | Command + Space             | コード補完（候補の表示）                          |
    | Ctrl + S                            | Command + S                 | スクリプトの保存                                  |
    | Ctrl + F                            | Command + F                 | 検索                                              |
    | Ctrl + H                            | Command + Option + F        | 置換                                              |
    | Ctrl + Z                            | Command + Z                 | 元に戻す                                          |
    | Ctrl + Y (または Ctrl + Shift + Z)  | Command + Shift + Z         | やり直す                                          |
    | Ctrl + /                            | Command + /                 | 行コメントの追加/削除                             |
    | Alt + Shift + F                     | Option + Shift + F          | コードの整形 (フォーマット) ※設定が必要な場合あり |
    | Ctrl + K, Ctrl + 0                  | Command + K, Command + 0    | コードの折りたたみ (全て)                         |
    | Ctrl + K, Ctrl + J                  | Command + K, Command + J    | コードの展開 (全て)                               |

    **補足:**

    - コード補完は、変数名や関数名を途中まで入力すると候補を表示してくれる便利な機能です。
    - コードの整形は、インデントを整えたり、不要な空白を削除したりすることで、コードを読みやすくする機能です。

2.  **フォーム操作のショートカット**

    | ショートカットキー（Windows/Linux） | ショートカットキー（macOS） | 説明                                                   |
    | ----------------------------------- | --------------------------- | ------------------------------------------------------ |
    | Ctrl + Alt + S                      | Command + Option + S        | レコードの保存                                         |
    | Ctrl + Alt + U                      | Command + Option + U        | レコードの更新                                         |
    | Alt + Insert                        | Option + Enter              | 新規レコードの作成（リストビューで）                   |
    | Ctrl + Shift + Delete               | Command + Shift + Delete    | レコードの削除（要確認ダイアログが表示される場合あり） |
    |                                     |                             |                                                        |

    **補足:**

    - これらのショートカットは、フォーム上で動作します。
    - 一部のショートカットは、設定によって異なる場合があります。

3.  **ナビゲーションのショートカット**

    | ショートカットキー（Windows/Linux） | ショートカットキー（macOS） | 説明                               |
    | ----------------------------------- | --------------------------- | ---------------------------------- |
    | Ctrl + Shift + A                    | Command + Shift + A         | アプリケーションナビゲーターの検索 |
    | Ctrl + Alt + T                      | Command + Option + T        | 現在のタブを複製する               |
    | Ctrl + Tab                          | Command + Tab               | タブを切り替える                   |
    | Ctrl + Shift + Tab                  | Command + Shift + Tab       | 逆順にタブを切り替える             |
    |                                     |                             |                                    |

    **補足:**

    - アプリケーションナビゲーターの検索は、特定のモジュールや機能を素早く見つけるのに役立ちます。
    - タブの切り替えは、複数のフォームやリストビューを開いている場合に便利です。

**実践的なテクニック**

- **よく使うショートカットキーを覚える:** すべてのショートカットキーを覚える必要はありません。日々の業務でよく使うショートカットキーを優先的に覚えましょう。
- **ショートカットキーチートシートを作成する:** 覚えたショートカットキーをメモしておき、すぐに参照できるようにします。
- **ショートカットキーを意識して使う:** 作業中にショートカットキーを意識して使うように心がけ、徐々に慣れていきましょう。
- **ブラウザの拡張機能:** ブラウザによっては、ショートカットキーをカスタマイズできる拡張機能があります。

**応用例とユースケース**

- **インシデント管理:** インシデントの優先度を素早く変更したり、担当者を割り当てたりするために、フォーム操作のショートカットキーを活用します。
- **スクリプト開発:** スクリプトの保存、検索、置換、コメントアウトなどの操作を、スクリプトエディタのショートカットキーで効率化します。
- **変更管理:** 変更リクエストの承認、却下、クローズなどの操作を、フォーム操作のショートカットキーで迅速に行います。

**トラブルシューティング**

- **ショートカットキーが動作しない:** ブラウザの拡張機能が競合している可能性があります。拡張機能を一時的に無効にして、動作を確認してください。
- **ショートカットキーが変更されている:** ブラウザの設定や OS の設定で、ショートカットキーが変更されている可能性があります。設定を確認し、必要に応じて修正してください。
- **ショートカットキーが一部のフィールドで動作しない:** フィールドの種類 (例: Rich Text Editor) によっては、一部のショートカットキーが動作しない場合があります。

**まとめと次のステップ**

ショートカットキーをマスターすることで、ServiceNow の開発効率を大幅に向上させることができます。日々の業務でショートカットキーを意識して使い、より生産性の高い開発者を目指しましょう。次のステップとして、ServiceNow の公式ドキュメントやコミュニティフォーラムで、さらに多くのショートカットキーや Tips を学習することをお勧めします。また、ご自身のブラウザや OS に合わせたカスタマイズを検討してみるのも良いでしょう。
