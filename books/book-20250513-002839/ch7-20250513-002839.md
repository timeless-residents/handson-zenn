## 第 7 章：ServiceNow API 徹底攻略：連携で広がる可能性

この章では、ServiceNow の API を徹底的に攻略し、その連携によって広がる可能性を探ります。ServiceNow は単体でも強力なプラットフォームですが、API を活用することで外部システムとの連携が容易になり、業務効率化や新たな価値創造に繋がります。REST API、SOAP API、Scripted REST API という 3 つの主要な API について、初心者から上級者まで理解できるように段階的に解説していきます。

### 7.1 REST API の活用：外部システムとのデータ連携

#### 7.1.1 概要と重要性

REST (Representational State Transfer) API は、Web 標準技術に基づいた軽量なアーキテクチャであり、ServiceNow と外部システム間のデータ連携において最も一般的な方法です。REST API の活用により、インシデント情報、ナレッジ記事、ユーザー情報など、ServiceNow 内のあらゆるデータに外部システムからアクセスし、データの作成、読み取り、更新、削除 (CRUD) 操作を行うことができます。

REST API の重要性は、そのシンプルさと柔軟性にあります。JSON や XML といった標準的なデータ形式を使用し、HTTP メソッド (GET, POST, PUT, DELETE) を通じてリソースを操作するため、様々なプログラミング言語やプラットフォームから容易に連携できます。

#### 7.1.2 特徴と利点

- **シンプルで理解しやすい:** HTTP メソッドと JSON/XML 形式のデータ交換に基づいているため、開発者が容易に理解し、実装できます。
- **標準化されたインターフェース:** Web 標準に準拠しているため、多様なシステムとの連携が可能です。
- **ステートレス:** 各リクエストは独立しており、サーバー側でセッション情報を保持する必要がないため、スケーラビリティが高いです。
- **パフォーマンス:** 軽量な設計により、高速なデータ転送が可能です。

#### 7.1.3 事前準備と前提条件

- ServiceNow インスタンスへのアクセス権（admin ロールまたは適切な権限を持つユーザー）。
- REST API クライアント (例: Postman, cURL)。
- API ドキュメントの確認: ServiceNow Developer サイトで、必要な API エンドポイント、パラメータ、データ形式を確認します。

#### 7.1.4 基本的な使い方

**7.1.4.1 ServiceNow REST API Explorer の利用**

REST API Explorer は、ServiceNow インスタンス内で REST API のテストと探索を行うための強力なツールです。

1.  **アクセス:** ServiceNow インスタンスにログインし、ナビゲータで「REST API Explorer」を検索して開きます。
2.  **設定:**

    - **Namespace:** 適切な API の名前空間を選択します（例: "Table API"）。
    - **API Name:** 使用する API を選択します（例: "Incident"）。
    - **Version:** API のバージョンを選択します。
    - **HTTP Method:** 実行する HTTP メソッドを選択します（例: "GET", "POST", "PUT", "DELETE"）。
    - **Request Parameters:** 必要なパラメータを入力します（例: `sysparm_limit=10`で 10 件のレコードを取得）。

3.  **リクエストの送信:** 「Send」ボタンをクリックしてリクエストを送信します。

4.  **レスポンスの確認:** レスポンスヘッダー、ステータスコード、レスポンスボディ（JSON 形式）を確認します。

REST API Explorer を使用することで、API の動作を理解し、必要なパラメータやデータ形式を把握することができます。

**7.1.4.2 GET, POST, PUT, DELETE メソッドの使い方**

- **GET:** リソースの取得。例：インシデントレコードの取得

  ```bash
  curl -X GET \
    'https://<インスタンス名>.service-now.com/api/now/table/incident?sysparm_limit=1' \
    -H 'Accept:application/json' \
    -H 'Content-Type:application/json' \
    -H 'Authorization: Basic <認証トークン>'
  ```

- **POST:** 新しいリソースの作成。例：新しいインシデントレコードの作成

  ```bash
  curl -X POST \
    'https://<インスタンス名>.service-now.com/api/now/table/incident' \
    -H 'Accept:application/json' \
    -H 'Content-Type:application/json' \
    -H 'Authorization: Basic <認証トークン>' \
    -d '{
        "short_description": "API経由で作成されたインシデント",
        "caller_id": "abel.tuter"
    }'
  ```

- **PUT:** 既存のリソースの更新。例：既存のインシデントレコードの更新

  ```bash
  curl -X PUT \
    'https://<インスタンス名>.service-now.com/api/now/table/incident/<sys_id>' \
    -H 'Accept:application/json' \
    -H 'Content-Type:application/json' \
    -H 'Authorization: Basic <認証トークン>' \
    -d '{
        "state": "3"
    }'
  ```

- **DELETE:** リソースの削除。例：インシデントレコードの削除

  ```bash
  curl -X DELETE \
    'https://<インスタンス名>.service-now.com/api/now/table/incident/<sys_id>' \
    -H 'Accept:application/json' \
    -H 'Content-Type:application/json' \
    -H 'Authorization: Basic <認証トークン>'
  ```

`<インスタンス名>`、`<sys_id>`、`<認証トークン>` は、実際の値に置き換えてください。

**7.1.4.3 認証と認可の設定**

ServiceNow REST API へのアクセスには、認証が必要です。基本的な認証方法としては、Basic 認証、OAuth 2.0、Session Cookie 認証などがあります。

- **Basic 認証:** ユーザー名とパスワードを Base64 エンコードした文字列を Authorization ヘッダーに含めます。

  ```
  Authorization: Basic <Base64エンコードされたユーザー名:パスワード>
  ```

- **OAuth 2.0:** よりセキュアな認証方法であり、アクセストークンを使用して API にアクセスします。ServiceNow OAuth 2.0 の設定については、公式ドキュメントを参照してください。
- **Session Cookie 認証:** ServiceNow にログインしているセッションの Cookie を使用して認証します。主にブラウザからアクセスする場合に使用されます。

#### 7.1.5 実践的なテクニック

- **sysparm_query:** 複雑な条件でレコードをフィルタリングする場合に使用します。例：`sysparm_query=category=network^priority=1`
- **sysparm_fields:** レスポンスに含めるフィールドを指定することで、データ転送量を削減できます。例：`sysparm_fields=sys_id,number,short_description`
- **データのページネーション:** 大量のデータを扱う場合、`sysparm_limit`と`sysparm_offset`を使用してデータを分割して取得します。
- **スクリプトでの REST API 呼び出し:** ServiceNow のサーバサイドスクリプト（Business Rule, Script Include など）から REST API を呼び出す場合は、`RESTMessageV2`クラスを使用します。

  ```javascript
  var r = new RESTMessageV2();
  r.setHttpMethod("get");
  r.setEndpoint(
    "https://<インスタンス名>.service-now.com/api/now/table/incident?sysparm_limit=1"
  );
  r.setRequestHeader("Accept", "application/json");
  r.setRequestHeader("Content-Type", "application/json");
  r.setBasicAuth("<ユーザー名>", "<パスワード>");
  var response = r.execute();
  var responseBody = response.getBody();
  var httpStatus = response.getStatusCode();
  gs.info("Response Status: " + httpStatus);
  gs.info("Response Body: " + responseBody);
  ```

#### 7.1.6 応用例とユースケース

- **外部監視システムとの連携:** 外部監視システムで検知されたアラートを ServiceNow のインシデントとして自動的に登録する。
- **チャットボットとの連携:** チャットボットを通じて ServiceNow のナレッジ記事を検索し、ユーザーに提供する。
- **CRM システムとの連携:** 顧客情報を ServiceNow と CRM システム間で同期する。
- **CI/CD パイプラインとの連携:** デプロイメントの成功/失敗を ServiceNow の変更リクエストに反映する。

#### 7.1.7 トラブルシューティング

- **認証エラー:** 認証情報が正しいか確認してください。OAuth 2.0 を使用している場合は、アクセストークンの有効期限が切れていないか確認してください。
- **権限エラー:** API へのアクセスに必要な権限を持っているか確認してください。
- **HTTP ステータスコード:** エラーが発生した場合は、HTTP ステータスコードを確認し、適切な対処を行ってください（例: 400 Bad Request, 401 Unauthorized, 404 Not Found, 500 Internal Server Error）。
- **レスポンスボディ:** レスポンスボディにエラーメッセージが含まれている場合は、その内容を確認し、問題を特定してください。
- **syslog の確認:** サーバースクリプトから REST API を呼び出している場合は、syslog にエラーメッセージが出力されているか確認してください。

#### 7.1.8 まとめと次のステップ

REST API は ServiceNow と外部システムを連携するための強力なツールです。基本的な使い方を理解し、様々なテクニックを習得することで、より高度な連携を実現できます。次のステップとして、OAuth 2.0 の設定や、より複雑なデータ連携シナリオに挑戦してみましょう。

### 7.2 SOAP API の活用：レガシーシステムとの連携

#### 7.2.1 概要と重要性

SOAP (Simple Object Access Protocol) API は、XML ベースのプロトコルであり、ServiceNow とレガシーシステムとの連携において依然として重要な役割を果たしています。SOAP API は、堅牢なメッセージングとトランザクション処理をサポートしており、セキュリティ要件が厳しい環境や、複雑なデータ構造を扱う場合に適しています。

#### 7.2.2 特徴と利点

- **標準化されたプロトコル:** SOAP は W3C によって標準化されており、多くのプラットフォームやプログラミング言語でサポートされています。
- **堅牢なメッセージング:** XML スキーマによる厳格なデータ検証と、WS-\*仕様による信頼性の高いメッセージングをサポートしています。
- **トランザクション処理:** ACID 特性（Atomicity, Consistency, Isolation, Durability）を保証するトランザクションをサポートしています。
- **セキュリティ:** WS-Security 仕様による強力なセキュリティ機能をサポートしています。

#### 7.2.3 事前準備と前提条件

- ServiceNow インスタンスへのアクセス権（admin ロールまたは適切な権限を持つユーザー）。
- SOAP クライアント (例: SoapUI, Apache Axis)。
- WSDL ファイルの確認: ServiceNow インスタンスから WSDL ファイルをダウンロードし、API のエンドポイント、操作、データ型を確認します。

#### 7.2.4 基本的な使い方

**7.2.4.1 WSDL ファイルのインポートと解析**

WSDL (Web Services Description Language) ファイルは、SOAP API のインターフェースを記述した XML ファイルです。WSDL ファイルを SOAP クライアントにインポートすることで、API のエンドポイント、操作、データ型を自動的に認識させることができます。

1.  **WSDL ファイルのダウンロード:** ServiceNow インスタンスにログインし、ナビゲータで「Web Services」を検索し、「WSDL」を選択します。目的のテーブル（例：Incident）の WSDL URL をコピーします。例: `https://<インスタンス名>.service-now.com/incident.do?WSDL`
2.  **SOAP クライアントへのインポート:** SOAP クライアント (例: SoapUI) を起動し、WSDL ファイルをインポートします。
3.  **操作の確認:** インポートされた WSDL ファイルから、利用可能な操作（例: `getRecords`, `insert`, `update`, `deleteMultiple`）を確認します。

**7.2.4.2 SOAP リクエストの作成と送信**

SOAP リクエストは、XML 形式で記述されたメッセージであり、API に対して実行する操作とパラメータを指定します。

1.  **リクエストの作成:** SOAP クライアントを使用して、実行する操作を選択し、必要なパラメータを入力します。例：`getRecords`操作でインシデントレコードを取得する場合。

    ```xml
    <soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" xmlns:ser="http://www.service-now.com/">
       <soapenv:Header/>
       <soapenv:Body>
          <ser:getRecords>
             <ser:sysparm_query>number=INC0010001</ser:sysparm_query>
          </ser:getRecords>
       </soapenv:Body>
    </soapenv:Envelope>
    ```

2.  **リクエストの送信:** SOAP クライアントを使用して、作成したリクエストを ServiceNow インスタンスに送信します。

3.  **レスポンスの確認:** ServiceNow インスタンスから返されたレスポンス（XML 形式）を確認します。

**7.2.4.3 認証と認可の設定**

ServiceNow SOAP API へのアクセスには、認証が必要です。SOAP API では、Basic 認証または WS-Security を使用して認証を行います。

- **Basic 認証:** SOAP リクエストの HTTP ヘッダーにユーザー名とパスワードを含めます。

  ```xml
  <soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" xmlns:ser="http://www.service-now.com/">
     <soapenv:Header>
        <wsse:Security soapenv:mustUnderstand="1" xmlns:wsse="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-wssecurity-secext-1.0.xsd">
           <wsse:UsernameToken>
              <wsse:Username>ユーザー名</wsse:Username>
              <wsse:Password Type="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-username-token-profile-1.0#PasswordText">パスワード</wsse:Password>
           </wsse:UsernameToken>
        </wsse:Security>
     </soapenv:Header>
     <soapenv:Body>
        <!-- リクエストボディ -->
     </soapenv:Body>
  </soapenv:Envelope>
  ```

- **WS-Security:** よりセキュアな認証方法であり、デジタル署名や暗号化を使用してメッセージを保護します。ServiceNow WS-Security の設定については、公式ドキュメントを参照してください。

#### 7.2.5 実践的なテクニック

- **sysparm_query:** 複雑な条件でレコードをフィルタリングする場合に使用します。例：`sysparm_query=category=network^priority=1`
- **データのページネーション:** 大量のデータを扱う場合、`sysparm_limit`と`sysparm_offset`を使用してデータを分割して取得します。
- **glideRecord API の利用:** サーバースクリプトから SOAP API を呼び出す場合は、`SOAPMessageV2`クラスを使用します。ただし、REST API の`RESTMessageV2`クラスの使用が推奨されます。

  ```javascript
  // SOAPMessageV2は非推奨。可能な限りREST APIを使用してください。
  var soapMessage = new SOAPMessageV2("incident", "getRecords");
  soapMessage.setStringParameter("sysparm_query", "number=INC0010001");
  var response = soapMessage.execute();
  var responseBody = response.getBody();
  gs.info("Response Body: " + responseBody);
  ```

#### 7.2.6 応用例とユースケース

- **レガシーシステムとの連携:** メインフレームや ERP システムなど、SOAP API をサポートするレガシーシステムと ServiceNow を連携する。
- **オンプレミスシステムとの連携:** ファイアウォールの内側に存在するオンプレミスシステムと ServiceNow を連携する。
- **セキュリティ要件の高い連携:** 金融機関や政府機関など、セキュリティ要件が厳しい環境で ServiceNow と外部システムを連携する。

#### 7.2.7 トラブルシューティング

- **WSDL ファイルの解析エラー:** WSDL ファイルが正しくダウンロードされているか、XML 構文エラーがないか確認してください。
- **認証エラー:** 認証情報が正しいか確認してください。WS-Security を使用している場合は、設定が正しいか確認してください。
- **SOAP Fault:** SOAP Fault が発生した場合は、Fault コードと Fault 文字列を確認し、問題を特定してください。
- **HTTP ステータスコード:** エラーが発生した場合は、HTTP ステータスコードを確認し、適切な対処を行ってください。
- **syslog の確認:** サーバースクリプトから SOAP API を呼び出している場合は、syslog にエラーメッセージが出力されているか確認してください。

#### 7.2.8 まとめと次のステップ

SOAP API はレガシーシステムとの連携において依然として重要な技術です。WSDL ファイルのインポート、SOAP リクエストの作成、認証の設定など、基本的な使い方を理解することで、より高度な連携を実現できます。次のステップとして、WS-Security の設定や、より複雑なデータ連携シナリオに挑戦してみましょう。ただし、新規開発においては、可能な限り REST API の利用を検討してください。

### 7.3 Scripted REST API：カスタム API の作成と公開

#### 7.3.1 概要と重要性

Scripted REST API は、ServiceNow 上でカスタム API を作成し、公開するための機能です。これにより、ServiceNow の機能を外部システムに公開したり、特定のビジネスニーズに合わせた API を開発したりすることができます。Scripted REST API は、柔軟性と拡張性に優れており、ServiceNow の可能性をさらに広げます。

#### 7.3.2 特徴と利点

- **柔軟性:** JavaScript を使用して API のロジックを自由に記述できるため、様々なビジネス要件に対応できます。
- **拡張性:** ServiceNow の機能を外部システムに公開したり、独自の API を開発したりすることができます。
- **セキュリティ:** 認証と認可の設定により、API へのアクセスを制御できます。
- **監視:** API の利用状況を監視し、パフォーマンスを最適化できます。

#### 7.3.3 事前準備と前提条件

- ServiceNow インスタンスへのアクセス権（admin ロールまたは適切な権限を持つユーザー）。
- JavaScript の知識。
- Scripted REST API モジュールの有効化（必要な場合）。

#### 7.3.4 基本的な使い方

**7.3.4.1 リソース定義と HTTP メソッドの実装**

1.  **Scripted REST API の作成:** ServiceNow インスタンスにログインし、ナビゲータで「Scripted REST APIs」を検索し、「New」をクリックして新しい Scripted REST API を作成します。
2.  **ベースパスの設定:** API のエンドポイントのベースとなるパスを設定します（例: `/api/x_mycompany_myapp/v1/`）。
3.  **リソースの定義:** API のリソースを定義します。リソースは、API のエンドポイントを構成するパスの一部です（例: `incidents`, `users`）。
4.  **HTTP メソッドの実装:** 各リソースに対して、対応する HTTP メソッド（GET, POST, PUT, DELETE）を実装します。各メソッドには、JavaScript コードを記述して、リクエストの処理とレスポンスの生成を行います。

    ```javascript
    (function process(
      /*RESTAPIRequest*/ request,
      /*RESTAPIResponse*/ response
    ) {
      var query = request.queryParams.number;
      var gr = new GlideRecord("incident");

      if (query) {
        gr.addQuery("number", query);
        gr.query();

        if (gr.next()) {
          var incident = {
            number: gr.getValue("number"),
            short_description: gr.getValue("short_description"),
            state: gr.getDisplayValue("state"),
          };

          response.setContentType("application/json");
          response.setBody(incident);
        } else {
          response.setStatus(404);
          response.setContentType("application/json");
          response.setBody({
            error: "Incident not found",
          });
        }
      } else {
        response.setStatus(400);
        response.setContentType("application/json");
        response.setBody({
          error: "Missing parameter: number",
        });
      }
    })(request, response);
    ```

**7.3.4.2 入力パラメータの検証と処理**

リクエストから渡された入力パラメータを検証し、適切な処理を行うことは、API のセキュリティと信頼性を確保するために重要です。

- **パラメータの存在確認:** `request.queryParams`、`request.pathParams`、`request.body`を使用して、必要なパラメータが存在するか確認します。
- **パラメータの型検証:** パラメータの型が期待される型と一致するか確認します（例: 数値、文字列、日付）。
- **パラメータのバリデーション:** パラメータの値が有効な範囲内にあるか確認します（例: 文字列の長さ、数値の範囲）。

**7.3.4.3 認証と認可の設定**

Scripted REST API へのアクセスを制御するために、認証と認可を設定します。

- **認証:** ユーザーの身元を確認します。ServiceNow の認証方法（Basic 認証、OAuth 2.0、JWT など）を使用できます。
- **認可:** ユーザーが API へのアクセス権を持っているか確認します。ロール、ACL、またはカスタムスクリプトを使用して認可を制御できます。

#### 7.3.5 実践的なテクニック

- **GlideRecord API:** ServiceNow のデータにアクセスし、操作するために使用します。
- **JSONUtil:** JSON データを操作するために使用します。
- **RESTAPIRequest と RESTAPIResponse:** リクエストとレスポンスを操作するために使用します。
- **スクリプトインクルード:** 共通のロジックを再利用するために使用します。
- **ログ:** API の動作を監視し、デバッグするために使用します。

#### 7.3.6 応用例とユースケース

- **モバイルアプリとの連携:** モバイルアプリから ServiceNow のデータにアクセスし、操作するための API を作成する。
- **カスタムポータルとの連携:** カスタムポータルから ServiceNow のデータにアクセスし、操作するための API を作成する。
- **外部システムとの連携:** 特定のビジネスニーズに合わせた API を作成し、外部システムと ServiceNow を連携させる。
- **イベント駆動型アーキテクチャ:** ServiceNow のイベントを外部システムに通知するための API を作成する。

#### 7.3.7 トラブルシューティング

- **スクリプトエラー:** JavaScript コードにエラーがある場合は、ブラウザのコンソールまたは ServiceNow の syslog でエラーメッセージを確認してください。
- **認証エラー:** 認証情報が正しいか確認してください。認可設定が正しいか確認してください。
- **HTTP ステータスコード:** エラーが発生した場合は、HTTP ステータスコードを確認し、適切な対処を行ってください。
- **ログ:** API の動作を監視し、問題を特定するために、ログを確認してください。

#### 7.3.8 まとめと次のステップ

Scripted REST API は、ServiceNow の可能性を広げる強力なツールです。リソース定義、HTTP メソッドの実装、入力パラメータの検証、認証と認可の設定など、基本的な使い方を理解することで、様々なビジネスニーズに対応した API を作成できます。次のステップとして、より複雑な API の作成や、OAuth 2.0 などの高度な認証方法の導入に挑戦してみましょう。

この章では、ServiceNow API の主要な 3 つのタイプ、REST、SOAP、そして Scripted REST API を詳細に解説しました。それぞれの API の特性を理解し、適切な API を選択することで、ServiceNow と外部システムとの連携を最大限に活用し、ビジネス価値を創造することができます。
