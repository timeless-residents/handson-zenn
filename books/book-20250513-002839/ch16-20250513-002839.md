## 第 16 章：AI と機械学習の活用：ServiceNow をインテリジェントに

ServiceNow は、その強力なワークフローエンジンとデータ管理能力によって、企業のデジタルトランスフォーメーションを加速させてきました。しかし、その真価は、AI と機械学習（ML）を統合することで、さらに引き出すことができます。この章では、ServiceNow の AI 機能を活用し、業務効率を向上させ、より良いユーザーエクスペリエンスを提供する方法について解説します。

### 16.1 Predictive Intelligence (PI) の概要と基本

#### 16.1.1 概要と重要性

Predictive Intelligence（PI）は、ServiceNow に組み込まれた機械学習機能スイートです。過去のデータに基づいて将来の傾向を予測し、インシデントの自動ルーティング、問題の優先度付け、解決策の推奨などを自動化します。これにより、人的リソースをより戦略的なタスクに集中させ、運用効率を大幅に向上させることができます。

#### 16.1.2 特徴と利点

- **予測分析**: 過去のインシデントデータ、問題データ、変更リクエストデータなどを分析し、将来の発生傾向を予測します。
- **自動ルーティング**: インシデントを適切な担当者やグループに自動的にルーティングし、解決までの時間を短縮します。
- **優先度付け**: インシデントの重要度を自動的に判断し、最も重要な問題に優先的に対応できるようにします。
- **解決策の推奨**: 過去の解決策データベースに基づいて、インシデントに対する最適な解決策を推奨します。
- **異常検知**: 異常なパターンや傾向を検出し、潜在的な問題を早期に発見します。

#### 16.1.3 事前準備と前提条件

- **十分なデータ**: 機械学習モデルを効果的にトレーニングするには、十分な量の過去データが必要です。通常、過去 1 年以上のデータが推奨されます。
- **データの品質**: データの正確性と一貫性が重要です。不正確なデータは、モデルのパフォーマンスに悪影響を及ぼします。
- **Predictive Intelligence の有効化**: ServiceNow インスタンスで Predictive Intelligence プラグインが有効になっていることを確認してください。
- **管理者権限**: Predictive Intelligence の設定と管理には、管理者権限が必要です。

#### 16.1.4 基本的な使い方

1.  **類似性グループの作成**: インシデント、問題、変更リクエストなど、類似したレコードをグループ化します。これにより、モデルはより正確な予測を行うことができます。

    _ナビゲーションメニューから「Predictive Intelligence」 -> 「類似性」 -> 「類似性グループ」を選択し、「新規」をクリックします。_

    _グループの名前、説明、および適用するテーブル（例：インシデント）を入力します。_

    _類似性の基準となるフィールド（例：カテゴリ、影響、緊急度）を選択します。_

    _「モデルをトレーニング」をクリックして、モデルのトレーニングを開始します。_

2.  **予測モデルのトレーニング**: 類似性グループに基づいて、予測モデルをトレーニングします。

    _ナビゲーションメニューから「Predictive Intelligence」 -> 「予測」 -> 「予測定義」を選択し、「新規」をクリックします。_

    _予測モデルの名前、説明、および適用するテーブル（例：インシデント）を入力します。_

    _予測するフィールド（例：割り当てグループ）を選択します。_

    _トレーニングデータとして使用する類似性グループを選択します。_

    _「モデルをトレーニング」をクリックして、モデルのトレーニングを開始します。_

3.  **予測モデルの評価**: トレーニングされたモデルの精度と信頼性を評価します。

    _予測定義を開き、「パフォーマンス」タブをクリックします。_

    _モデルの精度、適合率、再現率などの指標を確認します。_

    _必要に応じて、トレーニングデータを調整したり、モデルのパラメータを調整したりして、モデルのパフォーマンスを向上させます。_

#### 16.1.5 実践的なテクニック

- **カスタムフィールドの活用**: ServiceNow の標準フィールドだけでなく、カスタムフィールドも機械学習モデルのトレーニングに使用できます。
- **スクリプトによる自動化**: スクリプトを使用して、モデルのトレーニング、予測の実行、結果の処理を自動化できます。
- **スケジュールされたジョブ**: モデルの定期的な再トレーニングのために、スケジュールされたジョブを設定します。
- **外部データとの統合**: 外部データソース（例：ログデータ、センサーデータ）を ServiceNow に統合し、より包括的な予測モデルを構築します。

  例えば、インシデントの自動ルーティングを自動化するために、以下のスクリプトを使用できます。

  ```javascript
  function assignIncident() {
    var incident = new GlideRecord("incident");
    incident.get(current.sys_id);

    var prediction = sn_ml.Predictor.getPrediction(
      "incident_assignment_group_prediction",
      incident
    );

    if (prediction.confidence > 0.7) {
      incident.assignment_group = prediction.result;
      incident.update();
    }
  }
  ```

#### 16.1.6 応用例とユースケース

- **インシデントの自動ルーティング**: インシデントを適切な担当者やグループに自動的にルーティングし、解決までの時間を短縮します。
- **問題の優先度付け**: インシデントの重要度を自動的に判断し、最も重要な問題に優先的に対応できるようにします。
- **変更リスクの予測**: 変更リクエストのリスクを予測し、リスクの高い変更を事前に特定します。
- **サービスの停止予測**: サービスの停止を予測し、事前に問題を解決するための対策を講じます。
- **顧客離反の予測**: 顧客の離反を予測し、顧客維持のための対策を講じます。

#### 16.1.7 トラブルシューティング

- **モデルの精度が低い**: トレーニングデータの品質が低い、またはデータ量が不十分である可能性があります。データをクリーニングし、十分な量のデータを提供してください。
- **モデルのトレーニングに時間がかかる**: 大量のデータを使用している場合、モデルのトレーニングに時間がかかることがあります。より強力なハードウェアを使用するか、トレーニングデータを削減してください。
- **予測結果が正しくない**: モデルのパラメータが適切に設定されていない可能性があります。パラメータを調整したり、異なるアルゴリズムを試したりしてください。
- **"Maximum training time exceeded" エラー**: モデルのトレーニング時間が ServiceNow の制限を超えた場合、このエラーが発生します。トレーニングデータを削減するか、より強力なハードウェアを使用してください。

Predictive Intelligence は、ServiceNow の機能を大幅に拡張し、業務効率を向上させる強力なツールです。このセクションでは、PI の基本的な概念、使い方、および実践的なテクニックについて学びました。次のステップとして、実際のデータを使用して予測モデルを構築し、その効果を検証してみてください。

### 16.2 Virtual Agent (VA) の概要と基本

#### 16.2.1 概要と重要性

Virtual Agent（VA）は、ServiceNow の会話型 AI プラットフォームです。自然言語処理（NLP）を使用して、ユーザーからの質問やリクエストを理解し、自動的に回答またはタスクを実行します。これにより、Service Desk の負荷を軽減し、ユーザーエクスペリエンスを向上させることができます。

#### 16.2.2 特徴と利点

- **自然言語処理**: ユーザーの自然言語による質問やリクエストを理解し、適切な回答またはアクションを提供します。
- **会話型インターフェース**: ユーザーフレンドリーなチャットインターフェースを通じて、質問やリクエストをやり取りします。
- **自動応答**: よくある質問やリクエストに対して、自動的に回答を提供します。
- **タスクの自動化**: パスワードのリセット、インシデントの作成、ナレッジ記事の検索など、様々なタスクを自動化します。
- **マルチチャネル対応**: Web、モバイルアプリ、Slack、Microsoft Teams など、複数のチャネルで利用できます。

#### 16.2.3 事前準備と前提条件

- **Virtual Agent の有効化**: ServiceNow インスタンスで Virtual Agent プラグインが有効になっていることを確認してください。
- **自然言語理解（NLU）モデルの設定**: ユーザーの自然言語を理解するために、NLU モデルを設定します。
- **会話トピックの設計**: VA が処理できる質問やリクエストの種類を定義する会話トピックを設計します。
- **管理者権限**: Virtual Agent の設定と管理には、管理者権限が必要です。

#### 16.2.4 基本的な使い方

1.  **NLU モデルの作成**: ユーザーの自然言語を理解するための NLU モデルを作成します。

    _ナビゲーションメニューから「NLU Workbench」を選択し、「モデル」タブをクリックします。_

    _「新規」をクリックして、新しい NLU モデルを作成します。_

    _モデルの名前、説明、および言語を選択します。_

    _インテント（ユーザーの意図）とエンティティ（インテントに関連する情報）を定義します。_

    _トレーニングデータ（ユーザーの発話例）を追加して、モデルをトレーニングします。_

2.  **会話トピックの設計**: VA が処理できる質問やリクエストの種類を定義する会話トピックを設計します。

    _ナビゲーションメニューから「Virtual Agent」 -> 「デザイナー」を選択します。_

    _「新規」をクリックして、新しい会話トピックを作成します。_

    _トピックの名前、説明、およびトリガー条件（例：NLU インテント）を入力します。_

    _会話フローを設計します。ユーザーからの入力を取得し、条件に基づいて異なるアクションを実行することができます。_

    _アクションには、テキストの表示、質問の送信、レコードの検索、タスクの実行などが含まれます。_

3.  **Virtual Agent のテスト**: 設計した会話トピックをテストし、正常に動作することを確認します。

    _Virtual Agent デザイナーで、「テスト」ボタンをクリックします。_

    _チャットウィンドウが表示されます。ユーザーとして質問やリクエストを入力し、VA の応答を確認します。_

    _必要に応じて、会話トピックを修正し、テストを繰り返します。_

#### 16.2.5 実践的なテクニック

- **NLU モデルの最適化**: トレーニングデータを追加したり、エンティティを調整したりして、NLU モデルの精度を向上させます。
- **スクリプトによる拡張**: スクリプトを使用して、VA の機能を拡張し、より複雑なタスクを実行できるようにします。
- **変数の活用**: ユーザーからの入力やシステムからの情報を変数に格納し、会話フローの中で使用します。
- **外部システムとの連携**: REST API などを利用して、外部システムと連携し、より高度な機能を実現します。

  例えば、パスワードのリセットを自動化するために、以下のスクリプトを使用できます。

  ```javascript
  (function () {
    var user = new GlideRecord("sys_user");
    user.get(vaInputs.user_id);

    if (user.isValid()) {
      var passwordReset = new PasswordReset();
      passwordReset.initiateReset(user.user_name);

      vaOutputs.reset_url = passwordReset.getPasswordResetURL();
    } else {
      vaOutputs.error_message = "ユーザーが見つかりませんでした。";
    }
  })();
  ```

#### 16.2.6 応用例とユースケース

- **Service Desk のサポート**: パスワードのリセット、インシデントの作成、ナレッジ記事の検索など、Service Desk のサポートを自動化します。
- **IT ヘルプデスク**: ソフトウェアのインストール、プリンターのトラブルシューティングなど、IT ヘルプデスクのサポートを自動化します。
- **人事部門**: 有給休暇の申請、福利厚生に関する質問など、人事部門のサポートを自動化します。
- **顧客サポート**: 製品に関する質問、注文状況の確認など、顧客サポートを自動化します。
- **オンボーディング**: 新入社員向けのオンボーディングプロセスを自動化します。

#### 16.2.7 トラブルシューティング

- **VA がユーザーの意図を理解できない**: NLU モデルの精度が低い可能性があります。トレーニングデータを追加したり、エンティティを調整したりして、NLU モデルを改善してください。
- **会話フローが期待どおりに動作しない**: 会話フローの設定が間違っている可能性があります。会話フローを修正し、テストを繰り返してください。
- **スクリプトがエラーを返す**: スクリプトにエラーがある可能性があります。スクリプトをデバッグし、エラーを修正してください。
- **Virtual Agent が利用できない**: Virtual Agent プラグインが有効になっていること、および必要な設定が完了していることを確認してください。

#### 16.2.8 まとめと次のステップ

### 16.3 AI Search：検索精度とユーザーエクスペリエンスの向上

#### 16.3.1 概要と重要性

AI Search は、ServiceNow の検索機能を強化し、ユーザーがより迅速かつ正確に情報を発見できるようにします。機械学習アルゴリズムを使用して、ユーザーの検索意図を理解し、関連性の高い検索結果を提供します。これにより、ユーザーエクスペリエンスを向上させ、Service Desk の負荷を軽減することができます。

#### 16.3.2 特徴と利点

- **自然言語検索**: ユーザーの自然言語による検索クエリを理解し、関連性の高い検索結果を提供します。
- **スペルチェックとオートコンプリート**: スペルミスを自動的に修正し、検索クエリのオートコンプリートを提案します。
- **関連性の高い検索結果**: 機械学習アルゴリズムを使用して、ユーザーの検索意図を理解し、関連性の高い検索結果を優先的に表示します。
- **パーソナライズされた検索結果**: ユーザーのロール、グループ、および過去の検索履歴に基づいて、パーソナライズされた検索結果を提供します。
- **ナレッジベースの検索**: ナレッジベースの記事を検索し、問題解決に役立つ情報を提供します。
- **カタログアイテムの検索**: カタログアイテムを検索し、サービスリクエストを迅速に行えるようにします。

#### 16.3.3 事前準備と前提条件

- **AI Search の有効化**: ServiceNow インスタンスで AI Search プラグインが有効になっていることを確認してください。
- **インデックスの作成**: 検索対象となるテーブルのインデックスを作成します。
- **シノニムの設定**: 異なる単語やフレーズが同じ意味を持つように、シノニムを設定します。
- **ストップワードの設定**: 検索結果から除外する一般的な単語（例：the、a、is）を設定します。
- **管理者権限**: AI Search の設定と管理には、管理者権限が必要です。

#### 16.3.4 基本的な使い方

1.  **インデックスの作成**: 検索対象となるテーブルのインデックスを作成します。

    _ナビゲーションメニューから「AI Search」 -> 「インデックス」を選択し、「新規」をクリックします。_

    _インデックスの名前、説明、および適用するテーブルを選択します。_

    _インデックスに含めるフィールドを選択します。_

    _「インデックスをビルド」をクリックして、インデックスの作成を開始します。_

2.  **シノニムの設定**: 異なる単語やフレーズが同じ意味を持つように、シノニムを設定します。

    _ナビゲーションメニューから「AI Search」 -> 「シノニム」を選択し、「新規」をクリックします。_

    _シノニムの名前、説明、およびシノニムのリストを入力します。_

    _例えば、「password」と「パスワード」をシノニムとして設定します。_

3.  **ストップワードの設定**: 検索結果から除外する一般的な単語を設定します。

    _ナビゲーションメニューから「AI Search」 -> 「ストップワード」を選択し、「新規」をクリックします。_

    _ストップワードの名前、説明、およびストップワードのリストを入力します。_

    _例えば、「the」、「a」、「is」などをストップワードとして設定します。_

#### 16.3.5 実践的なテクニック

- **重み付けの設定**: 特定のフィールドを他のフィールドよりも重要視するように、重み付けを設定します。
- **検索結果の調整**: 検索結果の表示順序や表示内容を調整します。
- **カスタム検索ソースの追加**: 外部データソース（例：ファイルサーバー、データベース）を検索対象として追加します。
- **検索の最適化**: インデックスの最適化、クエリの最適化、およびキャッシュの活用により、検索パフォーマンスを向上させます。

  例えば、ナレッジ記事の検索結果を向上させるために、以下の手順を実行します。

  1.  `kb_knowledge` テーブルのインデックスを作成します。
  2.  記事のタイトル、概要、およびコンテンツをインデックスに含めます。
  3.  記事のビュー数や評価に基づいて、重み付けを設定します。
  4.  ユーザーの検索クエリに関連性の高い記事が優先的に表示されるように、検索結果を調整します。

#### 16.3.6 応用例とユースケース

- **Service Portal の検索**: Service Portal の検索機能を強化し、ユーザーがセルフサービスで問題を解決できるようにします。
- **IT ヘルプデスク**: IT ヘルプデスクの担当者が問題を解決するために必要な情報を迅速に発見できるようにします。
- **顧客サポート**: 顧客サポート担当者が顧客からの質問に迅速かつ正確に回答できるようにします。
- **ナレッジマネジメント**: ナレッジベースの記事を検索し、知識の共有と再利用を促進します。
- **カタログ管理**: カタログアイテムを検索し、サービスリクエストを迅速に行えるようにします。

#### 16.3.7 トラブルシューティング

- **検索結果が正しくない**: インデックスが最新の状態でない可能性があります。インデックスを再構築してみてください。
- **検索パフォーマンスが低い**: インデックスの最適化、クエリの最適化、およびキャッシュの活用を検討してください。
- **カスタム検索ソースが動作しない**: 外部データソースへの接続設定が正しいことを確認してください。
- **AI Search が利用できない**: AI Search プラグインが有効になっていること、および必要な設定が完了していることを確認してください。

この章では、ServiceNow の AI 機能を活用し、業務効率を向上させ、より良いユーザーエクスペリエンスを提供する方法について解説しました。これらの機能を活用することで、ServiceNow は単なるワークフロープラットフォームではなく、インテリジェントなビジネスパートナーとなります。
