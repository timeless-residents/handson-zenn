## 第 2 章：ServiceNow 開発の基礎：データモデル、スクリプト、API の理解

ServiceNow は、その強力なカスタマイズ性と拡張性によって、企業の様々な業務プロセスを効率化するプラットフォームです。この章では、ServiceNow 開発の根幹をなすデータモデル、スクリプト、API について、基礎から応用までを幅広く解説します。これらの要素を理解することで、ServiceNow のポテンシャルを最大限に引き出し、ビジネスニーズに合致したソリューションを構築できるようになります。

### 2.1 ServiceNow データモデルの理解：テーブル、フィールド、リレーションシップ

#### 2.1.1 概要と重要性

ServiceNow のデータモデルは、データベースのテーブル、フィールド、そしてテーブル間のリレーションシップによって構成されています。これは、業務プロセスに関する情報を整理し、構造化するための基盤となります。データモデルを深く理解することは、効率的なデータ管理、正確なレポート作成、そして自動化されたワークフロー構築のために不可欠です。適切に設計されたデータモデルは、パフォーマンス向上、スケーラビリティ確保、そしてメンテナンス容易性にも貢献します。

#### 2.1.2 特徴と利点

ServiceNow のデータモデルは、以下のような特徴と利点を持っています。

- **柔軟性:** 標準的なテーブル構造に加え、ビジネス要件に合わせてカスタムテーブルやフィールドを柔軟に作成できます。
- **拡張性:** 既存のデータモデルを拡張し、新たな機能やデータ要素を追加できます。
- **可視性:** データモデルの構造とリレーションシップは、ServiceNow の GUI を通じて可視化できます。
- **統合性:** 他のシステムとのデータ統合を容易にするための API を提供します。

#### 2.1.3 事前準備と前提条件

- ServiceNow インスタンスへのアクセス権が必要です。
- 基本的なデータベースの概念（テーブル、フィールド、主キー、外部キーなど）を理解していると、よりスムーズに学習できます。

#### 2.1.4 基本的な使い方

**主要なテーブル構造の把握（インシデント、変更、問題、要求など）**

ServiceNow には、ITSM（IT サービスマネジメント）プロセスをサポートするための様々な標準テーブルが用意されています。代表的なテーブルには以下のようなものがあります。

- **インシデント（incident）:** サービスの中断や障害に関する情報を管理します。
- **変更（change_request）:** インフラストラクチャやアプリケーションに対する変更要求を管理します。
- **問題（problem）:** インシデントの根本原因を特定し、恒久的な解決策を管理します。
- **要求（sc_request）:** サービスカタログを通じて行われるサービス要求を管理します。

これらのテーブルは、それぞれ特定の業務プロセスに対応しており、関連する情報をフィールドとして保持しています。例えば、インシデントテーブルには、担当者、影響度、緊急度、解決策などのフィールドが含まれています。

**カスタムテーブルの設計とベストプラクティス**

ビジネス要件に合わせてカスタムテーブルを作成することも可能です。カスタムテーブルを設計する際のベストプラクティスをいくつかご紹介します。

- **明確な目的:** テーブルの目的を明確にし、何を管理するためのテーブルなのかを定義します。
- **適切なフィールド:** 必要な情報を過不足なく格納できるフィールドを定義します。
- **命名規則:** テーブル名とフィールド名には、一貫性のある命名規則を適用します。（例：u*テーブル名、u*フィールド名）
- **インデックス:** 検索効率を向上させるために、適切なインデックスを設定します。
- **アクセス制御:** テーブルとフィールドへのアクセス権限を適切に設定します。

**例：社員スキル管理テーブルの作成**

1.  ナビゲーターで「System Definition」>「Tables」を選択します。
2.  「New」ボタンをクリックし、新しいテーブルを作成します。
3.  テーブル名（Label）に「Employee Skills」、名前（Name）に「u_employee_skills」を入力します。
4.  「Create module」チェックボックスをオンにすると、ナビゲーターにモジュールが自動的に作成されます。
5.  適切な設定を行い、「Submit」ボタンをクリックします。
6.  次に、「Columns」タブで必要なフィールドを定義します。（例：スキル名、レベル、認定資格）

**ディクショナリの設定とフィールドタイプの選択**

ディクショナリは、テーブルとフィールドのメタデータを定義します。フィールドタイプは、格納するデータの種類（文字列、数値、日付など）を指定します。適切なフィールドタイプを選択することは、データの整合性を保ち、効率的なデータ処理を行う上で重要です。

- **文字列（String）:** 短いテキストデータを格納します。
- **テキスト（Text）:** 長いテキストデータを格納します。
- **整数（Integer）:** 整数値を格納します。
- **日付（Date）:** 日付データを格納します。
- **日時（Date/Time）:** 日付と時刻データを格納します。
- **参照（Reference）:** 別のテーブルのレコードを参照します。
- **選択肢（Choice）:** 事前に定義された選択肢から値を選択します。
- **ブール値（True/False）:** 真偽値を格納します。

フィールドタイプの設定は、フィールドの定義画面で行います。適切なフィールドタイプを選択することで、データの入力規則を定義したり、データの検証を行ったりすることができます。例えば、数値フィールドには、数値以外の文字を入力できないように制限することができます。

#### 2.1.5 実践的なテクニック

- **参照整合性:** 参照フィールドを使用する際には、参照整合性を維持するために、削除時の動作（制限、カスケーディング削除など）を適切に設定します。
- **計算フィールド:** スクリプトを使用して、既存のフィールドの値から計算されるフィールドを作成できます。
- **グルーピング:** 関連するフィールドを UI 上でグルーピングすることで、見やすく整理されたフォームを作成できます。

**例：インシデントテーブルに「解決までの時間」を計算するフィールドを追加**

1.  インシデントテーブルのディクショナリを開きます。
2.  新しいフィールドを作成し、フィールドタイプを「Duration」に設定します。
3.  「Calculation」チェックボックスをオンにし、スクリプトフィールドに以下のスクリプトを入力します。

```javascript
(function calculatedFieldValue(current) {
  //解決済みになった日時から、作成日時を引いて差分を求める
  if (current.resolved_at && current.sys_created_on) {
    var created = new GlideDateTime(current.sys_created_on);
    var resolved = new GlideDateTime(current.resolved_at);
    var duration = GlideDateTime.subtract(created, resolved);
    return duration.getDisplayValue();
  }

  return ""; // 解決されていない場合は空文字列を返す
})(current);
```

#### 2.1.6 応用例とユースケース

- **サービスポートフォリオ管理:** サービス、アプリケーション、インフラストラクチャなどの情報をテーブルとして管理し、それらの間の関係性を定義することで、サービスポートフォリオを可視化できます。
- **構成管理データベース（CMDB）:** IT インフラストラクチャの構成アイテム（CI）とその属性をテーブルとして管理し、それらの間の依存関係を定義することで、CMDB を構築できます。
- **ナレッジマネジメント:** ナレッジ記事をテーブルとして管理し、カテゴリ、キーワード、評価などのフィールドを追加することで、ナレッジマネジメントシステムを構築できます。

#### 2.1.7 トラブルシューティング

- **パフォーマンス問題:** テーブルが大きくなりすぎると、パフォーマンスが低下する可能性があります。適切なインデックスを設定したり、アーカイブ戦略を検討したりすることで、パフォーマンスを改善できます。
- **データ整合性問題:** データの入力規則が不十分だと、データの整合性が損なわれる可能性があります。適切なフィールドタイプを選択したり、入力規則を設定したりすることで、データ整合性を維持できます。
- **アクセス制御問題:** ユーザーがアクセスできるべきでないデータにアクセスできてしまう場合は、アクセス制御設定を見直す必要があります。

#### 2.1.8 まとめと次のステップ

ServiceNow のデータモデルは、プラットフォームの中核をなす要素であり、その理解は ServiceNow 開発の基礎となります。テーブル、フィールド、リレーションシップを適切に設計することで、効率的なデータ管理、正確なレポート作成、そして自動化されたワークフロー構築が可能になります。

次のステップとして、GlideScript について学習し、データモデルとスクリプトを組み合わせて、より高度なカスタマイズを行う方法を習得しましょう。

### 2.2 GlideScript：ServiceNow スクリプトの基本文法とベストプラクティス

#### 2.2.1 概要と重要性

GlideScript は、ServiceNow プラットフォームで利用される JavaScript ベースのスクリプト言語です。GlideScript を使用することで、業務ロジックの自動化、データの操作、UI のカスタマイズなど、様々な機能を実装できます。GlideScript を習得することは、ServiceNow 開発者にとって不可欠なスキルです。

#### 2.2.2 特徴と利点

- **JavaScript ベース:** JavaScript の知識があれば、比較的容易に習得できます。
- **豊富な API:** ServiceNow の様々な機能を操作するための API が豊富に用意されています。
- **イベント駆動型:** 特定のイベントが発生した際に自動的に実行されるスクリプトを記述できます。
- **サーバーサイドとクライアントサイド:** サーバーサイドスクリプトとクライアントサイドスクリプトの両方を記述できます。

#### 2.2.3 事前準備と前提条件

- JavaScript の基本的な知識が必要です。
- ServiceNow インスタンスへのアクセス権が必要です。

#### 2.2.4 基本的な使い方

**GlideRecord オブジェクトの操作とクエリ**

GlideRecord オブジェクトは、データベースのテーブルのレコードを操作するための API です。GlideRecord を使用することで、レコードの検索、作成、更新、削除などを行うことができます。

**レコードの検索**

```javascript
var gr = new GlideRecord("incident");
gr.addQuery("category", "software");
gr.addQuery("priority", 1);
gr.query();

while (gr.next()) {
  gs.log("インシデント番号：" + gr.number + ", 概要：" + gr.short_description);
}
```

このスクリプトは、カテゴリが「software」で、優先度が「1」のインシデントレコードを検索し、そのインシデント番号と概要をログに出力します。`addQuery()`メソッドは、検索条件を追加するために使用されます。`query()`メソッドは、データベースに対してクエリを実行します。`next()`メソッドは、結果セットの次のレコードに移動します。

**レコードの作成**

```javascript
var gr = new GlideRecord("incident");
gr.initialize();
gr.category = "software";
gr.priority = 1;
gr.short_description = "新しいインシデント";
gr.insert();
```

このスクリプトは、新しいインシデントレコードを作成します。`initialize()`メソッドは、新しいレコードを初期化します。`insert()`メソッドは、レコードをデータベースに挿入します。

**レコードの更新**

```javascript
var gr = new GlideRecord("incident");
gr.get("sys_id", "YOUR_SYS_ID"); // sys_idで特定のレコードを取得
if (gr.isValid()) {
  gr.priority = 2;
  gr.update();
}
```

このスクリプトは、指定された sys_id を持つインシデントレコードを更新します。`get()`メソッドは、指定された sys_id を持つレコードを取得します。`isValid()`メソッドは、レコードが有効かどうかをチェックします。`update()`メソッドは、レコードをデータベースに更新します。

**レコードの削除**

```javascript
var gr = new GlideRecord("incident");
gr.get("sys_id", "YOUR_SYS_ID"); // sys_idで特定のレコードを取得
if (gr.isValid()) {
  gr.deleteRecord();
}
```

このスクリプトは、指定された sys_id を持つインシデントレコードを削除します。`deleteRecord()`メソッドは、レコードをデータベースから削除します。

**イベント駆動型スクリプト（ビジネスルール、クライアントスクリプト）**

ServiceNow では、特定のイベントが発生した際に自動的に実行されるスクリプトを記述できます。代表的なイベント駆動型スクリプトには、ビジネスルールとクライアントスクリプトがあります。

- **ビジネスルール:** データベースに対する操作（挿入、更新、削除など）の前後に実行されるサーバーサイドスクリプトです。ビジネスルールは、データの検証、自動的なフィールド更新、ワークフローのトリガーなど、様々な目的で使用できます。
- **クライアントスクリプト:** フォーム上で実行されるクライアントサイドスクリプトです。クライアントスクリプトは、UI のカスタマイズ、入力データの検証、サーバーへの非同期リクエストなど、様々な目的で使用できます。

**例：インシデントが作成された際に、担当者を自動的に割り当てるビジネスルール**

1.  ナビゲーターで「System Definition」>「Business Rules」を選択します。
2.  「New」ボタンをクリックし、新しいビジネスルールを作成します。
3.  テーブルに「Incident」を選択します。
4.  「When to run」タブで、「When」を「before」、「Insert」に設定します。
5.  「Actions」タブで、「Advanced」チェックボックスをオンにし、「Script」フィールドに以下のスクリプトを入力します。

```javascript
(function executeRule(current, previous /*null when async*/) {
  // 担当者を自動的に割り当てるロジックを記述
  // 例：カテゴリに基づいて担当者を割り当てる
  if (current.category == "software") {
    current.assigned_to = "62826bf03710200044e0bfc8bcbe5d83"; // Abel Tuterのsys_id
  } else if (current.category == "network") {
    current.assigned_to = "6816f79cc0a8016401c5a33be04be441"; // Beth Anglinのsys_id
  }
})(current, previous);
```

このビジネスルールは、インシデントが作成される前に実行され、カテゴリに基づいて担当者を自動的に割り当てます。

**例：優先度が「緊急」のインシデントが作成された際に、警告メッセージを表示するクライアントスクリプト**

1.  ナビゲーターで「System Definition」>「Client Scripts」を選択します。
2.  「New」ボタンをクリックし、新しいクライアントスクリプトを作成します。
3.  テーブルに「Incident」を選択します。
4.  「UI Type」に「All」を選択します。
5.  「Type」に「OnLoad」を選択します。
6.  「Script」フィールドに以下のスクリプトを入力します。

```javascript
function onLoad() {
  //優先度が「緊急」の場合、警告メッセージを表示
  if (g_form.getValue("priority") == "1") {
    alert("緊急度の高いインシデントです。迅速に対応してください。");
  }
}
```

このクライアントスクリプトは、インシデントフォームがロードされた際に実行され、優先度が「緊急」の場合、警告メッセージを表示します。

**非同期処理とスケジュールジョブ**

ServiceNow では、時間のかかる処理を非同期的に実行したり、定期的に実行されるジョブをスケジュールしたりすることができます。非同期処理には、ビジネスルールの「Asynchronous」オプションや、`GlideRecord`の`updateMultiple()`メソッドなどが使用されます。スケジュールジョブは、定期的に実行されるスクリプトを定義するために使用されます。

**例：大量のインシデントレコードを非同期的に更新する**

```javascript
// 非同期ビジネスルール
(function executeRule(current, previous /*null when async*/) {
  // 必要な処理を記述
  // 例：大量のインシデントレコードを更新する
  var gr = new GlideRecord("incident");
  gr.addQuery("active", true);
  gr.query();

  while (gr.next()) {
    gr.setValue("priority", 3);
    gr.update(); //  非同期処理なので、パフォーマンスへの影響を軽減
  }
})(current, previous);
```

このビジネスルールは、アクティブなインシデントレコードを検索し、優先度を「3」に更新します。`updateMultiple()`メソッドを使用することで、大量のレコードをまとめて更新できます。

**例：毎週日曜日の午前 0 時に実行されるスケジュールジョブ**

1.  ナビゲーターで「System Definition」>「Scheduled Jobs」を選択します。
2.  「New」ボタンをクリックし、新しいスケジュールジョブを作成します。
3.  「Run this script」フィールドに、実行するスクリプトを入力します。
4.  「Run」フィールドで、「Weekly」を選択し、曜日を「Sunday」に設定します。
5.  「Time」フィールドで、実行時間を「00:00:00」に設定します。

#### 2.2.5 実践的なテクニック

- **スクリプトインクルード:** 再利用可能なスクリプトをスクリプトインクルードとして定義し、複数のスクリプトから呼び出すことができます。
- **デバッグ:** `gs.log()`メソッドを使用して、スクリプトの実行中に変数の値や処理の流れをログに出力できます。
- **エラーハンドリング:** `try...catch`ステートメントを使用して、エラーが発生した場合の処理を記述できます。

#### 2.2.6 応用例とユースケース

- **自動通知:** インシデントのステータスが変更された際に、関係者に自動的に通知メールを送信する。
- **SLA 管理:** サービスレベルアグリーメント（SLA）に基づいて、インシデントの解決期限を自動的に計算する。
- **承認ワークフロー:** 変更要求の内容に応じて、承認者を自動的に決定する。

#### 2.2.7 トラブルシューティング

- **スクリプトエラー:** スクリプトにエラーがある場合、エラーメッセージが表示されます。エラーメッセージをよく読んで、スクリプトを修正してください。
- **パフォーマンス問題:** スクリプトが非効率な場合、パフォーマンスが低下する可能性があります。スクリプトを最適化したり、非同期処理を使用したりすることで、パフォーマンスを改善できます。
- **アクセス制御問題:** スクリプトがアクセスできないデータにアクセスしようとした場合、アクセス制御エラーが発生します。スクリプトを実行するユーザーに適切な権限を付与してください。

#### 2.2.8 まとめと次のステップ

GlideScript は、ServiceNow 開発において強力なツールです。基本的な文法、API、そしてベストプラクティスを理解することで、様々な業務ロジックを自動化し、UI をカスタマイズできます。

次のステップとして、ServiceNow API について学習し、外部システムとの連携やカスタム API の作成に挑戦してみましょう。

### 2.3 ServiceNow API の活用：REST API、SOAP API、Scripted REST API

#### 2.3.1 概要と重要性

ServiceNow API は、ServiceNow プラットフォームの機能やデータを外部システムからアクセスするためのインターフェースです。API を活用することで、ServiceNow と他のシステムとの連携、データの交換、そして自動化されたワークフローの構築が可能になります。ServiceNow API を理解することは、システム連携や自動化を行う上で非常に重要です。

#### 2.3.2 特徴と利点

- **REST API:** 軽量で柔軟な API であり、様々なプログラミング言語やプラットフォームから利用できます。
- **SOAP API:** 標準化されたプロトコルを使用する API であり、エンタープライズシステムとの連携に適しています。
- **Scripted REST API:** GlideScript を使用してカスタム API を作成できます。
- **セキュリティ:** API へのアクセスは、認証と認可によって保護されています。

#### 2.3.3 事前準備と前提条件

- ServiceNow インスタンスへのアクセス権が必要です。
- REST API と SOAP API の基本的な知識が必要です。
- API クライアントツール（Postman など）があると便利です。

#### 2.3.4 基本的な使い方

**REST API Explorer による API の検索とテスト**

ServiceNow には、REST API Explorer というツールが用意されており、利用可能な API を検索したり、API リクエストをテストしたりすることができます。REST API Explorer を使用することで、API の構造、パラメータ、そしてレスポンスを簡単に確認できます。

1.  ナビゲーターで「System Web Services」>「REST API Explorer」を選択します。
2.  テーブル、API 名、操作（GET, POST, PUT, DELETE）を選択します。
3.  必要なパラメータを入力し、「Send」ボタンをクリックします。
4.  レスポンスが表示されます。

**例：インシデントレコードを取得する**

1.  REST API Explorer で、テーブルに「incident」を選択します。
2.  API 名に「Table API」を選択します。
3.  操作に「GET」を選択します。
4.  「sysparm_query」パラメータに「number=INC0010001」（取得したいインシデント番号）を入力します。
5.  「Send」ボタンをクリックします。
6.  レスポンスにインシデントレコードの情報が表示されます。

**Scripted REST API によるカスタム API の作成**

Scripted REST API を使用することで、GlideScript を使用してカスタム API を作成できます。カスタム API を作成することで、特定のビジネス要件に合わせた API を構築したり、既存の API を拡張したりすることができます。

**例：インシデントを作成するカスタム API**

1.  ナビゲーターで「System Web Services」>「Scripted REST APIs」を選択します。
2.  「New」ボタンをクリックし、新しい Scripted REST API を作成します。
3.  「Name」に API の名前を入力します。
4.  「Base path」に API のエンドポイントを入力します。
5.  「Resources」タブで、「New」ボタンをクリックし、新しいリソースを作成します。
6.  「HTTP method」に「POST」を選択します。
7.  「Script」フィールドに以下のスクリプトを入力します。

```javascript
(function process(/*RESTAPIRequest*/ request, /*RESTAPIResponse*/ response) {
  var requestBody = request.body.data;

  var gr = new GlideRecord("incident");
  gr.initialize();
  gr.short_description = requestBody.short_description;
  gr.category = requestBody.category;
  var sysId = gr.insert();

  var responseBody = {
    sys_id: sysId,
    message: "インシデントが作成されました。",
  };

  response.setContentType("application/json");
  response.setBody(responseBody);
})(request, response);
```

このスクリプトは、POST リクエストを受け取り、リクエストボディのデータを使用して新しいインシデントレコードを作成します。そして、作成されたインシデントの sys_id とメッセージを JSON 形式でレスポンスとして返します。

**外部システムとの連携とデータ交換**

ServiceNow API を使用することで、外部システムとの連携やデータ交換が可能になります。例えば、外部システムからインシデントを作成したり、ServiceNow のデータを外部システムに送信したりすることができます。

**例：外部システムから REST API を使用してインシデントを作成する**

```python
import requests
import json

# ServiceNowの認証情報
USERNAME = 'YOUR_USERNAME'
PASSWORD = 'YOUR_PASSWORD'

# ServiceNowのインスタンスURL
INSTANCE_URL = 'YOUR_INSTANCE_URL'

# APIのエンドポイント
ENDPOINT = INSTANCE_URL + '/api/now/table/incident'

# リクエストヘッダー
HEADERS = {
    'Content-Type': 'application/json',
    'Accept': 'application/json'
}

# リクエストボディ
DATA = {
    'short_description': '外部システムから作成されたインシデント',
    'category': 'software'
}

# リクエストを送信
response = requests.post(ENDPOINT, auth=(USERNAME, PASSWORD), headers=HEADERS, data=json.dumps(DATA))

# レスポンスを確認
if response.status_code == 201:
    print('インシデントが作成されました。')
    print(response.json())
else:
    print('エラーが発生しました。')
    print(response.status_code)
    print(response.text)
```

この Python スクリプトは、REST API を使用して ServiceNow にインシデントを作成します。`requests`ライブラリを使用して API リクエストを送信し、認証情報、ヘッダー、そしてリクエストボディを設定します。

#### 2.3.5 実践的なテクニック

- **認証:** API へのアクセスは、ベーシック認証、OAuth 2.0 など、様々な認証方法によって保護されています。適切な認証方法を選択し、安全に API を利用してください。
- **エラーハンドリング:** API リクエストが失敗した場合、エラーコードとエラーメッセージが返されます。エラーコードに基づいて適切なエラーハンドリングを行うことで、システム連携の安定性を高めることができます。
- **レート制限:** API リクエストの回数に制限がある場合があります。レート制限を超えないように、API リクエストの頻度を調整してください。

#### 2.3.6 応用例とユースケース

- **チャットボット連携:** チャットボットから ServiceNow のデータを参照したり、ServiceNow にデータを登録したりする。
- **モニタリングシステム連携:** モニタリングシステムからアラートを受信し、ServiceNow にインシデントを自動的に作成する。
- **CRM システム連携:** CRM システムの顧客情報を ServiceNow に同期する。

#### 2.3.7 トラブルシューティング

- **認証エラー:** 認証情報が正しくない場合、認証エラーが発生します。認証情報が正しいことを確認してください。
- **アクセス権限エラー:** API にアクセスするための権限がない場合、アクセス権限エラーが発生します。適切なロールを付与してください。
- **データ形式エラー:** リクエストボディのデータ形式が正しくない場合、データ形式エラーが発生します。API のドキュメントをよく読んで、正しいデータ形式でリクエストを送信してください。

#### 2.3.8 まとめと次のステップ

ServiceNow API は、ServiceNow プラットフォームの機能を外部システムからアクセスするための強力なツールです。REST API、SOAP API、そして Scripted REST API を理解することで、様々なシステムとの連携や自動化を実現できます。

この章で学んだ知識を基に、実際のユースケースを想定して API を実際に活用してみましょう。さらに、ServiceNow のドキュメントやコミュニティを活用して、より高度な API の使い方を習得していきましょう。
