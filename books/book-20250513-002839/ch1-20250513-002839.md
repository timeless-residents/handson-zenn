## 第 1 章：ServiceNow カスタマイズの「なぜ？」と「どうすれば？」 - 業務効率化の鍵を握る技術

### 1.1 ServiceNow カスタマイズの必要性とビジネスインパクト

#### 概要と重要性

ServiceNow は、IT サービスマネジメント（ITSM）を中心に、様々な業務プロセスを効率化するための強力なプラットフォームです。しかし、どんなに優れた標準機能を持っていても、すべての企業のニーズに完璧に合致するわけではありません。特に、独自のビジネスプロセスや業界特有の要件を持つ企業にとって、ServiceNow の標準機能をそのまま利用するだけでは、真の業務効率化は実現できません。そこで重要になるのが ServiceNow のカスタマイズです。

カスタマイズとは、ServiceNow の標準機能を拡張したり、既存の機能を変更したりすることで、自社のビジネスプロセスに最適なプラットフォームに作り変えることです。適切なカスタマイズを行うことで、業務効率化、コスト削減、顧客満足度向上など、様々なビジネスインパクトを生み出すことができます。

#### ServiceNow の標準機能の限界とカスタマイズによる解決

ServiceNow の標準機能は、多くの企業が共通して抱える課題を解決できるように設計されています。しかし、企業によっては、以下のような課題に直面することがあります。

- **独自の承認フロー:** 標準の承認フローでは対応できない、複雑な承認プロセスが存在する。
- **特定の業界要件:** 金融業界や医療業界など、規制が厳しい業界では、独自のコンプライアンス要件を満たす必要がある。
- **社内システムとの連携:** 既存の社内システムと ServiceNow とのデータ連携が必要だが、標準機能では対応できない。
- **ユーザーエクスペリエンスの向上:** 標準の UI では、特定のユーザーグループにとって使いにくい。

これらの課題は、ServiceNow のカスタマイズによって解決することができます。例えば、独自の承認フローを実装したり、特定の業界要件を満たすように機能を拡張したり、社内システムとのデータ連携を自動化したり、ユーザーエクスペリエンスを向上させるための UI を構築したりすることができます。

#### 業務プロセス効率化、コスト削減、顧客満足度向上への貢献

ServiceNow のカスタマイズは、以下の点でビジネスに貢献します。

- **業務プロセス効率化:** 手作業で行っていた作業を自動化したり、複数のシステムにまたがる作業を統合したりすることで、業務プロセスを大幅に効率化できます。
- **コスト削減:** 人的コストや運用コストを削減できます。例えば、自動化によって人的リソースを削減したり、システム統合によって運用コストを削減したりできます。
- **顧客満足度向上:** 顧客向けのポータルサイトを構築したり、問い合わせ対応を自動化したりすることで、顧客満足度を向上させることができます。

#### カスタマイズ成功/失敗事例から学ぶ重要ポイント

ServiceNow のカスタマイズは、成功すれば大きなビジネスインパクトをもたらしますが、失敗すると逆に業務効率を悪化させたり、システムを複雑化させたりする可能性があります。以下に、カスタマイズの成功と失敗事例から学ぶべき重要なポイントをまとめます。

- **成功事例:**

  - **明確な目標設定:** カスタマイズの目的を明確にし、具体的な目標を設定することで、プロジェクトの方向性を定める。
  - **適切なスコープ設定:** 必要以上に広範囲なカスタマイズを避け、優先順位をつけて段階的に進める。
  - **十分なテスト:** 開発した機能を十分にテストし、バグを早期に発見して修正する。
  - **ユーザーからのフィードバック:** 開発段階からユーザーからのフィードバックを取り入れ、使いやすいシステムを構築する。
  - **継続的な改善:** リリース後もシステムの利用状況をモニタリングし、必要に応じて改善を行う。

- **失敗事例:**
  - **目的の曖昧さ:** カスタマイズの目的が曖昧なため、開発が進むにつれて方向性がずれてしまう。
  - **過剰なカスタマイズ:** 標準機能を無視して、過剰なカスタマイズを行うことで、システムが複雑化し、保守が困難になる。
  - **テスト不足:** 十分なテストを行わずにリリースしたため、バグが多発し、ユーザーからの不満が続出する。
  - **ユーザーの無視:** ユーザーからのフィードバックを無視して開発を進めたため、使いにくいシステムになってしまう。
  - **メンテナンス不足:** リリース後のメンテナンスを怠ったため、システムが老朽化し、パフォーマンスが低下する。

**重要な教訓:** カスタマイズは、明確な目標設定、適切なスコープ設定、十分なテスト、ユーザーからのフィードバック、継続的な改善が不可欠です。

#### まとめと次のステップ

ServiceNow のカスタマイズは、業務効率化、コスト削減、顧客満足度向上に大きく貢献する可能性を秘めています。しかし、成功するためには、明確な目標設定、適切なスコープ設定、十分なテスト、ユーザーからのフィードバック、継続的な改善が不可欠です。次のセクションでは、カスタマイズの種類と選択肢について詳しく解説します。

### 1.2 カスタマイズの種類と選択肢：ローコード/ノーコードからプロコードまで

#### 概要と重要性

ServiceNow のカスタマイズには、さまざまな種類と選択肢があります。大きく分けると、ローコード/ノーコード開発とプロコード開発の 2 つに分類できます。ローコード/ノーコード開発は、GUI ベースのツールやテンプレートを活用して、比較的容易にカスタマイズを行う方法です。一方、プロコード開発は、JavaScript などのプログラミング言語を用いて、より高度なカスタマイズを行う方法です。

#### ビジネスルール、クライアントスクリプト、UI ポリシー、UI アクション、スクリプトインクルード、ワークフロー

ServiceNow でよく使用されるカスタマイズの種類を以下に示します。

- **ビジネスルール:** レコードが挿入、更新、削除される際など、特定の条件が満たされた場合に実行されるスクリプト。例えば、インシデントの優先度に基づいて担当者を自動的に割り当てるビジネスルールを作成できます。

  ```javascript
  // ビジネスルール：インシデントの優先度に基づいて担当者を自動的に割り当てる
  (function executeRule(current, previous /*null when async*/) {
    if (current.priority == 1) {
      //優先度が高い場合
      current.assigned_to = "62826bf03710200044e0bfc8bcbe5d83"; //特定のユーザーID
    }
  })(current, previous);
  ```

- **クライアントスクリプト:** ブラウザ側で実行されるスクリプト。フォームの入力チェックや UI の制御など、ユーザーインターフェースの動作をカスタマイズできます。例えば、特定のフィールドが入力された際に、別のフィールドを自動的に表示/非表示にするクライアントスクリプトを作成できます。

  ```javascript
  // クライアントスクリプト：特定のフィールドが入力された際に、別のフィールドを自動的に表示/非表示にする
  function onChange(control, oldValue, newValue, isLoading, isTemplate) {
    if (isLoading || newValue === "") {
      return;
    }

    if (newValue == "true") {
      g_form.setVisible("additional_information", true);
    } else {
      g_form.setVisible("additional_information", false);
    }
  }
  ```

- **UI ポリシー:** 特定の条件が満たされた場合に、フォームのフィールドを必須にしたり、読み取り専用にしたり、非表示にしたりするルール。クライアントスクリプトよりも簡単に UI を制御できます。

- **UI アクション:** フォーム上にボタンやリンクを追加し、特定の処理を実行するためのスクリプト。例えば、インシデントをクローズするためのボタンを追加できます。

- **スクリプトインクルード:** 複数のビジネスルールやクライアントスクリプトで再利用できる関数を定義するためのスクリプト。コードの再利用性を高め、メンテナンスを容易にします。

- **ワークフロー:** 承認プロセスやタスクの割り当てなど、複数のステップからなる業務プロセスを自動化するためのツール。GUI ベースで、複雑なプロセスも視覚的に設計できます。

#### ローコード/ノーコード開発プラットフォームの活用（App Engine Studio など）

ServiceNow には、ローコード/ノーコード開発を支援するための様々なプラットフォームが用意されています。代表的なものとして、App Engine Studio があります。App Engine Studio は、GUI ベースのツールを用いて、アプリケーションを迅速に開発できるプラットフォームです。コーディングの知識がなくても、ドラッグ＆ドロップ操作で UI を作成したり、テンプレートを活用してワークフローを構築したりできます。

App Engine Studio を使用することで、開発期間を大幅に短縮し、ビジネスユーザー自身がアプリケーションを開発することも可能です。ただし、高度なカスタマイズを行う場合は、プロコード開発が必要になることもあります。

#### プロコード開発における注意点とガバナンス

プロコード開発は、高度なカスタマイズを実現できる反面、技術的な知識やスキルが必要となります。また、コードの品質やセキュリティを確保するために、適切なガバナンス体制を構築する必要があります。

プロコード開発を行う際には、以下の点に注意してください。

- **コードの標準化:** コーディング規約を定め、チーム全体で共有することで、コードの品質を維持する。
- **バージョン管理:** Git などのバージョン管理システムを導入し、コードの変更履歴を管理する。
- **テスト:** 開発したコードを十分にテストし、バグを早期に発見して修正する。
- **セキュリティ:** セキュリティ脆弱性がないかを確認し、適切な対策を講じる。
- **ドキュメント:** コードの仕様や使い方をドキュメントにまとめ、チーム全体で共有する。

#### 実践的なテクニック

- **ビジネスルールでの例外処理:** ビジネスルール内で例外が発生した場合に、ログを出力したり、エラーメッセージを表示したりすることで、問題を早期に発見できます。

  ```javascript
  // ビジネスルール：例外処理の例
  (function executeRule(current, previous /*null when async*/) {
    try {
      // 処理
      gs.info("処理が正常に完了しました。");
    } catch (e) {
      gs.error("エラーが発生しました：" + e);
      gs.addErrorMessage(
        "エラーが発生しました。システム管理者に連絡してください。"
      );
    }
  })(current, previous);
  ```

- **クライアントスクリプトでの非同期処理:** サーバーとの通信を行うクライアントスクリプトでは、非同期処理を使用することで、UI の応答性を維持できます。

  ```javascript
  // クライアントスクリプト：非同期処理の例
  function onClick() {
    var ga = new GlideAjax("MyScriptInclude");
    ga.addParam("sysparm_name", "getMyData");
    ga.addParam("sysparm_value", g_form.getValue("my_field"));
    ga.getAnswer(processResult);

    function processResult(response) {
      g_form.setValue("result_field", response);
    }
  }
  ```

- **スクリプトインクルードでの再利用性:** 複数のビジネスルールやクライアントスクリプトで再利用できる関数をスクリプトインクルードに定義することで、コードの重複を避け、メンテナンスを容易にします。

  ```javascript
  // スクリプトインクルード：例
  var MyScriptInclude = Class.create();
  MyScriptInclude.prototype = {
    initialize: function () {},

    getMyData: function (value) {
      // 何らかの処理
      return "処理結果：" + value;
    },

    type: "MyScriptInclude",
  };
  ```

#### 応用例とユースケース

- **自動化されたインシデント解決:** インシデントの内容に基づいて、自動的に解決策を提示するシステムを構築する。
- **AI を活用した問い合わせ対応:** AI チャットボットを導入し、ユーザーからの問い合わせに自動的に対応する。
- **IoT デバイスとの連携:** IoT デバイスから送信されるデータを ServiceNow に取り込み、障害予測や予防保全に活用する。

#### トラブルシューティング

- **ビジネスルールが実行されない:** ビジネスルールの条件が正しく設定されているか、アクティブになっているかを確認する。
- **クライアントスクリプトが動作しない:** ブラウザのデベロッパーツールでエラーを確認し、コードに誤りがないかを確認する。
- **ワークフローが期待通りに動作しない:** ワークフローのログを確認し、問題のあるアクティビティを特定する。

#### まとめと次のステップ

ServiceNow のカスタマイズには、ローコード/ノーコード開発からプロコード開発まで、さまざまな種類と選択肢があります。自社のニーズやスキルに応じて、最適な方法を選択することが重要です。次のセクションでは、カスタマイズ開発環境の構築について詳しく解説します。

### 1.3 カスタマイズ開発環境の構築：個人開発からチーム開発まで

#### 概要と重要性

ServiceNow のカスタマイズを行うためには、適切な開発環境を構築することが不可欠です。開発環境とは、コードを記述したり、テストを行ったり、デバッグを行ったりするためのツールやインフラのことです。個人で開発する場合と、チームで開発する場合とでは、必要なツールや設定が異なります。

#### ServiceNow 開発インスタンスの取得と設定

ServiceNow の開発インスタンスは、本番環境とは別に、カスタマイズの開発やテストを行うための環境です。ServiceNow Developer Program に登録することで、無料で開発インスタンスを取得できます。

開発インスタンスを取得したら、以下の設定を行うことを推奨します。

- **基本設定:** システム設定、タイムゾーン、言語などを設定する。
- **セキュリティ設定:** アクセス制御ルールを設定し、セキュリティを強化する。
- **テストデータ:** テストに必要なデータを投入する。

#### ソースコード管理（Git）と CI/CD パイプラインの導入

ソースコード管理とは、コードの変更履歴を管理し、複数の開発者が同時に作業できるようにするための仕組みです。Git は、最も広く利用されているソースコード管理システムの一つです。

Git を導入することで、以下のメリットが得られます。

- **変更履歴の追跡:** コードの変更履歴を追跡し、過去の状態に戻すことができます。
- **複数人での共同開発:** 複数の開発者が同時に作業し、変更をマージすることができます。
- **ブランチの活用:** 新しい機能を開発する際に、既存のコードに影響を与えずに作業できます。
- **コードのバックアップ:** コードをリモートリポジトリにバックアップすることで、万が一の事態に備えることができます。

CI/CD パイプラインとは、コードの変更を自動的にテストし、本番環境にデプロイするための仕組みです。CI/CD パイプラインを導入することで、開発サイクルを高速化し、品質を向上させることができます。

#### チーム開発における役割分担とコラボレーション

チームで ServiceNow のカスタマイズを行う場合は、役割分担を明確にし、チームメンバー間のコラボレーションを促進することが重要です。

一般的な役割としては、以下のようなものがあります。

- **開発リーダー:** プロジェクト全体の計画を立て、進捗を管理する。
- **開発者:** コードを記述し、テストを行う。
- **テスター:** 開発された機能をテストし、バグを発見する。
- **ビジネスアナリスト:** ユーザーの要件を収集し、開発チームに伝える。

チームメンバー間のコミュニケーションを円滑にするために、チャットツールやビデオ会議ツールなどを活用することを推奨します。また、定期的にミーティングを開催し、進捗状況や課題を共有することも重要です。

#### 実践的なテクニック

- **Update Set の活用:** 開発したカスタマイズを Update Set にまとめ、別のインスタンスに簡単にデプロイすることができます。

  1.  **Update Set の作成:** 「System Update Sets」 > 「Local Update Sets」から新しい Update Set を作成します。
  2.  **カスタマイズの記録:** 作成した Update Set を「In Progress」にし、カスタマイズを行います。カスタマイズ内容は自動的に Update Set に記録されます。
  3.  **Update Set の完了:** カスタマイズが完了したら、Update Set を「Complete」にします。
  4.  **別のインスタンスへの適用:** Update Set を XML ファイルとしてエクスポートし、別のインスタンスにインポートします。

- **Glide CLI の使用:** Glide CLI を使用すると、コマンドラインから ServiceNow の操作を行うことができます。例えば、Update Set をエクスポートしたり、スクリプトをアップロードしたりすることができます。

- **ServiceNow DevOps:** ServiceNow DevOps は、CI/CD パイプラインを構築するためのツールです。ServiceNow DevOps を使用することで、開発サイクルを自動化し、品質を向上させることができます。

#### 応用例とユースケース

- **アジャイル開発:** ServiceNow のカスタマイズをアジャイル開発で行う場合、短いスプリントで開発を進め、頻繁にリリースを行うことが重要です。
- **DevOps:** ServiceNow DevOps を導入し、開発、テスト、デプロイを自動化することで、開発サイクルを高速化し、品質を向上させることができます。
- **ローコード/ノーコード開発:** App Engine Studio を活用し、ビジネスユーザー自身がアプリケーションを開発することで、開発期間を短縮し、ビジネスニーズに迅速に対応することができます。

#### トラブルシューティング

- **Update Set が正常に適用されない:** Update Set のプレビューを確認し、競合が発生していないかを確認する。競合が発生している場合は、競合を解消してから Update Set を適用する。
- **Git でコンフリクトが発生する:** コンフリクトが発生したファイルを編集し、コンフリクトを解消する。
- **CI/CD パイプラインが正常に動作しない:** CI/CD パイプラインのログを確認し、問題のあるステップを特定する。

#### まとめと次のステップ

ServiceNow のカスタマイズ開発環境は、個人開発からチーム開発まで、さまざまな規模やニーズに対応できるように構築する必要があります。適切な開発環境を構築することで、開発効率を向上させ、高品質なカスタマイズを実現することができます。

この章では、ServiceNow のカスタマイズの必要性、種類、開発環境について解説しました。次のステップでは、具体的なカスタマイズの事例について解説します。
