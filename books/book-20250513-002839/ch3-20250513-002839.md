## 第 3 章：顧客を「ハッ」とさせる！UI/UX カスタマイズ：見た目と使いやすさの両立

ServiceNow の真価は、その柔軟なカスタマイズ性にあります。標準機能だけでも十分強力ですが、UI/UX を顧客のニーズに合わせて最適化することで、利用者の満足度を飛躍的に向上させることができます。本章では、ServiceNow における UI/UX カスタマイズの要となる、フォーム制御、操作性向上、Portal デザインの３つの要素について、具体的な手法と実践的なノウハウを解説します。

### 3.1 UI ポリシーとクライアントスクリプトによるフォーム制御

#### 3.1.1 概要と重要性

ServiceNow のフォームは、データの入力・表示の中核を担う重要な要素です。しかし、標準のフォームレイアウトや制御だけでは、特定の業務プロセスやユーザーの役割に最適化されているとは限りません。UI ポリシーとクライアントスクリプトを活用することで、フォームの表示/非表示、必須/任意、読み取り専用といった属性を動的に制御し、より直感的で使いやすいフォームを実現できます。

#### 3.1.2 特徴と利点

- **UI ポリシー：** コーディング不要で、宣言的な方法でフォームの制御を定義できます。ビジネスルールに基づいた条件設定が容易で、非開発者でも GUI を通じてカスタマイズできます。
- **クライアントスクリプト：** JavaScript を用いて、より複雑なフォーム制御を実現できます。例えば、API 連携や動的な値の計算など、高度なカスタマイズが可能です。
- **利点：**
  - ユーザーの入力ミスを減らし、データ品質を向上させます。
  - 特定のユーザーグループに必要な情報のみを表示し、混乱を防ぎます。
  - ワークフローの状態に応じてフォームを変化させ、プロセスを効率化します。

#### 3.1.3 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限、または UI ポリシー/クライアントスクリプトの作成権限が必要です。
- UI ポリシー、クライアントスクリプトの基本的な概念を理解していることが望ましいです。
- JavaScript の基本的な知識があると、クライアントスクリプトによるカスタマイズがよりスムーズに進みます。

#### 3.1.4 基本的な使い方

**UI ポリシー：**

1.  ナビゲーションメニューから「システム UI」>「UI ポリシー」を選択します。
2.  「新規」ボタンをクリックし、UI ポリシーのレコードを作成します。
3.  「テーブル」フィールドで、制御対象のテーブルを選択します。
4.  「適用条件」セクションで、ポリシーが適用される条件を設定します（例：担当者が特定のグループである場合）。
5.  「UI ポリシーアクション」セクションで、フィールドの表示/非表示、必須/任意、読み取り専用などのアクションを設定します。

**例：インシデントレコードの「影響」フィールドを、優先度が「高」の場合に必須にする**

- テーブル：インシデント[incident]
- 適用条件：優先度 is 高
- UI ポリシーアクション：
  - フィールド名：影響
  - 必須：True

**クライアントスクリプト：**

1.  ナビゲーションメニューから「システム定義」>「クライアントスクリプト」を選択します。
2.  「新規」ボタンをクリックし、クライアントスクリプトのレコードを作成します。
3.  「テーブル」フィールドで、制御対象のテーブルを選択します。
4.  「タイプ」フィールドで、スクリプトの実行タイミングを選択します（例：onChange、 onLoad）。
5.  「スクリプト」フィールドに、JavaScript コードを記述します。

**例：インシデントレコードの「カテゴリ」フィールドの値に応じて、「サブカテゴリ」フィールドの選択肢を動的に変更する**

```javascript
function onChange(control, oldValue, newValue, isLoading, isTemplate) {
  if (isLoading || newValue === "") {
    return;
  }

  var ga = new GlideAjax("CategorySubcategory"); // GlideAjaxを使ってサーバーサイドスクリプトを呼び出す
  ga.addParam("sysparm_name", "getSubcategories");
  ga.addParam("sysparm_category", newValue);
  ga.getAJAX(function (response) {
    var answer = JSON.parse(
      response.responseXML.documentElement.getAttribute("answer")
    );
    var subcategoryControl = g_form.getControl("subcategory");
    subcategoryControl.options.length = 0; // 選択肢をクリア

    var opt = new Option("-- なし --", "");
    subcategoryControl.options[subcategoryControl.options.length] = opt;

    for (var i = 0; i < answer.length; i++) {
      var opt = new Option(answer[i], answer[i]);
      subcategoryControl.options[subcategoryControl.options.length] = opt;
    }
  });
}
```

**サーバーサイドスクリプトインクルード (CategorySubcategory):**

```javascript
var CategorySubcategory = Class.create();
CategorySubcategory.prototype = Object.extendsObject(AbstractAjaxProcessor, {
  getSubcategories: function () {
    var category = this.getParameter("sysparm_category");
    var subcategories = [];
    var gr = new GlideRecord("subcategory_table"); // サブカテゴリを格納するテーブル
    gr.addQuery("category", category);
    gr.query();
    while (gr.next()) {
      subcategories.push(gr.getValue("name"));
    }
    return JSON.stringify(subcategories);
  },
  type: "CategorySubcategory",
});
```

#### 3.1.5 実践的なテクニック

- **UI ポリシーの順序：** 複数の UI ポリシーが同一フィールドに適用される場合、順序に基づいて実行されます。競合するポリシーがある場合は、順序を調整して意図した動作になるようにします。
- **クライアントスクリプトのデバッグ：** ブラウザの開発者ツールを活用して、クライアントスクリプトの動作をデバッグします。`console.log()` を使用して変数の値を出力したり、ブレークポイントを設定してスクリプトの実行を一時停止したりできます。
- **GlideForm API の活用：** クライアントスクリプトでは、`g_form` オブジェクトを通じて GlideForm API を利用できます。この API を利用することで、フィールドの値の取得/設定、フォームの表示/非表示、メッセージの表示など、様々な操作を実行できます。

#### 3.1.6 応用例とユースケース

- **インシデント管理：** 影響度と緊急度に応じて、担当者の割り当てを自動化する。
- **変更管理：** 変更要求の種類に応じて、承認ワークフローを動的に変更する。
- **要求管理：** 要求アイテムの内容に応じて、必須入力項目を切り替える。
- **ナレッジ管理：** ナレッジ記事のカテゴリに応じて、公開範囲を制限する。

#### 3.1.7 トラブルシューティング

- **UI ポリシーが期待通りに動作しない：**
  - 適用条件が正しく設定されているか確認します。
  - UI ポリシーの順序が競合していないか確認します。
  - ブラウザのキャッシュをクリアして、最新の UI ポリシーが適用されているか確認します。
- **クライアントスクリプトでエラーが発生する：**
  - ブラウザの開発者ツールでエラーメッセージを確認し、原因を特定します。
  - JavaScript の構文エラーがないか確認します。
  - GlideForm API の使い方が正しいか確認します。
- **UI ポリシーとクライアントスクリプトが競合する：**
  - UI ポリシーとクライアントスクリプトの両方で同じフィールドを制御しようとすると、予期せぬ動作が発生する可能性があります。どちらか一方に制御を集中させるか、両者の連携を考慮した設計を行います。

#### 3.1.8 まとめと次のステップ

UI ポリシーとクライアントスクリプトは、ServiceNow のフォームを柔軟に制御するための強力なツールです。これらの機能を使いこなすことで、ユーザーエクスペリエンスを向上させ、業務プロセスを効率化することができます。次のステップとして、より複雑な UI ポリシーやクライアントスクリプトの作成に挑戦し、GlideForm API の活用方法を深く掘り下げてみましょう。

### 3.2 UI アクションとコンテキストメニューによる操作性向上

#### 3.2.1 概要と重要性

UI アクションとコンテキストメニューは、ユーザーがレコードに対して実行できる操作を定義する要素です。これらをカスタマイズすることで、標準機能では実現できない独自の操作を追加し、ユーザーの作業効率を大幅に向上させることができます。

#### 3.2.2 特徴と利点

- **UI アクション：** フォーム上やリストビューにカスタムボタンやリンクを追加し、特定の処理を実行できます。
- **コンテキストメニュー：** レコードを右クリックした際に表示されるメニューをカスタマイズし、必要な操作に素早くアクセスできるようにします。
- **利点：**
  - 複雑な操作を簡素化し、ユーザーの作業時間を短縮します。
  - ワークフローをトリガーし、プロセスの自動化を促進します。
  - 外部システムとの連携を可能にし、ServiceNow の機能を拡張します。

#### 3.2.3 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限、または UI アクションの作成権限が必要です。
- UI アクション、コンテキストメニューの基本的な概念を理解していることが望ましいです。
- JavaScript の知識があると、スクリプトによるカスタマイズがよりスムーズに進みます。

#### 3.2.4 基本的な使い方

**UI アクション：**

1.  ナビゲーションメニューから「システム UI」>「UI アクション」を選択します。
2.  「新規」ボタンをクリックし、UI アクションのレコードを作成します。
3.  「テーブル」フィールドで、アクション対象のテーブルを選択します。
4.  「アクション名」フィールドに、アクションの名前を入力します。
5.  「フォームボタン」「フォームリンク」「フォームコンテキストメニュー」「リストコンテキストメニュー」などのチェックボックスをオンにして、アクションを表示する場所を指定します。
6.  「スクリプト」フィールドに、JavaScript コードを記述します。

**例：インシデントレコードに「エスカレーション」ボタンを追加し、担当マネージャーに通知を送信する**

- テーブル：インシデント[incident]
- アクション名：エスカレーション
- フォームボタン：True
- スクリプト：

```javascript
function escalateIncident() {
  var manager = g_form.getValue("assigned_to.manager"); // 担当者のマネージャーを取得
  if (manager) {
    var email = new GlideRecord("sys_user");
    if (email.get(manager)) {
      var gr = new GlideRecord("sys_email");
      gr.initialize();
      gr.setValue("type", "email");
      gr.setValue("recipients", email.email); // マネージャーのメールアドレス
      gr.setValue("subject", "インシデントのエスカレーション");
      gr.setValue(
        "body",
        "インシデント " +
          g_form.getValue("number") +
          " がエスカレーションされました。"
      );
      gr.insert();
    }
  } else {
    alert("担当者にマネージャーが設定されていません。");
  }
  action.setRedirectURL(current); // 現在のレコードにリダイレクト
  action.setReturnURL(current);
}

escalateIncident(); // 関数を実行
```

**コンテキストメニュー：**

UI アクションと同様の手順で作成しますが、「フォームコンテキストメニュー」または「リストコンテキストメニュー」のチェックボックスをオンにします。

#### 3.2.5 実践的なテクニック

- **GlideDialogWindow の活用：** UI アクションから GlideDialogWindow を呼び出すことで、モーダルウィンドウを表示し、追加情報の入力や確認を行うことができます。
- **クライアントサイドとサーバーサイドの連携：** UI アクションから GlideAjax を使用してサーバーサイドスクリプトを呼び出すことで、複雑な処理やデータベース操作を実行できます。
- **セキュリティ考慮：** UI アクションの実行権限を適切に設定し、不正な操作を防ぎます。

#### 3.2.6 応用例とユースケース

- **インシデント管理：** インシデントを特定の問題に関連付けるボタンを追加する。
- **変更管理：** 変更要求を承認または却下するボタンを追加する。
- **要求管理：** 要求アイテムを履行するタスクを作成するボタンを追加する。
- **ナレッジ管理：** ナレッジ記事を印刷または PDF としてエクスポートするボタンを追加する。

#### 3.2.7 トラブルシューティング

- **UI アクションが表示されない：**
  - UI アクションの「アクティブ」チェックボックスがオンになっているか確認します。
  - UI アクションが表示される条件が満たされているか確認します。
  - ユーザーのロールに UI アクションの実行権限があるか確認します。
- **UI アクションがエラーで失敗する：**
  - スクリプトに構文エラーがないか確認します。
  - GlideForm API の使い方が正しいか確認します。
  - サーバーサイドスクリプトでエラーが発生していないか確認します。

#### 3.2.8 まとめと次のステップ

UI アクションとコンテキストメニューは、ServiceNow の操作性を向上させるための強力な手段です。これらの機能を活用することで、ユーザーの作業効率を大幅に向上させ、業務プロセスを効率化することができます。次のステップとして、より複雑な UI アクションの作成に挑戦し、GlideDialogWindow や GlideAjax の活用方法を深く掘り下げてみましょう。

### 3.3 Portal デザインのカスタマイズ：Service Portal、Now Mobile

#### 3.3.1 概要と重要性

Service Portal と Now Mobile は、ServiceNow のユーザーインターフェースをエンドユーザー向けに提供する重要なコンポーネントです。これらのポータルサイトやモバイルアプリをカスタマイズすることで、ブランドイメージを反映させ、ユーザーエクスペリエンスを向上させることができます。

#### 3.3.2 特徴と利点

- **Service Portal：** ドラッグ＆ドロップでウィジェットを配置し、ノーコード/ローコードでポータルサイトを作成できます。
- **Now Mobile：** ネイティブアプリのような操作性を提供し、外出先でも ServiceNow の機能を利用できます。
- **利点：**
  - 直感的で使いやすいインターフェースを提供し、ユーザーの満足度を向上させます。
  - ブランドイメージを反映させ、企業の一貫性を保ちます。
  - モバイルデバイスに最適化されたインターフェースを提供し、場所を選ばずに業務を遂行できます。

#### 3.3.3 事前準備と前提条件

- ServiceNow インスタンスへの管理者権限、または Service Portal/Now Mobile のカスタマイズ権限が必要です。
- Service Portal、Now Mobile の基本的な概念を理解していることが望ましいです。
- HTML、CSS、JavaScript の知識があると、ウィジェットのカスタマイズがよりスムーズに進みます。

#### 3.3.4 基本的な使い方

**Service Portal ウィジェットの作成とカスタマイズ：**

1.  ナビゲーションメニューから「Service Portal」>「ウィジェット」を選択します。
2.  「新規」ボタンをクリックし、ウィジェットのレコードを作成します。
3.  「クライアントスクリプト」「サーバースクリプト」「HTML テンプレート」の各セクションに、必要なコードを記述します。

**例：シンプルな HelloWorld ウィジェット**

- **HTML テンプレート:**

```html
<div>
  <h1>Hello, World!</h1>
</div>
```

- **クライアントスクリプト:** (必要に応じて)

```javascript
function($scope) {
  /* widget controller */
  var c = this;
}
```

- **サーバーサイドスクリプト:** (必要に応じて)

```javascript
(function () {
  /* populate the 'data' object */
  /* e.g., data.table = $sp.getValue('table'); */
})();
```

**テーマとブランディングの適用：**

1.  ナビゲーションメニューから「Service Portal」>「テーマ」を選択します。
2.  既存のテーマを編集するか、新しいテーマを作成します。
3.  色、フォント、ロゴなどの設定を調整し、ブランドイメージに合わせます。

**Now Mobile アプリのカスタマイズ：**

1.  Studio を使用して、Now Mobile アプリの UI をカスタマイズします。
2.  画面、アクション、ナビゲーションなどを調整し、モバイルデバイスに最適化します。
3.  モバイルアプリの設定で、ブランドロゴやカラースキームを適用します。

#### 3.3.5 実践的なテクニック

- **AngularJS の活用：** Service Portal のウィジェットは、AngularJS フレームワークに基づいて構築されています。AngularJS の知識を習得することで、より高度なウィジェットを作成できます。
- **SCSS の活用：** テーマのスタイルを定義する際に、SCSS を使用することで、CSS を効率的に管理できます。
- **モバイルデザイン原則の適用：** Now Mobile アプリをカスタマイズする際には、モバイルデザインの原則を考慮し、タッチ操作に適したインターフェースを設計します。

#### 3.3.6 応用例とユースケース

- **Service Portal：**
  - IT サポートポータル：インシデントの登録、ナレッジ記事の検索、FAQ の閲覧など。
  - 人事ポータル：休暇申請、給与明細の確認、福利厚生情報の閲覧など。
  - 施設管理ポータル：会議室の予約、設備の故障報告など。
- **Now Mobile：**
  - フィールドサービスアプリ：作業指示の確認、作業時間の記録、部品在庫の確認など。
  - 承認アプリ：申請の承認、却下など。
  - インシデント管理アプリ：インシデントの登録、更新、解決など。

#### 3.3.7 トラブルシューティング

- **ウィジェットが表示されない：**
  - ウィジェットがアクティブになっているか確認します。
  - ウィジェットが適切なページに配置されているか確認します。
  - ウィジェットのアクセス制御が正しく設定されているか確認します。
- **テーマが適用されない：**
  - テーマがアクティブになっているか確認します。
  - テーマが正しいポータルに関連付けられているか確認します。
  - ブラウザのキャッシュをクリアして、最新のテーマが適用されているか確認します。
- **Now Mobile アプリが期待通りに動作しない：**
  - アプリの最新バージョンがインストールされているか確認します。
  - ネットワーク接続が安定しているか確認します。
  - サーバー側の設定がモバイルアプリと互換性があるか確認します。

#### 3.3.8 まとめと次のステップ

Service Portal と Now Mobile のカスタマイズは、ServiceNow のユーザーエクスペリエンスを向上させるための重要な手段です。これらの機能を活用することで、ブランドイメージを反映させ、ユーザーの満足度を向上させることができます。次のステップとして、より複雑なウィジェットの作成に挑戦し、AngularJS や SCSS の活用方法を深く掘り下げてみましょう。また、モバイルデザインの原則を学び、Now Mobile アプリの UI を最適化することをおすすめします。
